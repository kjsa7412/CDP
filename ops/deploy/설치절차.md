## 0. 준비물 — Node · git

`install.sh` 가 첫 줄에서 **Node 20 이상 · git** 을 확인하고 없으면 멈춘다. `npm` 은 필요 없다.

```bash
sudo apt-get install -y git                       # Debian · Ubuntu   (RHEL 계열: sudo dnf install -y git)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt-get install -y nodejs
#   RHEL 계열: curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash - && sudo dnf install -y nodejs
```

**인터넷이 막혔으면** — nodejs.org 의 `node-v20.*-linux-x64.tar.xz` 를 반입해서

```bash
sudo mkdir -p /usr/local/lib/nodejs && sudo tar -xJf node-v20.*-linux-x64.tar.xz -C /usr/local/lib/nodejs
sudo ln -sf /usr/local/lib/nodejs/node-v20.*-linux-x64/bin/node /usr/local/bin/node
```

**`nvm` 은 쓰지 않는다** — 사람의 셸에만 붙어 서비스 계정에서 안 보인다. `install.sh` 는 `command -v node` 경로를 유닛에 박으므로 어디에 깔았든 맞는다.

## 1. 산출물 반입

받는 것은 `cdp-server-v<판>.tar.gz` 와 `SHA256SUMS` 둘이다(GitHub Release · 또는 개발 PC 의 `npm run release:server -- <판>` → `ops/out/server/`).
**서버도 작업 PC 도 인터넷을 타지 않는다** — 화면의 글꼴까지 tar 안에 있고, 작업 PC 의 설치기는 이 서버에서 받는다.

```bash
scp cdp-server-v<판>.tar.gz SHA256SUMS <계정>@<서버 IP>:/tmp/
cd /tmp && sha256sum -c SHA256SUMS --ignore-missing
tar -xzf cdp-server-v<판>.tar.gz && node cdp-server-v<판>/bin/ctx.mjs version     # v<판> · 빌드 … / mcp: http
```

## 2. 방화벽

`install.sh` 는 여는 명령을 **안내만** 한다(배포판마다 다르고, 열지 않는 것도 선택이다).

```bash
sudo firewall-cmd --permanent --add-port=7374/tcp && sudo firewall-cmd --reload
#   firewall-cmd 가 없으면: sudo iptables -I INPUT -p tcp --dport 7374 -j ACCEPT
curl -s -m 5 http://<서버 IP>:7374/healthz; echo        # ← 다른 장비에서. 자기 주소는 방화벽을 안 탄다
```

이 배치에는 프록시가 없다 — 토큰이 사내망을 평문으로 흐르고, `--bind` 한 IP 가 경계다. TLS 가 필요하면 앞에 프록시를 둔다(4장).

## 3. git 자격을 손으로

설치 한 줄의 `--pat-stdin` · `--ssh` 와 콘솔 **서버 › git 자격**이 대신하는 일이다. 그 길이 막혔을 때만.

**PAT 발급** — GitLab › Preferences › Access Tokens. 스코프 `write_repository`(12.9 미만 GitLab 은 `api` 뿐 — 계정 전체를 연다 · `doctor` 가 계속 warn),
만료 **1년**(비워 두지 않는다). 값은 그 화면에서 한 번만 보인다. 계정은 그 프로젝트에 push 할 수 있어야 한다(Developer 이상 · 보호 브랜치면 그 브랜치에도).

```bash
cdp serve git-auth --host <GitLab[:포트]> --user <계정> --test http://<GitLab>/<그룹>/<프로젝트>.git   # 숨김 입력 · .git-credentials(600)
sudo -u cdp -H git ls-remote http://<GitLab>/<그룹>/<프로젝트>.git HEAD                                  # 해시 한 줄이면 읽기 됨
```

다른 `credential.helper` 가 걸려 있으면 멈춘다(바꾸려면 `--yes`). 쓰기 확인은 `cdp serve doctor` 의 `레포 … push 자격 있음` 줄이다 — 읽기만 되는
상태로 넘어가면 `save` 는 되는데 미러만 조용히 밀린다.

| 메시지 | 고칠 곳 |
|---|---|
| `HTTP Basic: Access denied` | 계정 이름 · 토큰이 틀렸다 · 만료 · 폐기 |
| `You are not allowed to upload code` | 스코프에 쓰기가 없다 |
| `protected branches` | 그 브랜치에 push 권한이 없다 |
| `could not be found` | 경로 오타 · 역할이 Developer 미만 |
| 패스워드를 묻는다 | `.git-credentials` 를 못 읽었다 — `sudo -u cdp -H`(HOME) 를 빠뜨렸다 |

**SSH 배포 키를 셸에서** — `cdp serve git-auth --ssh`(새로 만들기 `--rotate` · 옛 키는 `.old-<시각>`)가 공개 키를 찍는다 → GitLab 프로젝트 ›
Deploy keys 에 **쓰기 권한**으로(프로젝트마다) → 콘솔 **서버 › git 자격** 「호스트 키 받기」 · 지문 확인 · 「접속 확인」 → 레포의 「origin 연결」.
GitLab 의 SSH 가 서버에서 닿지 않으면(`No route to host` · 22 번이 OS sshd) PAT 로 간다.

## 4. 손으로 띄우기 · 설정

**설정은 `<prefix>/serve.json` 한 장**이다 — 유닛(`serve --config`)과 `cdp` 명령이 같이 읽는다. 명령줄 플래그가 이긴다.

```json
{ "root": "/opt/cdp/repos", "auth": "/opt/cdp/auth.json", "data": "/opt/cdp/data", "web": "/opt/cdp/web",
  "manual": "/opt/cdp/manual", "mirror": true, "bind": "<서버 IP>", "port": 7374 }
```

| 더할 수 있는 칸 | |
|---|---|
| `adminFrom` | 관리 API 를 사내 대역으로 좁힌다 — `"10.0.0.0/8"` |
| `publicUrl` | 화면 · 설치 한 줄에 찍을 주소(프록시 뒤일 때) |
| `forms` · `kit` | 번들 옆이 아닌 자리 |

소개 · 설명서까지 로그인 뒤에만 보이게 하려면 유닛 `ExecStart` 끝에 `--private-pages`. 고친 뒤 `sudo systemctl daemon-reload && sudo systemctl restart cdp-serve`.

**systemd 가 없으면 · root 가 없으면** — `install.sh` 가 유닛 대신 띄우는 한 줄을 찍는다. 그 OS 의 서비스(또는 `tmux`)에 건다.

```bash
node <prefix>/bin/ctx.mjs serve --config <prefix>/serve.json
```

**TLS** — `install.sh` 는 하지 않는다. 같은 장비에 Caddy 를 두면 한 줄이다 — `cdp.example.com { reverse_proxy 127.0.0.1:7374 }`(그때 `--bind 127.0.0.1` · `publicUrl`).

**첫 관리자를 나중에** — 설치 때 `--admin` 을 뺐으면 브라우저 `/setup` 에 부트스트랩 코드(`data/bootstrap.code` · 잃었으면
`sudo journalctl -u cdp-serve | grep setup`). 브라우저가 닿지 않으면 `cdp serve init --name <아이디> --label "<이름 · 소속>"`. 명부가 이미 있으면 둘 다 거절한다.

## 5. 막혔을 때

| 증상 | 고칠 곳 |
|---|---|
| `node 가 없다` · `20 이상이어야 한다` · `git 이 없다` | 0장 |
| `--bind <이 서버 IP> 가 필요하다` | 프록시 없는 배치의 경계라 기본값이 없다 |
| `root 가 아니면 --prefix 를 쓸 수 있는 자리로` | `sudo` 로 · 또는 `--prefix ~/cdp-server` |
| `bin/ctx.mjs 가 없다 — 서버 산출물 폴더 안에서` | `cdp-server-v<판>/` 안에서 `deploy/install.sh` 를 부른다 |
| `/healthz 가 10초 안에 답하지 않았다` | `journalctl -u cdp-serve -n 50` — 포트가 겹친다 · `serve.json` 이 JSON 이 아니다 · bind IP 가 이 장비 것이 아니다 |
| `status=203/EXEC` | 유닛의 node 경로가 없다(node 를 옮겼다) — `install.sh` 를 다시 |
| `거부: --bind … 인증 없이 밖으로 열 수 없다` | `serve.json` 에 `auth` 가 빠졌다 |
| `⚠ push 가 안 됐다` | 자격(3장) · origin 이 빈 프로젝트인가 — 고친 뒤 콘솔 「origin 연결」 |
| `PAT 를 두지 못했다` | 다른 `credential.helper` — `cdp serve git-auth … --yes` |
| 서버에서는 되는데 밖에서 안 된다 | 2장 |
| `repos: 0` · 레포가 안 보인다 | `<root>/<이름>/_vocab.md` 가 있는 git 폴더인가 · 전체 목록은 1분 주기 |
| `doctor` warn `git 자격 · 평문 PAT` | PAT 를 쓰는 한 계속 난다 — SSH 가 닿으면 배포 키로 좁힌다 |
| Docker 에서 새 판을 올렸더니 명부가 없다 | 옛 판은 `auth.json` 이 산출물 폴더에 있었다 — 옛 폴더의 것을 data 볼륨의 `/opt/cdp/data/auth.json` 으로 옮긴다 · `-p cdp` 를 늘 같게 |

## 6. 되돌리기

```bash
sudo systemctl disable --now cdp-serve
sudo rm /etc/systemd/system/cdp-serve.service /usr/local/bin/cdp && sudo systemctl daemon-reload
sudo rm -rf /opt/cdp && sudo userdel cdp          # 데이터를 지울 때만
```

GitLab 의 배포 키 · PAT 도 뗀다. **지식 레포는 origin 에 그대로 있다** — 미러로 보낸 커밋이 백업이다.

## 부록 B. v1.0 이전 서버에서 올리기

`upgrade.sh` 로 올린 뒤(관리자 설명서 8장) 둘이 더 있다.

**관리자 승격 — v0.9 이하 명부.** 역할이 없어 관리자가 0명이다(콘솔이 잠기고 `doctor` 가 「관리자 · 없다」). `/setup` 은 빈 명부에만 있으므로 셸로 —
`cdp serve user set <아이디> --role admin`. 옛 토큰은 90일짜리라 콘솔 **사람**에서 내 토큰을 재발급한다.

**레포 정리 — v0.x 레포.** `doctor` 의 「레포 … 도구 층」 warn 이 그 레포다(`bin/` · `.githooks` · `.claude` · `CLAUDE.md` · `MANUAL*` · `INDEX*`). 레포마다 하나를 고른다.

| 길 | 언제 | 하는 것 |
|---|---|---|
| **제자리 이행** | 관리 문서를 그대로 쓴다 | **서버를 멈추고** `cdp migrate /opt/cdp/repos/<레포> --dry` 로 보고 `--by <아이디>` 로 한 번 → 시작. 커밋 셋(전환 기록 · 서식 예시 정리 · 도구 층 걷기) — 섹션이 뒤처져 있던 좌표의 기록만 대기열에 남는다 |
| **다시 세우기** | 관리 문서가 엉망이다 | ① 옛 레포의 큐레이터가 근거 없는 섹션 스냅샷을 뜬다(`ctx rebuild snapshot` — 안 뜨면 정본에만 있던 지식이 사라진다) ② 서버를 멈추고 `mv repos/<레포> repos/<레포>_old` · GitLab 도 옛 프로젝트 이름을 바꾸고 빈 프로젝트를 새로 ③ 콘솔 **[새 레포]** 같은 이름 · 「기록만 옮겨 오기」 = `<레포>_old` · origin = 새 빈 프로젝트(셸 — `cdp repo new <레포> --records-from /opt/cdp/repos/<레포>_old --origin <url>`) |

그 뒤 — 레포마다 큐레이터를 맡기고(관리자 설명서 4장), 작업 레포마다 설치 한 줄 `--update`(옛 스킬이 걷히고 새 kit 이 들어간다), `/opt/cdp/packages` 는 확인 뒤 지운다.
`ctx serve kit-refresh` 같은 옛 명령이 운영 스크립트에 남아 있으면 지운다 — 부르면 무엇으로 바뀌었는지 말하고 exit 2.
