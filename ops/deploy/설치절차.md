> 다음으로 가지 않는다. 9장에 되돌리는 법이 있다.

> 콘솔에서(셸로도 된다 — `ctx repo new` · `git clone` · `ctx serve init`). 나머지는
> `doctor` 가 확인하고 `upgrade.sh` 가 갱신한다. 3장(git 자격)만 그대로 사람의
> 절차다 — PAT 를 발급받는 것은 스크립트도 화면도 대신할 수 없다.

## 0. 시작 전에 — 준비물

없는 것이 있으면 **여기서 멈추고** 구한 뒤 시작한다.

- [ ] `<서버 IP>` 에 SSH 접근 · `sudo` 권한
- [ ] 그 서버에 **Node 20 이상** · **git** — 없으면 아래 「없으면」. `install.sh` 가 첫 줄에서 확인하고 없으면 멈춘다
- [ ] 그 서버가 `<GitLab>:2900` 에 닿는다
- [ ] `<관리자>` 계정이 `<그룹>/cdp` 에 **push 할 수 있다** (Developer 이상 · 보호 브랜치라면 그 브랜치에도). 토큰은 3장에서 발급한다
- [ ] 명부에 올릴 **사람 이름과 권한** — 누가 어느 레포를 보고, **누가 `writer` 인가**(`save` 가 커밋을 만든다 · §4.5) · 누가 `admin` 인가
- [ ] 서버 산출물 **`cdp-server-v<버전>.tar.gz`** 한 개 (1장)

```bash
node --version                                   # v20 이상
command -v node                                  # install.sh 가 이 경로를 유닛에 박는다
git --version
curl -s -o /dev/null -w '%{http_code}\n' http://<GitLab>/   # 302 면 닿는다
```

### git 이 없으면

```bash
sudo apt-get install -y git        # Debian · Ubuntu
sudo dnf install -y git            # RHEL · Rocky · CentOS
```

### Node 가 없으면 — 셋 중 하나

```bash
# (가) 저장소 — 인터넷이 되는 Debian · Ubuntu
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash - && sudo apt-get install -y nodejs
# (가') RHEL · Rocky · CentOS
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash - && sudo dnf install -y nodejs
# (나) 공식 tarball — 인터넷이 막혔을 때. 개발 PC 에서 받아 scp 로 넘긴다
sudo mkdir -p /usr/local/lib/nodejs
sudo tar -xJf /tmp/node-v20.*-linux-x64.tar.xz -C /usr/local/lib/nodejs
sudo ln -sf /usr/local/lib/nodejs/node-v20.*-linux-x64/bin/node /usr/local/bin/node
```

`npm` 은 필요 없다 — 서버는 `ctx.mjs` 한 파일만 돌린다. **`nvm` 은 쓰지 않는다** —
사용자 셸에만 붙는 도구라 `cdp` 서비스 계정에서 보이지 않는다. `install.sh` 가
`command -v node` 로 찾은 경로를 유닛에 박으므로 **어디에 깔았든 그 경로가 맞는다**
(전에는 `/usr/bin/node` 로 박혀 있어 tarball 설치에서 `203/EXEC` 로 죽었다).

## 1. 산출물 (개발 PC 또는 GitHub Release)

**하나다.** 전에는 `ctx.mjs` 와 `web/` 을 따로 꺼내 scp 했고, `scp -r` 중첩으로 옛
화면이 그대로 깔리는 사고가 있었다. 지금은 tar.gz 한 개다.

```bash
# 개발 PC
cd C:\project\CDP
npm run release:server -- 0.10.0         # → ops/out/server/cdp-server-v0.10.0.tar.gz
# 또는 GitHub Release 의 cdp-server-v0.10.0.tar.gz + SHA256SUMS
```

```bash
scp ops/out/server/cdp-server-v0.10.0.tar.gz <SSH계정>@<서버 IP>:/tmp/
```

**확인** (서버)

```bash
cd /tmp && tar -xzf cdp-server-v0.10.0.tar.gz && cd cdp-server-v0.10.0
node bin/ctx.mjs version
#   2026-09-22 …
```

## 2. 설치 — `install.sh`

```bash
cd /tmp/cdp-server-v0.10.0
sudo bash deploy/install.sh --bind <서버 IP>
```

하는 일 — 계정 `cdp` · `/opt/cdp/{bin,repos,data,web,forms,kit,manual}` · 파일 배치 ·
**node 경로 · bind · port 를 박은 유닛** · `systemctl enable --now` · `/healthz` 확인 ·
방화벽 명령 안내. **두 번 돌려도 같다** — 있는 것은 건너뛰고 그 사실을 찍는다.
`--dry` 로 무엇을 할지 먼저 볼 수 있다.

**확인** — 스크립트 끝에 `healthz {"ok":true,…,"repos":0,…}` 한 줄이 찍힌다. `repos:0`
이 맞다 — 레포는 4장에서 둔다.

### 포트를 연다 — 이것을 빼면 서버에서만 보인다

`install.sh` 가 명령을 **안내만** 한다 — 배포판마다 다르고 열지 않는 것도 선택이다.

```bash
sudo firewall-cmd --permanent --add-port=7374/tcp && sudo firewall-cmd --reload
# firewall-cmd 가 없으면
sudo iptables -I INPUT -p tcp --dport 7374 -j ACCEPT && sudo service iptables save
```

**확인은 다른 장비에서 한다.** 자기 주소로 가는 패킷은 loopback 으로 빠져 방화벽을 안 탄다.

```bash
curl -s -m 5 http://<서버 IP>:7374/healthz; echo     # 개발 PC 에서
```

## 3. git 자격 — PAT (HTTP) · **사람의 절차**

**서버가 origin 으로 push 할 자격이다.** 커밋의 `author` 와는 다른 것 — `author` 는
CDP 토큰의 사용자로 서버가 채우므로(§4.5) 누가 정했는지는 사람별로 남는다.

> **왜 SSH 가 아니라 HTTP 인가.** 이 GitLab 의 SSH 는 `<서버 IP>` 에서 **닿지
> 않는다**(`No route to host`). 22 번은 그 장비의 OS sshd 라 Deploy Key 를 무시하고
> 패스워드를 묻는다. 열려 있는 길은 `2900` 하나다. 그리고 이 GitLab 은 12.9 미만이라
> PAT 에 `write_repository` 가 없다 — push 가 되는 스코프는 `api` 하나다. **계정
> 전체를 연다.** 감수하는 대신 아래 ②에서 좁힌다. `doctor` 가 이것을 **warn** 으로
> 계속 말한다 — 250 의 SSH 포트가 열리면 Deploy Key 로 되돌린다(10장).

### ① 토큰 발급 — `<관리자>` 계정

```
http://<GitLab>/-/profile/personal_access_tokens
  Name     cdp-server (<서버 IP>)
  Expires  1년 뒤            ← 비워 두지 않는다
  Scopes   ☑ api            ← 이것 하나만
```

`glpat-` 값은 **그 화면에서 한 번만** 보인다. 닫기 전에 ②를 끝낸다.

### ② 서버에 넣는다 — 토큰이 아무 데도 남지 않게

```bash
read -rsp 'PAT: ' PAT; echo
sudo -u cdp -H git config --global credential.helper 'store --file=/opt/cdp/.git-credentials'
printf 'http://<관리자>:%s@<GitLab>:2900\n' "$PAT" | sudo -u cdp -H sh -c 'umask 077; cat > /opt/cdp/.git-credentials'
unset PAT
sudo ls -l /opt/cdp/.git-credentials        # -rw------- cdp cdp
```

### ③ 커밋에 쓰일 이름 (폴백)

```bash
sudo -u cdp -H git config --global user.name  "cdp-server"
sudo -u cdp -H git config --global user.email "cdp-server@sjinc.co.kr"
```

**확인 — 읽기**

```bash
sudo -u cdp -H git ls-remote http://<GitLab>/<그룹>/<레포>.git HEAD    # 해시 한 줄
```

| 결과 | 뜻 |
|---|---|
| 해시 한 줄 | 4장으로 |
| `HTTP Basic: Access denied` | 사용자명이 `<관리자>` 가 아니거나 토큰이 틀렸다 — ②를 다시 |
| `could not be found` | 경로 오타이거나 권한이 없다 |
| 패스워드를 묻는다 | `.git-credentials` 를 못 읽었다 — `-H` 를 빼먹었거나 경로가 다르다 |

**쓰기는 4장의 `doctor` 가 본다** — `push --dry-run`. 읽기만 되는 상태로 넘어가면
`save` 는 성공하는데 미러만 조용히 밀린다.

## 4. 레포 — 두 길

**폴더명이 곧 레포 이름이다**(§4.2). 등록 = 폴더를 두는 것. 길이 둘이다.

```bash
CTX="sudo -u cdp node /opt/cdp/bin/ctx.mjs"
```

### (가) 이미 있는 지식 레포 — clone

```bash
sudo -u cdp -H git clone http://<GitLab>/<그룹>/<레포>.git /opt/cdp/repos/<레포>
```

폴더 이름이 레포 이름이다 — 개발 PC 의 폴더 이름과 달라도 정상이다. v0.x 에서 쓰던 레포(도구 층 · 훅이 든 것)면
`doctor` 가 「도구 층」 을 알린다 — 10장 「v1.0 으로 올릴 때」.

### (나) 새로 — 빈 틀 (콘솔 「새 지식 레포」 · `ctx repo new`)

빈 GitLab 프로젝트를 **웹에서 먼저 만든다**(서버가 만들 수는 없다). 그 주소를 준다.

```bash
$CTX repo new /opt/cdp/repos/<이름> --origin http://<GitLab>/<그룹>/<프로젝트>.git --push
```

빈 틀(README · `_vocab.md` · `_managed.md` · `docs/` · `work/` · `.gitattributes` · `.gitignore`)을 쓰고 · `git init` ·
첫 커밋 · `remote add` · `push -u`. 훅 · 도구 층은 없다 — 레포에는 지식만 둔다. 서식은 큐레이터가 문서를 세울 때
서식집(`forms/`)에서 고르고, 작업 레포의 스킬은 서버의 `kit/` 에서 나간다. 옛 레포의 작업 기록만 옮겨 다시 세우려면
`--records-from /opt/cdp/repos/<옛 레포>`. `--dry` 로 먼저 볼 수 있다. 콘솔 › 지식 레포 › [새 지식 레포] 가 같은 함수다.

> **서버는 새 폴더를 그 이름으로 가는 첫 요청에서 바로 알아본다** — 꾸러미 · 작업 레포
> 등록 · MCP · 화면 어느 것이든(모르는 이름이 오면 폴더를 다시 훑는다 · 2초에 한 번).
> 전체 목록(`/repos`)만 1분 주기이고, 비어 있으면 바로 다시 훑는다. 재시작은 필요 없다.
> `doctor` 의 「서버 … 레포 N」 이 폴더 수보다 작으면 아직 그 레포로 간 요청이 없었다는 뜻이다.

**확인 — `doctor`**

```bash
$CTX serve doctor --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data \
     --web /opt/cdp/web --bind <서버 IP> --port 7374
```

```
 ok    node             v20.x
 ok    git              git version 2.x
 warn  auth.json        /opt/cdp/auth.json 가 아직 없다 — 브라우저 /setup 또는 ctx serve init 으로 만든다   ← 5장에서 사라진다
 ok    --data           /opt/cdp/data
 ok    --web            /opt/cdp/web
 ok    kit              /opt/cdp/kit (번들 옆)
 ok    forms            /opt/cdp/forms (번들 옆)
 ok    레포 <레포>         head abc1234 · origin/main · push 자격 있음                     ← 이 줄이 3장의 쓰기 확인이다
 warn  git 자격         평문 PAT 가 있다 — 스코프가 api 면 계정 전체를 연다 …
 ok    서버             <서버 IP>:7374 응답 · built … · 레포 1
doctor: fail 0 · warn 2 · ok 8
```

`레포 <레포> push` 가 **fail** 이면 —

| 메시지 | 고칠 곳 |
|---|---|
| `You are not allowed to upload code` | 토큰 스코프에 `api` 가 없다 (3장 ①) |
| `HTTP Basic: Access denied` | 토큰이 만료 · 폐기됐다 (3장 ①) |
| `protected branches` | 보호 브랜치다 — `<관리자>` 가 그 브랜치에 push 할 수 있어야 한다 |
| `could not be found` | `<관리자>` 의 역할이 Developer 미만이다 |

> 서버 트리에서 **사람이 커밋하지 않는다.** 서버가 유일한 작성자다(§4.2).

## 5. 첫 관리자와 명부 — `/setup` 마법사, 그다음은 콘솔

**권한은 사람에게 붙고, 토큰은 신원만 증명한다**(§4.4). 발급은 **관리자**가 한다 — 콘솔 또는 서버 셸.
사용자가 화면에서 "토큰 주세요" 를 누를 자리는 없다(§4.4.1 정정).

### ① 첫 관리자 — 브라우저 `/setup` (명부가 없을 때 한 번)

`install.sh` 가 끝에 찍은 두 줄을 쓴다 —

```
[install] 첫 관리자: http://<서버 IP>:7374/setup 에 이 코드를 넣는다: m_…
```

브라우저로 그 주소 → 코드 → 내 아이디(`<관리자>`) · 라벨(`사경진 · 개발`) → **토큰 원문이 한 번** 보인다 — `CDP_TOKEN`
에 넣는다. 그 브라우저는 이미 로그인됐고 [콘솔로] 가 열린다. 코드는 `/opt/cdp/data/bootstrap.code` 에 있고 쓰면
지워진다 — 잃었으면 `sudo journalctl -u cdp-serve | grep 코드`.

셸로도 된다(브라우저로 서버에 닿지 못할 때) —

```bash
$CTX serve init --auth /opt/cdp/auth.json --data /opt/cdp/data --name <관리자> --label "사경진 · 개발"
```

첫 사용자는 `admin` · 레포 전체. **원문은 이때 한 번만 나온다.** 명부가 이미 있으면 둘 다 거절한다(덮지 않는다).

### ② 나머지 — 콘솔 > 사용자 > [+ 사용자] → [발급]

`http://<서버 IP>:7374/console` → **사용자** > [+ 사용자] — 아이디 · 라벨 · 역할 · 볼 수 있는 레포(<레포>).
저장하면 그 행의 [발급] → 사용자 · 메모("노트북") · 만료 → **원문 한 번** → [복사] → 본인에게 직접. 명부를 바꾸는
첫 동작에서 **관리자 확인**(내 토큰을 한 번 더 · 15분)을 묻는다.

| 칸 | 뜻 |
|---|---|
| 이름 | **영문·숫자·`.`·`_`·`-`** 만. 커밋의 `author` 로 남는다 — 사내 아이디를 쓴다 |
| 볼 수 있는 레포 | 체크. `*` 는 전부 — 역할처럼 사람에게 붙는다 |
| 역할 | `viewer` 기본. **`writer` 는 `save` 로 커밋을 만들고 레포를 세우고 작업 레포를 등록한다.** `admin` 은 콘솔 |
| 만료 | 기본은 역할이 정한다 — 관리자 30일 · 나머지 90일 |

**`writer` 를 기본으로 주지 않는다.** 정리를 맡은 사람에게만. 필요해지면 그 행의 [역할].

셸로 같은 것 —

```bash
A=/opt/cdp/auth.json; D=/opt/cdp/data
$CTX serve user add --auth $A --data $D --name <이름> --label "<소속 · 역할>" --repos <레포> [--role writer]
$CTX serve token    --auth $A --data $D --user <이름> --note "노트북"
```

**확인**

```bash
$CTX serve user list  --auth $A --data $D
$CTX serve token list --auth $A --data $D
sudo ls -l $A                                   # -rw------- cdp cdp
sudo ls /opt/cdp/data/bootstrap.code            # 없어야 한다 — 마법사가 지웠다
```

### 나중에

콘솔 > 사용자의 [역할] · [레포] · [비활성], 콘솔 > 토큰의 [재발급] · [연장] · [메모] · [폐기]. 셸로는 —

```bash
$CTX serve user set   --auth $A --data $D --name <이름> --role writer | --repos <레포>,foo | --inactive
$CTX serve token revoke --auth $A --data $D --name <이름> [--id 1a2b3c4d]
$CTX serve token reissue --auth $A --data $D --id 1a2b3c4d
```

**서버 재시작이 필요 없다.** 명부는 바뀌면 다음 요청부터 먹는다 — 열려 있던 화면도. 전부 `auth.log` 에 남고
콘솔 > 감사가 그 파일이다.


### 갱신 — `upgrade.sh`

```bash
# 개발 PC — 산출물 (1장과 같다)
npm run release:server -- 0.10.0
scp ops/out/server/cdp-server-v0.10.0.tar.gz <SSH계정>@<서버 IP>:/tmp/

# 서버
ssh <SSH계정>@<서버 IP>
cd /tmp && tar -xzf cdp-server-v0.10.0.tar.gz && node cdp-server-v0.10.0/bin/ctx.mjs version   # 날짜 · mcp: http
sudo bash /opt/cdp/deploy/upgrade.sh /tmp/cdp-server-v0.10.0.tar.gz
```

하는 일 — 푼다 · `.bak` 을 챙긴다(`bin/ctx.mjs.bak` · `web.bak` · `forms.bak` · `kit.bak` · `manual.bak` — 한 세대) · `ctx.mjs`
교체 · `web/` · `forms/` · `kit/` · `manual/` 은 **비우고** 넣는다 · 재시작 · **`/healthz.built` 가 새 번들 시각인지 · `index.html` 의
자산 해시가 tar 의 것과 같은지** 대조 · 다르면 `.bak` 으로 되돌리고 exit 1. 명부 · 대장 · 레포 · git 자격 · 유닛은 건드리지 않는다 —
레포에는 지식만 있고, 작업 레포의 스킬은 `kit/` 에서 나간다. 스킬이 바뀌었으면 관리 › 작업 레포에 `낡음` 이 뜬다 — 각자 설치 한 줄
`--update`(큐레이터는 `--curator`). 브라우저는 강제 새로고침(`Ctrl+Shift+R`).

> **`systemctl restart` 로 끊기는 것은 그 순간의 요청뿐이다.** 세션이 서버에
> 없어서(§4.4) 로그인 상태는 재시작을 넘어 그대로 살아 있다.

**확인**

```bash
CTX="sudo -u cdp node /opt/cdp/bin/ctx.mjs"
$CTX serve doctor --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data --web /opt/cdp/web --bind <서버 IP> --port 7374
curl -s http://<서버 IP>:7374/healthz; echo
```

브라우저 `http://<서버 IP>:7374/` — 소개 페이지 바닥의 판이 새 판 · [설명서] 에 세 권 · 콘솔 > 서버 > 진단 fail 0.
되돌리기 — `.bak` 을 제자리로 옮기고 `sudo systemctl restart cdp-serve`.

### 갱신 — v0.x → v1.0 은 레포 정리가 하나 더 있다

v1.0 은 쓰는 길을 서버 `save` 하나로 줄이고(모드 A 끝) · 관리 문서는 큐레이터가 반영하고 · 레포에는 지식만 둔다. `upgrade.sh`
뒤에 —

| 순서 | 하는 것 |
|---|---|
| 1 | `doctor` — 「레포 … 도구 층」 warn 이 v0.x 의 레포다(`bin/` · `.githooks` · `.claude` · `CLAUDE.md` · `MANUAL*.md` · `INDEX*.md`) |
| 2 | 레포마다 길을 고른다. **제자리 이행** — 서버를 멈추고 `sudo systemctl stop cdp-serve && $CTX migrate /opt/cdp/repos/<레포> --dry` 로 보고 `--dry` 를 빼고 한 번 → `start`. 전환 기록 하나(지금 섹션이 최신인 기록은 「반영됨」) · 서식 예시 · 도구 층 걷기가 커밋 셋으로 남는다. **다시 세우기** — 관리 문서가 엉망이면 옛 레포 이름을 바꿔 두고(`mv /opt/cdp/repos/<레포> /opt/cdp/repos/<레포>_old`) 콘솔 「새 지식 레포」 에서 같은 이름 · 「기록만 옮겨 오기」 = `<레포>_old` · 콘솔 「origin 연결」. 옮긴 기록은 전부 큐레이션 대기열에 선다 |
| 3 | 콘솔 › 사용자 › 「레포 × 큐레이터」 — 레포마다 큐레이터를 맡긴다(admin 은 어디서나 큐레이터) |
| 4 | 작업 레포마다 설치 한 줄 `--update` · 큐레이터는 자기 폴더에서 `--curator` |
| 5 | `/opt/cdp/packages` 는 쓰지 않는다 — 확인 뒤 지운다 |

### 갱신 — v0.9.0 → v0.10.0 은 관리자 승격이 하나 더 있다

v0.10.0 이 콘솔을 들였다(관리자 설명서 6장 · 9.1.1). v0.9.0 명부(v1.1)에는 역할이 없어 올린 직후 **관리자가 0명**이다 —
콘솔은 「관리자 권한이 필요합니다」 로 잠겨 있고 `doctor` 가 「관리자 · 없다 — ctx serve user set …」 을 낸다. 부트스트랩 코드와 `/setup` 마법사는
명부가 **빈** 서버에만 있으므로 여기서는 셸이다.

```bash
A=/opt/cdp/auth.json; D=/opt/cdp/data
$CTX serve user set  --auth $A --data $D --name <관리자> --role admin       # 한 번. auth.log 에 남는다
$CTX serve user list --auth $A --data $D                               # role 열에 admin · write 였던 사람은 writer
```

| 올린 뒤 | |
|---|---|
| 명부 | 파일은 손대지 않는다 — 읽을 때 `write: true` → `writer`, 콘솔의 첫 저장에서 `version: 1.2` |
| 관리자 토큰 | 옛 토큰은 90일짜리 — `doctor` 가 「관리자 토큰 … 30일 안으로 둔다」 를 낸다. 브라우저 `/console` > 토큰 > 내 행 [재발급] → `CDP_TOKEN` 교체 · Claude Code 재시작 |
| 둘째 관리자 | 콘솔 > 사용자 > [역할] — 마지막 관리자는 내릴 수 없다 |
| 화면 | `/` 가 소개 페이지다(전에는 `/r/<레포>/` 로 보냈다). 사람들의 `/r/<레포>/` 북마크 · 로그인 상태는 그대로. 사용자에게는 사용자 설명서 8.9 — 강제 새로고침 한 번 |
| 유닛 | 바꿀 것 없다 — `manual/` 은 `bin/` 옆에서 찾는다. 소개 · 설명서를 로그인 뒤에만, 콘솔 API 를 사내 대역으로만 두려면 `ExecStart` 끝에 `--private-pages` · `--admin-from <사내 대역>/24` 를 더하고 `sudo systemctl daemon-reload && sudo systemctl restart cdp-serve` |
| 확인 | `doctor` 에서 「관리자 · 없다」 · 「관리자 토큰」 warn 이 사라지고 「명부」 줄에 `admin 1` · 콘솔 > 감사에 `user set · <관리자> · {"role":"admin"}` 한 줄(셸이라 행위자는 `(셸)`) |

### 지식 레포 내용을 바깥에서 바꿨을 때 — **먼저 읽는다**

> **서버는 pull 하지 않는다.** 그 트리의 유일한 작성자라서다(§4.2). 바깥에서 origin 에
> push 하면 서버 트리가 뒤처지고, 다음 `save` 의 push 가 **non-fast-forward 로 거부**
> 된다. `mirror.lag` 가 안 풀리고 사람이 손으로 풀 때까지 그 레포의 모든 `save` 가
> origin 에 닿지 않는다.

```bash
# ① 서버가 origin 보다 앞서 있지 않은지 먼저 본다
sudo -u cdp -H git -C /opt/cdp/repos/<레포> fetch
sudo -u cdp -H git -C /opt/cdp/repos/<레포> status -sb | head -1
#   ## main...origin/main            ← 같다. ②로
#   ## main...origin/main [ahead 2]  ← 멈춘다. 아래 「앞서 있으면」

# ② 바깥에서 고치고 origin 에 올린다
# ③ 서버를 맞춘다 — ff 만 받는다
sudo -u cdp -H git -C /opt/cdp/repos/<레포> pull --ff-only
curl -s http://<서버 IP>:7374/healthz; echo    # mirror.ok 가 레포 수와 같아야 한다
```

스킬을 고쳤으면 **꾸러미도 새것이 된다** — 서버가 레포에서 그때그때 싼다. 관리 화면의
작업 레포 행이 `낡음` 으로 바뀌고, 각자는 `node install.mjs` 를 한 번 더 돌린다.

**앞서 있으면 (`ahead N`)** — 서버가 `save` 로 만든 커밋이 origin 에 못 갔다. 먼저 보낸다.

```bash
sudo -u cdp -H git -C /opt/cdp/repos/<레포> push
```

이것도 거부되면 origin 에 남의 커밋이 있다 — **서버 트리에서 사람이 합친다.** 자동으로
하지 않는다: 서버 트리의 커밋은 사람이 승인한 `save` 의 결과이고, 기계가 재작성하면
무엇이 승인된 것인지 흐려진다.
