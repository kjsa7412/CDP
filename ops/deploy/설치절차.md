## 0. 시작 전에 — 준비물

없는 것이 있으면 **여기서 멈추고** 구한 뒤 시작한다. 중간에 막히면 되돌리는
일이 더 크다.

- [ ] `10.10.20.188` 에 SSH 접근 · `sudo` 권한
- [ ] 그 서버에 **Node 20 이상** (`node --version`)
- [ ] 그 서버에 **git** (`git --version`) — 서버가 clone · commit · push 를 직접 한다
- [ ] 그 서버가 `10.10.20.250:2900` 에 닿는다
- [ ] `soln1/cdp` 프로젝트에 **Deploy Key 를 등록할 권한** (Maintainer 이상)
  - 키는 **3장에서 서버가 만든다.** 미리 준비할 것은 없고, 등록할 자리에
    들어갈 수 있는지만 본다 — 프로젝트 > `Settings` > `Repository` > `Deploy Keys`
  - 이 GitLab 은 **12.9 미만**이라 PAT 에 `write_repository` 스코프가 없다.
    남는 것은 `api` 뿐인데 그것은 **계정 전체**(모든 그룹·프로젝트 읽기·쓰기)를
    연다 — 서버 평문 파일에 두기엔 너무 넓다. **Deploy Key 는 그 레포에
    push 하는 것 하나만** 할 수 있고, SSH 라 평문 문제도 없다
- [ ] 명부에 올릴 **사람 이름과 권한** — 누가 어느 레포를 보고, **누가 `write` 인가**
      (`save` 가 커밋을 만든다 · §4.5)
- [ ] 개발 PC 에서 만든 **산출물 두 개** (1장)

### 준비물 확인 (서버에서)

```bash
node --version                                   # v20 이상
command -v node                                  # 경로 — 6장에서 쓴다
git --version                                    # 없으면 아래에서 깐다
curl -s -o /dev/null -w '%{http_code}\n' http://10.10.20.250:2900/   # 302 면 닿는다
nc -z -w3 10.10.20.250 22 && echo 'SSH 22 열림'      # push 가 이 길로 간다
```

`node --version` 이 없거나 v20 미만이면, 또는 `git` 이 없으면 아래로.
나머지가 다 되면 1장으로.

### git 이 없으면 — 설치

**서버가 git 을 직접 돌린다.** clone(4장)뿐 아니라 `save` 가 커밋하고
`--mirror` 가 push 한다(§4.5) — 없으면 읽기는 되고 쓰기가 전부 실패한다.

```bash
# Debian · Ubuntu
sudo apt-get install -y git

# RHEL · Rocky · CentOS
sudo dnf install -y git

git --version        # 2.x 면 충분하다
```

### Node 가 없으면 — 설치

**셋 중 하나.** 배포판과 인터넷 여부로 고른다.

#### (가) 패키지 저장소 — 인터넷이 되는 Debian · Ubuntu

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
```

#### (가') 패키지 저장소 — 인터넷이 되는 RHEL · Rocky · CentOS

```bash
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
sudo dnf install -y nodejs
```

#### (나) 공식 tarball — 인터넷이 막혔거나 저장소를 안 쓸 때

개발 PC 에서 받아 `scp` 로 넘긴다. **그냥 푸는 것이라 배포판을 안 탄다.**

```bash
# 개발 PC — https://nodejs.org/dist/latest-v20.x/ 에서 linux-x64 tar.xz
scp node-v20.*-linux-x64.tar.xz <SSH계정>@10.10.20.188:/tmp/

# 서버
sudo mkdir -p /usr/local/lib/nodejs
sudo tar -xJf /tmp/node-v20.*-linux-x64.tar.xz -C /usr/local/lib/nodejs
sudo ln -sf /usr/local/lib/nodejs/node-v20.*-linux-x64/bin/node /usr/local/bin/node
```

`npm` 은 필요 없다 — 서버는 `ctx.mjs` 한 파일만 돌린다(1장).

#### (다) 이미 있는데 낡았다

`node --version` 이 v18 이하면 **올려야 한다.** `ctx serve` 는 Node 20 을 요구한다
(§9). 위 (가)·(나) 로 덮으면 된다.

**확인 — 여기서 경로를 적어 둔다.**

```bash
node --version      # v20.x.x
command -v node     # 예: /usr/bin/node  ·  /usr/local/bin/node
```

> **이 경로가 6장의 systemd 유닛과 같아야 한다.** `cdp-serve.service` 는
> `/usr/bin/node` 로 적혀 있다 — (나) 로 깔면 `/usr/local/bin/node` 다.
> 다르면 서비스가 `203/EXEC` 로 죽는다. 6장에서 한 줄로 맞춘다.
>
> **`nvm` 은 쓰지 않는다.** 사용자 셸에만 붙는 도구라 `cdp` 서비스 계정에서는
> 안 보인다 — systemd 가 못 찾는다.

## 3. git 자격 — Deploy Key (SSH)

**서버가 origin 으로 push 할 자격이다.** 커밋의 `author` 와는 다른 것 — `author`
는 CDP 토큰의 사용자로 서버가 채우므로(§4.5) 누가 정했는지는 사람별로 그대로
남는다. 여기서 정하는 것은 **누가 보냈나** 뿐이다.

> **왜 Deploy Key 인가.** 이 GitLab 은 12.9 미만이라 PAT 에 `write_repository`
> 가 없고, push 가 되는 스코프는 `api` 하나뿐이다 — 그것은 계정 전체를 연다.
> Deploy Key 는 **그 레포에 push 하는 것 하나만** 할 수 있다. 사람 계정과도
> 무관해서 담당자가 바뀌어도 미러가 멈추지 않는다.

### ① 서버에서 키를 만든다

```bash
sudo -u cdp -H mkdir -p /opt/cdp/.ssh
sudo -u cdp -H chmod 700 /opt/cdp/.ssh
sudo -u cdp -H ssh-keygen -t ed25519 -N '' -C 'cdp-server@10.10.20.188'   -f /opt/cdp/.ssh/id_ed25519
```

`-H` 를 빼지 않는다 — `cdp` 의 홈(`/opt/cdp`)을 쓰게 하는 것이고, 안 주면
`root` 의 `~/.ssh` 에 만들어져 서비스가 못 찾는다.

### ② 공개키를 GitLab 에 등록한다

```bash
sudo cat /opt/cdp/.ssh/id_ed25519.pub
```

출력 한 줄(`ssh-ed25519 AAAA…`)을 통째로 복사해서 —

```
http://10.10.20.250:2900/soln1/cdp
  > Settings > Repository > Deploy Keys > Expand
  Title  cdp-server (10.10.20.188)
  Key    붙여넣기
  ☑ Write access allowed      ← **이 체크가 핵심이다**
  > Add key
```

체크를 빠뜨리면 clone 은 되고 push 만 막힌다. 4장에서 잡힌다.

### ③ 서버 키를 미리 받아 둔다

```bash
sudo -u cdp -H sh -c 'ssh-keyscan -H 10.10.20.250 >> /opt/cdp/.ssh/known_hosts'
sudo -u cdp -H chmod 600 /opt/cdp/.ssh/known_hosts
```

**이걸 안 하면 서비스가 멈춘다.** 사람이 `ssh` 를 처음 쓸 때 나오는
*"Are you sure you want to continue connecting?"* 를 systemd 밑에서는
답할 사람이 없어서, `push` 가 그 자리에서 영영 기다린다.

### ④ 커밋에 쓰일 이름 (표시용)

```bash
sudo -u cdp -H git config --global user.name  "cdp-server"
sudo -u cdp -H git config --global user.email "cdp-server@sjinc.co.kr"
```

**실제 커밋 `author` 는 이것이 아니다.** `save` 가 CDP 토큰의 사용자로
덮어쓴다(§4.5) — 이 값은 그것이 없을 때의 폴백일 뿐이다.

**확인 — 읽기. 여기서 반드시 한다.**

```bash
sudo -u cdp -H ssh -T git@10.10.20.250
#   Welcome to GitLab, @cdp-server!     ← 또는 deploy key 이름이 나온다
```

| 결과 | 뜻 |
|---|---|
| `Welcome to GitLab` | 키가 붙었다. 4장으로 |
| `Permission denied (publickey)` | ②의 등록이 안 됐거나 키 경로가 다르다 |
| `Host key verification failed` | ③을 빠뜨렸다 |
| 멈춘 채 안 끝난다 | SSH 22 가 막혔다 (0장) |

> **쓰기는 4장 끝에서 따로 본다.** `Write access allowed` 를 안 눌러도 여기까지는
> 통과한다. 그 상태로 넘어가면 서버는 정상으로 뜨고 `save` 도 성공하는데
> **미러만 조용히 밀린다.**
>
> SSH 라 자격이 사내망을 **평문으로 흐르지 않는다.** 0단계에서 감수하기로 했던
> HTTP 토큰 문제가 여기서 없어졌다.

## 4. 레포 받기

**폴더명이 곧 레포 이름이다**(§4.2). `cdp` 가 아니라 **`gdi`** 로 받는다 —
개발 PC 의 `C:\cdp` 와 이름이 달라도 정상이다.

```bash
sudo -u cdp -H git clone git@10.10.20.250:soln1/cdp.git /opt/cdp/repos/gdi
```

**확인**

```bash
sudo -u cdp -H ls /opt/cdp/repos/gdi/_vocab.md      # 이 파일이 있어야 레포로 인식된다
sudo -u cdp -H git -C /opt/cdp/repos/gdi log -1 --oneline

# **쓰기 권한을 여기서 확인한다.** 아무것도 보내지 않고 권한만 본다.
sudo -u cdp -H git -C /opt/cdp/repos/gdi push --dry-run origin HEAD
#   Everything up-to-date        ← 이것이면 쓰기까지 된다
```

`push --dry-run` 이 거부되면 —

| 메시지 | 고칠 곳 |
|---|---|
| `You are not allowed to upload code` | Deploy Key 에 **`Write access allowed`** 가 안 눌렸다 (3장 ②) |
| `You are not allowed to push code to protected branches` | 보호 브랜치다. Deploy Key 는 보호 브랜치를 못 넘는다 — 그 브랜치의 보호를 풀거나 `Allowed to push` 에 Deploy Key 를 넣는다 |
| `Permission denied (publickey)` | 3장 ②로 |

**여기서 안 잡으면** 뒤가 전부 정상으로 보인다. `/healthz` 의 `mirror.lag` 가
유일한 신호가 된다.

> **서버 트리에서 사람이 커밋하지 않는다.** 서버가 유일한 작성자다(§4.2).
> 사람은 origin 을 읽기 전용으로 clone 해서 본다.

## 5. 명부와 토큰

권한은 **사람에게** 붙는다. 토큰은 신원만 증명한다(§4.4).

```bash
CTX="sudo -u cdp node /opt/cdp/bin/ctx.mjs serve"
A=/opt/cdp/auth.json
D=/opt/cdp/data

# ① 사람을 먼저 올린다 — 여기 없는 이름으로는 토큰이 안 나간다
$CTX user add --auth $A --data $D --name kjsa --label "사경진 · 개발" --repos gdi --write
$CTX user add --auth $A --data $D --name <이름> --label "<설명>" --repos gdi          # 읽기만
# ... 2~5명

# ② 토큰 — 사람마다, 기계마다 하나
$CTX token --auth $A --data $D --user kjsa --note "노트북"
```

**토큰 원문은 이때 한 번만 나온다.** 다시 볼 수 없다.

```bash
sudo chmod 600 /opt/cdp/auth.json
$CTX user list --auth $A --data $D
```

**확인** — `user list` 에 사람이 다 있고 `write` 가 의도한 사람에게만 있다.

> **발급 엔드포인트는 없다**(§4.4.1). 여기 셸이 있는 사람만 발급할 수 있다.
> 원문은 **본인에게 직접** 전한다 — 메신저·메일·이슈에 남기지 않는다(§4.4.2).
> 기본 만료는 90일이다.

## 6. 서비스 등록

```bash
sudo cp <이 레포>/ops/deploy/cdp-serve.service /etc/systemd/system/

# **0장에서 적어 둔 node 경로와 맞춘다.** 유닛은 /usr/bin/node 로 되어 있다 —
# tarball 로 깔았으면 /usr/local/bin/node 다. 다르면 203/EXEC 로 죽는다.
sudo sed -i "s|^ExecStart=[^ ]*node|ExecStart=$(command -v node)|" /etc/systemd/system/cdp-serve.service
grep ExecStart /etc/systemd/system/cdp-serve.service

sudo systemctl daemon-reload
sudo systemctl enable --now cdp-serve
sudo systemctl status cdp-serve --no-pager
```

**확인**

```bash
curl -s http://10.10.20.188:7374/healthz
#   {"ok":true,"built":"2026-09-21 07:19","repos":1,"mirror":{"ok":1,"lag":0,"off":0}}

curl -s -H "Authorization: Bearer <토큰>" http://10.10.20.188:7374/repos
#   [{"name":"gdi","title":"…","head":"…","mirror":"ok"}]
```

- `repos:1` 이 아니면 4장으로 — 폴더에 `_vocab.md` 가 있는가.
- `mirror` 가 `off` 면 upstream 이 없는 것이고, `lag` 면 push 가 밀린 것이다(3장).
- `/healthz` 는 **인증 없이** 열린다. 레포 이름은 싣지 않는다 — 집계까지다(§4.3).

## 7. 화면 확인

브라우저로 `http://10.10.20.188:7374/` 를 연다.

1. 로그인 화면이 뜬다 — 입력이 **한 칸**이다(토큰이 아이디를 들고 있다)
2. 토큰을 넣으면 `/r/gdi/` 로 들어간다
3. 오른쪽 위에 **사용자 이름과 로그아웃**이 있다
4. 관리 > 메뉴가 **현황 · 동기화 · 작업 레포 · 진단** 이다
   (지식 레포 탭은 로컬 뷰어의 것이라 없다 · §6.6.3)

안 뜨면 `/opt/cdp/web/index.html` 이 있는지 본다(2장). 화면이 없어도
**MCP 와 읽기 API 는 돈다** — 서버가 죽지는 않는다.

## 8. 사람에게 붙이기

### 관리자가 — 작업 레포를 등록한다

화면에서 **관리 > 작업 레포 > 등록**. 이름 · 담당자(명부에서 고른다) · 메모.

### 각자가 — 꾸러미를 받아 푼다

등록한 행의 `[설치 방법]` 을 열면 4단계가 나온다.

1. `cdp-kit-<이름>.zip` 을 받아 **작업 레포 루트에 푼다**
   (`CLAUDE.md` 가 이미 있으면 `cdp:begin ~ cdp:end` 블록만 갈아 끼운다)
2. `setx CDP_TOKEN <관리자에게 받은 토큰>` (Windows) · `export` (macOS·Linux)
3. **Claude Code 를 다시 켠다** — 환경변수는 프로세스 시작 때 읽힌다
4. `git add .mcp.json .claude CLAUDE.md` 후 커밋

**확인** — Claude Code 의 `/mcp` 에 `cdp` 가 **connected** 이고 도구가 13건이다.

> 4번을 커밋하면 **팀원은 `git pull` 과 `CDP_TOKEN` 만으로 끝난다.** 꾸러미를
> 다시 받을 필요가 없다.
>
> `bin/ctx` 가 있는 사람은 1번 대신
> `ctx setup --server http://10.10.20.188:7374 --repo gdi --workrepo <id> <작업레포>` —
> 블록 병합과 대장 보고까지 한 번에 된다.

## 9. 막혔을 때 · 되돌리기

| 증상 | 볼 곳 |
|---|---|
| 서비스가 바로 죽는다 | `journalctl -u cdp-serve -n 50` · Node 버전 · `--auth` 경로 |
| `status=203/EXEC` | 유닛의 `ExecStart` 가 실제 node 경로와 다르다 (6장의 `sed` 줄) |
| `SyntaxError` 로 죽는다 | Node 가 v20 미만이다 (0장) |
| `거부: --bind … 인증 없이 밖으로 열 수 없다` | `--auth` 가 빠졌다. 루프백 밖은 인증 없이 못 연다(§8) |
| `Cannot find module '/opt/cdp/bin/ctx.mjs'` | 2장의 `sudo cp /tmp/ctx.mjs /opt/cdp/bin/` 을 빠뜨렸다. 복사하고 `chown` 을 다시 돌린다 |
| `Dynamic require of …` | 번들이 낡았다. 개발 PC 에서 `npm run build:ctx` 를 다시 (1장) |
| 읽기는 되는데 `save` 가 `E_GIT` · `mirror` 가 늘 `off` | 서버에 **git 이 없다.** `git --version` (0장) |
| `repos: 0` | `<root>/<name>/_vocab.md` 가 있는가 · 목록 갱신은 60초 주기 |
| `mirror: lag` 가 안 풀린다 | `sudo -u cdp -H git -C /opt/cdp/repos/gdi push` 를 손으로 돌려 본다. **`Write access allowed` 미체크가 가장 흔하다**(3장 ②) |
| `Host key verification failed` | 3장 ③의 `ssh-keyscan` 을 빠뜨렸다. 다시 돌린다 — 서비스 재시작은 필요 없다 |
| push 가 `Permission denied (publickey)` | GitLab 에서 Deploy Key 가 지워졌다. 3장 ②로 다시 등록한다 — 키는 서버에 그대로 있다 |
| 401 인데 토큰은 맞다 | 만료 · 명부에서 지워짐 · `active:false`. `serve user list` 로 본다 |
| 화면만 안 뜬다 | `/opt/cdp/web/index.html` · `--web` 경로 |

### 되돌리기

```bash
sudo systemctl disable --now cdp-serve
sudo rm /etc/systemd/system/cdp-serve.service
sudo systemctl daemon-reload
# 데이터를 지울 때만
sudo rm -rf /opt/cdp
sudo userdel cdp
```

GitLab 의 **Deploy Key 도 지운다** — `Settings > Repository > Deploy Keys`.

**지식 레포는 origin 에 그대로 있다.** 서버를 지워도 `--mirror` 로 보낸 커밋은
남는다 — 그것이 백업이기도 하다.
