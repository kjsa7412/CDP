(전에는 `/usr/bin/node` 로 박혀 있어 tarball 설치에서 `203/EXEC` 로 죽었다).

## 2. 설치 — `install.sh`

```bash
cd /tmp/cdp-server-v0.9.0
sudo bash deploy/install.sh --bind 10.10.20.188
```

하는 일 — 계정 `cdp` · `/opt/cdp/{bin,repos,data,web,packages}` · 파일 배치 ·
**node 경로 · bind · port 를 박은 유닛** · `systemctl enable --now` · `/healthz` 확인 ·
방화벽 명령 안내. **두 번 돌려도 같다** — 있는 것은 건너뛰고 그 사실을 찍는다.
`--dry` 로 무엇을 할지 먼저 볼 수 있다.

**확인** — 스크립트 끝에 `healthz {"ok":true,…,"repos":0,…}` 한 줄이 찍힌다. `repos:0`
이 맞다 — 레포는 4장에서 둔다.

### 포트를 연다 — 이것을 빼면 서버에서만 보인다

`install.sh` 가 명령을 **안내만** 한다 — 배포판마다 다르고 열지 않는 것도 선택이다.

```bash
sudo firewall-cmd --permanent --add-port=7374/tcp && sudo firewall-cmd --reload
# firewall-cmd 가 없으면
sudo iptables -I INPUT -p tcp --dport 7374 -j ACCEPT && sudo service iptables save
```

**확인은 다른 장비에서 한다.** 자기 주소로 가는 패킷은 loopback 으로 빠져 방화벽을 안 탄다.

```bash
curl -s -m 5 http://10.10.20.188:7374/healthz; echo     # 개발 PC 에서
```

## 3. git 자격 — PAT (HTTP) · **사람의 절차**

**서버가 origin 으로 push 할 자격이다.** 커밋의 `author` 와는 다른 것 — `author` 는
CDP 토큰의 사용자로 서버가 채우므로(§4.5) 누가 정했는지는 사람별로 남는다.

> **왜 SSH 가 아니라 HTTP 인가.** 이 GitLab 의 SSH 는 `10.10.20.188` 에서 **닿지
> 않는다**(`No route to host`). 22 번은 그 장비의 OS sshd 라 Deploy Key 를 무시하고
> 패스워드를 묻는다. 열려 있는 길은 `2900` 하나다. 그리고 이 GitLab 은 12.9 미만이라
> PAT 에 `write_repository` 가 없다 — push 가 되는 스코프는 `api` 하나다. **계정
> 전체를 연다.** 감수하는 대신 아래 ②에서 좁힌다. `doctor` 가 이것을 **warn** 으로
> 계속 말한다 — 250 의 SSH 포트가 열리면 Deploy Key 로 되돌린다(10장).

### ① 토큰 발급 — `kjsa` 계정

```
http://10.10.20.250:2900/-/profile/personal_access_tokens
  Name     cdp-server (10.10.20.188)
  Expires  1년 뒤            ← 비워 두지 않는다
  Scopes   ☑ api            ← 이것 하나만
```

`glpat-` 값은 **그 화면에서 한 번만** 보인다. 닫기 전에 ②를 끝낸다.

### ② 서버에 넣는다 — 토큰이 아무 데도 남지 않게

```bash
read -rsp 'PAT: ' PAT; echo
sudo -u cdp -H git config --global credential.helper 'store --file=/opt/cdp/.git-credentials'
printf 'http://kjsa:%s@10.10.20.250:2900\n' "$PAT" | sudo -u cdp -H sh -c 'umask 077; cat > /opt/cdp/.git-credentials'
unset PAT
sudo ls -l /opt/cdp/.git-credentials        # -rw------- cdp cdp
```

### ③ 커밋에 쓰일 이름 (폴백)

```bash
sudo -u cdp -H git config --global user.name  "cdp-server"
sudo -u cdp -H git config --global user.email "cdp-server@sjinc.co.kr"
```

**확인 — 읽기**

```bash
sudo -u cdp -H git ls-remote http://10.10.20.250:2900/soln1/cdp.git HEAD    # 해시 한 줄
```

| 결과 | 뜻 |
|---|---|
| 해시 한 줄 | 4장으로 |
| `HTTP Basic: Access denied` | 사용자명이 `kjsa` 가 아니거나 토큰이 틀렸다 — ②를 다시 |
| `could not be found` | 경로 오타이거나 권한이 없다 |
| 패스워드를 묻는다 | `.git-credentials` 를 못 읽었다 — `-H` 를 빼먹었거나 경로가 다르다 |

**쓰기는 4장의 `doctor` 가 본다** — `push --dry-run`. 읽기만 되는 상태로 넘어가면
`save` 는 성공하는데 미러만 조용히 밀린다.

## 4. 레포 — 두 길

**폴더명이 곧 레포 이름이다**(§4.2). 등록 = 폴더를 두는 것. 길이 둘이다.

```bash
CTX="sudo -u cdp node /opt/cdp/bin/ctx.mjs"
```

### (가) 이미 있는 지식 레포 — clone

```bash
sudo -u cdp -H git clone http://10.10.20.250:2900/soln1/cdp.git /opt/cdp/repos/gdi
```

`cdp` 가 아니라 **`gdi`** 로 받는다 — 개발 PC 의 `C:\cdp` 와 이름이 달라도 정상이다.

### (나) 패키지에서 새로 — `ctx repo new`

빈 GitLab 프로젝트를 **웹에서 먼저 만든다**(서버가 만들 수는 없다). 그 주소를 준다.

```bash
$CTX repo new /opt/cdp/repos/<이름> --package dpms --packages /opt/cdp/packages \
     --origin http://10.10.20.250:2900/<그룹>/<프로젝트>.git --push
```

패키지 폴더를 복사하고 · `git init` · `core.hooksPath` · **첫 커밋(훅이 `ctx check` 를
돈다)** · `remote add` · `push -u`. `--dry` 로 먼저 볼 수 있다. 관리 화면(7장)의
**지식 레포** 메뉴에서도 같은 것을 한다 — 같은 함수다.

> **서버는 `repos/` 를 요청이 올 때 1분에 한 번 다시 훑는다.** 셸에서 `repo new` 나
> `clone` 으로 둔 폴더는 늦어도 1분 안에 목록에 뜬다 — 바로 보려면
> `sudo systemctl restart cdp-serve`. 관리 화면에서 만든 것은 즉시 뜬다(만든 직후
> 다시 훑는다). `doctor` 의 「서버 … 레포 N」 이 폴더 수와 다르면 그 1분이다.

**확인 — `doctor`**

```bash
$CTX serve doctor --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data \
     --web /opt/cdp/web --packages /opt/cdp/packages --bind 10.10.20.188 --port 7374
```

```
 ok    node             v20.x
 ok    git              git version 2.x
 warn  auth.json        /opt/cdp/auth.json 가 아직 없다 — ctx serve init 으로 만든다   ← 5장에서 사라진다
 ok    --data           /opt/cdp/data
 ok    --web            /opt/cdp/web
 ok    packages         /opt/cdp/packages (--packages) · 1개
 ok    레포 gdi         head abc1234 · origin/main · push 자격 있음                     ← 이 줄이 3장의 쓰기 확인이다
 warn  git 자격         평문 PAT 가 있다 — 스코프가 api 면 계정 전체를 연다 …
 ok    서버             10.10.20.188:7374 응답 · built … · 레포 1
doctor: fail 0 · warn 2 · ok 7
```

`레포 gdi push` 가 **fail** 이면 —

| 메시지 | 고칠 곳 |
|---|---|
| `You are not allowed to upload code` | 토큰 스코프에 `api` 가 없다 (3장 ①) |
| `HTTP Basic: Access denied` | 토큰이 만료 · 폐기됐다 (3장 ①) |
| `protected branches` | 보호 브랜치다 — `kjsa` 가 그 브랜치에 push 할 수 있어야 한다 |
| `could not be found` | `kjsa` 의 역할이 Developer 미만이다 |

> 서버 트리에서 **사람이 커밋하지 않는다.** 서버가 유일한 작성자다(§4.2).

## 5. 명부와 토큰 — `init` 그리고 `user add`

**권한은 사람에게 붙고, 토큰은 신원만 증명한다**(§4.4). 발급은 서버 셸에서만 한다 —
화면에 "토큰 주세요" 자리가 없는 것이 의도다(§4.4.1).

### ① 첫 사용자 — `init` (명부가 없을 때 한 번)

```bash
$CTX serve init --auth /opt/cdp/auth.json --data /opt/cdp/data --name kjsa --label "사경진 · 개발" --repos '*' --write
```

`user add` + `token` 을 한 번에. **원문은 이때 한 번만 나온다** — 본인에게 직접 전한다.
명부가 이미 있으면 거절한다(덮지 않는다).

### ② 나머지 — `user add` → `token`

```bash
A=/opt/cdp/auth.json; D=/opt/cdp/data
$CTX serve user add --auth $A --data $D --name <이름> --label "<소속 · 역할>" --repos gdi
$CTX serve token    --auth $A --data $D --user <이름> --note "노트북"
```

| 옵션 | 뜻 |
|---|---|
| `--name` | **영문·숫자·`.`·`_`·`-`** 만. 커밋의 `author` 로 남는다 — 사내 아이디를 쓴다 |
| `--repos` | 볼 수 있는 레포. 쉼표로 여럿 · `*` 는 전부 |
| `--write` | **`save` 로 커밋을 만들 수 있다.** 레포를 세울 수도 있다(`POST /repos`). 빼면 읽기만 |

**`--write` 를 기본으로 주지 않는다.** 정리를 맡은 사람에게만. 필요해지면
`user set --name <이름> --write`.

**확인**

```bash
$CTX serve user list  --auth $A --data $D
$CTX serve token list --auth $A --data $D
sudo ls -l $A                                   # -rw------- cdp cdp
```

### 나중에

```bash
$CTX serve user set   --auth $A --data $D --name <이름> --write | --no-write | --repos gdi,foo | --inactive
$CTX serve token revoke --auth $A --data $D --name <이름> [--id 1a2b3c4d]
```

**서버 재시작이 필요 없다.** 명부는 바뀌면 다음 요청부터 먹는다 — 열려 있던 화면도.

## 8. 사람에게 붙이기

### 작업 레포를 등록한다 — 관문이 아니라 장부다

화면에서 **관리 > 작업 레포 > 등록**. 이름 · 담당자(명부에서) · 메모. **등록은 아무것도
막지 않는다** — 어느 작업 레포가 어느 판의 꾸러미를 들고 있나를 나중에 알 수 있게 하는
것뿐이다. 등록·삭제는 `write`, 조회·보고는 그 레포를 볼 수 있으면 된다.

### 각자가 — 꾸러미를 받아 푼다

등록한 행의 `[설치 방법]` 에서 `cdp-kit-<이름>.zip` 을 받는다.

```
1. zip 을 아무 데나 푼다 — kit/ 한 단 아래라 푸는 것만으로는 아무것도 안 덮인다
2. node install.mjs <작업 레포 경로>        무엇이 바뀔지 보여 주고 묻는다 (--dry · --yes)
3. setx CDP_TOKEN <관리자에게 받은 토큰>     (macOS·Linux 는 export)
4. Claude Code 를 다시 켠다
5. git add .mcp.json .claude CLAUDE.md 후 커밋   ← 팀원은 pull 과 CDP_TOKEN 만으로 끝난다
```

`bin/ctx` 를 가진 사람은 `ctx setup --server http://10.10.20.188:7374 --repo gdi --workrepo <id> <작업레포>` 도 된다 — 같은 함수다.

**확인** — Claude Code 의 `/mcp` 에 `cdp` 가 **connected** · 도구 13건. 관리 화면의 그 행이 `최신`.

| 증상 | 볼 곳 |

### 갱신 — `upgrade.sh`

```bash
scp ops/out/server/cdp-server-v0.9.1.tar.gz <SSH계정>@10.10.20.188:/tmp/
sudo bash /opt/cdp/deploy/upgrade.sh /tmp/cdp-server-v0.9.1.tar.gz
```

하는 일 — 푼다 · `.bak` 을 챙긴다 · `ctx.mjs` 교체 · `web/` 은 **비우고** 넣는다 ·
`packages/` 교체 · `systemctl restart` · **`/healthz.built` 가 새 번들 시각인지 · `index.html`
의 자산 해시가 tar 의 것과 같은지** 대조 · 다르면 `.bak` 으로 되돌리고 exit 1.
명부 · 대장 · 레포 · git 자격은 건드리지 않는다. 브라우저는 강제 새로고침(`Ctrl+Shift+R`).

> **`systemctl restart` 로 끊기는 것은 그 순간의 요청뿐이다.** 세션이 서버에
> 없어서(§4.4) 로그인 상태는 재시작을 넘어 그대로 살아 있다.

### 지식 레포 내용을 바깥에서 바꿨을 때 — **먼저 읽는다**

> **서버는 pull 하지 않는다.** 그 트리의 유일한 작성자라서다(§4.2). 바깥에서 origin 에
> push 하면 서버 트리가 뒤처지고, 다음 `save` 의 push 가 **non-fast-forward 로 거부**
> 된다. `mirror.lag` 가 안 풀리고 사람이 손으로 풀 때까지 그 레포의 모든 `save` 가
> origin 에 닿지 않는다.

```bash
# ① 서버가 origin 보다 앞서 있지 않은지 먼저 본다
sudo -u cdp -H git -C /opt/cdp/repos/gdi fetch
sudo -u cdp -H git -C /opt/cdp/repos/gdi status -sb | head -1
#   ## main...origin/main            ← 같다. ②로
#   ## main...origin/main [ahead 2]  ← 멈춘다. 아래 「앞서 있으면」

# ② 바깥에서 고치고 origin 에 올린다
# ③ 서버를 맞춘다 — ff 만 받는다
sudo -u cdp -H git -C /opt/cdp/repos/gdi pull --ff-only
curl -s http://10.10.20.188:7374/healthz; echo    # mirror.ok 가 레포 수와 같아야 한다
```

스킬을 고쳤으면 **꾸러미도 새것이 된다** — 서버가 레포에서 그때그때 싼다. 관리 화면의
작업 레포 행이 `낡음` 으로 바뀌고, 각자는 `node install.mjs` 를 한 번 더 돌린다.

**앞서 있으면 (`ahead N`)** — 서버가 `save` 로 만든 커밋이 origin 에 못 갔다. 먼저 보낸다.

```bash
sudo -u cdp -H git -C /opt/cdp/repos/gdi push
```

이것도 거부되면 origin 에 남의 커밋이 있다 — **서버 트리에서 사람이 합친다.** 자동으로
하지 않는다: 서버 트리의 커밋은 사람이 승인한 `save` 의 결과이고, 기계가 재작성하면
무엇이 승인된 것인지 흐려진다.
