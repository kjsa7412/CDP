## 0. 시작 전에 — 준비물

없는 것이 있으면 **여기서 멈추고** 구한 뒤 시작한다. 중간에 막히면 되돌리는
일이 더 크다.

- [ ] `10.10.20.188` 에 SSH 접근 · `sudo` 권한 (방화벽 포트를 여는 데도 쓴다 · 6장)
- [ ] 그 서버에 **Node 20 이상** (`node --version`)
- [ ] 그 서버에 **git** (`git --version`) — 서버가 clone · commit · push 를 직접 한다
- [ ] 그 서버가 `10.10.20.250:2900` 에 닿는다
- [ ] `kjsa` 계정이 `soln1/cdp` 에 **push 할 수 있다** (Developer 이상 · 보호
      브랜치라면 그 브랜치에도)
  - 토큰은 **3장에서 발급한다.** 미리 만들 것은 없고, 그 계정으로 GitLab 에
    들어갈 수 있는지만 본다
  - **SSH 는 쓰지 않는다.** 이 GitLab 의 SSH 포트는 `188` 에서 안 닿는다 —
    확인 방법과 이유는 3장 머리에 있다
- [ ] 명부에 올릴 **사람 이름과 권한** — 누가 어느 레포를 보고, **누가 `write` 인가**
      (`save` 가 커밋을 만든다 · §4.5)
- [ ] 개발 PC 에서 만든 **산출물 두 개** (1장)

### 준비물 확인 (서버에서)

```bash
node --version                                   # v20 이상
command -v node                                  # 경로 — 6장에서 쓴다
git --version                                    # 없으면 아래에서 깐다
curl -s -o /dev/null -w '%{http_code}\n' http://10.10.20.250:2900/   # 302 면 닿는다 — push 가 이 길로 간다
```

`node --version` 이 없거나 v20 미만이면, 또는 `git` 이 없으면 아래로.
나머지가 다 되면 1장으로.

### git 이 없으면 — 설치

**서버가 git 을 직접 돌린다.** clone(4장)뿐 아니라 `save` 가 커밋하고
`--mirror` 가 push 한다(§4.5) — 없으면 읽기는 되고 쓰기가 전부 실패한다.

```bash
# Debian · Ubuntu
sudo apt-get install -y git

# RHEL · Rocky · CentOS
sudo dnf install -y git

git --version        # 2.x 면 충분하다
```

### Node 가 없으면 — 설치

**셋 중 하나.** 배포판과 인터넷 여부로 고른다.

#### (가) 패키지 저장소 — 인터넷이 되는 Debian · Ubuntu

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
```

#### (가') 패키지 저장소 — 인터넷이 되는 RHEL · Rocky · CentOS

```bash
curl -fsSL https://rpm.nodesource.com/setup_20.x | sudo bash -
sudo dnf install -y nodejs
```

#### (나) 공식 tarball — 인터넷이 막혔거나 저장소를 안 쓸 때

개발 PC 에서 받아 `scp` 로 넘긴다. **그냥 푸는 것이라 배포판을 안 탄다.**

```bash
# 개발 PC — https://nodejs.org/dist/latest-v20.x/ 에서 linux-x64 tar.xz
scp node-v20.*-linux-x64.tar.xz <SSH계정>@10.10.20.188:/tmp/

# 서버
sudo mkdir -p /usr/local/lib/nodejs
sudo tar -xJf /tmp/node-v20.*-linux-x64.tar.xz -C /usr/local/lib/nodejs
sudo ln -sf /usr/local/lib/nodejs/node-v20.*-linux-x64/bin/node /usr/local/bin/node
```

`npm` 은 필요 없다 — 서버는 `ctx.mjs` 한 파일만 돌린다(1장).

#### (다) 이미 있는데 낡았다

`node --version` 이 v18 이하면 **올려야 한다.** `ctx serve` 는 Node 20 을 요구한다
(§9). 위 (가)·(나) 로 덮으면 된다.

**확인 — 여기서 경로를 적어 둔다.**

```bash
node --version      # v20.x.x
command -v node     # 예: /usr/bin/node  ·  /usr/local/bin/node
```

> **이 경로가 6장의 systemd 유닛과 같아야 한다.** `cdp-serve.service` 는
> `/usr/bin/node` 로 적혀 있다 — (나) 로 깔면 `/usr/local/bin/node` 다.
> 다르면 서비스가 `203/EXEC` 로 죽는다. 6장에서 한 줄로 맞춘다.
>
> **`nvm` 은 쓰지 않는다.** 사용자 셸에만 붙는 도구라 `cdp` 서비스 계정에서는
> 안 보인다 — systemd 가 못 찾는다.

## 3. git 자격 — PAT (HTTP)

**서버가 origin 으로 push 할 자격이다.** 커밋의 `author` 와는 다른 것 — `author`
는 CDP 토큰의 사용자로 서버가 채우므로(§4.5) 누가 정했는지는 사람별로 그대로
남는다. 여기서 정하는 것은 **누가 보냈나** 뿐이다.

> **왜 SSH 가 아니라 HTTP 인가.** 이 GitLab 의 SSH 는 `10.10.20.188` 에서
> **닿지 않는다.** 프로젝트 화면은 `ssh://git@10.10.20.250:443/…` 이라고
> 말하지만 그 포트는 열려 있지 않고(`No route to host`), 22 번은 그 장비의 OS
> sshd(`OpenSSH_7.4`) 라 Deploy Key 를 무시하고 패스워드를 묻는다. GitLab 이
> 컨테이너 안에 있고 SSH 포트가 바깥으로 안 나온 형태다.
> **열려 있는 길은 `2900` 하나뿐이다.**
>
> 그리고 이 GitLab 은 12.9 미만이라 PAT 에 `write_repository` 가 없다 —
> push 가 되는 스코프는 `api` 하나다. 그것은 **계정 전체**를 연다. 감수하는
> 대신 아래 ③에서 좁힌다.

> **250 의 SSH 포트가 열리면 이 장을 SSH 로 되돌리는 편이 낫다.** 자격이
> 레포 하나로 좁혀지고 평문도 없어진다. 지금은 그 길이 없어서 이렇게 간다.

### ① 토큰을 발급한다 — `kjsa` 계정

```
http://10.10.20.250:2900/-/profile/personal_access_tokens
  Name     cdp-server (10.10.20.188)
  Expires  1년 뒤            ← 비워 두지 않는다. 10장에 갱신이 있다
  Scopes   ☑ api            ← 이것 하나만. read_user 등은 켜지 않는다
  > Create personal access token
```

`glpat-` 로 시작하는 값이 **그 화면에서 한 번만** 보인다. 창을 닫으면 다시 못
본다 — 닫기 전에 ②를 끝낸다.

> **`api` 는 넓다.** 이 토큰을 가진 사람은 `kjsa` 가 볼 수 있는 모든 프로젝트를
> 읽고 쓸 수 있다. 그래서 파일 권한을 600 으로 두고(②), 만료를 반드시 걸고,
> 사고가 의심되면 위 화면에서 **Revoke** 한다 — 서버만 멈추고 계정은 산다.

### ② 서버에 넣는다

**토큰이 아무 데도 남지 않게** 받는다. `read -rsp` 라 화면과 히스토리에
안 찍히고, `printf` 는 bash 내장이라 `ps` 에도 안 뜬다.

```bash
read -rsp 'PAT: ' PAT; echo
sudo -u cdp -H git config --global credential.helper 'store --file=/opt/cdp/.git-credentials'
printf 'http://kjsa:%s@10.10.20.250:2900\n' "$PAT" | sudo -u cdp -H sh -c 'umask 077; cat > /opt/cdp/.git-credentials'
unset PAT
```

```bash
sudo ls -l /opt/cdp/.git-credentials
#   -rw------- 1 cdp cdp …          ← 600 이어야 한다. 아니면 지우고 다시
```

이 파일이 **평문 토큰**이다. `2900` 이 HTTPS 가 아니라서 push 할 때마다
사내망을 평문으로도 흐른다 — 폐쇄망이라 감수하는 부분이고, 0단계에서 정한
그대로다.

### ③ 커밋에 쓰일 이름 (표시용)

```bash
sudo -u cdp -H git config --global user.name  "cdp-server"
sudo -u cdp -H git config --global user.email "cdp-server@sjinc.co.kr"
```

**실제 커밋 `author` 는 이것이 아니다.** `save` 가 CDP 토큰의 사용자로
덮어쓴다(§4.5) — 이 값은 그것이 없을 때의 폴백일 뿐이다.

**확인 — 읽기. 여기서 반드시 한다.**

```bash
sudo -u cdp -H git ls-remote http://10.10.20.250:2900/soln1/cdp.git HEAD
#   <해시>	HEAD        ← 한 줄 나오면 자격이 붙었다
```

| 결과 | 뜻 |
|---|---|
| 해시 한 줄 | 4장으로 |
| `HTTP Basic: Access denied` | 사용자명이 `kjsa` 가 아니거나 토큰이 틀렸다 — ②를 다시 |
| `could not be found` (404) | 경로 오타이거나 `kjsa` 에게 그 프로젝트 권한이 없다 |
| **패스워드를 묻는다** | `.git-credentials` 를 못 읽었다. `-H` 를 빼먹었거나 `credential.helper` 경로가 다르다 |
| 멈춘 채 안 끝난다 | `2900` 이 막혔다 (0장) |

> **쓰기는 4장 끝에서 따로 본다.** 읽기만 되는 상태로 넘어가면 서버는 정상으로
> 뜨고 `save` 도 성공하는데 **미러만 조용히 밀린다.**

## 4. 레포 받기

**폴더명이 곧 레포 이름이다**(§4.2). `cdp` 가 아니라 **`gdi`** 로 받는다 —
개발 PC 의 `C:\cdp` 와 이름이 달라도 정상이다.

```bash
sudo -u cdp -H git clone http://10.10.20.250:2900/soln1/cdp.git /opt/cdp/repos/gdi
```

**확인**

```bash
sudo -u cdp -H ls /opt/cdp/repos/gdi/_vocab.md      # 이 파일이 있어야 레포로 인식된다
sudo -u cdp -H git -C /opt/cdp/repos/gdi log -1 --oneline

# **쓰기 권한을 여기서 확인한다.** 아무것도 보내지 않고 권한만 본다.
sudo -u cdp -H git -C /opt/cdp/repos/gdi push --dry-run origin HEAD
#   Everything up-to-date        ← 이것이면 쓰기까지 된다
```

`push --dry-run` 이 거부되면 —

| 메시지 | 고칠 곳 |
|---|---|
| `You are not allowed to upload code` | 토큰 스코프에 `api` 가 없다 (3장 ①) |
| `HTTP Basic: Access denied` | 토큰이 만료됐거나 폐기됐다 (3장 ①) |
| `You are not allowed to push code to protected branches` | 보호 브랜치다. `kjsa` 가 그 브랜치에 push 할 수 있어야 한다 — `Settings > Repository > Protected branches` |
| `could not be found` | `kjsa` 의 역할이 Developer 미만이다 |

**여기서 안 잡으면** 뒤가 전부 정상으로 보인다. `/healthz` 의 `mirror.lag` 가
유일한 신호가 된다.

> **서버 트리에서 사람이 커밋하지 않는다.** 서버가 유일한 작성자다(§4.2).
> 사람은 origin 을 읽기 전용으로 clone 해서 본다.

## 5. 명부와 토큰

**권한은 사람에게 붙고, 토큰은 신원만 증명한다**(§4.4). 그래서 토큰을 뺏겨도
명부에서 그 사람을 멈추면 끝이고, 사람이 나가도 토큰을 일일이 쫓을 필요가 없다.

파일 둘이 생긴다 — `auth.json`(명부·토큰 해시)과 `data/logs/auth.log`(이력).
둘 다 이 명령들이 알아서 만든다. 미리 만들 것은 없다.

### ① 손에 익게 줄여 둔다

```bash
CTX="sudo -u cdp node /opt/cdp/bin/ctx.mjs serve"
A=/opt/cdp/auth.json
D=/opt/cdp/data
```

**이 창을 닫으면 없어진다.** 나중에 다시 손볼 때는 이 세 줄부터 다시 친다.

### ② 사람을 올린다 — 토큰보다 먼저

```bash
$CTX user add --auth $A --data $D --name kjsa  --label "사경진 · 개발" --repos gdi --write
$CTX user add --auth $A --data $D --name <이름> --label "<소속 · 역할>" --repos gdi
```

한 줄에 한 사람. 2~5명이면 그만큼 반복한다.

| 옵션 | 뜻 |
|---|---|
| `--name` | **영문·숫자·`.`·`_`·`-`** 만. 이것이 커밋의 `author` 로 남는다(§4.5) — 사내에서 통하는 아이디를 쓴다 |
| `--label` | 사람이 읽을 설명. 목록에만 나온다 |
| `--repos` | 볼 수 있는 레포. 쉼표로 여럿 (`gdi,foo`) · `*` 는 전부 |
| `--write` | **`save` 로 커밋을 만들 수 있다.** 빼면 읽기만 |

> **`--write` 를 기본으로 주지 않는다.** 쓰기는 origin 에 커밋을 남기는 일이라
> 되돌리는 값이 비싸다. 처음에는 실제로 정리를 맡은 사람에게만 주고, 필요해지면
> 그때 `user set --name <이름> --write` 로 올린다.

**여기 없는 이름으로는 토큰이 안 나간다.** 순서가 반대면 ③에서 막힌다.

### ③ 토큰을 발급한다 — 사람마다·기계마다 하나

```bash
$CTX token --auth $A --data $D --user kjsa --note "노트북"
```

```
<토큰 원문 한 줄>

위 한 줄이 토큰 원문이다. 다시 볼 수 없다 — 본인에게 직접 전한다(§4.4.2).
id 1a2b3c4d · 사용자 kjsa · 만료 2026-12-20
```

**원문은 이때 한 번만 나온다.** `auth.json` 에는 해시만 남아서 나중에 누구도
꺼낼 수 없다 — 잃어버리면 새로 발급하고 옛것을 지우는 것 말고는 길이 없다.

- 기본 만료 **90일**. 다르게 하려면 `--expires 180` · 무기한은 `--expires never`
- 노트북과 데스크톱을 따로 쓰면 **기계마다 따로** 발급한다. `--note` 에 무엇인지
  적어 두면 나중에 하나만 지울 수 있다
- 전달은 **본인에게 직접**. 메신저·메일·이슈·위키에 평문으로 남기지 않는다.
  남겼으면 유출로 보고 `token revoke` 후 재발급한다

> **발급 엔드포인트는 없다**(§4.4.1). 이 서버에 셸이 있는 사람만 발급할 수 있다 —
> 화면에서 "토큰 주세요" 를 누를 자리가 없는 것이 의도다.

### ④ 확인

```bash
sudo ls -l /opt/cdp/auth.json          # -rw------- cdp cdp   (명령이 알아서 600 으로 둔다)
$CTX user list  --auth $A --data $D
$CTX token list --auth $A --data $D
```

```
이름          상태    레포                쓰기  토큰    마지막 사용   설명
kjsa          활성    gdi                 write 1/1     -             사경진 · 개발
```

| 보는 것 | 맞아야 하는 것 |
|---|---|
| 상태 | 전원 `활성` |
| 레포 | **`-` 인 사람이 없다.** `-` 면 그 사람은 아무것도 못 본다 — `user set --name <이름> --repos gdi` |
| 쓰기 | `write` 가 **의도한 사람에게만** |
| 토큰 | `발급된/전체`. 앞자리가 `0` 이면 ③을 안 했다 |

`token list` 의 `남음` 이 만료까지 남은 날이다. 90일 뒤 갱신을 위해 10장에 넣어 둔다.

### 나중에 — 고칠 때

```bash
$CTX user set --auth $A --data $D --name <이름> --write          # 쓰기를 준다
$CTX user set --auth $A --data $D --name <이름> --no-write       # 거둔다
$CTX user set --auth $A --data $D --name <이름> --repos gdi,foo  # 레포를 바꾼다
$CTX user set --auth $A --data $D --name <이름> --inactive       # 사람을 멈춘다 (나갔을 때)
$CTX token revoke --auth $A --data $D --name <이름>              # 그 사람 토큰 전부
$CTX token revoke --auth $A --data $D --name <이름> --id 1a2b3c4d  # 하나만
```

**서버 재시작이 필요 없다.** 매 요청마다 명부를 다시 읽으므로 `--inactive` 는
**다음 요청부터** 바로 막힌다 — 열려 있던 화면도 같이 막힌다(§4.4).

`--inactive` 는 토큰을 지우지 않는다. 되돌릴 수 있어야 하고 이력이 남아야 해서다.

## 6. 서비스 등록

```bash
sudo cp /tmp/cdp-serve.service /etc/systemd/system/

# **0장에서 적어 둔 node 경로와 맞춘다.** 유닛은 /usr/bin/node 로 되어 있다 —
# tarball 로 깔았으면 /usr/local/bin/node 다. 다르면 203/EXEC 로 죽는다.
sudo sed -i "s|^ExecStart=[^ ]*node|ExecStart=$(command -v node)|" /etc/systemd/system/cdp-serve.service
grep ExecStart /etc/systemd/system/cdp-serve.service

sudo systemctl daemon-reload
sudo systemctl enable --now cdp-serve
sudo systemctl status cdp-serve --no-pager
```

**확인**

```bash
curl -s http://10.10.20.188:7374/healthz
#   {"ok":true,"built":"2026-09-21 07:19","repos":1,"mirror":{"ok":1,"lag":0,"off":0}}

curl -s -H "Authorization: Bearer <토큰>" http://10.10.20.188:7374/repos
#   [{"name":"gdi","title":"…","head":"…","mirror":"ok"}]
```

- `repos:1` 이 아니면 4장으로 — 폴더에 `_vocab.md` 가 있는가.
- `mirror` 가 `off` 면 upstream 이 없는 것이고, `lag` 면 push 가 밀린 것이다(3장).
- `/healthz` 는 **인증 없이** 열린다. 레포 이름은 싣지 않는다 — 집계까지다(§4.3).

### 포트를 연다 — 이것을 빼면 서버에서만 보인다

**위 `curl` 이 서버 자신에서 됐다고 뚫린 것이 아니다.** 자기 주소로 가는
패킷은 loopback 으로 빠져서 방화벽을 안 탄다. 바깥에서는 그대로 막혀 있다 —
사람도 MCP 호스트도 못 들어온다.

```bash
sudo firewall-cmd --permanent --add-port=7374/tcp
sudo firewall-cmd --reload
sudo firewall-cmd --list-ports
#   7374/tcp        ← 이 줄이 나와야 한다
```

`firewall-cmd: command not found` 면 iptables 쪽이다:

```bash
sudo iptables -I INPUT -p tcp --dport 7374 -j ACCEPT
sudo service iptables save     # **빼면 재부팅 때 사라진다**
```

**확인은 다른 장비에서 한다.** 서버 자신에서는 열기 전에도 되므로 확인이 안 된다.

```bash
curl -s -m 5 http://10.10.20.188:7374/healthz; echo     # 개발 PC 에서
```

> **7374 하나만 연다.** 프록시가 없어서 이 포트가 유일한 경계다(§8) — 다른
> 것을 같이 열 이유가 없다.

## 8. 사람에게 붙이기

### 작업 레포를 등록한다 — 관문이 아니라 장부다

화면에서 **관리 > 작업 레포 > 등록**. 이름 · 담당자(명부에서 고른다) · 메모.

**등록은 아무것도 막지 않는다.** 등록 없이 꾸러미를 받아 설치해도 MCP 는
정상으로 돈다. 장부가 하는 일은 **어느 작업 레포가 어느 판의 꾸러미를 들고
있나**를 나중에 알 수 있게 하는 것뿐이다 — 보고에 담긴 꾸러미 해시를 서버가
지금 든 것과 견줘 `최신 · 낡음 · 미설치` 로 보여준다. 스킬을 고쳤을 때 누가
아직 옛 판인지 알 길이 달리 없다(작업 레포들은 서버가 보지 못하는 곳에 있다).

담당자를 한 명으로 두는 이유는 **꾸러미가 git 에 커밋되기 때문**이다.
다섯 명이 각자 다른 날 넣으면 서로 다른 판이 같은 파일을 두고 커밋을 주고받는다.
한 사람이 넣어 커밋하면 나머지는 `git pull` 과 `CDP_TOKEN` 만으로 끝난다.

> **전용 관리자 계정 같은 것은 없다.** 그 지식 레포를 볼 수 있는 사람이면
> 누구나 등록·삭제할 수 있다. 권한 축은 `repos` 와 `write` 둘뿐이다(§4.4).
> 팀이 작으면 등록을 아예 건너뛰어도 된다 — "누가 아직 옛 판인가" 가
> 궁금해지는 시점에 시작하면 된다.

### 각자가 — 꾸러미를 받아 푼다

등록한 행의 `[설치 방법]` 을 열면 4단계가 나온다.

1. `cdp-kit-<이름>.zip` 을 받아 **작업 레포 루트에 푼다**
   (`CLAUDE.md` 가 이미 있으면 `cdp:begin ~ cdp:end` 블록만 갈아 끼운다)
2. `setx CDP_TOKEN <관리자에게 받은 토큰>` (Windows) · `export` (macOS·Linux)
3. **Claude Code 를 다시 켠다** — 환경변수는 프로세스 시작 때 읽힌다
4. `git add .mcp.json .claude CLAUDE.md` 후 커밋

**확인** — Claude Code 의 `/mcp` 에 `cdp` 가 **connected** 이고 도구가 13건이다.

> 4번을 커밋하면 **팀원은 `git pull` 과 `CDP_TOKEN` 만으로 끝난다.** 꾸러미를
> 다시 받을 필요가 없다.
>
> `bin/ctx` 가 있는 사람은 1번 대신
> `ctx setup --server http://10.10.20.188:7374 --repo gdi --workrepo <id> <작업레포>` —
> 블록 병합과 대장 보고까지 한 번에 된다.

## 9. 막혔을 때 · 되돌리기

| 증상 | 볼 곳 |
|---|---|
| 서비스가 바로 죽는다 | `journalctl -u cdp-serve -n 50` · Node 버전 · `--auth` 경로 |
| `status=203/EXEC` | 유닛의 `ExecStart` 가 실제 node 경로와 다르다 (6장의 `sed` 줄) |
| `SyntaxError` 로 죽는다 | Node 가 v20 미만이다 (0장) |
| `거부: --bind … 인증 없이 밖으로 열 수 없다` | `--auth` 가 빠졌다. 루프백 밖은 인증 없이 못 연다(§8) |
| `Cannot find module '/opt/cdp/bin/ctx.mjs'` | 2장의 `sudo cp /tmp/ctx.mjs /opt/cdp/bin/` 을 빠뜨렸다. 복사하고 `chown` 을 다시 돌린다 |
| `Dynamic require of …` | 번들이 낡았다. 개발 PC 에서 `npm run build:ctx` 를 다시 (1장) |
| 읽기는 되는데 `save` 가 `E_GIT` · `mirror` 가 늘 `off` | 서버에 **git 이 없다.** `git --version` (0장) |
| `repos: 0` | `<root>/<name>/_vocab.md` 가 있는가 · 목록 갱신은 60초 주기 |
| `mirror: lag` 가 안 풀린다 | `sudo -u cdp -H git -C /opt/cdp/repos/gdi push` 를 손으로 돌려 본다. **토큰 만료가 가장 흔하다**(3장 ①) |
| push 가 `HTTP Basic: Access denied` | 토큰이 만료·폐기됐다. 3장 ①②를 다시 — 서비스 재시작은 필요 없다 |
| push 가 패스워드를 묻는다 | `/opt/cdp/.git-credentials` 가 없거나 `cdp` 가 못 읽는다 (3장 ②) |
| 401 인데 토큰은 맞다 | 만료 · 명부에서 지워짐 · `active:false`. `serve user list` 로 본다 |
| 화면만 안 뜬다 | `/opt/cdp/web/index.html` · `--web` 경로 |
| 서버에서는 `curl` 이 되는데 **밖에서 안 된다** | 방화벽에 7374 가 안 열렸다 (6장). loopback 은 방화벽을 안 타서 서버 자신에서는 늘 된다 |
| 로그인 뒤 `Origin 이 허용되지 않는다` | 번들이 낡았다 — 같은 출처 검사가 들어가기 전 것이다. 1·2장으로 다시 올리고 `systemctl restart cdp-serve` |

### 되돌리기

```bash
sudo systemctl disable --now cdp-serve
sudo rm /etc/systemd/system/cdp-serve.service
sudo systemctl daemon-reload
# 데이터를 지울 때만
sudo rm -rf /opt/cdp
sudo userdel cdp
```

GitLab 의 **토큰도 폐기한다** — `Profile > Personal Access Tokens > Revoke`.

**지식 레포는 origin 에 그대로 있다.** 서버를 지워도 `--mirror` 로 보낸 커밋은
남는다 — 그것이 백업이기도 하다.

### 고친 뒤 — 다시 올리기

설치는 한 번이지만 **이 절차는 계속 쓴다.** 명부 · 대장 · 지식 레포 · git 자격은
건드리지 않는다 — 갈아 끼우는 것은 산출물 둘뿐이다.

**무엇을 고쳤나에 따라 올릴 것이 다르다.**

| 고친 곳 | 올릴 것 |
|---|---|
| `core/` · `viewer/bin/` (서버·MCP·도구) | `ctx.mjs` |
| `viewer/src/` (화면) | `web/` |
| 둘 다 · 모르겠다 | **둘 다** — 틀려도 손해가 없다 |

#### ① 개발 PC — 만든다

```bash
cd C:\project\CDP
npm run build:ctx        # → ops/out/ctx/ctx.mjs
npm run build            # → ops/out/web/
node ops/out/ctx/ctx.mjs version      # 시각이 방금으로 바뀌었는지
```

```bash
scp ops/out/ctx/ctx.mjs  <SSH계정>@10.10.20.188:/tmp/
scp -r ops/out/web       <SSH계정>@10.10.20.188:/tmp/web
```

#### ② 서버 — 갈아 끼운다

```bash
# **되돌릴 것을 먼저 챙긴다.** 새것이 안 뜨면 이 한 줄이 5분을 아낀다.
sudo cp /opt/cdp/bin/ctx.mjs /opt/cdp/bin/ctx.mjs.bak

sudo cp /tmp/ctx.mjs /opt/cdp/bin/ctx.mjs

# 화면은 **비우고 넣는다.** 자산 파일 이름에 해시가 붙어서 덮어쓰기만 하면
# 옛 파일이 계속 쌓인다. 여기 있는 것은 전부 빌드 산출물이라 지워도 된다.
sudo rm -rf /opt/cdp/web/* && sudo cp -r /tmp/web/* /opt/cdp/web/

sudo chown -R cdp:cdp /opt/cdp/bin /opt/cdp/web
sudo systemctl restart cdp-serve
```

#### ③ 확인

```bash
curl -s http://10.10.20.188:7374/healthz; echo
#   "built" 가 ①의 version 시각과 같아야 한다 — 다르면 cp 가 안 먹었다
```

브라우저는 **강제 새로고침**(`Ctrl+Shift+R`)한다. 자산 이름이 바뀌었는데
옛 index.html 이 캐시에 남아 있으면 화면이 빈 채로 뜬다.

**안 뜨면 되돌린다.** 명부도 레포도 안 건드렸으니 번들만 되돌리면 원래대로다.

```bash
sudo cp /opt/cdp/bin/ctx.mjs.bak /opt/cdp/bin/ctx.mjs
sudo systemctl restart cdp-serve
journalctl -u cdp-serve -n 50 --no-pager -l
```

> **`systemctl restart` 로 끊기는 것은 그 순간의 요청뿐이다.** 세션이 서버에
> 없어서(§4.4) 로그인 상태는 재시작을 넘어 그대로 살아 있다 — 사람이 다시
> 로그인할 필요가 없다.
