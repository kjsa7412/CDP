# CDP 서버 관리자 설명서

> 공식 사이트의 화면용 **줄인 판**이다. 실제 설명서는 설치된 서버의 `/manual` 에 있다.

## 목차

0. 서버 관리자가 맡는 것 · 1. 개인 서버 · 2. 팀 서버 설치 · 3. 사람 — 명부와 토큰 · 4. 큐레이터 맡기기 · 5. 지식 레포 세우기 · 6. 작업 레포 · 7. 미러 · 8. 갱신

## 0. 서버 관리자가 맡는 것

서버 · 명부 · 지식 레포를 세우고, 레포마다 큐레이터를 맡긴다. 할 일은 서버 › 현황의 「시작하기」 가 말한다.

## 1. 개인 서버

```
ctx up ~/cdp/library --install ~/code/library-web --curator ~/cdp/curator
ctx self-update cdp-server-v<판>.tar.gz
```

빈 틀 · 빈 포트(7400 부터) · 토큰 · 연결까지 한 줄. 이미 떠 있으면 그 주소를 쓴다.

## 2. 팀 서버 설치

```
sudo bash deploy/install.sh --bind <서버IP> --admin lead --repo library --origin <git url> --ssh
```

첫 관리자 · git 자격 · 첫 레포와 push · doctor 까지. 설정은 `serve.json` 한 장이고 `cdp serve doctor` 는 플래그 없이 돈다. Docker 는 compose 한 장 — 명부 · git 자격이 data 볼륨 안이라 새 판에서도 이어진다.

## 3. 사람 — 명부와 토큰

서버 › 사람 한 화면. 역할은 셋 — viewer · writer · admin. 토큰은 사람 줄의 [발급] 에서, 원문은 **한 번만** 보인다.

## 4. 큐레이터 맡기기

서버 › 사람의 「레포 × 큐레이터」 — 체크 하나가 한 줄이다. admin 은 모든 레포의 큐레이터이고 viewer 는 될 수 없다.

## 5. 지식 레포 세우기

서버 › 지식 레포 › 새 레포 — **빈 틀**로 선다. 옛 레포가 있으면 작업 기록만 옮겨 와 큐레이션부터 다시 세운다.

## 6. 작업 레포

등록된 코드 레포는 서버 › 지식 레포의 펼침 열에서 본다 — 최신 · 낡음 · 미설치.

## 7. 미러

save 가 커밋하면 origin 으로 보낸다. 갈라지면 멈추고 그 행의 단추로 맞춘다.

## 8. 갱신

```
sudo bash /opt/cdp/deploy/upgrade.sh cdp-server-v<판>.tar.gz
node cdp-install.mjs --update
```
