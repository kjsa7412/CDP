# CDP 사용자 설명서

> 공식 사이트의 화면용 **줄인 판**이다. 장 제목은 제품 설명서와 같고 본문은 짧게 줄였다. 실제 설명서는 설치된 서버의 `/manual` 에 있다.

## 목차

0. 시작하기 전에 · 1. CDP 가 무엇인가 · 2. 처음 한 번 — 연결 · 3. 하루 흐름 · 4. 작업 요청 · 5. 좌표 · 6. 기록 · 8. 화면 · 9. 여럿이 할 때 · 10. 막혔을 때

## 0. 시작하기 전에 — 무엇을 받아야 하나

관리자에게 **토큰 하나**를 받는다. 서버 주소와 지식 레포 이름은 관리자가 알려 준다.

## 1. CDP 가 무엇인가

프로젝트 지식을 두 층으로 둔다.

| | | |
|---|---|---|
| `work/` | 작업 기록 | 사건 — 왜 그렇게 정했나. 고치지 않는다 |
| `docs/` | 관리 문서 | 상태 — 지금 어떻게 생겼나. 고친다 |

**좌표**(`테이블정의서:bk_loan_mst`)가 둘을 잇는다. 좌표를 건드린 기록은 그 섹션을 같이 고쳐야 커밋된다.

## 2. 처음 한 번 — 연결

작업 레포에서 한 줄을 친다. 설치기가 토큰을 숨김 입력으로 묻고, 서버에 확인한 뒤 둔다.

```
node cdp-install.mjs --repo library --workrepo <작업레포> .
```

## 3. 하루 흐름

1. 에이전트에게 일을 맡긴다 — 에이전트가 좌표를 찾아 **그 섹션만** 읽는다
2. 일을 한다
3. 기록한다 — 작업 기록 하나와 고친 섹션들이 한 커밋으로 들어간다

## 5. 좌표

`<타입>:<값>`. **바꾼 것에만** 붙인다. 언급한 것에는 붙이지 않는다.

## 6. 기록 — `cdp-save`

에이전트가 `save` 로 보낸다. 서버가 검사하고 커밋한다. 작성자는 토큰이 정한다.

## 8. 화면

왼쪽에서 찾고 오른쪽에서 읽는다. 목록 · 뻗어나가기 · 좌표 그래프 · 검색(`Ctrl+K`).

## 10. 막혔을 때

`E_CHECK` — 고친 좌표의 섹션이 빠졌다. `E_CONFLICT` — 그 섹션을 누가 먼저 고쳤다. 다시 읽고 합쳐 보낸다.
