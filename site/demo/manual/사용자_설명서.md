# CDP 사용자 설명서

> 공식 사이트의 화면용 **줄인 판**이다. 장 제목은 제품 설명서와 같고 본문은 짧게 줄였다. 실제 설명서는 설치된 서버의 `/manual` 에 있다.

## 목차

0. 시작하기 전에 · 1. CDP 가 무엇인가 · 2. 처음 한 번 — 연결 · 3. 하루 흐름 · 4. 작업 요청 · 5. 좌표 · 6. 기록 남기기 · 7. 미반영 읽는 법 · 8. 화면 · 10. 막혔을 때

## 0. 시작하기 전에 — 무엇을 받아야 하나

팀 서버면 관리자에게 **토큰 하나**를 받는다. 혼자 쓰면 받을 것이 없다 — `ctx up` 이 개인 서버와 토큰을 같이 만든다.

## 1. CDP 가 무엇인가

프로젝트 지식을 두 층으로 둔다.

| | | |
|---|---|---|
| `work/` | 작업 기록 | 사건 — 왜 그렇게 정했나. 고치지 않는다 |
| `docs/` | 관리 문서 | 상태 — 지금 어떻게 생겼나. 큐레이터가 반영한다 |

**좌표**(`테이블정의서:bk_loan_mst`)가 둘을 잇는다. 사용자는 **작업 기록만** 남긴다.

## 2. 처음 한 번 — 연결

한 줄이면 된다. 무엇이 남았는지는 화면 「시작하기」 와 명령의 끝 출력이 말한다.

```
ctx up ~/cdp/library --install ~/code/library-web        # 혼자 — 개인 서버 · 토큰 · 연결까지
node cdp-install.mjs --connect --repo library ~/code     # 팀 — 아래 git 레포를 한 번에 등록 · 설치
node cdp-install.mjs --update                             # 새 판 — 이 PC 의 작업 레포 전부
```

토큰은 숨김 입력으로 받아 `~/.config/cdp/token` 에 둔다(Windows 는 사용자 환경변수). 설치 뒤 Claude Code 를 한 번 다시 연다.

## 3. 하루 흐름

1. 에이전트에게 일을 맡긴다 — 좌표를 찾아 **그 섹션과 미반영 기록**을 읽는다(`cdp-work`)
2. 일을 한다
3. 기록한다 — 작업 기록 하나가 한 커밋이다(`cdp-save`). 기록은 큐레이션 대기열에 선다

## 4. 작업 요청 — `cdp-work`

평소 말로 맡긴다 — 「연체 현황에 엑셀 단추를 붙여 줘」. 에이전트가 대상을 좌표로 확정하고 섹션과 미반영 기록을 읽은 뒤 일한다.

## 5. 좌표 — 바꾼 것만

`<타입>:<값>`. **바꾼 것에만** 붙인다.

## 6. 기록 남기기 — `cdp-save`

값 · 결정 · 제약을 본문에 담는다 — 그 기록만 읽어도 알 수 있게. 서버가 검사하고 커밋한다. 작성자는 토큰이 정한다.

## 7. 미반영 읽는 법

섹션 제목 옆 **「미반영 n」** — 그 섹션 뒤에 아직 반영 안 된 기록이 있다. 그 기록까지 같이 읽는다 — 에이전트의 `section` 도 둘을 같이 준다.

## 8. 화면

**읽기**(문서 · 기록 세그 — 기록마다 대기 · 반영됨 · 기록으로 둠) · 좌표 그래프 · 검색(`Ctrl+K`). 문서를 고르기 전에는 「시작하기」 가 다음 할 일 하나를 보인다.

## 10. 막혔을 때

`E_FORBIDDEN` `need: curate` — 섹션은 큐레이터가 쓴다. 기록만 다시 보낸다. `E_INPUT` — 그 save 자신의 결함이다. 토큰이 만료되면 관리자에게 재발급을 받는다.
