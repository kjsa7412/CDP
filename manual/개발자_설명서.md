## 1. CDP 가 무엇인가 — 개발자의 눈으로

### 1.1 두 층 · 원천 셋 · 역할 넷

**대상마다 정본 섹션이 하나 있고 그 자리를 좌표로 부른다.** 작업 기록(`work/` · 사건 · 불변)과 관리 문서(`docs/` · 상태)를 좌표가 잇고,
섹션이 어느 기록까지 실었는지 `applied` 한 줄이 적는다. v1.0 에서 바뀐 것은 **누가 섹션을 쓰나**다.

| | v0.x | v1.0 |
|---|---|---|
| 쓰는 길 | PC 의 git 훅(모드 A) · 서버 `save`(모드 B) 둘 | **서버 `save` 하나**(I2) — 서버 없는 사람은 개인 서버(`--personal`) |
| 섹션 | 기록을 남긴 사람이 같이 고친다 · 안 고치면 「파생 누락」 error | **큐레이터만** 고친다(I6) · 늦은 반영은 「미반영」 상태로 섹션과 같이 실린다(I7) |
| 레포 | 지식 + 도구 층(`bin/` · 훅 · 스킬 사본 · INDEX · MANUAL) | **지식만**(I9) — 도구는 서버 번들 |
| 관리 문서의 원천 | 작업 기록 | 작업 기록 · 큐레이터의 판단 · **기준선**(기계 추출 블록) |

역할은 viewer · writer · **큐레이터**(레포별 `curate`) · admin(서버 · 모든 레포의 큐레이터)이다. 판정은 `core/` 의 순수 함수 한 벌이고(I1)
서버 · CLI · 화면이 부르기만 한다.

### 1.2 산출물 흐름

```
개발자 (이 문서)                 서버 관리자                              사용자 · 큐레이터
────────────────                ─────────────────────────────            ─────────────────────────────
소스 레포 고친다
node --test · verify · build:site
태그 v* push
  └─▶ release.yml ──▶ cdp-server-v<판>.tar.gz ──▶ install.sh · upgrade.sh ──▶ 설치 한 줄(작업 레포 · writer kit)
                 └──▶ cdp-site-v<판>.zip                    └ 콘솔: 레포 · 사람 · 큐레이터 └ --curator(큐레이터 폴더)
                 └──▶ SHA256SUMS                                                         └ 브라우저 /r/<레포>/
공식 사이트 — Vercel 이 site/ 를 빌드한다(사이트에 닿는 파일이 바뀐 push 만)
```

관리자는 CDP 를 만들지 않고, 사용자는 세우지 않는다. **개발자가 넘기는 것은 산출물 둘과 그 안의 문서**다 — 산출물에 없는 것은 받는 쪽에 없는 기능이다.

### 1.3 정본이 어디인가

| 무엇 | 정본 | 사본 · 산출물 (고치면 다음 빌드에 덮인다) |
|---|---|---|
| 판정 · 계산 | `core/` | — (서버 · CLI · 화면이 같이 부른다) |
| 받는 사람에게 가는 것 — 스킬 · CLAUDE 블록 · 서식집 | `agent/` | 서버 번들 `kit/` · `forms/` · 작업 레포 · 큐레이터 폴더의 `.claude/skills` |
| CLI · MCP · 서버 · 설치기 소스 | `viewer/bin/` | 번들 `ops/out/ctx/ctx.mjs` |
| 화면 | `viewer/src/` | `ops/out/web/` |
| 제품 설명서 넷 | `manual/` | 서버 번들 `manual/`(서버가 `/manual` 로 낸다) |
| 서버 설치 · 갱신 | `ops/deploy/` | 서버 번들 `deploy/` |
| 공식 사이트 | `site/` | `ops/out/site/`(Vercel · 사이트 zip) |
| 설계 · 검토 · 우리만 보는 것 | `docs/` | — |
| 단위 시험 · 하네스 | `test/` · `ops/verify/` | `ops/out/verify/result.json` |

**`core/` 의 모듈** — 순수(파일을 안 읽고 안 쓴다)와 I/O 를 이름으로 가른다.

| 무리 | 모듈 | |
|---|---|---|
| 모델 · 파서(순수) | `frontmatter` · `vocab` · `managed` · `forms` · `baseline` · `errors` | 프론트매터(`curates` · `baseline` 포함) · 좌표 문법 · 등록부와 섹션 · 서식 · 기준선 블록 · `CtxError` |
| 판정(순수) | `validity` · `curation` · `check` · `docrefs` · `docusage` · `search` | `later()` · 섹션 상태 · **대기열 · 미반영 · 판정 재료** · 검사(V21 의 전후 차) · 문서 참조 · 사용 현황 · 색인 |
| 계획(순수) | `managedops` · `edits` · `examples` · `docdrop` · `migrate` · `skeleton` · `setup` · `regen` | 등록부 연산 · 섹션 밖 쓰기 · 예시 정리 · 문서 지우기 · 전환 기록 · 빈 틀 · 작업 레포 병합 · 옛 등록부 사본 줄을 읽는 도우미(v1.0 은 만들지 않는다) |
| 도구 모양(순수) | `tools` | MCP 도구 결과의 모양 — CLI `--json` 이 같은 함수를 부른다 |
| I/O | `scan` · `repo`(`loadRepo`) · `store`(서버 레포 캐시 · 화면 view-model) · `save` · `git` · `mirror` · `lock` · `assets` · `auth` · `workrepos` · `reponew` · `rebuild` · `importdir` · `formslib` · `kit` · `gitauth` · `tokenstore` · `localreg` · `zip` · `appinfo` | |

### 2.2 진입점 — 셋

| 진입점 | 무엇 | 소스 |
|---|---|---|
| **서버** `ctx serve` | 한 프로세스 · 한 포트 — 소개 · 설명서 · 화면 · 콘솔(관리 API) · 읽기 API · MCP(Streamable HTTP) · `save` · kit · 설치기. 개인 서버(`--personal`)도 같은 코드 | `viewer/bin/ctx-mcp-serve.mjs` · `ctx-mcp.mjs` |
| **CLI** `ctx` | **읽기와 서버 관리만**(I2) — `check` · `docs` · `match` · `where` · `search` · `term` · `brief` · `serve …` · `repo` · `forms` · `migrate` · `baseline` · `import-dir` | `viewer/bin/ctx-cli.mjs` + `ctx-*.mjs` |
| **설치기** `install.mjs` | 작업 레포 · 큐레이터 폴더에 kit 을 병합한다 — 한 줄 · `--update` · `--curator` · 꾸러미 zip | `viewer/bin/cdp-install.mjs` → `core/setup.js` |

v0.x 의 로컬 뷰어 · `cdp.exe` · 트레이 · stdio MCP(`ctx mcp`) · git 훅 · CLI 쓰기 명령은 v1.0 에서 지웠다(개편안 §5.6). 없앤 명령을 부르면
`ctx-cli.mjs` 의 `gone` 표가 무엇으로 바뀌었는지 한 줄로 답하고 exit 2. `ctx serve` 의 모르는 하위 명령(없앤 `kit-refresh` · 오타)도
서버를 띄우지 않고 exit 2 다 — 전에는 상주 서버로 떴다.

### 2.3 불변조건 — 번호로 가리킨다

문장의 정본은 개편안 §2 다. 여기는 **어디서 지키나**를 적는다 — 이것을 고치는 커밋은 그 자리의 시험이 깨져야 정상이다.

| # | 짧게 | 지키는 자리 |
|---|---|---|
| I1 | 판정은 `core/` 한 곳 | `core/*.js` · MCP 도구와 `ctx --json` 의 바이트 대조(하네스) · 화면의 `lib/` 는 값을 그릴 뿐 |
| I2 | 쓰기 길은 서버 `save` 하나 · save 하나 = 커밋 하나 | `core/save.js` · CLI 의 `gone` 표 · `test/save*.test.mjs` |
| I3 | `work/` 는 불변 | save 의 `E_EXISTS` · `edits` 가 `work/` 를 거절(`core/edits.js`) |
| I4 | 좌표는 `_vocab.md` 에만 | `check` 의 `unregistered-coord` · save 의 어휘 등재 |
| I5 | 사실 하나에 정본 자리 하나 | `dup-anchor` error · 큐레이터 스킬의 정본 규칙 |
| I6 | 관리 문서는 큐레이션으로만 | save 의 `curatorOnly`(writer 가 `sections` · `managed` · `edits` · `curates` 를 보내면 `E_FORBIDDEN` `need: curate`) |
| I7 | 미반영은 상태 · 섹션을 내는 모든 자리가 미반영을 같이 낸다 | `core/curation.js` 의 `pendingOf` · `toolSection` · 화면 PendingChip · `test/curation.test.mjs` |
| I8 | 상태는 계산할 뿐 저장하지 않는다 | `status` 필드 error · 대기열은 `loadRepo` 가 그때 계산 |
| I9 | 레포에는 지식만 | `core/skeleton.js` · `migrate` 의 `TOOL_LAYER` · doctor 의 「도구 층」 |
| I10 | writer 의 save 는 자기 변경분으로만 막힌다 | `check.js` 의 `newErrors`(전 · 후 검사의 차 · V21) · `test/save.test.mjs` |
| I11 | 서버는 LLM 을 부르지 않는다 · CDN · 인터넷 없음 | 의존성 · 화면 폰트 인라인 · HTML 자료의 CSP |
| I12 | 기계는 merge 하지 않는다 · origin 으로는 미러가 민다 | `core/mirror.js` 의 ff-only `syncWithOrigin` · 강제 push 없음 |
| I13 | 정렬은 상태를 보지 않는다 · 읽는 경계에서 개행 정규화 · 실패는 조용하지 않다 · 토큰 원문은 저장하지 않는다 · 빌드는 스스로 검증한다 | `scan.readText` · `auth`(SHA-256 만) · `upgrade.sh` 의 대조 · `build-ctx` 의 probe |

### 2.4 거부한 설계 — 다시 제안되는 것들

| | 왜 안 했나 |
|---|---|
| 섹션의 최신성을 저장 · 상태 필드로 밀림 관리 | 저장하면 반드시 낡는다(I8). 질의 시점에 계산한다 |
| 미반영을 오류로 막기(v0.x 의 「파생 누락」) | 기록과 섹션을 한 세션에 쓰게 강제해 섹션이 근거보다 커지고 복제됐다(파생 검토 §2). 상태로 두고 도구가 같이 낸다(I7) |
| 반영과 구조를 다른 사람에게 | 「구조 필요」 왕복이 생기고 한 판단을 둘이 나눠 진다 — 큐레이터 하나가 둘 다(개편안 V2) |
| 서버가 LLM 으로 반영 | 판단과 글은 사람의 세션 — 서버는 검사 · 커밋만(I11) |
| 모드 플래그(옛 규칙 · 새 규칙 둘) | 모든 판정에 두 갈래가 생긴다 — v1.0 은 플래그 없이 전환(V14) |
| `CLAUDE.md` 에 절차 | 스킬과 중복 — 한쪽만 고쳐진다 |
| RAG · 임베딩 | 가까운 것과 맞는 것은 다르다 |
| 화면에서 쓰기 · 섹션 점유 | 쓰기는 save 하나 · 낙관 잠금(`applied`)이 맞는 도구다 |
| 알림 · 구독 · 코멘트 | git 밖 데이터가 생기는 순간 저장소가 필요해진다 — 명부 · 대장이 유일한 예외다 |
| 서버의 자동 pull | 그 트리의 유일한 작성자다 — ff-only 맞추기는 사람이 누른다 |

## 3. 개발 환경

```bash
node --version            # 20.x — .nvmrc · engines.node >=20
npm ci                    # npm install 이 아니다 — lock 이 실제 판을 고정한다
npm run build && npm start    # 화면을 빌드하고 개인 서버로 viewer/fixture 를 연다 — http://127.0.0.1:7373
```

`npm ci` 만 하면 빌드가 돈다 — 망에서 더 받아 오지 않는다. **worktree 에서 일하면** `node_modules` 가 없다 — 메인 체크아웃의 것을 junction
(Windows `mklink /J node_modules <메인>\node_modules`)으로 잇는다.

| 하려는 것 | 명령 |
|---|---|

### 5.2 하네스 — `npm run verify`

`ops/verify/run.mjs` — 번호 붙은 검증 항목 백여 개를 한 자리에서 돈다. fixture 를 임시 폴더에 복사하고 `ctx serve` 를 `--port 7377`(동시 기록은

번호는 설계서 §10 의 1~69 에서 시작해 판마다 더했다 — v1.0 이 더한 것이 118~138 이다. **남은 항목의 번호는 바꾸지 않는다**(옛 `result.json`

함께 적혀 있다 — 항목을 걷을 때도 그 표에 한 줄을 남긴다. 화면 항목은 `ops/out/web` 이 있어야 돈다(`npm run build` — 없으면 skip).

| 플래그 | |
|---|---|
| `--port <n>` | 서버 포트(기본 7377) |
| `--slow` | 시간이 걸리는 항목까지 |

**실패를 읽는 법** — 각 줄이 번호 · 무엇을 봤나 · 실측값이다. 줄줄이 ✗ 면 **첫 ✗ 의 stderr** · 미러 서버의 `serve.log` · 기계 부하부터 본다.
하네스가 초록이 아니면 커밋하지 않는다.

## 7. 서버 — `ctx serve`

### 7.1 한 프로세스

```
ctx serve --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data \
          --bind <IP> --port 7374 --web /opt/cdp/web --mirror
          [--manual <dir>] [--forms <dir>] [--kit <dir>] [--private-pages] [--admin-from <CIDR,…>]

  /healthz · /install.mjs · /site/*        공개 — 집계 · 설치기 · 소개 · 설명서
  / · /manual · /setup · /login · /r/… · /console/…   화면(같은 index.html · SPA)
  /login /logout /me                       세션 쿠키(HMAC · data/secret)
  /api/<repo>/…                            읽기 API + 첨부 · 문서 지우기 · 기록으로 둠 · 기준선
  /mcp/<repo>                              MCP Streamable HTTP(Bearer)
  /admin/…                                 관리 API(쿠키 + admin + 재인증)
  /repos · /workrepos · /kit/<repo>        레포 목록 · 작업 레포 대장 · kit
```

`viewer/bin/ctx-mcp-serve.mjs` 가 전부다. MCP 서버는 `ctx-mcp.mjs` 의 `buildServer()` 를 **요청마다** 만든다 — 그때 인증 결과를 들고 있어
역할에 없는 도구는 등록하지 않는다(9장). `forms/` · `kit/` · `manual/` 은 인자가 없으면 번들 옆(`bin/../`)을 찾고, 소스로 돌 때는 `agent/` ·
`manual/` 을 찾는다.

### 7.2 레포 저장소 — `core/store.js`

- `--root` 의 **하위 폴더가 레포**다 — `_vocab.md` 가 있는 것만. 폴더명 = 레포 이름(`REPO_NAME_RE`).
- 목록은 60초에 한 번 다시 훑는다. 모르는 이름이 오면 그 자리에서(`store.ensure`) · 세우거나 치운 뒤에는 즉시.
- 레포마다 캐시 — 스탬프가 바뀌면 통째로 교체한다. 부분 갱신은 없다. 감시자를 쓰지 않는다.
- **서버는 스스로 pull 하지 않는다**(I12). `save` 가 커밋하고 `--mirror` 가 **큐**(`core/mirror.js` · 레포당 하나)로 push 한다. 실패는
  `classifyPushError` 로 사유를 갈라 기억하고, non-ff 면 fetch 해서 `ahead/behind` 를 채운다. 상태 한 값 — `mirror.stateOf()` →
  `off · ok · lag · diverged · behind`. `/repos` · `/admin/repos` · `/healthz` · 현황 · doctor · `brief` · 상태 표시줄이 **같은 함수**를 본다.
- 복구 셋 — `POST /admin/repos/<이름>/{sync,push,restore}`(ff-only 맞추기 · 다시 보내기 · 트리 되돌리기) · 재인증 뒤 · save 와 같은 뮤텍스.

### 7.3 인증 — `core/auth.js`

```
auth.json   users[] { name label repos role curate active }      ← 권한은 여기
            tokens[] { sha256 id user issued expires note status }  ← 원문 없음
data/secret 세션 쿠키 서명 키(32바이트 · 자동 · 600)
```

| 규칙 | 구현 |
|---|---|
| 토큰 원문은 `issue()` 가 한 번 반환하고 SHA-256 만 저장 | 잃으면 `reissue`(폐기 + 발급) |
| `decide()` 다섯 단계 — 없음 · 무효 · 만료 · 고아 · 중지 | 화면의 실패 메시지는 하나 — 구분은 `serve.log` 에만 |
| 권한 묶음 `grantOf()` — `role` · `write` · `admin` · `allow(repo)` · **`curate(repo)`** | `curateOf(u)` — admin 은 `['*']` · writer 는 `curate` 목록 · viewer 는 `[]`. 볼 수 없는 레포는 큐레이션할 수 없다 |
| 발급 · 명부 편집은 CLI(`serve init/user/token`)와 관리 콘솔(`/admin/*` — 세션 + `cdp_su` 재인증 15분) | 사용자가 요청하는 엔드포인트는 없다 |
| `save` 의 `author` 는 서버가 토큰의 사용자로 채운다 | 클라이언트가 보내면 `E_INPUT` |
| 기본 만료 — admin 30일 · 나머지 90일 | `issue` 가 역할로 정한다 |
| 감사 로그 `data/logs/auth.log` — 발급 · 폐기 · 명부 · 레포 · 미러 단추(토큰 앞 8자) | 회전하지 않는다 |

### 7.4 개인 서버 — `--personal <레포>`

## 8. save

`core/save.js` 의 `save(root, input, { user, write, admin, curate, mirror, … })` — **한 번의 save 가 한 커밋이다**(I2). 레포당 뮤텍스(`core/lock.js`)
안에서 돈다.

### 8.1 단계

```
1   권한         write 가 없으면 E_FORBIDDEN
2   스키마       work · sections · vocab · managed · edits · assets · baseline · examples · dryRun
2.1 역할         curate 가 아니면 curatorOnly() — sections · managed · edits · examples · baseline · work.curates · 예약 태그 → E_FORBIDDEN need: curate (I6)
2.2 큐레이션     work.curates 정규화 · 중복 · touches 없음 · into 가 이번 sections 에 있나(전환 기록 transition 은 예외) · touchesEmpty 큐레이션 · 태그 curate
2.3 기준선       baseline[] 이면 touches 없음 · source 필수 · touchesEmpty 기준선 · 태그 baseline · 큐레이션과 섞지 않는다
3   존재         같은 id 의 기록이 있으면 E_EXISTS (I3)
3.5 트리         더러우면 E_GIT { reason: dirty }
3.7 좌표 0       touchesEmpty 없이 빈 touches 면 E_INPUT
4~6 쓰기         임시 스냅샷(Snap)에 — 어휘 더하기(있는 좌표는 건너뜀) · 등록부 연산(planManaged) · 서식에서 빈 문서(stampDoc) · 섹션 치환(applied 낙관 잠금) · 기준선 블록 갈아 끼우기 · edits · 첨부
7   기록         작업 기록 파일 — author 는 토큰의 사용자
8   검사         runBuiltinCheck 전 · 후 → 이 save 가 새로 만든 error 만 막는다(I10 · V21) · 원래 있던 오류는 warnings
9   커밋         한 커밋 · 훅 없음 — 같은 함수로 이미 검사했다(V5)
10  미러         (뮤텍스 밖) --mirror 면 큐에 넣고 잠깐 기다려 mirror · mirrorReason · mirrorLast · warnings
```

- **`applied`** — 클라이언트가 보낸 값은 **낙관 잠금으로만** 쓴다(읽었을 때와 다르면 `E_CONFLICT` · detail 에 `current` · `currentWork` · `currentCuration`(반영해 고친 큐레이션 기록) · `content`).
  새 값은 서버가 계산한다 — 이 save 의 `curates` 중 `into` 에 그 좌표가 있는 기록의 가장 늦은 것(날짜 → id). **뒤로 가지 않는다** — 지금
  applied 가 더 늦은 작업 기록이면 그것을 둔다(옛 날짜 편입 기록만 반영한 save 가 늦은 기록을 미반영으로 되살리지 않게). 판정 없이 섹션만
  고치면 그 큐레이션 기록 자신.
- **`dryRun`** — 검사까지 돈 뒤 스냅샷을 되돌리고 커밋하지 않는다. 큐레이터의 「판정표 + diff」 승인 · 화면의 지우기 미리보기가 쓴다.
- **`managed`** — `core/managedops.js` 의 `planManaged`(순수)가 계획을 세운다 — `add`(새 행은 마지막 규칙 행 뒤 · 앞 행에 덮이면 거절 · 한 문서
  한 레벨 · 걸리는 기존 좌표는 `needSections` · `form` 이면 `stampDoc`) · `rename` · `merge` · `retire` · `drop`(거절 판정 · 가리키는 줄은
  `core/docdrop.js` · `core/docrefs.js`).
- **`edits`** — `core/edits.js` — `old` 가 정확히 한 번 · 못 쓰는 자리(좌표 섹션 · applied · 어휘 줄 · 등록부 행 · `work/`).
- **기준선** — `core/baseline.js` — 블록은 `**경과**` 앞에 · 큐레이션 save 의 `body` 에 블록 표지가 있으면 거절.
- 화면이 부르는 save 셋(`POST /api/<repo>/docs-drop` · `/curate` · `/baseline`)은 서버가 작업 기록을 지어 **같은 `save`** 를 탄다 — 검사 · 커밋 · 로그가 같다.

### 8.2 오류 코드

`CtxError(code)` — `core/errors.js`. `E_COORD` · `E_INPUT` · `E_NOT_FOUND` · `E_REPO` · `E_AUTH` · `E_FORBIDDEN`(`need: curate` 면 역할) ·
`E_CONFLICT`(섹션 · edits · managed) · `E_GIT`(`reason: dirty`) · `E_EXISTS` · `E_CHECK`(`detail.findings` — 이 save 가 만든 것). MCP 는 `isError: true` 로
싸고, HTTP 는 상태 코드를 붙인다. 서버의 오류 문장이 **다음 할 일**을 말한다 — 스킬이 그 문장을 그대로 전한다.

## 12. kit · 설치기

### 12.1 kit — `core/kit.js`

`kitFiles({ role })` — kit 폴더(`--kit` → `CDP_KIT` → 번들 옆 `kit/` → 소스 `agent/`)에서 **역할의 kit** 을 낸다. writer 는 `WRITER_SKILLS`
(cdp-work · cdp-save · cdp-push) + `CLAUDE-프로젝트레포.md`, 큐레이터는 스킬 여섯 + `CLAUDE-큐레이터.md`. 블록은 작업 레포 쪽 이름
`.claude/work-repo/CLAUDE.md` 로 실린다. `hashOf(files)` 가 kit 해시 — 작업 레포 `CLAUDE.md` 의 `<!-- cdp:kit <해시> -->` 와 대 보아 「낡음」 을 안다.
**kit 을 읽는 자리는 모두 같은 폴더를 본다** — `/kit` · `brief` 의 `sync.kit` 해시 · load 프롬프트가 읽는 스킬이 서버의 `--kit` 을 따른다
(`buildServer({ kitDir })` · 하네스 57). 한 자리만 번들을 보면 「낡음」 이 거꾸로 뜬다.

`GET /kit/<repo>` — 토큰의 역할로 kit 을 고른다(`?role=writer` 면 writer). **`?workrepo=<id>`(등록된 작업 레포)는 늘 writer kit** 이다 —
팀이 같이 커밋하는 자리라 설치한 사람의 역할을 따르면 큐레이터 스킬이 그 레포에 들어가고 대장이 늘 「낡음」 이 된다. 다른 레포의 등록이면
409 · `&as=json` 은 설치기가 받는 모양 · 없으면 꾸러미 zip(`설치.md` · `install.mjs` · `kit/`). 큐레이터 kit 은 큐레이터 폴더
(`?as=json&role=curator` · 등록 없이)에만 간다.

### 12.2 설치기 — `viewer/bin/cdp-install.mjs`

| 모양 | 하는 것 |
|---|---|
| 한 줄 `--repo <r> --workrepo <id> <폴더>` | 공개 `GET /install.mjs`(서버 주소만 박힌 설치기)를 임시 폴더에 받아 돈다 → 토큰 확인(없으면 숨김 입력 · `core/tokenstore.js` 로 이 PC 에 둘지) → kit 을 그 토큰으로 → `core/setup.js` 의 `planSetup` · `applySetup` 으로 병합 → 대장에 보고 → 이 PC 의 설치 목록(`core/localreg.js`)에 적는다 |
| `--update [--commit] [--dry]` | 설치 목록의 작업 레포 전부를 새 kit 으로 · `--commit` 은 바꾼 파일만(그 파일에 원래 변경이 있으면 커밋하지 않는다) |

| 꾸러미 zip 의 `install.mjs <폴더>` | 설정 한 줄이 박힌 같은 설치기 · 옆의 `kit/` 을 쓴다 |

**병합 규칙은 `core/setup.js` 한 벌이다** — `CLAUDE.md` 는 `<!-- cdp:begin -->` … `<!-- cdp:end -->` 블록만 · `.mcp.json` 은 `cdp` 항목만(`mcpEntryServer`) ·

| info | `curation-pending` | 미반영 섹션 — v0.x 의 `derive-missing`(error)이 이것이 됐다 |
| info | `thin-body` · `single-coord` · `no-touches-key` | |
