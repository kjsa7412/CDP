## 1. CDP 가 무엇인가 — 개발자의 눈으로

### 1.1 한 줄과 두 층

**대상마다 정본이 하나 있고 그 자리를 좌표로 부른다.** 작업 기록(`work/` · 사건 · 불변)과 관리
문서(`docs/` · 상태 · 가변)를 좌표가 잇고, 관리 문서 섹션이 어느 기록까지 실었는지 `applied`
한 줄로 적는다. **그 한 줄이 유일한 규약이고 나머지는 전부 거기서 나온다** — 최신성 계산
`later(기준, 좌표)` 하나, 검사(`ctx check`), 화면, MCP 도구가 모두 같은 함수를 부른다.

### 1.2 세 역할과 산출물 흐름

```
개발자 (이 문서)                  관리자                                사용자
────────────────                 ──────────────────────────────         ──────────────────
소스 레포 고친다                                                        
npm test · verify · check:packages
태그 v* push
  └─▶ release.yml ──▶ cdp-v<버전>-win.zip ─────▶ 로컬형: xcopy → 지식 레포 · ctx setup ─▶ clone · ctx setup · cdp.exe
                 └──▶ cdp-server-v<버전>.tar.gz ▶ 서버형: install.sh · repo new · init ──▶ 꾸러미 zip → 작업 레포 · CDP_TOKEN
                 └──▶ SHA256SUMS
```

관리자는 CDP 를 만들지 않고, 사용자는 세우지 않는다. **개발자가 넘기는 것은 산출물 둘과
그 안의 문서**다 — 산출물에 없는 것은 받는 쪽에 없는 기능이다.

### 1.3 정본이 어디인가

| 무엇 | 정본 | 사본 (고치면 다음 빌드에 덮인다) |
|---|---|---|
| 판정 · 계산 | `core/` | — (앱 · `ctx` · MCP 가 같이 부른다) |
| 받는 사람에게 가는 것 — 스킬 · 규약 · 훅 · 레포 안 매뉴얼 · 패키지 | `agent/` | `viewer/fixture/.claude` · 배포본 `knowledge-repo-*/` · 지식 레포 · 작업 레포의 `.claude/skills` |
| 사람이 실행하는 명령 · 빌드 · 릴리스 · 배포 스크립트 | `ops/` | `ops/out/` · `ops/release/` (추적 안 함) |
| CLI · MCP · 서버 소스 | `viewer/bin/` | 번들 `ops/out/ctx/ctx.mjs` · `viewer/fixture/bin/ctx.mjs`(편의 사본 · 추적) |
| 화면 | `viewer/src/` | `ops/out/web/` |
| 설계 · 검토 · 우리만 보는 것 | `docs/` | — |
| **역할별 제품 설명서** | **`manual/`** (이 문서가 여기 있다) | `agent/manual/` 은 지식 레포로 들어가는 **짧은 판** |
| 단위 테스트 | `test/` | — |
| CI · 릴리스 워크플로 | `.github/workflows/` | — |

## 2. 구조

### 2.1 폴더

```
core/                    **계산 — 정본.** 앱과 ctx 와 MCP 가 같이 쓴다
  repo.js scan.js frontmatter.js vocab.js managed.js validity.js check.js search.js indexes.js
  tools.js               MCP 도구 12종의 순수 함수 (ctx --json 과 바이트 동일)
  auth.js                명부 · 토큰 · 세션 서명        save.js  서버의 save
  setup.js               작업 레포 세팅 계획 · 적용      sync.js  동기화 순서 (앱 · ctx 공용)
  packages.js reponew.js importdir.js                  패키지 · 레포 세우기 · md 들이기 (제품화)
  store.js git.js zip.js workrepos.js appstate.js appinfo.js logger.js

viewer/                  뷰어 프로그램
  server/                로컬 앱 서버 (index.js) · adapter/ HTTP + SSE · 트레이 · 토큰/Origin/경로 봉인
  src/                   화면 (React). components/admin/ 에 관리 화면
  bin/                   ctx 소스 — ctx-cli · ctx-mcp · ctx-mcp-serve · ctx-setup-server · ctx-serve-doctor
                         ctx-package · ctx-repo · ctx-import · cdp-install(꾸러미 실행기) · ctx · ctx.cmd
  fixture/               **뷰어 개발용 지식 레포.** 배포본에 안 들어간다

agent/                   **받는 사람에게 가는 것의 원본**
  skills/                cdp-work · load · save · import · edit · managed · push
  CLAUDE-지식레포.md · CLAUDE-프로젝트레포.md(블록) · TEMPLATE-work.md
  hooks/pre-commit       유일한 결정론적 보증 층
  manual/                system(정본) · user · admin  → 레포 안 MANUAL*.md
  packages/<이름>/       문서 골격 · _managed.md · _vocab.md · _package.json
  gitattributes · gitignore · install.md

ops/                     **명령**
  setup · dev · start · check · seed · release  (.cmd — npm 을 모르는 사람용 껍데기)
  lib/                   build-ctx · build-exe · assemble(조립 하나) · release · release-server · seed-kit
  deploy/                install.sh · upgrade.sh · cdp-serve.service · Dockerfile · docker-compose.yml · 설치절차.md
  verify/run.mjs         검증 하네스
  out/  release/         산출물 (추적 안 함)

test/                    단위 테스트 — node:test · 의존성 0
.github/workflows/       ci.yml · release.yml
docs/                    design/(보존) · dev/(메모) · attic/(끝난 것) · 관리문서패키지/ · 그림/ · 용어.md
manual/                  제품 설명서 세 권 — 원천
```

**루트에 남는 것은 도구가 요구하는 자리와 제일 위에 있는 것뿐이다** — `package.json` ·
`package-lock.json`(npm) · `.gitattributes` · `.gitignore`(git) · `README.md` · `core/` · `manual/`.
`node_modules/` 만 예외다 — `viewer/` 와 `ops/lib/` 가 둘 다 외부 의존을 쓰므로 루트에 있어야 한다.

### 2.2 층

```
core/                    HTTP 를 모른다.  파일 · 계산 · 판정
viewer/server/adapter/   로컬 앱 — HTTP + SSE · 트레이 · 보안 봉인      ─┐ 같은 core 를 부른다
viewer/bin/ctx-cli.mjs   CLI                                          ─┤
viewer/bin/ctx-mcp.mjs   MCP 서버 (전송을 모른다 — stdio · HTTP 공용)   ─┤
viewer/bin/ctx-mcp-serve.mjs   서버 — MCP(HTTP) + 읽기 API + 화면 + 관리 API  ─┘
viewer/src/              화면 — 마크다운 렌더는 전부 클라이언트가 소유한다
```

`core/` 가 루트에 있는 이유 — 앱과 `ctx` **양쪽의 상위**다. 어느 한쪽 밑에 두면 "누가 누구의
일부인가" 가 폴더와 어긋난다. 보안 심사가 localhost 리스너를 막으면 `adapter/` 만 갈아 끼우고
`core/` 와 화면은 그대로 쓴다.

### 2.3 불변조건 — 깨면 시스템이 거짓말을 시작한다

| # | 불변조건 | 깨지면 |
|---|---|---|
| 1 | **판정은 `core/` 한 곳** | 화면과 커밋 판정이 갈라지고, 사람은 화면을 믿는다 |
| 2 | **`later()` 는 하나** | 세 질문(기록 최신성 · 섹션 파생 · 좌표 최신 기록)의 답이 안 맞는다 |
| 3 | **`work/` 는 불변** | 사건을 고치면 그 시점의 판단이 사라진다 |
| 4 | **좌표는 `_vocab.md` 에만** | 두 이름이 갈라지고 좌표가 좌표가 아니다 |
| 5 | **결정론적 보증은 git 훅(서버형은 `save` 의 검사)뿐** | LLM 선의에 의존하는 층이 생긴다 |
| 6 | **error 등급을 함부로 늘리지 않는다** | `--no-verify` 가 관행이 되고 보증이 사라진다 |
| 7 | **없는 상태를 화면에 그리지 않는다** | "밀림" 이 정상 범주가 된다. 사실과 오류만 있다 |
| 8 | **정렬은 상태를 보지 않는다** | 같은 것을 두 번 봐도 자리가 달라진다 |
| 9 | **읽는 경계에서 개행을 정규화한다** | CRLF 클론이 조용히 아무것도 못 읽는다 |
| 10 | **기계가 merge 하지 않는다** | 섹션 두 갱신이 섞인 결과가 정본 자리에 앉는다 |
| 11 | **push 는 사람이 (서버형은 서버의 미러)** | 되돌릴 수 없는 것을 기계가 한다 |
| 12 | **CDN 을 타지 않는다** | 개발 PC 에서는 정상, 폐쇄망에서 조용히 다르게 그려진다 |
| 13 | **빌드가 스스로 검증한다** | 반쪽 exe 가 정상으로 배포된다 |
| 14 | **번들 시각이 찍힌다 (`ctx version`)** | 낡은 번들이 다른 답을 내는데 아무도 모른다 |
| 15 | **MCP 도구의 결과는 `ctx <명령> --json` 과 바이트까지 같다** | 통로에 따라 다른 답을 낸다 — 하네스가 대조한다 |
| 16 | **토큰 원문은 저장하지 않는다 · 발급은 서버 셸에서만** — v0.10.0: 관리자 콘솔에서도(세션 + 재인증 15분). 사용자가 요청하는 길은 여전히 없다 | 명부가 열쇠 다발이 된다 |

### 2.4 거부한 설계 — 다시 제안되는 것들

| | 왜 안 했나 |
|---|---|
| 상태 필드로 밀림 관리 | 상태로 보이면 정상 범주가 된다. 오류여야 막힌다 |
| 문서 단위 최신성 | 좌표가 여럿인 문서에서 반드시 둘 중 하나가 틀린다 |
| 최신성을 저장 | 저장하면 반드시 낡는다. 질의 시점에 계산한다 |
| `CLAUDE.md` 에 절차를 적기 | 스킬과 중복. 한쪽만 고쳐진다 |
| 하네스 훅으로 절차 강제 | 비결정을 비결정으로 덮는 것이다. 뒤에 결정론적 2층이 있다 |
| RAG · 임베딩 | 가까운 것과 맞는 것은 다르다 |
| 뷰어에서 쓰기 | 쓰기는 pull 선행이 필수인데 앱이 그것을 강제할 수 없다 |
| exe 를 git 에 커밋 | 68MB 는 이력에서 되돌릴 수 없다 |
| HTTP 로 토큰 발급 | 명부는 서버 셸의 것 (MCP 설계서 §4.4.1) |
| 알림 · 구독 · 코멘트 | git 밖 데이터가 생기는 순간 저장소가 필요해진다 — 명부가 유일한 예외다 |
| 서버가 pull | 서버는 그 트리의 유일한 작성자다. 바깥에서 바꿨으면 사람이 `pull --ff-only` |
| `cdp-managed` 모드 B | **미결(R15).** 서버형에는 작업 트리가 없다 — 설계서 §4.8 을 먼저 고친다 |

## 3. 개발 환경

### 3.1 준비

```bash
node --version            # 20.x — .nvmrc · engines.node >=20.  SEA 빌드 · 서버 절차 · 실측 전부 20 기준
git --version
npm ci                    # npm install 이 아니다 — lock 이 실제 판을 고정한다
npm run build && npm start
```

`npm ci` 만 하면 빌드가 돈다 — **망에서 뭔가를 더 받아 오지 않는다.** exe 빌드의 `postject` 도
`devDependencies` 에 정확한 판(`1.0.0-alpha.6`)으로 박혀 있다.

### 3.2 명령

| 하려는 것 | 명령 |
|---|---|
| 화면 개발 (HMR) | `npm run dev` (Vite 5173) + 다른 터미널에서 `npm run dev:server` 또는 `node viewer/server/index.js --repo <경로> --dev http://localhost:5173 --no-open` |
| 빌드된 화면으로 실행 | `npm start` — `viewer/fixture/` 로 뜬다. 다른 레포는 `node viewer/server/index.js --repo <경로>` |
| CLI 를 소스로 | `npm run ctx -- check` · `npm run ctx -- brief --repo <경로>` |
| ctx 번들 | `npm run build:ctx` → `ops/out/ctx/ctx.mjs`. `CDP_REPO=<지식레포>` 가 있으면 그 레포의 `bin/` 도 갱신 |
| exe | `npm run build:exe` → `ops/out/exe/cdp.exe` |
| fixture 재생성 | `npm run seed`(GDI 덤프 필요) · `npm run seed:kit`(`.claude/` 만 · `agent/` 에서) |
| 검사 | `npm test` · `npm run verify` · `npm run check:packages` |
| 릴리스 | `npm run release [-- <버전>]` · `npm run release:server [-- <버전>]` — 6장 |

`ops\*.cmd` 는 같은 것을 하는 껍데기다(npm 을 모르는 사람용). `.cmd` 는 **CP949** 로 쓴다 —
cmd.exe 가 OEM 코드페이지로 읽는다.

### 3.3 fixture

`viewer/fixture/` 는 **뷰어 개발용 지식 레포** 한 가지 용도다. 배포본에 안 들어가고 데이터 보관도
아니다. `.claude/` 는 추적하지 않고 `seed:kit` 이 `agent/` 에서 만든다(사본이 원본 노릇을 하던
시절에 스킬이 세 번 갈렸다). `bin/ctx.mjs` 는 반대로 추적한다 — clone 만 하면 샘플이 바로 돌게.
**커밋 가능한 정상 레포**여야 한다 — clone 직후 커밋이 막히는 샘플은 폐쇄망 반입 검증을 무의미하게 한다.

## 4. 고치기 — 어디를 어떻게

### 4.1 어디를 고치나

| 바꾸려는 것 | 자리 | 같이 볼 것 |
|---|---|---|
| 판정 — 검사 · 최신성 · 어휘 · 등록부 파서 | `core/check.js` `validity.js` `vocab.js` `managed.js` | `test/*.test.mjs` · 하네스 · 설계서 §1 · 불변조건 1 · 2 |
| MCP 도구의 **형태** | `core/tools.js` (순수 함수) | CLI `--json` 이 같은 것을 낸다 · 하네스가 바이트 대조 · 8장 |
| MCP 도구의 **명함**(description) | `viewer/bin/ctx-mcp.mjs` 의 `CARD` | MCP 설계서 §2.2 표 — **그대로 옮긴다. 요약하지 않는다** |
| CLI 명령 · 플래그 | `viewer/bin/ctx-cli.mjs` (`USAGE` · `parseArgs` · 분기) + `ctx-*.mjs` | `README.md` 의 ctx 표 · 부록 B |
| 서버 — HTTP · 관리 API · `save` · 미러 | `viewer/bin/ctx-mcp-serve.mjs` · `core/save.js` · `core/auth.js` | MCP 설계서 §4 · §6 · 하네스 §10 |

### 4.2 규칙

| 규칙 | 왜 |
|---|---|
| **`agent/` 의 판정 기준은 "받는 사람에게 가는가"** — 도구를 만드는 사람만 보는 것은 `docs/` | 두 폴더가 섞이면 릴리스가 무엇을 싸야 하는지 사람이 기억해야 한다 |
| **`docs/` 의 판정 기준은 "보존되는가"** — `dev/` 는 메모, `attic/` 은 끝난 것 | `dev/` 와 `design/` 이 어긋나면 `design/` 이 맞다 |

| **커밋 메시지 — `무엇을 한다 — 왜` 한 줄 + 근거 본문** | `git log` 가 설계 이력이다. 실측 수치가 있으면 적는다 |
| **`CHANGELOG.md` 의 그 판 절을 같이 고친다** | 릴리스 노트가 여기서 나온다(`release.yml`) |
| **error 등급을 늘릴 때는 설계서를 먼저** | 불변조건 6 |
| **`.gitattributes` 를 건드리지 않는다** — `*.sh` · `viewer/bin/ctx` · `**/pre-commit` 은 LF, `*.cmd` 는 CRLF | 훅이 CRLF 로 나가면 조용히 죽는다. 이 레포가 한 번 당했다 |
| **CDN · 런타임 다운로드 금지** — 폰트까지 인라인 | 불변조건 12 |
| **의존성은 선언한다** — `npx --yes` 금지 | `npm ci` 로 재현되지 않는 빌드는 되살릴 수 없다 |
| **서버 · 하네스 · 배포 스크립트의 메시지는 한글 + 영문 병기** | C 로캘 콘솔에서도 읽힌다 |

## 5. 검증

### 5.1 단위 테스트 — `npm test`

`test/*.test.mjs` 12파일 · `node --test test/` · 의존성 0. **파일 시스템 밖(네트워크 · 시계)에
기대지 않는다** — 시각이 필요한 함수는 `now` 를 인자로 받는다(`toolBrief(r, { now })` ·
`expiresInDays`). 임시 폴더는 `os.tmpdir()` 아래에 만들고 지운다.

| 파일 | 무엇 |
|---|---|
| `auth` | `decide` 5단계(토큰 없음 · 무효 · 만료 · 고아 · 중지) · `userAdd/Set/List` · `issue` · `revoke` · 세션 서명 왕복 · v1.0 형식 거부 |
| `setup` | `mergeClaude` · `kitOf` · `mergeMcpJson` · `mcpEntryLocal`(win32 · posix · `--also`) · `mcpEntryServer` · `desktopConfigPath` · `mergeDesktopConfig` |
| `vocab` · `managed` · `validity` · `frontmatter` | 파서 · `resolveCoord` · `later` 의 세 질문 · `supersedes` 순환 · `parseDoc` |
| `tools` | `checkCoord/checkId`(`..` · 제어문자 · 절대경로 · 한글 타입) · `guardSize` · `bundleAgeNotice` |
| `workrepos` · `zip` | 작업 레포 대장 · zip 왕복(한글 이름) |
| `packages` · `reponew` · `importdir` | 매니페스트 · `checkPackage` · `newRepo`(가짜 훅이 막는 경우 · bare origin push) · `planImport` 결정론 · 충돌 접미 · 링크 재작성 · `applyImport` 되돌리기 |

첫 테스트가 실제 버그를 잡았다 — `parseManagedSections` 의 applied 주석 탐색이 다음 제목을
넘어가 섹션 수가 하나 부풀었다. **테스트를 추가할 때는 `core/` 의 함수를 직접 부른다.** CLI 나
서버를 띄우는 것은 하네스의 일이다.

### 5.2 하네스 — `npm run verify`

`ops/verify/run.mjs`. MCP 설계서 §10 의 검증 항목 69줄과 제품화 70~74 를 **한 자리에서** 돈다.

```
하는 일
  ① fixture 를 임시 폴더에 복사한다 — 복사 전에 seedKit 이 .claude/ 를 agent/ 에서 만든다 (fresh clone 에서도 돈다)
  ② ctx mcp (stdio) 를 호스트처럼 spawn 해 initialize · tools/list · tools/call 을 대조한다
  ③ ctx serve 를 --port 7377 로 띄워 HTTP 로 로그인 · 읽기 · save · 충돌 · 검사 실패 · 미러 · 꾸러미 · POST /repos 를 돈다
  ④ 도구 결과와 ctx <명령> --json 을 바이트로 대조한다
결과  ✓ 통과 · ✗ 실패 · – 건너뜀(사람이 보는 항목 · 브라우저)     ops/out/verify/result.json
지금  ✓ 57  ✗ 0  – 17
```

| 플래그 | |
|---|---|
| `--port <n>` | 서버 포트(기본 7377). CI 와 로컬이 같은 값을 쓴다 |
| `--slow` | 시간이 걸리는 항목까지 |
| `--built-at <시각>` | (20번) `brief` 의 90일 경고를 시험하기 위해 번들 시각을 주입한다 — **하네스 전용 플래그**다 |

**실패를 읽는 법** — 각 줄이 번호 · 무엇을 봤나 · 실측값이다. `result.json` 에 요청과 응답이 남는다.
52번이 깨진 채 이틀이 갔던 것이 CI 를 P0 으로 올린 이유다 — 하네스가 초록이 아니면 커밋하지 않는다.

### 5.3 패키지 — `npm run check:packages`

`ctx package check --all`. 패키지마다 조립 함수로 임시 폴더에 **부어서** `loadRepo` +
`runBuiltinCheck` 를 돌리고, 등록부가 가리키는 문서가 있는지, `example:` 어휘 줄의 섹션이
문서에 있는지 본다. fail 이면 exit 1 — 릴리스가 깨진 패키지를 싸는 일이 없다.

### 5.4 CI — `.github/workflows/ci.yml`

| 잡 | 무엇 |
|---|---|
| `linux` (ubuntu · Node 20) | `npm ci` → `build` → `build:ctx` → `test` → `check:packages` → `verify` → `npm audit --omit=dev`(**경고만** · R16) → `result.json` 을 artifact 로 |
| `windows` | `npm ci` → `build:ctx` → `test`. exe 빌드는 릴리스에서 |

**워크플로가 부르는 명령은 전부 `package.json` 의 스크립트다.** CI 에만 있는 명령이 있으면
"CI 에서는 되는데 내 PC 에서는 안 된다" 가 생긴다. push 마다 · PR 마다 돈다. 같은 브랜치의 이전
실행은 취소된다(`concurrency`).

## 6. 릴리스

### 6.1 절차

```
1  package.json 의 version 을 올린다                          0.9.0 → 0.9.1
2  CHANGELOG.md 에 ## v0.9.1 절을 쓴다                        무엇이 바뀌었나만.  왜는 커밋과 설계서에
3  npm test · npm run verify · npm run check:packages        셋 다 초록
4  커밋 · push
5  git tag -a v0.9.1 -m "…" && git push origin v0.9.1       ← release.yml 이 돈다
6  GitHub Release 에 셋이 붙었는지 본다                       cdp-v0.9.1-win.zip · cdp-server-v0.9.1.tar.gz · SHA256SUMS
7  첫 릴리스는 로컬 npm run release 와 대조한다              cdp.exe ctx version · 크기 (제품화 검토 §8 위험 1)
8  관리자에게 알린다 — 관리자 설명서 9장(갱신)
```

**태그와 `package.json` 버전이 다르면 `release.yml` 이 실패한다.** 태그 없는 0.8.0 이 다시 생기지
않게 — 태그와 `package-lock.json` 둘 다 있어야 그 버전을 다시 만들 수 있다.

### 6.2 `release.yml` 이 하는 일

| 잡 | 러너 | 무엇 |
|---|---|---|
| `version` | ubuntu | `v<태그>` == `package.json` 아니면 실패 |
| `windows` | windows | `npm run release -- <버전>` → `ops/release/v<버전>/*` 를 `cdp-v<버전>-win.zip` 으로 |
| `server` | ubuntu | `npm run release:server -- <버전>` → `cdp-server-v<버전>.tar.gz` |
| `publish` | ubuntu | `sha256sum * > SHA256SUMS` · `CHANGELOG.md` 의 그 절을 노트로 · `gh release create` |

### 6.3 로컬에서 같은 것을

```bash
npm run release [-- 0.9.1] [-- --no-build]          # 화면 → ctx 번들 → exe → ops/release/v<버전>/
npm run release:server [-- 0.9.1] [-- --no-build]   # 화면 → ctx 번들 → ops/out/server/cdp-server-v<버전>/ + .tar.gz
```

| 산출물 | 안에 | 누구에게 |
|---|---|---|
| `ops/release/v<버전>/` | `cdp.exe` **하나**(루트) · `knowledge-repo-<패키지>/`(완성된 지식 레포 — 스킬 · 훅 · 규약 · 매뉴얼 3종 · `bin/ctx*` · 문서 골격 · 등록부 · 어휘 · 빈 `tools/`) · `설치.md` · `README.md`(패키지 표) | 로컬형 관리자 · 폐쇄망 |
| `ops/out/server/cdp-server-v<버전>/` | `bin/ctx.mjs` `ctx` `ctx.cmd` · `web/` · `packages/<이름>/`(exe 없음 · `_package.json` 없음) · `deploy/`(7파일) · `README.md` | 서버형 관리자 |

두 산출물의 지식 레포 폴더는 **같은 함수** `ops/lib/assemble.mjs` 가 만든다 — `_package.json` 과
`convert/` 는 빼고, LF 로 정규화하고, 빠진 것이 있으면 세어서 `exit 1`. `release.mjs` 는 마지막에
`cdp.exe ctx version` 이 날짜를 내놓지 않으면 실패로 보고 반쪽 파일을 지운다. 버전 폴더가 최근
2개를 넘으면 태그 없는 것을 알려 준다 — 지우지는 않는다.

### 6.4 관리자가 받은 뒤

`설치.md` · `deploy/README.md` · `deploy/설치절차.md` 가 산출물 안에 들어간다. 관리자 설명서
2 · 3 · 4 · 9장이 그 절차다. **산출물에 없는 문서는 받는 쪽에 없다** — 절차를 고쳤으면 그 파일을 고친다.

## 7. 서버 — `ctx serve`

### 7.1 한 프로세스

```
ctx serve --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data \
          --bind <IP> --port 7374 --web /opt/cdp/web --packages /opt/cdp/packages --mirror

  /healthz                 공개.  집계만 — 레포 이름을 싣지 않는다
  /login /logout /me       세션 쿠키 (HMAC · data/secret)
  /r/<repo>/…  + web/      화면 (정적)
  /api/<repo>/…            읽기 API (쿠키 · Bearer)
  /mcp/<repo>              MCP Streamable HTTP (Bearer)
  /repos  POST /repos      레포 목록 · 패키지에서 세우기(write)
  /packages                패키지 목록
  /workrepos …             작업 레포 대장 · 설치 보고
  /kit/<repo>?workrepo=    꾸러미 zip
```

`viewer/bin/ctx-mcp-serve.mjs` 가 전부다. MCP 서버 자체는 `ctx-mcp.mjs` 의 `buildServer()` 를
그대로 쓴다 — 전송만 HTTP 다(8장). 관리 화면은 로컬 앱과 **같은 빌드**(`web/`)를 서버가 내주며
`isServer` 로 메뉴가 갈린다(11장).

### 7.2 레포 저장소

- `--root` 의 **하위 폴더가 레포**다. `_vocab.md` 가 있는 것만. 폴더명 = 레포 이름
- 목록은 요청이 올 때 **60초에 한 번** 다시 훑는다(`refresh`). `POST /repos` 뒤에는 즉시
- 레포마다 캐시 — 요청마다 `_vocab.md` · `_managed.md` · `.git/HEAD` · `docs/` · `work/` 의 mtime 스탬프를 보고 바뀌었으면 **통째로** 교체한다. 부분 갱신은 없다. 감시자(chokidar)를 쓰지 않는다 — stdio 는 세션과 죽고 HTTP 는 레포가 N 개다
- **서버는 pull 하지 않는다.** 그 트리의 유일한 작성자다. `save` 가 커밋하고 `--mirror` 가 비동기로 push 한다. 바깥에서 origin 을 바꿨으면 사람이 `pull --ff-only`(관리자 설명서 7.6)

### 7.3 인증 — `core/auth.js`

```
auth.json   users[] { name label repos write active }      ← 권한은 여기
            tokens[] { sha256 user created expires lastUsed note }   ← 원문 없음
data/secret 세션 쿠키 서명 키 (32바이트 · 자동 생성 · 600)
```

| 규칙 | 구현 |
|---|---|
| 토큰 원문은 `issue()` 가 `randomBytes(32).toString('base64url')` 로 만들어 **한 번 반환**하고 SHA-256 만 저장 | 잃으면 `revoke` + 재발급 |
| `decide()` 5단계 — 토큰 없음 · 무효 · 만료 · 고아(사용자 없음) · 중지(`active:false`) | 화면의 실패 메시지는 하나("토큰을 확인하세요") — 구분은 `serve.log` 에만 |
| 권한은 `users[]` 에만(`repos` · `role`). 토큰에 `repos` · `write` 가 있는 v1.0 형식은 `load()` 가 거부 | 권한이 두 곳에 살면 어느 쪽이 이겼는지 모른다 |
| 발급 · 명부 편집은 CLI(`serve init/user/token`)와 **관리자 콘솔**(`/admin/*` — 세션 + `cdp_su` 재인증). 사용자가 요청하는 엔드포인트는 없음 | MCP 설계서 §4.4.1 정정 |
| `save` 의 `author` 는 서버가 토큰의 사용자로 채운다. 클라이언트가 보내면 `E_INPUT` | 남의 이름으로 기록이 남으면 기록의 의미가 없다 |
| 감사 로그 `data/logs/auth.log` — 발급 · 폐기 · 명부 변경 · 레포 생성(앞 8자) | 회전하지 않는다 |

### 7.4 `save` — `core/save.js`

`{ repo, work, sections[], vocab[] }` 한 번 → 임시 스냅샷에 쓰고 `runBuiltinCheck` → error 0 이면
한 커밋(작업 기록 1 + 관리 문서 N + 어휘) → `--mirror` 면 push 큐. `sections[].applied` 가
**낙관적 잠금**이다 — 읽었을 때 값과 다르면 `E_CONFLICT`. 검사 실패는 훅과 **같은 오류**로 돌아간다.

### 7.5 설치 · 갱신 스크립트 — 무엇을 보장하나

| 스크립트 | 보장 | 하지 않는 것 |
|---|---|---|
| `deploy/install.sh` | Node ≥ 20 · git 확인 → 계정 · 폴더 → 배치 → **`command -v node` 를 유닛에 박음**(전에는 `/usr/bin/node` 고정이라 tarball 설치에서 `203/EXEC`) → `enable --now` → `/healthz` 10초 대기. **멱등.** `--dry` | git 자격 · 명부 · 토큰 · 방화벽 실행(안내만) |
| `deploy/upgrade.sh` | tar 또는 폴더 → `.bak` 한 세대 → 교체(`web/` 는 비우고) → restart → **`healthz.built` == 새 번들 · `index.html` 자산 해시 == tar** 아니면 되돌리고 exit 1 | 명부 · 대장 · 레포 · 자격 |

## 8. MCP 서버

### 8.1 두 모드 · 한 서버

| | 모드 A — 로컬 (stdio) | 모드 B — 서버 (HTTP) |
|---|---|---|
| 실행 | 호스트(Claude Code)가 `.mcp.json` 대로 `bin/ctx mcp` 를 띄운다 — Windows 는 `cmd /c bin\ctx.cmd mcp` | `ctx serve` 가 `/mcp/<repo>` 에서 Streamable HTTP |
| 레포 | `--repo` 여럿 가능 · 첫 번째가 기본 · `bin/ctx` 가 자기 위치로 찾는다 | `--root` 의 하위 전부. URL 이 레포를 정한다 |
| 도구 | 읽기 12 | 읽기 12 + `save` |
| 인증 | 없다 (내 PC) | Bearer `CDP_TOKEN` · 명부의 `repos` · `role` |
| prompts | `auto` — Claude Code 면 내놓지 않는다(스킬이 있다). `--prompts always|never` | 같다. Claude Desktop 은 스킬 자리가 없어 prompt 로 간다 |

`buildServer({ repos, fallback, mode, prompts, allow, notice, saver, built })` 가 둘의 공통이다 —
**전송을 모른다.** 도구 · 리소스 · 명함 · 판정이 두 모드에서 같다.

### 8.2 도구 13종 — 어디에 있나

| 도구 | 함수 | 어디 |
|---|---|---|
| `match` `where` `section` `work` `search` `derive` `apply` `check` `brief` | `toolMatch` … `toolBrief` | `core/tools.js` — 순수 함수. 파일을 쓰지 않는다 |
| `sync` `version` `repos` | — | `ctx-mcp.mjs` — git · 프로세스 · 서버의 레포 목록이라 층이 다르다 |
| `save` | `saver` 주입 | `ctx-mcp-serve.mjs` → `core/save.js`. 모드 B 만 |

**형태는 `core/tools.js` 한 곳에서만 만든다.** CLI 의 `ctx <명령> --json` 이 같은 함수를 부르므로
결과가 바이트까지 같다(불변조건 15). 두 곳에서 각자 객체를 만들면 그 약속은 한쪽에 필드를 더하는
순간 조용히 깨진다. 하네스가 이것을 대조한다.

### 8.3 명함 — `CARD`

`ctx-mcp.mjs` 의 `CARD` 는 **MCP 설계서 §2.2 표를 그대로 옮긴 것**이다. 모델이 도구를 부를지
말지를 이 문구만 보고 정하므로 짧게 줄이면 그만큼 기억으로 답한다. 설계서 표를 고치면 여기도
같이 고친다. `match` 의 명함이 "레포를 안 주면 든 레포를 전부 대조한다" 고 말하는 것처럼 **레포를
가로지르는 유일한 도구는 `match`** 이고 나머지는 `repo` 를 받는다 — 레포는 고르는 것이지 합치는 것이 아니다.

### 8.4 규칙

| | |
|---|---|
| **오류** | `CtxError(code)` 를 던지고 `isError: true` 로 싸는 것은 부르는 쪽. 코드 — `E_COORD` `E_INPUT` `E_NOT_FOUND` `E_REPO` `E_AUTH` `E_FORBIDDEN` `E_CONFLICT` `E_GIT` `E_EXISTS` `E_CHECK` |
| **입력 검증** | 경로가 되는 값은 전부 `checkCoord` · `checkId` 를 지난다. `RE_COORD` 는 ASCII 타입은 **소문자만**(대문자를 열면 `C:/abs/path` 가 좌표가 된다 — 하네스 2번), 한글 첫 글자 타입은 허용(`테이블정의서:ex_plan_mst` — dpms 전부가 이렇다. 제품화 전에는 전부 `E_COORD` 였다). `..` 금지 + 부르는 쪽의 root 접두 검사 |
| **응답 상한** | `section` · `work` 본문 512KB(`guardSize`). 넘으면 **자르지 않고 거절**하고 `cdp://<repo>/doc` 리소스로 읽으라고 한다 — 잘린 정본은 정본이 아니다 |
| **섹션 상태** | `sectionState` 가 다섯을 셋으로 접는다 — `ok` · `derive-pending` · `missing`. 내부 값(stale · unwritten · empty · orphan)은 화면에 나가지 않는다 |
| **번들 나이** | `bundleAgeNotice(built, now, 90)` — `brief` 마지막 줄. `--built-at` 은 하네스 전용 |
| **레포 캐시** | 요청마다 스탬프 → 바뀌면 통째로 교체. 부분 갱신 없음 |
| **리소스** | `cdp://<repo>/doc/<path>` — 문서 전체는 도구가 아니라 리소스로 |

### 8.5 검증

하네스가 stdio 클라이언트로 `initialize` · `tools/list` · `tools/call` 을 돌리고, HTTP 로 `save` 정상 ·
충돌 · 검사 실패 · 미러 · 명부 5단계 · 꾸러미 · `POST /repos` 를 돈다. 도구를 추가하면 —
① `core/tools.js` 에 순수 함수 ② `ctx-cli.mjs` 에 같은 함수를 부르는 명령 + `--json` ③ `CARD` 와
설계서 §2.2 ④ 하네스에 바이트 대조 한 줄 ⑤ `test/tools.test.mjs`.

## 9. 패키지

### 9.1 무엇인가 — 서식이지 내용이 아니다

```
agent/packages/<이름>/
  _package.json     매니페스트 — name(폴더명과 같다) · title · version · description · source · updated.  **받는 사람에게 안 나간다**
  _vocab.md         좌표 타입과 순서.  값은 없다 (예시 좌표만)
  _managed.md       패턴 → 문서 · 섹션
  docs/**/*.md      문서 골격 — 머리 표 · (예시) 섹션 · ## 작성지침
  README.md · 관리번호.md
  convert/          (선택) 그 문서 종류의 변환기 자리.  안 나간다
```

문서 수 · 타입 · 패턴은 **폴더에서 센다** — 매니페스트에 적어 두면 갈라진다. 값(그 프로젝트의
테이블 · 용어)을 넣으면 이 패키지를 고른 다른 프로젝트에 남의 데이터가 따라 들어간다. 서식 규약은
`docs/관리문서패키지/`(`03_템플릿규약` · `04_좌표와등록부`)에 있고 패키지마다 복사하지 않는다.

### 9.2 명령 — `core/packages.js` · `viewer/bin/ctx-package.mjs`

```
ctx package list   [--packages <dir>] [--json]        이름 · 판 · 문서 · 타입 · 패턴
ctx package show <이름>                                등록부 표 · 어휘 타입 순서 · 문서 목록
ctx package check [<이름>|--all]                       부어서 ctx check + 등록부 문서 존재 + 예시 어휘 공백.  fail 이면 exit 1
ctx package new <이름> --from <이름> [--title] [--description]   복사 · 매니페스트 갱신 · README 제목 · check 한 번
ctx package rename <이름> <새 이름> [--title]                    폴더 · 매니페스트 name · README 제목을 한 번에
```

**패키지 이름은 프로젝트에 맞춰 바뀌는 것이 정상이다.** 패키지는 서식이고 서식은 그것을 쓰는
프로젝트의 것이 되므로, `project_1` 같은 이름은 자리표시자다. `rename` 이 셋을 한 번에 바꾼다 —
하나만 바꾸면 `readManifest` 가 "폴더명과 다르다" 로 거절하거나 레포를 연 사람이 옛 이름을 읽는다.
**패키지 이름 ≠ 지식 레포 이름** — 레포 이름은 `ctx repo new <경로>` 에서 정하고, 이미 세운 레포는
패키지 이름이 바뀌어도 그대로다. 서버의 `packages/` 는 다음 산출물이 따라간다.

패키지 폴더를 찾는 순서 — `--packages` → `CDP_PACKAGES` → 번들 옆 `packages/`(서버 산출물) →
소스 `agent/packages`. `check` 는 **조립 함수와 같은 것으로 붓는다**(`assemble.mjs`) — 검사한 것과
나가는 것이 같은 모양이어야 한다. `_managed.md` 의 설명 표(첫 칸이 `배치:` 같은 타입)를 규칙으로
읽던 것을 `ruleLike` 가드로 걸러낸 것이 첫 실측에서 잡은 버그다.

### 9.3 새 패키지

`ctx package new <이름> --from dpms --title … --description …` → 문서 목록을 사람이 고친다 →
`ctx package check <이름>` → `agent/packages/README.md` 목록에 한 줄 → 릴리스가
`knowledge-repo-<이름>/` 을 하나 더 낸다. `new` 는 복사하면서 매니페스트를 새로 쓰고, `README.md` 의
첫 제목을 새 이름으로 바꾸고 출처 한 줄(`dpms v1.0.0 에서 복제 · 날짜`)을 넣고, `convert/` 는 빼고 간다.

**지금 패키지는 셋이다** — `dpms` 와 그 복제 `project_1` · `project_2`(2026-09-23 · R17 정정).
복제 둘은 **다중 패키지 경로**(목록 · 검사 · 릴리스 · 서버 `POST /repos` · 화면의 패키지 선택)가
여럿일 때 맞게 도는지 실측하기 위한 것이고, 이름은 자리표시자다. 실제 프로젝트 패키지는 이 둘 중
하나를 `rename` 으로 그 프로젝트의 이름으로 바꾸고 문서 목록을 고쳐서 만든다. 여럿일 때 프로그램이 하는 것 — 릴리스 README 가 패키지 표를 내고
받는 사람이 **하나를 고른다** · 화면의 새 지식 레포는 첫 것을 미리 고르지 않는다 · `repo new` 와
`POST /repos` 가 없는 이름에 있는 것을 같이 낸다 · 하네스 74번이 `check --all`. 클라이언트 zip 의 exe 는
**배포본 루트에 하나**다(2026-09-23) — 패키지가 늘어도 커지지 않는다. 조립은 빈 `tools/`(`.gitkeep`)를
남기고, 받는 사람이 `copy cdp.exe <레포>\tools\` 한 줄을 더 한다(설치.md ③). 셋에서 213MB 였던 것이 75MB 다. dpms 가 어떻게 만들어졌는지는 `docs/attic/dpms-패키지/`
(원본 xlsx 변환기 · 원본이 없으면 돌지 않는다).

## 10. 지식 레포 생성 · 이관

### 10.1 `core/reponew.js` — `newRepo({ from, dest, origin, push, author, dry })`

```
0  dest 가 없거나 빈 폴더.  아니면 E_INPUT (남의 폴더에 쓰지 않는다)
1  from(완성 폴더)을 복사 — _package.json · convert/ · *.exe 는 빼고
2  work/.gitkeep · git init · core.hooksPath .githooks · core.autocrlf false
3  git add -A · commit "지식 레포 세움 — <패키지>"  ← 훅이 ctx check 를 돈다.  막히면 dest 를 지우고 E_CHECK
4  origin 이 있으면 remote add · push 면 push -u origin HEAD (실패는 pushError 로 — 레포는 남긴다)
→ { dest, commit, files, origin, pushed, pushError }
```

`from` 은 서버의 `packages/<이름>/`(완성 폴더) 또는 소스 `agent/packages/<이름>`(그때는 `assemble`
로 먼저 만든다 — `ctx-package.mjs` 의 `materializePackage`). 서버의 `POST /repos` 가 같은 함수를
`author: <토큰 사용자>` 로 부르고 `store.refresh()` · `auth.audit` 을 한다. 이름은
`REPO_NAME_RE = /^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$/`.

### 10.2 `core/importdir.js` — `planImport` · `applyImport`

`planImport(src, repo, { author, keepTouches })` 는 **파일을 쓰지 않고** 계획을 낸다 — `{ files[]
{ from, to, id, title, date, dateSource, author, tags, dropped, kind }, warnings }`. 규칙은
관리자 설명서 8장 표. 검토 §3.6 과 다르게 정한 것 하나 — `touches` 는 비우고 `tags` 에
`touches/<좌표>` 로 보존한다(기본). 남겨 두면 파생 문서가 없어 `applyImport` 가 E_CHECK 로 전부
되돌리기 때문이다. `applyImport(plan)` 은 쓴 뒤 `runBuiltinCheck` → error 가 있으면 쓴 것을 지운다.
결정론이다 — 두 번 돌려 같다.

가로 열) · 오른쪽은 문서와 세로 목차 · 상단 `문서 | 그래프 | 관리` 셋은 창 전체를 쓴다 · 검색은
이름 넷에 걸고 객체 셋으로 낸다. **상태로 정렬하지 않고 상태로 색을 쓰지 않는다.** 정렬은 늘 같다.
자세한 사용법은 사용자 설명서 8장.

**세 얼굴 한 번들**(v0.10.0) — `main.jsx` 가 경로 첫 조각으로 `App`(로컬 · `/r/<레포>/`) · `Site`(`/` · `/manual` ·
`/login` · `/setup` · `/r`) · `Console`(`/console/*`) 을 고르고 `<html data-face>` 를 찍는다. 라우터는 `lib/router.jsx`
(pushState · 의존성 0), 얼굴은 `lib/api.js` 의 `face`(local · repo · site · console) — 서버가 `index.html` 에
`window.__CDP_SERVER__` 를 박아 준다. 사이트 · 콘솔의 스타일은 `styles/site.css` · `console.css`, 색은 `tokens.css`
의 예산 그대로(초록 없음). 설명서는 `/site/manual/<파일>` 원문을 받아 `lib/markdown.js` 로 화면이 렌더한다 —
제목 slug 는 GitHub 규칙이라 세 권의 목차 링크가 그대로 앵커다. 설계 · 결정은
[`docs/design/CDP_제품관리서비스_검토_v0.1.md`](../docs/design/CDP_제품관리서비스_검토_v0.1.md).

### 11.3 관리 화면 — 로컬과 서버가 갈린다

`viewer/src/components/admin/AdminView.jsx` 의 `MENU` 다섯. `isServer` 로 갈린다.

| 메뉴 | 로컬 | 서버 |
|---|---|---|
| 현황 | ○ | ○ — 훅 · 설치 줄은 빠지고 **미러** 카드가 있다 |
| 지식 레포 | 경로 · 구조 검증 · 번들 시각 (`Repo.jsx`) | **든 레포 목록 · 미러 · 패키지에서 새 레포**(`RepoServer.jsx` → `POST /repos` · `writer` 이상). 콘솔 > 지식 레포는 여기에 clone · grant 를 더한다 |
| 동기화 | ○ | **없다** — git 을 도는 것은 서버 자신이다. `local: true` |
| 작업 레포 | 이 PC 에 깐다 · 계획 미리보기 · 일괄 갱신 (`WorkRepos.jsx` · `.mcp.json` 상태 한 줄) | **등록 · 꾸러미 발급 · 설치 대장 · 낡음**(`WorkReposServer`) |

서버 모드의 토프바 — `loopback 아님` 경고 대신 설명서 · **콘솔**(관리자) · 사용자 이름 · 역할 칩 · 로그아웃.
레포 이름표는 **언제나 메뉴**(쓰기/읽기 칩 · 관리자에게는 권한 밖 레포도 회색으로 → 콘솔 > 지식 레포).

(`repos` · `packages` · `repoNew` …).

**콘솔**(`viewer/src/console/`) — `Console.jsx`(메뉴 일곱 · `SudoProvider`: 쓰기가 401 `E_REAUTH` 를 받으면 재인증
모달 → `POST /admin/sudo` → 하던 동작을 재시도한다 · 비관리자는 「관리자 권한이 필요합니다」 한 장) ·

### 11.4 로컬 앱의 보안 — 새로 만든 위험면

로컬 리스너(`127.0.0.1:7373`)가 있으므로 브라우저의 임의 외부 페이지가 `fetch('http://127.0.0.1:7373/api/…')`
로 사내 문서를 가져가는 것이 가장 현실적인 사고다. `viewer/server/adapter/` 가 봉인한다.

| 시나리오 | 결과 |
|---|---|
| 정상 (토큰 + Host) | 200 |
| 토큰 없음 · 틀림 | 401 |
| **Host 위조 (DNS 리바인딩)** | **연결 종료** — 응답조차 주지 않는다 |
| 외부 Origin · `Sec-Fetch-Site: cross-site` | 403 |
| 경로 순회 (`../../Windows/win.ini`) | 403 |

`--host` 로 loopback 이 아닌 주소를 열면 콘솔과 화면에 상시 경고가 뜬다. 앱은 레포에 캐시 · 설정을
쓰지 않는다 — 전부 `%LOCALAPPDATA%\cdp\`. 문서 내용은 PC 를 떠나지 않는다 — 네트워크로 나가는
것은 git 원격뿐이고 사용자가 누를 때만 움직인다.

## 12. 단일 실행 파일 · 트레이

```bash
npm run build:exe        # → ops/out/exe/cdp.exe (~68MB).  더블클릭 한 번 — 콘솔 창 없음 · 아이콘 · 트레이
```

인자 없이 더블클릭하면 **exe 가 든 지식 레포**(`<레포>/tools/cdp.exe` → 부모에 `_vocab.md`)를 연다 —
`ctx` 의 규칙 ④(자기 위치의 부모)와 같다(2026-09-23). 밖에 있으면 저장된 설정, 그것도 없으면 경로 지정 화면.

Node SEA — 빌드에 쓴 `node` 바이너리를 복사해 blob 을 주입한다(`postject 1.0.0-alpha.6` 고정 ·
`rcedit`). **네이티브 모듈을 하나도 안 쓰기 때문에 성립한다.**

| 빌드가 더 하는 것 | |
|---|---|
| 아이콘 | `tools/make-icon.mjs` — 16~256px `.ico` 를 의존성 없이(무압축 DIB) |
| 콘솔 창 제거 | PE 서브시스템 `CONSOLE(3) → WINDOWS(2)` 2바이트 패치 |
| 로그 | 콘솔이 없어지므로 `<데이터폴더>/logs/app.log` 가 유일한 진단 수단. 3 × 1MB. 문서 내용 · 검색어 · 토큰은 안 쓴다 |
| **주입 후 검증** | `cdp.exe ctx version` 이 날짜를 내놓아야 성공. 아니면 반쪽 파일을 지우고 멈춘다 — 갓 복사한 68MB 를 백신이 잠그는 지점이 blob 주입 직전이다 |
| 시작 전 확인 | `postject` 가 없으면 `npm ci` 를 돌리라고 하고 멈춘다 — 66MB 를 복사한 뒤 죽으면 반쪽이 남는다 |

트레이는 npm 패키지 없이 Windows `NotifyIcon` 을 PowerShell 로 띄운다 — 스크립트를 앱 데이터
폴더에 **읽을 수 있는 `tray.ps1`** 로 쓰고 `-File` 로 넘긴다(`-EncodedCommand` 는 EDR 이 난독화로
본다). 부모 PID 를 폴링해 같이 종료한다. PowerShell 이 막히면 트레이 없이 그대로 동작한다.
`npm run test:tray` 가 클릭 없이 시험한다. exe 옆에 빈 파일 `cdp.portable` 을 두면 설정 · 캐시 ·
로그가 exe 폴더의 `data/` 로 간다.

## 13. 문제 해결 — 개발 중

| 증상 | 원인 | 고침 |
|---|---|---|
| `ctx: 모르는 명령` · 한 레포만 다른 답 · `serve init` 이 멎은 것처럼 보인다 | **번들이 낡았다.** 새 명령이 옛 번들에서 `serve` 로 떨어져 서버가 뜬 채 기다린다 | `npm run build:ctx` · `ctx version` 세 곳 대조 · 떠 있는 `node … ctx.mjs serve` 를 죽인다 |
| exe 빌드 `EBUSY` | `cdp.exe` 가 떠 있다 · 백신 스캔 | `taskkill /F /IM cdp.exe` |
| exe 는 있는데 `Cannot find module 'ctx'` | blob 주입 전에 죽은 반쪽 파일 | 지우고 다시. 지금 빌드는 스스로 막는다 |
| `release:server` 가 tar 에서 `Cannot connect to C` | Git for Windows 의 GNU tar 가 `C:` 를 원격 호스트로 읽는다 | 상대 경로 + `cwd` 로 부른다(고쳐져 있다) |
| 커밋한 `.sh` 가 리눅스에서 `$'\r': command not found` | 블롭이 CRLF | `.gitattributes` 가 `*.sh` 를 LF 로 정규화한다 — `git ls-files --eol` 로 `i/lf` 확인. `git show` 출력은 autocrlf 로 변환되니 `git cat-file -p` 로 본다 |
| Git Bash 에서 `wsl …` · `docker exec …` 인자가 `C:/Program Files/Git/…` 로 바뀐다 | MSYS 경로 변환 | `MSYS_NO_PATHCONV=1` |
| 하네스가 포트 충돌로 죽는다 | 7377 이 쓰인다 | `npm run verify -- --port 7390` |
| 하네스 52번 실패 | 꾸러미의 `kit/` 한 단을 하네스가 벗겨 읽는다 — 꾸러미 모양을 바꿨으면 하네스도 | `ops/verify/run.mjs` 의 52번 |
| fresh clone 에서 38 · 52 · 56 · 57 실패 | fixture 의 `.claude/` 가 없다 | 하네스가 `seedKit` 을 먼저 돈다 — 안 돌면 `npm run seed:kit` |
| `ctx package check` FAIL — `_managed.md` 설명 표가 규칙으로 읽힌다 | 첫 칸이 타입 모양(`배치:`) | `parseRegistry` 의 `ruleLike` 가드 — 규칙은 문서 경로 · `{값}` · `—` 를 가진 행만 |
| dpms 좌표가 전부 `E_COORD` | `RE_COORD` 가 한글 타입을 거절 | 고쳐져 있다. 타입 문자 집합은 `core/vocab.js` 의 `COORD` 와 같아야 한다 |
| Docker 실측이 `daemon not running` | Docker Desktop 이 꺼져 있다 | 켠다 · 끝나면 다시 끈다(테스트 스크립트가 그렇게 한다) |
| WSL 에서 `systemctl` 이 없다 | systemd 가 꺼진 WSL | `/etc/wsl.conf` 에 `[boot] systemd=true` · `wsl --shutdown`. 또는 `install.sh --no-systemd` 로 유닛 렌더까지만 |
