## 1. 한눈에

```
<서버>  /opt/cdp                      (--prefix 로 바꾼다)
  serve.json       설정 한 장 — root · auth · data · web · bind · port · mirror. 유닛과 cdp 명령이 같이 읽는다
  bin/ctx.mjs      서버 본체 — 화면 · MCP · save · 관리 API. Node 20 한 프로세스
  repos/<이름>/    지식 레포 — 지식만. 서버가 유일한 작성자이고 origin 으로 미러한다
  auth.json        명부 — 사람 · 역할 · 큐레이터 · 토큰(해시)
  data/            로그 · 작업 레포 대장 · SSH 키 · 휴지통 · 팀 서식
  web/ forms/ kit/ manual/ deploy/    화면 · 서식집 · 스킬 · 설명서 · 스크립트 (갱신이 간다)
/usr/local/bin/cdp                    서비스 계정으로 ctx 를 부르는 한 줄 — 플래그 없이 `cdp serve doctor`
```

**쓰는 길은 서버 `save` 하나다** — 검사하고 한 커밋으로 남기고 origin 에 민다. 레포에는 지식만 있어 서버를 갱신해도 레포는 그대로다.

**콘솔**(왼쪽 메뉴 「서버」 · admin 에게만) — 네 페이지. 쓰기마다 **관리자 확인**(내 토큰을 한 번 더 · 15분)을 묻는다.

| 페이지 | 하는 것 |
|---|---|
| 현황 | 「시작하기」(남은 일 한 줄씩) · 경고 · 최근 save · 감사 꼬리 · 진단 요약 |
| 지식 레포 | 레포 전부 · 미러 칩과 단추 · 대기 · 작업 레포(펼침) · [새 레포] · origin 연결 · 삭제 |
| 사람 | 사용자 · 토큰 · 「레포 × 사용자」 · 「레포 × 큐레이터」 |
| 서버 | 설정값 · 파일 자리 · 진단 · git 자격 · 갱신 명령 · 감사(접힘) · 로그(접힘) |

## 2. 팀 서버 — 설치 한 줄

**준비물** — Linux · `sudo` · **Node 20+** · **git**(없으면 `install.sh` 가 무엇을 깔지 말하고 멈춘다 — [설치 절차 0장](설치절차.md)) ·
서버 산출물 `cdp-server-v<판>.tar.gz`(+ `SHA256SUMS`) · origin 으로 쓸 **빈 GitLab 프로젝트**(웹에서 먼저 만든다).

```bash
tar -xzf cdp-server-v<판>.tar.gz && cd cdp-server-v<판>
sudo bash deploy/install.sh --bind <서버 IP> --admin <내 아이디> --label "<이름 · 소속>" \
     --repo <레포> --origin http://<GitLab>/<그룹>/<프로젝트>.git \
     --pat-stdin --git-host <GitLab> --git-user <GitLab 계정>
```

| 옵션 | |
|---|---|
| `--bind <IP>` | **필수.** 그 인터페이스 하나에만 연다 — 프록시가 없는 배치에서 유일한 경계다 |
| `--admin <id>` `[--label]` | 첫 관리자 · 토큰 원문을 **한 번** 찍는다. 빼면 끝에 `/setup` 주소와 부트스트랩 코드 |
| `--repo <이름>` `[--origin <url>]` | 첫 지식 레포(빈 틀) · origin 이면 첫 커밋을 보낸다 |
| `--pat-stdin --git-host --git-user` | origin 자격 — PAT 를 숨김 입력으로 묻는다(파이프로 줘도 된다) |
| `--ssh` | 대신 SSH 배포 키를 만든다(2.1) |
| `--port 7374` `--prefix /opt/cdp` `--user cdp` `--no-systemd` `--dry` | 기본값 · 미리 보기 |

**무엇이 일어났나** — 계정 `cdp` · 파일 배치 · `serve.json` · `/usr/local/bin/cdp` · systemd 유닛(`serve --config`) · `/healthz` 확인 →
첫 관리자 · git 자격 · 첫 레포와 push · `cdp serve doctor` → 끝에 **남은 일만**(방화벽 · 사람 · 팀원 PC). 두 번 돌려도 같다 — 있는 것은 건너뛴다.

**그다음** — 방화벽에서 `7374/tcp` 를 연다(안내만 한다 · [설치 절차 2장](설치절차.md)) → 브라우저 `http://<서버 IP>:7374/login` 에 토큰 →
콘솔 **현황**의 「시작하기」 가 남은 일을 줄마다 준다.

- **root 없이** — `bash deploy/install.sh --bind 127.0.0.1 --prefix ~/cdp-server …` — 계정 · 유닛 · `/usr/local/bin/cdp` 없이 지금 사람으로. 끝에 띄우는 한 줄(`… serve --config ~/cdp-server/serve.json`)과 명령 자리(`~/cdp-server/bin/ctx`)를 찍는다.
- **막히면** — `doctor` 의 fail 줄이 고칠 곳이다. `install.sh` 의 메시지별 표는 [설치 절차 5장](설치절차.md).

### 2.1 git 자격 — SSH 배포 키 · PAT

서버가 origin 으로 push 할 자격이다(커밋의 `author` 는 CDP 사용자로 채운다). **비밀은 브라우저를 건너지 않는다.**

| 길 | 원격 주소 | 하는 것 |
|---|---|---|
| **SSH 배포 키** — 닿으면 권장 | `ssh://git@<GitLab>/<그룹>/<프로젝트>.git` | 콘솔 **서버 › git 자격** 「배포 키 만들기」(또는 `--ssh` · `cdp serve git-auth --ssh`) → 공개 키를 GitLab 프로젝트 › Settings › Repository › **Deploy keys** 에 쓰기 권한으로 → 「호스트 키 받기」 → 지문이 GitLab 관리자에게 받은 것과 같으면 「이 지문을 믿는다」 → 「접속 확인」 |
| **PAT** | `http://<GitLab>/<그룹>/<프로젝트>.git` | `--pat-stdin`(설치 때) 또는 `cdp serve git-auth --host <GitLab> --user <계정> --test <url>`(숨김 입력). 스코프 `write_repository` · **만료 1년 — 달력에** |

SSH 는 키를 GitLab 에 붙여야 push 가 되므로 설치 한 줄에서 `--origin` 을 빼고, 붙인 뒤 콘솔 **지식 레포 › origin 연결**로 잇는다.
지금 상태 — `cdp serve git-auth --list`. PAT 를 바꿀 때도 같은 명령이다(재시작 없음).

### 2.2 Docker

```bash
cd cdp-server-v<판>
docker compose -p cdp -f deploy/docker-compose.yml up -d --build
docker compose -p cdp -f deploy/docker-compose.yml logs cdp        # 첫 관리자 코드 → 브라우저 http://<호스트>:7374/setup
```

명부(`/opt/cdp/data/auth.json`)와 git 자격(HOME = `/opt/cdp/data/home`)은 **data 볼륨 안**이다 — 새 판 폴더에서도 같은 `-p cdp` 로 올리면 이어진다.
셸 명령은 `docker compose -p cdp -f deploy/docker-compose.yml exec cdp node bin/ctx.mjs …` 에 `--auth /opt/cdp/data/auth.json --data /opt/cdp/data`
(serve.json 이 없다). 컨테이너 안 `--bind 0.0.0.0` 이 맞다 — 경계는 호스트의 `-p` 매핑이다.

## 3. 사람 — 명부와 토큰

**권한은 사람에 붙고, 토큰은 신원만 증명한다.** 바꾸면 그 사람의 토큰 전부에 다음 요청부터 먹는다 — 재시작 없음. 토큰 원문은 저장되지 않는다.

| 역할 | 할 수 있는 것 |
|---|---|
| `viewer` | 읽는다 — 화면 · 검색 · MCP 읽기 도구 |
| `writer` | + `save` 로 **작업 기록** · 작업 레포 등록 |
| `writer` + 큐레이터 | + 그 레포의 대기열 · 판정 · 관리 문서 · 기준선(4장) |
| `admin` | + 콘솔 전부 · 레포 전체 · **모든 레포의 큐레이터** |

**한 줄** — 콘솔 **사람** › [+ 사용자](아이디 · 라벨 · 역할 · 볼 레포) → 그 줄의 **[발급]**(메모 = 기기 · 만료) → 원문이 **한 번** 보인다 → [복사] 해서 **본인에게 직접**.

```bash
cdp serve user add <아이디> --role writer --curate <레포>      # --curate 만 주면 볼 레포도 그 레포 · --repos a,b 로 따로
cdp serve token --user <아이디> --note "<기기>"                 # stdout 한 줄이 원문
```

- 아이디는 영문 · 숫자 · `._-` — **커밋의 `author`** 로 남는다. 바꿀 수 없다.
- 만료 기본 — 관리자 30일 · 나머지 90일. `never` 는 감시 · 기준선 생성기 계정에만. 현황이 7일 전부터 경고한다.
- **잃었다 · 만료됐다 → [재발급]**(옛것 폐기 + 새것 한 동작). 기기마다 토큰 하나 · 메모로 구분한다. 메신저에 평문으로 남겼으면 유출로 보고 재발급.
- 퇴사 · 이동은 **[비활성]** — 삭제는 없다(커밋의 `author` 가 명부와 이어져야 한다). 마지막 관리자는 내릴 수 없다. `writer` · `admin` 은 필요한 사람에게만.
- 이력 — 발급 · 폐기 · 명부 · 레포 · 미러 단추는 `data/logs/auth.log`(콘솔 **서버 › 감사**). 셸에서 한 것은 행위자가 `(셸)`.

## 4. 큐레이터 맡기기

**관리 문서는 큐레이터만 바꾼다.** 큐레이터가 없는 레포는 기록이 대기열에만 쌓인다 — **레포를 세우면 큐레이터부터.**

**한 줄** — 콘솔 **사람 › 「레포 × 큐레이터」** 에서 체크(셸 — `cdp serve user set <아이디> --curate a,b` · 빈 값이면 해제).
그 레포의 writer 중 팀 리드 · 문서 담당에게. 여럿이어도 된다. admin 은 체크 없이 큐레이터다. 회색 칸은 그 사람이 볼 수 없는 레포다.

**그 뒤 큐레이터가** — 자기 PC 에 큐레이터 폴더(큐레이터 설명서 1장) → 메뉴에 「대기열」 · 「관리 문서 › 서식집」 이 생긴다 → 오래된 기록부터 판정.
가장 오래된 대기가 14일을 넘으면 **지식 레포** 표와 현황이 알린다.

## 5. 지식 레포 세우기

**폴더명이 곧 레포 이름이다**(영문 · 숫자 · `._-`). `<prefix>/repos/` 아래 `_vocab.md` 가 있는 git 폴더면 레포다 — 첫 요청에서 바로 알아본다(재시작 없음).

**한 줄** — 콘솔 **지식 레포 › [새 레포]** — 이름 · origin(빈 프로젝트) · 볼 사람.

| 탭 · 칸 | 하는 것 |
|---|---|
| **빈 레포로 세우기** | 빈 틀(`README.md` · `_vocab.md` · `_managed.md` · `docs/` · `work/`) · 첫 커밋 · origin 이면 push. 서식은 큐레이터가 서식집에서 고른다 |
| + 기록만 옮겨 오기 | 옛 레포의 작업 기록 · 첨부 · 그 기록의 어휘만 — 전부 대기열에 선다([설치 절차 부록 B](설치절차.md)) |
| origin 에서 받아 오기 | 이미 있는 지식 레포를 clone |

셸 — `cdp repo new <이름> [--origin <url>] [--title "<한 줄>"]` (`--origin` 이면 push · 안 하려면 `--no-push`).

**세운 뒤** — 행마다 둘. 둘 다 `save` 와 같은 줄에 서고 `auth.log` 에 남는다.

- **「origin 연결」** — `remote add` → `push -u`. **강제 push 는 없다** — 원격에 커밋이 있으면 거절된다. 실패해도 원격은 남으니 자격을 고치고 다시 누른다.
- **「삭제」** — 이름을 그대로 쳐야 열린다. `data/trash/<레포>-<시각>/` 로 **옮긴다**(영구 삭제 없음 · 스스로 비지 않는다). 되살리기 — 그 폴더를 `repos/<이름>` 으로 옮기고 할당을 다시.

**기존 md 폴더 수십 · 수백 건을 기록으로 들이기** — 사람이 쓰지 않는 때에.

```bash
cdp import-dir <원본 폴더> --repo /opt/cdp/repos/<레포> --dry     # 표만 — 먼저 본다
cdp import-dir <원본 폴더> --repo /opt/cdp/repos/<레포> [--author <이름>] --yes
```

날짜는 프론트매터 → 파일명 → git → mtime 순. 좌표는 추측하지 않는다. 검사 오류면 전부 되돌린다. 들인 기록은 대기열에 선다.

**산출물 문서 레포(md · git)의 지금으로 관리 문서까지 세우기** — 큐레이터의 일이다(`cdp-seed` · 큐레이터 설명서 12장). 서버를 멈추지 않는다 — 서버의 save 로 쓴다.

```bash
ctx seed check --from <문서 레포>                                   # 지도(cdp-sources.json) 검사
ctx seed apply --from <문서 레포> --server <주소> --repo <레포>       # 기준선 → 관리 문서 → 기록(CDP_TOKEN · 큐레이터) · 세운 자리는 _seed.json
```

## 6. 작업 레포 · 큐레이터 폴더

**사용자가 자기 PC 에서 한다**(사용자 설명서 2장) — 관리자는 길만 알면 된다.

- 작업 레포(코드 레포) — 레포 화면 **연결된 작업 레포**에 등록(장부일 뿐 · writer) → 그 행의 **설치 한 줄**(설치기가 토큰을 숨김 입력으로 묻는다) →
  `.mcp.json` · `.claude/` · writer 스킬 셋 · `CLAUDE.md` 블록 → 커밋. 아래 git 레포 여럿을 한 번에 — `--connect --repo <레포> <폴더>`.
- 큐레이터 폴더 — 같은 설치기 `--curator --repo <레포> <폴더>`(git · 등록 없이 · 큐레이터 스킬 일곱). 큐레이터가 아닌 토큰이면 멈춘다.
- **kit 은 서버 번들의 `kit/` 에서 나간다** — 판을 올려 kit 이 바뀌면 대장의 행이 `낡음` → 각자 `--update [--commit]` 한 줄(그 PC 의 작업 레포 · 큐레이터 폴더 전부).

서버 전부의 대장은 콘솔 **지식 레포**의 작업 레포 펼침 — 상태(최신 · 낡음 · 미설치) · 담당 · 마지막 보고. 지식 레포를 지운 뒤 남은 등록은 표 아래 「지식 레포 없음」 에서 지운다.

## 7. 운영

### 7.1 미러 — 칩과 단추

서버는 트리의 **유일한 작성자**다. `save` 뒤 origin 으로 밀고, 스스로 pull 하지 않는다. 어긋나면 콘솔 **지식 레포**의 칩이 말하고 단추가 푼다(관리자 확인 · `auth.log`).

| 칩 | 뜻 | 단추 |
|---|---|---|
| `밀림 N · <사유>` | 서버 커밋이 origin 에 못 갔다 — `인증 실패`(**PAT 만료가 가장 흔하다**) · `원격 불통` · `보호 브랜치` · `non-ff` | 사유를 고친 뒤 **「다시 보내기」** |
| `origin 앞섬` | 서버 밖에서 origin 에 썼다 | **「origin 과 맞추기」** — fetch → ff-only |
| `갈림 N` | 서로 모르는 커밋 — 기계는 합치지 않는다 | `sudo -u cdp -H git -C /opt/cdp/repos/<레포> pull --rebase` 뒤 「다시 보내기」 |
| `트리 더러움 N` | 커밋 안 된 변경 — **`save` 가 거절된다** | **「트리 되돌리기」** — 버릴 경로를 보인 뒤 HEAD 로 |

서버가 떠 있을 때 셸에서 git 을 만지면 `save` 와 겹칠 수 있다 — 화면이 안전하다.

### 7.2 점검 · 만료

| | |
|---|---|
| 매일 | 콘솔 **현황** — 「시작하기」 · 경고 · 감사 꼬리 |
| 감시 | `GET /healthz`(인증 없음 · 집계만 — `mirror.ok` 가 레포 수와 같은가) · `cdp serve doctor --json` 을 크론에 |
| 백업 | origin 미러 + `repos/` 스냅샷 · `auth.json` · `data/` |
| 만료 | CDP 토큰(관리자 30 · 나머지 90일 — 3장) · **GitLab PAT 1년**(지나면 미러가 조용히 멈춘다 — 2.1 을 다시) · 대기 14일(큐레이터에게) |

### 7.3 save 가 하지 않는 것 — 손으로

- **어휘 줄 · 타입 머리글 지우기** — 연산이 없다. 고치기 · 폐기 · 이름 바꾸기는 그 레포 큐레이터의 save(`vocab[].op`)다. 지우는 것이 정말 필요하면 clone 에서 `_vocab.md` 를 고쳐 origin 에 push → 「origin 과 맞추기」(과거 기록이 그 이름을 쓰면 미등재 오류가 된다).
- **팀 서식** — `data/forms/<묶음>/<번호>_<제목>.md` 에 두면 갱신이 덮지 않는다. 둔 뒤 `cdp forms check --data /opt/cdp/data`(문제가 있으면 exit 1).
- **기준선 생성기** — 프로젝트의 것이다. 생성기용 계정(writer + 그 레포 큐레이터 · 토큰 `never`)만 만들어 주고 토큰은 생성기 PC 에만.

## 8. 갱신 — 새 판

```bash
sudo bash /opt/cdp/deploy/upgrade.sh /tmp/cdp-server-v<판>.tar.gz      # [--prefix /opt/cdp] [--user cdp]
cdp serve doctor
```

**무엇이 일어났나** — `.bak` 한 세대(`bin/ctx.mjs` · `web` · `forms` · `kit` · `manual`) → 갈아 끼움 → 재시작 → `/healthz.built` 와 화면 자산 해시가
새 번들의 것인지 대조 → 다르면 **스스로 되돌리고** exit 1. 명부 · 대장 · 레포 · git 자격 · `serve.json` · 팀 서식은 건드리지 않는다.
**kit 이 바뀐 판이면** 끝에 사람들이 할 한 줄(`--update [--commit]`)을 말한다 — 안 바뀌었으면 말하지 않는다. 같은 명령이 콘솔 **서버 › 갱신**에 있다.

- 사람들에게 — 강제 새로고침(`Ctrl+Shift+R`) 한 번. 로그인은 재시작을 넘어 살아 있다.
- 되돌리기 — `.bak` 을 제자리로 옮기고 `sudo systemctl restart cdp-serve`.
- Docker — 새 판 폴더에서 `docker compose -p cdp -f deploy/docker-compose.yml up -d --build`.
- **v1.0 이전 서버**에서 올리면 레포 정리(`ctx migrate`)와 관리자 승격이 더 있다 — [설치 절차 부록 B](설치절차.md).

## 9. 개인 서버 — ctx up

서버가 없는 팀 · 혼자 쓰는 사람의 길이다. 같은 코드 · `save` · 화면 · MCP 를 자기 PC 의 `127.0.0.1` 에 띄운다.

```bash
tar -xzf cdp-server-v<판>.tar.gz
node cdp-server-v<판>/bin/ctx.mjs self-update cdp-server-v<판>.tar.gz    # 처음 한 번 — ~/.cdp/server/current · 명령 ~/.cdp/bin/ctx(PATH 한 줄을 알려 준다)
ctx up ~/cdp/<레포> --install <코드 폴더> --curator <큐레이터 폴더>        # 레포(없으면 빈 틀) · 서버 · 토큰 · 붙이기 · 브라우저
```

**무엇이 일어났나** — 빈 포트(7400~) · 명부(나 하나 · admin) · 토큰을 `~/.config/cdp/token` 에 · 설치기를 그 토큰으로(복사 없음) · 끝에 다음 할 일.
이미 떠 있으면 그 주소를 쓴다. 데이터는 `~/.cdp/personal/<레포>/`(자동 로그인 주소는 `login.url`).

| | |
|---|---|
| 늘 켜 두기 | `ctx up <레포> --service` — 로그인하면 뜬다(macOS launchd · Linux systemd --user) |
| 새 판 | `ctx self-update <tar.gz 또는 url>` — SHA256SUMS 대조 · 서비스면 다시 띄운다 → `ctx up <레포> --update [--commit]` |
| 점검 | `ctx serve doctor --personal <레포>` |
| origin | 원격이 있으면 save 마다 민다 |

팀이 같이 쓰게 되면 팀 서버(2장)를 세운다 — 한 레포를 두 서버가 쓰지 않는다(쓰는 길은 하나).

## 10. 막혔을 때

설치 · 셸 단계의 메시지는 [설치 절차 5장](설치절차.md). 먼저 `cdp serve doctor`(= 콘솔 **서버 › 진단**) — fail 줄이 답이다.

| 증상 | 볼 곳 |
|---|---|
| `밀림 · 인증 실패` 가 안 풀린다 | PAT 만료 · 배포 키 삭제 — 2.1 을 다시 → 「다시 보내기」 |
| `갈림` · `트리 더러움` · `origin 앞섬` | 7.1 |
| `save` 가 `E_CHECK` 인데 자기 잘못이 없다고 한다 | 막는 것은 **그 save 가 새로 만든 오류**뿐이다 — `detail` 이 기록 쪽이면 사용자, 문서 쪽이면 큐레이터 |
| 401 인데 토큰은 맞다 | 만료 · 비활성 · 폐기 — `cdp serve token list` · 3장 재발급 |
| 로그인은 되는데 레포가 없다 | 그 사람의 볼 레포가 비었다 — **사람 › 레포 × 사용자** |
| 큐레이터인데 대기열 메뉴가 없다 · 설치기가 「큐레이터가 아닙니다」 | viewer 다 · 그 레포를 못 본다 · 체크가 없다 — 4장 |
| 설치기 · `--update` 가 「그 등록은 X 의 것이다」(409) | 다른 레포의 한 줄을 썼다 — X 의 연결된 작업 레포에서 다시 받는다 |
| 현황 「주소와 다른 레포에 쓴 save」 | 그 작업 레포의 `.mcp.json` 과 `.claude/cdp.json` 이 갈렸다 — 원래 레포의 설치 한 줄을 다시 |
| 현황 「시계가 N분 빠르다 · 늦다」 | 서버 `timedatectl`(NTP) · PC `w32tm /resync` |
| 진단 「도구 층」 | v1.0 이전 레포 — [설치 절차 부록 B](설치절차.md) |
| 진단 `kit` · `forms` · `manual` | 번들 옆 폴더가 없다 — `upgrade.sh` 로 다시. 손으로 갈지 않는다 |
| 화면만 안 뜬다 | `<prefix>/web/index.html` — MCP · 읽기 API 는 돈다 |
| 밖에서만 안 된다 | 방화벽 — [설치 절차 2장](설치절차.md) |

로그 — `data/logs/serve.log`(요청 · 3 × 1MB 회전 · 내용 · 토큰 없음) · `auth.log`(이력) · `journalctl -u cdp-serve`(시작조차 못 할 때).

## 부록 A. 파일 자리

| 경로(`/opt/cdp` 아래) | 무엇 | 누가 바꾸나 |
|---|---|---|
| `serve.json` | 설정 한 장 — 사람이 더한 칸(`adminFrom` · `publicUrl` …)은 `install.sh` 가 다시 돌아도 둔다 | `install.sh` · 사람 |
| `bin/` `web/` `forms/` `kit/` `manual/` `deploy/` | 번들 · `*.bak` 한 세대 | `upgrade.sh` |
| `repos/<이름>/` | 지식 레포 | 서버의 `save` |
| `auth.json` | 명부(600 · 토큰은 해시) | 콘솔 **사람** · `cdp serve user/token` |
| `data/logs/` | `serve.log`(회전) · `auth.log`(회전 안 함) | 자동 |
| `data/workrepos.json` | 작업 레포 대장 | 등록 · 설치 보고 |
| `data/ssh/` · `.git-credentials` | 배포 키 · PAT(600) | git 자격 |
| `data/trash/` · `data/forms/` | 지운 레포 · 팀 서식 | 「삭제」 · 사람 |
| `data/bootstrap.code` | 첫 관리자 코드 — 명부가 비었을 때만 | 자동 |
| `/etc/systemd/system/cdp-serve.service` | 유닛 — node 경로 · `serve --config` | `install.sh` |

## 부록 B. 명령

`cdp` 는 `serve.json` 을 읽으므로 `serve …` · `repo new` 에 플래그가 없다. 다른 명령은 경로를 준다.

```
cdp serve doctor [--json]                         준비물 검사 — fail 이면 exit 1
cdp serve user add <아이디> [--role viewer|writer|admin] [--repos a,b|*] [--curate a,b] [--label "<…>"]
cdp serve user set <아이디> --role <r> | --repos <…> | --curate <…|빈 값> | --inactive | --active
cdp serve user list · cdp serve token list
cdp serve token --user <아이디> [--note "<기기>"] [--expires 30|90|never]
cdp serve token reissue --id <앞 8자> · revoke --name <아이디> [--id] · set --id <앞 8자> --note | --expires
cdp serve git-auth --host <h[:p]> --user <계정> [--test <url>] | --ssh [--rotate] | --list
cdp repo new <이름> [--origin <url> [--no-push]] [--records-from <옛 레포 경로>] [--dry]
cdp import-dir <원본> --repo <레포 경로> [--dry] [--yes]
ctx seed init|check|plan|apply|verify [--from <문서 레포>] [--server --repo] [--clone]   문서 레포에서 세우기(큐레이터)
ctx follow --from … --clone … --since <sha> · ctx update [--from …] <from> [<to>] | --save <초안> [--go]   정본 둘 잇기
cdp forms list | check --data /opt/cdp/data
cdp version
ctx up [<폴더>] [--install <폴더>]… [--curator <폴더>] [--service] [--update [--commit]]     개인 서버
ctx self-update <tar.gz|url> · ctx serve doctor --personal <레포>
```
