> 이 문서는 그것을 포함해 **서버 관리자가 맡는 일 전부**를 다룬다. 관리 문서의 내용은 큐레이터의 일이다 — admin 은 모든 레포의
> 큐레이터라 겸할 수 있다(큐레이터 설명서).
>
> **명령의 `<…>` 는 자리표시자다.** 꺾쇠까지 통째로 실제 값으로 바꾼다 — `<서버 IP>` → `192.0.2.10`, `<GitLab>` → `git.example.com:2900`.
> 그대로 치면 bash 가 `<` 를 파일 리다이렉션으로 읽어 `No such file or directory` 가 난다.

## 0. 서버 관리자가 맡는 것

### 0.1 서버 하나 · 쓰는 길 하나

```
<서버>  /opt/cdp
  bin/ctx.mjs      서버 본체 — 화면 · MCP(HTTP) · save · 관리 API · ctx 명령. Node 20 한 프로세스
  repos/<이름>/    지식 레포 — 지식만(work/ · docs/ · _vocab.md · _managed.md). 서버가 유일한 작성자
  auth.json        명부 — 사람 · 역할 · 큐레이터 · 토큰(해시)
  data/            세션 비밀 · 로그 · 작업 레포 대장 · 첨부 대기 · SSH 키 · 휴지통 · 팀 서식
  forms/ · kit/    서식집 · 작업 레포에 나가는 스킬(역할별)
  web/ · manual/   화면 · 설명서
```

**쓰는 길은 서버 `save` 하나다.** 사람이 기록을 남기든(writer) 큐레이터가 반영하든 기준선을 올리든, 서버가 검사하고 한 커밋으로
남기고 origin 에 미러한다. 레포에는 지식만 있다 — 도구 · 훅 · 스킬 사본이 레포에 없으므로 서버를 갱신해도 레포를 갈 일이 없다.

### 0.2 맡는 일

| 일 | 어디서 | 장 |
|---|---|---|
| 서버를 세우고 갱신한다 | 셸 — `install.sh` · `upgrade.sh` | 2 · 8 |
| 사람 · 역할 · 토큰 | 화면 **서버 › 사용자 · 토큰** (셸로도) | 3 |
| 레포마다 큐레이터를 맡긴다 | **서버 › 사용자 › 「레포 × 큐레이터」** | 4 |
| 지식 레포를 세운다 · origin 을 잇는다 · 치운다 | **서버 › 지식 레포** | 5 |
| 미러가 밀리거나 갈라지면 푼다 | **서버 › 지식 레포** 의 단추 · 셸 | 7 |
| v0.x 서버를 v1.0 으로 올린다 | 셸 — `ctx migrate` · 콘솔 「기록만 옮겨 오기」 | 9 |

화면의 **서버** 묶음(왼쪽 메뉴 · admin 에게만 보인다) — 현황 · 지식 레포 · 작업 레포 대장 · 사용자 · 토큰 · 감사 · 서버 설정.
주소는 `/console/…` 다. 쓰기마다 **관리자 확인**(내 토큰을 한 번 더 · 15분)을 묻는다.

## 1. 받는 것 — 산출물

개발자가 릴리스마다 둘을 낸다(GitHub Release 또는 개발 PC 의 `npm run release:server`).

| 산출물 | 누가 쓰나 | 안에 |
|---|---|---|
| **`cdp-server-v<판>.tar.gz`** | 서버 관리자 | `bin/ctx.mjs` · `web/` · `forms/`(서식집 묶음 넷) · `kit/`(스킬 다섯 · CLAUDE 블록 둘) · `manual/`(설명서 넷 · 그림) · `deploy/`(install.sh · upgrade.sh · 유닛 · Dockerfile · compose · 설치절차.md) · `README.md` |
| `cdp-site-v<판>.zip` | 공식 소개 사이트를 사내에 올릴 때만 | 정적 폴더 — 서버와 무관하다 |
| `SHA256SUMS` | 둘 다 | 반입 뒤 대조 |

```bash
sha256sum -c SHA256SUMS
tar -xzf cdp-server-v<판>.tar.gz && node cdp-server-v<판>/bin/ctx.mjs version     # 날짜 한 줄 · mcp: http
```

**폐쇄망 반입** — 인터넷을 타는 것이 하나도 없다(화면의 폰트까지 파일 안에 있다). tar.gz 한 개와 `SHA256SUMS` 를 옮기면 된다.
작업 PC 쪽은 설치 한 줄이 이 서버에서 받으므로 따로 반입할 것이 없다.

## 2. 서버 설치

사람이 셸에서 치는 것은 `install.sh` 와 git 자격(PAT 일 때) 둘이다. 첫 관리자는 브라우저 `/setup` **마법사**에서 만들고, 레포 · 사람은
**서버** 화면에서 한다. 나머지는 `doctor` 가 확인한다. 한 줄씩은 [서버 설치 절차](설치절차.md).

### 2.0 준비물

- [ ] 리눅스 서버에 SSH · `sudo`. Debian/Ubuntu 또는 RHEL 계열
- [ ] **Node 20 이상** · **git** — `install.sh` 가 첫 줄에서 확인하고 없으면 무엇을 깔지 말하고 멈춘다. `nvm` 은 쓰지 않는다(서비스 계정에서 안 보인다)
- [ ] 서버가 사내 GitLab(`<GitLab>`)에 닿는다 — 미러용. 그 프로젝트에 push 할 수 있는 자격(배포 키 또는 PAT)
- [ ] 명부에 올릴 **사람과 권한** — 누가 어느 레포를 보고, 누가 writer(기록을 남긴다)이고, **누가 어느 레포의 큐레이터**이고, 누가 admin 인가

### 2.1 `install.sh`

```bash
scp cdp-server-v<판>.tar.gz <계정>@<서버 IP>:/tmp/ && ssh <계정>@<서버 IP>
cd /tmp && tar -xzf cdp-server-v<판>.tar.gz && cd cdp-server-v<판>
sudo bash deploy/install.sh --bind <서버 IP>      # [--port 7374] [--prefix /opt/cdp] [--user cdp] [--no-systemd] [--dry]
```

하는 일 — Node · git 확인 → 계정 `cdp` → `/opt/cdp/{bin,repos,data,web,forms,kit,manual}` → 파일 배치 → **node 경로 · bind · port 를 박은 유닛**
→ `systemctl enable --now` → `/healthz` 확인 → 방화벽 명령 **안내** → 첫 관리자의 `/setup` 주소와 **부트스트랩 코드**. **두 번 돌려도 같다** —
있는 것은 건너뛰고 그 사실을 찍는다. `--bind` 는 필수다 — 프록시가 없는 배치에서 바인드가 유일한 경계다(`0.0.0.0` 이 아니라 그 IP 하나).

**포트를 연다** — `install.sh` 는 안내만 한다. 확인은 **다른 장비에서**(자기 주소는 방화벽을 안 탄다).

```bash
sudo firewall-cmd --permanent --add-port=7374/tcp && sudo firewall-cmd --reload
curl -s -m 5 http://<서버 IP>:7374/healthz          # 개발 PC 에서
```

> **systemd 가 무엇인가.** 리눅스가 백그라운드 서비스를 켜고 관리하는 장치다. `ctx serve` 한 프로세스를 `cdp-serve` 서비스로 등록해
> 부팅 때 켜고 죽으면 되살린다. 없으면 `install.sh` 가 유닛 파일만 써 두고 직접 띄우는 명령을 찍어 준다. Docker 는 이 층을 대신하는 선택지다(2.6).

### 2.2 git 자격 — SSH 배포 키 · PAT

**서버가 origin 으로 push 할 자격이다.** 커밋의 `author` 는 CDP 토큰의 사용자로 서버가 채우므로 누가 정했는지는 사람별로 남는다.
**어느 쪽이든 비밀은 브라우저를 건너지 않는다** — 서버는 평문 HTTP 다.

| 길 | 원격 주소 | 어디서 | 비밀 |
|---|---|---|---|
| **(가) SSH 배포 키 — 권장** | `ssh://git@<GitLab>/<그룹>/<프로젝트>.git` | **서버 › 서버 설정 › git 자격** | 개인 키는 서버가 만들고 `<data>/ssh/` 밖으로 안 나간다. 화면에는 공개 키 · 지문뿐 |
| **(나) PAT** | `http://<GitLab>/<그룹>/<프로젝트>.git` | 서버 셸 — `ctx serve git-auth` 한 줄 | 숨김 입력으로 셸에서만. 화면은 받지 않는다 |

**(가)** — 「배포 키 만들기」 → 공개 키를 GitLab › 프로젝트 › Settings › Repository › **Deploy keys** 에 붙이고 「Grant write permissions」 를 켠다
(프로젝트마다) → 원격 주소를 넣고 「호스트 키 받기」 → **GitLab 관리자에게 받은 지문과 같으면** 「이 지문을 믿는다」 → 「접속 확인」(`ls-remote` —
아무것도 보내지 않는다). 키는 레포마다 로컬 설정(`core.sshCommand`)으로 걸린다. 「새로 만들기」 는 옛 키를 `.old-<시각>` 으로 남긴다.

**(나)** — GitLab 에서 PAT 발급(`write_repository` · 만료 1년 — 비워 두지 않는다) → 서버 셸에서

```bash
sudo -u cdp -H node /opt/cdp/bin/ctx.mjs serve git-auth --host <GitLab> --user <GitLab 계정> \
     --test http://<GitLab>/<그룹>/<프로젝트>.git
sudo -u cdp -H node /opt/cdp/bin/ctx.mjs serve git-auth --list --data /opt/cdp/data     # 지금 상태 — 호스트 · 계정 · 키 지문(비밀 없음)
```

PAT 를 숨김 입력으로 받아 `.git-credentials`(600)에 쓰고 `credential.helper store` 를 건다. PAT 를 바꿀 때도 같은 명령이다. 다른
`credential.helper` 가 있으면 멈춘다(바꾸려면 `--yes`). 스코프가 `api` 뿐인 옛 GitLab 이면 계정 전체를 연다 — `doctor` 가 warn 을 계속 낸다.

### 2.3 첫 관리자 — `/setup` 마법사

`install.sh` 가 끝에 찍은 주소와 코드를 쓴다 — `http://<서버 IP>:7374/setup` → 코드 → 내 아이디 · 라벨 → **토큰 원문이 한 번** 보인다
(`CDP_TOKEN` 에 넣는다). 그 브라우저는 이미 로그인됐다. 코드는 `/opt/cdp/data/bootstrap.code` 에 있고 쓰면 지워진다 — 잃었으면
`sudo journalctl -u cdp-serve | grep 코드`.

브라우저로 서버에 닿지 못하면 셸로 — `sudo -u cdp node /opt/cdp/bin/ctx.mjs serve init --auth /opt/cdp/auth.json --data /opt/cdp/data --name <아이디> --label "<이름 · 소속>"`.
첫 사용자는 **admin** 이고 레포 전체(`*`)를 본다. 명부가 이미 있으면 둘 다 거절한다(덮지 않는다).

### 2.4 확인 — `doctor` 가 fail 0

```bash
CTX="sudo -u cdp node /opt/cdp/bin/ctx.mjs"
$CTX serve doctor --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data --web /opt/cdp/web --bind <서버 IP> --port 7374 [--json]
```

```
 ok    node        v20.x
 ok    git         git version 2.x
 ok    auth.json   /opt/cdp/auth.json
 ok    명부        사용자 3 · admin 1 · writer 2 · 토큰 3
 ok    --data      /opt/cdp/data
 ok    --web       /opt/cdp/web
 ok    manual      /opt/cdp/manual · 설명서 4권
 ok    kit         /opt/cdp/kit (번들 옆)
 ok    forms       /opt/cdp/forms (번들 옆)
 ok    레포 alpha   head abc1234 · origin/main · push 자격 있음      ← 2.2 의 쓰기 확인이 이 줄이다
 ok    서버        <서버 IP>:7374 응답 · built … · 레포 1 · 미러 ok 1 lag 0 off 0
doctor: fail 0 · warn 0 · ok 11
```

`fail` 이 하나라도 있으면 exit 1 — 고치기 전에는 다음으로 가지 않는다. 같은 줄이 화면 **서버 › 서버 설정 › 진단**에도 있다.

### 2.5 화면 확인

`http://<서버 IP>:7374/` — **소개 페이지**(인증 없음 · 레포 이름 · 사람 이름을 싣지 않는다) · [설명서] 에 네 권과 설치 절차.
[로그인] → 토큰 한 칸 → admin 은 **서버 › 현황**으로 들어간다. 왼쪽 메뉴의 묶음 — 지식 · 큐레이션(큐레이터) · 레포 관리 · 서버(admin) ·
설명서 · 내 계정. 화면이 안 떠도 **MCP 와 읽기 API 는 돈다** — `/opt/cdp/web/index.html` 을 본다.
소개 · 설명서까지 로그인 뒤에만 보이게 하려면 유닛의 `ctx serve` 에 `--private-pages`, 관리 API 를 사내 대역으로 좁히려면 `--admin-from <CIDR>`.

### 2.6 Docker — 선택지

같은 `ctx serve` 를 systemd 대신 컨테이너로 띄운다(`node:20-slim` + git).

```bash
cd cdp-server-v<판> && touch auth.json
docker compose -f deploy/docker-compose.yml up -d --build
docker compose -f deploy/docker-compose.yml exec cdp node bin/ctx.mjs serve init --auth /opt/cdp/auth.json --data /opt/cdp/data --name <아이디>   # 또는 /setup
```

컨테이너 안은 `--bind 0.0.0.0` 이 맞다 — 경계는 호스트의 `-p` 매핑이다. 명부 · 레포 · 자격은 볼륨과 호스트 파일에 남는다.
나머지 절차는 명령 앞에 `docker compose … exec cdp` 가 붙는 것만 다르다. Windows 서버는 WSL2 Ubuntu 에 2.1 로 설치한다.

### 2.7 되돌리기

```bash
sudo systemctl disable --now cdp-serve
sudo rm /etc/systemd/system/cdp-serve.service && sudo systemctl daemon-reload
sudo rm -rf /opt/cdp && sudo userdel cdp          # 데이터를 지울 때만
```

GitLab 의 배포 키 · PAT 도 뗀다. **지식 레포는 origin 에 그대로 있다** — 미러로 보낸 커밋이 백업이다.

## 3. 사람 — 명부와 토큰

### 3.1 모델 — 권한은 사람에게, 토큰은 신원만

```
auth.json
  users[]    name · label · repos(볼 수 있는 레포) · role(viewer · writer · admin) · curate(큐레이터인 레포) · active
  tokens[]   sha256 · id · user · issued · expires · note · status(active · revoked)     ← 원문은 없다
```

| 역할 | 할 수 있는 것 |
|---|---|
| `viewer` | 읽는다 — 화면 · 검색 · MCP 읽기 도구 |
| `writer` | + `save` 로 **작업 기록**을 남긴다 · 작업 레포를 등록한다 |
| `writer` + `curate` | + **그 레포의** 대기열 · 판정 · 섹션 쓰기 · 새 문서 · 등록부 · 기준선(4장) |
| `admin` | + **서버** 묶음 — 사람 · 토큰 · 지식 레포 세우기 · 서버 설정 · 감사. 레포 전체 · **모든 레포의 큐레이터** |

- **권한은 사람(`users[]`)에 붙는다.** 토큰은 "이 사람이다" 만 증명한다. 역할 · 레포를 바꾸면 그 사람의 토큰 전부에 **다음 요청부터** 먹는다 — 재시작 없음.
- **토큰 원문은 저장되지 않는다.** SHA-256 만 남는다. 사용자가 「토큰 주세요」 를 누를 자리는 없다 — 발급은 관리자가 한다.
- **`writer` 는 기본이 아니다.** 기록을 남길 사람에게만. `admin` 은 둘 이상 두되 아무에게나 주지 않는다 — 마지막 관리자는 내릴 수 없다.

### 3.2 사람을 추가한다

**서버 › 사용자** › [+ 사용자] — 이름(아이디) · 라벨 · 역할 · 볼 수 있는 레포. 저장하면 그 행의 [발급] 으로 이어진다(3.3).

| 칸 | |
|---|---|
| 이름 | 영문 · 숫자 · `.` `_` `-`. **커밋의 `author` 로 남는다** — 사내 아이디를 쓴다. 바꿀 수 없다 |
| 볼 수 있는 레포 | 체크. 전체(`*`)는 사람에게 붙는 값이다. 「레포 × 사용자」 표에서도 고친다 |
| 역할 | `viewer` 기본. 큐레이터는 역할이 아니라 레포별 체크다(4장) |

셸 — `$CTX serve user add --auth $A --data $D --name <아이디> --label "<소속 · 역할>" --repos alpha[,beta] [--role writer|admin] [--curate alpha]`.

### 3.3 토큰을 발급한다

**서버 › 토큰** › [발급] — 사용자 · 메모(기기) · 만료. **원문은 다음 화면에 한 번** 보인다 — [복사] 해서 **본인에게 직접** 전한다
(메신저 · 메일 · 이슈에 평문으로 남기지 않는다 — 남겼으면 유출로 보고 재발급). 받은 사람은 설치 한 줄이 물을 때 붙여넣는다(사용자 설명서 2장).

| | |
|---|---|
| 메모 | 기기마다 하나씩 발급하고 메모를 붙인다 — 하나를 잃으면 그것만 죽인다 |
| 만료 | 기본은 역할이 정한다 — **관리자 30일 · 나머지 90일.** `무기한` 은 감시용 계정 · 기준선 생성기에만 |

셸 — `$CTX serve token --auth $A --data $D --user <아이디> --note "<기기>" [--expires 30|90|never]`. stdout 한 줄이 원문이다.

### 3.4 바꾸기 · 비활성 · 재발급 · 폐기

**서버 › 사용자** — 행의 [역할] · [레포] · [비활성]. 퇴사 · 이동은 **비활성** — 삭제는 없다(그 사람이 남긴 커밋의 `author` 가 명부와
이어져야 한다). 자기 자신의 역할을 내리거나 자신을 끌 수 없다.

**서버 › 토큰** — [재발급] · [연장] · [메모] · [폐기]. **토큰을 잃었다 · 만료됐다 → 재발급**(옛것 폐기 + 새것 한 동작 · 원문 1회 · 30초).
권한은 그대로다. 폐기한 행은 회색으로 남는다 — 「이 사람 토큰이 언제 있었나」 가 이력이다. **분기마다** 「만료 · 마지막 사용」 으로 안 쓰는
토큰을 정리한다 — 현황이 7일 안 만료를 경고로 낸다.

셸 — `$CTX serve user set --name <아이디> --role <r> | --repos <…> | --curate <…> | --inactive` · `$CTX serve token revoke|reissue|set …` · `user list` · `token list`.

### 3.5 이력

발급 · 폐기 · 명부 변경 · 레포 생성 · 재인증 · 미러 단추는 `/opt/cdp/data/logs/auth.log` 에 남는다(토큰은 앞 8자만). **서버 › 감사**가 그 파일
그대로다 — 화면에서 한 것은 행위자가 붙고, 셸에서 한 것은 `(셸)`. 회전하지 않는다. 요청 로그는 `serve.log`(3 × 1MB 회전) — **서버 › 서버 설정 › 로그**.

## 4. 큐레이터 맡기기

**관리 문서는 큐레이터만 바꾼다.** 사람들은 작업 기록만 쌓고, 큐레이터가 판정해 반영한다. 큐레이터가 없는 레포는 기록이 대기열에만
쌓인다 — 읽는 사람은 섹션 옆 「미반영」 으로 기록을 보지만, 관리 문서는 자라지 않는다. **레포를 세우면 큐레이터부터 맡긴다.**

### 4.1 누구에게

- 그 레포의 **writer** 중 — 팀 리드 · 문서 담당. viewer 는 될 수 없다(역할을 writer 로 먼저).
- 레포마다 여럿이어도 된다 — 병목을 줄인다. 섹션 점유가 없으니 문서나 주제로 나눠 맡게 한다.
- admin 은 모든 레포의 큐레이터다 — 체크하지 않아도 된다.

### 4.2 어디서

**서버 › 사용자 › 「레포 × 큐레이터」** 표 — 체크 하나가 그 사람의 `curate` 한 줄이다(저장 즉시 다음 요청부터). 칸의 뜻 —
`●` 관리자(언제나) · `—` viewer(될 수 없다) · 회색 칸은 그 사람이 볼 수 없는 레포(위 표에서 먼저 연다).

셸 — `$CTX serve user set --auth $A --data $D --name <이름> --curate alpha,beta` (빈 값이면 해제 · `*` 는 볼 수 있는 레포 전부).

### 4.3 맡긴 뒤 큐레이터가 할 것

1. 자기 PC 에 **큐레이터 폴더**를 만들고 설치 한 줄 `--curator --repo <레포>`(큐레이터 설명서 1장) — git · 대장 등록 없이 폴더 하나.
2. 화면 왼쪽 메뉴에 「큐레이션」(대기열 · 이력 · 서식집)이 생긴다.
3. 대기열의 가장 오래된 것부터 판정한다. 가장 오래된 대기가 14일을 넘으면 검사가 경고하고 **서버 › 지식 레포** 표의 대기 열이 알린다.

기준선 생성기(7.5)도 큐레이터 권한의 토큰으로 돈다 — 생성기용 계정(writer + curate · 토큰 무기한 · 메모 「기준선 생성기」)을 따로 둔다.

## 5. 지식 레포 세우기

**폴더명이 곧 레포 이름이다.** 등록 = `/opt/cdp/repos/` 아래에 `_vocab.md` 가 있는 git 폴더를 두는 것. 이름은 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`.

### 5.1 서버 › 지식 레포 › [새 지식 레포]

| 길 | 언제 | 하는 것 |
|---|---|---|
| **빈 레포로 세운다** | 새 프로젝트 | **빈 틀 하나** — `README.md` · `_vocab.md` · `_managed.md` · `docs/` · `work/` · `.gitattributes` · `.gitignore` · 첫 커밋. 서식 · 문서는 붓지 않는다 — 큐레이터가 서식집에서 세운다 |
| **+ 기록만 옮겨 오기** | 옛 레포를 다시 세운다(9장) | 빈 틀 위에 옛 레포의 작업 기록 · 첨부 · **그 기록이 쓰는 좌표의 어휘만** 옮긴다. 관리 문서 · 등록부 행 · 옛 파생 정리 기록은 옮기지 않는다. 옮긴 기록은 **전부 대기열**에 선다 |
| **origin 에서 받아 온다** | 지식 레포가 이미 있다 | clone — `_vocab.md` 가 없으면 지운다 |

같은 창에서 볼 사람을 고른다(접근 부여). 관리자 확인(재인증) 뒤에 돌고 `auth.log` 에 남는다. GitLab 프로젝트는 **웹에서 먼저 만든다** —
서버가 만들 수는 없다. 세운 뒤 **큐레이터를 맡긴다**(4장).

셸에서 같은 것 —

```bash
$CTX repo new /opt/cdp/repos/<이름> [--title "<한 줄>"] [--origin http://<GitLab>/<그룹>/<프로젝트>.git --push] [--dry]
$CTX repo new /opt/cdp/repos/<이름> --records-from /opt/cdp/repos/<옛 레포>          # 다시 세우기
sudo -u cdp -H git clone <origin url> /opt/cdp/repos/<이름>
```

> **서버는 새 폴더를 그 이름으로 가는 첫 요청에서 바로 알아본다** — 재시작은 필요 없다. 전체 목록만 1분 주기다.

### 5.2 세운 뒤 — origin 연결 · 삭제

**서버 › 지식 레포** 의 행마다 — 둘 다 관리자 확인 뒤에 돌고 `save` 와 같은 줄(뮤텍스)에 서며 `auth.log` 에 남는다.

| 단추 | 하는 것 |
|---|---|
| **「origin 연결」** | 주소 하나를 받아 `remote add`(있으면 `set-url`) → `push -u origin HEAD`. **강제 push 는 없다** — 원격에 커밋이 있으면 `non-ff` 로 거절되고 남의 이력을 덮지 않는다. push 가 실패해도 원격은 남는다 — 자격을 고친 뒤 다시 누른다. 주소는 PAT(`http://…`) · 배포 키(`ssh://…`) 둘 다. 연결 창이 모자란 자격을 먼저 말한다 |
| **「삭제」** | 레포 이름을 **그대로 쳐야** 열린다. 폴더를 `<data>/trash/<레포>-<시각>/` 로 **옮긴다 — 영구 삭제는 없다.** 화면 · MCP 에서 사라지고 명부의 레포 할당에서 빠진다. 원격이 없거나 밀린 커밋이 있으면 창이 먼저 말한다 — 그때 휴지통이 유일한 사본이다 |

휴지통은 스스로 비지 않는다 — 셸에서 지운다. 되살리기 — `sudo -u cdp mv /opt/cdp/data/trash/<이름>-<시각> /opt/cdp/repos/<이름>` 뒤 할당을 다시 준다.

### 5.3 기존 문서 들이기 — `ctx import-dir`

회의록 · 검토서 같은 md 폴더 **수십 · 수백 건**을 작업 기록으로 들인다(몇 건이면 사용자의 `cdp-save` 편입이 맞다).
서버 트리에 직접 돌리지 않는다 — 서버를 멈추거나 사람이 쓰지 않는 때에.

```bash
$CTX import-dir <원본 폴더> --repo /opt/cdp/repos/<레포> --dry      # 표만 찍는다 — 먼저 본다
$CTX import-dir <원본 폴더> --repo /opt/cdp/repos/<레포> [--author <이름>] [--keep-touches] [--yes]
```

날짜는 프론트매터 → 파일명 → git → mtime 순으로 근거를 찾아 표에 적는다. **좌표는 추측하지 않는다**(원본의 `touches` 는 `tags` 에
`touches/<좌표>` 로 보존). 쓴 뒤 검사에서 오류가 나면 쓴 것을 전부 되돌린다. 들인 기록은 대기열에 선다 — 큐레이터가 판정한다.

## 6. 작업 레포 · 큐레이터 폴더

### 6.1 작업 레포 — 설치 한 줄

작업 레포(코드가 있는 레포)마다 한 번 — **사용자가 한다**(사용자 설명서 2장). 흐름 —

1. writer 가 그 지식 레포의 **레포 관리 › 연결된 작업 레포** 에 등록한다. 등록은 관문이 아니라 **장부**다.
2. 그 행의 [설치 방법] 한 줄 — 공개 `GET /install.mjs`(설치기 · 서버 주소뿐 — 레포 · 사람 · kit 은 없다)를 임시 폴더에 받아 돌린다.
   **토큰은 명령에도 설치기에도 없다** — 설치기가 숨김 입력으로 묻고 서버에 확인하고, kit 을 **그 토큰으로** 받는다.
3. 들어가는 것 — `.mcp.json`(cdp 항목) · `.claude/cdp.json` · `.claude/skills/` **writer kit**(cdp-work · cdp-save · cdp-push) · `CLAUDE.md` 블록. 커밋한다.
4. 대장에 보고 — 행이 `최신`.

**kit 은 서버 번들의 `kit/` 에서 나간다** — 레포마다 다르지 않다. 판을 올리면(8장) 모든 레포의 kit 이 같이 바뀌고, 대장의 행이 `낡음` 이
된다 → 담당자가 자기 PC 에서 `--update` 한 줄(그 PC 에 이 서버로 설치한 작업 레포 전부 · `--commit` 이면 바꾼 파일만 커밋).

서버 전부의 대장은 **서버 › 작업 레포 대장** — 레포 · 담당 · 상태 · 마지막 보고. 지식 레포를 휴지통으로 보낸 뒤 남은 등록은
「지식 레포 없음」 칩 · [삭제](admin). 등록 id 가 다른 레포의 것이면 서버가 409 로 막는다(「그 등록은 X 의 것이다」).

### 6.2 큐레이터 폴더 — `--curator`

큐레이터는 자기 PC 의 폴더 하나에 큐레이터 kit(스킬 다섯 · 큐레이터 블록)을 받는다 — git · 대장 등록 없이. 토큰이 그 레포의 큐레이터가
아니면 설치기가 멈춘다. 갱신은 같은 한 줄을 다시. 자세히는 [큐레이터 설명서](큐레이터_설명서.md) 1장.

## 7. 운영

### 7.1 점검

| 언제 | 무엇을 |
|---|---|
| 매일 | **서버 › 현황** — 경고 목록 · 최근 감사 · 대기가 오래된 레포 · `curl /healthz`(`mirror.ok` 가 레포 수와 같은가) |
| 주기적 | **서버 › 서버 설정 › 진단** fail 0(= `doctor`) · **서버 › 토큰** 의 만료 · 마지막 사용 · **서버 › 지식 레포** 의 대기 · 가장 오래된 열 |
| 감시 | `GET /healthz` 를 감시 목록에(인증 없음 · 레포 이름 없음 · 집계만) · `doctor --json` 을 크론에 |
| 백업 | `--mirror`(origin 이 백업이다) + `/opt/cdp/repos` 디스크 스냅샷 · `auth.json` · `data/` |

### 7.2 미러 — 서버 트리와 origin 을 맞추는 자리는 화면이다

서버는 그 트리의 **유일한 작성자**다. `save` 가 커밋하면 `--mirror` 가 origin 으로 민다. 서버는 스스로 fetch · pull 하지 않는다 —
대신 진단이 origin 이 앞선 것을 알아내고, push 가 거부되면 그때 fetch 해서 사유를 남긴다. **서버 › 지식 레포** 의 칩과 단추가 그 답이다.

| 칩 | 뜻 | 단추 |
|---|---|---|
| `밀림 N · <사유>` | 서버 커밋이 origin 에 못 갔다. 사유 — `인증 실패` · `원격 불통` · `보호 브랜치` · `ref 잠김` · `non-ff` | **「다시 보내기」** — 사유를 고친 뒤 |
| `origin 앞섬` | 누군가 서버 밖에서 썼다 — 서버는 아직 그 커밋이 없다 | **「origin 과 맞추기」** — fetch → ff-only → 다시 읽기. merge 가 아니다 |
| `갈림 N · non-ff` | 서버에도 origin 에도 서로 모르는 커밋 — 기계는 합치지 않는다 | 셸에서 `sudo -u cdp -H git -C /opt/cdp/repos/<레포> pull --rebase` 뒤 「다시 보내기」 |
| `트리 더러움 N` | 커밋 안 된 변경(중단된 save · 사람의 손). **`save` 가 거절된다** | **「트리 되돌리기」** — 버릴 경로를 보여 준 뒤 HEAD 로 |

단추는 전부 관리자 확인 뒤에 돌고 `save` 와 같은 줄(뮤텍스)에 서며 `auth.log` 에 남는다. 레포 화면 아래 상태 표시줄 · `save` 의 경고 ·
`brief` 는 같은 사실을 **이상이 있을 때만** 한 줄로 말한다. 서버가 떠 있을 때 셸에서 git 을 만지면 `save` 와 겹칠 수 있다 — 화면이 안전하다.

### 7.3 바깥에서 고쳤을 때

쓰는 길은 `save` 하나다. 그래도 서버 밖(clone)에서 origin 에 push 했으면 서버 트리가 뒤처지고 다음 `save` 의 push 가 non-ff 로 거부된다.
**origin 앞섬**이 뜨면 「origin 과 맞추기」. 서버에도 밀린 커밋이 있었으면 갈림이다(위 표). 바깥에서 쓰는 일은 드물게 둔다 — 검사 ·
큐레이션 판정을 거치지 않은 글이 들어간다.

### 7.4 어휘 정리 — save 의 연산이 없는 것

`save` 로 어휘는 **더하기만** 된다. **있는 좌표에 alias 를 더하는 것 · 폐기(`deprecated`) 표시**는 연산이 없다 — 큐레이터가 청하면
관리자가 clone 에서 `_vocab.md` 를 고쳐 origin 에 push 하고 「origin 과 맞추기」(7.3) 로 들인다. 지우지는 않는다 — 과거 기록이 그 이름을 쓴다.

```markdown
- `table:bk_loan_old` — 대출 (구)
  deprecated: 2026-10-01 bk_loan_mst 로 합침
  supersededBy: table:bk_loan_mst
```

### 7.5 기준선 생성기

코드 · DB 에서 기계로 뽑는 사실(컬럼 표 · 프로그램 목록)은 섹션 안 **기준선 블록**으로 들어간다(큐레이터 설명서 9장). 생성기는
**프로젝트의 것**이다 — 제품은 블록 형식과 올리는 길(`POST /api/<레포>/baseline` · `ctx baseline push`)만 준다. 관리자가 할 것은
생성기용 계정(writer + 그 레포 curate · 토큰 무기한)을 만들어 주고, 야간 크론이면 그 토큰을 생성기 PC 에만 두는 것이다.

### 7.6 팀 서식

팀이 만든 서식은 `/opt/cdp/data/forms/<묶음>/<번호>_<제목>.md`(+ `_묶음.json`)에 둔다 — `upgrade.sh` 가 덮지 않는 자리다. 같은 id 면
팀 서식이 이긴다. 서식 파일의 모양은 큐레이터 설명서 7.2.

### 7.7 만료가 있는 것들

| | 주기 | 지나면 |
|---|---|---|
| CDP 토큰 | 관리자 30일 · 나머지 90일 | 그 사람만 401. 3.4 — 재발급. 현황이 7일 전부터 경고한다 |
| GitLab PAT | 1년(발급 때 정한 것) | **미러가 조용히 멈춘다** — `doctor` 의 push 줄 · `밀림 · 인증 실패`. 2.2 를 다시(재시작 불필요). 달력에 넣는다 |
| 큐레이션 대기 | 14일이면 경고 | 큐레이터에게 — 맡긴 사람이 없으면 4장 |

## 8. 갱신 — 새 판이 나왔을 때

새 판을 올리는 것은 **한 명령**이고, 그 앞뒤에 사람이 보는 것이 셋이다.

```bash
# ① 받는다 — 판을 본다
scp cdp-server-v<판>.tar.gz <계정>@<서버 IP>:/tmp/ && ssh <계정>@<서버 IP>
cd /tmp && tar -xzf cdp-server-v<판>.tar.gz && node cdp-server-v<판>/bin/ctx.mjs version     # 날짜 · mcp: http

# ② 올린다
sudo bash /opt/cdp/deploy/upgrade.sh /tmp/cdp-server-v<판>.tar.gz      # [--prefix /opt/cdp] [--user cdp]

# ③ 확인한다
$CTX serve doctor --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data --web /opt/cdp/web --bind <서버 IP> --port 7374
curl -s http://<서버 IP>:7374/healthz; echo          # built 가 새 번들 시각
```

`upgrade.sh` 가 하는 일 — 푼다 → 되돌릴 것을 챙긴다(`bin/ctx.mjs.bak` · `web.bak` · `forms.bak` · `kit.bak` · `manual.bak` — 한 세대) → `ctx.mjs`
교체 · `web/` · `forms/` · `kit/` · `manual/` 은 **비우고** 넣는다 · 설치절차.md 교체 → 재시작 → **`/healthz.built` 가 새 번들 시각인지 · 화면 자산 해시가
tar 의 것과 같은지** 대조 → 다르면 `.bak` 으로 되돌리고 exit 1. **명부 · 대장 · 레포 · git 자격 · 유닛 · 팀 서식은 건드리지 않는다** — 레포에는
지식만 있다.

올린 뒤 —

| | |
|---|---|
| 브라우저 | 사람들에게 강제 새로고침(`Ctrl+Shift+R`)을 알린다. 로그인은 재시작을 넘어 살아 있다 — 끊기는 것은 그 순간의 요청뿐이다 |
| 스킬이 바뀐 판 | 작업 레포 대장의 행이 `낡음` — 담당자가 `--update` 한 줄. 큐레이터는 자기 폴더에서 `--curator` 한 줄을 다시 |
| 되돌리기 | `.bak` 을 제자리로 옮기고 `sudo systemctl restart cdp-serve` — 한 세대만 있다 |

v0.9 이하의 서버를 올리면 **관리자 승격**이 한 번 더 있다(명부에 역할이 없어 관리자가 0명) — [설치 절차](설치절차.md) 10장.

## 9. v1.0 으로 올리기

v1.0 은 세 가지를 바꾼 메이저 판이다 — ① **쓰는 길은 서버 `save` 하나**(PC 의 지식 레포 + git 훅 + 로컬 앱으로 쓰던 길은 끝났다)
② **관리 문서는 큐레이터만 바꾼다**(writer 는 기록만 · 늦은 반영은 「미반영」 으로 섹션과 같이 실린다) ③ **레포에는 지식만**(도구 층 ·
훅 · 스킬 사본 · INDEX · 서식 예시가 레포에서 나간다). 패키지는 없어지고 서식집(`forms/`)이 그 자리다.

### 9.1 순서

| 순서 | 하는 것 |
|---|---|
| 1 | **`upgrade.sh`** — 8장 그대로. `/opt/cdp/packages` 는 더 쓰지 않는다 |
| 2 | **`doctor`** — 「레포 … 도구 층」 warn 이 아직 v0.x 모양인 레포다(`bin/` · `.githooks` · `.claude` · `CLAUDE.md` · `MANUAL*.md` · `INDEX*.md` · `TEMPLATE-work.md`) |
| 3 | **레포마다 길을 고른다** — 제자리 이행(9.2) 또는 다시 세우기(9.3) |
| 4 | **큐레이터를 맡긴다** — 서버 › 사용자 › 「레포 × 큐레이터」(4장) |
| 5 | **작업 레포마다 설치 한 줄 `--update`** — 옛 스킬 일곱이 걷히고 writer kit 셋이 들어간다. 큐레이터는 자기 폴더에서 `--curator` |
| 6 | `/opt/cdp/packages` 를 확인 뒤 지운다 · 사람들에게 알린다(9.4) |

### 9.2 제자리 이행 — `ctx migrate`

관리 문서를 그대로 쓰는 레포. **서버를 멈추고** 돌린다 — 서버의 save 뮤텍스는 이 프로세스와 공유되지 않는다.

```bash
sudo systemctl stop cdp-serve
$CTX migrate /opt/cdp/repos/<레포> --dry                  # 무엇을 할지 — 전환 기록의 판정 수 · 서식 예시 · 도구 층
$CTX migrate /opt/cdp/repos/<레포> --by <내 아이디>        # [--keep-tools] 도구 층을 남긴다
sudo systemctl start cdp-serve
```

커밋 셋이 남는다 —

| 커밋 | 무엇 |
|---|---|
| **전환 기록** | 큐레이션 기록 하나 — 지금 섹션이 최신이던 좌표만 건드린 기록은 「반영됨」, 실을 섹션이 없던 기록 · 옛 기계 기록은 「기록으로 둠」. **옛 판에서 섹션이 뒤처져 있던 좌표의 기록만 대기열에 남는다** |
| 서식 예시 정리 | `example:` 좌표와 짝 섹션 |
| 도구 층 걷기 | `bin/` · `.githooks` · `.claude` · `MANUAL*` · `CLAUDE.md` · `TEMPLATE-work.md` · `INDEX*` 를 지우고 `core.hooksPath` 를 푼다 |

`start` 뒤 그 레포의 미러가 세 커밋을 origin 으로 민다(「다시 보내기」 가 필요하면 7.2).

### 9.3 다시 세우기 — 기록만 옮긴다

관리 문서가 엉망이라 고치는 것보다 빈 레포에서 큐레이션부터 다시 하는 쪽이 나은 레포.

1. **옛 레포를 비켜 둔다** — `sudo systemctl stop cdp-serve && sudo -u cdp mv /opt/cdp/repos/<레포> /opt/cdp/repos/<레포>_old && sudo systemctl start cdp-serve`.
   옛 레포는 지우지 않는다 — 읽기로 둔다.
2. **GitLab 도 비켜 둔다** — 옛 프로젝트를 `<레포>_old` 로 바꾸고 같은 이름의 **빈 프로젝트**를 새로 만든다. 새 레포는 이력이 달라 옛 프로젝트에는
   push 되지 않는다(강제 push 는 없다). 옛 폴더의 원격은 `sudo -u cdp -H git -C /opt/cdp/repos/<레포>_old remote set-url origin <바뀐 주소>`.
3. **서버 › 지식 레포 › [새 지식 레포]** — 이름 `<레포>` · 「기록만 옮겨 오기」 = `<레포>_old` · 볼 사람. 셸이면 `$CTX repo new /opt/cdp/repos/<레포> --records-from /opt/cdp/repos/<레포>_old`.
4. **「origin 연결」** — 새 빈 프로젝트의 주소.
5. **큐레이터를 맡긴다** — 옮긴 기록은 전부 대기열에 서 있다. 큐레이터가 묶음을 짓고 서식집에서 문서를 세우며 반영한다(큐레이터 설명서 11.1).
6. 작업 레포의 `--update` 는 이름이 같으므로 그대로 새 레포를 가리킨다.

### 9.4 사람들에게 알릴 것

| 누구 | 무엇 |
|---|---|
| 모두 | 왼쪽 메뉴 하나로 화면이 바뀌었다 · 강제 새로고침 한 번 · 설명서가 넷이다 |
| writer | **기록만 남긴다** — 섹션을 고치던 길(파생)은 없다. 바꿀 것은 기록에 쓰고 큐레이터가 반영한다. 작업 레포마다 `--update` |
| 큐레이터 | 큐레이터 폴더 설치(`--curator`) · 대기열 · 큐레이터 설명서 |
| PC 에 지식 레포를 clone 해 쓰던 사람(옛 로컬형) | 그 clone 은 읽기용이다 — 커밋 · push 하지 않는다. 서버에 닿지 못하는 사람은 개인 서버(부록 D) |

## 10. 장애 대응

| 증상 | 원인 · 볼 곳 |
|---|---|
| `install.sh` 가 `node 가 없다` · `20 이상이어야 한다` | 2.0 |
| `/healthz 가 10초 안에 답하지 않았다` · `status=203/EXEC` | `journalctl -u cdp-serve -n 50` · 유닛의 `ExecStart` 경로 ≠ 실제 node(node 를 옮겼으면 `install.sh` 다시) |
| `거부: --bind … 인증 없이 밖으로 열 수 없다` | 유닛에 `--auth` 가 빠졌다 |
| `repos: 0` · 레포가 안 보인다 | `<root>/<이름>/_vocab.md` 가 있는가 · git 레포인가 · 목록 갱신은 1분 |
| 읽기는 되는데 `save` 가 `E_GIT` · `mirror` 가 늘 `off` | 서버에 git 이 없다 · upstream 이 없다(5.2 「origin 연결」) |
| `밀림 · 인증 실패` 가 안 풀린다 | **PAT 만료가 가장 흔하다** — 2.2 를 다시 · 「다시 보내기」 |
| `갈림` · 진단 `origin` 줄 fail | 서버 밖에서 origin 에 썼고 그 뒤 서버가 커밋했다 — 7.2(셸 rebase 뒤 「다시 보내기」) |
| `save` 가 `E_GIT dirty` · 진단 `트리` 줄 fail | 서버 트리에 커밋 안 된 변경 — 「트리 되돌리기」 |
| `save` 가 `E_CHECK` 인데 사용자는 자기 잘못이 없다고 한다 | 막는 것은 **그 save 가 새로 만든 오류**뿐이다 — 레포에 원래 있던 오류는 경고로 간다. 오류 내용을 보고(`detail`) 기록 쪽이면 사용자에게, 문서 쪽이면 큐레이터에게 |
| 진단 「레포 … 도구 층」 | v0.x 레포다 — 9장 |
| 진단 `kit` fail · `forms` warn | 번들 옆 `kit/` · `forms/` 가 없다 — `upgrade.sh` 로 다시 올린다. 손으로 갈지 않는다 |
| 401 인데 토큰은 맞다 | 만료 · 비활성 · 폐기 — `serve user list` · `token list` |
| 로그인은 되는데 레포가 없다 | 그 사람의 `repos` 가 비었다 — 3.4 |
| 큐레이터인데 「큐레이션」 메뉴가 없다 | 역할이 viewer 다 · 그 레포를 볼 수 없다 · `curate` 체크가 없다 — 4.2 |
| 설치기가 「이 토큰은 … 큐레이터가 아닙니다」 | 같다 — 4.2 |
| 설치기 · `--update` 가 「그 등록(wr_…)은 X 의 것이다」 · HTTP 409 | 다른 레포의 등록 id 로 받았다 — X 의 레포 관리 › 연결된 작업 레포에서 한 줄을 다시 받는다 |
| 서버 › 현황 「주소와 다른 레포에 쓴 save N」 | 그 작업 레포의 `.mcp.json` 주소와 `.claude/cdp.json` 의 `repo` 가 갈렸다 — 그 작업 레포 폴더에서 원래 레포의 설치 한 줄을 다시 |
| 서버 › 현황 「이 PC 시계가 서버보다 N분 빠르다 · 늦다」 | 두 기계의 시계가 어긋났다 — 기록 id 의 날짜 · 토큰 만료가 갈릴 수 있다. 서버 `timedatectl`(NTP) · PC `w32tm /resync` |
| 화면만 안 뜬다 · 고친 것이 화면에 안 보인다 | `/opt/cdp/web/index.html` · 손으로 갈았으면 되돌리고 `upgrade.sh` 로 |
| 서버에서는 `curl` 이 되는데 밖에서 안 된다 | 방화벽에 7374 가 안 열렸다(2.1) |

로그 — `/opt/cdp/data/logs/serve.log`(요청 · 3 × 1MB 회전 · 문서 내용 · 토큰은 쓰지 않는다) · `auth.log`(이력) · `journalctl -u cdp-serve`(프로세스가 시작조차 못 할 때).

**사용자가 자주 묻는 것**

| 질문 | 답 |
|---|---|
| 토큰을 잃었다 | 3.4 — 재발급(폐기 + 발급 한 동작). 복구는 없다 |
| 다른 PC 에서도 쓰고 싶다 | 기기마다 토큰 하나 · 메모로 구분 |
| `E_FORBIDDEN` 이 난다 | `need: curate` 면 섹션을 쓰려 한 것 — 기록에 쓰게 한다(writer 는 기록만). 아니면 writer 가 아니다 — 맡길 사람인지 먼저 판단한다 |
| 섹션이 안 바뀐다 · 기록이 반영 안 된다 | 큐레이터가 판정해야 바뀐다 — 그 레포의 큐레이터 · 대기열의 나이를 본다 |
| 새 좌표 타입이 필요하다 | 사용자의 기록이 `vocab` 으로 만든다(새 타입 절). 그 타입을 받는 관리 문서는 큐레이터가 서식에서 세운다 |

## 11. 하지 않는 것

관리자가 "이거 넣으면 좋겠다" 고 생각하기 쉬운데 **일부러 안 하는 것들**이다.

| | 왜 |
|---|---|
| **알림** | 무시되기 시작하면 되돌릴 수 없고, 「알림이 안 왔으니 없는 것」 이라는 더 나쁜 오해가 자리 잡는다. 화면은 사람이 열었을 때 말한다 |
| **사용자가 화면에서 토큰을 요청** | 발급은 관리자가 한다. 「토큰 주세요」 버튼이 있으면 그 버튼이 가장 약한 곳이 된다 |
| **화면에서 갱신 · PAT · 재시작** | 자기 자신을 갈아 끼우는 일이라 실패했을 때 되돌리는 길이 셸뿐이다. 서버 설정은 판과 명령을 **보이기만** 한다 |
| **화면에서 문서 편집** | 쓰기는 `save` 하나다 — 화면이 하면 좌표 대조 · 검사 · 큐레이션 판정을 우회하는 길이 생긴다 |
| **서버가 LLM 을 부르기** | 판단과 글은 사람의 에이전트 세션이 한다 — 서버는 권한 · 검사 · 커밋만. CDN · 인터넷도 타지 않는다 |
| **자동 merge · 충돌 해결** | 섹션 두 갱신을 기계가 섞으면 그 결과가 정본 자리에 앉는다. 갈라지면 사람이 셸에서 rebase 한다 |
| **서버의 자동 pull · 주기 push** | 사람이 모르는 사이 트리가 바뀌면 안 된다. ff-only 맞추기는 사람이 누른다 · push 는 `save` 뒤와 「다시 보내기」 뿐 |
| **섹션 점유 · 잠금 화면** | 낙관 잠금(`applied`)이 맞는 도구다. 같은 섹션을 동시에 건드릴 걱정은 일감 분배의 문제다 |
| **큐레이터 없이 관리 문서 자동 생성** | 관리 문서는 큐레이터의 판단으로만 바뀐다 — 기계는 기준선 블록만 갈아 끼운다 |
| **RAG · 임베딩** | 좌표가 답이다. 근사 검색은 「없는 것」 을 「비슷한 것」 으로 채운다 |

## 부록 D. 개인 서버

**서버가 없는 팀 · 혼자 쓰는 사람**의 길이다. 같은 서버를 자기 PC 에 띄운다 — 같은 코드 · 같은 `save` · 같은 화면 · 같은 MCP.
PC 의 지식 레포를 git 훅과 로컬 앱으로 쓰던 옛 길(로컬형)을 대신한다.

```bash
node <산출물>/bin/ctx.mjs serve --personal <지식 레포 폴더> --web <산출물>/web     # [--port 7400] [--mirror]
```

| | |
|---|---|
| 준비물 | Node 20 · git · 서버 산출물을 푼 폴더(`bin/` · `web/` · `forms/` · `kit/` · `manual/` 이 형제로) |
| 주소 | `127.0.0.1` 만 — 이 PC 밖에서는 닿지 않는다. 포트 기본 7400 |
| 레포 | 하나 — `_vocab.md` 가 있는 git 폴더. 폴더 이름이 레포 이름이다(영문 · 숫자 · `._-`). 새로 세우려면 `node <산출물>/bin/ctx.mjs repo new <폴더>`(빈 틀) |
| 명부 | **스스로 만든다** — 이 PC 의 사용자 이름 하나 · admin(그 레포의 큐레이터) · 토큰 무기한 |
| 데이터 | `~/.cdp/personal/<레포>/` — `auth.json` · `personal.token`(원문 · 600 — 이 PC 의 주인만 쓰므로 둔다) · 로그 · 세션 비밀 |

시작하면 세 줄을 찍는다.

```
개인 서버 — alpha (…/alpha)
  화면   http://127.0.0.1:7400/login?auto=<토큰>       ← 이 주소로 열면 바로 로그인된다
  MCP    http://127.0.0.1:7400/mcp/alpha   (토큰은 ~/.cdp/personal/alpha/personal.token)
  작업 레포에 깔기 — … install.mjs --curator --repo alpha <폴더>
```

**작업 레포 · 큐레이터 폴더에 붙이기** — 혼자이므로 등록 없이 `--curator` 한 줄로 그 폴더에 스킬 다섯 · 블록을 받는다(토큰을 물으면
`personal.token` 의 내용). 기록(`cdp-save`)과 반영(`cdp-curate`)을 한 사람이 같이 한다 — 순서는 팀과 같다: 기록을 남기고, 대기열을
보고, 판정한다.

| 하는 것 | 하지 않는 것 |
|---|---|
| 화면 · MCP · `save` · 큐레이션 · 서식집 · 기준선 — 팀 서버와 같다 | 다른 사람이 붙는 것 — 루프백만이다. 팀이 쓰면 서버 하나를 세운다(2장) |
| 원격이 있으면 `--mirror` 로 save 마다 origin 에 민다 | 서비스로 늘 켜 두기 — 창을 닫으면 끝난다. 다시 띄우면 같은 명부 · 토큰이다 |

옛 로컬형 레포(도구 층 · 훅이 든 clone)를 개인 서버로 열려면 먼저 `node <산출물>/bin/ctx.mjs migrate <폴더> --by <이름>` 으로 v1.0 모양으로
옮긴다(9.2). 그 레포를 팀 서버도 쓰고 있으면 개인 서버로 열지 말고 팀 서버를 본다 — 쓰는 길은 하나여야 한다.
