> 파일 리다이렉션으로 읽어 `No such file or directory` 가 난다.

## 1. 관리자가 맡는 것

### 1.1 지식 레포 — 두 층 · 세 파일 · 한 검사

```
<지식 레포>/
  work/            ① 작업 기록 — 사건.  불변.  사용자가 쓴다
  docs/            ② 관리 문서 — 상태.  가변.  사용자가 갱신한다
  _vocab.md        ③ 어휘     — 좌표의 이름표.  사용자가 추가, 관리자가 정리
  _managed.md      ④ 등록부   — 좌표 패턴 → 문서 · 섹션.  관리자만
  .githooks/       ⑤ pre-commit — 유일한 결정론적 보증 (로컬형)
  bin/ctx          ⑥ 도구 (번들).  관리자가 갱신
  .claude/skills/  ⑦ 절차 — 에이전트가 읽는 지시문
  tools/cdp.exe    로컬형의 실행기 (git 에 안 들어간다)
  CLAUDE.md · MANUAL*.md · INDEX*.md · .gitattributes · .gitignore
```

**관리자가 손대는 것은 ③④⑤⑥뿐이다.** ①②는 사용자가 쓴다.

| | 누가 | 언제 |
|---|---|---|
| ③ `_vocab.md` | 사용자가 추가, **관리자가 정리** | 새 좌표가 나올 때 · 주기적으로 |
| ④ `_managed.md` | **관리자만** | 새 문서 종류를 정본으로 삼을 때 · 안 쓰는 문서를 뺄 때 |
| ⑤ 훅 | 배포본에 들어 있다. **각자 한 번 설정** (`core.hooksPath`) | clone 직후 |
| ⑥ `bin/ctx` | **관리자가 갱신** | 새 배포본이 나올 때 |

> ③④를 사용자에게 완전히 열면 어휘가 갈라지고, 완전히 닫으면 커밋이 관리자를 기다린다.
> **어휘 추가는 열고, 등록부는 닫는다** — 이것이 그 타협이다.

### 1.2 두 배치 — 어느 쪽으로 세우나

| | **서버형** (모드 B · 권장) | **로컬형** (모드 A · 폐쇄망 PC) |
|---|---|---|
| 지식 레포 | 서버 `/opt/cdp/repos/<이름>` 하나. 서버가 유일한 작성자 | 사람마다 clone. 원격이 정본 |
| 에이전트 연결 | HTTP + 토큰. `.mcp.json` 을 **커밋**한다 | 각 PC 의 `bin/ctx mcp`(stdio). `.mcp.json` 은 커밋 안 함 |
| 검사 · 커밋 | 서버가 `save` 때 검사 · 커밋 · origin 미러 | 각 PC 의 git 훅이 검사. 스킬이 커밋 · push |
| 사람 붙이기 | 명부(`auth.json`) + 토큰 · 꾸러미 zip | clone + `ctx setup` 각자 한 번 |
| 화면 | 브라우저 `http://<서버>:7374` | `tools\cdp.exe` |
| 필요한 것 | 리눅스 서버(Node 20 · git · systemd) · GitLab 자격(PAT) | PC 마다 git. Node 는 없어도 된다(exe) |
| 어디에 맞나 | 팀이 한 서버에 닿는다 · 레포를 여럿 둔다 · 훅 설정을 사람마다 기대하기 어렵다 | 서버가 없다 · 망이 막힌 PC |

둘을 섞어 쓸 수도 있다 — 지식 레포 하나를 서버가 미러하고, 어떤 사람은 clone 해서 로컬형으로 본다.
**쓰기는 한 길로** 모으는 것이 안전하다(서버형이면 `save`, 로컬형이면 훅).

### 1.3 이 문서를 읽는 순서

```
2장 받는다 → 3장(서버형) 또는 4장(로컬형) → 5장 작업 레포 → 6장 사람 → 7장 운영 · 9장 갱신
```

## 2. 받는 것 — 배포본

개발자가 릴리스마다 둘을 낸다. GitHub Release 또는 개발 PC 에서 받는다.

| 산출물 | 누가 쓰나 | 안에 |
|---|---|---|
| **`cdp-v<버전>-win.zip`** | 로컬형 · 폐쇄망 PC | `cdp.exe` **하나**(루트 · 앱 + ctx · 68MB) · `knowledge-repo-<패키지>/` 패키지마다 하나(완성된 지식 레포 — exe 없음 · 빈 `tools/`) · `설치.md` · `README.md`(패키지 표 — 프로젝트에 맞는 **하나만** 고른다) |
| **`cdp-server-v<버전>.tar.gz`** | 서버형 | `bin/ctx.mjs` · `web/` · `packages/<패키지>/` · `deploy/`(install.sh · upgrade.sh · 유닛 · Dockerfile · 설치절차.md) · `README.md` |
| `SHA256SUMS` | 둘 다 | 반입 뒤 대조 |

```bash
sha256sum -c SHA256SUMS                        # Linux
certutil -hashfile cdp-v0.9.0-win.zip SHA256   # Windows — SHA256SUMS 의 값과 눈으로 대조
```

**판을 확인한다.** 풀어서 `node bin/ctx.mjs version`(서버) 또는 `knowledge-repo-*\bin\ctx version`(PC).
날짜 한 줄과 `mcp: stdio · http` 가 나와야 MCP 가 든 번들이다.

**폐쇄망 반입.** 인터넷을 타는 것이 하나도 없다 — 화면의 폰트까지 파일 안에 있다. zip 또는
tar.gz 한 개(+ SHA256SUMS)를 옮기면 된다. 지식 레포가 이미 있다면 `git bundle create knowledge.bundle --all` 로 같이 옮긴다.

## 3. 서버형 설치

사람이 셸에서 치는 것은 둘이다 — `install.sh` 와 git 자격(3.3). 첫 관리자는 브라우저 `/setup` **마법사**에서
만들고, 레포는 **콘솔**에서 세우거나 clone 한다(셸로도 된다 — `serve init` · `repo new`). 나머지는 `doctor`
가 확인한다. 3.3(git 자격)만 스크립트도 화면도 대신할 수 없다.

### 3.0 준비물

- [ ] 리눅스 서버에 SSH · `sudo`. 배포판은 Debian/Ubuntu 또는 RHEL 계열
- [ ] **Node 20 이상** · **git**. `install.sh` 가 첫 줄에서 확인하고 없으면 멈춘다
- [ ] 서버가 사내 GitLab(예 `10.10.20.250:2900`)에 닿는다 — 미러용
- [ ] GitLab 에서 그 프로젝트에 **push 할 수 있는 계정** (Developer 이상)
- [ ] 명부에 올릴 **사람 이름과 권한** — 누가 어느 레포를 보고, **누가 `writer`**(기록을 만들 사람) · 누가 `admin` 인가

```bash
node --version && command -v node && git --version
curl -s -o /dev/null -w '%{http_code}\n' http://10.10.20.250:2900/     # 302 면 닿는다
```

Node 가 없으면 — nodesource(`deb.nodesource.com/setup_20.x` · `rpm.nodesource.com`) 또는 공식
tarball 을 `/usr/local/lib/nodejs` 에 풀고 `/usr/local/bin/node` 로 링크. **`nvm` 은 쓰지 않는다** —
서비스 계정에서 보이지 않는다. `install.sh` 가 `command -v node` 로 찾은 경로를 유닛에 박으므로
어디에 깔았든 그 경로가 맞는다.

> **systemd 가 무엇인가.** 리눅스가 백그라운드 서비스를 켜고 관리하는 기본 장치다. CDP 서버
> (`ctx serve` 한 프로세스)를 `cdp-serve` 라는 서비스로 등록해 부팅 때 켜고 죽으면 되살린다.
> 없으면 `install.sh` 가 유닛 파일만 써 두고 직접 띄우는 명령을 찍어 준다. Docker 는 이 층을
> 대신하는 선택지다(3.8).

### 3.1 산출물을 올린다

```bash
scp cdp-server-v0.9.0.tar.gz <계정>@<서버>:/tmp/
ssh <계정>@<서버>
cd /tmp && tar -xzf cdp-server-v0.9.0.tar.gz && cd cdp-server-v0.9.0
node bin/ctx.mjs version          # 2026-09-22 … · mcp: stdio · http
ls deploy/ packages/              # install.sh upgrade.sh cdp-serve.service … / dpms
```

### 3.2 `install.sh`

```bash
sudo bash deploy/install.sh --bind <이 서버 IP>      # [--port 7374] [--prefix /opt/cdp] [--user cdp] [--no-systemd] [--dry]
```

하는 일 — Node · git 확인 → 계정 `cdp` → `/opt/cdp/{bin,repos,data,web,packages,deploy}` →
파일 배치 → **node 경로 · bind · port 를 채운 유닛** `/etc/systemd/system/cdp-serve.service` →
`systemctl enable --now` → `/healthz` 확인 → 방화벽 명령 **안내**. **두 번 돌려도 같다** — 있는
것은 건너뛰고 그 사실을 찍는다. `--dry` 로 무엇을 할지 먼저 볼 수 있다.

**확인** — 끝에 `[install] healthz {"ok":true,…,"repos":0,…}`. `repos:0` 이 맞다 — 레포는 3.4 에서 둔다.

**포트를 연다.** `install.sh` 는 안내만 한다.

```bash
sudo firewall-cmd --permanent --add-port=7374/tcp && sudo firewall-cmd --reload     # 또는
sudo iptables -I INPUT -p tcp --dport 7374 -j ACCEPT && sudo service iptables save
curl -s -m 5 http://<서버IP>:7374/healthz      # 다른 장비에서 — 자기 주소는 방화벽을 안 탄다
```

`--bind` 는 필수다 — 프록시가 없는 배치에서 바인드가 유일한 경계다. `0.0.0.0` 이 아니라 그 서버의 IP 하나.

### 3.3 git 자격 — PAT · 사람의 절차

**서버가 origin 으로 push 할 자격이다.** 커밋의 `author` 는 CDP 토큰의 사용자로 서버가 채우므로
누가 정했는지는 사람별로 남는다. GitLab 의 SSH 가 서버에서 닿지 않으면 HTTP + PAT 를 쓴다.

1. GitLab `Profile > Personal Access Tokens` — Name `cdp-server`, Expires **1년 뒤**(비워 두지 않는다),
   Scopes: `write_repository`(GitLab 12.9+) 또는 `api`(그 미만 — 계정 전체를 여니 `doctor` 가 warn 을 계속 낸다)
2. 서버에 넣는다 — 토큰이 아무 데도 남지 않게
   ```bash
   read -rsp 'PAT: ' PAT; echo
   sudo -u cdp -H git config --global credential.helper 'store --file=/opt/cdp/.git-credentials'
   printf 'http://<계정>:%s@10.10.20.250:2900\n' "$PAT" | sudo -u cdp -H sh -c 'umask 077; cat > /opt/cdp/.git-credentials'
   unset PAT
   sudo -u cdp -H git config --global user.name  "cdp-server"
   sudo -u cdp -H git config --global user.email "cdp-server@<회사도메인>"
   ```
3. **확인** — 해시 한 줄이 나와야 한다. 쓰기는 3.6 의 `doctor` 가 `push --dry-run` 으로 본다.
   ```bash
   sudo -u cdp -H git ls-remote http://10.10.20.250:2900/soln1/cdp.git HEAD     # <origin url> 자리에 실제 주소
   ```
   `<origin url>` 을 그대로 치면 bash 가 `<origin` 을 파일 리다이렉션으로 읽어 `origin: No such file or directory` 가 난다 —
   꺾쇠까지 통째로 실제 값으로 바꾼다.

| 결과 | 뜻 |
|---|---|
| `HTTP Basic: Access denied` | 사용자명이 다르거나 토큰이 틀렸다 |
| `could not be found` | 경로 오타이거나 권한이 없다 |
| 패스워드를 묻는다 | `-H` 를 빼먹었거나 `.git-credentials` 경로가 다르다 |

### 3.4 지식 레포 — 세 길

**폴더명이 곧 레포 이름이다.** 등록 = `/opt/cdp/repos/` 아래에 폴더를 두는 것.

```bash
CTX="sudo -u cdp node /opt/cdp/bin/ctx.mjs"
```

| 길 | 언제 | 명령 |
|---|---|---|
| **(가) clone** | 지식 레포가 이미 있다 | `sudo -u cdp -H git clone <origin url> /opt/cdp/repos/<이름>` |
| **(나) `ctx repo new`** | 패키지에서 새로 세운다 | 아래 |
| **(다) 콘솔** | 같은 것을 브라우저에서 — **권장** | 콘솔 > 지식 레포 > **[+ 새 레포]** — 패키지에서 세우기 · origin 에서 clone · 볼 사람 지정까지 한 모달(관리자). 레포 화면의 관리 > 지식 레포에서도 세운다(`writer` 이상). 첫 관리자(3.5) 뒤에 |

```bash
$CTX repo new /opt/cdp/repos/<이름> --package dpms --packages /opt/cdp/packages \
     [--origin <빈 GitLab 프로젝트 url> --push] [--dry]
```

패키지 폴더 복사 → `work/.gitkeep` → `git init` → `core.hooksPath` → **첫 커밋(훅이 `ctx check` 를
돈다 — 막히면 폴더를 지우고 실패)** → `remote add` → `push -u`. GitLab 프로젝트는 **웹에서 먼저
만든다** — 서버가 만들 수는 없다. `--push` 없이 세웠으면 나중에 `git remote add origin … && git push -u origin HEAD`.

첫 커밋 뒤 안내가 찍힌다 — **첫날 할 일**이다(7.1). 레포 이름은 `^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`.
패키지가 여럿이다 — `$CTX package list --packages /opt/cdp/packages` 로 이름 · 판 · 문서 수 · 설명을
보고 고른다. `--package` 를 빼거나 틀리면 있는 패키지 이름을 같이 찍어 준다.

> **서버는 새 폴더를 그 이름으로 가는 첫 요청에서 바로 알아본다** — 꾸러미 · 작업 레포 등록 ·
> MCP · 화면 어느 것이든. 전체 목록(`/repos`)만 1분 주기이고, 비어 있으면 바로 다시 훑는다.
> 재시작은 필요 없다. `doctor` 의 「서버 … 레포 N」 이 폴더 수보다 작으면 아직 그 요청이 없었다는 뜻이다.

### 3.5 첫 관리자 — `/setup` 마법사 또는 `init`

6장이 전부를 다룬다. 설치 순서상 여기서 **첫 관리자 하나**를 만든다 — 명부가 없을 때 한 번. 길이 둘이다.

**브라우저(권장)** — `install.sh` 가 끝에 찍은 주소와 **부트스트랩 코드**를 쓴다.
`http://<서버IP>:7374/setup` → 코드 → 내 아이디 · 라벨 → **토큰 원문이 한 번** 보인다(`CDP_TOKEN` 에 넣는다).
그 브라우저는 이미 로그인된 상태이고 [콘솔로] 가 열린다. 코드는 `/opt/cdp/data/bootstrap.code` 에 있고
쓰면 지워진다 — 잃었으면 `journalctl -u cdp-serve | grep 코드`.

**셸** — 브라우저로 서버에 닿지 못할 때.

```bash
A=/opt/cdp/auth.json; D=/opt/cdp/data
$CTX serve init --auth $A --data $D --name <내 아이디> --label "<이름 · 역할>"
```

첫 사용자는 **`admin`** 이고 레포 전체(`*`)를 본다. stdout 한 줄이 **토큰 원문** — 이때 한 번만 나온다.
명부가 이미 있으면 둘 다 거절한다(덮지 않는다). 둘째 사람부터는 콘솔 > 사용자(6장).

### 3.6 확인 — `doctor` 가 fail 0

```bash
$CTX serve doctor --root /opt/cdp/repos --auth $A --data $D --web /opt/cdp/web \
     --packages /opt/cdp/packages --bind <서버IP> --port 7374 [--json]
```

```
 ok    node       v20.x
 ok    git        git version 2.x
 ok    auth.json  /opt/cdp/auth.json
 ok    명부       사용자 1 · write 1 · 토큰 1
 ok    --data     /opt/cdp/data
 ok    --web      /opt/cdp/web
 ok    packages   /opt/cdp/packages (--packages) · 1개
 ok    레포 gdi   head abc1234 · origin/main · push 자격 있음        ← 3.3 의 쓰기 확인이 이 줄이다
 warn  git 자격   평문 PAT 가 있다 — 스코프가 api 면 계정 전체를 연다 …
 ok    서버       <서버IP>:7374 응답 · built … · 레포 1
doctor: fail 0 · warn 2 · ok 8
```

`fail` 이 하나라도 있으면 exit 1 — 그것을 고치기 전에는 다음으로 가지 않는다. `warn` 은 알아 두는 것.
`레포 … upstream 없음` 은 origin 을 아직 안 붙였다는 뜻이고, `push 자격 없음` 은 3.3 을 다시 본다.

### 3.7 화면 확인

브라우저로 `http://<서버IP>:7374/` — **소개 페이지**가 뜬다(인증 없음 · 레포 이름 · 사람 이름은 싣지 않는다).
[설명서] 에 이 문서 세 권과 설치 절차가 있다 — 서버가 든 판 그대로다.

[들어가기] → 로그인 입력이 **한 칸**(토큰) → `/r/<레포>/` → 오른쪽 위에 설명서 · **콘솔**(관리자만) · 내 이름 ·
역할 칩. 상단 레포 이름표는 언제나 메뉴다 — 볼 수 있는 레포와 쓰기/읽기가 보인다. 관리 > 메뉴는
**현황 · 지식 레포 · 작업 레포 · 진단** 넷 + 관리자에게 「콘솔로 →」 — 동기화 메뉴는 없다(서버가 커밋하고 미러한다).

`/console` — 관리자의 자리. **현황 · 사용자 · 토큰 · 지식 레포 · 작업 레포 · 서버 · 감사** 일곱. 6장 · 7장의
관리자 일이 여기서 된다. 화면이 안 떠도 **MCP 와 읽기 API 는 돈다** — `/opt/cdp/web/index.html` 을 본다.
소개 · 설명서까지 로그인 뒤에만 보이게 하려면 유닛의 `ctx serve` 에 `--private-pages`.

### 3.8 Docker — 선택지

같은 `ctx serve` 를 systemd 대신 컨테이너로 띄운다. 이미지는 리눅스(`node:20-slim` + git).
호스트에 Node · git 이 없어도 되고, 켜고 되살리는 것은 Docker 가 맡는다. systemd 가 있는 서버라면 3.2 가 더 단순하다.

```bash
cd cdp-server-v0.9.0
docker build -f deploy/Dockerfile -t cdp-server:0.9.0 .
touch auth.json                                    # 명부 파일 — 호스트에 둔다. 없으면 Docker 가 폴더를 만든다
docker run -d --name cdp -p 7374:7374 --restart unless-stopped \
  -v cdp-repos:/opt/cdp/repos -v cdp-data:/opt/cdp/data -v "$PWD/auth.json:/opt/cdp/auth.json" cdp-server:0.9.0
docker exec cdp node bin/ctx.mjs serve init --auth /opt/cdp/auth.json --data /opt/cdp/data --name <아이디>     # 또는 브라우저 /setup
curl -s http://127.0.0.1:7374/healthz
```

또는 `docker compose -f deploy/docker-compose.yml up -d --build`. 컨테이너 안은 `--bind 0.0.0.0` 이
맞다 — 경계는 호스트의 `-p` 매핑이다. 명부 · 레포 · 자격은 볼륨과 호스트 파일에 남아 컨테이너를
지워도 살아 있다. 나머지 절차(3.3 · 3.4 · 6장)는 명령 앞에 `docker exec cdp` 가 붙는 것만 다르다.

**Windows 서버에서는** Docker Desktop(Windows 10/11 용 · Windows Server 는 지원 대상이 아니다)
또는 WSL2 Ubuntu 에 3.2 로 설치한다. `ctx serve` 자체는 Node 라 Windows 에서 직접 돌지만 서비스
등록 스크립트는 없다.

### 3.9 되돌리기

```bash
sudo systemctl disable --now cdp-serve
sudo rm /etc/systemd/system/cdp-serve.service && sudo systemctl daemon-reload
sudo rm -rf /opt/cdp && sudo userdel cdp          # 데이터를 지울 때만
```

GitLab 의 PAT 도 폐기한다. **지식 레포는 origin 에 그대로 있다** — 미러로 보낸 커밋이 백업이다.

## 4. 로컬형 설치

설치는 네 자리에서 벌어진다 — ① 개발 PC(배포본) ② 반입 ③ 지식 레포(관리자 · 프로젝트당 1회)
④ 작업 레포(관리자 · 레포당 1회) ⑤ 팀원 PC(사람마다). 배포본 루트의 `설치.md` 가 같은 순서다.

### 4.1 ③ 지식 레포 세우기 — 폴더 하나를 복사한다

```
xcopy /E /I <배포본>\knowledge-repo-dpms C:\cdp
copy <배포본>\cdp.exe C:\cdp\tools\              ← 실행기. 패키지가 여럿이어도 exe 는 배포본 루트에 하나다
cd /d C:\cdp
git init && git config core.hooksPath .githooks
bin\ctx check                                     → 이상 없음 (작업 기록 0건)
git add -A && git commit -m "지식 레포 세움 — dpms"
git remote add origin <url> && git push -u origin main
```

배포본에 `knowledge-repo-*` 폴더가 여럿이면 프로젝트에 맞는 **하나만** 복사한다 — 프로젝트당
지식 레포는 하나다. 어느 패키지가 무엇인지는 배포본 루트 `README.md` 의 패키지 표(제목 · 판 ·
문서 수 · 설명)에 있다. 패키지 이름은 개발자가 그 패키지에 붙인 것이고(`dpms` 처럼 문서 세트의
이름이거나, 프로젝트별로 고친 패키지면 그 프로젝트의 이름), **지식 레포 이름과는 다르다** —
레포 이름은 복사할 폴더(`C:\cdp`)와 원격이 정한다.

**복사한 순간 지식 레포다** — `ctx` 는 `_vocab.md` 로 알아본다. 폴더 안에 이미 다 들어 있다:

| 있는 것 | 빠지면 |
|---|---|
| `_vocab.md` · `_managed.md` · `docs/` | 좌표가 안 잡힌다 · 파생 검사가 아무것도 안 한다 · 등록부가 가리키는 섹션이 없다 |
| `.gitattributes` (`eol=lf`) | **훅이 조용히 죽는다** — CRLF 로 체크아웃되면 셔뱅 뒤에 `\r` 이 붙어 커밋은 통과하고 검사만 사라진다 |
| `bin/` · `.githooks/` · `.claude/skills` · `.claude/work-repo/CLAUDE.md` | 검사도 절차도 없다 · `ctx setup` 이 서식을 못 찾는다 |
| `tools/cdp.exe` — **배포본 루트의 `cdp.exe` 를 복사해 넣는다** | 없으면 Node 없는 PC 에서 훅이 검사를 건너뛰고 더블클릭할 것이 없다. `.gitignore` 로 git 에는 안 들어간다 — 반입 때 **파일이 둘**이다 |

첫날 할 일(7.1)을 한 뒤 push 한다.

### 4.2 ⑤ 팀원 PC — 사람마다

```
git clone <지식레포>  C:\cdp
cd C:\cdp && git config core.hooksPath .githooks      ← 훅은 clone 을 따라오지 않는다
copy <배포본>\cdp.exe C:\cdp\tools\
git clone <코드레포>  C:\gdi
C:\cdp\tools\cdp.exe ctx setup C:\gdi                  ← 5장.  .claude/cdp.json 은 커밋되지 않아 각자 한 번
```

### 4.3 ⑥ 확인 — 세 곳이 같아야 한다

```
C:\cdp\tools\cdp.exe ctx version
C:\cdp\bin\ctx version
<배포본>\cdp.exe ctx version
cd C:\cdp && bin\ctx check                    → 이상 없음
```

**훅이 실제로 도는지 한 번 본다.** 미등재 좌표를 하나 넣은 기록을 만들어 커밋을 시도하고
**막히는 것을 눈으로 확인한다.** 막히지 않으면 `core.hooksPath` 나 `.gitattributes` 를 다시 본다.
이것이 점검표의 목적이다.

### 4.4 화면

`C:\cdp\tools\cdp.exe` 를 더블클릭하면 그 레포를 열고 브라우저가 뜬다(loopback `127.0.0.1:7373`,
다른 주소로 열면 상시 경고). 트레이 아이콘 — 열기 · 레포 폴더 · 탭 닫아도 계속 실행 · 종료.
`⚙ 설정` 에서 지식 레포 경로 · 작업 레포 에이전트 설치 · 원격을 본다. **git 로그인은 앱이 하지
않는다** — `git config --global credential.helper manager` 한 번, 그 뒤로는 받기 · 보내기가 그대로 된다.

## 5. 작업 레포에 에이전트 세팅 넣기

**코드가 있는 레포에서 Claude Code 를 열면 지식 레포의 스킬이 보이지 않는다.** 하네스는 프로젝트
루트의 `.claude/skills/` 만 읽는다. 그래서 작업 레포마다 한 번 넣는다.

### 5.1 무엇이 들어가나

| 파일 | 서버형 | 로컬형 |
|---|---|---|
| `.claude/skills/cdp-*` | 스킬 7종 · **커밋** | 같다 · **커밋** |
| `CLAUDE.md` | `<!-- cdp:begin -->` … `<!-- cdp:end -->` **블록만** 갈아 끼운다. 첫 줄에 `<!-- cdp:kit <해시> -->` · **커밋** | 같다 · **커밋** |
| `.claude/cdp.json` | `{ "server": …, "repo": … }` · **커밋** (PC 와 무관) | `{ "knowledgeRepo": "<경로>" }` · **커밋 안 함** (사람마다 다르다) |
| `.mcp.json` | `mcpServers.cdp` = `{ type: http, url: <서버>/mcp/<레포>, headers: { Authorization: Bearer ${CDP_TOKEN} } }` · **커밋** | `{ type: stdio, command: <지식레포>/bin/ctx, args: [mcp] }` · **커밋 안 함** |

남의 것을 지우지 않는다 — `cdp-` 가 아닌 스킬은 그대로, `CLAUDE.md` 의 나머지는 그대로, `.mcp.json`
의 다른 서버는 그대로. **git 레포일 때만** 쓴다.

### 5.2 서버형 — 등록 · 꾸러미 · 설치

1. **등록한다** — 관리 화면 > 작업 레포 > **[+ 등록]**. 이름 · 담당자(명부에서) · 메모. 등록은
   관문이 아니라 **장부**다 — 어느 작업 레포가 어느 판의 꾸러미를 들고 있나를 나중에 알기 위한 것.
   등록 · 삭제는 `writer` 이상, 조회는 그 레포를 볼 수 있으면 된다. 서버 전체의 대장은 **콘솔 > 작업 레포**에서
   한눈에 본다 — 등록은 여기(그 레포의 관리 화면)에서 한다. 꾸러미가 레포마다 다르기 때문이다.
2. **꾸러미를 받는다** — 그 행의 `[설치 방법]` → `cdp-kit-<레포>.zip`. 안에 `설치.md` · `install.mjs`
   · `kit/`. **토큰은 들어 있지 않다.**
3. **작업 레포에 넣는다** — 담당자가 (또는 관리자가) 아무 데나 풀고
   ```
   node install.mjs <작업 레포 경로>          무엇이 바뀔지 보여 주고 묻는다.  --dry · --yes
   ```
   `bin/ctx` 가 있는 사람은 대신 `CDP_TOKEN` 을 두고 `ctx setup --server http://<서버>:7374 --repo <레포> --workrepo <id> <작업레포>`.
   같은 함수다.
4. **커밋한다** — `git add .mcp.json .claude CLAUDE.md`. **팀원은 pull 과 `CDP_TOKEN` 만으로 끝난다.**
5. **확인** — Claude Code `/mcp` 에 `cdp` **connected** · 도구 **13**. 관리 화면의 그 행이 `최신` —
   설치 보고는 `install.mjs` 를 돌린 셸에 `CDP_TOKEN` 이 있을 때 간다(없어도 설치는 된다). 그래서
   사용자 설명서 2.1 은 **토큰을 먼저** 두게 한다. `미설치` 로 남았으면 토큰을 두고
   `node install.mjs <작업 레포>` 를 한 번 더 — 바뀐 것이 없어도 보고는 보낸다.

### 5.3 로컬형 — `ctx setup`

**`_vocab.md` 가 있는 지식 레포를 먼저 세운 뒤** 한다.

```
C:\cdp\tools\cdp.exe ctx setup C:\gdi [--dry]      또는  앱 ⚙ 설정 → 작업 레포 → [에이전트 설치]
```

```
ctx setup: C:\gdi
  .claude\skills\   cdp-work · cdp-load · cdp-save · cdp-managed · cdp-import · cdp-edit · cdp-push
  CLAUDE.md         블록
  .claude\cdp.json  { knowledgeRepo }      커밋하지 않는다
  .mcp.json         stdio                 커밋하지 않는다
```

스킬과 `CLAUDE.md` 블록은 커밋해 둔다 — 팀원은 clone 으로 받고 **`ctx setup` 만 각자 한 번**
돌린다(경로 파일 둘을 자기 것으로).

| 옵션 | |
|---|---|
| `--also <다른 지식레포>` | `.mcp.json` 한 항목에 레포 여럿(`--repo A --repo B`). 항목을 늘리지 않는다 |
| `--desktop` | Claude Desktop 의 `claude_desktop_config.json` 에 `mcpServers["cdp-<폴더명>"]` 병합. 다른 키는 보존 |
| `--dry` | 쓰지 않고 계획만 |

### 5.4 `.gitignore` 를 본다

많은 프로젝트가 `.claude/*` 를 통째로 막아 둔다. 그대로 두면 스킬이 **설치한 사람 PC 에만** 남고
팀은 받지 못한다 — 그리고 설치한 사람은 되니까 됐다고 생각한다. `ctx setup` 이 이 경우를 경고하지만
고치는 것은 사람이 한다.

```
.claude/*
!.claude/skills/        ← 이 줄
.claude/cdp.json        ← 로컬형만.  서버형은 커밋한다
.mcp.json               ← 로컬형만.  서버형은 커밋한다
```

### 5.5 여러 지식 레포 · 여러 작업 레포

작업 레포는 여럿이어도 된다 — 각각에 넣는다. 지식 레포가 둘이면 서버형은 `.mcp.json` 항목 하나가
서버를 가리키므로 `repos` 도구로 고른다(`match` 는 든 레포 전부를 대조한다). 로컬형은 `--also`.
**레포는 고르는 것이지 합치는 것이 아니다** — 한 답에 두 레포를 섞지 않는다.

## 6. 사람 관리 — 명부와 토큰

서버형에만 있다. 로컬형은 git 원격의 권한이 곧 권한이다. **콘솔 `/console` 에서 한다** — 관리자(`admin`)만
들어간다. 셸에서도 같은 것을 할 수 있다(부록 B) — 두 길이 같은 명부와 같은 `auth.log` 를 쓴다.

### 6.1 모델 — 권한은 사람에게, 토큰은 신원만

```
auth.json (v1.2)
  users[]    name · label · repos(볼 수 있는 레포) · role(viewer · writer · admin) · active
  tokens[]   sha256 · id · user · issued · expires · note · status(active · revoked)     ← 원문은 없다
```

| 역할 | 무엇을 할 수 있나 |
|---|---|
| `viewer` | 읽는다 — 화면 · 검색 · MCP 읽기 도구 |
| `writer` | + `save` 로 기록을 만든다 · 지식 레포를 세운다 · 작업 레포를 등록한다 |
| `admin` | + **콘솔** — 사람 · 토큰 · 레포 전부 · 서버. 레포는 전체(`*`) |

- **권한은 사람(`users[]`)에 붙는다.** 토큰은 "이 사람이다" 만 증명한다. 사람의 역할 · 레포를 바꾸면 그 사람의 토큰 전부에 즉시 먹는다
- **토큰 원문은 저장되지 않는다.** SHA-256 만 남는다. `auth.json` 이 새도 쓸 수 있는 값이 없다
- **발급은 관리자가 한다** — 콘솔 > 토큰, 또는 서버 셸. 사용자가 "토큰 주세요" 를 누를 자리는 없다 — 의도다
- **`writer` 는 기본이 아니다.** 정리를 맡은 사람에게만. `admin` 은 둘 이상 두되 아무에게나 주지 않는다 — 마지막 관리자는 내릴 수 없다
- 명부가 바뀌면 **다음 요청부터** 먹는다. 서버 재시작이 필요 없다 — 열려 있던 화면도

### 6.2 사람을 추가한다

콘솔 > **사용자** > [+ 사용자] — 이름(아이디) · 라벨 · 역할 · 볼 수 있는 레포. 저장하면 그 행의 [발급] 으로
이어진다(6.3). 명부를 바꾸는 첫 동작에서 **관리자 확인**(내 토큰을 한 번 더 · 15분)을 묻는다 — 세션이 탈취돼도
15분 밖에서는 명부가 바뀌지 않게 하는 장치다.

| 칸 | |
|---|---|
| 이름 | 영문 · 숫자 · `.` `_` `-`. **커밋의 `author` 로 남는다** — 사내 아이디를 쓴다. 바꿀 수 없다 |
| 볼 수 있는 레포 | 체크. 전체(`*`)는 역할처럼 사람에게 붙는 값이다. 「레포 × 사용자」 표에서도 고친다 — 저장 즉시 다음 요청부터 |
| 역할 | `viewer` 기본. `writer` 는 `save` · 레포 세우기 · 작업 레포 등록. `admin` 은 콘솔 |

셸 — `$CTX serve user add --auth $A --data $D --name <아이디> --label "<소속 · 역할>" --repos gdi[,foo] [--role writer|admin]`.

### 6.3 토큰을 발급한다

콘솔 > **토큰** > [발급] — 사용자 · 메모(기기) · 만료. **원문은 다음 화면에 한 번** 보인다 — [복사] 해서 **본인에게
직접** 전한다(메신저 · 메일 · 이슈에 평문으로 남기지 않는다. 남겼으면 유출로 보고 폐기 후 재발급). [확인 — 전했다]
를 누르면 다시 볼 수 없다. 받은 사람은 환경변수 `CDP_TOKEN` 에 넣는다 — 사용자 설명서 2장.

| | |
|---|---|
| 메모 | 기기마다 하나씩 발급하고 메모를 붙인다 — 하나를 잃으면 그것만 죽인다 |
| 만료 | 기본은 역할이 정한다 — **관리자 30일 · 나머지 90일.** `무기한` 은 감시용 계정에만 |

셸 — `$CTX serve token --auth $A --data $D --user <아이디> --note "<기기>" [--expires 90|never]`. stdout 한 줄이 원문이다.

### 6.4 바꾸기 · 비활성 · 폐기

콘솔 > 사용자 — 행의 [역할] · [레포] · [비활성]. 퇴사 · 이동은 **비활성** — 삭제는 없다. 그 사람이 남긴 커밋의
`author` 가 명부와 이어져야 한다. 자기 자신의 역할을 내리거나 자신을 끌 수 없고, 마지막 관리자를 내릴 수 없다 —
다른 관리자가 한다.

콘솔 > 토큰 — 행의 [재발급] · [연장] · [메모] · [폐기]. **폐기한 행은 회색으로 남는다** — "이 사람 토큰이 언제
있었나" 가 이력이다.

셸 — `$CTX serve user set --name <아이디> --role writer|--repos gdi,foo|--inactive` ·
`$CTX serve token revoke --name <아이디> [--id <앞 8자>]` · `user list` · `token list`.

### 6.5 토큰을 잃었다 · 만료됐다 → **재발급**

토큰 원문은 어디에도 없으므로 **복구가 아니라 재발급**이다. 콘솔 > 토큰 > 그 행의 **[재발급]** — 옛것을 폐기하고
새것을 한 동작으로 낸다(원문 1회). 사람의 권한은 그대로다. 30초 일이다.

사용자는 `CDP_TOKEN` 을 바꾸고 Claude Code 를 다시 켠다. 브라우저 세션 쿠키는 서버 재시작을 넘어 살아 있고,
로그아웃하면 새 토큰으로 다시 들어간다.

**분기마다** 같은 절차 — 콘솔 > 토큰의 `만료` · `마지막 사용` 으로 안 쓰는 토큰을 정리한다. 현황이 7일 안 만료를
경고로 낸다.

### 6.6 이력

발급 · 폐기 · 명부 변경 · 레포 생성 · 재인증은 `/opt/cdp/data/logs/auth.log` 에 남는다(토큰은 앞 8자만).
콘솔 > **감사** 가 그 파일 그대로다 — 콘솔에서 한 것은 행위자가 붙고, 셸에서 한 것은 `(셸)`. 회전하지 않는다 —
이력이다. 요청 로그는 `serve.log`(3 × 1MB 회전) — 콘솔 > 서버 > 로그.

## 7. 지식 레포 운영 — 어휘 · 등록부 · 검사

### 7.1 첫날 — 패키지를 프로젝트에 맞춘다

패키지(dpms 는 문서 46종)를 다 쓰는 프로젝트는 드물다.

```
1  안 쓰는 문서를 지운다               docs/ 에서
2  _managed.md 에서 그 패턴을 지운다     없는 문서를 가리키면 커밋이 막힌다 — 조용하지 않다
3  문서마다 예시 섹션을 지운다          `(예시)` 가 붙어 있다
4  _vocab.md 에 프로젝트의 좌표를 등록한다
5  ctx check                          이상 없음이 나오면 시작할 수 있다
```

**반대는 조용하다** — 문서만 있고 패턴이 없으면 그 문서는 갱신이 강제되지 않는다. 좌표를 갖는
문서를 남겼으면 패턴도 남았는지 확인한다. 문서마다 끝의 `## 작성지침` 이 서식 규약이다 —
지침이 모자라면 고쳐서 같이 커밋한다.

### 7.2 어휘 `_vocab.md`

```markdown
## table                      ← ## <타입> 섹션 순서 = 화면의 카테고리 순서.  자주 쓰는 것을 위에

- `table:rp_plnd_mst` — 계획서마스터
  aliases: 계획서마스터, RP_PLND_MST, 계획서
- `table:rp_rdc_opl_mst` — 연관위 의견 (구)
  deprecated: 2026-03-26 오타 정정
  supersededBy: table:rp_rdc_opl_list
```

| 일 | 누가 | 어떻게 |
|---|---|---|
| 늘리기 | **사용자** | 커밋이 막히면 그 자리에서 한 줄. 관리자를 기다리게 하지 않는다 |
| 정리하기 | **관리자** | 같은 대상에 좌표 둘 → 하나를 `deprecated` 로 접고 alias 로 흡수 · alias 없는 좌표 · **라벨을 붙여 쓴 alias 하나뿐인 좌표** |
| 지우기 | **하지 않는다** | 과거 문서가 그 이름을 쓴다. `deprecated:` 로 표시한다 |

**alias 는 맥락 주입의 단일 실패점이다.** 자연어 → (alias) → 좌표 → 섹션 사슬에서 alias 가 끊기면
오류 없이 빈손이 되고, 요청을 받은 쪽은 그것을 *"레포에 내용이 없다"* 로 읽는다. 넣을 것은 그
대상을 **부르는 말**(줄임말 · 화면의 말 · 요구사항서의 말), 넣지 말 것은 그 대상의 **속성**(그것은
다른 좌표다 — 먼저 등재된 쪽이 조용히 이긴다). API 경로나 모듈명이 좌표인 타입을 특히 살핀다.

```
ctx term <이름>        어휘 조회       ctx match <이름...>   이름 → 좌표       ctx search <말...>   말 → 후보
```

### 7.3 등록부 `_managed.md` — 여기가 판단이 필요한 자리다

```markdown
| 좌표 패턴 | 정본 문서 | 섹션 |
|---|---|---|
| `screen:PS*` | `docs/화면정의서_인사.md` | `## {값}` |     ← 좁은 것을 위에.  먼저 걸리는 패턴을 쓴다
| `screen:*`   | `docs/화면설계서.md`      | `## {값}` |
| `table:*`    | `docs/테이블정의서.md`    | `## {값}` |
```

**등록부에 패턴을 올리는 것이 곧 "이건 정본 문서로 관리한다"는 팀의 결정이다.** 올리면 그 좌표를
건드린 모든 작업이 그 섹션 갱신을 요구받는다 — 검사가 막는다. 그래서 가볍게 올리지 않는다.

| 그 좌표를… | 등록부에 |
|---|---|
| 여러 사람이 자주 찾고, 한 문서에서 모아 보는 게 이득이다 | **올린다** |
| 드물게 찾고, 그 작업 기록 하나로 충분하다 | **안 올린다** — 그 기록이 원천이다. 결함이 아니다 |
| `domain:` 같은 **축**(대상이 아닌 분류) | **넣지 않는다** |

### 7.4 검사 — 무엇이 커밋을 막는가

훅(로컬형) 과 `save`(서버형) 가 `ctx check` 를 돌리고 **error 가 하나라도 있으면 거부**한다.

| 등급 | 이름 | |
|---|---|---|
| **error** | `derive-missing` | **관리 문서 파생 누락** — 좌표를 건드렸는데 섹션을 안 채웠다 |
| **error** | `unregistered-coord` | `_vocab.md` 미등재 좌표 |
| **error** | `dangling-anchor` | 등록부가 가리키는 섹션이 없음 |
| **error** | `dup-anchor` | 같은 좌표의 섹션이 한 문서에 둘 — 뒤의 것은 보이지 않는다 |
| **error** | `orphan-applied` | `applied` 가 없는 작업 기록을 가리킴 |
| **error** | `missing-field` · `frontmatter` · `id-mismatch` | 필수 필드 · YAML · `id` ≠ 파일명 |
| **error** | `agenda-status` · `status-value` | `status: 미결·제안` · `status` 에 쓸 수 있는 값이 없다 |
| **error** | `broken-supersedes` · `cycle` | `supersedes` 대상 없음 · 순환 |
| warn | `derive-sameday` | 같은 날 기록이 더 있다(시각 없음) — 눈으로 확인 |
| warn | `deprecated-coord` · `hooks-off` · INDEX 불일치 | 폐기 좌표 사용 · **훅 미설치(가장 조용한 실패)** · `ctx index` |
| info | `thin-body` · `single-coord` · `no-touches-key` | 본문이 얇다 · 좌표 1개 · `touches` 키 없음 |

**error 를 함부로 늘리지 않는다.** 막히는 것이 잦으면 사람들이 `--no-verify` 를 쓰기 시작하고
보증 층이 통째로 사라진다. 파생 누락을 error 로 두는 이유 — "밀림" 이라는 상태가 없어야 하기 때문이다.

### 7.5 점검

| 언제 | 서버형 | 로컬형 |
|---|---|---|
| 매일 | `curl /healthz` — `mirror.ok` 가 레포 수와 같은가 · 콘솔 **현황**(경고 목록 · 최근 감사) | 상단 **⭮ 동기화** · `⚠ 검증 N` |
| 주기적 | 콘솔 > 서버 진단 fail 0(= `doctor`) · 콘솔 > 토큰의 만료 · 마지막 사용 · `ctx derive` 오래 남은 것 | `ctx derive` · `ctx index` · `ctx sync`(훅 설정 여부) |
| 어휘 | 화면 좌표 탭 · `ctx term` — 갈라진 이름 · alias 없는 좌표 | 같다 |
| 감시 | `GET /healthz` 를 감시 목록에 · `doctor --json` 을 크론에 | |
| 백업 | `--mirror` + `/opt/cdp/repos` 스냅샷 · `auth.json` · `data/` | 원격이 백업이다 |

### 7.6 서버형 — 서버는 pull 하지 않는다

서버는 그 트리의 **유일한 작성자**다. 스킬 · 어휘를 서버 밖에서 고쳐 origin 에 push 하면 서버 트리가
뒤처지고, 다음 `save` 의 push 가 거부되어 `mirror: lag` 가 안 풀린다.

```bash
sudo -u cdp -H git -C /opt/cdp/repos/gdi fetch && sudo -u cdp -H git -C /opt/cdp/repos/gdi status -sb | head -1
#   ## main...origin/main            ← 같다.  바깥에서 고치고 origin 에 올린 뒤 ↓
sudo -u cdp -H git -C /opt/cdp/repos/gdi pull --ff-only
#   ## main...origin/main [ahead 2]  ← 서버 커밋이 origin 에 못 갔다.  먼저 push.  그것도 거부되면 사람이 서버 트리에서 합친다
```

스킬을 고쳤으면 꾸러미도 새것이 된다 — 관리 화면의 작업 레포 행이 `낡음` 으로 바뀌고 각자
`install.mjs` 를 한 번 더 돌린다(9.3).

## 8. 기존 문서 들이기 — `ctx import-dir`

회의록 · 검토서 같은 md 폴더 **수십 · 수백 건**을 `work/` 로 옮긴다. 몇 건이면 사용자의
`cdp-import` 스킬이 맞다.

```bash
ctx import-dir <원본 폴더> --repo <지식 레포> --dry            # 표만 찍는다.  먼저 본다
ctx import-dir <원본 폴더> --repo <지식 레포> [--author <이름>] [--keep-touches] [--yes] [--json]
```

| 규칙 | |
|---|---|
| 이름 | 하위 폴더를 평면화 → `work/YYYY-MMDD-<폴더조각>-<이름>.md`. 충돌은 `-2` 접미. 150자에서 자른다 |
| `date` | 프론트매터 → 파일명의 날짜 → git 최초 커밋 → mtime 순으로 근거를 찾고 **근거를 표에 적는다** |
| `author` | 프론트매터 → `--author` → git → `import` |
| **좌표** | **추측하지 않는다.** 원본의 `touches` 는 비우고 `tags` 에 `touches/<좌표>` 로 보존한다(`--keep-touches` 면 그대로 — 파생 문서가 없으면 검사에서 전부 되돌아온다) |
| `status` | 지운다. 모르는 필드는 `tags` 로 접는다 |
| 첨부 | md 가 아닌 파일은 `work/assets/<조각>/` 로, 본문의 상대 링크를 다시 쓴다 |
| 결정론 | 두 번 돌려 같다. 이미 있는 파일은 건너뛴다 |
| 끝 | 쓴 뒤 `ctx check`. error 가 있으면 **쓴 것을 전부 되돌린다** |

끝나면 *"좌표 0건 — 붙이는 것은 사람이"* 라고 말한다. 원본에 규약이 없었으니 어떤 대상을 **바꾼**
사건이었는지는 사람이 읽어야 안다. 서버형에서는 서버 트리에 직접 돌리지 않는다 — 바깥에서 돌려
origin 에 올리고 7.6 의 순서로 서버를 맞춘다.

## 9. 갱신 — 새 판이 나왔을 때

### 9.1 서버형 — `upgrade.sh`

```bash
scp cdp-server-v0.9.1.tar.gz <계정>@<서버>:/tmp/
sudo bash /opt/cdp/deploy/upgrade.sh /tmp/cdp-server-v0.9.1.tar.gz      # [--prefix] [--user]
```

푼다 → `bin/ctx.mjs.bak` · `web.bak` · `packages.bak`(한 세대) → `ctx.mjs` 교체 · `web/` 은 비우고
넣는다 · `packages/` 교체 → `systemctl restart` → **`/healthz.built` 가 새 번들 시각인지 · 화면
자산 해시가 tar 의 것과 같은지** 대조 → 다르면 `.bak` 으로 되돌리고 exit 1. **명부 · 대장 ·
레포 · git 자격은 건드리지 않는다.** 브라우저는 강제 새로고침(`Ctrl+Shift+R`). 로그인 상태는
재시작을 넘어 살아 있다.

### 9.2 로컬형 — 도구만 덮어쓴다

```
copy <새 배포본>\knowledge-repo-dpms\bin\*         C:\cdp\bin\
copy <새 배포본>\cdp.exe                             C:\cdp\tools\
copy <새 배포본>\knowledge-repo-dpms\MANUAL*.md    C:\cdp\
copy <새 배포본>\knowledge-repo-dpms\.gitattributes C:\cdp\     ← 도구 파일이다. 2026-09-23 이전 레포는 *.cmd eol=crlf 가 없다
git add -A && git commit -m "도구 갱신 — v0.9.1" && git push
C:\cdp\tools\cdp.exe ctx setup C:\gdi              ← 스킬도 같이 갱신된다.  작업 레포마다
```

`_vocab.md` · `_managed.md` · `docs/` · `work/` 는 **건드리지 않는다.** 그것이 지식이고 도구는 그
위에서 도는 것이다. 팀원은 pull 뒤 `ctx version` 이 새 날짜인지 본다 — **번들이 낡은 레포는 조용히
옛 답을 낸다.** `brief` 가 90일 넘은 번들을 한 줄로 경고한다.

### 9.3 작업 레포의 스킬 — 낡음

| 어디 | 어떻게 보이나 | 고침 |
|---|---|---|
| 관리 화면 > 작업 레포 (서버형) | 그 행이 `낡음` — 설치 보고의 kit 해시 ≠ 서버의 해시 | 각자 `install.mjs` 다시 (또는 `ctx setup --server`) |
| Claude Code (서버형) | `sync` 도구의 `kit.hash` ≠ `CLAUDE.md` 의 `cdp:kit` → 스킬이 답에 적는다 | 같다 |
| 관리 화면 > 작업 레포 (로컬형) | `갱신 필요` — 계획을 dry 로 돌려 안다 | `ctx setup` 다시 · 일괄 갱신 버튼 |

| 질문 | 답 |
|---|---|

## 11. 하지 않는 것

관리자가 "이거 넣으면 좋겠다" 고 생각하기 쉬운데 **일부러 안 하는 것들**이다.

| | 왜 |
|---|---|
| **알림** | 무시되기 시작하면 되돌릴 수 없고, 그때 *"알림이 안 왔으니 없는 것"* 이라는 더 나쁜 오해가 자리 잡는다 |
| **사용자가 화면에서 토큰을 요청** | 발급은 관리자가 한다 — 콘솔 또는 셸. "토큰 주세요" 버튼이 있으면 그 버튼이 가장 약한 곳이 된다 |
| **화면에서 갱신 · PAT · 재시작** | 자기 자신을 갈아 끼우는 일이라 실패했을 때 되돌리는 길이 셸뿐이다. 콘솔 > 서버는 판과 명령을 **보이기만** 한다 |
| **화면에서 문서 편집** | 쓰기는 스킬과 `save` 의 일. 화면이 하면 좌표 대조와 검사를 우회하는 길이 생긴다 |
| **자동 merge · 충돌 해결 · 서버의 pull** | 섹션 두 갱신을 기계가 섞으면 그 결과가 정본 자리에 앉는다 |
| **관리 문서 자동 생성** | 입도는 팀이 정한다 |
| **작업 할당 · 이슈 트래커** | 조직 구조와 얽힌다. 아젠다는 위험및이슈관리대장 한 문서다 |
| **RAG · 임베딩** | 좌표가 답이다. 근사 검색은 "없는 것" 을 "비슷한 것" 으로 채운다 |
| **두 번째 패키지를 미리** | 표본이 둘이 될 때 만든다 — 만드는 길(`ctx package new`)만 있다 |
