## 1. CDP 가 무엇인가

```
work/   작업 기록   무슨 일이 있었나 · 왜 그렇게 정했나    사건 · 고치지 않는다 · 쌓인다       writer 가 쓴다
docs/   관리 문서   대상이 지금 어떻게 생겼나              상태 · 정본 · 현재형으로 고친다     큐레이터가 쓴다
```

- **좌표가 두 층을 잇는다** — `<타입>:<값>`(`table:bk_loan_mst` · `screen:HRC043`). 타입 목록은 그 지식 레포의 `_vocab.md` 가 정한다 —
  이 책의 `table:` · `screen:` 은 예시다. 모르면 지어내지 말고 에이전트에게 맡긴다(`match` 가 이름을 정본 좌표로 푼다).
- **역할** — **viewer** 읽기 · **writer** + 작업 기록 · **큐레이터**(레포별) + 관리 문서 반영 · **admin** + 서버 전부(모든 레포의 큐레이터).
  내 역할은 화면 왼쪽 아래 「내 계정」 에 있다.
- **writer 는 관리 문서를 쓰지 않는다** — 섹션이 틀렸거나 바꿀 것이 있으면 그것을 작업 기록에 쓴다. 큐레이터가 보고 반영한다.
- **미반영** — 기록을 남긴 뒤 큐레이터가 반영하기까지 섹션은 옛것이다. 그래서 섹션을 내보내는 모든 자리(도구 · 화면)가 그 섹션의
  미반영 기록을 같이 낸다(§5).
- **쓰는 길은 서버 `save` 하나** — 서버가 검사 · 커밋 · origin 미러까지 한다. 지식 레포를 clone 해서 고치고 push 하지 않는다.

## 2. 처음 한 번 — 연결

### 2.1 무엇을 받나

| 받는 것 | 어디에 쓰나 |
|---|---|
| 서버 주소 `http://<서버>:7374` | 브라우저 · 설치 한 줄 |
| 지식 레포 이름 | 레포 고르기 |
| **토큰 한 줄** — 받은 그 순간 한 번만 보인다(서버에는 해시만) | 화면 로그인 · Claude Code 가 서버에 붙을 때 |

토큰에 이름이 들어 있다 — 기록의 작성자는 서버가 토큰에서 채운다. 설명서(`/manual`)는 토큰 없이 읽는다.
**서버가 없는 사람**은 자기 PC 에 개인 서버를 띄운다 — 아래 2.3.

### 2.2 팀 서버 — 작업 레포마다 한 줄

**한 줄** — 화면 **작업실 › 작업 레포 연결** 에서 작업 레포를 등록하면(writer 이상) 그 행의 설치 한 줄이 펼쳐진다. 셸(PowerShell ·
명령 프롬프트 · macOS/Linux)을 골라 **그 작업 레포 폴더에서** 붙여넣는다. Node 20 이상이 있어야 한다.

```
curl -fsSLo /tmp/cdp-install.mjs http://<서버>:7374/install.mjs && node /tmp/cdp-install.mjs --repo <레포> --workrepo <id> .
```

코드 레포가 여럿이면 그것들이 든 상위 폴더 하나로 한 번에 — 등록 · 설치까지 한다(`--commit` 이면 레포마다 CDP 파일만 커밋).

```
node /tmp/cdp-install.mjs --connect --repo <레포> <코드 레포들이 있는 폴더> [--commit]
```

**무엇이 일어났나**

- 토큰 — `CDP_TOKEN` → 이 PC 의 `~/.config/cdp/token` 순으로 찾고, 없거나 안 통하면 **보이지 않게 묻는다.** 서버에 확인하고
  (`확인했습니다 — <이름> (writer)`) 이 PC 에 둘지 묻는다 — Windows 는 사용자 환경변수 `CDP_TOKEN`, macOS · Linux 는 `~/.config/cdp/token`(600) + rc 한 줄.
- 바뀔 것을 먼저 보이고 묻는다. 남의 것은 지우지 않는다(`cdp-` 아닌 스킬 · `CLAUDE.md` 의 나머지 · `.mcp.json` 의 다른 서버).

  ```
  .mcp.json            cdp 항목 — 서버 /mcp/<레포> · Authorization: Bearer ${CDP_TOKEN}
  .claude/cdp.json     { "server": …, "repo": … }
  .claude/skills/cdp-* 스킬 셋 — cdp-work · cdp-save · cdp-push
  CLAUDE.md            <!-- cdp:begin --> … <!-- cdp:end --> 블록만
  ```
- 서버의 작업 레포 대장에 보고한다 — 화면의 그 행이 `최신`.

**그다음 둘** — ① Claude Code 를 **완전히** 끄고 다시 켠다(VS Code · 데스크톱 앱 안이면 그 앱째) ② 처음 설치한 사람은
`git add .mcp.json .claude CLAUDE.md` 후 커밋한다. **팀원**은 pull 뒤 같은 한 줄을 각자 한 번 — 설치할 것은 없고(「이미 최신입니다」) 토큰만 둔다.

**확인** — `/mcp` 에 `cdp` connected · 도구 10(viewer 9 — `save` 가 없다). 에이전트에게 *"cdp 브리핑 보여줘"* → `brief` 두 줄.

### 2.3 개인 서버 — `ctx up`

서버가 없으면 자기 PC 에 띄운다. 폴더 이름이 지식 레포 이름이다(영문 · 숫자 · `._-`). `ctx` 를 받는 길은 [서버 관리자 설명서](관리자_설명서.md)의 개인 서버 절.

```
ctx up ~/cdp/<레포> --install <코드 폴더> [--install <코드 폴더>…] [--curator <폴더>] [--skills <폴더>]
```

**무엇이 일어났나** — 빈 폴더면 빈 틀로 세우고 · 빈 포트(7400 부터 — 이미 떠 있으면 그 주소)로 서버를 띄우고 · 이 PC 에 토큰을 두고 ·
`--install` 마다 대장 등록과 설치를 토큰 복사 없이 하고 · 브라우저를 연다. 끝 출력이 다음 할 일(다시 켜기 · 커밋 줄)이다.
로그인할 때 뜨게 하려면 `ctx up ~/cdp/<레포> --service`. 다시 칠 때도 같은 한 줄이다.

### 2.4 막히면

| 증상 | 할 일 |
|---|---|
| `! .gitignore 가 CDP 파일을 막습니다` | `.claude/*` 를 통째로 막은 레포다 — 그대로면 스킬이 팀에 안 간다. 보인 줄(`!.claude/skills/` · `!.claude/cdp.json`)을 넣거나 `--fix-gitignore` |
| `--commit` 했는데 커밋이 없다 | `.gitignore` 에 막혔거나 그 파일에 원래 커밋 안 된 변경이 있던 레포다 — 스테이징을 되돌리고 대장에 「최신」 으로 보고하지 않는다. 위 줄을 고치고 다시 |
| 「그 등록은 X 의 것이다」 · 409 | 다른 레포의 등록 id — X 의 작업 레포 연결에서 한 줄을 다시 받는다 |
| 「쓰기 권한」 으로 멈춘다(`--connect`) | viewer 토큰이다 — 관리자에게 writer 를 청한다 |
| Node 가 없다 · 내려받기가 막힌 망 | 같은 행의 「꾸러미 zip」 — 풀고 그 안에서 `node install.mjs <작업 레포>`. Node 도 없으면 꾸러미 안 `설치.md` 대로 손으로 |
| 그 밖 | §9.2 |

## 3. 일하기 — `cdp-work`

작업 레포의 `CLAUDE.md` 블록에 적혀 있어 시키지 않아도 에이전트가 쓴다. 요청 하나에 —

```
① 검토   무엇을 바꿀 것인가 — 좌표 · 판정(변경 · ? · 참조) · 주입할 것 · 이미 정해진 것. 4~6줄 · 멈추지 않는다
② 주입   좌표마다 section 한 번 — 섹션 + 미반영 기록 + 건 정본 + 기준선
③ 수행   그것을 근거로 한다
```

**요청이 먼저다** — 무엇을 바꿀지 알기 전에 맥락을 넣으면 엉뚱한 곳을 좁힌다. 검토가 이름표(`match` · `where` · `search`)만 보는 까닭이다.
들어오는 것은 **그 좌표의 섹션 하나와 그 미반영 기록**이다 — 문서의 다른 섹션 · 이미 반영된 옛 기록은 오지 않는다.
섹션이 사실상 비었으면 에이전트가 그렇게 말해야 한다(「정의가 없다」 가 「제약이 없다」 로 바뀌면 확신 있게 틀린 답이다).

| 검토에 보이는 것 | 이렇게 말한다 |
|---|---|
| 대상이 빠졌다 · 넘친다 | *"HRC031 도 바뀌어"* · *"HR130 은 안 건드려"* |
| 맥락이 필요 없다 | *"맥락 필요 없어, 그냥 해"* |
| `?` | 에이전트가 확신이 없다 — 먼저 볼 자리 |
| `(미등재)` | 어휘에 없는 이름 — 지금 바꾸지 말고 기록할 때 등재한다(§4.2) |

**부르지 않는 때** — 지식 레포와 무관한 요청(정규식 · 이름 바꾸기) · 같은 주제의 이어지는 대화. 그 도메인의 리더라 내 로컬이 최신이면
주입은 건너뛰어도 되지만 **기록은 남긴다.** `/mcp` 에 `cdp` 가 없으면 에이전트는 기억으로 답하지 않고 그렇게 말해야 한다(§9.2).

## 4. 기록 남기기 — `cdp-save`

### 4.1 흐름

```
① 길        이 세션의 작업 · 밖에서 온 문서(편입) · 문서를 고치라는 지시
② 좌표 판정  바꾼 · 정한 · 정의한 · 제기한 대상만
③ 기록      홀로 선다 — 값 · 표 · 결정 · 제약은 본문에
④ 승인      【좌표 판정】 과 기록을 보이고 받는다 — 건너뛰지 않는다
⑤ save      work · vocab · assets 한 번 → 서버가 검사 · 커밋 · 미러
⑥ 끝 보고    커밋 · 미러 · 「큐레이션 대기 n번째」
```

**요청 하나가 작업 하나가 아니다** — 요청 셋이 한 작업이면 기록은 하나다. **④ 를 꼭 읽는다** — 기록은 커밋되면 고칠 수 없고,
서버는 좌표를 **빠뜨린** 것을 모른다. 【좌표 판정】 의 **뺀 것** 줄이 빠진 좌표를 잡는 유일한 자리다.

```
【좌표 판정】 기록 2026-0908-출장보고-사진첨부 · 길: 이 세션의 작업
  ―― 넣는다 ――
  screen:BZD020             변경   사진 첨부 영역 신설
  table:pj_trip_photo_list  신설   사진 저장 테이블 (미등재 → 등재)
  issue:ISS-015             제기   차량 이용 여부를 무엇으로 가르나 — 회신 대기
  ―― 뺀다 ――
  screen:BZD012             참조   출장등록에서 넘어오지만 안 바뀐다
승인하시면 남깁니다.
```

### 4.2 좌표 — 바꾼 것만

판정 기준은 하나 — **6개월 뒤 그 대상을 맡은 사람이 이 기록을 찾아야 하는가.**

| 이 작업이 그 대상을… | 좌표 |
|---|:--:|
| 신설 · 변경 · 삭제 · 폐기했다 / (편입 · 지시) 그러기로 **정했다** | O |
| 용어 · 개념을 정의했다 · 답이 안 난 것을 이슈로 **제기했다** | O |
| 참조 · 호출 · 언급했다 · 그것을 쓰는 다른 것을 만들었다 · 「검토하기로 했다」 | X |

예 — HRA021 에서 `bk_member_mst` 의 컬럼으로 트리를 묶었다 → `screen:HRA021` 만(테이블은 읽기만). 임시저장에 작성일을 안 남기기로 했다 →
`screen:HRB020` · `table:bk_review_list`(컬럼이 언제 채워지는지가 바뀌었다). 일정만 확정했다 → 좌표 없음, `touchesEmpty` 에 사유.

- **억지 좌표는 없는 좌표보다 나쁘다** — 찾는 사람에게 무관한 기록을 내민다. 본문에만 `` `type:값` `` 으로 쓴 좌표는 경고가 난다 — 참조면 두고, 바꿨으면 넣는다.
- **어휘에 없는 좌표**면 에이전트가 `vocab` 에 같이 보낸다 — `aliases` 에는 그 작업에서 **실제로 쓴 말**을 넣는다. writer 는 어휘를 더하기만 한다 — 이미 있는 좌표는 건너뛰고 경고가 온다. label · alias 고치기 · 폐기 · 이름은 큐레이터에게.
  새 타입이면 서버가 타입 절을 만든다(오타면 지울 수 없다 — 「새 타입」 줄을 확인한다).
- 그 타입을 받는 관리 문서가 없어도(`where` 가 `registry: null`) 정상이다 — 같은 타입이 쌓이면 기록 끝에 「큐레이터에게 — 받을 문서가 없다」 한 줄.

### 4.3 기록은 홀로 선다

큐레이터는 **이 기록만 보고** 반영하고, 반영 전까지 그 좌표를 읽는 사람은 섹션 옆에 실린 이 본문을 본다. 둘 다 이 세션 · DB · 코드에 닿지 못한다.

| 본문에 쓴다 | 쓰지 않는다 |
|---|---|
| **값** — 컬럼 · 타입 · 코드값 · 규격 · 기본값 · 한도 · 정한 표 그대로 | 「섹션 X 참조」 · 「DB 에서 확인」 · 값 없는 「기본값 표를 정했다」 |
| **결정과 제약** — 무엇을 왜 · 버린 안과 이유 | 경위만 길게 |
| **남은 것** — 회신 대기 · 열린 물음(따로 한 절) | |

큰 추출물(DDL 전문 · 덤프 · 캡처)은 첨부로, 요지는 본문 표로. 이유가 안 보이면 에이전트가 한 번 묻는다.

| `work.` | |
|---|---|
| `id` · `title` · `date` | 필수. `YYYY-MMDD-slug` · `YYYY-MM-DD HH:MM`(그 일이 있었던 때 — 시각까지) |
| `touches` | 필수. 0개면 `touchesEmpty` 에 사유 |
| `source` · `supersedes` · `tags` | 편입의 출처 · 정정(§4.6) · 자유(`curate` · `baseline` · `registry` 같은 예약 태그는 큐레이터 몫) |
| `body` | 마크다운 |

`author` 는 보내지 않는다(토큰에서). `status` 필드는 없다(적으면 막힌다).

### 4.4 편입 · 문서 수정 지시

- **편입** — *"이 회의록 넣어 줘"*. 날짜는 **사건의 날**(오늘이면 반년 전 회의록이 어제 결정을 덮는다) · 언급은 좌표가 아니다 ·
  **본문을 다시 쓰지 않는다**(프론트매터만) · `source` 에 출처. 문서가 많으면 세션이 아니라 CLI 로 — [4.8 문서 · 폴더에서 들이기](#48-문서--폴더에서-들이기--ctx-ingest).
- **문서 수정 지시** — *"BZD020 첨부 용량을 10MB 로 고쳐 줘"*. writer 는 섹션을 고치지 않고 **고칠 것을 기록한다** — 본문은
  `## 지시`(원문 그대로 · 요약하지 않는다 — 「어차피 안 올라가」 가 제약의 출처다) · `## 바꿀 것` · `## 확인한 것`. 끝 보고는
  「고칠 것을 기록했다 · 큐레이터가 반영한다」 다.
- **결정이 안 났으면 기록하지 않는다** — `미결` · `제안` 상태는 없다. 정해진 부분만 기록하고, 열린 물음은 「남은 것」 에 쓰거나 이슈 좌표로 제기한다.

### 4.5 그림 · 첨부

에이전트가 셸에서 올리고 받은 `ref` 를 `save` 에 싣는다 — 서버가 `work/assets/<기록 id>/<이름>` 에 기록과 한 커밋으로 넣는다.

```bash
curl -sS -H "Authorization: Bearer $CDP_TOKEN" --data-binary @구성도.png "http://<서버>:7374/api/<레포>/assets"
```

png · jpg · gif · webp · pdf · html, 하나에 10 MB(svg 는 받지 않는다) · 24시간 안에 save 에 싣는다. 본문은 `![구성도](assets/<id>/구성도.png)`.
HTML 시각 자료는 링크로 걸면 화면이 「본문 | 자료」 탭으로 연다 — 검색 · 큐레이션은 md 만 보므로 요지는 본문에도 쓴다.

### 4.6 정정

기록은 불변이다. 틀렸으면 `supersedes: <틀린 id>` 를 단 새 기록. **좌표 누락도 오기재다** — id `<원 id>-좌표정정` · date 는 원 기록의 날 ·
`touches` 는 빠졌던 좌표만. 같은 좌표를 나중에 또 바꾼 것은 정정이 아니다(날짜로 계산된다).

### 4.7 save 의 답

| `mirror` | 뜻 |
|---|---|
| `ok` · `queued` | 커밋했고 origin 에 갔다 · 가는 중 |
| `lag` · `diverged` | 커밋했다 · 미러는 못 갔다 — 사유를 그대로 전한다(고치는 것은 관리자) |
| `off` | 커밋했다 · 원격이 없는 레포 |

어느 경우든 기록은 서버에 있다. **push 할 것이 없다.** 거절은 §9.1.

### 4.8 문서 · 폴더에서 들이기 — `ctx ingest`

이미 써 둔 문서 · 문서가 모인 폴더 · git 레포를 **작업 기록으로** 들인다. 사람이 터미널에서 돌린다(에이전트가 아니다). 결과는 대기열에 서고
좌표 · 관리 문서 반영은 큐레이터가 한다 — writer 권한이면 된다.

```bash
ctx login --server http://<서버>:7374
```

```bash
ctx ingest D:\설계\회의록 --repo <레포>
```

```bash
ctx ingest D:\설계\회의록 --repo <레포> --analyze
```

```bash
ctx ingest D:\설계\회의록 --repo <레포> --apply
```

화면 **작업실 › 지식 생성 › 새 들이기** 가 이 명령들을 셸에 맞게 짓고(잡 id 를 붙여), 돌리면 진행 · 파일마다 결과 · 들어간 기록의 대기열 상태를 그 잡에서 보인다.
서버는 파일을 읽지도 LLM 을 부르지도 않는다 — 돌리는 것은 그 사람 PC 다.

- **처음 한 번 `ctx login`** — 토큰을 숨김 입력으로 받아 `/me` 로 확인하고 둔다(작업 레포가 쓰는 그 자리). `ctx whoami` 로 누구 · 어느 서버인지 본다.
- **`--apply` 없이는 계획만** — 무엇이 어떤 기록이 되나(id · 날짜와 그 근거 · 첨부) · 건너뛰는 것과 까닭. 아무것도 쓰지 않는다.
- 받는 글 — **md · markdown · txt** 와 변환한 것: **docx · xlsx · pptx · hwpx 는 늘**(ctx 가 직접 — 제목 · 문단 · 목록 · 표 · 그림), **pdf 는 `pdftotext`(poppler)** ·
  **doc · xls · ppt · hwp 는 LibreOffice(`soffice`)** 가 그 PC 에 있을 때. 변환하지 못하면 들이지 않고 까닭을 낸다(스캔 pdf 는 글이 없어 건너뛴다 — OCR 은 하지 않는다).
  본문이 가리키는 그림 · pdf · 변환한 문서 안의 그림은 그 기록의 첨부로 간다. pdf 는 원본도 첨부한다.
- **판단(`--analyze`)** — 그 PC 의 `claude`(Claude Code)가 파일마다 문서 성격 · 날짜 · 나눌 자리 · **좌표 후보와 근거 인용**을 낸다. 편입 규칙(cdp-save)을 그대로 따르고
  `match` 로 이 레포의 어휘와 대조한다. **아무것도 쓰지 않는다** — save · 편집 · 셸이 막혀 있고 본문도 다시 쓰지 않는다(줄 범위만 고른다).
  `claude` 의 로그인은 그 사람이 한 번 켜서 한다 · 비용도 그 사람의 계정이다. `--budget <토큰>` 으로 멈출 자리를 둔다. `ctx ingest doctor [--live]` 가 준비물을 본다.
- **승인(`review.md`)** — 판단 뒤 상태 폴더의 `review.md` 에 파일마다 후보가 체크 목록으로 선다. **체크한 좌표 · 어휘만 들어간다**(기본 체크는 이미 등재되고 인용이 있는 것).
  미등재 좌표는 그 어휘 제안도 같이 체크해야 올라간다. 고르지 않은 후보는 태그 `touches?/<좌표>` 로 남아 큐레이터가 본다. 「제외」 로 판단한 파일은 들이지 않는다.
  `--approve registered` 는 review.md 를 열지 않고 기본 체크대로 들인다. 판단 없이 들이려면 `--no-llm`.
  **화면에서 골라도 된다** — 작업실 › 지식 생성 › 그 잡에서 판단한 파일을 펴 체크하고 「승인 저장」. 다음 `--apply` 가 그 승인을 먼저 쓴다(그 파일은 review.md 보다 화면이 이긴다).
- **본문은 원문 그대로** — 머리에 한 줄(원문 경로 · 원문 작성자 · 들인 날)이 붙는다. 날짜는 원문의 날(프론트매터 → 파일명 → git 첫 커밋 → 파일 시각).
- **판단 없이 들이면 좌표는 비운다** — 추측하지 않는다. 원문 프론트매터의 `touches` 는 태그 `touches/<좌표>` 로 남고 큐레이터가 대조한다.
- 서버 관리자가 그 레포를 「LLM 판단 없이」 로 정했으면(`--no-llm-ingest`) `--analyze` 를 거절한다 — 사내 문서가 밖으로 나가지 않게.
- **다시 돌려도 된다** — 들어간 원본은 건너뛴다(내용이 같으면 이름 · 자리가 바뀌어도). 끊겨도 같은 명령을 다시 돌리면 이어진다.
  원본을 고쳤으면 **새 기록**이 생기고 머리에 「이전 판」 이 걸린다. `--status` 로 대기 · 반영 · 기록으로 둠을 본다.
- `--glob '**/*.md'` · `--exclude '초안/**'` 로 고르고, 한 번에 200 개까지다(`--max-files`). 상태는 이 PC 의 `~/.cdp/ingest/` 에만 둔다 — 원천 폴더 · 지식 레포에는 쓰지 않는다.

## 5. 미반영 읽는 법

**섹션은 큐레이터가 반영한 데까지만 지금이다.** 그 뒤에 같은 좌표를 건드린 기록이 **미반영**이고, 섹션과 같이 나온다.

| 자리 | 보이는 것 |
|---|---|
| 섹션 제목 | **「미반영 n」** — 누르면 그 기록들이 펴진다 |
| 작업 기록 머리 · 목록 | **대기** · **반영됨 → 좌표** · **기록으로 둠(사유)** · 거름 「대기 · 내 기록」 |
| 에이전트의 답 | `⚠ screen:HRC043 섹션 뒤에 미반영 기록 1건 — …  아래는 섹션과 그 기록을 합친 상태가 기준이다` |

- **어긋나면 늦은 기록이 지금이다.** 좌표마다 따로 본다(「이 문서는 낡았다」 는 반드시 절반이 틀린다).
- 「후속이 있다」 를 「뒤집혔다」 로 읽지 않는다 — 기록 본문이 말한 것만 사실이다.
- 섹션이 없는데 미반영이 있으면 그 기록이 유일한 근거다. 「n건 중 일부만 실었다」 가 붙으면 나머지가 있다.

큐레이터가 판정하면 사라진다 — 반영 · 새 문서는 **판정에 적힌 좌표의 섹션에서만**, 기록으로 둠은 모든 섹션에서. 내 기록이 오래 대기에 있으면 그 레포의 큐레이터에게 말한다.

## 6. 화면

`http://<서버>:7374` → [로그인] → **토큰 한 칸**. 실패 문장은 「토큰을 확인하세요」 하나다(만료 · 오타를 가리지 않는다). 로그아웃은 쿠키만 지운다.

### 6.1 왼쪽 메뉴 — 영역 셋

메뉴 맨 위 스위치로 **보기 · 작업실 · 서버** 를 고른다. 메뉴에는 고른 영역의 항목만 나온다. 고를 영역이 하나뿐이면(viewer) 스위치가 없다.
스위치를 누르면 그 영역에서 마지막으로 본 화면으로 돌아간다.

| 영역 | 묶음 | 항목 | 누구 |
|---|---|---|---|
| **보기** | 지식 | **읽기**(문서 · 기록 세그) · **좌표 · 그래프** | 모두 — 쓰는 단추가 없다 |
| **작업실** | 만든다 | **작업 레포 연결** | writer 이상 |
| | 정리한다 | 대기열(› 이력 탭) · 진단 | 그 레포의 큐레이터 |
| | 세운다 | 관리 문서 · 서식집 · **현황**(맨 위 「시작하기」) | 관리 문서 · 서식집은 큐레이터 · 현황은 writer 이상 |
| **서버** | 서버 | 현황 · 지식 레포 · 사람 · 서버 | admin |

권한 밖 메뉴는 보이지 않는다. 맨 아래 **내 계정** — 역할 · 할 수 있는 것 · 토큰 만료 D-n · 판 · 테마 · 단축키. `Ctrl+B` 로 접는다.

### 6.2 읽기

- 왼쪽 위 세그로 **문서**(관리 문서) · **기록**(작업 기록 — 거름 전체 · 대기 · 내 기록)을 고른다. 문서를 안 골랐으면 오른쪽은 「시작하기」 · 담긴 수 · zip 내려받기.
- **뻗어나가기**(`\`) — 고른 것에서 한 단계씩 가로로 편다(기록 → 문서 · 좌표 / 좌표 → 문서 · 기록 / 문서 → 섹션). 정렬은 상태를 보지 않는다.
- 본문 — 오른쪽 목차 · 섹션의 「미반영 n」 · 끝의 `**경과**` 줄이 그 섹션을 만든 기록으로 이어진다 · 좌표는 누르면 따라간다 ·
  위 줄에 이전 · 최근 · 열린 문서 탭 · 아래 「내려받기 (.md)」. 문서가 주소에 있다 — 새로고침 · 공유 · 뒤로가 그 문서다.
- **좌표 · 그래프** — 이어진 좌표만 그린다(노드 크기 = 작업 건수). 누르면 1단계만 남고 「뻗어나가기 →」 로 나간다.
- **검색 `Ctrl+K`** — 관리 문서 · 작업 기록 · 좌표 이름과 alias 를 건다(띄어쓰기 · 대소문자 · `_` · `-` 무시). 이름에서 못 찾을 때만
  본문 전문(`Shift+Enter` 로 강제). 지금 레포 안에서만 · 유사도 검색이 아니다 — 걸리지 않으면 없는 것이다.

### 6.3 작업실

| 화면 | 무엇 |
|---|---|
| 작업 레포 연결 | 등록 · 행마다 설치 한 줄 · 상태(최신 · 낡음 · 미설치) |
| 현황 | 「시작하기」 — 이 레포에서 내 역할로 할 다음 일 · 문서 · 기록 · 미러 · 검사 |
| 관리 문서 · 서식집 | (큐레이터) 문서마다 쓰이는가(반영된 섹션 · 닿은 기록 · 들어오는 참조 · 필수) · 서식에서 새 문서 |

보기의 「시작하기」 는 누구에게나 할 일(토큰 만료 같은 것)만 낸다. 등록 · 큐레이션 할 일은 작업실 › 현황에 있다.

### 6.4 단축키

`Ctrl+K` 검색 · `Ctrl+B` 메뉴 · `\` 목록 ↔ 뻗어나가기 · `Ctrl+.` 읽기 모드 · `Ctrl` `+` `−` `0` 글자 크기 · `j` `k` `x` 기록 목록 · `Shift+C` 요약 복사(AI 세션에 붙이는 형식) ·
`Alt+←` `Alt+→` 이전 · 다음 문서 · `?` 도움말. Mac 은 `⌘` · `⌥`.

## 7. 새 판이 올라간 뒤

| | |
|---|---|
| 브라우저 | `Ctrl+Shift+R` 한 번. 로그인 · 주소는 그대로 |
| 에이전트 세팅이 바뀐 판 | 「시작하기」 에 **에이전트 세팅이 바뀌었다 · n곳** 이 뜨고, 에이전트의 `brief` 도 말한다. 그 PC 에서 한 줄 — 이 서버로 설치한 작업 레포 · 큐레이터 폴더 · 스킬 폴더를 전부 돈다 |
| 토큰 · `.mcp.json` | 그대로 |

```
node /tmp/cdp-install.mjs --update [--commit]          # 팀 서버 — 「시작하기」 의 [설치 한 줄]
ctx up ~/cdp/<레포> --update [--commit]                 # 개인 서버
```

`--commit` 이면 레포마다 바꾼 파일만 커밋한다. 팀원은 그 커밋을 pull. 새 스킬은 Claude Code 를 다시 켜야 읽힌다.

## 8. 여럿이 할 때

- **서버가 언제나 최신이다** — pull 이 없다. 동시에 `save` 해도 서버가 레포마다 줄을 세워 차례로 커밋한다.
- writer 의 기록은 서로 막지 않는다 — 같은 좌표를 둘이 건드려도 기록이 둘 남고 큐레이터가 같이 판정한다. 같은 id 만 `E_EXISTS`.
- 미러 push 는 서버가 한다 — 밀리면 `save` 경고 · 상태 표시줄 · `brief` 가 말하고, 푸는 것은 관리자다. 섹션 점유는 없다.
- 레포가 둘이면 한 답에 섞지 않는다. `match` 만 레포를 가로지른다.

## 9. 막혔을 때

먼저 — 에이전트에게 *"cdp 상태 봐줘"*(`brief` — 레포 상태 · 대기 · 미러 · 세팅 낡음 · 토큰 만료) · 화면의 「시작하기」 · 아래 상태 표시줄.

### 9.1 기록이 막힌다 — `save` 의 거절

| 답 | 할 일 |
|---|---|
| `E_FORBIDDEN` · `need: curate` | 섹션 · 등록부 · 문서 머리말을 고치려 했다 — 그 내용을 **기록 본문에** 쓰고 `work` 만 다시 |
| `save` 도구가 없다(도구 9) | viewer 다 — 관리자에게 writer 를 청한다 |
| `E_INPUT` `work.touches` | 좌표 0개 — §4.2. 정말 0개면 승인받고 `touchesEmpty` 에 사유 |
| `E_INPUT` 「어휘에 없는 좌표」 | 그 좌표를 `vocab` 에 같이 |
| `E_EXISTS` | 다른 id. 고치려던 것이면 정정 기록(§4.6) |
| `E_CHECK` | **이 save 가 만든** 오류(필드 · id · YAML · `status`) — `detail` 을 고쳐 다시. 원래 있던 오류는 경고로 온다 |
| `E_GIT` · `dirty` | 관리자에게 — 「트리 되돌리기」. 보낼 것은 그대로다 |

### 9.2 연결이 안 된다

| 증상 | 고침 |
|---|---|
| `/mcp` 에 `cdp` 가 없다 | `.mcp.json` 이 없다 — pull 또는 설치 한 줄(§2) |
| `cdp` 가 **failed** | `CDP_TOKEN` 이 비었거나 열려 있던 앱이다 — 새 터미널에서 `echo $CDP_TOKEN`(PowerShell `$env:CDP_TOKEN`) · Claude Code 를 앱째 재시작 · `curl http://<서버>:7374/healthz` |
| 로그인 401 · 도구 `E_AUTH` | 토큰 오타 · **만료(기본 90일)** · 폐기 — 관리자에게 새 토큰 |
| 「시작하기」 · `brief` 의 「토큰 만료 n일 남음」 | 관리자에게 재발급을 청한다 |
| 로그인은 되는데 레포가 없다 | 볼 수 있는 레포가 비었다 — 관리자에게 |
| `brief` 「이 연결의 기본 레포와 다르다」 | `.mcp.json` 과 `.claude/cdp.json` 이 갈렸다 — 원래 지식 레포의 설치 한 줄을 다시 |
| 새 판인데 화면이 옛것 | `Ctrl+Shift+R` |

### 9.3 토큰을 잃었다

복구가 아니라 **재발급**이다 — 관리자가 [재발급](옛것 폐기 + 새것) → 설치 한 줄을 다시 돌리면 묻고 둔다 → Claude Code 를 다시 켠다. 권한은 그대로다.
기기마다 토큰을 따로 받으면 하나를 잃어도 그것만 죽인다.

스킬을 못 부르면 — `.claude/skills/*/SKILL.md` 는 사람이 읽는 마크다운이다. 열어 붙여도 돈다. 기록을 남기는 길만은 서버 `save` 다.

## 부록. 스킬 · 도구 · 용어

**스킬** — 작업 레포의 `.claude/skills/`. 에이전트가 요청을 보고 고른다.

| 스킬 | 언제 |
|---|---|
| `cdp-work` | 테이블 · 화면 · API · 용어 · 코드값의 지금 상태를 알아야 하는 요청 — 검토 → 주입 → 수행 |
| `cdp-save` | 작업 끝 · 편입 · 문서 수정 지시 — 작업 기록 하나(writer) |
| `cdp-push` | *"푸시해"* — 사람이 부를 때만. 이 세션이 만진 코드를 커밋 · push. 기록은 안 만든다 |

**MCP 도구** — 역할에 없는 도구는 보이지 않는다. 읽기 아홉은 모두 · `save` 는 writer 이상 · `queue` · `forms` · `drift` 는 큐레이터.

| 도구 | 무엇 |
|---|---|
| `match` · `search` | 이름 · alias · 말 → 정본 좌표(`미등재` 면 어휘에 없다) · `match` 가 못 찾을 때의 폴백 |
| `where` · `section` | 좌표의 지금 — 어느 섹션 · 미반영 수 · 건드린 기록 / 섹션 + 미반영 + 건 정본 + 기준선 |
| `work` · `docs` | 작업 기록 본문과 큐레이션 상태 / 관리 문서 목록 · 원문 |
| `check` · `brief` · `repos` | 레포 검사 / 두 줄 요약 / 볼 수 있는 레포 |
| `save` | writer 는 작업 기록 하나(+ 어휘 · 첨부) |

**용어**

| 말 | 뜻 |
|---|---|
| 지식 레포 · 작업 레포 | `_vocab.md` · `_managed.md` 가 있는 지식만의 git 레포(서버가 쓴다) / 코드가 있는 레포 — 스킬 · 블록 · `.mcp.json` 이 들어간다 |
| 좌표 | `<타입>:<값>` — 대상마다 하나 · 두 층을 잇는다 |
| 작업 기록 · 관리 문서 · 섹션 · 정본 | `work/<id>.md`(사건 · 불변) · `docs/*.md`(상태) · 좌표 하나의 자리 · 한 사실이 적히는 유일한 섹션 |
| 대기열 · 반영 · 미반영 · 판정 | 아직 판정 안 된 기록(오래된 순) · 섹션에 들어갔다 · 아직 · 큐레이터의 반영 · 새 문서 · 기록으로 둠 |
| 기준선 | 섹션 안의 기계 추출 블록(코드 · DB 에서) |
| 어휘 · 등록부 · 서식 | `_vocab.md`(이름표 · alias) · `_managed.md`(좌표 패턴 → 문서) · 새 문서를 세우는 틀 |
| 미러 | 서버가 `save` 뒤 origin 에 push 하는 것. `queued` 는 정상 |
| 개인 서버 | 자기 PC 에 띄우는 같은 서버(`ctx up`) |
