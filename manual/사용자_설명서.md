# CDP 사용자 설명서

**판 v1.0 · 2026-10-07 · 대상: 작업 레포에서 Claude Code 로 일하고 작업 기록을 남기는 사람(writer) · 읽기만 하는 사람(viewer)**

CDP 설명서는 네 권이다. 맡은 일이 다르면 다른 권을 본다.

| 권 | 누가 | 무엇을 |
|---|---|---|
| **사용자 설명서 (이 문서)** | 개발자 · 기획자 · 운영자 등 **일반 사용자** | 작업 레포에서 에이전트로 일하고, 작업 기록을 남기고, 화면으로 읽는다 |
| [큐레이터 설명서](큐레이터_설명서.md) | 지식 레포 하나의 **관리 문서를 맡은 사람** | 쌓인 작업 기록을 판정해 관리 문서에 반영한다 |
| [서버 관리자 설명서](관리자_설명서.md) | **서버를 맡은 사람** | 서버를 세우고 · 사람과 토큰을 붙이고 · 지식 레포를 세운다 |
| [개발자 설명서](개발자_설명서.md) | **CDP 자체**를 고치는 사람 | 소스를 고치고 · 검증하고 · 릴리스한다 |

> 이 문서는 **하루 쓰는 법**을 다룬다. 폐쇄망에서는 물어볼 사람이 없다 — 이 문서가 그 사람을 대신한다.
>
> **명령의 `<…>` 는 자리표시자다.** 꺾쇠까지 통째로 실제 값으로 바꾼다 — `<서버>` 는 `cdp.example.com` 같은 서버 주소,
> `<레포>` 는 지식 레포 이름. 그대로 치면 셸이 `<` 를 리다이렉션으로 읽어 오류가 난다.

## 0. 시작하기 전에 — 무엇을 받아야 하나

서버 관리자에게 셋을 받는다.

| 받는 것 | 예 | 어디에 쓰나 |
|---|---|---|
| 서버 주소 | `http://<서버>:7374` | 설치 한 줄 · 브라우저 |
| 지식 레포 이름 | `alpha` | 레포 고르기 · 도구의 `repo` |
| **토큰 한 줄** | (원문 한 번만 보인다) | 화면 로그인 · Claude Code 가 서버에 붙을 때 |

**토큰은 받은 그 순간 한 번만 보인다.** 관리자도 다시 볼 수 없다 — 서버에는 해시만 남는다. 잃으면 새로 받는다(§10.4).
토큰에는 이름이 들어 있다 — 그 토큰으로 남긴 기록의 작성자(`author`)는 서버가 토큰에서 채운다.

역할도 같이 정해진다. **viewer** 는 읽기만, **writer** 는 작업 기록을 남긴다. 어느 쪽인지는 화면 왼쪽 아래 「내 계정」 에 보인다.

**서버가 없는 팀 · 혼자 쓰는 사람**은 자기 PC 에 개인 서버를 띄운다 — [서버 관리자 설명서 부록 D](관리자_설명서.md#부록-d-개인-서버).
화면과 도구가 똑같이 돈다.

설명서는 서버의 `/manual` 에 있다 — 토큰 없이 읽는다.

## 1. CDP 가 무엇인가

### 1.1 두 층

```
work/   작업 기록   무슨 일이 있었나 · 왜 그렇게 정했나     사건 · 고치지 않는다 · 쌓인다
docs/   관리 문서   대상이 지금 어떻게 생겼나               상태 · 정본 · 큐레이터가 고친다
```

| | `docs/` 관리 문서 | `work/` 작업 기록 |
|---|---|---|
| 답하는 질문 | **지금 어떤가** | **왜 그런가** |
| 고치나 | 고친다 — 큐레이터가 현재형으로 다시 쓴다 | **고치지 않는다** — 틀렸으면 정정 기록을 새로 쓴다 |
| 몇 개 | 대상 하나에 섹션 하나 | 작업 하나에 파일 하나 |
| 누가 쓰나 | 큐레이터 | writer (그리고 누구든 자기 작업은) |

6개월 뒤 누군가 *"이 컬럼 왜 이렇게 생겼지"* 를 물으면 관리 문서가 답하고, *"왜 그렇게 정했지"* 를 물으면 작업 기록이 답한다.

### 1.2 좌표

**좌표가 두 층을 잇는다.** 검색이 아니라 좌표로 찾는다. 이름은 사람마다 다르게 부르지만 좌표는 하나다.

```
<타입>:<값>        table:bk_loan_mst    screen:HRC043    code:HR130    issue:ISS-007
                   테이블정의서:bk_loan_mst      ← 타입을 관리 문서 이름으로 쓰는 레포도 있다
```

타입 목록은 **그 지식 레포의 `_vocab.md` 가 정한다.** 이 문서와 스킬의 예시에 나오는 `table:` · `screen:` 은 설명을 위한
것이지 정해진 이름이 아니다. 모르면 지어내지 말고 에이전트에게 맡긴다 — `match` 가 이름을 정본 좌표로 풀어 준다.

### 1.3 누가 무엇을 쓰나 — 역할 넷

| 역할 | 범위 | 하는 것 |
|---|---|---|
| **viewer** | 레포별 | 읽기 · 검색 · 에이전트에게 지금 상태를 묻기 |
| **writer** | 레포별 | + **작업 기록**을 남긴다(어휘 추가 · 첨부 포함) |
| **큐레이터** | **레포별** 권한 | + 쌓인 작업 기록을 판정해 **관리 문서에 반영**한다 · 새 문서 · 등록부 |
| **admin** | 서버 | + 사람 · 토큰 · 레포 세우기. admin 은 모든 레포의 큐레이터다 |

**writer 는 관리 문서를 쓰지 않는다.** 섹션이 틀렸거나 바꿀 것이 생기면 그 내용을 작업 기록에 쓴다 — 그 레포의 큐레이터가
기록을 보고 반영한다. 관리 문서에는 원천이 셋 있다 — 작업 기록(사건 · 결정) · 큐레이터의 판단(정본 · 현재형) ·
**기준선**(코드 · DB 에서 기계로 뽑은 블록). 사용자가 쓰는 것은 첫째뿐이다.

### 1.4 미반영 — 늦은 반영이 정보를 잃지 않는 까닭

기록을 남긴 뒤 큐레이터가 반영하기까지 시간이 걸린다. 그 사이 섹션만 읽으면 옛것이다. 그래서 **섹션을 내보내는 모든
자리(도구 · 화면)가 그 섹션의 미반영 기록을 같이 낸다.** 섹션은 큐레이터가 반영한 데까지만 지금이고, 그 뒤의 기록까지가 지금이다.
읽는 법은 §7.

### 1.5 쓰는 길은 하나 — 서버 `save`

기록은 언제나 서버의 `save` 한 번으로 남는다 — 서버가 검사하고, 한 커밋으로 남기고, origin 에 미러한다.
**지식 레포를 clone 해서 고치고 커밋 · push 하지 않는다.** 화면에도 편집기가 없다. clone 은 읽기용이다.

## 2. 처음 한 번 — 연결

### 2.1 작업 레포를 등록하고 설치 한 줄을 받는다

작업 레포(코드가 있는 레포)마다 한 번이다. 이미 팀의 누군가 설치해 커밋해 두었으면 2.4 로 간다.

1. 브라우저로 `http://<서버>:7374` → [로그인] → 토큰 한 칸.
2. 왼쪽 메뉴 **레포 관리 › 연결된 작업 레포** → 맨 아래 「등록」 에 작업 레포 이름 · 담당자 · 메모(writer 이상).
   등록은 관문이 아니라 **장부**다 — 어느 작업 레포가 어느 판의 에이전트 세팅을 들고 있나를 나중에 알기 위한 것.
3. 그 행의 **[설치 방법]** — 서버 주소 · 레포 · 등록 id 가 채워진 한 줄이 있다. PowerShell · 명령 프롬프트 · macOS/Linux 탭에서 고른다.

```
curl.exe -fsSLo "$env:TEMP\cdp-install.mjs" http://<서버>:7374/install.mjs; if ($?) { node "$env:TEMP\cdp-install.mjs" --repo <레포> --workrepo <id> . }
```

**작업 레포 폴더에서** 붙여넣는다. 설치기는 임시 폴더에 받는다 — 작업 레포에는 CDP 파일만 들어간다. Node 20 이상이 있어야 한다.

### 2.2 토큰을 물으면 붙여넣는다

이 PC 에서 처음일 때만 묻는다. 화면에 안 보이는 입력이다. 설치기가 **그 자리에서 서버에 확인하고**(`확인했습니다 — <이름> (writer)`)
이 PC 에 둘지 묻는다.

```
Windows         사용자 환경변수 CDP_TOKEN                          (관리자 권한 필요 없음)
macOS · Linux   ~/.config/cdp/token (600) + ~/.zshrc 또는 ~/.bashrc 에 그것을 읽는 한 줄
```

이미 `CDP_TOKEN` 이 있으면 묻지 않고 확인만 한다. 통하지 않으면(만료 · 폐기) 새로 묻는다.
**왜 두나** — Claude Code 가 서버에 붙을 때마다 쓴다. `.mcp.json` 은 커밋돼 팀이 같이 쓰는 파일이라 원문 대신
`Bearer ${CDP_TOKEN}` 자리만 있고, Claude Code 가 시작할 때 환경변수로 채운다.

### 2.3 무엇이 들어오나

설치기가 무엇이 바뀔지 먼저 보여 주고 묻는다. 끝나면 서버의 작업 레포 대장에 보고한다.

```
.mcp.json               cdp 항목 — 서버 주소 · Authorization: Bearer ${CDP_TOKEN}   (다른 MCP 서버는 그대로)
.claude/cdp.json        { "server": "http://<서버>:7374", "repo": "<레포>" }
.claude/skills/cdp-*    스킬 셋 — cdp-work · cdp-save · cdp-push
CLAUDE.md               <!-- cdp:begin --> … <!-- cdp:end --> 블록                (직접 쓴 내용은 그대로)
```

남의 것을 지우지 않는다 — `cdp-` 가 아닌 스킬, `CLAUDE.md` 의 나머지, `.mcp.json` 의 다른 서버는 그대로다.
처음 설치한 사람은 `git add .mcp.json .claude CLAUDE.md` 후 커밋한다. `.gitignore` 가 `.claude/*` 를 통째로 막고 있으면
설치기가 알려 준다 — `!.claude/skills/` 한 줄을 넣어야 팀이 스킬을 받는다.

### 2.4 팀원 — pull 뒤 같은 한 줄을 한 번

커밋된 세팅은 pull 로 온다. 토큰은 사람마다 다르므로 **같은 한 줄을 각자 한 번** 돌린다 — 설치할 것은 없고(**이미 최신입니다**)
토큰을 묻고 두고 대장에 보고한다.

**Node 가 없거나 내려받기가 막힌 망**이면 같은 자리의 「꾸러미 zip」 — 아무 데나 풀고 그 안에서 `node install.mjs <작업 레포 경로>`
(하는 일은 같다). Node 도 없으면 꾸러미 안 `설치.md` 대로 손으로 옮긴다.

### 2.5 Claude Code 를 완전히 끄고 다시 켠다

환경변수와 `.mcp.json` 은 시작할 때 읽는다 — VS Code · 데스크톱 앱 안의 Claude Code 면 **그 앱을** 다시 켠다.

**확인** — Claude Code 에서 `/mcp` → `cdp` 가 **connected** · 도구 **10**건. 에이전트에게 *"cdp 브리핑 보여줘"* 라고 하면
`brief` 두 줄(절차 · 레포 상태 · 큐레이션 대기)이 나온다.

### 2.6 점검표

| ☐ | |
|---|---|
| ☐ | `/mcp` 에 `cdp` connected · 도구 10 |
| ☐ | 새 터미널에서 `CDP_TOKEN` 이 보인다 |
| ☐ | 브라우저 로그인이 되고 왼쪽 메뉴에 그 레포가 있다 |
| ☐ | `.claude/cdp.json` 이 `{ server, repo }` 이고 커밋됐다 · `.claude/skills/` 가 `.gitignore` 에 막히지 않았다 |
| ☐ | 화면 **레포 관리 › 연결된 작업 레포** 의 그 행이 `최신` |

## 3. 하루 흐름

```
작업 요청  ─┐
            │  ① 검토      무엇을 바꿀 것인가.  4~6줄
            │  ② 주입      그 대상의 지금 — 섹션 + 미반영 기록 + 건 정본 + 기준선
            │  ③ 수행      그것을 근거로 한다
            ─┘   ← 여기까지가 cdp-work 하나

작업이 끝나면 → cdp-save   작업 기록 하나 → 서버 save → 「큐레이션 대기 n번째」
              → 큐레이터가 판정 · 반영 → 섹션에 들어간다(그 전까지는 섹션 옆에 「미반영」 으로)
```

| 언제 | 무엇을 |
|---|---|
| 아침 | 화면을 연다. 작업 기록 목록의 「대기」 · 아래 상태 표시줄의 「대기 n」 으로 레포가 어떤지 본다 |
| 작업 요청 | 에이전트가 `cdp-work` 로 처리한다. `CLAUDE.md` 블록에 적혀 있어 시키지 않아도 된다 |
| 작업 끝 | `cdp-save` — 【좌표 판정】 을 보고 승인한다. 서버가 커밋 · 미러까지 한다. **push 할 것이 없다** |
| 그 뒤 | 기록은 큐레이션 대기열에 선다. 반영 전까지 그 좌표를 읽는 사람 · 에이전트에게 기록이 같이 보인다 |

**요청 하나가 작업 하나가 아니다.** 요청 셋이 한 작업이면 기록은 하나다. 요청마다 기록하면 이력이 파편화되고,
큐레이터는 같은 좌표의 조각 여럿을 맞춰야 한다.

기록이 생기는 길은 셋이다 — 어느 길이든 `cdp-save` 하나다.

| 어떤 일이었나 | 무엇이 기록이 되나 |
|---|---|
| 이 세션에서 작업했다 | 무엇을 · 왜 · 어떤 제약 때문에 · 결과 값 |
| 이미 쓴 문서가 있다(회의록 · 검토서 · 설계 메모) | **편입** — 원문을 보존한 채 들인다(§6.4) |
| 작업은 없고 **문서를 고치라는 지시**다 | **지시 자체**가 기록의 본문이다(§6.5) — 반영은 큐레이터가 한다 |

셋째가 중요하다. 지시를 기록으로 남기지 않으면 *"왜 이렇게 적혀 있지"* 에 답할 것이 없다 — 큐레이터도 반영할 근거가 없다.

## 4. 작업 요청 — `cdp-work`

### 4.1 왜 순서가 이런가

**요청이 먼저다.** 세션이 시작되자마자 맥락을 넣으면 두 가지가 어긋난다. 좌표는 "이 작업이 바꾸는 대상"인데 무엇을
바꿀지 모르면 뽑을 것이 없고, 정본 문서 다섯 개가 먼저 들어오면 요청을 그 다섯의 틀로 읽어 여섯 번째를 못 본다.
**주입은 답을 좁히는 행위다** — 무엇을 좁혀야 하는지 알기 전에 좁히면 엉뚱한 곳을 좁힌다.

### 4.2 ① 검토 — 4~6줄

```
【검토】
요청  HRC043 면접심사의견등록에 심사위원 연대서명 출력물을 추가한다

대상
  screen:HRC043   변경   출력물 2종 추가
  code:HR130      ?      업무구분 코드를 쓸지 미정
  screen:HRC031   참조   첨부를 읽어 오지만 안 바뀐다 → 좌표 아님

주입  2건 — 좌표마다 섹션 하나와 그 미반영 기록
  screen:HRC043   docs/화면설계서.md ## HRC043 · 22줄 · 미반영 1건
  code:HR130      docs/코드정의서.md ## HR130 · 9줄 · 반영 최신
이미 정해진 것  2026-0821-면접심사의견-개편 — 같은 화면의 출력물을 정했다
```

| 규칙 | 왜 |
|---|---|
| **이름표만 본다**(`match` · `where` · `search`) | 어휘 · 등록부는 의견이 없다. 관리 문서와 작업 기록은 의견을 담아 요청을 그 틀로 읽게 한다 |
| **좌표 아닌 것도 적는다** | 무엇을 왜 제외했는지가 판정의 근거다 |
| **멈추지 않는다** | 검토는 감사 흔적이지 승인 관문이 아니다. 판정이 틀렸으면 답에서 드러나고 그때 고친다 |
| **이미 정해진 것을 본다** | `where` 의 작업 기록 id 는 `날짜-주제` 라 id 만으로 주제가 읽힌다. 같은 요청이 두 번 와 처음부터 다시 정한 일이 있었다 |

**멈추는 경우는 하나뿐이다** — *"채용 쪽 정리해 줘"* 처럼 요청 자체가 무엇을 원하는지 모를 때.

### 4.3 ② 주입 — `section` 한 번

검토가 좌표 이름을 늘어놓으면 *"그 좌표에 관한 것이 전부 들어왔다"* 고 읽기 쉬운데, 들어오는 것은 **그 좌표의 섹션 하나와
그 섹션의 미반영 기록**이다.

| 받는 것 | 뜻 |
|---|---|
| 섹션 본문 | 큐레이터가 쓴 정본 서술 — **반영한 데까지의 지금** |
| 기준선 | 코드 · DB 에서 기계로 뽑은 블록(어디서 · 언제 뽑았나가 붙는다) — 컬럼 · 타입 같은 사실 값 |
| 미반영 기록 | 섹션 뒤에 그 좌표를 건드린 기록의 목록과 본문 — §7 |
| 건 정본 | 본문이 `` `좌표` `` 로 건 다른 섹션 — 한 단계 · 다섯까지. 그 사실의 정본은 거기다 |
| 상태 | `ok`(섹션이 지금) · `pending`(미반영이 있다) · `missing`(섹션이 없다) |

안 들어오는 것 — 그 문서의 다른 섹션 · 이미 반영된 옛 기록. 더 보고 싶으면 에이전트에게 말하거나 화면에서 `Ctrl+K` 에 좌표를 붙여 넣는다.

**빈 섹션을 조용히 쓰지 않는다.** 섹션이 사실상 비었으면 에이전트가 그렇게 말해야 한다 — 밝히지 않으면 *"문서에 정의가 없다"* 가
*"제약이 없다"* 로 바뀐다. 확신 있게 틀린 답이다. 코드나 담당자를 본다.

### 4.4 검토 출력을 고치는 말

| 보이는 것 | 이렇게 말한다 |
|---|---|
| 대상에 없는 것이 있다 | *"HRC031 도 바뀌어"* |
| 대상에 있으면 안 되는 것 | *"HR130 은 안 건드려"* |
| 주입이 과하다 | *"맥락 필요 없어, 그냥 해"* |

`?` 는 에이전트가 확신이 없다는 뜻이다 — 거기가 먼저 볼 자리다. `(미등재)` 는 그 이름이 어휘에 없다는 뜻이다.
**지금 다른 좌표로 바꾸지 마라.** 기록할 때 등재하면 된다(§5.4).

### 4.5 언제 건너뛰나

| 상황 | |
|---|---|
| *"이 정규식 왜 안 되지"* · *"이 함수 이름 바꿔줘"* | `cdp-work` 를 안 부른다. 지식 레포와 무관하다 |
| 이어지는 대화(같은 주제) | 다시 안 부른다. 이미 주입한 맥락을 쓴다 |
| **내가 그 도메인의 리더이고 내 로컬이 최신** | 주입은 건너뛰어도 된다. 다만 **기록은 남긴다** — 안 남기면 그 결정이 내 머리와 로컬 코드에만 남는다 |

### 4.6 도구가 없을 때

`/mcp` 에 `cdp` 가 없으면 에이전트는 **기억으로 답하지 않고 그렇게 말해야 한다.** 설치 한 줄을 다시 돌리고(§2) Claude Code 를
다시 켠다. 그동안 사람은 화면에서 같은 것을 읽는다 — 좌표를 `Ctrl+K` 에 붙이면 그 섹션과 미반영 기록이 보인다.

## 5. 좌표 — 바꾼 것만

### 5.1 무엇이 좌표인가

| 이 작업이 그 대상을… | 좌표 |
|---|:--:|
| 신설했다 · 변경했다(컬럼 추가 · 규격 변경 · 상태값 추가) · 삭제 · 폐기했다 | **O** |
| (편입 · 지시) 신설 · 변경 · 폐기하기로 **정했다** | **O** |
| 용어 · 개념을 **정의했다 · 처음 도입했다** | **O** |
| 답이 안 난 것을 이슈로 **제기했다** | **O** |
| 참조했다 · 호출했다 · 언급했다 · 그것을 쓰는 다른 것을 만들었다 | **X** |
| 「검토하기로 했다」 | **X** — 아직 안 정해졌다. 제기로 |

판정 기준은 하나다 — **6개월 뒤 그 대상을 맡은 사람이 이 기록을 찾아야 하는가.**
*"주제인가?"* 는 답이 갈리지만 *"바꿨는가?"* 는 결판나고, diff 로 확인된다.

### 5.2 예시

| 작업 | 좌표 | 아닌 것 |
|---|---|---|
| `bk_member_mst` 에 컬럼 2개 추가 | `table:bk_member_mst` | |
| HRC043 을 현황 · 작성 화면으로 분리 | `screen:HRC043` | `module:grid-common` (쓰기만 함) |
| 코드그룹 HR130 신설 | `code:HR130` | |
| HRA021 에서 `wrk_tp_cd` 로 트리 묶기 | `screen:HRA021` | **`table:bk_member_mst`** — 읽기만 한다 |
| 임시저장에 작성일을 안 남기기로 | `screen:HRB020` · **`table:bk_review_list`** | — 컬럼이 언제 채워지는지가 바뀌었다 |
| 통합시험 일정 확정 | **없음** — 사유를 적는다(`touchesEmpty`) | 아무 대상도 안 바꿨다 |
| 알림 문구를 사용자 말로 | `screen:HRA021` | 조건은 그대로다. 문구도 그 화면의 정의다 |

"그 테이블을 쓰는 화면 작업" 은 대개 테이블이 좌표가 아니다. 반대로 **컬럼이 언제 채워지는지가 바뀌었으면** 그 컬럼을 맡은
사람이 알아야 하므로 좌표다.

### 5.3 빠진 좌표는 조용하다

**억지 좌표는 없는 좌표보다 나쁘다** — 그 좌표를 찾는 사람에게 무관한 기록을 내민다. 반대로 **빠진 좌표는 조용하다** —
서버는 0개만 막고, 하나라도 있으면 나머지가 빠져도 통과한다. 큐레이터도 `touches` 로 반영할 자리를 찾는다.
빠진 것을 잡는 것은 【좌표 판정】 을 승인하는 사람뿐이다 — **뺀 것** 줄을 꼭 읽는다.

본문에 `` `type:값` `` 으로 쓴 좌표가 `touches` 에 없으면 검사가 경고한다(「본문에만 있는 좌표」). 참조만 한 것이면 그대로 두고,
바꾸거나 제기한 것이면 넣는다.

### 5.4 미등재 좌표 · 새 타입

어휘에 없는 좌표를 쓰면 `save` 가 막힌다. 에이전트가 그 좌표를 `vocab` 에 같이 보낸다 — 관리자를 기다리지 않는다.

```markdown
- `code:HR130` — 외부인원 업무구분
  aliases: 업무구분코드, HR130
```

**`aliases` 가 이 파일의 값어치다.** 그 작업에서 실제로 쓴 표현을 그대로 넣는다 — 나중에 지어낸 별칭은 아무도 안 쓴다.
어휘는 **더하기만** 한다. 지우는 길은 없다(폐기는 `deprecated` 표시 — 큐레이터 · 관리자에게).

- **새 타입**이면 서버가 `_vocab.md` 에 타입 절을 만든다(경고). 오타로 만들면 지우는 연산이 없으니 【좌표 판정】 의 「새 타입」 을 확인한다.
- **관리 문서가 없는 타입**(`where` 가 `registry: null`)도 정상이다 — 그 좌표의 원천은 작업 기록 자체다. 같은 타입 좌표가 여럿으로
  자라면 기록 끝에 「큐레이터에게 — <타입> 좌표 n개를 받을 관리 문서가 없다」 한 줄을 남긴다. 문서는 큐레이터가 서식에서 세운다.

## 6. 기록 남기기 — `cdp-save`

### 6.1 단계

```
① 길       이 세션의 작업 · 밖에서 온 문서(편입) · 문서를 고치라는 지시
② 좌표 판정  이 기록이 바꾼 · 정한 · 정의한 · 제기한 대상만 (§5)
③ 기록     기록은 홀로 선다 — 값 · 표 · 결정 · 제약은 본문에
④ 승인     【좌표 판정】 과 기록을 보이고 승인을 받는다 — 필수
⑤ save     work · vocab · assets 한 번. 서버가 검사 · 커밋 · 미러한다
⑥ 끝 보고   커밋 · 미러 · 큐레이션 대기 n번째
```

**④ 는 건너뛰지 않는다.** 기록은 커밋되면 고칠 수 없고(정정 기록만 된다), 서버 검사는 좌표를 **빠뜨린** 것을 모른다.

```
【좌표 판정】 기록 2026-0908-출장보고-사진첨부 · 길: 이 세션의 작업
  ―― 넣는다 ――
  screen:BZD020             변경   사진 첨부 영역 신설 · 입력 영역을 맨 위로
  table:pj_trip_photo_list  신설   사진 저장 테이블 (미등재 → 등재 · 이름 제안)
  issue:ISS-015             제기   차량 이용 여부를 무엇으로 가르나 — 회신 대기 (미등재 → 등재)
  ―― 뺀다 ――
  screen:BZD012             참조   출장등록에서 넘어오지만 안 바뀐다
【기록】 제목 · date 14:30 · 본문 요지(첨부 자리 · 대상자 · 여러 장 · 남은 것 1) · 첨부 1
승인하시면 남깁니다. 고칠 좌표가 있으면 알려 주세요.
```

승인 뒤 고친 것은 다시 묻지 않고 고친 대로 보낸다.

### 6.2 기록은 홀로 선다

큐레이터는 **이 기록만 보고** 섹션에 반영하고, 반영 전까지 그 좌표를 읽는 사람은 섹션 옆에 실린 **이 본문**을 본다.
둘 다 이 세션의 기억 · DB · 코드에 닿지 못한다.

| 본문에 쓴다 | 쓰지 않는다 |
|---|---|
| **값** — 컬럼 · 타입 · 길이 · 코드값 · 규격 · 기본값 · 한도 | 「섹션 X 참조」 · 「DB 에서 확인」 · 「코드를 보면 안다」 |
| **표** — 정한 값의 표 그대로 | 「기본값 표를 정했다」 (값 없는 사건) |
| **결정과 제약** — 무엇을 왜 · 어떤 제약 때문에 · 버린 안과 버린 이유 | 경위만 길게 · 누가 언제 물었나만 |
| **예외 · 남은 것** — 회신 대기 · 열린 물음(따로 한 절) | |

실제로 이렇게 샜다 — 결제수단별 기본값 표를 정한 기록이 「기본값이 여기서 정해진다」 만 남겼고, 같은 요청이 다시 왔을 때
이미 정한 값을 처음부터 다시 정했다.

- **큰 추출물은 첨부다** — DDL 전문 · 덤프 · 긴 목록 · 캡처 · 구성도는 본문을 채우지 않는다. 바뀐 값의 요지는 본문 표로, 전문은 첨부로(§6.6).
  DB · 코드에서 정기적으로 기계로 뽑는 것이면 그것은 기준선의 일이다 — 큐레이터에게.
- **이유가 안 보이면 한 번 묻는다** — 6개월 뒤 이 결정을 뒤집으려는 사람은 *"무엇을 했는지"* 가 아니라 *"어떤 제약 때문에"* 를 찾는다.

### 6.3 필드

| `work.` | | |
|---|---|---|
| `id` | 필수 | `YYYY-MMDD-slug` — 날짜와 짧은 주제. id 만으로 주제가 읽혀야 한다 |
| `title` | 필수 | 무엇에 관한 기록인지 보이게 |
| `date` | 필수 | `YYYY-MM-DD HH:MM` — **그 일이 있었던 때. 시각까지.** 하루에 같은 좌표를 두 번 건드려도 선후가 결판난다 |
| `touches` | 필수 | §5 의 결과. 0개면 `touchesEmpty` 에 사유 — 없으면 서버가 거절한다 |
| `source` | 편입만 | 원문이 어디서 왔나 — 되짚을 유일한 길 |
| `supersedes` | | **이 기록 자체가 틀렸을 때만**(§6.7) |
| `tags` | | 자유. 단 `curate` · `baseline` · `registry` · `docs-prune` · `derive` 는 큐레이터 몫이다 |
| `body` | | 마크다운 — 홀로 서는 본문 |

**`author` 는 보내지 않는다** — 서버가 토큰에서 채운다. 원문 작성자 · 지시한 사람은 본문에 적는다.
**`status` 필드는 없다** — 작업 기록은 작업의 완료에서 나온다(적으면 검사가 막는다).

### 6.4 편입 — 밖에서 온 문서

*"이 회의록 레포에 넣어 줘"* · *"예전 검토서를 옮겨 줘"*. 뼈대는 같고 **날짜와 좌표**가 다르다.

- **날짜는 사건의 날.** 오늘로 적으면 반년 전 회의록이 어제 결정을 덮는다.
- **언급은 좌표가 아니다.** 화면 이름이 열다섯 개 나와도 그 회의가 바꾼 것은 둘일 수 있다.
- **본문을 다시 쓰지 않는다.** 회의록의 반대 의견이 6개월 뒤 유일한 단서다. 프론트매터만 씌운다.
- `source` 에 출처를 적는다. 날짜가 옛것이라 대기열의 앞쪽에 선다.

md 파일이 **수십 · 수백 개**라면 스킬이 아니라 관리자의 `ctx import-dir` 가 맞다.

### 6.5 문서 수정 지시 — 지시가 곧 본문이다

*"화면설계서 BZD020 첨부 용량을 10MB 로 고쳐 줘"* — 코드 없이 문서만 바꾸라는 지시. writer 는 섹션을 직접 고치지 않는다 —
**고칠 것을 기록한다.**

```markdown
## 지시
> 사진 첨부 용량은 10MB 로 해 줘. WAS 업로드 상한이 그거라서 20MB 로 적어 놔도 어차피 안 올라가.
(지시한 사람 · 날짜)

## 바꿀 것
docs/화면설계서.md ## BZD020 — 첨부 대목의 용량 20MB → 10MB

## 확인한 것
지금 섹션은 20MB(2026-0822 기록이 정함). 그 기록의 근거는 「넉넉히」 뿐 — 지시와 어긋나는 제약은 없다.
```

**지시를 요약하지 않는다.** "20MB 로 적어 놔도 어차피 안 올라가" 가 제약의 출처다. 지시가 지금 섹션 · 다른 기록과 어긋나면
에이전트가 정한 이유를 인용해 되묻는다. 끝 보고는 「문서를 고쳤다」 가 아니라 **「고칠 것을 기록했다 · 큐레이터가 반영한다 ·
그동안 섹션을 읽는 자리에 이 기록이 같이 실린다」** 다.

### 6.6 그림 · 첨부

화면 캡처 · 구성도 · pdf · HTML 시각 자료를 기록에 넣는다. 레포를 받아 커밋할 필요가 없다 — 에이전트가 셸에서 파일을 올리고
(바이트는 도구 인자로 가지 않는다) 받은 `ref` 를 `save` 에 싣는다.

```bash
curl -sS -H "Authorization: Bearer $CDP_TOKEN" --data-binary @구성도.png "http://<서버>:7374/api/<레포>/assets"
```

- 서버가 `work/assets/<기록 id>/<이름>` 에 **기록과 한 커밋**으로 넣는다. 본문에는 `![구성도](assets/<id>/구성도.png)`
  (공백이 있으면 `(<assets/<id>/시스템 개요.png>)`).
- png · jpg · gif · webp · pdf · html, 하나에 10 MB(svg 는 받지 않는다 · 종류는 내용으로 가린다). writer 이상이 올린다.
  올린 것은 24시간 안에 save 에 실어야 한다 — 지나면 다시 올린다.
- **HTML 시각 자료** — 에이전트가 구성도 · 시퀀스를 한 장짜리 HTML 로 내놓았으면 그대로 첨부하고 본문에는 링크로 건다
  `[연계 구성도](assets/<id>/연계_구성도.html)`. 화면이 문서 머리에 「본문 | 자료」 탭을 세우고 격리된 틀로 연다.
  **검색 · 큐레이션은 md 만 본다** — 요지(무엇을 정했나 · 수치 · 확인 목록)는 본문에 md 로 같이 적는다.

### 6.7 정정 — 고치지 않고 대신한다

기록은 불변이다 — 고치거나 지우는 길이 없다. 틀렸으면 `supersedes: <틀린 기록 id>` 를 단 새 기록을 낸다.
**좌표 누락도 오기재다** — `id` 는 `<원 id>-좌표정정` · `date` 는 **원 기록의 날** · `touches` 는 빠졌던 좌표만 · 본문은 무엇이 왜
빠졌나와 원 기록 링크.

같은 좌표를 나중에 또 바꾼 것은 `supersedes` 가 아니다 — 날짜와 `touches` 로 계산된다.

### 6.8 결정이 안 났으면 — 여기 쓰지 않는다

**`미결` · `제안` · `진행중` 이라는 상태는 없다.** 결정을 기다리는 것은 기록할 사실이 아니라 아젠다다.

- **판단이 끝난 부분과 안 끝난 부분을 가른다.** 정해진 것은 기록이고, 남은 것이 남의 회신뿐이면 그 열린 물음만 본문 끝 「남은 것」 에.
- **열린 물음은 제기한다** — 레포에 이슈를 받는 타입이 있으면 새 이슈 좌표를 등재하고 `touches` 에 넣는다(제기했다).
  큐레이터가 대장에 올린다.
- 「이렇게 하면 어떨까?」 만 있고 아무것도 정해지지 않았으면 기록하지 않는다.

### 6.9 save 의 답 — 끝 보고

| 응답 | 이렇게 말한다 |
|---|---|
| `mirror: ok` | 서버에 커밋했고(`<commit>`) origin 미러에도 갔다 |
| `mirror: queued` | 서버에 커밋했다 · 미러는 가는 중이다 |
| `mirror: lag` · `diverged` | 서버에 커밋했다 · 미러는 못 갔다 — 사유를 그대로 전한다. 고치는 것은 관리자다 |
| `mirror: off` | 서버에 커밋했다 · 이 레포는 원격이 없다 |

어느 경우든 **기록은 서버 트리에 있다.** 그리고 **큐레이션 대기** — 대기열은 오래된 순이라 오늘 기록은 맨 뒤다 —
「큐레이션 대기 n번째」. **push 할 것이 없다** — 서버의 일이다.

거절은 §10.2 의 표.

## 7. 미반영 읽는 법

### 7.1 무엇인가

**섹션은 큐레이터가 반영한 데까지만 지금이다.** 그 뒤에 같은 좌표를 건드린 기록 — 아직 큐레이터가 판정하지 않은 기록 — 이
**미반영**이다. CDP 는 그 기록을 감추지 않고 **섹션과 같이 낸다** — 화면도 도구도.

### 7.2 화면에서

| 자리 | 보이는 것 |
|---|---|
| 관리 문서의 섹션 제목 | **「미반영 n」** 칩 — 누르면 제목 아래에 그 기록들이 펴진다(날짜 · 제목 · 작성자 · 첫 문단 · 「기록 열기」) |
| 작업 기록 머리 | 큐레이션 상태 한 줄 — **대기** · **반영됨 → 좌표** · **기록으로 둠(사유)** |
| 작업 기록 목록 | 줄마다 상태 칩 · 거름 「전체 · 대기 · 내 기록」(주소 `…/w?only=pending` · `…/w?only=mine`) |
| 아래 상태 표시줄 · 메뉴 배지 | 큐레이션 대기 n · 미반영 섹션 n |

색은 하나다 — 대기 · 미반영은 보라. 반영됨 · 기록으로 둠은 조용한 무채색이다. 초록은 없다 — 정상은 조용하다.

### 7.3 에이전트의 답에서

`section` 이 미반영 기록을 실어 오면 `cdp-work` 는 답에 적는다.

```
⚠ screen:HRC043 섹션 뒤에 미반영 기록 1건 — 2026-0905-HRC043-출력물(dev.b): 출력물을 PDF 한 종으로 고정.
  아래 설계는 섹션과 그 기록을 합친 상태가 기준이다. 큐레이터가 반영하면 섹션에 들어간다.
```

### 7.4 읽는 규칙

| 규칙 | |
|---|---|
| **섹션과 기록이 어긋나면 늦은 기록이 지금이다** | 섹션은 그 기록 전의 상태를 말한다 |
| **좌표마다 따로 본다** | 한 기록이 좌표 셋을 건드렸어도 좌표마다 사정이 다르다. 「이 문서는 낡았다」 는 말은 반드시 절반이 틀린다 |
| **「후속이 있다」 를 「뒤집혔다」 로 읽지 않는다** | 기록 본문이 말한 것만 사실이다 |
| **섹션이 없는데 미반영이 있으면** 그 기록이 유일한 근거다 | 관리 문서 자리가 아직 없다 — 큐레이터가 세운다 |
| **「n건 중 일부만 실었다」 가 붙으면** 나머지가 있다 | 에이전트에게 그 좌표를 한 번 더 부르게 하거나 화면에서 본다 |

### 7.5 미반영이 사라지는 때

큐레이터가 그 기록을 판정하면 사라진다 — **반영**(섹션에 들어갔다 · 섹션 끝 `**경과**` 에 그 기록 한 줄) · **새 문서**(서식에서
문서를 세워 들였다) · **기록으로 둠**(옮길 사실이 없다 — 기록이 원천으로 남는다 · 사유가 기록 머리에 뜬다).
대기가 14일을 넘으면 큐레이터 · 관리자에게 경고가 간다. 내 기록이 오래 대기에 있으면 그 레포의 큐레이터에게 말한다.

## 8. 화면

### 8.1 들어가기

브라우저로 `http://<서버>:7374` → **소개 페이지** → [로그인] → **토큰 한 칸**(아이디 칸이 없다 — 토큰이 아이디를 들고 있다).
실패 메시지는 "토큰을 확인하세요" 하나다(만료 · 폐기 · 오타를 가려 주지 않는다 — 의도다). 로그인하면 볼 수 있는 레포의 문서가 열린다
(관리자는 서버 현황).
로그아웃은 쿠키만 지운다 — 토큰은 그대로 쓸 수 있다.

### 8.2 왼쪽 메뉴 — 하나다

```
┌ C CDP                 « ┐   접기 · 펴기 (Ctrl+B · Mac ⌘B) — 브라우저마다 기억한다
│ [alpha ▾]              │   레포 고르기 — 볼 수 있는 레포 · 쓰기/읽기 표시
│ 지식                    │   문서 · 작업 기록(대기 배지) · 「좌표 · 그래프」
│ 큐레이션   큐레이터       │   대기열 · 이력 · 서식집          ← 그 레포의 큐레이터에게만
│ 레포 관리               │   현황 · 관리 문서 · 연결된 작업 레포
│ 서버       admin        │   현황 · 지식 레포 · 작업 레포 대장 · 사용자 · 토큰 · 감사 · 서버 설정
│ 설명서 · 내 계정         │
└────────────────────────┘
```

**권한 밖의 메뉴는 보이지 않는다** — 회색으로도 없다. 막는 것은 서버다(권한 밖 주소는 그 레포 첫 화면으로 돌아간다).
창이 760px 보다 좁으면 메뉴가 숨고 위의 ☰ 로 연다. 위 줄은 지금 있는 곳(`alpha › 지식 › 문서`) · 검색 · 검증이다.

**내 계정** — 이름 · 역할 · 이 레포에서 할 수 있는 것(읽기 · 기록 save · 큐레이션 · 서버 관리) · **토큰 만료 D-n** · 판 · 테마(자동 · 밝게 ·
어둡게) · 단축키 · 로그아웃.

### 8.3 문서 — 왼쪽에서 찾고 오른쪽에서 읽는다

**왼쪽은 한 번에 하나만 한다** — 고르는 중이면 목록, 따라가는 중이면 **뻗어나가기**(`\` 로 바꾼다). 「문서」 는 관리 문서 목록,
「작업 기록」 은 작업 기록 목록이다(주소가 정한다 — `/r/<레포>/` · `/r/<레포>/w`).

**뻗어나가기** — 고른 것에서 다음 한 단계만 펼친다. 작업 기록 → 관리 문서 · 좌표, 좌표 → 관리 문서 · 작업 기록, 관리 문서 → 섹션.
열 하나가 한 단계라 지나온 길이 왼쪽에 남는다. 같은 것이 여러 열에 다시 나올 수 있다(트리가 아니라 그래프다).
**정렬은 늘 같다** — 좌표는 카테고리순 + 이름순, 작업 기록은 날짜순, 관리 문서와 섹션은 섹션 순서. 상태로 정렬하지 않는다.

**본문** — 오른쪽에 세로 목차가 선다. 섹션 제목의 「미반영 n」(§7.2). 섹션 끝 `**경과**` 줄이 그 섹션을 만든 기록으로 이어진다.
본문의 좌표는 누르면 따라간다.

- **그림** — `![설명](경로)` 의 경로는 그 문서가 있는 폴더 기준이다. 파일이 없으면 「그림을 찾을 수 없음 · <경로>」 가 나온다.
- **내려받기** — 문서 아래 「내려받기 (.md)」 가 그 파일을 그대로 받는다. 레포 전체 묶음(관리 문서 · 작업 기록 zip)은 문서를 고르기 전 첫 화면에.
- **문서 사이를 오가기** — 본문 위 한 줄. 「‹ 이전 <제목>」 · ▾ 최근 10건 · **열린 문서 탭**(찾기 · 검색 · 본문 링크로 연 문서는 탭이 하나 더 ·
  8개까지 · 📌 고정). 문서가 주소에 있다(`…/d/<문서>`) — 새로고침 · 주소 공유 · 브라우저 뒤로 · `Alt+←` 가 그 문서다.

### 8.4 좌표 · 그래프

왼쪽 레일에 타입 묶음 → 좌표. 가운데는 좌표망이다 — **이어진 좌표만** 그린다(고립 좌표는 「고립 +N」). 노드 크기는 작업 건수다.
노드를 누르면 1단계로 이어진 것만 남고, 아래 바의 「뻗어나가기 →」 로 문서 화면으로 나간다. 휠 · 끌기 · `Shift`+끌기 · 「맞춤」.
좌표를 우클릭하면 「내 좌표」 로 표시된다.

### 8.5 검색 — `Ctrl+K`

```
거는 곳    관리 문서명 · 작업 기록명 · 좌표명 · 좌표 alias
나오는 것  맨 위 「대조」(alias → 정본 좌표) · 관리 문서 · 작업 기록 · 좌표
```

띄어쓰기 · 대소문자 · `_` · `-` 는 양쪽에서 지우고 맞춘다. 걸린 좌표는 그 좌표를 건드린 작업 기록과 실린 관리 문서를 끌고 온다.
이름에서 아무것도 못 찾았을 때만 본문 전문 검색이 돈다(`Shift+Enter` 로 강제). **지금 레포 안에서만** 찾는다. 유사도 검색이 아니다 —
걸리지 않으면 없는 것이다.

### 8.6 레포 관리 — 읽기면 보인다

| 메뉴 | 무엇 |
|---|---|
| **현황** | 지금 이 레포를 쓸 수 있는 상태인가 — 문서 · 기록 · 좌표 수 · 큐레이션(대기 · 가장 오래된 · 미반영 섹션) · 검사 · 원격(미러) · 작업 레포 |
| **관리 문서** | 문서마다 쓰는가(반영된 섹션 · 닿은 기록 · 들어오는 참조 · 필수) — 보기는 누구나, 지우기는 큐레이터 |
| **연결된 작업 레포** | 이 레포를 쓰는 작업 레포 — 등록 · 설치 방법 · 상태(최신 · 낡음 · 미설치). 등록 · 삭제는 writer 이상 |

| | |

| 에이전트 세팅이 바뀐 판 | **레포 관리 › 연결된 작업 레포** 의 행이 `낡음` — 담당자가 자기 PC 에서 맨 위 「에이전트 세팅이 바뀌었습니다」 카드의 한 줄(`--update` — 그 PC 에 이 서버로 설치한 작업 레포 전부 · `--commit` 이면 바꾼 파일만 커밋). 팀원은 그 커밋을 pull. 새 스킬은 Claude Code 를 다시 켜야 읽힌다 |

| 기록을 남길 때 관리 문서 섹션까지 고쳤다 · 안 고치면 「파생 누락」 으로 막혔다 | **기록만 남긴다.** 섹션은 큐레이터가 반영하고, 그 전까지 섹션 옆에 「미반영」 으로 실린다 |
| 스킬 일곱(work · load · save · import · edit · managed · push) | writer 는 셋(**cdp-work · cdp-save · cdp-push**). 편입 · 문서 수정 지시는 `cdp-save` 의 길이다 |
| 로컬형 — PC 의 지식 레포 · `bin/ctx` · git 훅 · `cdp.exe` | **없다.** 서버 하나 — 서버가 없으면 개인 서버(관리자 설명서 부록 D) |
| 상단 바 · 레포 세그(문서 · 그래프 · 관리) · 콘솔 | **왼쪽 메뉴 하나** — 지식 · 큐레이션 · 레포 관리 · 서버 · 설명서 |
| 도구 14 | 10(큐레이터 12) — `derive` · `apply` · `sync` · `version` 은 없다. 그 일은 `section` · `brief` 가 한다 |

작업 레포마다 **설치 한 줄을 한 번 다시**(`--update`) 돌려야 새 스킬 · 블록이 들어간다.

## 9. 여럿이 할 때

**서버가 언제나 최신이다** — pull 이 없다. 여럿이 동시에 `save` 해도 서버가 레포마다 줄을 세워 차례로 커밋한다
(실측 — 다섯이 같은 순간 눌러도 전부 커밋 · 건당 약 2초).

- **writer 의 기록은 서로 막지 않는다** — 섹션을 쓰지 않으므로 같은 좌표를 둘이 건드려도 기록이 둘 남는다. 큐레이터가 같이 판정한다.
  같은 id 만 `E_EXISTS` 로 막힌다(다른 id 로).
- **미러 push 는 서버가 한다** — 밀리거나 갈라지면 `save` 의 경고 · 상태 표시줄 · `brief` 가 말하고, 푸는 것은 관리자다.
- **섹션 점유("누가 편집 중")는 없다** — 같은 좌표를 동시에 건드릴 걱정은 일감 분배의 문제다.
- 레포가 둘이면 고른다 — 한 답에 두 레포를 섞지 않는다. `match` 만 레포를 가로지른다.

## 10. 막혔을 때

### 10.1 먼저 볼 것

- 에이전트에게 *"cdp 상태 봐줘"* — `brief` 가 레포 상태 · 큐레이션 대기 · 미러 · 에이전트 세팅이 낡았는지를 말한다. `[CDP]` 로 시작하는 줄은 그대로 읽는다.
- 화면 아래 상태 표시줄 · **레포 관리 › 현황**.
- 서버의 로그는 관리자가 본다.

### 10.2 기록이 막힌다 — `save` 의 거절

| 답 | 원인 | 할 일 |
|---|---|---|
| `E_FORBIDDEN` · `need: curate` | 섹션 · 등록부 · 문서 머리말을 고치려 했다(큐레이터의 입력) | 그 내용을 **기록 본문에** 쓰고 `work` 만 다시. 큐레이터가 반영한다 |
| `E_FORBIDDEN` (그 밖) | 그 레포에 쓰기 권한이 없다(viewer) | 관리자에게 writer 를 청한다 — 권한은 명부의 사람에 붙는다 |
| `E_INPUT` `field: work.touches` | 좌표 0개 | §5 를 다시 본다. 정말 0개면 승인받고 `touchesEmpty` 에 사유 |
| `E_INPUT` 「어휘에 없는 좌표」 | 미등재 좌표 | 그 좌표를 `vocab` 에 같이(§5.4) |
| `E_EXISTS` | 그 id 의 기록이 있다 | 다른 id. 고치려던 것이면 정정 기록(§6.7) |
| `E_CHECK` | **이 save 가 만든** 오류(필수 필드 · id · YAML · `status` 를 적었다 등) | `detail` 을 고쳐 다시. 레포에 원래 있던 오류는 막지 않고 경고로 온다 |
| `E_GIT` · `reason: dirty` | 서버 트리에 커밋 안 된 변경 | 관리자에게 — 「트리 되돌리기」. 보낼 것은 그대로다 |

`warnings`(시각 없는 날짜 · 레포에 없는 그림 · 아무 본문도 안 가리키는 첨부 · 원래 있던 오류)는 그대로 전해 받는다. 고칠 것은 정정 기록으로.

### 10.3 연결이 안 된다

| 증상 | 원인 | 고침 |
|---|---|---|
| `/mcp` 에 `cdp` 가 없다 | `.mcp.json` 이 없다 | pull 또는 [설치 방법] 의 한 줄(§2) |
| `cdp` 가 **failed** | `CDP_TOKEN` 이 비었거나 새 터미널 · 앱이 아니다 · 서버가 안 뜬다 | `echo %CDP_TOKEN%`(PowerShell `$env:CDP_TOKEN`) · Claude Code 를 앱째 재시작 · `curl http://<서버>:7374/healthz` |
| 로그인 401 · 도구가 `E_AUTH` | 토큰 오타 · **만료(기본 90일)** · 폐기 · 비활성 | 관리자에게 새 토큰 — 화면은 이유를 가려 주지 않는다(의도다) |
| `brief` 첫 줄 「토큰이 n일 뒤 만료된다」 | 7일 안 만료 | 관리자에게 재발급을 청한다 |
| 로그인은 되는데 레포가 없다 | 명부에서 볼 수 있는 레포가 비었다 · 방금 세운 레포 | 관리자에게 · 1분 뒤 |
| `brief` 가 「이 연결의 기본 레포와 다르다」 | `.mcp.json` 의 주소와 `.claude/cdp.json` 의 `repo` 가 갈렸다 | 그 작업 레포 폴더에서 **원래 지식 레포의** [설치 방법] 한 줄을 다시 |
| 설치기가 「그 등록은 X 의 것이다」 · HTTP 409 | 다른 레포의 등록 id 로 받았다 | X 의 **레포 관리 › 연결된 작업 레포** 에서 한 줄을 다시 받는다 |
| 새 판이 올라갔다는데 화면이 옛것 | 브라우저가 옛 화면 파일을 갖고 있다 | `Ctrl+Shift+R` 한 번 |

### 10.4 토큰을 잃었다

토큰 원문은 어디에도 저장되지 않는다 — **복구가 아니라 재발급**이다. 관리자가 콘솔에서 [재발급](옛것 폐기 + 새것 한 동작 · 30초) →
새 원문을 `CDP_TOKEN` 에 넣고(같은 설치 한 줄이 물어 준다) Claude Code 를 다시 켠다. 권한은 그대로다.
기기마다 토큰을 따로 받으면 하나를 잃어도 그것만 죽인다.

### 10.5 스킬을 못 부르면

`.claude/skills/*/SKILL.md` 는 **사람이 읽는 마크다운이다.** 열어서 붙여넣어도 동작한다. 사람만 있어도 된다 — 화면에서 좌표를 찾고,
섹션과 미반영 기록을 읽는다. 기록을 남기는 길만은 서버 `save` 다.

## 부록 A. 스킬

작업 레포의 `.claude/skills/cdp-*` 에 있다. 에이전트가 요청을 보고 고른다 — 이름을 부를 필요는 없다.

| 스킬 | 누가 | 언제 · 무엇을 |
|---|---|---|
| `cdp-work` | 모두 | 테이블 · 화면 · API · 용어 · 코드값의 **지금 상태를 알아야 하는 요청** — ① 검토 → ② 주입 → ③ 수행 |
| `cdp-save` | writer | 작업이 끝났을 때 · 밖에서 온 문서를 들일 때 · 문서를 고치라는 지시 — **작업 기록 하나** |
| `cdp-push` | 모두 | *"푸시해"* · *"커밋해"* — **사람이 부를 때만.** 이 세션이 만진 파일을 그 레포(작업 레포의 코드)에 커밋 · push. 기록은 안 만든다 |
| `cdp-curate` · `cdp-registry` | 큐레이터 | writer kit 에는 없다 — [큐레이터 설명서](큐레이터_설명서.md) |

## 부록 B. MCP 도구

`cdp` 서버의 도구다. 스킬이 부르고, 사람도 에이전트에게 말로 시킬 수 있다. **역할에 없는 도구는 보이지 않는다.**

| 도구 | 무엇 | viewer · writer | 큐레이터 |
|---|---|:--:|:--:|
| `match` | 이름 · alias · 자유 표현 → 정본 좌표. `미등재` 면 어휘에 없다. 레포를 안 주면 든 레포 전부 대조 | ○ | ○ |
| `where` | 좌표의 지금 상태 — 어느 문서 어느 섹션 · 마지막 반영 · 미반영 수 · 건드린 기록들 | ○ | ○ |
| `section` | 그 좌표의 **섹션 + 미반영 기록 + 건 정본 + 기준선** — 문서 전체를 읽지 않는다 | ○ | ○ |
| `work` | 작업 기록 본문 — "왜 그렇게 정했나" · 큐레이션 상태 | ○ | ○ |
| `search` | 말 → 좌표 후보. `match` 가 미등재를 낼 때의 폴백. 유사도 검색이 아니다 | ○ | ○ |
| `check` | 레포 검사 — `save` 가 같은 검사로 그 save 가 새로 만든 오류만 막는다 | ○ | ○ |
| `brief` | 두 줄 요약 — 절차 · 레포 상태 · 큐레이션 대기 · 미러 · 에이전트 세팅이 낡았는지 | ○ | ○ |
| `repos` | 이 서버가 든 지식 레포(볼 수 있는 것만) | ○ | ○ |
| `docs` | 관리 문서 목록 · 등록부 대상인지 · 한 문서의 원문 — 머리말과 등록부 밖 문서는 이것으로 읽는다 | ○ | ○ |
| `save` | writer 는 작업 기록 하나(+ 어휘 · 첨부). viewer 가 부르면 `E_FORBIDDEN` | ○ | ○ |
| `queue` · `forms` | 큐레이션 대기열 · 서식집 | | ○ |

## 부록 C. 용어

| 말 | 뜻 |
|---|---|
| **지식 레포** | `_vocab.md` 와 `_managed.md` 가 있는 git 레포. 프로젝트당 하나. **지식만** 둔다 — 서버가 쓴다 |
| **작업 레포** | 코드가 있는 레포. 여럿이어도 된다. 스킬 · `CLAUDE.md` 블록 · `.mcp.json` 이 들어간다 |
| **좌표** | `<타입>:<값>`. 대상마다 하나. 두 층을 잇는다 |
| **작업 기록** | `work/<id>.md`. 사건. 불변 |
| **관리 문서 · 섹션 · 정본** | `docs/*.md`. 상태. 좌표 하나에 섹션 하나 — 한 사실이 적히는 유일한 섹션이 정본이다 |
| **큐레이터** | 그 레포의 작업 기록을 판정해 관리 문서에 반영하는 사람. **레포별 권한**이다 |
| **대기열** | 아직 아무 큐레이터도 판정하지 않은 작업 기록, 오래된 순 |
| **반영 · 미반영** | 기록이 섹션에 들어갔다 · 아직 안 들어갔다. 미반영은 섹션과 같이 실린다 |
| **판정** | 큐레이터가 기록마다 내리는 것 — 반영 · 새 문서 · 기록으로 둠 |
| **`applied`** | 섹션이 어느 기록까지 실었나 — 서버가 계산해 섹션 머리에 쓴다 |
| **기준선** | 섹션 안의 기계 추출 블록(코드 · DB 에서). 생성기만 쓴다 |
| **어휘 · 등록부** | `_vocab.md`(좌표의 이름표와 alias) · `_managed.md`(좌표 패턴 → 관리 문서 · 섹션) |
| **서식 · 서식집** | 새 관리 문서를 세울 때 고르는 틀과 그 모음 — 큐레이터가 쓴다 |
| **명부 · 토큰** | 서버의 사용자 목록(권한은 여기)과 신원 증명. 토큰 원문은 저장되지 않는다 |
| **미러** | 서버가 `save` 뒤 origin 에 push 하는 것. `queued` 는 정상 |
| **개인 서버** | 서버가 없을 때 자기 PC 에 띄우는 같은 서버(`ctx serve --personal`) |
