# CDP 사용자 설명서

**판 v0.13.0 · 2026-09-28 · 대상: 세팅된 작업 레포에서 Claude Code 로 일하는 사람**

CDP 설명서는 세 권이다. 역할이 다르면 다른 권을 본다.

| 권 | 누가 | 무엇을 |
|---|---|---|
| **사용자 설명서 (이 문서)** | 개발자 · 기획자 · 운영자 등 **일반 사용자** | 작업 레포에서 에이전트로 일하고, 지식 레포에 기록을 남기고, 화면으로 본다 |
| [관리자 설명서](관리자_설명서.md) | 프로젝트의 **지식 레포를 맡은 관리자** | 서버를 세우고 · 지식 레포를 만들고 · 사람을 붙이고 · 어휘와 등록부를 지킨다 |
| [개발자 설명서](개발자_설명서.md) | **CDP 자체**를 고치는 개발자 | 소스를 고치고 · 검증하고 · 릴리스한다 |

> 이 문서는 **하루 쓰는 법**을 다룬다. 설치와 사람 관리는 관리자 설명서, 도구를 고치는 일은
> 개발자 설명서에 있다. 폐쇄망에서는 물어볼 사람이 없다 — 이 문서가 그 사람을 대신한다.
>
> **명령의 `<…>` 는 자리표시자다.** 꺾쇠까지 통째로 실제 값으로 바꾼다 — `<토큰>` 은 관리자가 준
> 한 줄, `<작업 레포 경로>` 는 `C:\gdi` 같은 실제 폴더. 그대로 치면 셸이 `<` 를 리다이렉션으로 읽어 오류가 난다.

## 0. 시작하기 전에 — 무엇을 받아야 하나

CDP 는 두 가지 배치로 쓴다. **어느 쪽인지는 관리자가 정했고**, 받는 것이 다르다.

| | **서버형** (관리자가 서버를 세웠다) | **로컬형** (내 PC 에 지식 레포가 있다) |
|---|---|---|
| 관리자에게 받는 것 | 서버 주소 `http://<서버>:7374` · 지식 레포 이름 · **토큰 한 줄** | 지식 레포 git 주소 · 배포본의 `tools/cdp.exe` |
| 작업 레포에서 | `git pull` 뒤 관리 화면 `[설치 방법]` 의 한 줄 — 토큰을 묻고 둔다. 세팅 파일이 없으면 넣는다 | `git pull` 뒤 **각자 한 번** `ctx setup` |
| 내 PC 에 두는 것 | 환경변수 `CDP_TOKEN` 하나 | 지식 레포 clone · `tools/cdp.exe` |

**토큰은 그 순간 한 번만 보인다.** 관리자도 다시 볼 수 없다. 잃어버리면 새로 받으면 된다
(§10). 어디에도 저장되어 있지 않으므로 **본인이 환경변수에 넣는 것으로 끝이다.**

서버 주소를 브라우저로 열면 **소개 페이지**와 이 설명서가 있다 — `http://<서버>:7374/manual`. 토큰 없이 읽는다.

내가 어느 배치인지 모르겠으면 작업 레포의 `.claude/cdp.json` 을 연다.

```json
{ "server": "http://10.10.20.188:7374", "repo": "gdi" }   ← 서버형
{ "knowledgeRepo": "C:/cdp" }                              ← 로컬형
```

## 1. CDP 가 무엇인가

### 1.1 세 줄

```
① 작업이 끝나면 무엇을 왜 그렇게 했는지 한 문서로 남긴다   work/   작업 기록 · 사건 · 불변
② 그 문서가 바꾼 대상에 좌표를 붙인다                     table:rp_plnd_mst · screen:PLA011 …
③ 그 대상의 "지금 상태"를 정본 문서에 옮긴다              docs/   관리 문서 · 상태 · 가변
```

①은 **사건**이라 고치지 않는다. ③은 **상태**라 계속 덮어쓴다. 6개월 뒤 누군가 *"이 컬럼 왜
이렇게 생겼지"* 를 물으면 ③이 답하고, *"왜 그렇게 정했지"* 를 물으면 ①이 답한다.

| | `docs/` 관리 문서 | `work/` 작업 기록 |
|---|---|---|
| 답하는 질문 | **지금 어떤가** | **왜 그런가** |
| 고치나 | 고친다 (덮어쓴다) | **고치지 않는다** (쌓인다) |
| 몇 개 | 대상당 하나 (섹션) | 사건마다 하나 (파일) |

### 1.2 좌표

**좌표가 이 시스템의 전부다.** 검색이 아니라 좌표로 찾는다. 이름은 사람마다 다르게 부르지만
좌표는 하나다.

```
<타입>:<값>        table:rp_plnd_mst    screen:PLA011    code:PS130    issue:ISS-002
                   테이블정의서:ex_plan_mst      ← 타입을 관리 문서 이름으로 쓰는 레포도 있다
```

타입 목록은 **그 지식 레포의 `_vocab.md` 가 정한다.** 스킬과 이 문서의 예시에 나오는
`table:` `screen:` 은 설명을 위한 것이지 정해진 이름이 아니다. 모르면 지어내지 말고
`_vocab.md` 를 연다 — 없는 타입을 쓰면 커밋이 막힌다.

좌표를 물으면 검색 결과가 아니라 **지금 상태 하나**가 나온다.

```
$ ctx where screen:EXD020
screen:EXD020
  문서   docs/화면설계서.md
  섹션   ## EXD020            ← 정본은 여기 하나뿐이다
  상태   반영 2026-0922-EXD020-첨부용량
  작업   6건                  ← 여기까지 오는 동안 있었던 일
```

### 1.3 사용자가 쓰는 도구 셋

| 도구 | 어디서 | 무엇 |
|---|---|---|
| **스킬 7종** | Claude Code (작업 레포의 `.claude/skills/cdp-*`) | 절차. 요청을 받으면 에이전트가 알아서 부른다 — 부록 A |
| **MCP 도구 13종** | Claude Code 의 `cdp` 서버 | 스킬이 부르는 읽기 도구 12 + 서버형의 `save` — 부록 B |
| **화면** | 브라우저 | 문서 · 좌표 · 그래프를 사람이 본다. 쓰지는 않는다 — §8 |

셋은 **같은 계산**을 쓴다. 화면에서 본 것과 도구가 답한 것과 커밋 훅이 막은 것이 어긋나지 않는다.

### 1.4 두 배치 — 사용자에게 다른 점

| | 서버형 (모드 B) | 로컬형 (모드 A) |
|---|---|---|
| 지식 레포가 어디에 | 서버 `/opt/cdp/repos/<이름>` | 내 PC (예 `C:\cdp`) |
| Claude Code 가 붙는 길 | HTTP · `CDP_TOKEN` | 내 PC 의 `bin/ctx mcp` (stdio) |
| 기록이 커밋되는 곳 | **서버가** 검사하고 커밋하고 origin 에 미러한다 (`save` 도구) | **내 PC 에서** 스킬이 파일을 쓰고 커밋하고 push 한다 (git 훅이 검사) |
| 쓰기 전 pull | 없다 — 서버가 언제나 최신이다 | **필수** — 스킬이 `git pull --ff-only` 로 시작한다 |
| 화면 | `http://<서버>:7374` 소개 페이지 → [들어가기] → 토큰으로 로그인. 설명서는 `/manual` | `tools\cdp.exe` 더블클릭 |
| 도구 수 | 13 (`save` 있음) | 12 (`save` 없음) |

절차와 스킬은 **같다.** 스킬이 `save` 도구가 있는지 보고 쓰기 경로만 바꾼다.

## 2. 처음 한 번 — 연결

### 2.1 서버형

1. **작업 레포 폴더에서 설치 명령 한 줄.** 관리 화면(레포 › 관리 › 작업 레포) 의 내 행 → `[설치 방법]` 에
   서버 주소 · 레포 · 등록 id 가 채워진 한 줄이 있다 — PowerShell · 명령 프롬프트 · macOS/Linux 탭에서 골라 복사한다.
   ```
   curl.exe -fsSLo "$env:TEMP\cdp-install.mjs" http://<서버>:7374/install.mjs; if ($?) { node "$env:TEMP\cdp-install.mjs" --repo <레포> --workrepo <id> . }
   ```
   설치기는 임시 폴더에 받는다 — 작업 레포에는 CDP 파일만 들어간다. Node 20 이상이 있어야 한다.
2. **토큰을 물으면 붙여넣는다** — 이 PC 에서 처음일 때만. 관리자가 준 한 줄이다(화면에 안 보인다).
   설치기가 **그 자리에서 서버에 확인하고**(`kjsa (writer) 로 확인했습니다`) 이 PC 에 둘지 묻는다 —
   ```
   Windows         사용자 환경변수 CDP_TOKEN            (관리자 권한 필요 없음)
   macOS · Linux   ~/.config/cdp/token (600) + ~/.zshrc 또는 ~/.bashrc 에 그것을 읽는 한 줄
   ```
   이미 `CDP_TOKEN` 이 있으면 묻지 않고 확인만 한다. 통하지 않으면(만료 · 폐기) 새로 묻는다.
   **왜 두나** — Claude Code 가 서버에 붙을 때마다 쓴다. `.mcp.json` 은 커밋돼 팀이 같이 쓰는 파일이라
   원문 대신 `Bearer ${CDP_TOKEN}` 자리만 있고, Claude Code 가 시작할 때 **환경변수로** 채운다.
   그다음 무엇이 바뀔지 보여 주고 묻는다 — 설치 뒤 관리자의 설치 대장에 보고까지 간다.
   세팅 파일 넷이 들어온다(이미 pull 로 받았으면 **이미 최신입니다** — 토큰과 보고만 한다) —
   ```
   .mcp.json               cdp 서버 주소 · Authorization: Bearer ${CDP_TOKEN}   (다른 MCP 서버는 그대로)
   .claude/cdp.json        { "server": …, "repo": … }
   .claude/skills/cdp-*    스킬 7종
   CLAUDE.md               <!-- cdp:begin --> … <!-- cdp:end --> 블록           (직접 쓴 내용은 그대로)
   ```
   처음 설치한 사람은 `git add .mcp.json .claude CLAUDE.md` 후 커밋한다. **다음 사람은 pull 뒤 같은 한 줄을 한 번.**
   Node 가 없거나 내려받기가 막힌 망이면 같은 자리의 **꾸러미 zip** — 풀고 그 안에서 `node install.mjs <작업 레포 경로>`
   (하는 일은 같다), Node 도 없으면 안의 `설치.md` 대로 손으로. 토큰을 직접 둘 때는 `setx CDP_TOKEN <토큰>` · `export CDP_TOKEN=<토큰>`.
3. **Claude Code 를 완전히 끄고 다시 켠다.** 환경변수와 `.mcp.json` 은 시작할 때 읽는다 — VS Code · 데스크톱 앱 안의
   Claude Code 면 **그 앱을** 다시 켠다(열려 있던 터미널 · 앱에는 새 값이 없다).
4. **확인.** Claude Code 에서 `/mcp` → `cdp` 가 **connected** · 도구 **13**건. 에이전트에게
   *"cdp 브리핑 보여줘"* 라고 하면 `brief` 두 줄이 나온다.
5. **화면.** 브라우저로 `http://<서버>:7374` → 소개 페이지의 [들어가기] → 토큰 한 칸 → `/r/<레포>/` 가 열린다.
   설명서는 상단 [설명서](`/manual`) — 로그인 없이 읽는다.

### 2.2 로컬형

1. **지식 레포를 받는다.** 관리자가 준 주소로 clone 한다. 어디에 두든 된다.
   ```
   git clone <지식 레포 주소> C:\cdp
   cd C:\cdp
   git config core.hooksPath .githooks       ← 훅은 clone 을 따라오지 않는다. 각자 한 번
   ```
2. **실행기를 넣는다.** 배포본 루트의 `cdp.exe` 를 `C:\cdp\tools\` 에 복사한다(패키지가 여럿이어도 exe 는 하나다).
   68MB 라 git 에 없다. Node 가 깔린 PC 면 없어도 `bin\ctx` 가 돈다 — 화면을 보려면 있어야 한다.
3. **작업 레포를 받는다.** `git clone <코드 레포>`. 스킬과 `CLAUDE.md` 블록은 관리자가 커밋해 두었으면 따라온다.
4. **각자 한 번 `ctx setup`.** 지식 레포 경로는 사람마다 달라 커밋되지 않는다 — 그래서 각자 돌린다.
   ```
   C:\cdp\tools\cdp.exe ctx setup C:\gdi     또는  C:\cdp\bin\ctx setup C:\gdi
   ```
   `.claude/cdp.json`(경로) · `.mcp.json`(stdio 항목) · 스킬 · `CLAUDE.md` 블록이 들어간다.
   앱에서도 된다 — `⚙ 설정 → 작업 레포 → [에이전트 설치]`. 같은 함수다.
5. **Claude Code 를 다시 켠다.** `/mcp` 에 `cdp` connected · 도구 **12**건.
6. **확인 셋.** 아래가 다 같아야 한다 — 다르면 그 레포만 옛 답을 낸다.
   ```
   C:\cdp\tools\cdp.exe ctx version
   C:\cdp\bin\ctx version
   cd C:\cdp && bin\ctx check                → 이상 없음
   ```

### 2.3 점검표

| | 서버형 | 로컬형 |
|---|---|---|
| ☐ | `/mcp` 에 `cdp` connected · 도구 13 | `/mcp` 에 `cdp` connected · 도구 12 |
| ☐ | `CDP_TOKEN` 이 새 터미널에서 보인다 | `core.hooksPath` = `.githooks` |
| ☐ | 브라우저 로그인이 된다 | `ctx version` 세 곳 일치 · `ctx check` 이상 없음 |
| ☐ | `.claude/cdp.json` 이 `{ server, repo }` | `.claude/cdp.json` 이 `{ knowledgeRepo }` 이고 **커밋되지 않는다** |

## 3. 하루 흐름

```
작업 요청  ─┐
            │  ① 검토      무엇을 바꿀 것인가.  4~6줄
            │  ② 주입      그 대상의 지금 상태를 가져온다 (필요할 때만)
            │  ③ 요청수행   그것을 근거로 답한다
            ─┘   ← 여기까지가 cdp-work 하나

작업이 끝나면 → cdp-save   기록 + 정본 문서 갱신 + 커밋 (서버형은 save 한 번)
```

| 언제 | 무엇을 |
|---|---|
| 아침 | 화면을 켠다. 로컬형은 상단 **⭮ 동기화**. `⚠ 검증 N` 이 켜져 있으면 눌러 본다 |
| 작업 요청 | 에이전트가 `cdp-work` 로 처리한다. 규약(`CLAUDE.md` 블록)에 적혀 있어 시키지 않아도 된다 |
| 작업 끝 | `cdp-save`. 서버형은 서버가 커밋·미러까지, 로컬형은 커밋·push 까지 |
| 퇴근 전 (로컬형) | 상태바 `⬆ 미전송 N건` 이 있으면 보낸다 — **안 보내면 남에게는 없는 일이다** |

**요청 하나가 작업 하나가 아니다.** 요청 세 개가 한 작업일 수 있고, 그때 기록은 하나다.
요청마다 기록하면 이력이 파편화된다.

기록이 생기는 길은 셋이다. **어느 길이든 관리 문서 갱신이 함께 간다.**

| 어떤 일이었나 | 스킬 |
|---|---|
| 이 세션에서 작업했다 | `cdp-work` → `cdp-save` |
| 이미 쓴 문서가 있다 (회의록 · 검토서 · 설계 메모) | `cdp-import` — 원문을 보존한 채 들인다 |
| 작업은 없고 **문서를 고치라는 지시**다 | `cdp-edit` — **지시가 곧 기록의 본문**이다 |

셋째가 중요하다. 관리 문서만 고치고 기록을 안 남기면 **출처 없는 변경**이 되고, 6개월 뒤
"왜 이렇게 적혀 있지" 에 답할 것이 없다. 이 경우는 `ctx check` 도 잡지 못한다 — 기준이 될
기록이 없기 때문이다.

## 4. 작업 요청 — `cdp-work`

### 4.1 왜 순서가 이런가

**요청이 먼저다.** 세션이 시작되자마자 맥락을 넣으면 두 가지가 어긋난다. 좌표는 "이 작업이
바꾼 대상"인데 무엇을 바꿀지 모르면 뽑을 것이 없고, 정본 문서 다섯 개가 먼저 들어오면 요청을
그 다섯의 틀로 읽어 여섯 번째를 못 본다. **주입은 답을 좁히는 행위다** — 무엇을 좁혀야 하는지
알기 전에 좁히면 엉뚱한 곳을 좁힌다.

### 4.2 ① 검토 — 4~6줄

```
【검토】
요청  PSC043 면접심사의견등록에 심사위원 연대서명 출력물을 추가한다

대상
  screen:PSC043      변경   출력물 2종 추가
  code:PS130         ?      업무구분 코드를 쓸지 미정
  screen:PSC031      참조   첨부를 읽어오지만 PSC031 은 안 바뀜 → 좌표 아님

주입  screen:PSC043 · code:PS130
```

| 규칙 | 왜 |
|---|---|
| **`_vocab.md` 만 읽는다** | 어휘는 이름표라 의견이 없다. 정본 문서와 작업 기록은 의견을 담는다 |
| **좌표 아닌 것도 적는다** | 무엇을 왜 제외했는지가 판정의 근거다 |
| **멈추지 않는다** | 검토 출력은 감사 흔적이지 승인 관문이 아니다. 판정이 틀렸으면 답에서 드러나고 그때 고친다 |

**멈추는 경우는 하나뿐이다** — *"채용 쪽 정리해줘"* 처럼 요청 자체가 무엇을 원하는지 모를 때.

### 4.3 ② 주입 — 섹션 하나다

검토가 좌표 이름을 늘어놓으면 *"그 좌표에 관한 것이 전부 들어왔다"* 고 읽기 쉬운데, 실제로
들어온 것은 **그 관리 문서의 한 섹션**이다.

```
[정본]   docs/테이블정의서.md  ## ps_ext_emp_mst
[범위]   그 섹션만 — 18줄 · 약 520자 (docs/테이블정의서.md:839)
```

안 들어온 것 셋 — 그 문서의 다른 섹션 · 그 좌표를 건드린 작업 기록 · 등록부에 안 걸리는
관련 좌표. 더 보고 싶으면 에이전트에게 말하거나 화면에서 `Ctrl+K` 에 좌표를 붙여 넣는다.

### 4.4 주입 결과에서 봐야 하는 것 셋

| 줄 | 뜻 |
|---|---|
| `[상태] … 반영 2026-0903-…` | 이 섹션이 어느 작업까지 실었나. `파생 남음`(`derive-pending`) 이면 **아직 최신이 아니다** — 아래 작업 기록을 직접 읽어라 |
| `table:rp_plnd_mst 후속 3건` / `api:… 최신` | **한 문서 안에서 좌표마다 판정이 다르다.** "이 문서는 낡았다" 는 말은 반드시 절반이 틀린다 |
| `[절단] 매칭 8건 중 3건 주입. 나머지 id: …` | 이 줄이 없으면 나머지 5건이 존재하지 않는다고 판단하게 된다 |

`사실상 비어 있다` 가 붙으면 주입은 성공했고 내용이 없다는 뜻이다. 그 상태로 답을 받으면
*"문서에 정의가 없다"* 가 *"제약이 없다"* 로 바뀐다 — 확신 있게 틀린 답이다. 코드나 담당자를 본다.

### 4.5 검토 출력을 고치는 말 셋

| 보이는 것 | 이렇게 말한다 |
|---|---|
| 대상에 없는 것이 있다 | *"PSC031 도 바뀌어"* |
| 대상에 있으면 안 되는 것 | *"PS130 은 안 건드려"* |
| 주입이 과하다 | *"맥락 필요 없어, 그냥 해"* |

`?` 는 에이전트가 확신이 없다는 뜻이다 — 거기가 먼저 볼 자리다. `(미등재)` 는 그 이름이
`_vocab.md` 에 없다는 뜻이다. **지금 다른 좌표로 바꾸지 마라.** 기록할 때 등재하면 된다.

### 4.6 언제 건너뛰나

| 상황 | |
|---|---|
| *"이 정규식 왜 안 되지"* · *"이 함수 이름 바꿔줘"* | `cdp-work` 를 안 부른다. 지식 레포와 무관하다 |
| 이어지는 대화 (같은 주제) | 다시 안 부른다. 이미 주입된 맥락을 쓴다 |
| **내가 그 도메인의 리더이고 내 로컬이 최신** | 안 부른다. 지식 레포가 나보다 뒤에 있으면 주입은 나를 어제로 되돌린다 |

셋째는 뒤가 구멍이다. 그렇게 작업하고 **지식 레포에 아무것도 안 쓰면** 그 결정이 내 머리와
로컬 코드에만 남고, 그 좌표를 건드린 기록이 없으니 그 섹션은 **최신인 척한다.** 리더일수록
기록이 중요하다 — 6개월 뒤 그 결정을 되짚는 첫 사람은 대개 자기 자신이다.

### 4.7 도구가 없을 때

`cdp` 서버가 안 붙어 있어도 절차는 돈다. 스킬이 `bin/ctx` 를 직접 부른다 — 같은 함수라
결과가 바이트까지 같다. 사람만 있어도 된다.

```
<지식 레포>/bin/ctx match 면접심사의견등록      이름 → 좌표
<지식 레포>/bin/ctx where screen:PSC043        그 좌표의 지금 상태가 어디에
```

## 5. 좌표

### 5.1 무엇이 좌표인가 — 이 작업이 **바꾼** 것만

| 이 작업이 그 대상을… | 좌표 |
|---|:--:|
| 신설했다 | **O** |
| 변경했다 (컬럼 추가 · 규격 변경 · 상태값 추가) | **O** |
| 삭제 · 폐기했다 | **O** |
| 작업 중 발견해 **이슈로 제기했다** (`issue:`) | **O** |
| 참조했다 · 호출했다 · 언급했다 | **X** |
| 그것을 쓰는 다른 것을 만들었다 | **X** |

판정 기준은 하나다 — **6개월 뒤 그 대상을 맡은 사람이 이 작업을 찾아야 하는가.**
*"주제인가?"* 는 답이 갈리지만 *"바꿨는가?"* 는 결판나고, diff 로 확인된다.

### 5.2 예시

| 작업 | 좌표 | 아닌 것 |
|---|---|---|
| `PS_EXT_EMP_MST` 에 컬럼 2개 추가 | `table:ps_ext_emp_mst` | |
| PSC043 을 현황/작성 화면으로 분리 | `screen:PSC043` | `module:grid-common` (쓰기만 함) |
| 코드그룹 PS130 신설 | `code:PS130` | |
| EXA021 에서 `wrk_tp_cd` 로 트리 그룹핑 | `screen:EXA021` | **`table:ps_ext_emp_mst`** — 읽기만 한다 |
| SEB020 임시저장에 작성일 미기록 | `screen:SEB020` · **`table:rp_pre_rview_opl_list`** | — 컬럼이 언제 채워지는지가 바뀌었다 |
| 통합테스트 일정 확정 | **없음** (`touches: []`) | 아무 대상도 안 바꿨다 |
| 계획서 관리번호 중복 검증 | `screen:PLA011` · `screen:PLA021` · `table:rp_plnd_mst` | 제약은 안 걸었지만 그 **판단**이 테이블 정의에 남는다 |
| 알림 문구를 사용자 말로 | `screen:SEA021` | 조건은 그대로다. 문구도 그 화면의 정의다 |

"그 테이블을 쓰는 화면 작업" 은 대개 테이블이 좌표가 아니다. 반대로 **컬럼이 언제 채워지는지가
바뀌었으면** 그 컬럼을 맡은 사람이 알아야 하므로 좌표다.

### 5.3 스스로 검산하는 법

**갱신할 것이 없으면 좌표 판정이 틀린 것이다.** `cdp-save` 가 정본 문서 갱신을 요구하는데
그 섹션에 고칠 내용이 떠오르지 않으면, 그 좌표는 참조였다. 빼라.

**없는 좌표보다 억지 좌표가 나쁘다.** 그 좌표를 찾는 사람에게 무관한 문서를 내밀기 때문이다.
0개면 `touches: []` 로 적는다 — 키를 빼지 말고 **0개임을 확인했다는 선언**으로 남긴다.

### 5.4 미등재 좌표

어휘에 없는 이름을 쓰면 커밋(서버형은 `save`)이 막힌다. 그때 `_vocab.md` 의 해당 타입 섹션에
**한 줄** 추가한다 — 관리자를 기다리지 않는다. 서버형은 `save` 의 `vocab` 인자로 같이 보낸다.

```markdown
- `code:PS130` — 외부인원 업무구분
  aliases: 업무구분코드, PS130
```

**`aliases` 가 이 파일의 값어치다.** 그 작업에서 실제로 쓴 표현을 그대로 넣는다 — 나중에 지어낸
별칭은 아무도 안 쓴다. 지우지는 않는다 — 폐기는 관리자가 `deprecated:` 로 표시한다.

## 6. 기록 — `cdp-save`

### 6.1 단계 — 두 배치에서 무엇이 다른가

| | 로컬형 (`save` 도구 없음) | 서버형 (`save` 도구 있음) |
|---|---|---|
| ① 시작 | `git pull --ff-only`. **실패하면 시작하지 않는다** | 없다 — 서버가 언제나 origin HEAD 다 |
| ② 좌표 판정 | §5. 판정 근거를 보여 준다 | 같다 |
| ③ 작업 기록 | `work/<id>.md` 에 쓴다 | **파일을 만들지 않는다.** 내용을 준비해 사람에게 보인다 |
| ④ 정본 갱신 | 관리 문서 섹션을 고친다. **③ 과 함께 필수.** 사람이 승인한다 | 같다 — 준비만 |
| ⑤ 끝 | 작업 기록 1 + 관리 문서 N 을 **한 커밋** → 훅이 검사 → push | `save({ repo, work, sections, vocab })` **한 번.** 서버가 검사 · 커밋 · 미러 |
| 충돌 | 훅이 막는다 · non-fast-forward 면 멈추고 사람에게 | `E_CONFLICT` 면 `section` 을 **다시 읽고 ④ 를 다시** 만든다 |

**③ 만 하고 ④ 를 미룰 수 없다.** `ctx check` 가 파생 누락을 **오류**로 잡아 커밋을 막는다.
④ 를 채울 자신이 없으면 ③ 도 아직 쓰지 마라 — 안 채운 것은 검사가 알려 주고, 틀리게 채운
것은 아무도 모른다.

### 6.2 작업 기록 — 프론트매터

```yaml
---
id: 2026-0821-면접심사의견-개편        # 파일명과 같아야 한다.  YYYY-MMDD-slug
title: PSC043 개편 — 현황/작성 화면 분리
date: 2026-08-21 14:30                # 사건의 날짜.  시각까지 적는다
author: kjsa                          # 서버형은 보내지 않는다 — 서버가 토큰에서 채운다
touches:
  - screen:PSC043
  - code:PS130
tags: [채용, 화면개편]
---
```

| 필드 | | |
|---|---|---|
| `id` | 필수 | 파일명과 같다. 등록부의 `applied` 가 이 값으로 가리킨다 |
| `title` | 필수 | `[` `{` `&` `*` 로 시작하거나 `: ` 를 포함하면 **따옴표로 감싼다** — 아니면 YAML 이 제목을 지운다 |
| `date` | 필수 | **그 일이 있었던 때.** 오늘이 아니다. 시각까지 적으면 같은 날 두 번 건드려도 순서가 결판난다 |
| `author` | 필수 (로컬형) | 서버형은 서버가 채운다 |
| `touches` | 필수 | 0개여도 `[]` |
| `tags` | | 자유 |
| `supersedes` | | **이 기록 자체가 틀렸을 때만.** 같은 좌표를 나중에 또 바꾼 것은 적지 않는다 — 계산으로 나온다 |
| `status` | **쓰지 않는다** | 쓸 수 있는 값이 없다. 완료가 기본값이고, `미결` · `제안` 은 아젠다라 이슈 대장으로 (§9.3) |

### 6.3 본문은 자유 형식이다

섹션을 강요하지 않는다. 다만 6개월 뒤 이 결정을 뒤집으려는 사람은 *"무엇을 했는지"* 가 아니라
**"어떤 제약 때문에 그렇게 했는지"** 를 찾는다. `touches` 는 붙었는데 본문에 *"용량 제한을
10MB 로 올렸다"* 만 남는 것이 남는 문제다 — 화면이 **본문이 얇은 기록**을 알려 준다.

### 6.4 ④ 정본 갱신 — 섹션은 홀로 서야 한다

**그 섹션만 읽고 대상의 현재 상태를 알 수 있어야 한다.** 주입은 섹션만 싣기 때문이다 — 값이
기록에만 있으면 주입받은 쪽은 그 값이 없다고 판단하고 새로 정하려 든다. 실제로 지불 수단별
기본값 표를 기록에만 남기고 섹션에는 *"기본값이 여기서 정해진다"* 한 줄만 남겨, 같은 요청이
다시 왔을 때 이미 정해진 값을 처음부터 다시 정하는 일이 있었다.

| 요약해도 되는 것 (기록에 남긴다) | 반드시 옮길 것 (섹션에) |
|---|---|
| *"현장 요청으로"* · *"협의 결과"* · 논의 · 대안 | **그래서 값이 무엇인가** — 판단 · 표 · 규칙 · 값 · 제약 |
| 누가 언제 무엇을 물었나 | 그 답이 만든 **규칙과 예외** |

변경 줄(`**변경** · 날짜 [링크]`)은 출처 표시이지 내용이 아니다. `ctx apply <좌표>` 가 초안과
작업 기록의 목차를 준다. 문서마다 끝에 `## 작성지침` 이 있다 — **어느 칸에 무엇을 어떻게 적나**.
처음 그 문서를 고칠 때 한 번 읽는다.

### 6.5 서버형 — `save` 한 번

```
save({
  repo: "gdi",                              // 필수. 쓰기에서 기본값은 사고다
  work: { id, title, date, touches, tags, body },
  sections: [{ coord, applied, body }],     // 좌표 하나에 하나. applied 는 section 이 준 값 그대로.
                                            // body 는 section 의 **content**(헤딩 · applied 없는 본문)를 고친 것 — 헤딩을 넣으면 E_INPUT
  vocab: [{ coord, label, aliases }]        // ② 에서 (미등재) 였던 것만
})
→ { commit: "1bc1eec", sections: 2, vocab: 1, mirror: "ok", mirrorReason: null, mirrorLast: {…}, warnings: [] }
```

| 답 | 뜻 |
|---|---|
| `E_CONFLICT` | 그 사이 남이 같은 섹션을 갱신했다. 거절에 **재료가 실려 온다** — `detail.currentWork`(누가 · 언제 · 어느 기록) · `detail.content`(지금 본문). **그 `content` 위에 ④ 를 다시 만들고 `applied` 에 `detail.current` 를 넣어 다시** 보낸다 — `section` 을 다시 부르지 않아도 된다(`truncated` 일 때만). 옛 본문을 재전송하면 그 사람의 갱신이 사라진다 |
| `E_GIT` · `reason: dirty` | 서버 트리에 커밋 안 된 변경이 있어 거절됐다(중단된 save · 사람의 손). 관리자에게 — 콘솔 > 지식 레포 > 「트리 되돌리기」. 보낼 것은 그대로다 |
| `E_FORBIDDEN` | 그 레포에 쓰기 권한이 없다. 관리자에게 말한다 |
| `E_INPUT` | 인자 모양. 메시지의 `field` 를 본다. "헤딩 줄이 있다" 면 `body` 에 `## …` 를 넣은 것 — `section` 의 `content` 를 고쳐 보낸다 |
| 검사 실패 | §6.6 의 표와 같은 오류들이다. 고치고 다시 `save` |
| `mirror` | origin 미러의 실제 상태 — `ok`(갔다) · `queued`(아직 가는 중) · `lag`(못 갔다 · `mirrorReason` 이 사유) · `diverged`(origin 에 서버가 모르는 커밋 — 관리자가 맞춘다) · `off`. 어느 경우든 **커밋은 서버 트리에 있다.** `ok` 가 아니면 `warnings` 의 줄을 그대로 전한다 — 고치는 것은 관리자다 |

`section` → ④ → `save` 사이가 짧을수록 충돌이 적다. 미리 다 읽어 두고 오래 붙들지 마라.
**push 는 사람이 누르지 않는다** — 서버의 일이다.

### 6.6 커밋이 거부되면

`--no-verify` 로 넘기지 마라 — 그 검사가 유일한 기계 보증이다.

| 거부 사유 | 고치는 법 |
|---|---|
| **관리 문서 파생 누락** | ④ 를 끝낸다. `ctx apply <좌표>` 가 초안을 준다 |
| `_vocab.md` 미등재 좌표 | 어휘에 한 줄 (§5.4) |
| 등록부가 가리키는 섹션이 없음 | 그 문서에 섹션을 만든다. 앵커 형태는 등록부가 정한 그대로 (`## {값}`) |
| `status: 미결` · `제안` | 아젠다다. 이슈 대장으로 (§9.3) |
| 필수 필드 누락 · `id` ≠ 파일명 · YAML 오류 | §6.2 |
| `applied` 가 없는 기록을 가리킴 | **고치지 마라.** 이름 오기이거나 기록이 지워진 것 — 사람에게 알린다 |

**커밋을 되돌리지 마라.** 로컬형에서 push 가 안 됐다고 커밋을 지우면 ③④ 를 다시 해야 한다.
올리는 것만 다시 하면 된다.

## 7. 다른 길 — `cdp-import` · `cdp-edit` · `cdp-managed` · `cdp-load` · `cdp-push`

### 7.1 `cdp-import` — 밖에서 온 문서

*"이 회의록 반영해줘"* · *"예전 검토서를 지식 레포로 옮겨줘"*. 뼈대는 `cdp-save` 와 같고
**날짜와 좌표**가 다르다.

- **날짜는 사건의 날.** 오늘로 적으면 반년 전 회의록이 어제 결정을 덮는다
- **언급은 좌표가 아니다.** 화면 이름이 열다섯 개 나와도 그 회의가 바꾼 것은 둘일 수 있다
- **본문을 다시 쓰지 않는다.** 회의록의 반대 의견이 6개월 뒤 유일한 단서다
- 편입 문서가 섹션의 `applied` 보다 **과거**면 `applied` 를 바꾸지 않는다

md 파일이 **수백 개**라면 스킬이 아니라 관리자의 `ctx import-dir` 가 맞다 (관리자 설명서 8장).

### 7.2 `cdp-edit` — 문서 수정 지시

*"화면설계서 EXD020 에 사진 첨부 추가해줘"* · *"이 컬럼 설명이 틀렸으니 고쳐줘"*. 코드 작업 없이
관리 문서만 고치는 경우다. 문서를 고치고 **지시 자체를 기록의 본문으로** 남긴다.

```markdown
## 지시
> 사진 첨부 용량은 10MB 로 해줘. WAS 업로드 상한이 그거라서 20MB 로 적어 놔도 어차피 안 올라가.
kjsa, 2026-09-22.

## 반영
docs/화면설계서.md ## EXD020 의 첨부 대목에 10MB.
```

**지시를 요약하지 않는다.** "20MB 로 적어 놔도 어차피 안 올라가" 가 제약의 출처다.
이 자리는 기계가 막지 못한다 — 기록이 없으면 검사할 기준이 없다. 그래서 스킬이 있다.

### 7.3 `cdp-managed` — 파생이 남은 섹션 채우기

`ctx derive` 가 목록을 준다. 화면의 `⚠ 검증 N` 도 같은 것이다.

| 규칙 | |
|---|---|
| **전부 몰아서 하지 마라** | 내용을 모르고 옮기게 되고, 20개 섹션을 한 번에 고치면 그 사이 아무도 커밋 못 하고, 큰 diff 는 승인이 형식이 된다 |
| 우선순위 | ① 요청받은 좌표 ② 방금 내가 작업한 좌표 ③ `섹션 없음`(내용 판단이 필요 없다) ④ 오래 남은 것 |
| **확신이 없으면 반영하지 마라** | 틀리게 채운 것은 아무도 모른다 |
| 바뀐 게 없으면 그렇게 적는다 | `… 그룹핑 키로 사용. **컬럼 변경 없음**` |
| `applied 깨짐` 은 고치지 마라 | 어느 쪽이 맞는지 모르고 바꾸면 이력이 끊긴다. 사람에게 알린다 |
| **서버형** — 「파생 정리 기록」 | 커밋 대신 `save` 한 번 — `id: YYYY-MMDD-파생정리-<좌표>` · `tags: [derive]` · `touches` 는 치운 좌표 · 본문은 `근거: <기록 id> … 판단: …`. 좌표 하나에 하나. 따라잡은 판단이 기록으로 남는다(모드 A 는 커밋 메시지뿐이었다). `where` 가 그 좌표의 최신 기록으로 이것을 내는 것은 사실이다 |

### 7.4 `cdp-load` — 좌표를 알 때

*"table:rp_plnd_mst 지금 어떻게 돼 있어?"* — 검토 없이 그 좌표의 섹션만 주입한다.
`cdp-work` 의 ② 가 이것을 쓴다.

### 7.5 `cdp-push` — 코드 레포 커밋 · push

*"푸시해"* · *"커밋해"* · *"변경사항 올려"*. **이 세션에서 만지거나 고친 파일**을 그 파일이
속한 레포에 커밋하고 push 한다. 지식 기록은 만들지 않는다 — 그것은 `cdp-save` 다.
세션 밖 변경은 건드리지 않는다. **사람이 부를 때만** 돈다.

> **정정(v0.13.0 · 2026-09-28 · [화면 · 권한 검토 v0.1](../docs/design/CDP_화면_권한_검토_v0.1.md))** — 8.1 의 「소개」 탭이 빠졌다 — **C CDP** 가 소개다. 얼굴 사이(소개 · 설명서 · 레포 · 콘솔)와 레포 바꾸기 · 로그인 · 로그아웃이
> 전부 **한 화면 안의 이동**이 됐다 — 전에는 그때마다 페이지가 통째로 다시 떠 밝게 깜빡이고 「읽는 중…」 을 다시 거쳤다. 그래프 · 관리도 주소가 됐다.

### 8.2 구조 — 좌우 2분할

```
┌── 왼쪽 ─────────────────────┬── 문서 ──────────────┬─────┐
│ [목록] [뻗어나가기]          │                      │ 목  │
│                             │   오른쪽은 문서다.    │ 차  │
│   한 번에 하나만 한다.       │                      │ ▸   │
└─────────────────────────────┴──────────────────────┴─────┘
```

왼쪽에서 찾고 오른쪽에서 읽는다. **왼쪽은 한 번에 하나만 한다** — 고르는 중이면 목록,
따라가는 중이면 뻗어나가기. 가운데 구분선은 끌어서 조절하고, 하는 일마다 폭을 따로 기억한다.

### 8.3 왼쪽 — 목록

| 탭 | |
|---|---|
| **관리문서** | 정본 문서. 옆 숫자는 섹션 수 |
| **작업문서** | 작업 기록. 제목이 맨 앞. 안 읽은 것은 왼쪽 모서리에 파란 선. 시각은 같은 날 두 건 이상일 때만 붙는다 |
| **좌표** | 카테고리 칩으로 좁힌다. 우클릭하면 `내 좌표` 로 표시된다 |

찾기는 탭 아래 자기 줄에 있다 — 제목 · id · 좌표 · 작성자에 걸린다. 관리문서 · 작업문서를
고르면 오른쪽에 열리고 목록은 남는다. 좌표를 고르면 **뻗어나가기로 넘어간다.**

### 8.4 왼쪽 — 뻗어나가기

**이 화면의 핵심이다.** 고른 것에서 **다음 한 단계만** 펼친다.

| 지금 보는 것 | 다음에 나오는 것 |
|---|---|
| 작업문서 | 관리문서 · 좌표 |
| 좌표 | 관리문서 · 작업문서 |
| 관리문서 | 섹션 |

열 하나가 한 단계다. 가로로 뻗으므로 지나온 길이 왼쪽에 남고, 중간 열에서 다시 고르면 그
오른쪽이 전부 교체된다. **루프를 허용한다** — 같은 것이 여러 열에 다시 나올 수 있다(트리가
아니라 그래프다). 어디서 멈춰도 오른쪽에 문서가 뜬다. 정렬은 늘 같다 — 좌표는 카테고리순 +
이름순, 작업문서는 작성일자순, 관리문서와 섹션은 섹션 순서. **상태로 정렬하지 않는다.**

### 8.5 오른쪽 — 문서와 목차

본문 오른쪽에 목차가 세로로 선다. 지금 읽는 섹션이 파랗게 남고 스크롤하면 따라온다. 섹션이
159개여도 다 들어간다 — 넘치면 목차만 스크롤된다. 머리(`▸ 목차 N`)를 누르면 접히고 띠 아무
데나 누르면 펴진다. **본문의 좌표에 상태 배지는 붙지 않는다** — 갱신 누락은 상태가 아니라
커밋을 막는 오류라, 붙일 상태가 없다.

**내려받기** — 문서 맨 아래 「복사」 줄의 **「내려받기 (.md)」** 가 그 파일을 그대로(프론트매터 포함) 받는다. 묶음은
**관리 › 현황 › 내려받기** — 관리 문서(`docs/` 의 `.md` 전부) · 작업 문서(`work/` 전부 · 첨부 포함) zip 하나씩.
레포 안의 경로 그대로 묶여서 풀면 레포와 같은 모양이다. 볼 수 있는 레포면 누구나(viewer 포함) 받는다.

### 8.6 그래프

상단 `그래프` 를 누르면 창 전체가 좌표망이 된다. `Esc` 로 돌아온다.

| | |
|---|---|
| 기본 | **이어진 좌표만** 그린다. 고립 좌표(어휘에만 있고 작업이 없는 것)는 `고립 +N` 을 눌러 켠다 |
| 왼쪽 카테고리 | 고르면 그 타입의 좌표만 색이 붙는다 |
| 노드 클릭 | 1단계로 이어진 것만 진해지고 고정된다. 다시 누르거나 빈 곳을 누르면 풀린다 |
| 아래 바 `뻗어나가기 →` | 그 좌표를 시작점으로 문서 화면으로 나간다 |
| 휠 · `−` `+` / 끌기 / `Shift`+끌기 / `맞춤` | 확대 · 축소 / 회전 / 공간 이동 / 기본 배율로 |

노드 크기는 작업 건수다. **노드를 누르는 것은 고르는 것이지 떠나는 것이 아니다** — 읽고 나서
아래 바에서 정한다.

### 8.7 검색 — `Ctrl+K`

```
거는 곳    관리문서명 · 작업문서명 · 좌표명 · 좌표 alias
나오는 것  관리문서 · 작업문서 · 좌표
```

띄어쓰기 · 대소문자 · `_` · `-` 는 양쪽에서 지우고 맞춘다 — `RP_PLND_MST` 도 `rp plnd mst` 도
같은 것을 가리킨다. alias 로 걸렸으면 그 alias 를 줄에 그대로 보여 준다. 걸린 좌표는 그 좌표를
건드린 작업문서와 실린 관리문서를 끌고 온다. 이름에서 아무것도 못 찾았을 때만 본문 전문 검색이
폴백으로 돈다(`Shift+Enter` 로 강제). **서버형은 현재 레포 안에서만 찾는다.**

|---|---|---|
| 상단 | 왼쪽 **C CDP** · **설명서 · 레포 ▾ · 콘솔**(관리자) — 소개 · 콘솔과 같은 바 · 가운데 `문서 · 그래프 · 관리` · 검색 · **⚠ 검증 N** · 오른쪽 내 이름 · 역할 칩 · 로그아웃 · **⋯**(도움말 · 읽기 모드 · 글자 · 폭 · 테마). 창이 1080px 보다 좁으면 소개 ~ 콘솔이 **C CDP ▾** 메뉴로 접힌다 | 왼쪽 **C CDP** · **레포 · <이름>** · `문서 · 그래프 · 관리` · 검색 · **⭮ 동기화** · **⚠ 검증 N** · **⋯** |
| 관리 메뉴 | **현황 · 작업 레포 · 정보** 셋 — 누구에게나 같다. 작업 레포의 등록 · 삭제는 `writer` 이상. 「정보」 는 판 · 내 계정 · 역할 · 이 레포에서 할 수 있는 것 · **토큰 만료 D-n** · 단축키. 다른 레포는 「레포 ▾」, 지식 레포를 세우는 것 · 사람 · 토큰은 **관리자의 콘솔**이다 | 현황 · 지식 레포 · 동기화 · 작업 레포 · 진단 · 정보 |
| 상태바 | | `✓ 검사` · `⬇ 원격 N건 받기` · **`⬆ 미전송 N건 보내기`** · `⚠ 훅 없음` · `감시 중` |

> **정정(v0.13.0 · 2026-09-28 · [화면 · 권한 검토 v0.1](../docs/design/CDP_화면_권한_검토_v0.1.md))** — 서버형 관리 메뉴가 넷(+ 관리자에게 「콘솔」 · 「문서로 돌아가기」)에서 **셋**이 됐다. 「지식 레포」 는 빠졌다 —
> 목록은 「레포 ▾」 가, 세우기는 관리자의 콘솔이 든다(일반 사용자는 지식 레포를 세우지 않는다). 「진단 · 정보」 는 영원히 「읽는 중…」 이던
> 자리였고 이제 값만 내는 「정보」 다. ⋯ 메뉴의 「관리 —」 줄도 빠졌다 — 상단의 「관리」 와 같은 일이었다.

`⭮ 동기화` 는 fetch → (뒤처졌으면) ff pull → 다시 읽기를 한 번에 하고, 도는 동안 단계와 걸린
초가 그 버튼에 뜬다 — 사내망에서는 20초쯤 걸린다. **보내기(push)는 상단에 없다.** 상태바의
`⬆ 미전송` 뿐이다 — 받는 것과 보내는 것을 같은 자리에 두지 않는다.

| 키 | |
|---|---|
| `Ctrl+K` / `⌘K` | 검색 · 이동 |
| `Ctrl+.` / `⌘.` | 읽기 모드 — 왼쪽을 접는다 |
| `Ctrl+` `+` `−` `0` | 본문 글자 크기 |
| `Alt+←` `Alt+→` | 방문 이력 |

| `\` | 왼쪽 전환 — 목록 ↔ 뻗어나가기 |
| `Esc` | 검사 결과 · 메뉴 닫기 · 그래프/관리에서 문서로 |
| `?` | 도움말 — 단축키 · 설명서 링크 · 레포 문서 |

### 8.9 새 판이 올라간 뒤 — 무엇이 달라지나

관리자가 서버에 새 판을 올리면(관리자 설명서 9.1) 사용자가 할 일은 하나다 — **브라우저 강제 새로고침**
(`Ctrl+Shift+R`) 한 번. 옛 화면 파일이 브라우저에 남아 있을 수 있다. 그 밖은 그대로다 —

| | 그대로다 |
|---|---|
| 로그인 | 다시 하지 않는다. 세션이 서버에 있지 않아 재시작을 넘어 살아 있다 |
| 토큰 · Claude Code | `CDP_TOKEN` · `.mcp.json` 그대로. `/mcp` 의 `cdp` connected · 도구 13 그대로 |
| 주소 | `/r/<레포>/` 북마크 · 공유한 링크 그대로 |
| 작업 레포 | 스킬이 바뀐 판이면 관리 > 작업 레포의 내 행이 `낡음` — `[설치 방법]` 의 한 줄 한 번 더(2.1). 아니면 없다 |

서버가 어느 판인지는 소개 페이지 바닥(`CDP v… · 빌드 …`)에 있다.

**v0.10.0 에서 달라진 것** — 소개 · 설명서 · 콘솔이 들어온 판이다. 사용자 눈에는 이렇게 보인다.

| 전 | 지금 |
|---|---|
| `http://<서버>:7374/` 가 바로 로그인 → 레포였다 | **소개 페이지**다. [들어가기] 가 로그인이다. `/r/<레포>/` 로 바로 가는 북마크는 그대로 든다 |
| 설명서는 관리자에게 받았다 | 상단 [설명서](`/manual`) — 이 문서 · 관리자 · 개발자 설명서 · 설치 절차. **로그인 없이** 읽는다. 도움말(`?`)에도 링크 |
| 레포 이름표는 레포가 둘 이상일 때만 메뉴였다 | **언제나 메뉴**다 — 내가 볼 수 있는 레포와 그 레포에서 내가 쓰기인지 읽기인지 |
| 오른쪽 위에 이름과 로그아웃 | 설명서 · 이름 · **역할 칩**(viewer · writer) · 로그아웃. 기록을 만들 수 있는 사람(`writer`)인지 여기서 안다 — 전에는 `write` 라 불렀다 |
| 토큰을 잃으면 관리자가 셸에서 발급했다 | 관리자가 **콘솔**에서 [재발급] — 30초. 받는 쪽은 같다: 원문 한 줄을 `CDP_TOKEN` 에(10.3) |
| — | 관리자에게만 상단에 **콘솔** 링크와 관리 메뉴의 「콘솔로 →」 가 보인다. 일반 사용자에게는 없다 — 권한 밖은 존재를 알리지 않는다 |

바뀌지 않은 것 — 문서 · 그래프 · 검색 · 단축키 · 주소 규칙 · MCP 도구 13 · 사용자 토큰의 만료(90일).

**v0.11.0 에서 달라진 것** — 상단 바를 하나로 합친 판이다(화면 UX 검토). 기능은 그대로고 **길**이 바뀌었다.

| 전 | 지금 |
|---|---|
| 소개 · 레포 · 콘솔의 상단이 제각각이었다 — 표식을 누르면 소개 · 콘솔 홈 · 레포 메뉴로 갈렸다 | 어디서나 같은 바 — 왼쪽 **C CDP** 는 언제나 소개로, 그 옆 **소개 · 설명서 · 레포 ▾ · 콘솔**(관리자). 지금 있는 곳에 밑줄 |

## 9. 여럿이 할 때

### 9.1 로컬형 — 쓰기 전에는 받고, 읽기 전에는 확인한다

```
쓰기  git pull --ff-only    실패하면 시작하지 않는다        cdp-save · cdp-import · cdp-edit · cdp-managed
읽기  ctx sync              받지 않는다. 받을 것이 있으면 알린다   cdp-work ② · cdp-load
```

pull 안 하고 기록하면 낡은 섹션 위에서 diff 를 만들고, 남이 어제 추가한 컬럼이 사라진 diff 를
승인하게 된다 — 그리고 그 손실은 **조용하다.** 읽기에는 pull 을 강제하지 않는다(보는 것조차
막히면 과하다) 하지만 확인은 한다 — 주입된 섹션이 그 뒤 작업 전체의 근거가 되기 때문이다.

**ff 가 안 되면** 스킬과 앱은 손을 뗀다. 터미널에서 `git pull --rebase`. merge · rebase · 충돌
해결을 기계가 하지 않는다 — 섹션 두 갱신을 섞으면 그 결과가 정본 자리에 앉는다.

**안 보낸 커밋은 남에게 존재하지 않는 것과 같다.** `cdp-save` 가 push 까지 하지만, 원격이
거부했거나 네트워크가 끊겼으면 상태바의 `⬆ 미전송 N건 보내기` 로 남는다.

### 9.2 서버형 — 서버가 언제나 최신이다

pull 이 없다. 그 대신 `save` 의 `applied` 가 **낙관적 잠금**이다 — 내가 섹션을 읽은 뒤 남이
같은 섹션을 갱신했으면 `E_CONFLICT` 로 거부되고, 거절에 실려 온 지금 본문(`detail.content`) 위에
다시 만든다(§6.5). 다른 섹션이면 서로 막지 않는다 — 서버가 `save` 를 한 줄로 세워 차례로 커밋한다
(실측 — 다섯이 같은 순간 눌러도 전부 커밋 · 건당 약 2초). 미러 push 는 서버가 한다 — 밀리거나
갈라지면 `save` 의 `warnings` · 화면 아래 상태바 · `brief` 가 말하고, 푸는 것은 관리자다(관리자 설명서 7.6).
**섹션 점유("누가 편집 중")는 없다** — 같은 좌표를 동시에 건드릴 걱정은 일감 분배의 문제다.

### 9.3 결정이 안 났으면 — 여기 쓰지 않는다

**`미결` · `제안` · `진행중` 이라는 상태는 없다.** 지식 레포의 기록은 작업의 **완료**에서
발생한다. 끝나지 않은 일은 아직 기록할 사실이 없고, 결정을 기다리는 것은 아젠다다.

아젠다는 `docs/위험및이슈관리대장.md` 로 간다. 좌표는 `issue:<번호>`.

```markdown
## ISS-002 — A10 고정 작성자 계정 생성
<!-- applied: null -->

- **제기** 2026-09-02 · 홍은택
- **결정권자** A10(더존)
- **상태** 회신 대기
```

판단이 끝난 부분과 안 끝난 부분을 가른다 — *"왜 이렇게 하는가"* 가 정해졦으면 그것은 기록이고,
남은 것이 남의 회신뿐이면 **그 회신 대기만** 대장으로 보낸다. 대장으로 보내되 작업 기록의
`touches` 에는 `issue:` 좌표를 남긴다 — 그래야 `ctx where issue:…` 가 왜 제기됐는지 찾는다.
**아젠다는 작성자가 관리한다.** 결정권자에게 가져가는 것까지가 작성자의 일이다. 알림은 없다.

## 10. 막혔을 때

### 10.1 먼저 치는 명령 다섯

```
bin/ctx check      커밋 가능한가.  오류가 있으면 exit 1
bin/ctx brief      지금 레포 상태 두 줄 (+ 번들이 90일 넘었으면 한 줄 더)
bin/ctx derive     정본 문서에 아직 안 채운 섹션
bin/ctx sync       원격과의 차이 · 훅 설정 여부
bin/ctx version    이 번들이 언제 만들어졌나
```

서버형은 에이전트에게 *"cdp 상태 봐줘"* 라고 하면 `brief` · `check` · `derive` 도구가 같은 것을 낸다.

**로그** (로컬형) — `%LOCALAPPDATA%\cdp\logs\app.log`. exe 옆에 빈 파일 `cdp.portable` 을 두면
`<exe폴더>\data\logs\app.log`. 서버형의 로그는 관리자가 본다.

### 10.2 기록 · 커밋이 막힌다

| 증상 | 원인 | 고침 |
|---|---|---|
| `관리 문서 파생 누락` | 좌표를 건드렸는데 정본 섹션을 안 채웠다 | §6.4 · `ctx apply <좌표>` |
| `_vocab.md 미등재 좌표` | 어휘에 없는 좌표를 썼다 | §5.4 — 한 줄 추가 |
| `등록부가 가리키는 섹션이 없음` | 등록부는 자리를 아는데 문서에 그 섹션이 없다 | 섹션을 만든다. 앵커 형태 그대로 |
| `status: 미결·제안` | 아젠다를 기록에 뒀다 | §9.3 — 이슈 대장으로 |
| `프론트매터 YAML 오류` | 제목이 `[` `{` `&` `*` 로 시작하거나 `: ` 포함 | 따옴표로 감싼다 |
| `id ≠ 파일명` | 둘이 다르다 | 맞춘다 |
| **커밋은 되는데 검사가 안 돈다** (로컬형) | `core.hooksPath` 미설정 · 훅이 CRLF | `git config core.hooksPath .githooks` · 관리자에게 |
| `E_CONFLICT` (서버형) | 그 사이 남이 같은 섹션을 갱신 | 거절의 `detail.content` 위에 ④ 다시 · `applied` 는 `detail.current` (§6.5) |
| `E_GIT` `dirty` (서버형) | 서버 트리에 커밋 안 된 변경 | 관리자 — 콘솔 > 지식 레포 > 「트리 되돌리기」. 보낼 것은 그대로 |
| `E_FORBIDDEN` (서버형) | `writer` 역할이 아니다 | 관리자에게 — 권한은 명부의 사람에 붙는다 |

### 10.3 연결이 안 된다

| 증상 | 원인 | 고침 |
|---|---|---|
| `/mcp` 에 `cdp` 가 없다 | `.mcp.json` 이 없다 | 서버형: pull 또는 `[설치 방법]` 의 한 줄 · 로컬형: `ctx setup` |
| `cdp` 가 **failed** (서버형) | `CDP_TOKEN` 이 비었거나 새 터미널이 아니다 · 서버가 안 뜬다 | `echo %CDP_TOKEN%` · Claude Code 재시작 · `curl http://<서버>:7374/healthz` |
| `cdp` 가 **failed** (로컬형) | `.mcp.json` 의 지식 레포 경로가 틀렸다 · `bin/ctx` 가 없다 | `ctx setup` 을 다시 · `bin\ctx version` |
| 로그인 401 · 도구가 `E_AUTH` | 토큰 오타 · **만료(기본 90일)** · 관리자가 폐기 · 비활성 | 관리자에게 새 토큰 — 화면은 이유를 구분해 주지 않는다(의도다) |
| **토큰을 잃었다** | 토큰 원문은 어디에도 저장되지 않는다 | **새로 받는다.** 관리자가 콘솔에서 [재발급] — 옛것을 폐기하고 새것을 낸다. 30초. 권한은 그대로다 |
| 로그인은 되는데 "볼 수 있는 지식 레포가 없습니다" | 명부의 `repos` 가 비었다 | 관리자에게 |
| 레포 목록에 레포가 안 보인다 | 권한 밖(회색으로도 안 보인다) · 방금 세운 레포(1분 안에 뜬다) | 관리자에게 · 1분 뒤 |
| `[CDP] 번들이 N일 됐다` (brief 첫 줄) | `bin/ctx.mjs` 가 90일 넘었다. 옛 판정을 낼 수 있다 | 로컬형: 관리자에게 새 배포본 · 서버형: 관리자가 `upgrade.sh` |
| `ctx: 모르는 명령` | 번들이 낡았다 | `ctx version` 확인 → 관리자에게 |
| 새 판이 올라갔다는데 화면이 옛것 · 어긋난다 | 브라우저가 옛 화면 파일을 갖고 있다 | `Ctrl+Shift+R` 강제 새로고침 한 번. 로그인 · 토큰은 그대로(8.9) |

### 10.4 Node 가 없어도 된다

`bin/ctx` 가 알아서 넘긴다 — node 가 있으면 `node bin/ctx.mjs`, 없으면 `tools/cdp.exe ctx`,
둘 다 없으면 그 사실을 말하고 멈춘다(exit 127). exit code 까지 같아서 git 훅도 그대로 돈다.

### 10.5 스킬을 못 부르면

`.claude/skills/*/SKILL.md` 는 **사람이 읽는 마크다운이다.** 열어서 붙여넣어도 동작한다.
사람만 있어도 된다 — `bin/ctx where <좌표>` 가 그 좌표의 지금 상태를 알려 주고, `docs/` 를
직접 읽으면 된다.

작업 레포의 `.claude/skills/cdp-*` 에 있다. 에이전트가 요청을 보고 고른다 — 이름을 부를 필요는 없다.

|---|---|---|
| `cdp-work` | 테이블 · 화면 · API · 용어 · 코드값의 **현재 상태를 알아야 하는 요청** | ① 검토 → ② 주입 → ③ 수행 |

| `cdp-import` | 회의록 · 검토서 같은 **밖에서 온 md** 를 들일 때 | 원문 보존 · 사건의 날짜 · 관리 문서 갱신 |
| `cdp-edit` | 코드 작업 없이 **관리 문서만 고치라는 지시** | 문서 수정 + 지시를 기록으로 |

| `cdp-push` | *"푸시해"* · *"커밋해"* — **사람이 부를 때만** | 이 세션이 만진 파일을 그 레포에 커밋 · push. 기록은 안 만든다 |

## 부록 B. MCP 도구 13종

`cdp` 서버의 도구다. 스킬이 부르고, 사람도 에이전트에게 말로 시킬 수 있다. `ctx <명령> --json`
과 결과가 바이트까지 같다.

| 도구 | 무엇 | 로컬형 | 서버형 |
|---|---|:--:|:--:|
| `match` | 이름 · alias · 자유 표현 → 정본 좌표. `미등재` 면 어휘에 없다. 레포를 안 주면 든 레포 전부 대조 | ○ | ○ |
| `where` | 좌표의 지금 상태가 어느 문서 어느 섹션에 · 마지막 반영 · 건드린 작업들 | ○ | ○ |
| `section` | 그 좌표의 관리 문서 **섹션 본문만**. 없으면 `body: null` | ○ | ○ |
| `work` | 작업 기록 본문 — "왜 그렇게 정했나" | ○ | ○ |
| `search` | 말 → 좌표 후보. `match` 가 미등재를 낼 때의 폴백. 유사도 검색이 아니다 | ○ | ○ |
| `derive` | 파생이 남은 섹션과 깨진 섹션 | ○ | ○ |
| `apply` | 파생할 섹션에 붙일 변경 줄 초안. 파일은 안 고친다 | ○ | ○ |
| `check` | 커밋 가능한가 — 훅과 같은 검사 | ○ | ○ |

| `brief` | 두 줄 요약 + 번들 나이 경고 | ○ | ○ |

| `version` | 번들이 언제 만들어졌나 | ○ | ○ |
| `save` | 작업 기록 1 + 섹션 N + 신규 어휘를 **한 번에** 검사 · 커밋 · 미러 | — | ○ (`writer`) |

## 부록 C. `ctx` 명령 — 사용자가 치는 것

지식 레포 안의 `bin/ctx` (Windows 는 `bin\ctx.cmd` 또는 `tools\cdp.exe ctx`). 작업 레포에서
불러도 `.claude/cdp.json` 으로 지식 레포를 찾는다.

```
ctx check [--json]        커밋 가능한가.  오류가 있으면 exit 1
ctx brief                 두 줄 요약
ctx where <좌표...>        그 좌표의 상태가 어느 문서 어느 섹션에 · 얼마나 되나
ctx match <이름...>        이름 → 정본 좌표 (대조)
ctx search <말...>         말 → 좌표 후보
ctx term <이름>            어휘 조회 (정본 / alias / deprecated)
ctx derive [--json]       파생이 안 된 섹션 목록
ctx apply <좌표> [--json]  파생할 섹션에 붙일 변경 줄 초안
ctx sync [--pull]         원격과의 차이. --pull 은 ff 만 한다
ctx index                 INDEX.md · INDEX-by-coord.md 재생성 (훅이 커밋마다 한다)
ctx version               이 번들이 언제 만들어졌나
ctx setup <작업 레포>      (로컬형) 그 레포에 규약과 스킬을 넣는다.  --dry 로 미리보기
```

## 부록 D. 용어

| 말 | 뜻 |
|---|---|
| **지식 레포** | `_vocab.md` 와 `_managed.md` 가 있는 git 레포. 프로젝트당 하나 |
| **작업 레포** | 코드가 있는 레포. 여럿이어도 된다. 스킬과 규약 블록이 들어간다 |
| **좌표** | `<타입>:<값>`. 대상마다 하나. 두 층을 잇는다 |
| **작업 기록** | `work/<id>.md`. 사건. 불변 |
| **관리 문서** | `docs/*.md`. 상태. 좌표 하나에 섹션 하나 |
| **파생** | 작업 기록을 남긴 뒤 그 좌표의 관리 문서 섹션을 갱신하는 일. **필수** |
| **`applied`** | 섹션이 어느 작업 기록까지 실었는지 적은 한 줄 주석. 서버형에서는 낙관적 잠금 |
| **등록부** | `_managed.md`. 좌표 패턴 → 정본 문서 · 섹션. 관리자만 고친다 |
| **어휘** | `_vocab.md`. 좌표의 이름표와 alias. 사용자가 추가하고 관리자가 정리한다 |
| **명부 · 토큰** | 서버형의 사용자 목록(권한은 여기)과 신원 증명. 토큰 원문은 저장되지 않는다 |
| **꾸러미(kit)** | `cdp-kit-<레포>.zip`. 작업 레포에 세팅을 넣는 실행기와 파일 |
| **훅** | `.githooks/pre-commit`. 커밋 직전 `ctx check`. 유일한 결정론적 보증 (로컬형) |
| **번들** | `bin/ctx.mjs`. 도구 한 파일. `ctx version` 이 만든 시각을 찍는다 |
| **서버형 / 로컬형** | 모드 B / 모드 A. 지식 레포가 서버에 있나 내 PC 에 있나 |
| **미러** | 서버가 `save` 뒤 origin 에 push 하는 것. `queued` 는 정상 |
