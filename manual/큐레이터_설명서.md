## 1. 큐레이터 폴더

큐레이션은 **큐레이터 폴더**의 Claude Code 에서 한다 — 레포마다 폴더 하나. git 레포가 아니어도 되고 작업 레포 대장에 오르지 않는다.
큐레이터를 맡기는 것은 admin 이다(서버 › 사람 · [서버 관리자 설명서](관리자_설명서.md)의 큐레이터 맡기기). 맡으면 왼쪽 메뉴에 **큐레이션**(대기열 · 진단)이 보인다.

**한 줄** — 화면 **레포 관리 › 현황** 맨 위 「시작하기」 의 「큐레이터 폴더가 없다」 줄이 셸에 맞는 한 줄을 준다. 그 폴더에서 붙여넣는다.

```
curl -fsSLo /tmp/cdp-install.mjs http://<서버>:7374/install.mjs && node /tmp/cdp-install.mjs --curator --repo <레포> .
ctx up ~/cdp/<레포> --curator <폴더>                                     # 개인 서버
```

**무엇이 일어났나** — 토큰을 찾고(`CDP_TOKEN` → `~/.config/cdp/token` · 없으면 묻는다) 그 레포의 큐레이터인지 확인한 뒤, 바뀔 것을 보이고 묻는다.
있는 `CLAUDE.md` · `.mcp.json` 은 병합한다. 이 PC 의 설치 목록에 남아 `--update` 가 같이 돈다.

```
.claude/skills/cdp-*   스킬 일곱 — cdp-work · cdp-save · cdp-push · cdp-curate · cdp-registry · cdp-rebuild · cdp-seed
CLAUDE.md              큐레이터 블록 — 승인 · 정본 · 기준선 규칙
.mcp.json · .claude/cdp.json   서버 /mcp/<레포> · Bearer ${CDP_TOKEN}
```

Claude Code 를 완전히 끄고 다시 켠다 → `/mcp` 에 `cdp` connected · 도구 13(writer 의 10 + `queue` · `forms` · `drift`).

**막히면** — 「이 토큰은 <레포> 의 큐레이터가 아닙니다」 면 admin 에게 청한다. 새 판에서 스킬이 바뀌면 「시작하기」 의 「에이전트 세팅이 바뀌었다」 줄 —
`--update` 한 줄이 작업 레포와 큐레이터 폴더를 같이 돈다. **작업 레포의 설치 한 줄은 누가 돌려도 writer kit** 이다 — 큐레이터 스킬은 큐레이터 폴더에만 간다.

## 2. 대기열 · 판정 재료

화면 **큐레이션 › 대기열** — 위 숫자(대기 · 가장 오래된 · 미반영 섹션 · 마지막 큐레이션) · 왼쪽 대기열(**오래된 순**) · 오른쪽 판정 재료.
**이력**은 같은 화면의 탭이다(§4.4).

| 칩 | 뜻 | 대개의 판정 |
|---|---|---|
| **섹션 n** | 그 좌표의 섹션이 있다 | 반영 |
| **섹션 없음 n** | 등록부에 패턴은 있는데 섹션이 없다 | 섹션을 세우며 반영 |
| **등록부 없음 n** | 그 타입을 받는 관리 문서가 없다 | 서식에서 새 문서 · 또는 기록으로 둠 |
| **좌표 0** | 기록에 좌표가 없다 | 대개 기록으로 둠 |

대기열에 서는 것은 **사람이 남긴 작업 기록 중 아직 판정 안 된 것**이다 — 큐레이션 · 기준선 · 등록부(`registry` · `docs-prune`) 기록은 서지 않는다.
가장 오래된 대기가 14일을 넘으면 「시작하기」 줄이 앰버가 되고 검사가 경고한다(`curation-stale` — 큐레이터 · admin 에게만).

기록 하나를 고르면 판정 재료가 뜬다(그 레포의 큐레이터만).

| 재료 | 쓰는 곳 |
|---|---|
| 반영 후보(섹션 있음) · 섹션 없음 · 등록부 없음 | 반영할 자리 · 세울 섹션 · 새 문서 후보 |
| 비슷한 서식 | 등록부 없는 타입의 서식 후보(§6) |
| **정본 후보** | 같은 좌표를 건드린 다른 대기 기록 — **같이 다룬다**(따로 하면 같은 섹션을 두 번 쓴다) |
| 본문에만 있는 좌표 | 기록이 그 대상을 바꿨으면 판정표에 적는다 · 언급이면 둔다 |

에이전트는 같은 재료를 도구로 읽는다 — `queue({ repo })` 대기열 · `queue({ repo, id })` 재료(`coords` · `unregisteredTypes` · `bodyOnly` · `together`) ·
`work({ id })` 본문(**오래된 기록부터** — 추가 뒤 이름을 바꾼 경우 최신만 읽으면 추가를 놓친다) · `section({ coord })` 의 `content` · **`applied`(잠금 값 — 그대로 보낸다)** ·
`baseline` · `pendingRecords` · `refs` · `form`.

**기록이 홀로 서지 못하면 지어내지 않는다** — 「섹션 X 참조」 · 값 없는 「정했다」 면 작성자에게 묻고 대기열에 남긴다.

## 3. 판정 셋

| 판정 | `verdict` | 언제 | 보낼 것 |
|---|---|---|---|
| **반영** | `reflect` | 기록의 사실이 있는 섹션(또는 등록부 행만 있는 자리)에 들어간다 | `into: [좌표]` — 그 좌표들이 **같은 save 의 `sections`** 에 있어야 한다 |
| **새 문서** | `new` | 받을 문서가 없다 — 서식에서 세우고 반영한다 | `into` + `managed` 새 행(§6) |
| **기록으로 둠** | `keep` | 옮길 사실이 없다 — 경위 · 논의 · 사전 지식 · 버린 안 · 참조만 | `reason` 한 줄 |

- **판정은 기록 단위 · 미반영은 좌표 단위다** — `keep` 이면 모든 섹션에서, `reflect` · `new` 면 **`into` 의 좌표에서만** 미반영이 사라진다.
  그래서 기록의 `touches` 를 하나씩 본다 — 반영할 좌표는 전부 `into` 에, 아닌 좌표는 판정표에 까닭을. 이번에 다 못 다루면 그 기록은 판정에서 뺀다.
- **확신이 없으면 판정하지 않는다** — 남겨 두면 대기열과 섹션 옆에 계속 실린다. 모를 때 `keep` 을 쓰면 표시만 사라진다. 틀리게 채운 것은 아무도 모른다.
- 바뀐 게 없는데 좌표가 걸렸으면 — `reflect` 로 본문은 두고 경과 한 줄만(「컬럼 변경 없음 — …의 묶음 키로 쓴다」). 그것도 없으면 `keep`.
- **문서 수정 지시 기록** — 본문의 「지시 · 바꿀 것 · 확인한 것」 이 재료다. 지금 섹션이나 다른 기록의 이유와 어긋나면 반영하지 않고 지시한 사람에게 묻는다.
- 좌표 0 기록도 옮길 사실이 있으면 반영해도 된다(`into` 는 `touches` 밖이어도 된다) — `touches` 가 틀렸으면 작성자에게 정정 기록을 청한다.
- 등록부 밖 문서(회의록 · 가이드)에 옮길 것은 `edits`(§7.4)로 쓰고 그 기록은 `keep` · `reason: "<문서> 에 반영(edits)"`.
- 가장 늦은 판정이 이긴다 — 판정된 기록도 다시 다룰 수 있다.

**화면에서 하는 판정은 「기록으로 둠」 하나다** — 기록을 고르고(체크 여럿) **[기록으로 둠…]** → 사유(필수) → 한 커밋(50건까지).
반영 · 새 문서는 글을 쓰는 일이라 에이전트가 한다.

## 4. 한 바퀴 — 지시 복사에서 save 까지

### 4.1 한 줄

대기열에서 기록을 고르고 **[에이전트 지시 복사]** → 큐레이터 폴더의 Claude Code 에 붙인다. 고르지 않고 *"큐레이션해 줘"* 만 해도 된다(대기열 전부 · 오래된 순).

```
cdp-curate alpha
대상: 2026-0901-ERP-연계-사전조사
      2026-0908-ERP-연계방식-결정
정본 한 곳 · 본문 현재형 · 경과 한 줄. 판정표를 보이고 승인 뒤 save.
```

### 4.2 `cdp-curate` 가 도는 길

```
① 대기열 → ② 묶기(같은 좌표 · 같은 주제 · 섹션 50 이하가 save 하나) → ③ 재료 → ④ 판정 → ⑤ 쓰기(§5)
→ ⑥ save({ …, dryRun: true }) — 판정표 + 섹션 diff 를 보이고 승인 → ⑦ 같은 입력에서 dryRun 만 빼고 save → ⑧ 끝 보고
```

대기가 많으면 묶음 목록을 먼저 보이고 **하나씩** 승인받는다 — 큰 diff 는 승인이 형식이 된다.

### 4.3 판정표 — 승인하는 자리

```
【판정표】 큐레이션 — ERP 연계 기록 3건 · 섹션 3 · 새 문서 1
  2026-0901-ERP-연계-사전조사    keep     사전 조사 — 결론은 방향 결정 기록이 원천
  2026-0903-ERP-전문규격-초안    new      인터페이스:ERP-결의서전송(새 문서 · 서식 public-si/DE_501)
  2026-0908-ERP-연계방식-결정    reflect  인터페이스:ERP-결의서전송 · 이슈:ISS-007
  정본   전문 규격 → 인터페이스:ERP-결의서전송 (이슈는 결론 한 줄 + 좌표)
【등록부 변경】 인터페이스:* → docs/인터페이스정의서.md
【섹션 diff】 …   【dryRun】 통과
승인하시면 커밋합니다.
```

| 볼 것 | |
|---|---|
| 판정 | `keep` 의 사유가 「옮길 것이 없다」 인가(「모르겠다」 가 아닌가) |
| **정본** | 한 사실이 한 섹션에만 적히는가 · 대장(이슈 · 위험)이 설계서가 되지 않았나 |
| 등록부 변경 | 이름만 다른 중복이 아닌가 · 패턴의 타입이 기록이 쓴 타입인가 |
| 섹션 diff | 현재형인가 · 경과가 한 줄씩인가 · 근거 기록에 없는 값이 들어가지 않았나 |

`dryRun` 은 권한 · 판정 · 잠금 · 등록부 · 검사까지 돌고 커밋하지 않는다. **승인 전에는 커밋하는 save 를 부르지 않는다.**

### 4.4 무엇이 일어났나

save 한 번이 **큐레이션 기록 하나**를 남긴다 — id `YYYY-MMDD-큐레이션-<주제>` · `curates: [{ id, verdict, into?, reason? }]` · 본문은 판정표
(좌표는 **백틱 없이** — 백틱이면 「본문에만 있는 좌표」 경고). `touches` 는 없다(서버가 `touchesEmpty: 큐레이션` · 태그 `curate`).
**대기열 › 이력** 탭에 한 줄로 서고(누르면 판정표), 다룬 기록의 머리에 「반영됨 → 좌표」 · 「기록으로 둠(사유)」 이 뜬다.
끝 보고는 커밋 · 미러 · 판정 수 · 바뀐 섹션 · 세운 문서 · **남은 대기 n건 · 가장 오래된 m일** · 판정하지 않고 남긴 기록과 까닭이다.

## 5. 섹션 쓰기 규칙

```markdown
## bk_member_mst — 회원마스터
<!-- applied: 2026-1006-LN010-회원번호-직접입력 -->       ← 서버가 쓴다

도서관 회원. 회원번호는 대출 화면에서 직접 넣는다(`screen:LN010`) …   ← 정본 서술 · 현재형

<!-- cdp:baseline src="개발 DB pg_catalog" asof="2026-10-04" -->     ← 기준선 블록 · 생성기만
| 컬럼 | 타입 | … |
<!-- /cdp:baseline -->

**경과**
- 2026-10-06 [`LN010-회원번호-직접입력`](../work/2026-1006-LN010-회원번호-직접입력.md) `mbr_no` 를 화면 입력으로
```

헤딩은 `## <값> — <설명>`. 보내는 `body` 는 `section` 의 **`content` 를 고친 것** — 헤딩 · `applied` · 기준선 블록 없이(서버가 붙인다).

| 규칙 | |
|---|---|
| **정본 한 곳** | 사실은 정본 섹션에만. 다른 섹션은 한 줄 + 정본 좌표를 `` `좌표` `` 로 건다 — `section` 이 한 단계 따라가 같이 싣는다 |
| **홀로 선다** | 그 섹션만 읽고 대상의 지금을 안다 — 판단 · 표 · 규칙 · 값 · 제약. 경위 · 논의 · 대안은 기록의 것 |
| **현재형으로 다시 쓴다** | 날짜별로 덧붙이지 않는다. 뒤집힌 판단은 본문에서 지우고 경과에 한 줄 |
| **경과는 한 줄씩** | `- YYYY-MM-DD [<주제>](<상대경로>/work/<id>.md) 무엇이` — 추가만. 경과만 붙이고 본문을 안 고치면 반영이 아니다 |
| **기준선 블록은 손대지 않는다** | 블록 밖에만 쓴다 · 블록의 값을 서술에 다시 옮기지 않는다 · 틀렸으면 생성기 담당에게 |
| **근거보다 크게 쓰지 않는다** | 섹션이 근거 기록보다 몇 배 크면 지어낸 것이다 |
| **정본 자리가 없으면 가까운 좌표에 쓰지 않는다** | 새 좌표를 등재하고 섹션을 세운다 |

정본은 그 사실을 **가장 오래 책임지는 대상**의 섹션이다 — 규격이면 인터페이스 · 컬럼이면 테이블 · 뜻이면 용어.

| 종류(서식의 `kind`) | 섹션은 | 덮어쓰나 |
|---|---|---|
| **대상** — 테이블 · 화면 · 인터페이스 · 코드 | 현재 사양 — 표 · 규칙 · 예외 | 본문 덮어씀 · 경과만 쌓음 |
| **대장** — 이슈 · 위험 · 일정 | 고정 표 + **결론 한 줄** + 경과. 설계 서술 금지 · 진행상태는 서식의 어휘로만 | 표 · 결론 덮어씀 |
| **정의** — 용어 | 뜻 · 쓰임 · 관련 좌표 | 덮어씀 |
| **사건** — 회의록 · 보고서 | 결정 · 할 일만 | 추가만 |
| **서술** — 가이드 · 계획서 | 절을 고쳐 쓴다(등록부 밖이면 `edits`) | 고쳐 씀 |

대장 40줄 · 정의 25줄을 넘으면 서술이 들어간 것이다. 전후 예시는 큐레이터 폴더의 `.claude/skills/cdp-curate/종류별.md`.

- **`applied`** — `section` 이 준 값을 **그대로** 보낸다(낙관 잠금 — 그 사이 바뀌었으면 `E_CONFLICT`). 새 값은 서버가 `into` 의 가장 늦은 기록으로
  계산하고 뒤로 가지 않는다. 새 섹션은 `applied: null` · `heading: "<값> — <설명>"`.
- **링크 · 그림** — 그 문서에서 본 상대경로(`docs/X.md` 면 `../work/…`). 그림은 첨부를 올려(사용자 설명서 4.5) `save` 의 `assets` 에 —
  본문은 `![설명](../work/assets/<큐레이션 기록 id>/<이름>)`.

## 6. 서식에서 새 문서

화면 **레포 관리 › 관리 문서 › 문서 추가 › 서식집** 탭(큐레이터에게만). 관리 문서가 하나도 없으면 「시작하기」 가 여기로 보낸다.
왼쪽은 찾기 · 묶음 거름 · 목록(이 레포가 쓰는 서식은 「씀」), 오른쪽은 탭 셋 — **만들어지는 문서**(서버가 실제로 찍을 그대로) · 작성지침 · 예시(문서로 가지 않는다).
[에이전트 지시 복사] 가 `cdp-registry` 지시를 준다.

묶음은 서버 설치본의 `forms/` — `public-si`(공공 SI 산출물) · `agile-product` · `cloud-native` · `ai-service`. 팀 서식은 관리자가 `<data>/forms/<묶음>/` 에 둔다(같은 id 면 팀 서식이 이긴다).
문제가 있는 서식으로는 서버가 문서를 세우지 않는다 — 목록 · `ctx forms check` 가 말한다. 셸에서도 `ctx forms list` · `ctx forms show <묶음/번호>`.

**세우는 길**

1. **찾는다** — `forms({ repo, q })`. 재료의 「비슷한 서식」 · `unregisteredTypes` 가 좋은 말이다. `used: true` 면 그 문서가 이미 있다 — 거기 붙인다.
2. **읽는다** — `forms({ repo, form })` 의 `guide` — 「여기 적지 않는 것」 이 정본 자리를 정한다 · `coordValue` 가 좌표 값이 무엇인지 말한다.
3. **고른다** — 같은 이름이 묶음마다 있으면 묶음을 보고. **맞는 서식이 없으면 서식 없이**(`title` 만) — 억지로 고르지 않는다.
4. **보낸다** — 한 save 에 셋이 같이.

```
managed:      [{ pattern: "인터페이스:*", doc: "docs/인터페이스정의서.md", form: "public-si/DE_501" }]
sections:     [{ coord: "인터페이스:ERP-결의서전송", applied: null, heading: "ERP-결의서전송 — ERP 결의서 전송", body: "…" }]
work.curates: [{ id: "…", verdict: "new", into: ["인터페이스:ERP-결의서전송"] }]
```

서버는 `# <제목>` · 서식 표지 `<!-- cdp:form … -->` · `form:head` 첫 문단**만** 찍는다 — 예시 · 작성지침은 가지 않는다.
패턴의 타입은 **기록이 쓴 좌표의 타입**이다(서식의 `registry` 는 제안). 경로는 레포의 폴더 규약을 따른다 — `docs/` 밖 · `..` 는 거절.

## 7. 등록부 · 문서 구조 — `cdp-registry`

반영은 `cdp-curate`, **구조**는 `cdp-registry` — *"용어집 문서를 세워 줘"* · *"이 문서 이름 바꿔"* · *"안 쓰는 관리 문서 지워"*.
구조만 바꾸는 save 도 작업 기록 하나와 같이 간다 — `touches: []` + `touchesEmpty` 사유 · `tags: ["registry"]`(지우기는 `["docs-prune"]` — 이 태그라야 대기열에 안 선다) ·
본문에 왜 · 무엇이 어디로. 승인 게이트(dryRun → 【등록부 변경】 → 승인)는 §4 와 같다.

### 7.1 행 더하기 — `managed: [{ pattern, doc, form?, title? }]`

- **먼저 있는지 본다** — 이름만 다른 중복이 첫 부작용이다. 패턴은 타입 하나에 `type:*` 가 기본.
- 새 행이 걸리는 좌표를 이미 `touches` 한 기록이 있으면 섹션을 같이 보내야 한다(`E_INPUT { needSections }`) — `cdp-curate` 로 판정하며 한 save 에.
- 앞 행에 덮이는 패턴은 거절(`shadowedBy`) · 같은 패턴이 다른 문서에 있으면 `E_CONFLICT` `kind: managed`.
- 행을 더하면 거짓이 되는 문구(「<타입> 타입이 없다」 · 머리말의 「비대상」)를 서버가 `E_INPUT { lines }` 로 막는다 — 같은 save 의 `edits` 로 고치거나 `reviewed`.
- 새 행은 등록부 맨 끝에 붙는다 · 한 save 에 10건까지.
- **종류 칸** — 서식을 주면 서식의 종류(대상 · 대장 · 정의 · 사건 · 서술)가 「종류」 칸에 들어간다. 서식 없이 세우면 `kind` 를 같이 주고, 이미 있는 행은 `{ op: "kind", pattern, kind }` 로 칸만 바꾼다. 진단(§11)의 비대 잣대가 이 칸에서 온다 — 비어 있으면 모든 섹션을 40줄로 잰다.

### 7.2 이름 · 합치기 · 폐기 · 지우기

| | `managed` | 행 | 파일 | 언제 |
|---|---|---|---|---|
| 이름 · 위치 | `{ op: "rename", doc, to }` | 경로를 바꾼다 | 옮긴다 | 다른 문서 안의 링크는 경고 — `edits` 로 |
| 합치기 | `{ op: "merge", doc, into }` | `into` 로 | 지운다(섹션은 `into` 끝에) | 같은 이름의 섹션이 양쪽에 있으면 전부 되돌린다 |
| 폐기 | `{ op: "retire", pattern }` | 지운다 | 남긴다 | 그 타입의 섹션이 정말 더 안 쓰일 때만 — 검사를 끄는 수단이 아니다 |
| **지우기** | `drop` | 지운다 | **지운다**(git 이력에만) | 이 프로젝트에 필요 없는 문서 |

지우기는 화면 **레포 관리 › 관리 문서** 에서 — 거름(서식 그대로 · 쓰는 중 · 필수)으로 고르고 → 미리보기(지울 행 · 그 문서를 가리키는 다른 줄) →
줄마다 「행 지우기 · 링크만 풀기 · 알고 둔다」 → 사유 → 지우기. `_managed.md` 의 「지운 관리 문서」 표에 남는다.
반영된 섹션이나 `touches` 이력이 있으면 서버가 거절한다 — 안 쓰는 문서가 아니다(`merge` · `retire` 로). 산문을 고쳐야 하는 줄은 `cdp-registry` 가 낫다.

### 7.3 서식 예시 정리 — 옛 레포

옛 패키지로 세운 레포의 `example:` 어휘와 「(예시)」 섹션(검사의 `example-coord`)은 `save({ repo, work, examples: "purge" })` 한 번이 걷는다.
기록이 이미 쓴 예시 좌표는 표시만 뗀다.

### 7.4 섹션 밖 글 — `edits: [{ file, old, new }]`

문서 머리말(첫 `##` 앞) · 등록부 밖 문서 · `_vocab.md` · `_managed.md` 의 산문. `docs({ repo, doc })` 로 읽고 **지금 글 그대로**를 `old` 에 —
정확히 한 번 나와야 한다(바뀌었으면 `E_CONFLICT`). 지우려면 `new: ""` · 한 save 에 20건. 좌표 섹션 · `applied` · 어휘 줄 · 등록부 행은 못 건드린다(서버가 갈 곳을 말한다).

### 7.5 어휘

큐레이터의 save 로도 어휘는 **더하기만** 된다(`vocab: [{ coord, label, aliases }]`). 있는 좌표에 alias 를 더하거나 `deprecated` 표시는 서버 관리자에게.
새 좌표에는 aliases 를 넉넉히 — 그 대상을 **부르는 말**(줄임말 · 화면의 말 · 요구사항서의 말). alias 는 맥락 주입의 단일 실패점이다.

## 8. 기준선

섹션 안의 **추출 블록** — 코드 · DB · 매뉴얼에서 기계로 뽑은 사실(컬럼 표 · 프로그램 목록 · 코드값). **기준선 save 만** 블록을 통째로 갈아 끼운다(멱등).
기준선 기록은 대기열에 안 서고 미반영을 만들지 않는다 — 블록의 `asof` 가 신선도다. 한 save 에 기준선과 큐레이션을 섞지 않는다.

**한 줄** — 큐레이터 토큰(환경변수 `CDP_TOKEN`)으로 JSON 하나를 올린다. 생성기(뽑는 스크립트)는 프로젝트의 것이다 — 야간 크론이나 손으로.

```json
{ "source": "개발 DB pg_catalog", "asof": "2026-10-04",
  "managed": [{ "pattern": "테이블정의서:*", "doc": "docs/테이블정의서.md", "form": "public-si/DE_431" }],
  "vocab":   [{ "coord": "테이블정의서:bk_member_mst", "label": "회원마스터" }],
  "items":   [{ "coord": "테이블정의서:bk_member_mst", "heading": "bk_member_mst — 회원마스터", "body": "| 컬럼 | 타입 | … |" }] }
```

```bash
ctx baseline push 기준선.json --server http://<서버>:7374 --repo <레포>
curl -sS -X POST -H "Authorization: Bearer $CDP_TOKEN" -H "content-type: application/json" \
     --data-binary @기준선.json "http://<서버>:7374/api/<레포>/baseline"          # ctx 가 없으면
```

`managed` · `vocab` 은 처음 세울 때만. 한 커밋에 기준선 기록(`tags: [baseline]`)이 남는다.
옛 레포의 대상형 문서를 블록으로 옮기려면 `ctx baseline extract <옛 레포 clone> --doc <문서> [--form <묶음/번호>] > 기준선.json` — 사람 글까지 들어가므로
기계로 뽑을 수 있는 사실만 남기는지 보고 `push`.

## 9. 충돌 · 거절

| 응답 | 할 일 |
|---|---|
| `E_CONFLICT`(섹션) | 읽은 뒤 누가 바꿨다 — `detail.content`(지금 본문) **위에 다시 만들고 `applied` 에 `detail.current`** 를 넣어 dryRun 부터. 옛 본문을 다시 보내면 그 사람의 반영이 사라진다. `currentWork` · `currentCuration` 이 누가 무엇으로 바꿨나다 |
| `E_CONFLICT`(`edits`) | `old` 가 원문에 없다 — `docs` 로 다시 읽는다 |
| `E_INPUT` 「into … 가 sections 에 없다」 | 반영한 섹션을 같이(바뀐 게 없으면 `content` + 경과) · 아니면 `keep` |
| `E_INPUT` 「헤딩 줄」 · 「기준선 블록 표지」 | `body` 에 `##` 나 블록을 넣었다 |
| `E_INPUT` `needSections` · `lines` · `shadowedBy` · `kind: managed` | 등록부 행의 일 — §7.1 |
| `E_INPUT` 「큐레이션 · 기준선 · 옛 기계 기록이다」 | `curates` 에는 사람의 작업 기록만 |
| `E_EXISTS` | 큐레이션 기록 id 가 있다 — 다른 id |
| `E_CHECK` | **이 save 가 만든** 오류 — `detail.findings` 를 고쳐 다시(원래 있던 오류는 경고 — 그것을 푸는 것도 큐레이터의 일) |
| `E_FORBIDDEN` · `need: curate` | 이 레포의 큐레이터가 아니다 |
| `E_GIT` · `dirty` | 서버 관리자에게 「트리 되돌리기」 |

`section` → 쓰기 → `save` 가 짧을수록 충돌이 적다 — 묶음 하나씩 읽고 바로 보낸다. 섹션 점유는 없다 — 큐레이터가 여럿이면 문서나 주제로 나눠 맡는다.

## 10. 옛 레포를 넘겨받았을 때

v0.x 레포는 두 길로 왔다 — 어느 쪽인지는 서버 관리자가 정했다.

**기록만 옮겨 온 레포**(관리 문서가 엉망이던 레포) — 관리 문서 · 등록부 행은 오지 않았고 **옮긴 기록이 전부 대기열에 서 있다.**
① 대기열을 주제로 묶고(칩과 날짜) ② 묶음마다 서식집에서 깨끗한 문서를 세워 반영한다 — 첫 큐레이션이 레포의 모양을 정한다
③ 기계적 사실은 `ctx baseline extract` → `push`(§8) ④ 옛 레포(`<레포>_old`)는 참고로 읽되 정본은 새 레포에 다시 쓴다.
대기열이 0 이 될 때까지 미반영이 실리므로 읽는 사람이 기록을 잃지 않는다.

**제자리로 옮긴 레포**(`ctx migrate`) — 섹션이 뒤처져 있던 좌표의 기록만 대기열에 남았다. 남은 대기부터 다룬다. 옛 `**변경** · 날짜` 줄은
섹션을 다시 쓸 때 `**경과**` 로 · 머리의 관리번호 표 · `## 작성지침` 은 `edits` 로 걷는다 · 일지형 섹션은 현재형으로(`종류별.md`).

## 11. 다시 세우기 — 어긋남 진단 · `cdp-rebuild`

**대기열과 다른 일이다** — 정본은 반영된 뒤에도 시간이 지나며 어긋난다(미반영이 0 이어도). 진단하고 · 원천을 채우고 · 묶음으로 다시 쓴다.
「시작하기」 에 「어긋남 n」 줄이 뜨면 여기다.

### 11.1 진단 — 화면 「큐레이션 › 진단」 · 도구 `drift`

| 신호 | 뜻 | 손보는 길 |
|---|---|---|
| **근거 없음** | 그 좌표를 건드린 기록 · 스냅샷 · 기준선이 없는 섹션 — 기록만 옮겨 다시 세우면 사라진다 | 본문이 기록을 인용하면(「인용」) 그 기록의 좌표정정 · 아니면 스냅샷 |
| **복제 n** | 같은 산문 줄이 다른 섹션 n 곳에 | 정본 자리를 하나로 · 나머지는 좌표로 |
| **비대 n줄** | 대장 40 · 정의 25줄을 넘는다 | 경위는 기록으로 · 정책은 정본 섹션으로 |
| **큼 n줄** | 대상 · 서술 섹션이 150줄을 넘는다 | 하위 좌표로 쪼갤 안(`cdp-registry`) |
| **일지형** | 날짜별로 덧붙인 줄 | 지금의 상태로 다시 쓴다 |
| **좌표 없는 기록** | 정본과 만나지 않는다 | 좌표정정 기록 |

문서 화면에서도 섹션 제목 옆에 같은 신호가 점선 칩으로 보인다(큐레이터에게만).

### 11.2 원천 채우기 — 스냅샷

**정본 스냅샷**은 근거 없는 섹션을 서버가 **원문 그대로** 기록 하나로 뜬 것이다(섹션 하나에 하나 · 날짜는 그 섹션 줄의 마지막 커밋).
섹션은 바뀌지 않고 대기열에도 서지 않는다. 화면은 진단의 [근거 없는 섹션 스냅샷 뜨기](미리보기 뒤 확인 · 200 개씩), 셸은
`ctx rebuild snapshot --server <주소> --repo <레포> [--doc <문서>] [--dry]`. 기록을 인용하는 섹션은 기본으로 빠진다 — 좌표정정이 진짜 출처를 남긴다.

### 11.3 좌표정정 · 다시 쓰기

진단에서 좌표를 고르고 [에이전트 지시 복사] → 큐레이터 폴더에 붙인다. 순서는 늘 **원천부터**.

1. **좌표 보완** — 좌표 없는 기록을 20건 안팎씩 읽고 좌표정정 초안(`<원 id>-좌표정정` · 원 기록의 날 · `supersedes` · 빠진 좌표만)을 판정표로 → 승인 → save. 정정은 대기열에 선다.
2. **재유도** — 고른 묶음의 원천 전부(기록 · 스냅샷 · 기준선)에서 섹션을 다시 쓰고 지금과 견준다. **「사라지는 사실」**(지금 섹션에만 있는 문장)이 있으면 다시 쓰지 않는다 — 스냅샷부터.
3. **남기기** — 재큐레이션 save(`tags: [rebuild]` · 본문 끝에 진단 합계).

레포를 통째로 다시 세울 때는 그 **전에** 옛 레포에서 11.2 를 먼저 한다 — 옮긴 스냅샷이 새 레포의 대기열에 서므로 정본에만 있던 지식을 잃지 않는다.

## 12. 문서 레포에서 세우기 — `cdp-seed`

이미 산출물을 md 로 쓰던 git 레포(예: WBS 폴더의 정의서 · 설계서 · 회의록)가 있으면, 그 지금으로 관리 문서를 세우고 판단 문서를 작업 기록으로 들인다. **기계는 옮기기만 하고, 판정은 큐레이션이다** — 기록을 읽지 않고 반영하지 않는다.

**지도** — 문서 레포 루트의 `cdp-sources.json`. 문서마다 관리 문서 · 기록 · 들이지 않음, 좌표 타입 · 쪼개는 모양(`h2` · `whole` · `chapters`) · 서식 · 종류 · 별칭 · 그림 · 첨부, 기록마다 id · 날 · 바꾼 좌표. `ctx seed init` 이 뼈대를 짐작하고, 분류는 `cdp-seed` 스킬과 사람이 문서를 읽고 정한다(「초안」 이라는 이름은 미정이 아니다).

```
ctx seed check --from <문서 레포>                              # 지도 검사 — 오류 0 · 지도에 없는 md
ctx seed plan  --from … --server <주소> --repo <레포>           # 전 단계 dryRun
ctx seed apply --from … --server … --repo …                    # 기준선 → 관리 문서 → 기록 편입(다시 부르면 이어서 · 멱등)
ctx seed verify --from … --clone <지식 레포 클론>                # 섹션 대조 — 같음 · 형식 차이(intent) · 확인 필요 · drift
```

**세우는 흔적은 작업 기록이 아니다** — 이관 · 기준선 · 스냅샷 기록 대신 레포 뿌리의 `_seed.json`(`{ at, from, records, sections }`) 하나가 남는다. 함께 들인 기록은 판정 없이 반영됨(대기열 0) · 세운 섹션의 근거는 원천이다(drift 근거 없음 0). 그래도 묶음마다 기록을 한 번 읽는다 — **작업문서에만 있던 사실 · 산출물끼리의 모순 · 늦음**이 큐레이션이 찾아내는 몫이다(고치면 그 묶음의 큐레이션 save 가 seeded 를 덮는다).

**정본이 둘이면**(문서 레포도 계속 쓴다) 위키는 기록으로만 따라간다. 그 문서를 고친 세션이 작업 끝에 `ctx update` 로 업데이트 기록(바뀐 좌표 · 바뀐 줄 · **왜**)을 남기고(cdp-save 「원천 문서 레포를 고쳤으면」), 큐레이터는 그 기록을 판정한다. 주 1회 `ctx follow --from … --clone … --since <sha>` 가 기록 없는 커밋(누락)을 낸다 — 큐레이터가 문서 레포의 diff 를 보고 섹션을 직접 고치지 않는다(「왜」 없는 손 미러가 된다).

## 부록. 도구 · 스킬 · save 입력

| 스킬 | 언제 |
|---|---|
| `cdp-curate` | 대기열의 기록을 반영 — *"큐레이션해 줘"* · [에이전트 지시 복사] |
| `cdp-registry` | 등록부 · 문서 구조 — 서식에서 행 더하기 · 이름 · 합치기 · 폐기 · 지우기 · 예시 정리 · 섹션 밖 글 |
| `cdp-rebuild` | 어긋난 정본 — 진단 · 스냅샷 · 좌표정정 · 다시 쓰기 |
| `cdp-seed` | 기존 문서 레포에서 세우기 — 지도 · `ctx seed` · 정본 둘이면 `ctx follow` |
| `cdp-work` · `cdp-save` · `cdp-push` | writer 와 같다 — 사용자 설명서 |

**큐레이터에게만 보이는 도구** — `queue`(대기열 · `{ id }` 판정 재료) · `forms`(`{ q }` 목록 · `{ form }` 하나 — 찍힐 빈 문서까지) · `drift`(어긋남 진단). 나머지는 사용자 설명서 부록.

**save 입력 — 큐레이터만**(writer 가 보내면 `E_FORBIDDEN` `need: curate`)

| 입력 | 무엇 |
|---|---|
| `work.curates` | `[{ id, verdict: reflect · new · keep, into?, reason? }]` |
| `sections` | `[{ coord, applied, heading?, body }]` — 한 save 에 50 |
| `managed` | 행 `{ pattern, doc, form?, kind? }` · 종류 칸 `{ op: kind, pattern, kind }` · `{ op: rename · merge · retire · drop }` |
| `edits` | 섹션 밖 글 `{ file, old, new }` |
| `examples` | `"purge"` |
| `snapshot` | `[{ coord }]` — 정본 스냅샷 · 다른 쓰기와 섞지 않는다 |
| `baseline` | 기준선(보통은 `POST /api/<레포>/baseline`) |
| `dryRun` | `true` — 검사까지 돌고 커밋하지 않는다 |

예약 태그 `curate` · `baseline` · `transition` · `registry` · `docs-prune` · `derive` · `snapshot` 은 큐레이터의 것이다.
