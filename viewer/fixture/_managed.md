# 관리 문서 등록부

좌표가 어느 관리 문서의 어느 섹션에 대응하는지 **여기에만** 적는다.
매핑이 두 곳에 있으면 반드시 어긋난다.

| 좌표 패턴 | 관리 문서 | 섹션 |
|---|---|---|
| `table:*` | `docs/테이블정의서.md` | `## {값}` |
| `term:*` | `docs/DB도메인용어정의서.md` | `### {값}` |
| `code:*` | `docs/코드정의서.md` | `## {값}` |
| `screen:*` | `docs/화면설계서.md` | `## {값}` |
| `api:*` | `docs/인터페이스정의서.md` | `## {값}` |
| `req:*` | `docs/요구사항정의서.md` | `## {값}` |
| `proc:*` | `docs/프로세스정의서.md` | `## {값}` |
| `func:*` | `docs/기능정의서.md` | `## {값}` |
| `prog:*` | `docs/프로그램사양서.md` | `## {값}` |
| `batch:*` | `docs/프로그램사양서.md` | `## {값}` |
| `module:*` | `docs/프로그램사양서.md` | `## {값}` |
| `arch:*` | `docs/시스템아키텍처정의서.md` | `## {값}` |
| `issue:*` | `docs/위험및이슈관리대장.md` | `## {값}` |
| `test:*` | `docs/테스트케이스.md` | `## {값}` |
| `scenario:*` | `docs/테스트시나리오.md` | `## {값}` |

**패턴은 위에서부터 먼저 걸리는 것을 쓴다.**

## 등록부에 없는 좌표는 정상이다

**관리 문서는 자주 쓰는 내용을 하나로 모아 둔 것이다.** 모든 내용이 여기
녹지는 않는다.

| | 원천 |
|---|---|
| 자주 쓰는 내용 | 관리 문서 섹션 — 하나로 수렴시키고 그 대가로 갱신 부담을 진다 |
| 덜 쓰는 내용 | **그 지식공유문서 자체** — 하나로 모으는 부담이 이득보다 크다 |

`domain:` 이 그렇다. 업무 영역에는 "지금 상태"라고 적을 것이 없다 — 산출물이
아니라 **작업을 묶는 축**이다. 밀림·최신성 계산에서도 뺀다.

## 좌표가 없는 관리 문서

`회의록` · `프로그램목록` · `개발일정계획서` 는 관리 문서이되 등록부 대상이
아니다. 날짜·목록·일정 축이라 좌표-섹션이 1:1로 대응하지 않는다.
