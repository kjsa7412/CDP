# 지식 레포

프로젝트의 **"지금 어떤 상태인가"** 와 **"왜 그렇게 됐나"** 가 전부 여기 있다.
사람에게 묻지 않고 여기서 찾는다.

## 두 층

| | |
|---|---|
| `docs/` | **관리 문서** — 지금 어떤 상태인가. 테이블정의서 · 코드정의서 · 용어집 · 화면정의서 |
| `work/` | **작업 기록** — 무슨 일이 있었나. append-only · 자유 형식 |

`_managed.md` 가 좌표 → 문서·섹션 매핑이고, `_vocab.md` 가 정본 이름과 별칭이다.

## 5분 안에 시작하기

**1. 앱을 띄운다** — `tools/cdp.exe` 더블클릭 *(없으면 `npx cdp`)*
**2. 이 폴더 경로를 넣는다**
**3. 화면 셋을 본다**

```
대상  Ctrl+1   좌표 -> 지금 상태 + 그것을 바꾼 작업
작업  Ctrl+2   시간순 작업 기록
현황  Ctrl+3   밀린 섹션 · 미결 · 진행중
Ctrl+K         검색.  별칭으로도 걸린다
```

**4. 커밋할 사람은 한 번 더 한다**

```
git config core.hooksPath .githooks
```

훅은 clone 을 따라오지 않는다. **이걸 안 하면 검사가 조용히 통과한다** —
커밋은 되는데 미등재 좌표가 그대로 들어간다.

## 작업할 때

프로젝트 세션에서 요청하면 AI 가 **cdp-work** skill 로
① 검토 → ② 맥락 주입 → ③ 요청수행 순서로 처리한다.

작업이 끝나면 **cdp-save** 로 기록하고 커밋한다. **push 는 사람이 누른다.**

**자세한 것은 [MANUAL.md](MANUAL.md).** 2장(작업 절차)과 3장(좌표 붙이기)이
가장 길다 — 그 둘이 갈리면 나머지가 무의미해진다.

## 터미널에서

```
bin/ctx brief                     지금 레포 상태 두 줄
bin/ctx where table:rp_plnd_mst   그 좌표의 상태가 어디 있나
bin/ctx match "면접심사의견등록"    이름 -> 정본 좌표
bin/ctx stale                     밀린 섹션
bin/ctx check                     커밋 가능한가 (오류면 exit 1)
bin/ctx sync                      원격과의 차이 · 훅 설정 여부
```

**Node 가 없어도 된다** — `bin/ctx` 가 알아서 `tools/cdp.exe` 로 넘긴다.

## 지금 이 레포의 상태

**일부러 어긋나 있다.** 정상 데이터만으로는 도구가 무엇을 하는지 검증할 수 없다.

| 심어둔 것 | 어디 |
|---|---|
| **밀린 섹션** | `ps_ext_emp_mst` · `rp_pre_rview_opl_list` · `expense-slip` · `SEC011` · `SEC014` |
| 빈 섹션 | `applied: null` 인 것들 |
| 미등재 좌표 | `batch:project-status-nightly` — **커밋이 거부된다** |
| **앵커 없음** | `screen:SEB020` 을 쓰는데 화면정의서에 그 섹션이 없다 — **거부** |
| 등록부 없는 타입 | `module:` · `domain:` — **정상이다** |
| 좌표 0개 | `2026-0630-통합테스트-1차` |
| 미결 · 진행중 | 연심회 상태값 · 계획서변경 |
| 오기재 정정 | `2026-0902-업무이력-오기재` ← `2026-0903-업무이력-상태분리` |

**좌표별 판정이 갈리는 것을 보려면** `2026-0821-면접심사의견-개편` 을 열어라.

```
screen:PSC043           최신          화면정의서_인사 반영됨
table:ps_ext_emp_mst    이후 1건      테이블정의서 밀림 1건
code:PS130              최신          코드정의서 미작성      <- 이게 핵심
domain:인사채용          (계산 제외)
```

**세 좌표가 같은 문서에 있는데 판정이 다 다르다.** `code:PS130` 이 특히 중요한데 —
이 문서가 그 좌표의 최신인데도 **코드정의서에 가면 없다.** 문서 단위로 판정하면
이것을 "최신"이라고만 말하고 끝난다.

`design/` 에 설계서 사본이 있다 — 왜 이렇게 만들었는지가 거기 있다.
