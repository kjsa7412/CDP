# cdp-work — 요청 하나를 CDP 절차로 수행한다

이 skill 은 **요청 하나**를 세 단계로 처리한다. 순서를 바꾸지 말고, 단계를 건너뛰지 마라.

```
① 검토       요청을 이해하고 대상을 뽑는다.  지식 레포 본문은 읽지 않는다
② 주입       필요하면 관리 문서 섹션을 읽어 맥락으로 삼는다
③ 요청수행   주입된 상태를 근거로 요청을 수행한다
```

**요청된 작업이 우선이다.** 절차는 그것을 돕는 것이고, 절차 자체가 산출물이 되면 실패다.

## 준비 — 지식 레포 위치

지식 레포는 프로젝트 레포의 `CLAUDE.md` 에 경로가 적혀 있다. 없으면 상위 폴더에서
`_vocab.md` 와 `_managed.md` 를 가진 폴더를 찾는다. 그래도 못 찾으면 **사용자에게 묻고 멈춘다** —
경로를 모르면 이 skill 이 할 수 있는 것이 없다.

이하에서 `<repo>` 는 그 경로다.

---

## ① 검토

### 하는 일

1. **요청을 한 줄로 요약한다.** 무엇을 해달라는 것인가.

2. **대상 후보를 뽑는다.** 요청문·`git diff`·열려 있는 파일에서 이름을 긁는다.
   테이블명·화면 코드·API 경로·모듈명·도메인 용어·코드그룹.

3. **이름을 정본 좌표로 대조한다.**

   ```
   <repo>/bin/ctx match "면접심사의견등록" "PS130" "서류심사"
   ```
   ```
   면접심사의견등록  ->  screen:PSC043  (이름 일치 · _vocab.md:70)
   PS130             ->  code:PS130     (값 일치 · _vocab.md:112)
   서류심사          ->  screen:PSC031  (alias 일치 · _vocab.md:68)
   ```

   **Node 가 없어도 된다** — `bin/ctx` 가 `tools/cdp.exe` 로 넘긴다.
   `(미등재)` 로 나오면 어휘에 없는 것이다. 그대로 두고 ①의 출력에 적어라 —
   커밋 때 `ctx check` 가 막는다. 여기서 임의로 다른 좌표로 바꾸지 마라.

   **폐기 좌표를 쓰면 후속을 알려준다.** 그러면 후속 좌표를 쓴다.
   ```
   연심회의견상세  ->  table:rp_rdc_opl_dtl  [폐기 2026-03-26 -> table:rp_rdc_opl_mst]
   ```

   `bin/ctx` 가 아예 없는 레포라면 `_vocab.md` 를 직접 읽어 대조한다.
   그 파일은 사람이 읽는 마크다운이고 `aliases:` 줄에 별칭이 있다.

4. **각 대상이 좌표인지 판정한다.**

   | 이 작업이 그 대상을… | 좌표 |
   |---|:--:|
   | 신설했다 | **O** |
   | 변경했다 (컬럼 추가, 규격 변경, 상태값 추가) | **O** |
   | 삭제·폐기했다 | **O** |
   | 참조했다 · 호출했다 · 언급했다 | **X** |
   | 그것을 쓰는 다른 것을 만들었다 | **X** |

   판정 기준은 하나다 — **6개월 뒤 그 대상을 맡은 사람이 이 작업을 찾아야 하는가.**
   "주제인가?"는 답이 갈리지만 **"바꿨는가?"는 결판난다.**

5. **주입할 좌표를 정한다.** 좌표로 판정된 것 중, **그 대상의 현재 상태를 모르면
   요청을 수행할 수 없는 것**만. 애매하면 넣되 **후보를 늘리지 마라** — 많이 주입할수록
   요청의 해석이 그 맥락에 편향된다.

### 출력

**아래 형태로 4~6줄만 낸다.**

```
【검토】
요청  PSC043 면접심사의견등록에 심사위원 연대서명 출력물을 추가한다

대상
  screen:PSC043      변경   출력물 2종 추가
  code:PS130         ?      업무구분 코드를 쓸지 미정
  screen:PSC031      참조   첨부를 읽어오지만 PSC031 은 안 바뀜 → 좌표 아님

주입  screen:PSC043 · code:PS130
```

- **좌표 아닌 것도 적는다.** 무엇을 왜 제외했는지가 판정의 근거다
- 애매한 것은 **`?`** 로 두고 단정하지 마라
- 주입할 것이 없으면 `주입  없음` 한 줄

### 금지

- **`<repo>/docs/` 와 `<repo>/work/` 를 읽지 마라.** 이 단계에서 읽어도 되는 것은
  `_vocab.md` 와 `_managed.md` 뿐이다.
  어휘·등록부는 **이름표**라서 읽어도 요청 해석이 편향되지 않지만,
  관리 문서와 작업 기록은 **의견을 담으므로** 요청을 이해하기 전에 읽으면
  그 틀로 요청을 읽게 된다.

- **검토를 출력한 뒤 멈추지 마라.** 승인을 구하지 말고 바로 ②로 간다.
  판정이 틀렸으면 ③의 답변에서 드러나고 그때 사용자가 고친다.
  **모든 요청에 정지를 거는 비용이 잘못된 주입의 비용보다 크다.**

- **길게 쓰지 마라.** 검토가 답변보다 길면 절차가 작업을 잡아먹은 것이다.

### 압축·생략

| 상황 | |
|---|---|
| 사용자가 대상을 이미 명시 (*"PSC043 화면에…"*) | 대상 한 줄로 압축 |
| 좌표 후보가 0개 | `주입  없음` 만 적고 ③으로 |
| **요청이 크고 모호** (*"채용 쪽 정리해줘"*) | **여기서 되묻고 멈춘다.** ②③으로 가지 마라. 맥락 문제가 아니라 요청 문제다 |

## ② 주입

①에서 정한 좌표가 있을 때만 한다. 없으면 건너뛰고 ③으로 간다.

**`cdp-load` skill 을 부를 수 있으면 부른다.**

```
cdp-load screen:PSC043 code:PS130
```

**부를 수 없으면 `<repo>/.claude/skills/cdp-load/SKILL.md` 를 읽어 그 절차를 그대로 따른다.**
지시문이지 API 가 아니므로 사람이나 다른 LLM 도 따라갈 수 있다.

좌표 하나만 빠르게 보려면 `ctx where` 가 더 싸다.

```
<repo>/bin/ctx where table:ps_ext_emp_mst
```
```
  문서   docs/테이블정의서.md
  섹션   ## ps_ext_emp_mst
  상태   밀림 1건 (applied 2026-0821-면접심사의견-개편 까지만 반영)
```

주입 결과에서 **반드시 확인해야 하는 것**:

| | |
|---|---|
| **밀림** | 관리 문서 섹션이 밀렸다고 나오면 **그 사실을 ③의 답변에 포함하라.** 밀린 섹션은 낡은 것보다 나쁘다 — 확신 있게 틀린 답을 준다 |
| **좌표별 후속** | 작업 기록을 근거로 쓸 때, 그 기록의 어느 좌표 부분이 최신인지 따로 본다. "이 문서는 낡았다"가 아니라 "이 문서의 `table:X` 부분은 이후 3건이 더 있다" 로 판단하라 |
| **절단** | 매칭됐으나 주입되지 않은 것이 있으면 그것도 답변에 적는다 |

---

## ③ 요청수행

**주입된 상태를 근거로 요청을 수행한다.** 요청이 요구한 것이 코드든 답변이든 문서든 분석이든,
그것을 낸다. 이 단계에 정해진 산출물 형태는 없다.

지켜야 할 것 셋:

1. **주입된 것을 근거로 쓴다.** 관리 문서 섹션이 현재 상태이므로 그것과 어긋나게
   설계하지 마라. 어긋나야 한다면 왜 그런지 답변에 적어라.

2. **밀림·후속·절단을 답변에 옮긴다.** ②에서 확인한 것을 사용자가 알아야 한다.

   ```
   ⚠ 테이블정의서의 ps_ext_emp_mst 섹션이 2건 밀렸습니다.
      아래 설계는 밀린 상태를 기준으로 한 것이므로,
      2026-0902·2026-0903 작업 내용을 확인하는 것이 좋습니다.
   ```

3. **"왜"가 필요해지면 그때 작업 기록을 연다.** *"이 컬럼이 왜 nullable 이지"* 같은
   질문이 생기면 섹션의 변경 줄이 어느 작업 기록을 볼지 알려준다.
   ②에서 미리 다 읽지 않는다.

---

## 이 skill 을 다시 부르지 않는 경우

**작업 주제가 그대로면 다시 부르지 마라.** 이미 주입된 맥락을 쓴다.
매 턴 부르면 같은 섹션이 반복 주입되고 절차가 소음이 된다.

다시 부르는 것은 **작업 주제가 바뀔 때**다 — 다른 화면, 다른 테이블로 넘어갈 때.

## 작업이 끝나면

이 skill 은 **기록하지 않는다.** 요청 여러 개가 한 작업일 수 있으므로,
작업이 끝난 시점에 **`cdp-save` 를 따로 부른다.**

```
요청1 → cdp-work
요청2 → cdp-work
요청3 → cdp-work
        ──────────
        작업 종료 → cdp-save  (한 번)
```
