## 0.2 결정 ②와 ③의 충돌 해소

②는 *"현행 75~110건만 소급"*, ③은 *"558건 전량에 좌표 부여"* 다. **둘을 가르는
축이 하나 빠져 있었다.**

```
좌표 부여(touches)     — 그 작업이 무엇을 바꿨나.  사실의 기록
섹션 본문 실채움        — 정본 문서에 지금 상태를 적는 일.  판단이 필요
```

**앞의 것은 전량 하고, 뒤의 것은 현행 범위만 한다.** 이렇게 갈라야 두 결정이
동시에 성립하고, 동시에 **error 폭발도 막힌다.**

CDP 자신이 같은 방법을 쓴다 — 시드 생성기의 `fill_applied()` 는 *"작업 기록이
있는 섹션을 그 좌표의 최신 작업으로 채운다"*. 좌표를 붙이면서 `applied` 를
**그 좌표의 최신 기록으로 일괄 착지**시키면 `later(applied, 좌표)` 가 비어
파생 누락이 0 이 된다.

| | 전량 (558건) | 현행 범위 (약 100건) |
|---|---|---|
| `touches` 좌표 | **O** | O |
| 정본 섹션 `applied` | **일괄 착지** (최신 기록 id) | 실제 반영한 기록 id |
| 정본 섹션 본문 | 비어 있음 (제목·SoT 줄만) | **실제로 채운다** |

> ⚠ **이 착지에는 대가가 있다.** `applied` 는 최신인데 본문이 비어 있는 섹션은
> CDP 가 가장 경계하는 것이다 — *"안 채워진 섹션은 낡은 것보다 나쁘다.
> 최신인 척한다."* 그래서 **§4.8 의 미채움 표식**을 규약으로 둔다.
> 검사는 통과하되 읽는 사람과 `cdp-load` 가 그 사실을 본다.

셋 있고, 그것이 이관 작업량을 정한다.**

`status` 도 마찬가지다. `normStatus()` 는 `확정` 과 빈값만 지우므로

`미결` · `제안` 둘뿐(`AGENDA`). **막히지 않기 때문에 더 위험하다** — 그대로

# 제1부 — 이집이지가 CDP 전제와 다른 한 가지

**이것이 이 설계의 중심이다.** 여기를 틀리면 나머지가 전부 어긋난다.

## 1.1 CDP 의 숨은 전제 — 문서가 SoT 다

CDP 의 관리 문서 16종(테이블정의서·화면설계서·코드정의서…)은 **SI 프로젝트
산출물**이다. 그 세계에서는 **문서가 정본**이고 코드가 문서를 따라간다.
그래서 *"이 컬럼 왜 이렇게 생겼지"* 의 답이 테이블정의서에 있는 것이 옳다.

## 1.2 이집이지는 반대다 — 실측

| 대상 | 실제 SoT | 근거 |
|---|---|---|
| 팩터 존재·활성 | `ezipez_data/catalog/팩터.xlsx` 02·03시트 | 런북 §1 — *"xlsx 에 없으면 에셋도 빌드 대상도 안 생긴다"* |
| 팩터 가중치·산출 파라미터 | `factor` 스키마 **DB** | *"reload 가 절대 안 건드림 → SoT=DB"* |
| 수집원 83종 · 마스터 43종 | `data_admin` **DB** 직독 | `catalog/db_source.py:50-64` — `WHERE 활성=true` fail-fast |
| 스케줄 on/off | `ezipezdb_dagster_meta.public.instigators` | STATE/ops |
| 서비스 지역 | `mart.서비스지역` **DB** | STATE/region — *"regions.py 는 서울hidden 오도"* |
| 알림 KIND 24종 | 코드 + DDL | STATE/notification |

**이집이지의 "지금 상태"는 대부분 코드와 DB에 있다.** 그리고 그 사실을 이미
비싸게 배웠다 — `팩터.lock.json` 은 *"카운트 스텁"* 이 되어 2026-08-05 폐지됐고,
`web_front/public/data/factors.json` 은 *"수동 정준·재생성 금지"* 로 못 박혀
있으며, `regions.py` 는 DB와 갈라져 STATE 에 **오도한다**고 적혀 있다.

## 1.3 그래서 규칙 하나 — **정본 섹션은 SoT를 복제하지 않는다. 가리킨다**

정본 문서에 팩터 가중치 표를 옮겨 적는 순간 그것은 **네 번째 `lock.json`** 이
된다. CDP 불변조건 1·2 가 *"판정을 두 곳에 두면 갈라진다"* 라고 말하는 것과
정확히 같은 규칙이고, 이집이지는 그 규칙을 이미 세 번 위반해 봤다.

**섹션 규격을 둘로 나눈다.**

```
[규격 A — SoT 가 문서에 있다]        api: page: term: issue:
  ## <값> — <이름>
  <!-- applied: <작업id> -->
  (지금 상태를 여기에 적는다.  이것이 정본이다)
  ### 변경
  · YYYY-MM-DD [`작업id`](../work/…) 무엇이 바뀌었나

[규격 B — SoT 가 코드·DB에 있다]     factor: table: source:
  ## <값> — <이름>
  <!-- applied: <작업id> -->
  **SoT** `ezipez_data/catalog/팩터.xlsx` 03시트 · `factor.팩터_소분류.가중치`(DB)
  **확인** `GET /api/factors/subs?mid=E010`
  (값을 옮겨 적지 않는다.  여기 적는 것은 셋뿐이다 —)
  · 결착된 판단     왜 이 형태인가.  뒤집으려면 무엇을 알아야 하나
  · 함정            여기서 났던 사고.  같은 함정을 다시 밟지 않게
  · 배선 지점        이걸 바꾸면 어디를 같이 고쳐야 하나
  ### 변경
  · YYYY-MM-DD [`작업id`](../work/…) …
```

> **규격 B 가 이 이관의 발명이다.** CDP 원형에는 없다 — SI 전제에서는 필요가
> 없었기 때문이다. 그러나 CDP 의 원칙(*"원본이 하나여야 한다"*)에서 그대로
> 따라 나온다.
>
> 그리고 규격 B 는 **실제로 이집이지가 이미 쓰고 있는 형식**이다.
> `신규팩터_추가_런북` 의 "함정 카탈로그 26" 과 `STATE/factor.md` 의 ⛔·⭐
> 항목들이 정확히 이것이다. 다만 **좌표별로 나뉘어 있지 않아** 379줄 한 덩어리로
> 쌓여 있을 뿐이다.

스키마 포함 소문자 한글(`mart.마스터_단지`), API 는 라우트 원문 그대로.
*"같은 대상에 두 표기가 생기는 순간 좌표는 좌표가 아니다."*

## 2.2 `factor:` 를 세 레벨로 쪼개지 않는다

카테고리·중분류·소분류는 코드 길이(1/4/6자)로 **이미 구별된다.** 타입을 셋으로
나누면 `_vocab.md` 섹션이 셋이 되고 등록부 패턴도 셋이 되는데, 얻는 것이 없다.

## 2.3 `aliases` 의 원천 — 지어내지 않는다

CDP 는 *"그 작업에서 실제로 쓴 표현을 그대로 넣어라 — 나중에 지어낸 별칭은
아무도 안 쓴다"* 고 못 박는다. 이집이지는 **그 표현이 이미 문서에 있다.**

```
factor:I007   aliases: 대지지분, 세대당 대지지분, I007
factor:E010   aliases: 생활편의, E010
table:mart.마스터_단지   aliases: 마스터_단지, 단지마스터
```

초기 `_vocab.md` 는 **본문 언급 빈도 상위에서 기계적으로 뽑아** 초안을 만들고
사람이 정본명만 확정한다 (§5 Stage 2).

## 4.2 `work/` 는 평면이다 — 평면화 규칙

`layerOf()` 가 `work/` 하위 폴더를 인정하지 않는다(`assets/` 제외). `archive/`
의 5단 구조를 펴야 하고, **basename 충돌 19종**이 실측된다
(`README.md` · `TODO.md` · `00_인덱스.md` · `HANDOFF.md` …).

**규칙 — 날짜 + 출처 폴더 + 원래 이름**

```
archive/projects/이집이지_비교개편/02_구현_결과.md
   → work/2026-0612-비교개편-02_구현_결과.md

archive/dev/redesign/topnav, ticker/HANDOFF_HOME.md
   → work/2026-0605-redesign-HANDOFF_HOME.md
```

| | |
|---|---|
| 날짜 | 프론트매터 `date` → 없으면 **git 최초 커밋 날짜** → 그래도 없으면 폴더 맥락 |
| 출처 조각 | 원 폴더명에서 `이집이지_` 접두와 공백·쉼표 제거 |
| 충돌 시 | 출처 조각이 이미 다르므로 대부분 해소된다. 남으면 `-2` 접미 |

> **공백·쉼표가 든 파일명 7건은 반드시 고친다.** `topnav, ticker/` 같은 폴더는
> `bin/ctx`(sh) 와 훅에서 인용 없이 다뤄지면 깨진다. CDP 가 CRLF 로 두 번
> 물린 것과 같은 종류의 **조용한 실패**다.

## 4.3 파일명·`id` — `wiki/` 356건은 개명하지 않는다

검사는 `id !== fileId` 만 본다(§0.3). `2026-09-05_ops로그-주간검토-….md` 는
`id:` 를 같은 문자열로 두면 **그대로 통과한다.**

**개명하지 않는 이유가 더 크다** — 문서 간 상대 링크와 git 이력이 파일명에
걸려 있고, 356건을 개명하면 `kb lint` 가 이미 잡고 있는 링크 깨짐이 대량으로
늘어난다. CDP 의 `YYYY-MMDD-slug` 는 **규약이지 검사 대상이 아니다.**

```
wiki/2026-09-05_ops로그-….md  →  work/2026-09-05_ops로그-….md   (그대로)
work/2026-0908-새작업.md                                        (신규는 CDP 규약)
```

> ⚠ **127자짜리 파일명이 있다.** Windows `MAX_PATH`(260) 에서 깊은 경로와
> 합쳐지면 걸린다. CDP 는 폐쇄망 Windows 를 전제하므로, **150자 초과 파일명만**
> 잘라 개명한다(실측 3건).

## 4.5 `status` 11종 소거

**CDP 에서 `status` 는 쓸 값이 하나도 없는 필드다.** 상태는 **폴더 위치가 말한다.**

> 이 문서를 쓸 때는 `진행중`(점유) 하나가 남아 있었다. **v0.2.6 에서 그것도
> 폐지됐다** — 지식공유문서는 작업의 *완료*에서 발생하므로 "지금 만지고 있다"는
> 문서에 적을 상태가 아니고, 점유는 브랜치와 사람이 말한다. 이관에는 오히려
> 유리하게 작용했다: 아래 표의 17건을 `진행중` 으로 통일했다면 그 값들이 지금
> 전부 오류가 되어 다시 걷어내야 했을 것이다.

| 지금 | 건수 | 이후 |
|---|---:|---|
| `Done` `done` | 337 | **삭제** — `work/` 에 있으면 완료된 사건이다 |
| `current` | 82 | **삭제** — 그 내용은 `docs/` 섹션으로 간다 |
| `Not started` `In progress` `진행중` `partial` | 17 | **삭제.** (당초 `진행중` 통일 → v0.2.6 폐지로 **전건 삭제**로 바뀜) |
| `historical` `history` | 2 | **삭제** |
| `draft` `draft-needs-revision` | 3 | **삭제** + 본문에 미확정 표시. 결정 대기면 `issue:` 로 |
| `superseded` | 0 (배너만) | §4.6 |

> `Done`·`current` 는 **오류가 아니라서 그대로 두면 살아남는다**(§0.3).
> 남겨 두면 CDP 의 "상태는 없다" 모델과 이집이지의 4종 어휘가 한 레포에
> 공존하고, 그때 읽는 사람은 어느 쪽이 규칙인지 알 수 없다. **전건 소거한다.**

## 4.6 `superseded` — 배너는 남기고 판정은 계산에 넘긴다

| | CDP | 이관 후 |
|---|---|---|
| `supersedes` | **오기재 정정에만.** 판정이 아니라 참조 | 그대로 |
| 후속이 있다 | `later()` 가 **계산**한다 | 그대로 |
| **뒤집혔다** | 개념이 없다 | **배너를 본문에 남긴다** |

이집이지의 사고 1순위(*"뒤집힌 결정을 현행으로 오판"*)는 실재하는 위험이고,
`later()` 는 *"후속이 있다"* 까지만 말한다. **그래서 배너를 버리지 않는다** —
다만 프론트매터가 아니라 **본문 첫 줄**로 옮긴다.

```markdown
> ⚠️ **뒤집힘** (2026-06-14) — 액센트 iris(보라) 실험 → 딥그린 회귀 확정
> 현행: [`docs/보이스가이드.md`](../docs/보이스가이드.md)
```

`work/` 는 불변이므로(불변조건 3) **문서를 지우거나 옮기지 않는다.**
`archive/superseded/` 는 사라지고 배너만 따라간다. 실측 대상 1건.

## 4.8 미채움 표식 — §0.2 의 대가를 갚는 곳

`applied` 를 일괄 착지시킨 섹션은 **본문이 비어 있는데 최신으로 보인다.**
검사는 통과하지만 읽는 사람이 속는다. **한 줄로 못 박는다.**

```markdown
## E01004 — 베이커리
<!-- applied: 2026-0822-E01004-소급등재 -->
**SoT** `catalog/팩터.xlsx` 03시트 · `factor.팩터_소분류.가중치`(DB)
> 🔸 **이관 착지 — 본문 미작성.** 이 섹션은 좌표만 자리를 잡았고 내용은 아직
> 옮기지 않았다. 근거는 아래 `변경` 의 작업 기록이다.
```

`ctx check` 는 이것을 모르지만 **사람과 `cdp-load` 는 본다.**
`grep -c '🔸 이관 착지' docs/*.md` 가 남은 부채의 계량이 된다.

# 제5부 — 이관 순서

**순서가 실질이다.** 파생 누락이 error 인 이상, 좌표를 붙이는 시점과 훅을 켜는
시점을 틀리면 **아무 커밋도 못 한다.**

각 Stage 는 **다음으로 넘어가는 조건**을 갖는다.

| Stage | 하는 일 | 넘어가는 조건 |
|---|---|---|
| **0. 안전망** | 이관 브랜치 · 원본 태그(`pre-cdp`) · 전체 백업 | `git tag pre-cdp` 존재 |
| **1. 골격** | `work/` `docs/` `work/assets/` 생성 · `.gitattributes`(`eol=lf`) | — |
| **2. 어휘** | `_vocab.md` 초안(빈도 상위 기계 추출) → **사람이 정본명 확정** | 타입 10종 · 정본 중복 0 |
| **3. 정본 자리** | `docs/` 13종 생성 (제목 + 좌표 섹션 껍데기 + SoT 줄) | — |
| **4. 등록부** | `_managed.md` 7패턴 | — |
| **5. 이력 이관** | `wiki`·`archive`·`specs` → `work/` 평면화 · 프론트매터 변환 (§4.2~4.5) | 파일명 충돌 0 · `id`=파일명 전건 |
| **6. 좌표 소급** | `touches` 전량 부여 + `applied` 일괄 착지 + 미채움 표식 | **`ctx check` error 0** ← 여기가 관문 |
| **7. 훅 ON** | `bin/ctx.mjs` 번들 · `.githooks/pre-commit` · `core.hooksPath` | 시험 커밋이 통과 |
| **8. 본문 채움** | 현행 범위(약 100건) 섹션 실채움 · 미채움 표식 제거 | 표식 잔량이 목표 이하 |

> **6과 7 의 순서를 바꾸면 안 된다.** `ctx check` 가 error 0 인 것을 확인한
> 뒤에 훅을 켠다. 반대로 하면 첫 커밋부터 막히고, 그때 사람이 배우는 것은
> `--no-verify` 다 — CDP 불변조건 6 이 통째로 무너지는 경로다.

**Stage 5~6 은 스크립트가 한다.** 558건을 손으로 옮기지 않는다. 그러나
**Stage 2 의 정본명 확정과 Stage 8 의 본문 채움은 사람이 한다** — CDP:
*"틀리게 반영하느니 안 채운 채로 두라. 안 채운 것은 검사가 알려주고 틀리게
채운 것은 아무도 모른다."*

| `record` | **폐기** | `cdp-save` skill |
| `supersede` `archive` `promote` | **폐기** | 계층 이동이라는 개념 자체가 사라진다 (§3.3) |

**전량 폐기다.** 다만 `parse()`·`layer_of()` 는 **Stage 5 이관 스크립트의
재료로 쓴다** — `tools/kb.py` 를 `work/assets/` 로 옮겨 이관 사건의 첨부로
남긴다.

## 6.3 스킬 통합 — `ezipez-*` 와 `cdp-*`

| 기존 | CDP | 처분 |
|---|---|---|
| `ezipez-wiki-load` | `cdp-work` ① · `cdp-load` | **대체.** 좌표 기반이 STATE grep 보다 정확하다 |
| `ezipez-save` | `cdp-save` | **부분 대체.** 아래 |
| `ezipez-push` | (없음) | **존치** — CDP 는 push 를 사람이 누르게 두고 스킬이 없다 |
| `ezipez-factor-add` | (없음) | **존치** — 런북 드라이버. CDP 와 층이 다르다 |
| `ezipez-help` | (없음) | **존치** — 커맨드 안내 갱신 |

**`ezipez-save` 가 `cdp-save` 로 완전히 대체되지 않는다.** 기존 스킬은
**8개 코드 레포**의 커밋·푸시까지 한 벌로 묶는데, `cdp-save` 는 지식 레포
하나만 본다.

```
cdp-save        지식 레포:  pull → 좌표 판정 → 작업 기록 → 파생 갱신 → 한 커밋
ezipez-save     그 뒤에:    코드 8레포 커밋·푸시  (지식 레포 기록은 cdp-save 에 위임)
```

→ **`ezipez-save` 를 코드 레포 전용으로 좁히고, 지식 기록은 `cdp-save` 를
부르게 고친다.** 두 스킬이 같은 파일을 쓰면 반드시 갈라진다.

⚠ **`ezipez-factor-add` 는 Stage 9(기록)에서 `cdp-save` 를 부르도록 고쳐야
한다.** 그 런북이 만드는 것이 곧 `factor:` 좌표의 신설이다.

# 제7부 — 이관 후 일상

```
작업 요청 → cdp-work  ① 검토(_vocab.md 만 읽는다) → ② 주입 → ③ 수행
             ↑ 요청 여러 개가 한 작업일 수 있다
작업 종료 → cdp-save  지식 기록 + 정본 갱신 + 한 커밋
          → ezipez-save  코드 8레포 커밋·푸시
퇴근 전   → push (사람이)
```

**커밋을 막는 것 7가지** — 필수 필드 누락 · `id`≠파일명 · 미등재 좌표 ·
**정본 파생 누락** · 등록부가 가리키는 섹션 없음 · `applied` 유령 참조 ·
`status: 미결·제안`.

**결정이 안 난 것은 `docs/위험및이슈관리대장.md` 로 간다.** 이것이 이집이지가
얻는 새 규율이다 — 지금은 `보류/백로그` category 로 wiki 에 섞여 있고,
*"불변인 사건과 가변인 상태가 섞이면 둘 다 안 맞는다."*

| 5 | Stage 8 본문 채움의 완료 기준 | **결정됨 (03 §11.4 → §12.1)** — 아래 |

**8.1-5 결정 — 완료 기준 셋** (03 §11.4 에서 제안, §12.1 에서 충족)

1. **미채움 표식 0 을 목표로 하지 않는다.** 스냅샷에 원천이 없어 *작업 기록이
   원천*인 섹션이 61% 다. 목표는 **"근거가 있는데 안 채운 것" 0**.
2. **`현행_` 접두 0** — 단 개명 전에 그 문서의 좌표 모양 내용을 섹션으로 옮긴다.
   이름만 바꾸면 계량만 0 이 되고 내용은 그대로다.
3. **중복 0** — 좌표 섹션과 정본 문서에 같은 문장이 있으면 그것이 진짜 부채다.

> 3번이 이 이관에서 가장 자주 발동했다. 섹션을 채우자마자 같은 내용이 두 곳에
> 생겨 `현행_factor` 를 얇은 인덱스로 되돌리고(379→100줄) 파이프라인정의서의
> 원천별 블록을 포인터로 바꿔야 했다. **채움이 중복을 만든다** — 규격 B 가
> 존재하는 이유다(§1.3).
