# 제0부 — 이 분석의 전제

## 0.1 목표

```
① CDP 가 무엇을 어떻게 강제하는 방법론인지 확정한다
② 이집이지 지식문서가 지금 어떤 상태인지 숫자로 확정한다
③ 둘의 거리를 재고, 이관 시 운영자가 결정해야 할 것을 뽑는다
```

**②가 이 문서의 값어치다.** 이집이지 지식베이스는 "정리되지 않은 문서 더미"가
아니다 — 이미 2계층 모델·통제어휘·검증계약·린터를 갖춘 **자체 방법론이 있고
문서화까지 돼 있다**(`CONVENTIONS.md`). 따라서 이관은 "무에서 도입"이 아니라
**두 방법론의 병합**이고, 어디가 겹치고 어디가 어긋나는지가 실질이다.

## 0.2 범위 밖

이 문서는 **이관 설계가 아니다.** 좌표 타입 확정·등록부 확정·이관 순서·실행은
다음 문서(`02_이관설계`)가 다룬다. 여기서는 **결정이 필요한 자리만 지목**한다.

# 제1부 — CDP 방법론 해부

## 1.1 푸는 문제

세 질문의 답이 사람 머리·채팅 로그·흩어진 문서에 있다는 것.

```
"이 컬럼 왜 이렇게 생겼지"           → 지금 상태를 묻는다
"왜 그렇게 정했지"                   → 그때의 판단을 묻는다
"내가 이걸 바꾸면 누가 알아야 하지"   → 영향을 묻는다
```

그리고 **검색으로는 안 된다**는 진단 — 같은 대상을 사람마다 다르게 부르고
(`PS_EXT_EMP_MST` · 외부인원마스터 · 외부심의위원테이블), 안 걸리면 "없다"가
된다. RAG·임베딩은 더 나쁘다 — **"없는 것"을 "비슷한 것"으로 채운다.**

## 1.2 첫 번째 설계 결정 — 두 층

```
work/   작업 기록 — 사건.  일어났다.  고치지 않는다.  계속 쌓인다
docs/   정본 문서 — 상태.  지금 이렇다.  덮어쓴다.  하나뿐이다
```

| | `work/` | `docs/` |
|---|---|---|
| 성질 | 불변 사건 | 가변 상태 |
| 개수 | 좌표당 N개 | 좌표당 1개 (섹션) |
| 답하는 질문 | **왜** 그렇게 정했나 | **지금** 어떻게 생겼나 |
| 낡는가 | 안 낡는다 | 갱신 안 하면 낡는다 |

## 1.3 두 층을 잇는 것 — 좌표

```
table:ps_ext_emp_mst
  ↑        ↑
 타입      값
```

- **통제 어휘 `_vocab.md`** — 정본 하나 + `aliases` 여럿. `## <타입>` 섹션의
  **선언 순서가 곧 카테고리 순서**다(알파벳 재정렬 안 함).
- 샘플 레포 기준 타입 9종 — `table` `screen` `api` `module` `term` `issue`
  `batch` `code` `domain`.
- **삭제하지 않는다.** 폐기는 `deprecated:` + `supersededBy:` 로 표시한다 —
  지우면 그 이름을 쓰던 과거 문서가 검색에서 사라진다.

**좌표를 붙이는 기준은 하나다 — 바꾼 것만.** 참조·호출·언급은 아니다.
판정 기준: *"6개월 뒤 그 대상을 맡은 사람이 이 작업을 찾아야 하는가."*

> *"주제인가?"* 는 답이 갈린다. **"바꿨는가?" 는 결판나고 diff 로 확인된다.**
> 그래서 후자를 기준으로 삼았다. **없는 좌표보다 억지 좌표가 나쁘다** —
> 그래서 `touches: []`(0개)를 정상으로 두고 오류로 막지 않는다.

## 1.4 등록부 — "이건 정본으로 관리한다"는 결정

`_managed.md` 가 좌표 패턴 → 문서 · 섹션 앵커를 정한다. 샘플 기준 **패턴 15행 →
문서 13종**, 여기에 좌표를 안 갖는 3종(회의록·프로그램목록·개발일정계획서)을
더해 **관리 문서 16종**.

```
| table:*  | docs/테이블정의서.md    | ## {값} |
| screen:* | docs/화면설계서.md      | ## {값} |
| issue:*  | docs/위험및이슈관리대장.md | ## {값} |
```

**가장 자주 오해되는 지점** — 초기 설계는 *"모든 좌표는 관리 문서 섹션을 가져야
한다"* 고 썼고, **그것이 틀렸다고 명시적으로 정정됐다.**

```
등록부에 있다   → 정본 문서 섹션이 지금 상태다.  갱신이 필수다
등록부에 없다   → 그 작업 기록 자체가 원천이다.  정상이다
```

그래서 앱은 *"관리 문서가 없다"* 가 아니라 **"원천 — 지식공유문서 N건"** 이라고
말한다. `domain:` 은 **바꾸는 대상이 아니라 작업을 묶는 축**이라 등록부에도 없고
최신성 계산에서도 뺀다.

## 1.5 계산은 하나다 — `later(기준, 좌표)`

```
later(기준, 좌표) = 그 좌표를 touches 에 가진 작업 기록 중 기준보다 나중인 것
```

기준을 바꾸면 **같은 함수가 세 질문에 답한다** — (문서,좌표) 쌍의 최신성 /
섹션에 남은 갱신 / 그 좌표의 최신 기록. 구현도 한 곳뿐이다
(`viewer/server/core/validity.js`).

정본 문서 섹션에는 **`<!-- applied: <작업id> -->` 하나가 유일한 규약**이다.
그 섹션이 어느 작업까지 실었나를 말하고, "최신인가"는 계산해서 나온다.

> **같은 날짜는 후속이 아니다** — 였다. 날짜 입도가 하루면 하루 안의 순서를 모르고,
> id 문자열로 순서를 매기면 오탐이 난다. **이 목록의 오탐은 부식성이 크다** —
> 한 번 틀리면 사람이 목록 전체를 안 믿는다. 그래서 같은 날은 판정을 포기했다.
>
> **개정(v0.2.6) — `date` 에 시각을 붙일 수 있다.** `2026-09-08 14:30` 으로 적으면
> 하루에 같은 좌표를 두 번 건드려도 선후가 결판나 파생 누락이 잡힌다. 시각이 없어
> 같은 날로 남는 짝만 **경고**로 내려가 "모른다"고 말한다 — 오탐을 만들지 않으면서
> 맹점을 메운 자리다. 이관에서 실제로 436건에 시각을 붙였고, 그 즉시 감춰져 있던
> 파생 누락 13건이 드러났다(같은 날 맹점이 닫혔다는 증거다).

## 1.6 판정 모델의 정정 — 없앤 상태 넷

이것이 CDP 를 이해하는 데 가장 중요한 부분이고, **이집이지 이관에서 가장 크게
부딪히는 부분**이다.

| 없앤 것 | 왜 |
|---|---|
| **"밀림"** | 정본 갱신은 필수다. 그러면 "밀린 섹션"은 구조적으로 존재할 수 없다 — 있으면 상태가 아니라 **오류**이고 커밋이 막힌다. "미작성"도 같은 위반으로 **한 건으로** 낸다 |
| **"미결"·"제안"** | 지식공유문서는 **작업의 완료**에서 발생한다. 결정을 기다리는 것은 아젠다이고 이슈 대장이 다룬다. 둘은 같은 것이라 이름이 둘이면 한쪽으로 흘러 들어간다 |
| **"덮힘"** | 후속이 조금 손봤는지 완전히 뒤집었는지 **도구는 모른다.** *"후속 있음"* 만 말하고 *"덮임"* 이라 말하지 않는다 |
| **"진행중"** (v0.2.6 추가) | 위 셋과 같은 이유의 마지막 한 칸이다. 끝나지 않은 일은 문서가 아니다 — 지식공유문서는 작업의 **완료**에서 발생하므로 "지금 만지고 있다"는 문서에 적을 상태가 아니고, 점유는 브랜치와 사람이 말한다 |

```
남은 어휘 — 상태는 없고 사실과 오류만 있다

후속(later)     그 좌표를 이 뒤에 건드린 작업이 있다   — 사실
반영(applied)   이 섹션이 어느 작업까지 실었다        — 사실
파생 누락       갱신을 안 했다                        — 오류
섹션/문서 없음   등록부가 없는 자리를 가리킨다          — 오류
끊김            applied 가 유령을 가리킨다            — 오류
같은 날 (경고)   시각이 없어 선후를 모른다              — **모름**
```

마지막 한 줄이 v0.2.6 에 늘었다. **모른다는 것을 오류로도 사실로도 말하지 않는
세 번째 등급**이다 — `date` 에 시각이 있으면 선후가 결판나 파생 누락(오류)이 되고,
없으면 여기로 내려와 사람이 눈으로 본다. "오탐은 부식성이 크다"(§1.5)와
"error 등급을 함부로 쓰지 않는다"(§1.7) 를 동시에 지키는 자리다.

`status` 로 뜻이 있는 값은 **하나도 없다**. `확정` 은 기본값이라 읽는 경계에서 지우고,
`미결`·`제안` 은 아젠다라 이슈 대장으로 가고, **`진행중` 은 v0.2.6 에서 폐지됐다**(오류).

> 폐지 이유가 이 문서의 논지와 같다 — 지식공유문서는 작업의 **완료**에서 발생하므로
> "지금 만지고 있다"는 문서에 적을 상태가 아니다. 점유는 브랜치와 사람이 말한다.
> 상태를 하나라도 남겨 두면 그 값이 낡아도 아무도 모른다는, 이 문서 §1.5 의
> "수기 상태는 부식한다"가 `status` 자신에게 적용된 결과다.

## 1.7 보증 층 — git 훅 하나

```
.githooks/pre-commit  →  bin/ctx check  →  error 있으면 exit 1
```

> **LLM 의 선의에 의존하는 층이 하나도 없어야 한다.** skill 은 지시문이고
> 사람도 LLM 도 안 부를 수 있다. **결정론적 보증은 이 한 줄뿐이고 그것이
> 충분하다.**

| 등급 | 뜻 | 커밋 |
|---|---|:--:|
| **error** | 이 상태로 남기면 나중에 **틀린 답을 확신 있게** 준다 | 막힌다 |
| warn | 알아야 하지만 지금 막을 근거는 아니다 | 된다 |
| info | 참고 | 된다 |

**error 7종** — 필수 필드 누락 / `id`≠파일명 / 미등재 좌표 / **파생 누락** /
등록부가 가리키는 섹션 없음 / `applied` 유령 참조 / `status: 미결·제안`.
**warn 4종** — INDEX 불일치 / `deprecated` 좌표 사용 / 본문이 얇다 / 훅 미설치.

훅 자체에도 설계가 들어 있다 —

- `bin/ctx` 가 없으면 **막지 않는다**(`exit 0`). 검사를 **못 하는 것**과 검사에
  **실패한 것**은 다르고, 전자로 막으면 도구가 깨진 날 아무도 일하지 못한다.
- 실행기 부재는 `127` 로 구분한다. 폐쇄망 실측에서 이 둘을 안 가르자 Node 없는
  PC 에서 커밋이 전부 막혔다.
- 통과 후 `ctx index` 로 `INDEX.md` 를 재생성해 **그 커밋에 포함**한다.

## 1.8 절차 6종 (skills)

| skill | 언제 | 하는 일 |
|---|---|---|
| `cdp-work` | 작업 요청마다 | ① 검토(대상 추출) → ② 주입(필요시) → ③ 요청수행 |
| `cdp-load` | ②가 부른다 / 단독 | 좌표 → 관리 문서 섹션 주입. **좌표를 추측하지 않는다** |
| `cdp-save` | **작업 끝에 한 번** | pull → 좌표 판정 → 작업 기록 → **파생 갱신** → 한 커밋 |
| `cdp-managed` | 파생이 남았을 때 | `ctx derive` 목록을 좌표 단위로 치운다 |
| **`cdp-import`** | 밖에서 온 문서를 들일 때 | 회의록·검토서·인수인계 문서를 작업 기록으로. **날짜는 오늘이 아니다** |
| **`cdp-edit`** | 코드 없이 문서만 고칠 때 | 관리 문서를 고치고 **그 지시를 기록으로** 남긴다 |

> **뒤의 둘은 v0.2.6 에 늘었고, 하필 이 이관이 손으로 하던 두 가지다.**
> `cdp-import` 는 "규약을 모르고 쓰인 본문에서 좌표를 읽어낸다"는 문제를 절차로
> 세운 것이고 — 이관 740건이 정확히 그 일이었다. 특히 **날짜를 오늘로 찍지
> 않는다**는 조항은 이 이관에서 부동심 기록이 2026-09-08 로 만들어졌던 사고와
> 같은 자리를 가리킨다(§4 · 03 §12). `cdp-edit` 는 코드 작업 없이 관리 문서만
> 고치는 길이고, 그 변경이 **출처 없는 변경**이 되지 않도록 지시 자체를 `work/`
> 에 남긴다 — 이관 뒤 정본 채우기가 바로 이 모양이다.

절차에 박힌 판단 넷이 중요하다.

1. **주입은 요청 뒤다.** 세션 시작에 맥락을 넣으면 *"정본 문서 다섯의 틀로
   요청을 읽고 여섯 번째를 못 본다."* 그리고 무엇을 바꿀지 모르면 뽑을 좌표가
   없다.
2. **검토 뒤에 멈추지 않는다.** 검토 출력은 **감사 흔적이지 승인 관문이
   아니다** — 관문으로 두면 매 요청 정지 1회로 절차가 작업을 잡아먹는다.
   틀린 주입의 비용은 틀린 답이 아니라 낭비된 토큰이다.
3. **요청 하나 ≠ 작업 하나.** 요청 셋이 한 작업일 수 있고 그때 기록은 하나다.
   요청마다 기록하면 이력이 파편화되고 **같은 좌표의 기록들이 서로의 후속이
   된다.**
4. **확신이 없으면 반영하지 마라.** 안 채운 것은 검사가 알려주고,
   **틀리게 채운 것은 아무도 모른다** — 최신인 척한다.

## 1.9 프로그램

```
cdp.exe (~68MB, Windows 단일 실행 파일)
  ├── 로컬 HTTP 서버 (loopback only · 토큰 · Sec-Fetch-Site · 경로 봉인)
  ├── 화면 (React · 좌우 2분할 · 뻗어나가기 · 3D 좌표 그래프)
  ├── ctx CLI (10 명령)
  └── 트레이 아이콘 (Windows)
```

**폐쇄망이 전제다** — CDN 을 타는 것이 하나도 없고 웹폰트까지 base64 인라인이다.
판정은 `viewer/server/core/` 한 곳이고 **앱과 CLI 가 같은 계산을 쓴다.**

## 3.2 어긋나는 세 가지

**① `superseded` 를 둘러싼 철학 차이 — 가장 큰 충돌**

| | CDP | 이집이지 |
|---|---|---|
| 후속 문서가 생기면 | *"후속 있음"* 만 말한다. **덮임이라 말하지 않는다** | `superseded` 로 **판정**하고 배너를 달아 경고한다 |
| `supersedes`/`superseded_by` | **참조다. 오기재 정정에만** 쓴다 | **상태 전이다.** 라이프사이클의 축 |
| 근거 | 도구는 조금 손봤는지 뒤집었는지 모른다 — **아는 것만 말한다** | 사람이 판단해서 명시적으로 찍는다 |

**둘 다 맞다. 전제가 다르다.** CDP 는 좌표별 `later()` 계산이 있으므로 사람의
판정 없이도 "이후에 뭐가 더 있다"를 알 수 있다. 이집이지는 그 계산이 없어서
사람이 배너로 대신하고 있다. **좌표를 도입하면 배너의 부담이 줄어든다** —
없애자는 것이 아니라, **뒤집힌 것만 배너로 남기고 나머지는 계산에 맡긴다.**

**② `status` 의 의미가 반대다**

CDP 는 `status` 를 **없앴다**(v0.2.6 부터 쓸 수 있는 값이 하나도 없다. 적으면 오류).
이집이지는 `status` 가 **분류 축의 핵심**이다(4종 통제어휘 + 계층 정합 검사).

이관하면 이집이지의 `status: current|done|superseded|historical` 은
**"어느 폴더에 있는가"로 대체된다** — CDP 에서는 `work/` 에 있으면 사건,
`docs/` 에 있으면 상태다. 실제로 `kb.py` 도 이미 *"저신뢰(archive/wiki)는
folder 로 이미 '이력' 신호"* 라고 같은 말을 하고 있다.

**③ 관리 문서 16종은 SI 산출물 세트다**

CDP 의 16종(테이블정의서·화면설계서·요구사항정의서·테스트케이스…)은
**SI 프로젝트 표준 산출물**이다. 이집이지는 라이브 서비스 운영이라 산출물 축이
다르다 — 실제 대응물은 `STATE/` 11도메인 + `specs/`(폴더 23 + 단독 문서 11)다.

**16종을 그대로 가져오면 안 된다.** §4.2 의 결정 사항이다.

| `table:` | `mart.마스터_단지` · `팩터_원시값` 등 |
| `api:` | `/api/pick/report` · `/api/compare/:slug/env-matrix` |
| `screen:` / `page:` | 홈·비교·집BTI·`/pick` |

→ **결정 필요**: 타입 몇 개로 시작할 것인가. CDP 원칙은 *"자주 쓰는 것을
위에"* 이고, **가볍게 늘리지 않는 것**이다.

## 4.2 등록부 — 무엇을 정본 문서로 삼는가

**16종을 그대로 쓰지 않는다.** 후보 둘:

| 안 | 내용 | 장 | 단 |
|---|---|---|---|
| **A. STATE 확장** | `STATE/<도메인>.md` 를 정본 문서로 삼고 좌표 섹션을 그 안에 둔다 | 기존 구조 유지. 이관 최소 | 743줄 문서가 더 커진다. 도메인 입도가 굵어 섹션 충돌 |
| **B. 대상축 신설** | `docs/팩터정의서.md` · `docs/테이블정의서.md` · `docs/API정의서.md` … 를 새로 만들고 STATE 는 얇은 인덱스로 되돌린다 | CDP 원형에 맞음. 섹션 1:1 | 새 문서 세트를 채워야 함 |

CDP 의 판단 기준 — *"여러 사람이 자주 찾고 한 문서에서 모아 보는 게 이득이면
올린다. 드물게 찾고 그 작업 기록 하나로 충분하면 안 올린다."*
**등록부에 올리는 것이 곧 갱신 부담을 지겠다는 결정**이므로 가볍게 올리지 않는다.

→ **결정 필요**: A / B / 혼합. 그리고 **1차로 올릴 패턴은 최소 몇 개인가.**

## 4.3 `archive/` 202건을 어디에 두는가

| 안 | |
|---|---|
| **a. `work/` 로 흡수** | 전부 사건이므로 층은 맞다. 파일명 규칙(`YYYY-MMDD-slug`)·프론트매터를 붙여야 한다. 202건 작업 |
| **b. 그대로 둔다** | CDP 는 `work/`·`docs/` 밖 폴더를 스캔하지 않는다 — **뷰어·검사에서 안 보인다.** 사실상 동결 |
| **c. 좌표 없는 `work/`** | `touches: []` 로 흡수. 검색·뷰어에는 들어오되 파생 요구는 안 받는다 |

**c 가 CDP 철학에 가장 맞는다** — *"0개도 정상이다"*, *"억지 좌표가 없는 좌표보다
나쁘다"*. 다만 202건에 프론트매터 4필드를 붙이는 일이 남는다(자동화 가능).

→ **결정 필요**. 같은 질문이 `wiki/` 356건에도 적용된다.

## 4.4 소급 좌표 부여 범위

**전량은 불가능하고 필요도 없다.** 후보 셋:

```
① 앞으로만        신규 기록부터 좌표. 과거는 touches: [] 로 흡수
② 현행만 소급     STATE·specs 가 가리키는 문서만 (약 75~110건)
③ 최근 N개월      2026-07 이후 wiki (약 60건) + specs 현행
```

CDP 설계서의 시드 교훈 — *"clone 직후 커밋이 막히는 샘플이 되면 안 된다"*.
**①이 가장 안전하고, ②가 실익이 가장 크다.**

## 4.5 게이트 도입 순서

파생 누락이 error 인 이상, **좌표를 붙이는 순서와 훅을 켜는 순서가 실질이다.**
설계서 `등록부_관리문서16종.md` 가 남긴 순서를 그대로 따를 수 있다 —

```
① 정본 문서 자리를 먼저 만든다 (빈 파일 + 섹션)
② 어휘를 등재한다 (_vocab.md)
③ 등록부를 갈아끼운다 (_managed.md)
④ ctx check — 앵커 없음이 0 이어야 한다
⑤ 훅을 켠다                          ← 여기서 처음 커밋이 막힌다
⑥ 남은 파생을 채운다
```

**⑤를 ①~④보다 먼저 켜면 아무 커밋도 못 한다.**

## 4.6 `kb.py` 와 `ctx` 의 관계

| `kb.py` | `ctx` | 판단 |
|---|---|---|
| `lint` | `check` | **대체.** 판정은 한 곳뿐이어야 한다(불변조건 1) |
| `index` | `index` | 대체 |
| `impact` | `where`·`derive` | 대체 |
| `record` | `cdp-save` skill | 대체 |
| `supersede` `archive` `promote` | — | **대응물 없음.** 계층 이동은 CDP 에 없는 개념 |

→ **결정 필요**: `kb.py` 를 폐기할 것인가, 계층 이동 3명령만 남길 것인가.
CDP 불변조건 1·2 는 *"판정을 두 곳에 두면 갈라진다"* 이므로 **`lint` 는 반드시
없앤다.**

- exe·트레이·`.cmd` 는 **범위 밖** (§1.11)

# 제5부 — 결론과 다음 단계

## 5.1 판정

**이관은 타당하다.** 두 방법론이 같은 문제 인식에서 출발해 같은 결론(2계층·
append-only·RAG 거부·통제어휘·린터)에 도달해 있고, **CDP 가 더 멀리 가 있다** —
좌표라는 축과 `later()` 라는 계산, 그리고 git 훅이라는 결정론적 보증.

이집이지 지식베이스의 실측 결함 셋은 전부 **"규율로 막고 있어서" 생긴 것**이다.

```
훅이 없다        → 규약이 요구한 스탬프 202건 중 0건 이행
등급을 나눴다    → WARN 342건이 아무것도 막지 않았다
verified_on 수기 → STATE 11 중 8건이 초기값 그대로
```

CDP 는 그 셋을 정확히 겨냥한다.

## 5.2 그러나 그대로 옮기지 않는다

| 그대로 쓴다 | 바꿔서 쓴다 | 안 쓴다 |
|---|---|---|
| 두 층 (`work`/`docs`) | 관리 문서 세트 (16종 → 이집이지 축) | `cdp.exe` · 트레이 · `.cmd` |
| 좌표 · `_vocab` · `_managed` | 좌표 타입 (SI 축 → 서비스 축) | (폐쇄망 전제 항목들) |
| `applied` + `later()` | `archive/` 처리 (2층에 없는 층) | |
| git 훅 · error 7종 | `superseded` 배너 (판정 → 계산 + 배너 병행) | |
| skills 6종 | 기존 `ezipez-*` 스킬과 통합 | |
