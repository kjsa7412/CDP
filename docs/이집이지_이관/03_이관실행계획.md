# 제2부 — `_vocab.md` 생성

## 2.1 `factor:` 는 xlsx 에서 기계 생성한다

`ezipez_data/catalog/팩터.xlsx` 가 존재·활성의 SoT 다(02 §1.2). 사람이 옮겨
적지 않는다.

| 시트 | 뽑는 것 |
|---|---|
| `01. 카테고리` (8행) | `factor:A` … 카테고리명 |
| `02. 중분류` (35행) | `factor:A003` — 중분류명. **registry 관문이라 이것이 정본** |
| `03. 소분류` (135행) | `factor:A00301` — 소분류명 |

```
- `factor:A003` — 도시 중심성
  aliases: 광역 생활권 중심성, A003
```

> ⚠ **02시트와 04시트의 중분류명이 갈라져 있다** — `A003` 이 02 에서는
> *"도시 중심성"*, 04 에서는 *"광역 생활권 중심성"*. **02 를 정본으로 삼고
> 04 의 표기를 alias 로 흡수한다.** 이것이 `_vocab.md` 가 하는 일이다.

## 2.2 나머지 타입은 본문 빈도에서 초안

```
table:    /\b(mart|ods|stg|raw|ops|lab|factor)\.[가-힣A-Za-z_]+/   빈도 ≥3
api:      /\/api\/[a-z0-9/:_-]+/                                   빈도 ≥3
source:   xlsx 없음 → data_admin DB 미접근 → 본문에서 `원천_*` 추출
page:     수기 확정 (홈·비교·단지상세·집BTI·pick·지도·알림)
term:     docs/용어사전.md 의 `###` 제목에서
issue:    ISS-NNN 패턴
domain:   기존 12종 그대로
asset: kind:   어휘에만 등재. 등록부 제외
```

**빈도 하한 3을 두는 이유** — 1~2회 언급은 오타·일회성 표기일 확률이 높고,
어휘에 들어가면 그것이 정본 행세를 한다.

## 2.3 사람이 하는 일은 하나 — 정본명 확정

기계는 **후보와 빈도만** 낸다. 같은 대상에 두 표기가 있을 때 어느 쪽이
정본인지는 사람이 정한다. *"같은 대상에 좌표 둘이 생기는 순간 좌표는 좌표가
아니다."*

## 3.1 `id` = 파일명 — 개명한다

CDP 규약 `YYYY-MMDD-slug`. **02 §4.3 의 "개명하지 않는다"를 뒤집는다**
(02 §0.4 지시 3).

### 날짜 결정 — 폴백 7단

| 순위 | 원천 | 실측 커버 |
|---:|---|---:|
| 1 | 프론트매터 `date:` | 416 |
| 2 | 파일명 `YYYY-MM-DD_` 접두 | (wiki 355 는 1에 포함) |
| 3 | 경로의 `YYYYMMDD` | 7 |
| 4 | 본문 첫 60줄의 첫 날짜 | 260 |
| 5 | **같은 폴더 형제들의 최소 날짜** | 90 중 대부분 |
| 6 | git 최초 커밋 날짜 | 잔여 |
| 7 | 이관일 `2026-09-08` + 본문에 `날짜 추정` 표시 | 최후 |

5를 6보다 위에 두는 이유 — 이 레포의 git 이력은 **이관 시점**이지 저술
시점이 아니다(`archive/` 는 전부 2026-07-29 근처). 형제 문서의 날짜가 더
참에 가깝다.

### slug 생성

```
1. 원본 파일명에서 날짜 접두·확장자 제거
2. 공백·쉼표·괄호 → 하이픈.  연속 하이픈 축약
3. 하이픈 토큰 앞에서부터 누적, 24자를 넘기 직전까지
4. archive/specs 는 앞에 출처 조각 1개를 붙인다 (원 폴더명에서 `이집이지_` 제거)
5. 충돌하면 -2, -3 …
```

```
wiki/2026-09-05_ops로그-주간검토-42601회귀-테스트오염-….md
  → work/2026-0905-ops로그-주간검토.md
```

**공백·쉼표가 든 파일명 7건은 여기서 사라진다.** `sh` 로 도는 훅과 `bin/ctx`
에서 인용 없이 다뤄지면 깨지는 자리라, CDP 가 CRLF 로 두 번 물린 것과 같은
종류의 조용한 실패다.

## 3.2 프론트매터 — 9필드만 남긴다

```yaml
---
id: 2026-0905-ops로그-주간검토      # = 파일명. 필수
title: ops 로그 주간검토 — …        # 원본 title 전문. 없으면 H1 → 파일명
date: 2026-09-05                   # 필수
author: kjsa                       # 필수. 실측 0건이라 전건 신설
touches: []                        # 키는 필수. P2 에서 채운다
tags: [ops, 작업기록, repo/web_back, source/notion]
attachments: [assets/…/x.sql]      # 있을 때만
---
```

| 원본 | 처리 |
|---|---|
| `status` (11종 441건) | **전건 삭제.** `In progress`·`진행중`·`Not started` 는 목록만 남겨 사람이 확인 (v0.2.6 에서 `진행중` 도 폐지돼 예외가 사라졌다) |
| `domain` (109) | → `touches` 에 `domain:<값>` 좌표로 승격 |
| `category` (388) | → `tags` |
| `repos` (423) | → `tags` 에 `repo/<값>` |
| `source` (260) | → `tags` 에 `source/<값>` |
| `icon` (361) | 버린다 |
| `verified_on` (81) | 버린다 — `applied`+`later()` 가 대체 |
| `superseded_by` (1) | 본문 배너로 (§3.5) |
| `project` `step` `depends` `date_estimated` | → `tags` |

**`title` 은 자르지 않는다.** 파일명이 짧아진 대신 제목이 전문을 보존한다.
YAML 특수문자(`[` `{` `&` `*` `!` `|` `>` `%` `@` · `: `)로 시작하거나 포함하면
**따옴표로 감싼다** — 안 그러면 제목이 통째로 사라진다.

# 제4부 — 좌표 부여 (P2)

**여기가 어렵고, 어렵다는 것을 전제로 설계한다.**

## 4.1 기계는 후보만 낸다

본문·제목에서 `_vocab.md` 의 정본·alias 를 문자열 매칭해 후보를 뽑는다.
**그러나 CDP 의 좌표 기준은 "언급"이 아니라 "바꿨는가"** 이고, 기계는 그것을
가르지 못한다.

## 4.2 그래서 3등급으로 착지한다

| 등급 | 조건 | `touches` |
|---|---|---|
| **강** | 좌표가 **제목**에 나온다 · 또는 본문 5회 이상 + `category: 작업기록\|트러블슈팅` | **부여** |
| 중 | 본문 2~4회 | **보류** — 후보만 `coord-candidates.tsv` 로 |
| 약 | 1회 | 버린다 |

**보류가 기본값이다.** CDP: *"없는 좌표보다 억지 좌표가 나쁘다 — 그 좌표를
찾는 사람에게 무관한 문서를 내민다."* 그리고 `touches: []` 는 **정상**이다.

`domain:` 은 예외로 프론트매터 `domain` 이 있으면 무조건 부여한다 — 그것은
사람이 이미 판정한 값이고, 등록부에 없어 파생을 요구하지 않는다.

## 4.3 중등급은 배치로 판정한다

`coord-candidates.tsv` 를 도메인·연도 단위로 잘라 **LLM 이 문서를 읽고 판정**한다.
한 배치 = 20~30건. 판정 근거를 같이 남긴다(CDP 검토 출력 형식).

**이번 이관에서 다 하지 않는다.** 강등급으로 착지시키고 나머지는 목록으로
남긴다 — 그 목록이 있는 한 "없는 것"이 되지 않는다.

## 4.4 `applied` 일괄 착지

좌표 문서 7종의 섹션은 이렇게 태어난다.

```
좌표 하나당 섹션 하나
  applied = 그 좌표를 touches 에 가진 작업 기록 중 **가장 나중 것**
  본문    = 제목 + SoT 줄 + 미채움 표식 (02 §4.8)
  작업 기록이 0건이면 → applied: null  (위반 아님)
```

이러면 `later(applied, 좌표)` 가 비어 **파생 누락 error 가 0** 이다.

## 10.1 횟수로는 못 가른다 — 분류기가 실패했다

먼저 위치·동사 기반 분류기를 만들었다(제목/소제목 · 변경 동사 문맥 · 참조 동사

**표본 8건을 읽어 보니 부여 중 3건만 맞았다.** 오탐은 한 종류였다 —
**팩터 코드를 15~40개씩 나열하는 검토·감사·설계 문서.**

> `조사 A`, `01c 팩터 전수 수집검토`, `최종 통합 보고서` 에서 `C003` 이 다섯 번

> 행**이라는 뜻이다. 기계는 "언급했는가"는 세지만 "바꿨는가"는 못 센다.

## 10.2 그래서 문서 종류를 먼저 봤다

```
① 후보 8개 이상을 가진 문서 38개를 제목으로 판정
   35개 = 검토·감사·보고서·설계·TODO → 후보 454건(36%) 일괄 기각
② 나머지 300개 문서 816건을 문맥과 함께 4배치로 읽어 개별 판정
```

**설계·검토·계획 문서는 대상을 바꾸지 않는다.** 바꾼 것은 그 뒤의 구현 기록이고,
그 기록은 제목에 대상 이름이 들어 있어 P1 의 제목 매칭에서 이미 잡혔다.
그래서 잔여 후보에 남은 것은 대부분 열거였다.

djy → per-호 CSV 로 **원천을 교체**했는데 판정에서 걸렀다. 좌표를 붙이고 섹션을 신설했다.
정정 기록은 `cand-verdicts.tsv` 에 `부여(정정)` 로 남는다.

## 11.4 남은 것 — 그리고 결정이 필요한 자리

`현행_*` 7종(1,033줄) — design 173 · event 287 · notification 123 · ops 102 · region 239 ·
share 57 · factor 100.

**`현행_factor` 100줄은 더 이상 부채가 아니다** — 팩터 체계 전반(규모·SoT 체인·공통 함정·토글)은
좌표에 안 붙고, 얇은 인덱스가 그 내용의 옳은 형태다.

나머지 6종도 같은 성격이 대부분이다. **그래서 선택지가 둘이다.**

| 안 | 내용 | 대가 |
|---|---|---|
| **A. 이름을 준다** | `이벤트정의서` · `알림정의서` · `지역확장정의서` · `디자인정의서` · `운영봇정의서` 로 개명(§3.2 세트 확장) | 부채 계량이 0이 되지만 **내용은 그대로다** — 측정을 만족시킨 것일 수 있다 |
| **B. 먼저 옮기고 남은 것만 개명** | 각 문서에서 좌표 모양인 부분을 섹션으로 옮긴 뒤 개명 | 정직하지만 문서마다 읽고 판단해야 한다 |

**02 §8.1-5(Stage 8 완료 기준)가 아직 비어 있어 여기서 멈춘다.** 기준 없이 A 로 가면
숫자만 0이 되고, 기준 없이 B 를 끝까지 하면 어디가 끝인지 알 수 없다.

권장 기준 셋 —
1. **미채움 표식**은 0을 목표로 하지 않는다. 144개는 스냅샷에 원천이 없어 **작업 기록이 원천**인
   정상이고, CDP 는 *"추측으로 채우지 마라 — 근거 없는 문서가 정본 자리에 앉는다"* 고 한다.
   ⇒ 목표는 **"근거가 있는데 안 채운 것" 0** (현재 41 중 28 완료 · 잔여 13).
2. **`현행_` 접두는 0** — 다만 개명 전에 그 문서의 좌표 모양 내용을 옮겼는지 확인한다.
3. **중복 0** — 좌표 섹션과 정본 문서에 같은 문장이 있으면 그것이 진짜 부채다.

## 12.2 날짜 — 제일 크게 틀렸던 자리

사람이 발견했다. **부동심 관련 기록이 2026-09-08(이관일)로 만들어져 있었다.**
부동심은 이집이지 서비스 **이전의 컨셉 아이디어**다. 파고 보니 결함이 둘이었다.

| | |
|---|---|
| **본문 날짜 추출이 UI 목업을 물었다** | `05-events.md` 안의 `"2024.01.10 · 영향 단지 128개"` 는 화면 예시지 작성일이 아니다. 그리고 폴백이 형제 파일의 **최솟값**이라 그 오염이 폴더 전체로 번졌다 |
| **같은 md 가 여러 기록이 됐다** | 첨부만 내용 해시로 중복을 걷었고 md 는 안 걷었다 |

고친 것 넷 — ① 본문 날짜에 범위 가드(2026-01-01 ~ 2026-09-08) ② **mtime 을 본문보다
위 순위로** ③ 형제 폴백 최솟값 → **중앙값** ④ md 내용 해시 중복 제거.

②는 검증하고 채택했다. mtime 은 100% 가 실제 날짜와 3일 이내로 맞았다 — 단
대량 복사일 **2026-07-29 하나에 777개 중 272개(35%)가 몰려** 있어, 그 날짜만 신뢰하지
않고 다음 순위로 넘긴다. 결과 **153건 교정 · 11건 병합 · applied 22건 재착지**,
프론트매터에 날짜가 있던 건은 **한 건도 바꾸지 않았다.** 부동심은 이제 한 건이고
날짜는 **2026-05-14** 다.

> 이 사고가 남긴 규칙은 v0.2.6 의 `cdp-import` ② 와 같다 — **"날짜를 정한다.
> 오늘이 아니다."** 밖에서 들이는 문서는 들인 날이 아니라 **쓰인 날**을 가진다.
> 절차에 그 한 줄이 있었다면 사람이 찾아 주기 전에 걸렸을 자리다.

## 12.3 프로토콜 개정(v0.2.6) 반영

이관 중에 CDP 본체를 9커밋 당겨받았다(`5025427` → `bc485cf`). 개정 셋이 이 레포를
직접 건드렸다.

**① `status: 진행중` 폐지** — 이관 때 5건을 `진행중` 으로 남겨 뒀는데 그 즉시
**오류가 됐다.** 전건 제거했다. 02 §4.5 가 당초 "17건을 `진행중` 으로 통일"을
제안했는데, 그러지 않고 전건 삭제한 판단이 결과적으로 맞았다.

**② `date` 에 시각 허용** — 같은 날 맹점이 닫혔다. **437건에 시각을 붙였다.**
붙인 근거는 `date` 의 날짜와 파일 mtime 의 날짜가 같을 때 그 시각을 쓰는 것뿐이고,
어긋나는 **26건은 붙이지 않았다** — 없는 정밀도를 지어내지 않는다.

```
시각 붙이기 전   같은 날 경고 31건
붙인 뒤          같은 날 경고  1건 · 파생 누락 오류 13건  ← 감춰져 있던 것이 드러났다
재착지 후        오류 0 · 경고 1
```

드러난 13건은 회귀가 아니라 **맹점이 닫혔다는 증거**다. 각 좌표의 최신 기록으로
`applied` 를 다시 착지시켰다.

**③ 경로·스킬 개편** — `repo-kit/` → `kit/`, `ops/tools/` → `ops/lib/`,
스킬 4종 → **6종**(`cdp-import`·`cdp-edit` 추가), 매뉴얼에 `MANUAL-시스템.md` 신설.
레포의 `.claude/skills/` · 매뉴얼 3종 · `TEMPLATE-work.md` 를 새 kit 으로 동기화하고,
01 §1.8 · 02 §6.1 · 03 §1 의 서술을 전부 새 이름으로 고쳤다.
