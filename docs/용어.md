# 용어 v1.0

> **CDP 의 말은 여기 한 곳이 정본이다.** 스킬 · 설명서 · 화면 문구 · 설계서 · 코드 주석이 이 표를 따른다(개편안 V15). 새 말을 만들기 전에 여기서 찾고, 말을 바꾸면 여기부터 바꾼다 — 같은 상태의 이름이 여덟이던 일(밀림 · stale · 파생 누락 …)을 되풀이하지 않는다.
> 뼈대는 [`design/CDP_v1.0_개편안.md`](design/CDP_v1.0_개편안.md) §4.5 의 쓴다 · 버린다 표다. 뜻보다 **「왜 여기서 그 말이 나오나」** 를 적는다. 그림은 [그림/](그림/).
> v1.0 · 2026-10-07 · 코드 main `d5e0a1c`. 설계는 [`design/CDP_시스템설계서_v2.0.md`](design/CDP_시스템설계서_v2.0.md) 부터. 이전 판(파일 · 실행 · 빌드 · git 중심)에서 살아남은 말은 [§5](#5-고칠-사람의-말--파일--실행--빌드--git)에, 버린 말은 [§4](#4-버린다--대신)에 무엇이 대신하나와 함께 두었다.

## 1. 쓴다 — 기록과 문서

| 용어 | 뜻 | 어디서 |
|---|---|---|
| **좌표** | 대상 하나의 정본 이름 `타입:값` — 이 시스템의 기본키. 그 작업이 **바꾼** 대상에만 붙인다(참조 · 언급은 아니다) | 작업 기록의 `touches` · `_vocab.md` |
| **어휘** | `_vocab.md` — 좌표 · 별칭(`aliases`) · 폐기(`deprecated`)의 통제 목록. **좌표는 여기에만 등재된다**(I4). 타입 절 순서가 화면의 카테고리 순서다 | save 의 `vocab` 이 더한다 · 지우지 않는다 |
| **등록부** | `_managed.md` — 좌표 패턴 → 관리 문서 · 섹션 앵커. 매핑이 선언되는 **유일한** 곳이다(두 곳이면 반드시 어긋난다) | 큐레이터의 `managed[]` 가 고친다 |
| **작업 기록** | `work/<id>.md` — 한 작업의 사건. **불변 · 원천**이고 홀로 선다(값 · 표 · 결정 · 제약은 본문에) | writer 의 save · `cdp-save` |
| **큐레이션 기록** | `curates` 키가 있는 작업 기록 — 다룬 기록과 판정을 데이터로 남긴다 | 큐레이터의 save · 화면 「기록으로 둠」 |
| **기준선 기록** | `baseline` 키가 있는 작업 기록 — 기준선 블록을 갈아 끼운 출처 · 시점 | `ctx baseline push` |
| **전환 기록** | 옛 레포를 v1.0 으로 옮길 때 **한 번** 남기는 큐레이션 기록(태그 `transition`) — 「그때 섹션에 실린 기록은 반영됨」 을 굳힌다 | `ctx migrate` |
| **관리 문서** | `docs/**.md` — 대상마다 지금 상태를 적는 문서. 큐레이션으로만 바뀐다(I6) | |
| **섹션** | 관리 문서 안 좌표 하나의 자리 — `## <값> — <설명>` | |
| **정본** | 한 사실이 적히는 **유일한** 섹션(I5). 다른 섹션은 그 좌표를 건다 | `section` 의 `refs` |
| **applied** (반영 표지) | 섹션 헤딩 아래 `<!-- applied: <기록 id> -->` — 그 섹션이 반영한 기록 중 가장 늦은 것. **save 가 계산해 쓴다** | |
| **경과** | 섹션 끝 `**경과**` 목록 — 반영한 기록을 한 줄씩. 본문을 일지로 만들지 않는다 | |
| **기준선** · **기준선 블록** | 섹션 안 `<!-- cdp:baseline src=… asof=… -->` ~ `<!-- /cdp:baseline -->` — 코드 · DB 에서 **기계로 뽑은** 추출. 기준선 save 만 통째로 갈아 끼운다 | 프로젝트의 생성기 |
| **서식 표지** | 관리 문서 H1 바로 아래 `<!-- cdp:form <묶음>/<번호> -->` — 그 문서를 세운 서식 | 화면의 칩 |
| **빈 틀** | 새 지식 레포 — `README.md` · `_vocab.md` · `_managed.md` · `docs/` · `work/` · `.gitattributes` · `.gitignore` 뿐 | `ctx repo new` · 콘솔 「새 지식 레포」 |

## 2. 쓴다 — 큐레이션

| 용어 | 뜻 | 어디서 |
|---|---|---|
| **큐레이션** | 대기열의 기록을 판정하고 섹션에 반영하는 일 — 판정표 + diff 를 보이고 승인 뒤 save 한 번 | `cdp-curate` |
| **큐레이터** | 그 레포의 관리 문서를 쓰는 사람 — **레포별 권한**(명부의 `curate`). admin 은 모든 레포의 큐레이터다 | |
| **판정** | 기록 하나를 어떻게 다뤘나 — **반영**(`reflect`) · **새 문서**(`new` — 서식에서 문서를 세워 반영) · **기록으로 둠**(`keep` — 사유와 함께 기록을 원천으로 둔다) | `curates: [{ id, verdict, into, reason }]` |
| **반영** | 기록의 내용을 정본 섹션에 옮기는 것 — 현재형으로 다시 쓰고 경과 한 줄 | |
| **대기열** | 아직 어떤 판정도 받지 않은 작업 기록 — 오래된 순. **저장하지 않고 계산한다**(I8) | MCP `queue` · 화면 큐레이션 › 대기열 |
| **미반영** | 섹션 뒤에 그 좌표를 건드린 기록이 아직 대기열에 있는 것(큐레이션 기록이 없는 옛 레포는 applied 뒤 후속) — **상태다**(I7). 섹션을 내보내는 자리가 그 기록을 같이 낸다 | `section` 의 `pendingRecords` · 화면 「미반영 n」 |
| **섹션 상태** | `ok` · `pending`(미반영) · `missing`(문서 · 섹션이 없다) — 셋뿐이다 | `where` · `section` |
| **기록의 큐레이션 상태** | 대기 · 반영됨(→ 좌표) · 기록으로 둠(사유) | `work` 의 `curation` · 화면 칩 |
| **좌표 분류** | 대기 기록의 좌표마다 — 섹션 있음 · 등록부 있음 · 섹션 없음 · 등록부 없음 · 좌표 0 | 판정 재료 |
| **판정 재료** | 기록 하나를 판정하는 데 필요한 것 — 걸린 섹션 · 등록부 없는 타입과 비슷한 서식 · 정본 후보 · 본문에만 있는 좌표 | `queue({ id })` |
| **암묵 전환** | 큐레이션 기록이 없는 옛 레포를 옛 판정(applied 뒤 후속)으로 읽는 것 — 판을 올린 순간 대기열이 기록 전부로 쏟아지지 않게 | 계산 |
| **에이전트 지시** | 화면이 복사해 주는 `cdp-curate <레포>` · 대상 · 규칙 한 줄 — 큐레이터가 자기 Claude Code 에 붙인다 | 대기열 [에이전트 지시 복사] |
| **어긋남** | 반영된 뒤 시간이 지나며 정본이 원천 · 규칙과 어긋난 것 — 근거 없음 · 복제 · 비대 · 일지형 · 좌표 없는 기록. **미반영과 다르다**(미반영이 0 이어도 생긴다) · 저장하지 않고 계산한다 | MCP `drift` · 화면 큐레이션 › 진단 · `ctx drift` |
| **근거 없음** | 그 좌표를 건드린 기록 · 스냅샷 · 기준선이 없는 섹션 — 기록만 옮겨 다시 세우면 사라진다. 본문이 기록을 인용하면 「인용」 | `drift` 의 `unsourced` · `linked` |
| **정본 스냅샷** | 근거 없는 섹션을 서버가 **원문 그대로** 뜬 기계 기록 — 섹션 하나에 하나 · 날짜는 섹션 줄의 마지막 커밋. 사건이 아니라 그때의 상태다 · 섹션이 있으면 대기열에 안 선다 | `save.snapshot[]` · 기록 종류 `snapshot` · `ctx rebuild snapshot` |
| **큼** | 대상 · 서술 섹션이 150줄을 넘는다는 진단 신호 — 줄 수로 비대를 재지 않는 종류의 「쪼갤 후보」 | `drift` 의 `big` |
| **문서 종류** | 등록부(`_managed.md`) 행의 「종류」 칸 — 대상 · 대장 · 정의 · 사건 · 서술(서식집과 같은 다섯). 비대 잣대가 여기서 온다 | `_managed.md` |
| **리빌딩 · 재유도** | 어긋난 섹션 묶음을 원천(기록 · 스냅샷 · 기준선)에서 다시 쓰고 지금과 견줘(「사라지는 사실」) 재큐레이션으로 남기는 일 | `cdp-rebuild` · 큐레이션 기록 `tags: [rebuild]` |

## 3. 쓴다 — 서식 · 사람 · 자리

| 용어 | 뜻 | 어디서 |
|---|---|---|
| **서식** | 새 관리 문서를 세우는 재료 — 머리말 + head(문서로 간다) · guide · example(큐레이터가 읽는다) | `agent/forms/<묶음>/<번호>_<제목>.md` |
| **서식집** | 서식의 모음 — 번들 `forms/`(제품 판) + 팀 서식 `<data>/forms/` | MCP `forms` · 화면 서식집 |
| **묶음** | ① 서식집의 갈래(`public-si` · `agile-product` · `ai-service` · `cloud-native`) ② 왼쪽 메뉴의 갈래(지식 · 큐레이션 · 레포 관리 · 서버) — 문맥이 가른다 | |
| **문서 종류** | 대상 · 대장 · 정의 · 사건 · 서술 — 서식 머리의 `kind`. 문서에는 적지 않는다 | |
| **찍기** | 서식에서 제목 · 서식 표지 · 첫 문단만 있는 깨끗한 빈 문서를 만드는 것(`stampDoc`) | `managed.add { form }` |
| **viewer · writer · admin** | 명부의 역할 — 읽기 · + 작업 기록 · + 서버 관리. 큐레이터는 여기에 레포별 `curate` 를 더한 것 | `auth.json` |
| **명부** | `auth.json` — 사람과 권한. **토큰은 신원만 증명한다** | 콘솔 › 사용자 · `ctx serve user` |
| **토큰** | 32바이트 난수 — 원문은 발급 때 한 번, 서버에는 해시만 | 콘솔 › 토큰 |
| **재인증** | 콘솔에서 쓰기 전에 내 토큰을 한 번 더 — 15분 | |
| **지식 레포** | 지식이 있는 git 레포 — **서버가 쓴다** · 지식만 둔다(I9) | 서버 `<root>/<이름>/` |
| **작업 레포** | 사람이 코드를 짜는 레포 — kit 이 깔리고 서버의 MCP 를 부른다 | |
| **큐레이터 폴더** | 큐레이터가 큐레이션 세션을 여는 폴더 — 작업 레포가 아니어도 된다 | 설치 한 줄 `--curator` |
| **kit** | 작업 레포 · 큐레이터 폴더에 까는 스킬 + CLAUDE 블록 — **서버 번들 `kit/` 에서 역할별로** | `/kit/<레포>` |
| **설치 한 줄** | 서버의 `/install.mjs` 를 받아 kit 을 까는 명령 — `--update`(이 PC 의 작업 레포 전부) · `--curator`(큐레이터 폴더) | 레포 관리 › 연결된 작업 레포 |
| **작업 레포 대장** | 어느 작업 레포가 어느 kit 을 들고 있나 — 최신 · 낡음 · 미설치 | 서버 › 작업 레포 대장 |
| **개인 서버** | `ctx serve --personal <레포>` — 서버 없는 팀 · 한 사람의 서버. 같은 코드 · 같은 save · 같은 화면 | |
| **미러** | 서버 커밋을 origin 으로 보내는 레포당 push 큐 — `off` · `ok` · `lag` · `diverged` · `behind` | 상태 표시줄 · 서버 › 지식 레포 |
| **다시 세우기** | 옛 레포의 작업 기록만 옮겨 빈 틀로 새 레포를 세우는 것 — 기록은 전부 대기열에 선다 | `--records-from` · 「기록만 옮겨 오기」 |
| **제자리 이행** | 옛 레포를 그 자리에서 v1.0 으로 — 전환 기록 · 서식 예시 정리 · 도구 층 걷기 | `ctx migrate` |
| **얼굴** | 한 번들의 화면 갈래 — 사이트 · 레포 · 콘솔 | 주소가 고른다 |
| **정본 한 곳 · 사실 하나에 자리 하나** | I5 의 줄임 | 큐레이터의 쓰기 규칙 |

### MCP

| 용어 | 뜻 |
|---|---|
| **MCP** | 에이전트 호스트가 서버의 도구를 부르는 규약 — CDP 는 HTTP 하나다(`/mcp/<레포>`) |

## 4. 버린다 → 대신

| 버린다 | 대신 | 왜 |
|---|---|---|
| 지식공유문서 · 지식 단위 · 작업문서 · 작업 문서 | **작업 기록** | 같은 것의 이름이 넷이었다 |
| 파생 · 따라잡기 | **반영**(큐레이션) | 섹션 쓰기는 작업한 사람의 의무가 아니다 — 큐레이터의 일이다 |
| 밀림 · stale · 파생 누락 · derive-pending · 파생 남음 · pendingDerive · 미작성 | **미반영** | 같은 상태의 이름이 여덟이었다. 이제 오류가 아니라 **상태**다 |
| 파생 정리 기록 | **큐레이션 기록** | |
| (큐레이터 설계 v0.1 의) 기준선 — 옛 레포를 한 번에 판정해 두는 것 | **전환 기록** | 「기준선」 은 추출 블록의 이름이다 |
| 정본 문서 | **관리 문서** | 「정본」 은 문서가 아니라 섹션 하나의 성질이다 |
| 「원본 파일」 뜻의 정본 | 원본 · 원천 | 위와 같다 |
| 패키지 | **서식집 · 묶음** | 레포에 붓지 않는다 — 큐레이터가 하나씩 고른다 |
| 템플릿 | **서식** | |
| 서식 예시 · `(예시)` 섹션 · `example:` 어휘 | 서식의 **example** | 문서로 가지 않는다 · 좌표로 잡히지 않는다 |
| `## 작성지침` 섹션 | 서식의 **guide** | |
| 패키지 붓기 · `ctx package` · `knowledge-repo-<묶음>` | **빈 틀** + 서식에서 세우기 | |
| 섹션 이력의 `### 변경` · `**변경**` 줄 | `**경과**` 목록 | 개편안 §4.3 — 서식 51종에는 아직 `**변경**` 이 남았다([서식집 규약 §12](design/CDP_서식집_규약_v1.0.md#12-코드와-어긋난-곳)) |
| 모드 A · 모드 B · 로컬형 · 서버형 | (갈래가 없다) 서버 하나 — 혼자면 **개인 서버** | 쓰는 길은 서버 save 하나다(I2) |
| 로컬 뷰어 · `cdp.exe` · 트레이 앱 | **개인 서버** | |
| 관리 서비스 · 원격 뷰어 | 서버의 **화면**(얼굴 — 사이트 · 레포 · 콘솔) | |
| 콘솔(화면 이름) | 왼쪽 메뉴의 **서버** 묶음 — 주소는 `/console/…` 그대로 | 「콘솔」 은 하는 일이 아니다 |
| 관리 › 작업 레포 | 레포 관리 › **연결된 작업 레포** | 서버의 대장과 이름이 같았다 |
| 콘솔 › 작업 레포 | 서버 › **작업 레포 대장** | |
| 콘솔 › 서버 | 서버 › **서버 설정** | 묶음 이름과 같았다 |
| stdio MCP · `ctx mcp` | HTTP MCP(`/mcp/<레포>`) | |
| `ctx setup` · `ctx setup --server` | **설치 한 줄** | |
| 에이전트 세팅 갱신 · kit-refresh · 도구 층 갱신 | 설치 한 줄 `--update` | kit 은 서버 번들에서 나간다 |
| 도구 층 · 레포 안 `bin/ctx` · `.githooks/pre-commit` · `core.hooksPath` | (없다) — 레포에는 지식만 · 검사는 save 가 한다 | 옛 레포의 도구 층은 `ctx migrate` 가 걷는다 |
| INDEX(`INDEX.md` · `INDEX-by-coord.md`) · 등록부 사본(머리 표 `등록부` 칸 · 어휘 생성 블록) | (없다) — 화면 · 도구가 계산한다 | 사본은 반드시 낡는다 |
| `derive` · `apply` · `sync` · `version`(도구 · 명령) | `queue` · `section`(미반영 기록) · `brief`(미러 · kit · 판) | |
| `write`(권한 축) | `role`(viewer · writer · admin) + `curate` | |
| 결정론적 보증은 git 훅 | save 의 검사 + 도구가 미반영을 싣는다 | |
| SEA · blob · exe 폴백 | (없다) — 서버는 Node 20 이상 | exe 빌드를 걷었다 |
| `git bundle`(반입) · 반입 묶음 | (없다) | |
| exit code 127(도구 없음 — 훅이 건너뛴다) | (없다) | 훅이 없다 |
| 포인터 파일의 `knowledgeRepo`(PC 경로) | `.claude/cdp.json` 의 `{ server, repo }` | PC 와 무관하니 커밋한다 |

## 5. 고칠 사람의 말 — 파일 · 실행 · 빌드 · git

이전 판에서 살아남은 말이다. 자리만 지금 것으로 고쳤다.

### 파일과 실행

| 용어 | 뜻 | CDP 어디서 |
|---|---|---|
| `.js` | 자바스크립트 소스 | `core/*.js` |
| `.mjs` | **m**odule JS — 「이 파일은 ESM」 이라고 확장자로 못박은 것 | `viewer/bin/*.mjs` · `ops/lib/*.mjs` · 서버 번들 `bin/ctx.mjs` |
| `.cjs` | 옛 모듈 방식(CommonJS) | CDP 에는 없다 — 번들 안의 CJS 의존(MCP SDK 등)은 `createRequire` 로 부른다 |
| `.cmd` · sh | 윈도 배치 · 유닉스 셸 스크립트 | 서버 산출물의 `bin/ctx.cmd` · `bin/ctx` · `deploy/install.sh` · `upgrade.sh` · `ops/*.cmd` |
| 셔뱅(shebang) | 첫 줄 `#!/usr/bin/env node` — 「node 로 실행해라」 | 서버 번들 맨 앞줄. **CRLF 면 실행되지 않는다** — 산출물은 LF 로 복사한다 |
| 실행 권한 | 유닉스의 「실행해도 된다」 표시(`chmod 755`) | `release-server.mjs` 가 `bin/ctx` · `install.sh` · `upgrade.sh` 에 |

### 모듈

**모듈 = 파일 하나.** `export` 한 것만 밖에서 보이고, 어느 파일이 어느 파일에 기대는지가 `import` 줄에 드러난다. CDP 가 모듈을 나눈 기준은 **계산을 한 곳에 두는 것**이다(I1) — `core/repo.js` 의 `loadRepo` 하나를 서버 · MCP · 화면 API · CLI 가 같이 부른다. 베껴 두면 둘이 갈라지고, 그때 사람은 어느 쪽을 믿을지 모른다.

| | 가져오기 | 내보내기 | 확장자 |
|---|---|---|---|
| ESM (최신) | `import x from 'y'` | `export` | `.mjs` 또는 `.js`(`package.json` `"type": "module"`) |
| CJS (옛것) | `const x = require('y')` | `module.exports` | `.cjs` 또는 `.js` |

### 실행 환경 · 빌드

| 용어 | 뜻 | 왜 중요한가 |
|---|---|---|
| Node | 자바스크립트를 브라우저 밖에서 돌리는 프로그램 | 서버는 **Node 20 이상**. 작업 PC 는 설치 한 줄에 쓴다(없으면 꾸러미를 손으로 옮긴다) |
| 의존성 · `node_modules` | 내 코드가 돌려면 있어야 하는 남의 코드 | 서버 번들 `bin/ctx.mjs` 하나에 SDK · zod 까지 들어간다 — 서버에 `npm i` 가 없다 |
| 네이티브 모듈 | OS 마다 다시 컴파일해야 하는 라이브러리 | 하나도 안 쓴다 |
| 번들 · 번들러 | 여러 파일을 **한 파일로** 합치는 것 · 그 도구(esbuild) | `npm run build:ctx` → `ops/out/ctx/ctx.mjs` |
| 산출물 | 빌드가 만든 파일 — 손으로 고치면 다음 빌드에 날아간다 | `ops/out/` · 서버 tar · 사이트 zip |
| 번들 시각 | 번들에 박힌 빌드 시각 | `ctx version` · `/healthz` 의 `built` — upgrade 가 이것으로 새 판이 섰는지 본다 |
| base64 | 이진 파일을 글자로 바꾸는 방식 | kit 을 JSON 으로 낼 때(`/kit/<레포>?as=json`) |
| 폐쇄망 | 인터넷이 끊긴 망 — CDN · 설치 · 업데이트를 못 쓴다 | 화면 번들은 외부 자원 0(I11). 서버 하나는 세울 수 있어야 한다 |

### 명령줄

| 용어 | 뜻 |
|---|---|
| CLI · 인자 · 플래그 | 창 없이 명령으로 쓰는 프로그램 · 명령 뒤의 값 · `--json` 같은 옵션 |
| stdout / stderr | 정상 출력 / 오류 출력 |
| CP949 | 윈도 한국어 콘솔의 옛 인코딩 — `ctx` 는 ASCII 구두점만 쓴다 |
| exit code | 끝날 때 남기는 숫자 — `0` 정상 · `1` 검사 실패(`ctx check` 의 error) · `2` 사용법 틀림 · 지식 레포 못 찾음 · v1.0 에서 없앤 명령 |

### git

| 용어 | 뜻 | CDP 에서 |
|---|---|---|
| `.gitattributes` · CRLF / LF | 파일별 취급 규칙 · 줄바꿈 문자 | 빈 틀이 `* text=auto eol=lf` 를 둔다. 읽는 경계에서도 CRLF 를 지운다(I13) |
| `git clone` · fetch · pull | 원격을 복사 · 받기만 · 받아서 합치기 | 사람의 읽기용 clone 은 자유다. 서버는 「origin 과 맞추기」 에서 **ff 만** 한다 |
| ff (fast-forward) | 충돌 없이 그냥 따라붙는 것 | 갈라졌으면 기계는 멈추고 사람이 셸에서 rebase 한다(I12) |
| origin · upstream · ahead / behind | 원격 · 따라가는 가지 · 앞섬 / 뒤처짐 | 미러 상태의 재료 |
| `--no-verify` | 커밋 훅을 건너뛴다 | **서버 save 의 커밋** — 같은 검사를 save 가 이미 돌았다(V5) |
| 훅 · `pre-commit` · `core.hooksPath` | git 이 정한 때 자동으로 도는 스크립트 | v1.0 레포에는 없다 — 옛 레포의 것은 `ctx migrate` 가 걷고 푼다 |
