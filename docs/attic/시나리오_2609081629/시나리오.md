# 시나리오 — 기록이 생기는 세 길

    작성   2026-09-08 16:29
    대상   C:{B}cdp  (브랜치에서 하고 끝나면 버린다)
    번들   v0.2.7
    결과   [결과.md](결과.md)

지식공유문서가 생기는 길은 셋이다. **셋 다 관리 문서 갱신이 함께 간다** —
그것이 이 프로토콜의 전부다.

```
A  이 세션에서 작업했다        cdp-work → cdp-save
B  이미 쓴 문서가 있다          cdp-import
C  작업은 없고 문서 수정 지시    cdp-edit
```

초판 시나리오(`시나리오_지식공유문서_테스트.md`)는 A 만 다뤘고, 그 안에서도
**생기지 않는 상태**를 시험하고 있었다. 이번에는 세 길을 각각 밟고, 막아야
할 자리에서 막히는지 본다.

    A1  정상 경로                기록 + 파생 + 커밋
    A2  파생 누락 (머지)          커밋이 막혀야 한다
    A3  같은 날                  경고만. 막지 않는다
    B1  회의록 편입              날짜는 사건의 날 · 언급은 좌표가 아니다
    B2  과거 문서 편입            applied 를 바꾸지 않는다
    C1  문서 수정 지시            지시가 곧 본문이다
    C2  기계가 못 막는 자리        기록 없이 문서만 고치면 아무 말도 없다
    D   미등재 좌표 · status      커밋이 막혀야 한다
    E   뷰어                     세 길의 결과가 다 보이나

---

## 0. 준비

```
cd C:{B}cdp
git switch -c test/세길-2609081629
git log --oneline -1            ← 되돌아올 자리
git config core.hooksPath       → .githooks
tools{B}cdp.exe ctx check          → 이상 없음 (경고는 있어도 된다)
```

**훅이 없으면 A2·D 는 전부 통과해 버리고 시험은 아무것도 증명하지 못한다.**

---

# A — 이 세션에서 작업했다

## A1 정상 경로

### 시키는 말

> 출장복명작성(EXD020)에 차량 미이용자용 사진 첨부 영역을 넣어 줘.
> 입력 영역은 화면 맨 위로 — 출장자 본인이 아니어도 놓치지 않게.

### 일어나야 하는 것

`cdp-work` ② 주입에서 **이미 있던 결정이 나와야 한다.**

> 차를 안 가져간 사람이 사진을 붙이려는데 **붙일 곳이 없어서** 복명만 하고
> 담당자에게 전화했다

안 나오면 `cdp-load` 가 섹션을 못 찾은 것이고, 그러면 모르는 채로 같은
결정을 다시 하게 된다.

`cdp-save` 가 **한 커밋**으로 낸다.

```
work/2026-MMDD-출장복명-사진첨부.md
docs/화면설계서.md  ## EXD020    applied 교체
```

### 확인

```
ctx where screen:EXD020     → 반영이 새 기록을 가리킨다
ctx check                   → 오류 없음
git commit                  → 통과
```

---

## A2 파생 누락 — 머지 (**막혀야 한다**)

### 이 상태는 어떻게 생기나

**"기록만 남기고 정본은 나중에" 로는 안 생긴다.** `cdp-save` ⑤ 는 한
커밋이고 그 요청은 skill 이 거절한다. 실제로 생기는 길은 —

| | |
|---|---|
| **머지** | 둘 다 절차를 지켰는데도 걸리는 유일한 경우 |
| skill 을 안 부름 | 1층은 비결정적이다 (작업환경 §8) |
| 중간에 끊김 | ③ 과 ④ 사이에서 세션이 끝난다 |

### 시키는 말

```
git switch -c a
  work/2026-0920-A-복명버튼.md   (screen:EXD020, 09-20) + 섹션 · applied=A
  커밋                                                    ← 통과
git switch main && git switch -c b
  work/2026-0921-B-첨부제한.md   (screen:EXD020, 09-21) + 섹션 · applied=B
  커밋                                                    ← 통과
git switch a && git merge b
```

### 일어나야 하는 것

`applied` 가 두 줄로 충돌한다. **옛것(A)을 남기면** —

```
[오류] 관리 문서 파생 누락  1건
   screen:EXD020  applied 2026-0920-A-복명버튼 뒤 후속 1건
exit=1
```

최신(B)을 남기면 통과한다. **둘 다 확인한다.**

**충돌을 해소하는 사람은 `applied` 의 의미를 모른다.** 두 줄 중 하나를 고를
뿐이고 절반의 확률로 틀린다. diff 에는 아무 표시가 없다.

---

## A3 같은 날 (**경고만**)

같은 좌표를 같은 날 두 번 건드리고 두 번째 파생을 뺀다.

```
[경고] 같은 날 기록이 더 있습니다 — 반영됐는지 눈으로 확인하세요
ctx check: 오류 없음 (경고 N건)      exit=0
```

**막지 않는 것이 맞다.** 날짜 입도가 하루라 순서를 모르고, 섹션이 이미 둘 다
담고 있을 수도 있다 — 기계가 판단할 수 없는 자리다. 오탐으로 커밋을 막으면
사람들이 목록 전체를 안 믿는다.

---

# B — 이미 쓴 문서가 있다 (`cdp-import`)

## B1 회의록 편입

### 시키는 말

> 이 회의록 지식 레포에 넣어 줘. (md 파일 하나를 준다)

원문에는 화면 이름이 여럿 나오고, 정해진 것과 "다음에 보자" 가 섞여 있다.

### 일어나야 하는 것

| | |
|---|---|
| **날짜** | 본문의 회의 일자. **오늘이 아니다** |
| **`author`** | 원문 작성자. 편입한 사람이 아니다 |
| **`source`** | 원문이 어디서 왔는지 |
| **좌표** | **정해진 것만.** 언급·배경·"검토하기로 했다" 는 좌표가 아니다 |
| **본문** | 그대로. 요약하지 않는다 |
| **미결** | 이슈 대장으로 간다. 하나의 원문이 둘로 갈라지는 것이 정상 |

판정 근거를 보여줘야 한다 —

```
【좌표 판정 — 원문: …】
  screen:EXA021   변경   … 로 결정
  screen:EXA022   언급   "다음 안건 화면도 봐야 한다" → 결정 아님
  ―― 이슈로 ――
  … 미결 → 위험및이슈관리대장
```

**제외한 것을 보여주지 않으면 사용자가 고칠 수 없다.**

### 확인

```
head -12 work/<id>.md         → date 가 회의일 · author 가 원문 작성자 · source 있음
ctx where <좌표>              → 반영이 편입 기록을 가리킨다
ctx check                     → 오류 없음
```

---

## B2 과거 문서 편입 — `applied` 를 바꾸지 않는다

편입 문서의 날짜가 **이미 반영된 기록보다 이전**인 경우.

```
ctx where screen:EXA021
  상태   반영 2026-0902-…          ← 09-02
편입: 2026-08-14                   ← 이전
```

섹션 본문의 `변경` 목록에 그 날짜로 한 줄만 끼우고 **`applied` 는 그대로
둔다.** 더 최신이 이미 실려 있다.

```
ctx derive     → 비어 있어야 한다
ctx check      → 오류 없음
```

`applied` 를 옛 문서로 바꿔 버리면 그 순간 **후속 1건이 생겨** 파생 누락으로
막힌다. 그것으로도 확인된다.

---

# C — 작업은 없고 문서 수정 지시 (`cdp-edit`)

## C1 지시가 곧 본문이다

### 시키는 말

> 사진 첨부 용량은 10MB 로 해줘. WAS 업로드 상한이 그거라서 20MB 로
> 적어 놔도 어차피 안 올라가.

코드 작업은 없다. 문서만 고친다.

### 일어나야 하는 것

관리 문서가 바뀌고 **작업 기록이 함께 생긴다.** 기록에 세 대목 —

```markdown
## 지시
> (말한 그대로 인용)
kjsa, 2026-09-08.

## 반영
docs/화면설계서.md ## EXD020 의 첨부 표에서 20MB → 10MB.

## 확인한 것
기존에 20MB 로 적혀 있었다. 어디서 왔는지 확인했고 회의에서 나온 말을
옮긴 것이지 WAS 설정을 본 것이 아니었다.
```

**지시를 요약하지 않는다.** "20MB 로 적어 놔도 어차피 안 올라가" 는 제약이
어디서 왔는지를 담고 있고, "10MB 로 변경" 으로 줄이면 6개월 뒤 "왜 10인가"
에 다시 답할 수 없다.

`author` 는 **지시한 사람**이다.

### 확인

```
ctx where screen:EXD020    → 반영이 이 기록을 가리킨다
git show --stat            → work/ 1 + docs/ 1
ctx check                  → 오류 없음
```

---

## C2 기계가 못 막는 자리 (**중요**)

**기록 없이 관리 문서만 고치고 커밋한다.**

```
docs/화면설계서.md 만 수정
git commit
```

### 일어나는 것

```
ctx check: 이상 없음        exit=0     ← 통과한다
```

**막히지 않는다.** 파생 누락 검사는 작업 기록을 기준으로 도는데 기록이
없으면 기준이 없다. 2층이 못 잡는 자리다.

그래서 `cdp-edit` 이 필요하다 — **1층이 지켜야 하는 유일한 자리**이므로,
이 시험의 목적은 "막히나" 가 아니라 **"skill 이 이 요청을 잡아채나"** 다.

---

# D — 막아야 하는 것들

| 시킬 것 | 나와야 하는 것 |
|---|---|
| 미등재 좌표(`table:rp_trip_photo_list`)를 쓴 기록 | **exit 1** · 미등재 + 섹션 없음 + (있으면) 파생 누락이 **한 번에** |
| `status: 진행중` | **exit 1** · `status 에 쓸 수 있는 값이 없습니다` |
| `status: 미결` | **exit 1** · `아젠다입니다 — 이슈 대장으로` |
| `status: 확정` · `완료` | 통과. 기본값이라 파싱 경계에서 지워진다 |

앞의 셋은 메시지가 **서로 달라야 한다.** 미결은 갈 곳이 있고 진행중은 없다.

---

# E — 뷰어

`tools{B}cdp.exe` 로 열어 세 길의 결과가 다 보이는지 본다.

| 보는 곳 | |
|---|---|
| 작업문서 탭 | A·B·C 기록이 **작성일자순** · 작성자가 각각 다르다 |
| 관리문서 탭 | 해당 섹션이 새 내용 |
| 좌표 탭 | 새 좌표가 있다 |
| 그래프 | 그 좌표 노드가 커졌다 · 왼쪽 목록에서 골라 찾을 수 있다 |
| 뻗어나가기 | 작업문서 → 관리문서·좌표 |

**B 기록의 `author` 가 다른 사람 이름으로 뜨는지** 특히 본다 — 편입이
제대로 됐다는 눈에 보이는 증거다.


## 점검표

| | | 통과 기준 |
|---|---|---|
| ☐ | A1 | 주입에 "붙일 곳이 없어서" · 한 커밋 · `ctx where` 가 새 기록 |
| ☐ | A2 옛 applied | **exit 1 · derive-missing** |
| ☐ | A2 새 applied | 통과 |
| ☐ | A3 | **경고** · exit 0 |
| ☐ | B1 날짜 | `date` 가 회의일. 오늘이 아니다 |
| ☐ | B1 좌표 | 언급만 한 것이 `touches` 에 **없다** |
| ☐ | B1 본문 | 원문이 그대로다 · `source` 가 있다 |
| ☐ | B1 미결 | 이슈 대장으로 갔다 |
| ☐ | B2 | `applied` 가 안 바뀌었다 · `ctx derive` 가 비었다 |
| ☐ | C1 | 지시가 **인용**으로 남았다 · `author` 가 지시자 |
| ☐ | C2 | **통과한다** — 그리고 그것이 skill 이 필요한 이유다 |
| ☐ | D | 넷 다 예상대로 |
| ☐ | E | 다섯 자리 · B 의 작성자가 다르게 뜬다 |
| ☐ | 정리 | 흔적 0 |

**막아야 할 것이 안 막히면 실패다.** C2 는 예외 — 거기서 통과하는 것이
설계이고, 그래서 `cdp-edit` 이 있다.
