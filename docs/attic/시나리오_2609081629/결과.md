## A — 이 세션에서 작업했다

### A1 정상

`ctx where` + 섹션 읽기에서 **이미 있던 결정이 나왔다.**

> 차를 안 가져간 사람이 사진을 붙이려는데 **붙일 곳이 없어서** 복명만 하고
> 담당자에게 전화했다

이것이 CDP 의 목적이다 — 모르는 채로 같은 결정을 다시 하지 않는 것.

### A2 머지 — 초판이 틀렸던 자리

초판 시나리오는 "기록만 남겨줘" 를 시험했다. **생기지 않는 상태였다** —
`cdp-save` ⑤ 는 한 커밋이고 그 요청은 skill 이 거절한다.

머지로 바꿔 재현했다. A(09-20)와 B(09-21)가 각자 절차를 지켜 커밋했고,
머지에서 `applied` 가 두 줄로 충돌한다.

```
옛것(A)을 남긴다  →  [오류] applied 2026-0920-A-복명버튼 뒤 후속 1건   exit=1
최신(B)을 남긴다  →  통과
```

**아무도 잘못하지 않았다.** 충돌 해소자는 `applied` 의 의미를 모르고 한 줄을
고를 뿐이고, 절반의 확률로 틀린다. diff 에는 아무 표시가 없다.

### A3 같은 날 — 경고가 실제로 동작한다

```
[경고] 같은 날 기록이 더 있습니다 — 반영됐는지 눈으로 확인하세요  6건
   screen:EXD020  applied 2026-0921-B-첨부제한 와 같은 날 1건 — 2026-0921-B-용량
ctx check: 오류 없음 (경고 7건)      exit=0
```

이번에 추가한 규칙이다. 직전 수행에서 **이 자리가 통째로 안 보였다.**

## B — 이미 쓴 문서가 있다 (`cdp-import`)

회의록 한 장을 만들어 넣었다. 원문에는 화면 이름이 여럿 나오고 정해진 것과
"다음에 보자" 가 섞여 있다.

### 좌표 판정 — 이 skill 의 존재 이유

```
screen:EXA021         변경   외부 위원 그리드에 소속 컬럼 추가로 결정
code:PS130            신설   업무구분 코드그룹 신설로 결정
screen:EXA022         언급   "한번 봐야 한다" · 이번 범위는 아니다  → 좌표 아님
table:ps_ext_emp_mst  배경   "현재 그대로 쓴다. 별도 변경 없음"     → 좌표 아님
―― 이슈로 ――
A10 결재 취소 자동 반영   결정 못 함 → ISS-003 에 붙였다
```

**넷 중 둘만 좌표다.** 넷 다 넣었으면 채울 내용 없는 파생 의무가 둘 더
생기고, 억지로 채우면 틀린 내용이 정본에 들어간다.

### 편입 결과

```
id: 2026-0814-연심회준비-회의록
date: 2026-08-14        ← 회의한 날. 오늘이 아니다
author: 홍길동           ← 원문 작성자. 편입한 사람이 아니다
source: 2026-08-14 연심회 준비회의록.md
touches: [screen:EXA021, code:PS130]
```

본문은 그대로다. 원문의 인용("소속 없으면 명단이 아니죠")과 범위 밖 논의가
그대로 남아 있다 — 6개월 뒤 "왜 소속을 넣었나" 의 단서다.

### 곁들여 나온 것 — 원문과 어휘의 이름이 다르다

원문은 `PS130` 이라 쓰는데 이 레포의 코드 어휘는 `PS-0xx` 꼴이다.
`ctx match` 가 `(미등재)` 로 잡아냈다.

실제 프로젝트가 쓰는 이름(`PS130`)을 정본으로 등재하고 `업무구분` 을
별칭으로 걸었다. **밖에서 온 문서를 들일 때 반드시 나오는 종류의 마찰**이고,
`ctx match` 를 거치지 않으면 조용히 두 이름이 생긴다.

### B2 과거 문서 — `applied` 를 바꾸지 않는다

`screen:EXA021` 은 09-02 가 이미 반영돼 있고 편입 문서는 08-14 다.
섹션의 `변경` 목록에 한 줄만 끼우고 `applied` 는 그대로 뒀다.

```
그대로 둔다        → ctx derive: 파생 남은 섹션 없음
옛 문서로 바꾼다   → 파생 남은 섹션 1곳 (+ 2026-09-02 후속)
```

**기계가 규칙을 확인해 준다.** 판단이 헷갈리면 `ctx derive` 를 돌리면 된다.

## C — 작업은 없고 문서 수정 지시 (`cdp-edit`)

### C1 지시가 곧 본문이다

```markdown
## 지시
> 사진 첨부 용량은 10MB 로 해줘. WAS 업로드 상한이 그거라서 20MB 로
> 적어 놔도 어차피 안 올라가.
kjsa, 2026-09-22.

## 반영
docs/화면설계서.md ## EXD020 의 사진 첨부 대목에 용량 10MB.

## 확인한 것
앞서 20MB 로 적혀 있었다. 회의에서 나온 말을 옮긴 것이고 WAS 설정을 본
것이 아니었다. 제약이 WAS 에 있으므로 근거를 함께 적는다 — 근거 없이
숫자만 있으면 다음 사람이 또 올린다.
```

`work/` 1 + `docs/` 1 이 한 커밋. `ctx where` 가 이 기록을 가리킨다.

**요약하지 않은 것이 핵심이다.** "20MB 로 적어 놔도 어차피 안 올라가" 가
제약의 출처를 담고 있고, "10MB 로 변경" 으로 줄이면 그것이 사라진다.

### 수행 중 나온 것 — 지시 날짜가 과거면 막힌다

처음에 지시일을 09-08 로 잡았는데 A2 가 09-20·09-21 기록을 넣어 둔 상태라
**지시가 과거가 되어 커밋이 막혔다.** 시험 데이터의 날짜 문제이지 제품
결함은 아니다. 다만 실무에서도 같은 일이 난다 — **지시일을 임의로 적으면
안 된다.** 09-22 로 옮기니 통과했다.

### C2 기계가 못 막는 자리

기록 없이 관리 문서만 고치고 커밋했다.

```
$ ctx check
ctx check: 오류 없음 (경고 5건)
$ git commit
[test/... 652d90e] 확장자 heic 추가        exit=0
```

**통과한다.** 파생 누락 검사는 작업 기록을 기준으로 도는데 기록이 없으면
기준이 없다.

이것이 `cdp-edit` 이 존재하는 이유다. 2층(git 훅)이 닿지 않는 유일한
자리이므로 **1층(skill)이 지켜야 한다.** 그래서 이 항목의 통과 기준은
"막히나" 가 아니라 **"skill 이 이 요청을 잡아채나"** 이고, 그것은 skill 이
로드된 세션에서만 확인할 수 있다.

## D — 막아야 하는 것들

```
[오류] _vocab.md 미등재 좌표  1건
   table:rp_trip_photo_list
[오류] status: 미결·제안 — 지식공유문서가 아니라 아젠다입니다  1건
   status: 미결 — docs/위험및이슈관리대장.md 로 옮기세요
[오류] status 에 쓸 수 있는 값이 없습니다 — 지우세요  1건
   status: 진행중 — 지식공유문서는 완료된 것만 옵니다
[오류] 등록부가 가리키는 섹션이 없음  1건

ctx check: 오류 4건.       exit=1
```

`status: 확정` · `완료` 는 **아무 말 없이 통과**했다. 기본값이라 파싱
경계에서 지워진다. 그리고 미결과 진행중의 **메시지가 서로 다르다** —
미결은 갈 곳이 있고 진행중은 없다.
