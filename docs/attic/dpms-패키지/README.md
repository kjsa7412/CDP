# dpms 패키지가 어디서 나왔나

`agent/packages/dpms` 를 만든 기록이다. **배포본에 들어가지 않는다** —
받는 사람에게 `convert_table.py` 는 원본 xlsx 가 없어 돌릴 수도 없다.

## 원천

```
C:\project\DPMS\
  01. 관리 산출물(BM)\      사업관리 11종
  02. 개발 산출물\          분석 · 설계 · 구현 · 시험 · 이행 36종
```

**형상관리대장(`GDI_BM_301`)이 정본 목록이다** — 폴더 구조가 아니다.
두 시트(`사업관리` 10행 · `공정관리` 40행)에서 47종을 뽑았고, 대장에 없으나
실물이 있는 **회의록**을 더했다.

> **원본 xlsx·pptx 는 여기 넣지 않는다.** 발주처 산출물이다. 대신 **어디에
> 있었는지와 어떻게 변환했는지**를 남긴다 — `viewer/fixture` 의 테이블정의서가
> 생성 원천을 개인 PC Desktop 에만 두어 **덤프 없는 PC 에서 32섹션이
> 1섹션으로 줄었던 사고**(커밋 `caa835a`)가 있었다.

## 47종 → 46 문서

| | |
|---|---|
| 산출물 47종 | 형상관리대장 기준 (BM 11 + 개발 36) |
| 문서 46개 | `데이터이관정의서` 가 설계(`DE_461`)와 구현(`EC_301`)에 **띄어쓰기만 다르게** 두 번 올라 있다. 한 문서로 합쳤다 |

## 원본에서 고친 것

| | 원본 | 패키지 |
|---|---|---|
| 제출시기 표기 | `설계 완료`(사업관리 시트) · `설계완료`(공정관리 시트) | **`설계완료`** 하나로 |
| 데이터이관정의서 | `DE_461` 데이터이관정의서 · `EC_301` 데이터이관 정의서 | **한 문서로** |

첫 줄은 두 시트를 다른 사람이 관리해서 생긴 표기 차이다. 같은 시점을 가리키는데
갈라져 있으면 **"설계가 끝나면 무엇이 나와야 하나" 의 답이 쪼개진다** — 그리고
빠지는 것이 중간보고서였다.

## 변환

`convert_table.py` 는 테이블정의서 하나를 변환한다. 나머지는 아직 없다.

```
python docs/attic/dpms-패키지/convert_table.py <출력경로>
```

`GDI` 시트가 **54행 고정 블록 × 77** 이라는 구조에 의존한다. 다른 프로젝트의
테이블정의서는 구조가 다를 수 있다 — **그대로 쓰지 말고 읽고 고쳐 쓴다.**

## 패키지 README 에서 옮긴 것 (2026-10-02)

`dpms` 를 `public-si` 로 이름 바꿀 때 패키지 `README.md` 에서 뺀 두 절이다 — **원천 사업의 폴더와 실물을 센 기록**이라
받는 사람의 것이 아니다(패키지 재편 검토 v0.1 P3). 패키지에는 「어디서 왔나」 한 단락만 남았다.
### 왜 40종인가 — **폴더가 정본이다**

원천은 `C:\project\DPMS` 의 **폴더 구조**다. 형상관리대장이 아니다.
대장은 이 사업에서 **고쳐야 할 문서**이고, 폴더가 실제 일하는 자리를 말한다.

폴더에 산출물 자리가 **32개** 있고, 거기에 40종이 들어간다.

| | |
|---|---|
| 대장 고유 산출물 | 45 |
| **폴더에 자리가 없어 뺀 것** | **−7** |
| 요구사항추적표 | **−1** |
| **폴더에 자리가 있는데 대장이 비운 것** | **+2** |
| 대장에 없는데 폴더·번호·실물이 다 있는 것 | **+1** (회의록) |
| | **40** |

#### 뺀 7종 — 폴더에 자리가 없다

| | 대장 | 폴더 |
|---|---|---|
| 보안서약서 | `BM_601` | 보안관리 자리 없음 |
| 데이터 값 검증 방안서 · 업무규칙(BR) 정의서 | `DE_431` | 데이터구조검증 자리 없음 |
| 메타데이터 현행화 결과 · 데이터 개방 지원 방안 | `DE_441` | 데이터개방 자리 없음 |
| ERD모델링 | `DE_421` | 전용 자리 없음 — 관계는 테이블정의서의 `키` 칸이 갖는다 |
| 인터페이스목록 | `AN_241` | 전용 자리 없음 — 목록은 `INDEX-by-coord.md` 가 만든다 |

**되살리려면** 그 TASK 폴더를 만들고 대장에 행을 더한 다음 문서를 세운다.
`관리번호.md`(패키지 안) §4 가 번호 주는 법이다.

#### 더한 2종 — 폴더가 자리를 만들어 두었다

| 자리 | 세운 것 |
|---|---|
| `03. 구현(EC)/03. 데이터이관계획` | `EC_301` 데이터이관계획서 |
| `05. 이행(TR)/01. 구축/01. 데이터이관` | `TR_111` 데이터이관결과서 |

**이관이 셋으로 갈린다** — 무엇을(`DE_601` 정의서) · 언제 어떻게(`EC_301`
계획서) · 어떻게 됐나(`TR_111` 결과서). 대장은 정의서를 두 번 세고 나머지
둘을 비워 두었다.

#### 요구사항추적표는 뺐다

요구사항이 어느 화면 · 프로그램 · 시험으로 갔는지는 손으로 유지하는 표가
아니라 **좌표가 답한다** — `ctx where 요구사항:…` 가 그 요구사항에 실린 작업을
전부 세우고 `INDEX-by-coord.md` 가 파일로 만든다.

#### 비어 있는 자리 하나

`01. 분석(AN)/01. 사전분석` 에는 산출물이 없다. 대장은 여기에 "현황분석"
6종을 걸었지만 **그 문서들은 전부 설계 단계 정본이 있다**(프로세스정의서 ·
기능정의서 · 프로그램목록 · 코드정의서 · 시스템아키텍처정의서). AS-IS 를 따로
관리하지 않기로 했으므로 자리를 비워 둔다.

### 서식 원본이 없는 15종

40종 중 **25종**은 DPMS 에 실물이 있다 — 21종은 이 사업 것이고 4종은 타 사업
서식(`DB개발가이드` · `개발가이드` · `프로그램사양서` · `검수요청서`)이다.
나머지 15종은 **골격만 세웠다.**

| | |
|---|---|
| 보고 4 | 착수 · 중간 · 완료보고서 · 사업수행계획서 |
| 시험 6 | 단위 · 성능 테스트의 계획서 · 시나리오 · 결과서 |
| 이행 3 | 운영자메뉴얼 · 사용자메뉴얼 · 안정화계획서 |
| 이관 2 | 데이터이관계획서 · 데이터이관결과서 — 폴더에만 자리가 있던 것 |

필수 제출물 둘(`착수보고서` · `사업수행계획서`)은 **발주처 양식**이라 패키지가
정할 것이 아니다. 첫 프로젝트가 채우면 그것이 두 번째 패키지의 씨앗이 된다.
