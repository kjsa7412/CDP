# 템플릿 규약

2026-09-14 · 대상 47종 · 분석은 [`02_문서분석.md`](02_문서분석.md)

## 0. 이 규약은 코드에서 나왔다

서식을 먼저 상상하고 도구가 받아 주기를 바라지 않는다. **`core/`
가 실제로 무엇을 파싱하는지 읽고** 거기서 규약을 역산했다. 어긋나면 문서는
멀쩡해 보이는데 좌표가 안 잡히고, **그것은 조용하다.**

읽은 것 — `managed.js`(섹션·등록부) · `frontmatter.js`(층·프론트매터) ·
`check.js`(검사 범위) · `DocView.jsx`(경고 표시).

## 1. 도구가 강제하는 것 — 열 가지

| # | 제약 | 근거 | 어기면 |
|--:|---|---|---|
| 1 | 관리 문서는 **`docs/*.md`** 에 있어야 한다 | [frontmatter.js:23](../../core/frontmatter.js:23) | 층 판정이 `null` — 문서로 안 읽힌다 |
| 2 | 섹션 **레벨이 등록부와 정확히 같아야** 한다 | [managed.js:191](../../core/managed.js:191) | `## {값}` 인데 `###` 로 쓰면 **안 잡힌다** |
| 3 | 섹션 값은 제목에서 **` — ` 앞부분**이다 | [managed.js:121](../../core/managed.js:121) | 값에 ` - ` 가 있으면 잘린다 |
| 4 | `<!-- applied: -->` 는 제목 **3줄 안**에 | [managed.js:133](../../core/managed.js:133) | 밀리면 `applied 없음` 으로 잡힌다 |
| 5 | 값 비교는 **소문자화 + `[공백 _ · -]` 제거** 후 | [managed.js:156](../../core/managed.js:156) | `PS001` 과 `ps-001` 이 **같은 값**이다 |
| 6 | 코드펜스 안의 `#` 는 섹션이 아니다 | [managed.js:30](../../core/managed.js:30) | (예시를 넣어도 안전하다는 뜻) |
| 7 | `<!-- -->` 줄과 `>` 인용 줄은 **내용으로 안 센다** | [managed.js:147](../../core/managed.js:147) | 인용만 있으면 **빈 섹션**이다 |
| 8 | 관리 문서 프론트매터는 **검사 대상이 아니다** | [check.js:36](../../core/check.js:36) | 필수 필드·오류 검사가 `work/` 에만 돈다 |
| 9 | 등록부 **패턴은 대소문자를 구분**한다 | [managed.js:25](../../core/managed.js:25) | `scenario:ut-*` 가 `scenario:UT-*` 에 안 걸린다 |
| 10 | 좌표 값에 **공백을 못 쓴다** | [vocab.js:14](../../core/vocab.js:14) | `\S+` 로 검사한다. 한글은 된다 |

### 3 · 5 · 9 가 실제로 문제를 일으키는 자리

**3번** — 섹션 제목을 `## <값> — <이름>` 으로 쓰는데, 구분자는 **공백으로 둘러싸인**
`—` `–` `-` 셋 다다. 그래서 **값 안에 ` - ` 를 쓸 수 없다.**

```
## SFR-01-01 — 전자정부프레임워크 기반       ✔  값 = SFR-01-01   (하이픈에 공백이 없다)
## 응시 원서 - 접수부 — 설명                  ✖  값 = "응시 원서"  로 잘린다
```

**5번** — `PS001` `ps-001` `PS_001` `ps 001` 이 전부 같은 값으로 읽힌다.
관대해서 좋은 쪽이 크지만(별칭이 저절로 걸린다), **정규화 후 충돌하는 좌표가
있으면 둘이 한 섹션을 가리킨다.** 어휘를 등록할 때 확인할 것이 하나 생긴다.

**9번은 5번과 방향이 반대라 더 위험하다.** 등록부 패턴은 대소문자를 **구분**하고
섹션 값 비교는 **무시**한다. 규칙이 둘로 다르므로 좌표 표기를 `_vocab.md` 에
하나로 고정해 두고 거기서만 복사해 쓴다.

## 2. 문서 하나의 골격

```markdown
# 테이블 정의서

연구관리(RP) 스키마. `GDI_DE_422_테이블정의서` 에서 옮겼다.

<!-- 연구과제 -->

## rp_plnd_mst — 계획서마스터
<!-- applied: 2026-0903-계획서-상태값추가 -->

| 컬럼 | 타입 | NULL | 키 | 설명 |
|---|---|:--:|:--:|---|
| `WRK_MAST_ID` | VARCHAR(20) | N | PK | 업무마스터ID |

**변경** · 2026-09-03 [`계획서-상태값추가`](../work/2026-0903-계획서-상태값추가.md) `50`(반려) 추가
```

| 자리 | 규칙 |
|---|---|
| `# ` 한 줄 | 문서명. **파일명과 같은 이름을 쓴다** |
| 설명 문단 | 무엇을 담는 문서인가 · **원본이 무엇인가**. 2~4줄 |
| `<!-- 그룹 -->` | 분류. **제목으로 쓰지 않는다** — 제약 2 때문 |
| `## <값> — <이름>` | 섹션. 값이 좌표다 |
| `<!-- applied: -->` | 바로 다음 줄 |
| 본문 | 상태. 표 또는 산문. **형식 자유** |
| `**변경** · …` | 이력. **제목이 아니라 볼드 텍스트** |

### 그룹을 어떻게 표시하나 — 좌표 레벨에 따라 갈린다

| 좌표 레벨 | 그룹 | 예 |
|---|---|---|
| `## {값}` | **HTML 주석** `<!-- 연구과제 -->` | 화면설계서 · 테이블정의서 · 코드정의서 |
| `### {값}` | `##` 을 그룹으로 | DB도메인용어정의서 (`## 산출물` → `### 응시원서접수부`) |

**하위 제목을 쓰지 않는다.** 좌표가 `###` 인 문서에서 `### 변경` 같은 것을 쓰면
그것도 섹션으로 잡힌다(제약 2·5). 이력은 볼드 텍스트로 적는다 — viewer/fixture
16종이 전부 그렇게 돼 있고, 그게 우연이 아니다.

### 미작성 섹션

```markdown
## PSC043 — 면접심사의견서
<!-- applied: null -->

> ⚠ 아직 정리되지 않았습니다.
```

인용줄은 내용으로 안 세므로(제약 7) **빈 섹션으로 잡힌다.** 의도된 것이다 —
빈 섹션을 감추지 않는다. 작업 기록이 아직 없는 섹션은 위반이 아니다.

## 3. 프론트매터 — 관리 문서에는 **쓰지 않는다**

DPMS 문서들은 관리번호 · 제출시기 · 제출여부 · 승인내역을 갖고 있다. 그것을
YAML 프론트매터로 올리고 싶어진다. **지금은 올리지 않는다.**

| 사실 | 근거 |
|---|---|
| 관리 문서 프론트매터는 **검사가 안 본다** | [check.js:36](../../core/check.js:36) — `units` 가 `work/` 로만 잡힌다 |
| 모르는 필드는 **뷰어가 경고를 띄운다** | [DocView.jsx:234](../../viewer/src/components/DocView.jsx:234) |
| 허용 필드는 9개로 박혀 있다 | [frontmatter.js:180](../../core/frontmatter.js:180) — id title date author status touches supersedes attachments tags |

즉 지금 프론트매터를 넣으면 **읽는 기능은 없고 경고만 47개 뜬다.**

**그래서 메타는 문서 머리에 표로 둔다.**

```markdown
# 테이블 정의서

연구관리(RP) 스키마의 지금 상태. 섹션 하나가 테이블 하나다.

| | |
|---|---|
| 관리번호 | `GDI_DE_422` |
| 제출시기 | 설계완료 |
| 필수 제출 | 아니오 |
| 원천 | `GDI_DE_422_테이블정의서.xlsx` · `GDI` 시트 |
| 좌표 | `table:` — 값은 테이블 물리명 |
```

사람이 읽고, 검색에 걸리고, 도구를 안 고쳐도 된다.

> **언제 프론트매터로 올리나** — "지금 단계에서 갱신이 밀린 문서" 를 기계가
> 물으려 할 때다. 그때 `frontmatter.js` 의 허용 목록을 늘리고 이 표를
> 프론트매터로 옮긴다. **기능이 생긴 뒤에 옮긴다** — 먼저 옮기면 읽는 곳이
> 없는 데이터가 47개 생긴다.

## 5. 유형별 골격

### ① 좌표형 — 섹션 = 좌표

```markdown
## <좌표값> — <이름>
<!-- applied: <작업기록 id> -->

<상태. 표 또는 산문>

**변경** · <YYYY-MM-DD> [`<work id>`](../work/<파일>.md) <무엇이 바뀌었나>
```

| 문서 | 레벨 | 값 | 그룹 |
|---|:--:|---|---|
| 요구사항정의서 | `##` | `SFR-01-01` · `USR-RP-01` | `<!-- 기능(SFR) -->` |
| 프로세스정의서 | `##` | `1.2.3` *(입도 미정)* | `<!-- 연구과제선정 -->` |
| 기능정의서 | `##` | `FNC_RP_01` | `<!-- 연구과제 -->` |
| 시스템아키텍처정의서 | `##` | `hw` `db` `sw` `link` | — |
| 화면설계서 | `##` | `SEA011` | `<!-- 연구과제선정 -->` |
| DB도메인용어정의서 | `###` | `가격배수값` *(단위 미정)* | `## <분류>` |
| 테이블정의서 | `##` | `rp_plnd_mst` | `<!-- 연구과제 -->` |
| 코드정의서 | `##` | `PS001` | `<!-- 인사(PS) -->` |
| 인터페이스정의서 | `##` | `INT_RP_1001` | `<!-- G20 연계 -->` |
| 프로그램사양서 | `##` | `SEA011` | `<!-- 연구과제선정 -->` |
| 위험및이슈관리대장 | `##` | `SJ-RIS-01` | — |
| 테스트시나리오 | `##` | *(D4 미정)* | `<!-- 통합 -->` |

### ② 대장형 — 표 하나. 섹션이 없다

```markdown
# 프로그램 목록

전체 프로그램의 집계. **각 프로그램의 내용은 프로그램사양서가 갖는다.**
여기는 무엇이 있는지만 본다.

| | |
|---|---|
| 관리번호 | `GDI_DE_321` |
| 등록부 | **비대상** — 목록은 집계다 |

| 대분류 | 중분류 | 프로그램ID | 프로그램명 | 권한 | 비고 |
|---|---|---|---|---|---|
| PS 인사 | PSB 인적정보 | `PSB010` | 인사기본정보 | | |
```

**좌표를 링크로 걸지 않는다.** `prog:PSB010` 의 정본은 프로그램사양서다.
대장에서 링크를 걸면 정본이 둘로 보인다 — 값만 적고 뷰어의 좌표 검색에
맡긴다.

### ③ 사건형 — 섹션 = 날짜

```markdown
# 회의록

날짜축. 회의는 대상이 아니라 사건이라 좌표-섹션이 1:1로 대응하지 않는다.
**등록부 비대상**이다.

## 2026-04-21 — 중간보고
<!-- applied: null -->

| | |
|---|---|
| 장소 | 세정아이앤씨 |
| 참석 | 마종희 · 사경진 (세정) · 하영진 (경북연구원) · 조문영 (더존) |

1. **결재 시스템 이력 관리** — 과제 결재 이력은 삭제되지 않는다. …
```

날짜를 `##` 값으로 쓰되 **등록부에는 올리지 않는다.** 올리면 `날짜:*` 라는
좌표 타입이 생기는데, 날짜는 바꾸는 대상이 아니다.

> **주간·월간보고서는 같은 골격에 주기만 다르다**(분석에서 확인). 서식 하나로
> 두고 `## 2026-W05 — 1/19~1/23` · `## 2026-03 — 3월` 로 값만 바꾼다.

### ④ 서술형 — 섹션이 대상이 아니다

```markdown
# 개발 가이드

| | |
|---|---|
| 관리번호 | `GDI_DE_311` |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

## 명명 규칙
## 예외 처리
```

제목을 자유롭게 쓴다. **등록부에 올리지 않으므로 제목이 좌표와 충돌하지
않는다.** 다만 등록부에 올릴 생각이 조금이라도 있으면 그때는 제약 2·3·5 가
살아난다.

> 서술형도 `—`(문서 전체)로 등록부에 올릴 수는 있다([managed.js:70](../../core/managed.js:70)
> 가 `—` 를 "문서 전체가 그 좌표의 상태" 로 받는다). **지금은 안 쓴다** —
> 쓸 좌표가 없다.

## 6. 큰 표를 어떻게 쓰나

DPMS 문서는 컬럼이 많다 — 테이블정의서 TO-BE 8열, 코드정의서 상세 19열,
인터페이스정의서 21열. **그대로 옮기면 MD 표가 가로로 터진다.**

### 규칙 — 세 갈래로 나눈다

| 무엇 | 어디에 | 왜 |
|---|---|---|
| **매 행마다 다른 값** | 표 컬럼 | 비교하며 읽는 것 |
| **섹션 전체에 하나인 값** | 섹션 머리 `| | |` 표 | 반복하면 표가 넓어진다 |
| **대부분 비어 있는 값** | 있는 행에만 산문/비고 | 빈 칸 컬럼은 자리만 먹는다 |

테이블정의서 예 —

```markdown
## rp_plnd_mst — 계획서마스터
<!-- applied: null -->

| | |
|---|---|
| DB USER | `dbo` |
| AS-IS | `RP_PLAN_MST` |

| 컬럼 | 타입 | NULL | 키 | 기본값 | 설명 |
|---|---|:--:|:--:|---|---|
| `WRK_MAST_ID` | VARCHAR(20) | N | PK | | 업무마스터ID |
| `WRK_CHASU` | VARCHAR(5) | N | | `1` | 업무차수 |
```

`COMMENT` 는 `설명` 으로, `DEFAULT` 는 비어 있는 행이 대부분이라 뒤로 뺐다.

### 가로로 펼친 축은 값 하나로 접는다

기능정의서의 `단계 1~8` 이 그렇다. 컬럼 8개 중 7개가 항상 비어 있다.

```
원본   … | 필수 | 선택 | 조건 | 4 | 5 | 6 | 7 | 8 | 내용 | …
         |      | 연구활동 접수 |   |   |   |   |   |   | …

MD     **단계** 2 (선택) — 연구활동 접수
```

**표의 가로 위치는 엑셀에서 흐름을 눈으로 보려던 장치이지 데이터가 아니다.**

### 같은 값의 섹션을 두 번 만들지 않는다

파서는 값이 같은 섹션 중 **첫 번째만 찾는다**([managed.js:190](../../core/managed.js:190)
가 `find` 다). 두 번째부터는 **도달 불가 섹션**이 된다 — 화면에는 보이는데
좌표로는 영영 안 걸린다.

원본에 중복이 있다. DB도메인용어집 도메인 시트는 논리명 4,671개에 **중복
404건**이고, 그중 399건은 물리명까지 같은 순수 중복행이다(§05 실측).

```
변환할 때   물리명까지 같은 중복  →  버린다
            값이 다른 동명이의     →  사람이 정본을 정하고 aliases 로 건다
```

**정규화 충돌도 본다.** `관리번호ID` 와 `관리번호id` 는 제약 5 때문에 같은
값이다. 실제로 한 건 있었다.

### 목록이 필요하면 만들지 않는다

인터페이스정의서는 요약 시트와 상세 시트가 갈려 있다. MD 에서는 **섹션 하나에
둘 다 넣고** 목록은 `INDEX.md` 가 만든다 — `ctx index` 가 재생성한다.
사본을 손으로 유지하지 않는다.

## 7. 원본을 어디까지 옮기나

| 옮긴다 | 버린다 |
|---|---|
| 값 · 관계 · 판단 근거 | 색 · 셀 병합 · 열 너비 · 그림의 배치 |
| 이력(변경 영역 · 등록/수정 컬럼 · 셀 안 날짜 접두) | 서명란 · 승인 도장 자리 |
| 작성지침 | 빈 템플릿 행(테이블정의서 블록 1번 같은 것) |
| 흐름의 순서와 분기 | 스윔레인 그림 자체 |

### AS-IS 를 어떻게 하나 — **TO-BE 만 상태다**

테이블정의서 · 화면설계서 · 프로그램목록이 전부 AS-IS ↔ TO-BE 대칭이다.
**관리 문서는 "지금 상태" 하나이고 AS-IS 는 지금이 아니다.**

> **실측 정정** — 테이블정의서 `GDI` 시트의 AS-IS 열은 **76블록 전부 비어
> 있다**([`05_실측.md`](05_실측.md) §2). 대응 관계는 `테이블목록` 시트에
> 따로 있다(AS-IS 354 ↔ TO-BE 46). 머리 표의 `AS-IS` 줄은 **그 시트에서**
> 채운다.

```
TO-BE      → 섹션 본문 (상태)
AS-IS 대응  → 섹션 머리 표에 한 줄 (`AS-IS | RP_PLAN_MST`)
전체 대응표 → 대장형 문서 하나 (테이블목록 · 이관대상 목록)
```

이관이 끝나면 머리 표의 AS-IS 줄을 지운다. **그때 지우는 것이 맞다** —
남겨 두면 6개월 뒤 사람이 둘 중 어느 것이 지금인지 묻는다.

### 그림은 어떻게 하나

프로세스정의서 40장이 흐름도이고, 화면설계서 147장이 레이아웃이다.

| | |
|---|---|
| 흐름도 | **텍스트로 옮긴다.** 값은 순서와 분기이고 둘 다 적을 수 있다 |
| 화면 레이아웃 | **그림을 첨부로 둔다.** `viewer/fixture/work/assets/` 에 전례가 있다 |

> **뷰어는 mermaid 를 렌더하지 않는다** — `viewer/src/lib/markdown.js` 가
> markdown-it 만 쓰고 mermaid 는 코드·설정 어디에도 없다. 확인하지 않은 기능을 서식에 넣지
> 않는다 — 흐름은 번호 목록과 표로 적는다. **D 단계에서 실제로 한 장을
> 옮겨 보고 결정한다.**

## 8. 작성지침 — 문서마다 붙인다

위험및이슈관리대장에만 있던 `작성지침` 시트를 **47종 전부에 적용한다**
(분석 §관통하는 발견 ④).

문서 맨 아래에 둔다.

```markdown
---

## 작성지침

이 문서는 **연구관리 스키마의 지금 상태**다. 테이블을 바꾸면 그 섹션을 고친다.

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<물리명 소문자> — <논리명>` | 필수 |
| `applied` | 이 섹션에 반영한 작업 기록 id. 없으면 `null` | 필수 |
| 컬럼 표 | TO-BE 기준. 타입은 원본 표기 그대로 | 필수 |
| AS-IS | 이관 전까지만. 끝나면 지운다 | 선택 |
| 변경 | `**변경** · 날짜 [작업기록] 무엇이` | 작업 후 필수 |
```

**왜 문서마다 붙이나** — 서식에 "이 칸에 무엇을 어떻게 적나" 가 없으면
사람마다 다르게 적고, 그때부터 문서가 검색되지 않는다. DPMS 에서 이미
그렇게 됐다 — 이력을 적을 자리가 없으니 `[20260204]` 와 `<7/5 기준>` 두 가지
표기가 각각 생겼다.

지침은 **`## 작성지침`** 이라는 제목을 쓴다. 값이 `작성지침` 인 섹션으로
잡히지만 그런 좌표가 없으므로 무해하고, 뷰어 목차에 나와 찾기 쉽다.

> 다만 **좌표가 `##` 인 문서에서는 이것도 섹션으로 센다.** 통계(섹션 수)에
> 1이 더해진다. 감수할 만하다 — 감추려고 HTML 주석에 넣으면 사람이 못 읽는다.
