# 실측 — 테이블정의서 변환과 규모

2026-09-14 · 규약 [`03_템플릿규약.md`](03_템플릿규약.md) · 좌표 [`04_좌표와등록부.md`](04_좌표와등록부.md)

## 0. 무엇을 쟀나

세 가지다.

```
① 규약대로 변환이 되는가        테이블정의서 → docs/테이블정의서.md
② 규모가 감당되는가             ctx check 시간 · 파일 크기
③ term: 을 어느 단위로 할 것인가  도메인(5,117) vs 용어사전(1,726)
```

**실측용 지식 레포를 만들어 진짜로 돌렸다.** 스크래치패드에 `bin/ctx` ·
`_vocab.md` · `_managed.md` · `docs/` · `work/` 를 갖춘 레포를 세우고
`node viewer/bin/ctx-cli.mjs check --repo <경로>` 를 실행했다.

## 1. 변환 실측 — 테이블정의서

| | 원본 | MD |
|---|---|---|
| 크기 | `GDI` 시트 4,932행 | **115 KB · 2,049행** |
| 단위 | 54행 고정 블록 × 77 | `##` 섹션 **77** (테이블 76 + 작성지침 1) |
| 컬럼 | — | 표 행 **1,565** (블록당 최대 41) |

viewer/fixture 의 같은 문서가 47 KB · 32섹션이므로 **2.4배**다.

**규약대로 나왔다.** 섹션 제목 `## rp_rsch_prj_mst — 연구과제마스터`,
바로 다음 줄 `<!-- applied: null -->`, 섹션 머리 표, 컬럼 표, 맨 아래
`## 작성지침`. 예상대로 작성지침이 섹션으로 한 개 더 세어져 77이 됐고,
무해했다.

> **변환기를 두 번 고쳤다.** 첫 판은 `DB USER` 라는 **라벨을 값으로** 넣고,
> 옆 블록 배너의 `변환` 을 특이사항으로 넣었다. 병합 셀이 있는 엑셀에서는
> 라벨과 값이 같은 열에 오는 자리가 있다 — **출력을 눈으로 보지 않았으면
> 76개 섹션에 그대로 들어갔다.**

## 2. ★ 자리는 있고 값은 없다

변환기가 센 것이다.

| 자리 | 채워진 것 |
|---|---|
| 테이블정의서 **AS-IS 컬럼**(1~7열) | **0 / 76 블록** |
| 테이블정의서 **변경 이력 영역** | **0 / 76** |
| 테이블정의서 **기타 특이 사항** | **0 / 76** |
| 프로그램목록 **TAB ID** | 0 / 200 |
| 요구사항정의서 **추적 컬럼**(화면·프로그램·시험ID) | 0 / 84 |
| 위험및이슈관리대장 **대장 시트** | 예시 1행 |

**이것이 이 패키지의 존재 이유다.** 서식이 부족한 것이 아니다 — 자리는
설계돼 있고, 만든 사람들은 그것이 필요하다고 합의했다. **채우도록 강제하는
것이 없어서 비어 있다.**

`ctx check` 가 하는 일이 정확히 그 강제다. 실측에서 확인했다 — 작업 기록이
`table:rp_rsch_prj_mst` 를 건드렸는데 그 섹션의 `applied` 가 `null` 이면
**커밋이 막힌다.**

> **나도 같은 함정에 세 번 빠졌다.** `TAB ID` · 요구사항 추적 컬럼 ·
> 테이블정의서 이력 영역을 전부 "있다" 고 적었다가 세어 보고 고쳤다.
> **헤더는 설계자의 의도이고 값은 운영의 사실이다.** 둘을 같은 것으로 읽으면
> 문서를 잘못 읽는다.

### 그래서 02_문서분석 §테이블정의서의 한 줄을 고쳐야 한다

원본이 [머리 + 상태 + 이력 + 비고] 4부인 것은 맞다. 다만 **이력과 비고는
76개 전부 빈 템플릿**이다. "이미 하고 있는 것을 꺼낸다" 가 아니라
**"하려고 만들어 두고 못 한 것을 돌아가게 한다"** 가 맞는 말이다.

## 3. `ctx check` 실측 — 어디가 비싼가

같은 레포에서 구성만 바꿔 가며 쟀다.

| 구성 | 섹션 | 어휘 | 시간 |
|---|--:|--:|--:|
| (a) 테이블만 — 기준선 | 77 | 76 | **368 ms** |
| (b) + 용어 **문서**만 (어휘 없음) | 5,194 | 76 | 479 ms |
| (c) + 용어 **어휘**만 (문서 없음) | 77 | 4,747 | 433 ms |
| (d) **둘 다** | 5,194 | 4,747 | **3,926 ms** |

**파싱은 싸다.** 문서를 5,117섹션으로 키워도 +111 ms, 어휘를 4,671건 더해도
+65 ms 다. 그런데 **둘을 합치면 8배**가 된다.

비싼 것은 파싱이 아니라 **매칭**이다.

## 4. 병목 — O(좌표 × 섹션)

[`managed.js:190`](../../viewer/server/core/managed.js:190) 이다.

```js
const section =
  (doc.managedSections || []).find((s) => s.level === hit.level && normValue(s.value) === normValue(hit.value)) || null
```

좌표 하나를 찾을 때마다 **그 문서의 전 섹션을 훑고, 섹션마다 `normValue` 를
다시 부른다.** 4,747 × 5,194 ≈ **2,460만 번**이다.

### 고칠 수 있다 — 프로토타입으로 확인했다

문서마다 `Map(level + '\0' + normValue(value) → section)` 을 **한 번** 만들고
조회하게 바꿔 봤다.

| | 시간 |
|---|--:|
| 선형 탐색 | 3,579 ms |
| **Map 색인 (반영됨)** | **498 ms** |

**7.2배. 출력이 바이트 단위로 같다** — `ctx check --json` 을 두 레포에서
각각 받아 `diff` 로 대조했다.

> **들어갔다 (2026-09-14).** `buildManagedIndex` 가 문서마다 Map 을 하나씩
> 만든다 — 거기가 `loadRepo` 당 한 번 불리는 자리다. `doc` 객체에 캐시를
> 붙이는 프로토타입도 됐지만, 스캔이 그 객체를 재사용할 때 낡을 수 있어
> 쓰지 않았다.

## 5. `term:` 결정 — 도메인이 맞다. 단, 중복을 걸러야 한다

### 중복 404건의 정체

| | 건수 |
|---|--:|
| 고유 논리명 | **4,671** |
| 중복 논리명 | 404 (행 850) |
| ├ 물리명까지 같은 **순수 중복행** | **399** |
| └ 물리명이 다른 **진짜 충돌** | **5** |

진짜 충돌 다섯 —

| 논리명 | 물리명 둘 |
|---|---|
| 브랜드존 | `BRNDZ_NM` · `BRND_ZONE_NM` |
| 브랜드존코드 | `BRNDZ_CD` · `BRND_ZONE_CD` |
| 행정동코드 | `ADMB_CD` · `ADM_DONG_CD` |
| 주기능용도 | (한쪽만 물리명 있음) |
| GSSID | (한쪽만 물리명 있음) |

**399는 걸러내면 되고, 5는 사람이 정해야 한다.** 그리고 후자가 바로
`_vocab.md` 가 있는 이유다 — 정본 하나를 정하고 나머지를 `aliases` 로 건다.

### 결정

| | |
|---|---|
| 단위 | **도메인 시트의 논리명.** 용어사전(어절)이 아니다 |
| 개수 | **4,671** (중복 제거 후) |
| 전제 | ~~Map 색인이 들어가야 한다~~ → **들어갔다.** 4,671 + 76 에서 0.5초 |

용어사전(1,726)은 `가격` `인하` 같은 **어절**이라 `term:` 이 가리켜야 할
대상이 아니다. 어절은 도메인 섹션 안의 필드로 들어간다.

## 6. 검증된 것 — C 의 `test:` 판단

등록부에 `test:*` → `docs/테스트케이스.md` 를 넣고 없는 문서를 가리키게
해 봤다.

```
[오류] 등록부가 가리키는 섹션이 없음  1건
   test:TC-001  docs/테스트케이스.md 문서가 없음
```

**커밋이 막힌다.** C 에서 `test:` 를 등록부에서 뺀 것이 맞았다.

## 7. B 를 고쳐야 하는가 — 두 군데

| | 무엇 |
|---|---|
| §7 AS-IS | *"테이블정의서가 AS-IS ↔ TO-BE 대칭"* → **`GDI` 시트의 AS-IS 는 비어 있다.** 대응은 `테이블목록` 시트에서 온다 |
| §6 큰 표 | **중복 제거 규칙을 더한다** — 같은 값의 섹션이 두 번 나오면 파서는 첫 번째만 찾고 나머지는 **도달 불가**가 된다 |

나머지 규약은 실측에서 그대로 통했다 — 섹션 제목 형식 · `applied` 위치 ·
머리 표 · 작성지침 섹션이 하나 더 세어지는 것까지 예상대로였다.
