## 1. 관리자 — 첫날

```
xcopy /E /I <배포본>\repo-kit\* .
xcopy /E /I <배포본>\packages\dpms\* .
```

부으면 그 폴더가 지식 레포가 된다. **그다음이 실질이다.**

| | 하는 일 | 안 하면 |
|---|---|---|
| 1 | 안 쓰는 문서를 지운다 | 46개를 다 쓰는 프로젝트는 드물다 |
| 2 | **`_managed.md` 에서 그 패턴도 지운다** | `등록부가 가리키는 섹션이 없음` — **커밋이 막힌다** |
| 3 | 문서마다 `(예시)` 섹션을 지운다 | 예시가 좌표로 잡힌다 |
| 4 | `_vocab.md` 에 좌표를 등록한다 | `_vocab.md 미등재 좌표` — **커밋이 막힌다** |
| 5 | `ctx check` | `이상 없음` 이 나오면 시작할 수 있다 |

**2번의 반대는 조용하다.** 문서만 남기고 패턴을 지우면 그 문서는 **갱신이
강제되지 않는다.** 좌표를 갖는 문서를 남겼으면 패턴도 남았는지 본다.

> 4번은 한 번에 다 할 일이 아니다. 어휘는 **발견될 때마다 늘린다**
> (`MANUAL-관리자.md` 4장). 처음에는 `arch:` 넷만 들어 있다.

## 2. PM · PL — 제출시기가 곧 일정이다

훅**이다. 단계가 끝날 때 무엇이 나와야 하는지가 여기 있다.

`●` 는 **계약상 필수 제출물**이다 — 넷뿐이고 전부 착수 시점이다.

> **CDP 는 아직 이 표를 읽지 못한다.** `제출시기` 는 문서 머리의 사람용
> 표이고 기계가 쓰는 필드가 아니다([`03_템플릿규약.md`](03_템플릿규약.md) §3).

## 3. 개발자 — 매일

CDP 의 절차가 그대로다. **패키지가 절차를 바꾸지 않는다.**

```
작업한다  →  cdp-work 가 작업 기록을 만든다 (touches: 좌표)
          →  cdp-managed 가 갱신할 섹션을 찾아 준다
          →  섹션을 고치고 applied 를 적는다
          →  ctx check  →  커밋
```

패키지가 더하는 것은 둘이다.

| | |
|---|---|
| **어느 문서를 고치나** | `_managed.md` 가 좌표 패턴에서 문서·섹션으로 보낸다 |
| **어떻게 적나** | 문서마다 맨 아래 `## 작성지침` 이 있다 |

두 번째가 없으면 사람마다 다르게 적는다. DPMS 에서 실제로 그렇게 됐다 —
이력을 적을 자리가 없어서 셀 안에 `[20260204]` 와 `<7/5 기준>` 두 표기가
각각 생겼다([`02_문서분석.md`](02_문서분석.md)).

## 4. 무엇이 커밋을 막나 — 셋

실측한 것이다([`06_패키지골격.md`](06_패키지골격.md) §7).

| 오류 | 뜻 | 고치는 법 |
|---|---|---|
| `_vocab.md 미등재 좌표` | 어휘에 없는 좌표를 썼다 | 어휘에 한 줄 넣거나, 오타면 고친다 |
| `등록부가 가리키는 섹션이 없음` | 문서나 섹션이 없다 | 섹션을 만들거나, 안 쓰는 패턴이면 등록부에서 뺀다 |
| `관리 문서 파생 누락` | 작업했는데 섹션을 안 고쳤다 | `ctx apply <좌표>` 로 초안을 받아 섹션을 고친다 |

**셋 다 error 다.** "밀림" 같은 상태는 없다 — 갱신은 필수이고, 안 했으면
그것은 상태가 아니라 오류다(CDP 시스템설계서 §1.5).

### 막지 **않는** 것

| | 왜 |
|---|---|
| 등록부에 없는 좌표를 쓰는 것 | 정상이다. 그 작업 기록이 원천이다 |
| 좌표가 0개인 작업 기록 | 정상이다. 억지 좌표가 없는 좌표보다 나쁘다 |
| **대장형 · 사건형 · 서술형 32종을 안 고치는 것** | **보증이 없다.** 사람이 본다 |

마지막 줄이 이 패키지의 한계다. CDP 의 보증은 좌표에 붙고, 좌표가 없는
문서는 강제할 방법이 없다. **주간보고서를 안 써도 커밋은 통과한다.**

## 5. 패키지를 고치는 것과 프로젝트를 고치는 것은 다르다

```
agent/packages/dpms/     서식.   고치면 **다음 프로젝트부터** 적용된다
C:\cdp\            사본.   고쳐도 패키지로 돌아가지 않는다
```

부은 순간 둘은 갈라진다. **자동으로 합쳐지지 않는다** — 그래서 좋은 개선이
나오면 **사람이 패키지로 옮긴다.**

| 프로젝트에서 나온 것 | 패키지로 옮기나 |
|---|---|
| 작성지침이 부족해서 보탠 문장 | **옮긴다** |
| 표 컬럼을 늘린 것 | **옮긴다** — 다음 프로젝트도 같은 필요가 있다 |
| 그 프로젝트의 좌표 값 · 테이블 · 용어 | **옮기지 않는다** — 패키지는 서식이다 |
| 그 발주처 양식에 맞춘 보고서 서식 | 판단한다. 발주처가 같으면 새 패키지가 낫다 |

## 6. 두 번째 패키지

```
agent/packages/dpms/ 를 복사해 이름을 바꾼다
  ├ docs/          **문서 목록이 바뀐다** — 이것이 패키지의 차이다
  ├ _managed.md    없는 문서의 패턴을 뺀다
  ├ _vocab.md      쓰지 않는 타입을 뺀다
  └ origin/        새 원천을 적는다
```

**규약([`03`](03_템플릿규약.md))과 좌표 설계([`04`](04_좌표와등록부.md))는 복사하지
않는다.** `docs/관리문서패키지/` 에 한 벌만 두고 패키지들이 공유한다 — 두 벌이
되면 갈라진다.

### 규모별로 나눌 것인가

**지금은 나누지 않는다.** 표본이 하나뿐인데 축을 세우면 그 축은 DPMS 한 건을
일반화한 것에 지나지 않는다([`00_계획검토.md`](00_계획검토.md) §5).

두 번째가 생기면 **둘이 실제로 무엇에서 갈리는지** 보인다. 그때 이름표를
정한다 — 규모일 수도, 발주처 유형일 수도, 업무 도메인일 수도 있다.
