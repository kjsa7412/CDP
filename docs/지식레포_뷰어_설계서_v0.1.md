# 지식 레포 뷰어 (ctx-view) 설계서

v0.1 · 2026-09-02

> **한 줄 요약** — Vercel에 정적 SPA 하나를 올려두고, 각자 자기 PC의 지식 레포 clone 폴더를 브라우저에서 한 번 지정하면, 그 뒤로는 좌표 기반으로 탐색 가능한 마크다운 뷰어가 된다. **문서는 서버로 전송되지 않는다.**
>
> 전제 문서 — 「AI 기반 맥락 배포 프로토콜 설계서 v1.1」
>
> **절 참조 표기** — `프로토콜 §9.4` 는 전제 문서의 절, `본서 §8.4` 는 이 문서의 절. 문맥상 명백한 경우 접두어를 생략한다.

# 제1부 — 검토

## 1. 요구사항 확인

| 요구 | 해석 |
|---|---|
| 특정 경로에 md를 넣어두고 루트 경로만 지정 | 각자 로컬의 clone 폴더를 지정. 서버 업로드 없음 |
| Vercel에 올려서 사용 | 배포·접속 편의. 서버 로직은 필요 없음 |
| 아주 가벼운 형태 | 정적 빌드, 의존성 최소, 서버 함수 0 |
| md가 문서 양식으로 보이는 뷰어 | GFM 렌더링. 표·코드블록·인용이 설계서 수준으로 나와야 함 |
| 맥락 배포 프로토콜에서 써먹을 수 있게 | 프론트매터 인식, 좌표 네비게이션, 유효성 표시 |

## 2. "로컬 경로를 입력받는" 구조가 가능한가 — 가능하다

Vercel은 서버리스라 **서버가 사용자 PC의 디스크를 볼 수 없다.** 그러나 이 앱에서 파일을 읽는 주체는 서버가 아니라 **브라우저**다.

브라우저에는 `window.showDirectoryPicker()` — File System Access API — 가 있다. 사용자가 폴더를 한 번 고르면 그 폴더에 대한 핸들을 얻고, 하위 파일을 읽을 수 있다. 그리고 그 핸들을 IndexedDB에 저장해두면 **다음 방문 때 다시 고를 필요가 없다.**

```
[Vercel]  정적 HTML/JS 만 전송  ────────>  [브라우저]
                                              │
                                              │ showDirectoryPicker()
                                              ↓
                                          C:\work\knowledge-repo\
                                          (사용자 PC. 서버는 못 봄)
```

**이 구조의 결정적 이점**

| | |
|---|---|
| **문서가 서버로 안 간다** | 사내 문서를 외부 호스팅에 올리는 문제가 원천적으로 없다. 보안 심사가 쉬워진다 |
| **인증이 필요 없다** | 앱 자체에는 아무 데이터가 없으므로 URL이 공개돼도 무해하다. 로그인·토큰·권한 설계가 전부 사라진다 |
| **항상 최신이다** | `git pull` 한 결과를 그대로 읽는다. 동기화 지연이 없다 |
| **서버 비용 0** | 정적 파일만. Vercel 무료 플랜으로 충분하고 함수 실행이 없다 |
| **레포 구조를 안 건드린다** | 지식 레포에 앱 코드를 넣지 않는다. 완전히 독립 |

앞서 검토했던 세 방안(레포 동거 배포 / GitHub API / 빌드타임 fetch)이 전부 토큰 관리와 접근 제어 설계를 요구했는데, **이 방식은 그 문제 자체가 발생하지 않는다.** 더 가볍다.

## 3. 제약 — 먼저 확인해야 할 것

조사 결과 (2026-09 기준):

| 브라우저 | 지원 |
|---|---|
| Chrome 데스크톱 | ✅ 105+ |
| Edge 데스크톱 | ✅ 105+ |
| Firefox | ❌ 미지원 (구현 반대 입장) |
| Safari | ❌ 미지원 |
| 모바일 전체 (Android Chrome, iOS Safari 포함) | ❌ 미지원 |

전역 사용률로는 약 27%지만, **사내 표준 브라우저가 Chrome 또는 Edge라면 실질 커버리지는 100%다.** 반대로 Firefox·Safari 사용자가 섞여 있으면 폴백 경로(§9)가 필요하다.

**권한 지속성** — Chrome 122부터 권한 프롬프트에 "매번 허용" 옵션이 생겼다. 사용자가 이것을 고르면, 재방문 시 IndexedDB의 핸들로 `requestPermission()`을 호출했을 때 프롬프트 없이 바로 승인된다. 즉 **폴더 선택은 사실상 최초 1회다.**

> ### ⚠ 0단계에서 반드시 확인할 것
>
> 사내 Chrome/Edge 엔터프라이즈 정책에 `FileSystemReadBlockedForUrls` 또는 유사한 파일 접근 차단 정책이 걸려 있으면 **이 설계 전체가 무효다.** 개발 시작 전에 실제 사내 PC 한 대에서 다음을 확인한다.
>
> ```js
> // 사내 PC의 Chrome 콘솔에서 (https 페이지에서 실행)
> await window.showDirectoryPicker()
> ```
>
> 폴더 선택 창이 뜨면 진행, 예외가 나면 §9의 대안으로 전환한다. **반나절도 안 걸리는 확인이고, 이게 안 되면 나머지 설계는 읽을 필요가 없다.**

## 4. 왜 이걸 만드는가 — 프로토콜의 어느 구멍을 메우나

기존 수단으로 안 되는 이유가 분명해야 만들 가치가 있다.

| 대안 | 되는 것 | 안 되는 것 |
|---|---|---|
| **VS Code 마크다운 프리뷰** | 렌더링. 개발자에겐 충분 | 좌표 네비게이션 없음. 유효성 신호 없음. 비개발 직군 진입 장벽 |
| **GitHub 웹 UI** | 렌더링, 검색 | 좌표 네비게이션 없음. `supersedes` 체인이 안 보임. 사내망 GitHub이 아니면 접근 문제 |
| **MkDocs · Docusaurus** | 예쁜 정적 사이트 | **문서가 서버로 올라간다.** 빌드·배포 파이프라인 필요. 문서 push마다 재배포 |
| **로컬 CLI (`npx ctx-view`)** | 브라우저 제약 없음 | 각자 Node 설치 + 명령 실행. 비개발 직군에겐 더 어려움 |
| **이 뷰어** | 좌표 네비게이션 + 유효성 신호 + 문서 로컬 유지 | Chrome/Edge 데스크톱 전용 |

**이 조합이 다른 데 없다.** 특히 프로토콜 설계서의 두 지점을 직접 메운다.

**(1) §10.2가 감수한다고 한 것** — *"감수하는 것: 비개발 직군의 진입 장벽"*. clone은 시켰어도 raw 마크다운을 읽으라고 하는 건 무리다. 뷰어가 이 장벽을 낮춘다.

**(2) §12의 신호를 사람은 못 본다** — 유효성·결착도·절단 신호는 `knowledge-load`가 **AI 세션에만** 주입한다. 사람이 문서를 직접 열면 그 문서가 이미 덮였는지, 같은 좌표에 이후 문서가 몇 건인지 알 방법이 없다. **뷰어가 그 신호를 사람에게도 보여준다.**

### 반대로 — 이 뷰어가 풀지 못하는 것

> **프로토콜 §11.4의 함정은 그대로 남는다.** *"모르는 사람은 `knowledge-load`를 부를 생각조차 하지 않는다."*

뷰어는 **사람이 찾아볼 때** 도와주는 도구다. 찾아볼 생각을 안 하는 사람에게는 아무 효과가 없다. 프로토콜의 본체는 여전히 `CLAUDE.md`의 자동 발동 규칙이고, **뷰어는 보조지 대체가 아니다.**

이 구분이 흐려지면 "뷰어를 잘 만들면 프로토콜이 완성된다"는 오해가 생기고, 정작 중요한 자동 발동 규칙에 투자가 안 간다. 도입 순서를 프로토콜 뒤에 두는 이유다(§11).

# 제2부 — 설계

## 5. 아키텍처

```
┌─────────────────────────────────────────────┐
│  Vercel (정적 호스팅)                        │
│  index.html + bundle.js + bundle.css        │
│  ← 여기에 문서는 하나도 없다                  │
└──────────────────┬──────────────────────────┘
                   │ 최초 1회 다운로드 (~200KB)
                   ↓
┌─────────────────────────────────────────────┐
│  브라우저 (사용자 PC)                         │
│                                             │
│  ┌───────────┐   showDirectoryPicker()      │
│  │ 폴더 핸들 │ ─────────────────────────┐   │
│  └─────┬─────┘                          │   │
│        │ 저장                            ↓   │
│  ┌─────▼──────────┐          ┌──────────────┴──┐
│  │  IndexedDB     │          │ C:\work\knowledge│
│  │  - 폴더 핸들    │  ◀────── │   knowledge/*.md │
│  │  - 파싱 캐시    │   읽기   │   INDEX.md       │
│  │  - 검색 인덱스  │          │   _vocab.md      │
│  └────────────────┘          │   assets/        │
│                              └──────────────────┘
└─────────────────────────────────────────────┘
```

**서버 코드가 0줄이다.** API 라우트도, 환경변수도, 데이터베이스도 없다.

## 6. 기술 선택

| 항목 | 선택 | 근거 |
|---|---|---|
| 빌드 | **Vite** | 정적 SPA. Vercel이 프리셋으로 자동 인식. Next.js는 이 용도에 과함 |
| 프레임워크 | **React** (또는 Preact) | 상태가 트리·목록·본문 3영역으로 얽힘. 바닐라로는 금방 지저분해짐. 번들이 걱정되면 Preact로 교체(~4KB) |
| 마크다운 | **markdown-it** | GFM 표 지원이 확실하고 플러그인 구조가 단순. `marked`도 가능 |
| 프론트매터 | **js-yaml** | 제목에 콜론이 들어가는 등 YAML 엣지 케이스가 실제로 발생. 자체 파서는 여기서 깨진다. ~28KB는 지불할 가치가 있음 |
| 살균 | **DOMPurify** | 문서가 팀 내부 것이라도 렌더 전 살균은 기본. ~20KB |
| 검색 | **MiniSearch** | ~10KB. 한국어 토크나이징이 약하므로 본서 §8.4의 보완 필요 |
| 하이라이팅 | **highlight.js (지연 로드)** | 초기 번들에 넣지 않는다. 코드블록이 보이는 순간 동적 import. 언어는 yaml·bash·json·sql·js·ts만 등록 |

**예상 초기 번들: 150~200KB (gzip).** 최초 1회만 받고 이후 캐시된다.

**넣지 않는 것** — Mermaid(설계서는 코드펜스 ASCII 다이어그램을 쓴다. 필요해지면 지연 로드로 추가), 편집 기능(본서 §10 비목표), 서버 상태 관리 라이브러리(서버가 없다).

## 7. 데이터 흐름

### 7.1 최초 연결

```
1. "폴더 선택" 클릭
2. showDirectoryPicker({ mode: 'read' })
3. 권한 프롬프트 → 사용자가 "매번 허용" 선택
4. 핸들을 IndexedDB에 저장
5. 전체 스캔 (아래 7.3)
```

### 7.2 재방문

```
1. IndexedDB에서 핸들 로드
2. handle.queryPermission({ mode: 'read' })
   → 'granted'  : 바로 진행 (프롬프트 없음)
   → 'prompt'   : requestPermission() 호출. 클릭 1회
   → 'denied'   : 폴더 다시 선택 안내
3. 증분 스캔 (변경된 파일만)
```

### 7.3 스캔 전략

전체 재파싱은 문서가 늘수록 느려지므로 **파일 단위 캐시**를 둔다.

```
디렉터리 순회
  └ 각 파일의 (path, lastModified) 확인
      ├ 캐시에 있고 lastModified 동일  → 캐시 재사용 (읽지 않음)
      └ 없거나 변경됨                  → 읽어서 파싱 → 캐시 갱신
```

`File.lastModified`만 보면 되므로 변경 없는 파일은 **디스크에서 읽지도 않는다.** 300건 중 3건이 바뀌었으면 3건만 읽는다.

**파일 감시는 없다.** 브라우저에 폴더 watch API가 없으므로 `git pull` 후에는 **새로고침 버튼**을 눌러야 한다. 상단에 마지막 스캔 시각을 항상 표시해 착각을 막는다.

### 7.4 인식하는 구조

프로토콜 §10.1의 저장소 구조를 그대로 인식한다.

```
<선택한 루트>/
  knowledge/*.md          지식 단위 (프론트매터 파싱 대상)
  knowledge/assets/**     첨부 (렌더링만, 프론트매터 없음)
  INDEX.md                무시 (뷰어가 직접 집계하므로)
  _vocab.md               좌표 어휘 (파싱 대상)
  TEMPLATE.md, CLAUDE.md  일반 문서로 표시
```

> **`INDEX.md`를 읽지 않는 이유** — 뷰어는 전체 파일을 직접 훑으므로 인덱스가 필요 없고, 오히려 `ctx index`가 밀린 상태면 **어긋난 인덱스를 믿는 위험**(§10.5)이 생긴다. 다만 뷰어가 집계한 결과와 `INDEX.md`가 다르면 **경고를 띄운다** — 인덱스가 밀렸다는 신호이므로 유용하다.

### 8.1 좌측 — 좌표 트리

- `_vocab.md`의 타입별로 그룹핑, 좌표마다 문서 수 표시
- **`deprecated` 좌표는 흐리게 + 후속 좌표로 가는 링크** (§9.4의 `deprecated` 필드 활용)
- **미등재 좌표 섹션** — `touches`에 있는데 `_vocab.md`에 없는 좌표를 따로 모아 경고. `ctx check`가 잡는 것을 화면에서도 보게 한다

### 8.2 가운데 — 문서 목록

- 선택한 좌표에 걸린 문서, 최신순
- **덮인 문서(`supersedes` 대상)는 흐리게 표시하고 기본 접힘.** 지우지 않는 이유는 §9.7과 같다 — 과거 결정의 근거로 필요하다
- `status: 미결` 배지 강조 (미결만 필터하면 그것이 결정 대기 목록, §8.3)

### 8.3 우측 — 본문과 유효성 헤더

**본문 위에 붙는 배지가 이 뷰어의 존재 이유다.** 프로토콜 §12.3의 신호를 사람이 읽을 형태로 옮긴다.

| 배지 | 계산 | 표시 |
|---|---|---|
| **유효성** | `supersedes` 체인 역참조 | ✅ 유효 / ⛔ 덮임 → *(덮은 문서 링크)* |
| **나이** | `date` 기준 경과 | 3주 전 · 결정 2026-08-19 |
| **결착도** | 같은 좌표의 이후 문서 수 | ⚠ `table:tb_research_plan`에 이후 2건 *(링크)* |

**나이와 유효성을 시각적으로 구분한다.** 2년 전이어도 안 덮였으면 ✅, 어제 것이어도 덮였으면 ⛔ — §12.2의 원칙을 색으로 강제한다. 나이를 경고색으로 칠하면 안 된다.

첨부(`attachments`)는 하단에 링크로, 클릭하면 같은 뷰어로 렌더한다.

### 8.4 검색 — 대조를 사람이 쓸 수 있게

프로토콜 §9.5(2)의 **읽기 시점 대조**를 그대로 구현한다. 이게 단순 전문 검색과 다른 지점이다.

```
입력: "연구계획 테이블 관련 최근 변경"
  ↓
① _vocab.md의 aliases 조회
   "연구계획테이블" → table:tb_research_plan  ← 정규화 성공
  ↓
② 해당 좌표로 필터 → 유효 문서 최신순
  ↓
③ (좌표 매칭 0건일 때만) 전문 검색으로 폴백
```

**①이 핵심이다.** 사람이 정본 좌표를 외울 필요가 없어진다. 그리고 ③으로 넘어간 검색어는 **로그로 쌓아둔다** — §9.7의 *"alias는 발견될 때마다 추가한다"* 를 실천할 재료가 된다. 로컬 저장이므로 개인 로그다.

> 한국어 토크나이징이 약한 것은 알려진 한계다. MiniSearch의 기본 토크나이저는 공백 분리이므로 조사가 붙은 형태를 못 잡는다. v1에서는 **부분 문자열 매칭을 병행**하고, 필요해지면 그때 형태소 분석을 검토한다.

### 8.5 검증 뷰

`bin/ctx check`가 커밋 시점에 잡는 것들을 화면에서도 보여준다. **훅이 안 걸린 사람(clone만 받은 비개발 직군, 다른 PC)도 상태를 볼 수 있게** 하는 것이 목적이다.

| 검사 | 표시 |
|---|---|
| `_vocab.md` 미등재 좌표 | 해당 문서와 좌표 나열 |
| `supersedes` 대상 문서 없음 | 끊어진 참조 |
| 필수 필드 누락 | 필드명과 문서 |
| `INDEX.md`와 실제 집계 불일치 | "인덱스가 밀렸습니다. `ctx index` 실행 필요" |
| 좌표 1개짜리 문서 | 안내 (§9.3 — 대개 놓친 게 있다) |

## 9. 폴백 — 미지원 브라우저

| 단계 | 방식 | 제약 |
|---|---|---|
| **1순위** | File System Access API | Chrome/Edge 데스크톱 |
| **2순위** | `<input type="file" webkitdirectory>` | 전 데스크톱 브라우저. **매번 폴더 재선택**, 전체 파일을 메모리에 로드, 증분 스캔 불가 |
| **3순위** | 안내 화면 | 모바일. "Chrome/Edge 데스크톱에서 열어주세요" |

2순위는 기능이 아니라 **최소한의 예의**다. Firefox 사용자가 빈 화면을 보고 "고장났다"고 판단하는 것만 막으면 된다. 여기에 공을 들이지 않는다.

## 10. 명시적 비목표

v1에서 **하지 않는 것**을 못박는다. 뷰어는 편집기가 되려는 유혹이 강하다.

| 안 하는 것 | 이유 |
|---|---|
| **문서 편집·생성** | 작성은 `knowledge-share` skill의 일이다. 뷰어가 이걸 하면 좌표 대조·훅 검증을 우회하는 경로가 생긴다 — §11.2의 *"skill은 편의, hook은 보증"* 이 무너진다 |
| **Git 조작 (pull/commit)** | 브라우저에서 할 수 없고, 하려면 서버가 필요해진다. 설계 전제가 무너짐 |
| **여러 레포 동시 연결** | 지식 레포는 하나라는 것이 프로토콜 전제(§10.2) |
| **AI 질의응답** | `knowledge-load`가 하는 일이다. 중복 |
| **좌표 편집** | `_vocab.md`는 Git으로 관리된다 |

**읽기 전용을 지키면 이 앱은 영원히 가볍다.** 쓰기가 들어오는 순간 충돌·검증·권한이 전부 따라온다.

## 11. 단계 계획

| 단계 | 작업 | 소요 | 검증 |
|---|---|---|---|
| **0** | **사내 PC에서 `showDirectoryPicker()` 동작 확인** | 반나절 | **폴더 선택 창이 뜨는가. 안 뜨면 여기서 중단** |
| 1 | Vite + React 골격, 폴더 연결, IndexedDB 핸들 저장/복원 | 1일 | 재방문 시 프롬프트 없이 재연결되는가 |
| 2 | 디렉터리 순회, 프론트매터 파싱, 증분 캐시 | 1일 | 300건 스캔 시간. 변경 3건일 때 3건만 읽는가 |
| 3 | 마크다운 렌더 (표·코드·인용) + 3분할 레이아웃 | 1일 | **설계서 v1.1 원문이 제대로 렌더되는가** |
| 4 | 좌표 트리 + `_vocab.md` 파싱 + 문서 목록 | 1일 | 미등재 좌표가 잡히는가 |
| 5 | 유효성 배지 (`supersedes` 체인·나이·결착도) | 반나절 | 덮인 문서가 흐리게 나오는가 |
| 6 | 검색 + alias 대조 + 폴백 | 1일 | "연구계획테이블"로 정본 좌표가 잡히는가 |
| 7 | 검증 뷰 | 반나절 | `ctx check` 결과와 일치하는가 |
| 8 | `webkitdirectory` 폴백 + 미지원 안내 | 반나절 | — |

**합계 약 6.5일.** 0단계가 통과해야 나머지가 의미를 갖는다.

**3단계의 검증을 설계서 v1.1 원문으로 하는 이유** — 그 문서에 이 뷰어가 다뤄야 할 요소가 전부 들어 있다. 중첩 표, 인용 안의 표, ASCII 다이어그램 코드펜스, YAML 블록, 각주 화살표, 한글·영문 혼용. **이게 깨지지 않으면 실사용 문서 대부분이 통과한다.**

## 12. 도입 순서 — 프로토콜보다 뒤

> **뷰어를 프로토콜보다 먼저 만들면 안 된다.**

프로토콜 §17의 3단계(최근 작업 10건 직접 문서화)를 통과하기 전에는 **볼 문서가 없다.** 문서 10건짜리 저장소에 뷰어는 과잉이고, 그 상태에서 만들면 무엇이 실제로 불편한지 모른 채 화면을 짜게 된다.

§11.5에서 MCP 서버를 두고 내린 판단이 그대로 적용된다.

> *"지금 당장 붙이면 `ls`와 `cat`을 감싼 래퍼에 불과하다. 경로 A로 2주 써봐야 무엇이 불편한지 나오고, 그 불편이 곧 툴 설계가 된다."*

**권장 순서**

```
프로토콜 §17 1~6단계  (기반 구축 + skill)
        ↓
프로토콜 §17 7단계     (2주 운용) ← 이 기간에 불편이 드러난다
        ↓
뷰어 0단계             (브라우저 확인)
        ↓
뷰어 1~8단계
```

2주 운용에서 나올 법한, 그리고 화면 설계를 바꿀 수 있는 신호들:

| 관측되면 | 설계 변경 |
|---|---|
| 좌표보다 사람으로 찾는 일이 많다 | `author` 필터 추가 |
| `status: 미결` 추적이 주 용도다 | 미결 목록을 첫 화면으로 |
| 첨부를 여는 빈도가 높다 | 첨부를 본문에 인라인 전개 |
| 좌표 트리를 안 쓰고 검색만 쓴다 | 트리를 접고 검색을 전면에 |

## 14. 핵심 코드 스케치

위험한 부분만 미리 확인한다.

### 14.1 핸들 저장과 재연결

```js
// IndexedDB에 FileSystemDirectoryHandle 을 그대로 저장할 수 있다
// (structured clone 가능한 객체다. JSON 직렬화는 안 된다)

async function saveHandle(handle) {
  const db = await openDB();                       // idb-keyval 등 사용
  await db.put('config', handle, 'rootHandle');
}

async function reconnect() {
  const db = await openDB();
  const handle = await db.get('config', 'rootHandle');
  if (!handle) return null;                        // 최초 방문

  let perm = await handle.queryPermission({ mode: 'read' });
  if (perm === 'prompt') {
    // "매번 허용"을 골랐다면 프롬프트 없이 granted 로 즉시 해소된다
    perm = await handle.requestPermission({ mode: 'read' });
  }
  return perm === 'granted' ? handle : null;
}
```

### 14.2 증분 스캔

```js
async function* walk(dir, prefix = '') {
  for await (const [name, handle] of dir.entries()) {
    const path = prefix ? `${prefix}/${name}` : name;
    if (handle.kind === 'directory') {
      yield* walk(handle, path);
    } else if (name.endsWith('.md')) {
      yield { path, handle };
    }
  }
}

async function scan(root, cache) {
  const docs = [];
  for await (const { path, handle } of walk(root)) {
    const file = await handle.getFile();           // 메타데이터만. 아직 안 읽음
    const hit = cache.get(path);

    if (hit && hit.lastModified === file.lastModified) {
      docs.push(hit.doc);                          // 디스크 읽기 없음
      continue;
    }
    const text = await file.text();                // 여기서 처음 읽는다
    const doc = parse(path, text);
    cache.set(path, { lastModified: file.lastModified, doc });
    docs.push(doc);
  }
  return docs;
}
```

### 14.3 유효성 계산

```js
// supersedes 는 문자열 또는 { id, scope } 배열 (설계서 §9.8 확장 대비)
function buildValidity(docs) {
  const supersededBy = new Map();                  // id → 덮은 문서 id

  for (const d of docs) {
    for (const s of normalizeSupersedes(d.supersedes)) {
      supersededBy.set(s.id, d.id);                // scope 는 v1에서 무시
    }
  }
  return (id) => ({
    valid: !supersededBy.has(id),
    replacedBy: supersededBy.get(id) ?? null,
  });
}

// 결착도: 같은 좌표에 이 문서보다 뒤에 온 문서
function settledness(doc, docs) {
  const later = new Map();                         // 좌표 → 이후 문서 id[]
  for (const c of doc.touches) {
    later.set(c, docs
      .filter(o => o.id !== doc.id
                && o.touches.includes(c)
                && o.date > doc.date)
      .map(o => o.id));
  }
  return later;
}
```

`normalizeSupersedes`를 처음부터 두는 이유는, §9.8의 좌표 단위 무효화가 나중에 도입돼도 **뷰어가 깨지지 않게** 하기 위해서다. 문자열이면 `[{id}]`로, 객체 배열이면 그대로 반환한다.

## 15. 배포

```
vercel.json 불필요 — Vite 프로젝트를 자동 인식

Build Command    : npm run build
Output Directory : dist
Framework Preset : Vite
```

- **무료 플랜으로 충분하다.** 서버 함수 실행이 0이므로 사용량이 정적 대역폭뿐이다
- HTTPS는 Vercel 기본 제공 — File System Access API가 secure context를 요구하므로 필수 조건이 자동 충족된다
- **접근 제어는 필요 없다.** 앱에 데이터가 없으므로 URL이 공개돼도 문서는 노출되지 않는다. 다만 팀 외부 노출이 부담스러우면 Vercel 배포 보호를 나중에 켜도 되고, 앱 구조를 바꿀 필요는 없다
- 로컬 개발은 `localhost`도 secure context이므로 그대로 동작한다
