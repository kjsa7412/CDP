# CDP 관리 화면 설계서 v0.1
> **v1.0 이후** — 관리 화면은 왼쪽 메뉴의 「레포 관리」 · 「큐레이션」 · 「서버」 묶음이 됐다 — [`CDP_화면_설계서_v1.0.md`](../design/CDP_화면_설계서_v1.0.md).

2026-09-16 · 대상 릴리스 v0.6.0 · 전제 문서 [`CDP_시스템설계서_v1.0`](../design/CDP_시스템설계서_v1.0.md)

> **뷰어라고 부르지만 하는 일은 이미 관리 프로그램이다.** 레포를 지정하고,
> 원격과 맞추고, 작업 레포에 에이전트를 심는다. 그 셋이 지금 380px 팝오버
> 한 장에 들어 있다. 이 문서는 그것을 **창 전체를 쓰는 화면**으로 올리고,
> 없던 것 둘 — **진행 상태**와 **한 일의 기록** — 을 만든다.

## 0. 무엇이 문제인가 — v0.5.0 실측

| 기능 | 지금 어디에 | 무엇이 없나 |
|---|---|---|
| 지식 레포 경로 | `⋯ > 설정` 의 입력칸 하나 | 구조 검증 다섯 줄(`probe`)은 **첫 실행 화면에만** 있다. 바꿀 때는 `_vocab.md` 유무 한 줄이 전부 |
| 원격 동기화 | `⋯ > 문서 동기화` → 토스트 2.6초 | **진행 단계·직전 결과·이력이 어디에도 안 남는다.** 누르고 딴 데를 보면 끝난 건지 실패한 건지 알 방법이 없다 |
| git 설정 | 설정 팝오버의 안내문 두 줄 | upstream·`core.hooksPath`·`credential.helper`·remote URL 이 **어떻게 돼 있는지 화면이 말하지 않는다.** 훅 없음만 상태바 배지 하나 |
| 에이전트 설치 | 설정 > 경로 목록 + `[에이전트 설치]` | **언제 무엇을 넣었는지 기록이 없다.** `state.workRepos` 는 문자열 배열이고 그게 전부다. 설치된 레포와 안 한 레포가 같은 줄로 보인다 |
| 현황 | `/api/status` 가 **있는데 화면이 안 쓴다** | 파생 남은 섹션·깨진 섹션·미등재가 검사 오버레이 밖에서는 안 보인다 |
| 진단 | 없다 | 데이터 폴더·로그 파일·포트·번들 시각(`ctx version`)을 **화면에서 볼 길이 없다.** 문제가 나면 탐색기로 `%LOCALAPPDATA%` 를 찾아가야 한다 |

세 가지가 겹쳐 있다.

```
자리가 좁다        평생 한 번 하는 설치와 매일 하는 동기화가 같은 팝오버에 있다
상태가 안 보인다    동기화·git 설정·설치 여부가 전부 "눌러 봐야 아는" 값이다
한 일이 안 남는다   성공도 실패도 2.6초 뒤 사라진다
```

**셋 다 자리 문제다.** 기능은 대부분 이미 있다 — `core/setup.js` 는 계획과 적용을
나눠 놨고, `core/git.js` 는 ahead/behind/훅/dirty 를 다 낸다. **그것을 담을 화면이
없어서 안 보이는 것이다.**

## 1. 무엇을 만드는가

**관리 화면 — 창 전체를 쓰는 세 번째 모드.**

```
topMode:  doc  |  graph  |  admin
```

그래프를 패널에서 화면으로 올린 것과 **같은 이유**다(설계서 §2.4). 좌표 288개짜리
그림이 400px 패널에 안 들어가듯, 작업 레포 6개의 설치 상태와 동기화 이력 20줄은
380px 팝오버에 안 들어간다. **`Esc` 로 돌아온다** — 그래프와 같은 규칙이다.

### 1.1 진입점 — 아이콘과 자리

| | 지금 | 바꾼다 |
|---|---|---|
| 상단 모드 | `[문서] [그래프]` | `[문서] [그래프] [관리]` — 관리는 **톱니(`gear`)** 아이콘. `Icon.jsx` 에 추가한다 |
| `⋯ > 설정 — 레포 · 에이전트 설치` | 팝오버를 연다 | **관리 화면으로 간다.** 줄은 남긴다(근육 기억) |
| `⋯ > 문서 동기화` | 그대로 둔다 | 매일 누르는 것이다. 다만 **결과가 관리>동기화에 남는다** |
| 첫 실행 `SetupView` | 별도 화면 한 장 | **관리>지식 레포와 같은 화면**을 쓴다. 레포 미지정이면 그 메뉴로 열리고 머리에 안내 띠가 붙는다 |
| `Settings` 팝오버 | 있음 | **삭제.** 같은 것을 두 군데 두지 않는다 |

**읽기 설정(글자 크기·본문 폭·테마)은 `⋯` 에 그대로 둔다.** 매일 만지는 것과
평생 한 번 하는 것을 같은 스크롤에 두지 않는다는 판단은 v0.5 에서 이미 내렸고
(`App.jsx` 의 `Settings` 주석), 그것을 되돌리지 않는다. 관리 화면에 **복제하지도
않는다** — 같은 값을 고치는 자리가 둘이면 어느 쪽이 정본인지 사람이 모른다.

### 1.2 레이아웃

```
┌── 상단바 (그대로) ────────────────────────────────────────────┐
├── 메뉴 (200px) ──┬── 내용 (max 860px) ─────────────────────────┤
│  현황            │   ┌─ 카드 ────────────────────────────┐    │
│  지식 레포        │   │  제목 · 값 · [행동]                │    │
│  동기화          │   └───────────────────────────────────┘    │
│  작업 레포        │                                            │
│  진단 · 정보      │                                            │
├──────────────────┴────────────────────────────────────────────┤
│  상태바 (그대로)                                                │
└───────────────────────────────────────────────────────────────┘
```

기존 토큰과 클래스를 쓴다 — `.pane` · `.step`(메뉴 줄) · `.field` · `.popover__cap`
(→ `.card__cap` 으로 승격) · `.seg` · `.pill`. **새 디자인 언어를 만들지 않는다.**
색 예산도 그대로다 — 정상은 무채색으로 조용하고, 파랑은 지금 고른 것, 노랑/빨강은
이상뿐이다(`tokens.css`).

## 2. 정보 구조 — 메뉴 다섯

**작업의 성격으로 가른다.** "설정"이라는 한 덩어리가 아니다.

| 메뉴 | 성격 | 얼마나 자주 |
|---|---|---|
| **현황** | 지금 쓸 수 있는 상태인가 — 읽기만 | 매일 |
| **지식 레포** | 어디를 보고 있나 · 그 레포가 규약대로인가 | 바꿀 때 |
| **동기화** | 원격과 맞나 · git 이 제대로 설정돼 있나 | 매일 |
| **작업 레포** | 어느 코드 레포에 에이전트가 들어가 있나 | 프로젝트 시작할 때 |
| **진단 · 정보** | 뭔가 이상할 때 볼 것 | 문제 날 때 |

## 3. 화면별 설계

### 3.1 현황 — 한 장으로 답한다

**질문은 하나다: "지금 CDP 를 쓸 수 있는 상태인가."** 카드 넷에 답이 있고,
각 카드는 자기 메뉴로 간다.

| 카드 | 보이는 것 | 출처 |
|---|---|---|
| 지식 레포 | 레포 이름 · 문서 n · 좌표 n · 마지막 스캔 · 감시 상태 | `/api/repo` |
| 동기화 | 받을 것 n · 보낼 것 n · 마지막 fetch 시각 · 직전 결과 한 줄 | `/api/sync` (신설) |
| 검증 | error n · warn n — 0이면 "통과" | `/api/repo` 의 `checkCounts` |
| 문서 상태 | 파생 남은 섹션 n · 깨진 섹션 n · 미등재 좌표 n | **`/api/status` — 이 화면이 처음 쓴다** |

**작업 레포 요약 줄**이 그 아래 붙는다 — `등록 6곳 · 최신 4 · 갱신 필요 1 · 미설치 1`.

> **알림을 만들지 않는다**(설계서 제4부). 이 화면은 **사람이 열었을 때** 말한다.
> 뱃지를 띄우거나 창을 올리지 않는다.

### 3.2 지식 레포

| 구역 | 내용 |
|---|---|
| 지금 보는 레포 | 절대경로(복사) · `[폴더 열기]` · 문서/좌표 수 · 마지막 스캔 · `[다시 스캔]` |
| **구조 검증** | `probe` 다섯 줄을 **상시로** 보여 준다 — `knowledge/` · `_vocab.md` · `INDEX.md` · `bin/ctx` · `_managed.md`. 지금은 첫 실행 때만 보이는 것을 **바꾼 뒤에도** 보이게 한다 |
| 번들 | 레포 안 `bin/ctx.mjs` 의 빌드 시각. **낡으면 그 레포만 옛 답을 낸다**(README 의 경고). 앱이 든 번들과 다르면 ⚠ |
| 경로 바꾸기 | 입력 → 300ms 뒤 `probe` → 다섯 줄 미리보기 → `[이 경로로 바꾸기]` → `location.reload()` |
| 설정이 어디 있나 | `%LOCALAPPDATA%\cdp\state.json` 경로를 **적어 둔다.** 포터블이면 `<exe>\data\`. 사용자 질문 1순위가 "내 설정 어디 갔나" 다 |

레포 안에는 아무것도 쓰지 않는다는 불변조건은 그대로다(설계서 §6.1).

### 3.3 동기화 — **이 문서의 핵심**

지금 문제는 기능이 아니라 **가시성**이다. 세 가지를 만든다.

#### ① 진행을 서버가 안다

지금은 `App.jsx` 의 `syncNow()` 가 클라이언트에서 `git(fetch)` → `gitPull` →
`reload` 를 순서대로 부른다. 그래서 **진행 상태가 그 컴포넌트 안에만 있고**,
탭을 바꾸거나 다른 창에서 보면 아무것도 모른다.

**서버로 올린다.**

```
POST /api/sync            시작.  이미 돌고 있으면 409 + 현재 상태
GET  /api/sync            현재 단계 + 직전 결과 + 최근 이력
SSE  {type:'sync', ...}   단계가 바뀔 때마다
```

상태 기계 — **한 번에 하나만 돈다**:

```
idle ─▶ fetching ─▶ [behind>0] pulling ─▶ rescanning ─▶ done
                 └─ [behind=0] ─────────────────────────┘
                              실패하면 ─▶ failed(사유 그대로)
```

| 단계 | 화면이 말하는 것 |
|---|---|
| `fetching` | `원격 확인 중…` + 경과 초. **사내망 실측 19.5초**라 초를 안 세면 멎은 줄로 안다 |
| `pulling` | `n건 받는 중…` |
| `rescanning` | `다시 읽는 중…` |
| `done` | `n건 받음` · `이미 최신` · `이미 최신 · 미전송 n건` |
| `failed` | **git 이 낸 문장 그대로.** 앱이 고쳐 쓰지 않는다 |

#### ② 결과가 남는다

`state.json` 에 `syncLog` 를 **최근 20건** 둔다. 동기화 화면 아래 표로 선다.

```
시각          결과        받음  보냄  걸린 시간   비고
09-16 14:02  받음 3건      3     -     4.1s
09-16 09:30  이미 최신      -     -    19.8s
09-15 18:44  실패          -     -     2.0s     ff 불가 — 로컬 커밋 2건
```

> **로그에 무엇을 안 넣나** — 문서 내용·검색어·토큰은 안 쓴다(`core/logger.js` 의
> 규칙과 같다). 커밋 메시지도 안 쓴다. 건수와 사유 문장까지다.

#### ③ git 설정이 보인다

점검 여섯 줄. 각 줄은 `상태 마크 · 값 · 고치는 법`.

| 줄 | 정상 | 아니면 |
|---|---|---|
| remote | `origin  https://…` | `remote 없음` — 받을 곳도 보낼 곳도 없다 |
| upstream | `main -> origin/main` | `upstream 없음` — 명령 복사 `git push -u origin main` |
| **`core.hooksPath`** | `.githooks` | ⚠ **조용한 실패다.** 커밋은 통과하고 검사는 안 돈다. `[설정]` 버튼 |
| `credential.helper` | `manager` | 명령 **복사만** — `git config --global credential.helper manager` |
| `user.name` · `user.email` | 값 | 비어 있으면 커밋이 막힌다 |
| 마지막 fetch | 시각 | 없으면 `한 번도 안 함` |

**`core.hooksPath` 만 버튼을 준다.** 로컬 레포 설정이고, 되돌리기가 한 줄이고,
안 돼 있을 때의 손해(커밋 검사가 조용히 통과)가 가장 크다. **`--global` 을 건드리는
것은 전부 명령 복사까지다** — 자격 증명 설정을 앱이 대신 하지 않는다는 결정
(README 「보안」)과 같은 선이다.

**받기·보내기 버튼은 상태바에 그대로 둔다.** 관리 화면에도 같은 버튼을 놓되,
*"받는 것과 보내는 것을 같은 자리에 두지 않는다"* 는 규칙은 유지한다 — 받기는
동기화 블록에, 보내기는 **미전송 블록**에 따로 선다.

### 3.4 작업 레포 — 에이전트 설치

지금은 경로 문자열 목록이다. **카드로 바꾼다.**

```
┌─────────────────────────────────────────────────────────┐
│  C:\gdi                              ● 최신             │
│  skill 7종 · CLAUDE.md 블록 · .claude/cdp.json          │
│  마지막 설치  09-14 11:20  ·  kit 3f9c1a                │
│  [다시 점검]  [폴더 열기]  [빼기]                         │
└─────────────────────────────────────────────────────────┘
```

상태 다섯 — **`planSetup` 을 dry 로 돌려서 계산한다.** 새 판정을 만들지 않는다.

| 상태 | 뜻 | 판정 |
|---|---|---|
| ● 최신 | 모든 action 이 `same` | 아무것도 안 쓴다 |
| ◐ 갱신 필요 n건 | `create`/`update`/`append`/`remove` 가 있다 | 무엇이 바뀌는지 줄로 보여 준다 |
| ○ 미설치 | `.claude/skills/cdp-*` 가 하나도 없다 | 첫 설치 |
| ⚠ 경고 | 설치는 됐는데 `.gitignore` 가 `.claude` 를 막고 있다 등 | `plan.warnings` 그대로 |
| ✕ 오류 | 폴더 없음 · git 레포 아님 · 지식 레포 자신 | `plan.reason` 그대로 |

추가로 —

- **계획 미리보기는 지금처럼 먼저 보여 준다.** 레포 밖에 파일을 쓰는 유일한
  자리다(`http.js` 주석). 다만 팝오버 안의 다섯 줄이 아니라 **카드가 펴져서** 전부 보인다.
- **일괄 갱신** — `갱신 필요` 인 레포가 여럿이면 `[전부 갱신]`. 각각의 계획을
  먼저 다 보여 주고 한 번 누른다.
- **설치 이력** — 레포마다 마지막 설치 시각·kit 해시·그때 쓴 action 요약.
  화면 아래 전체 이력 표(최근 20건).
- **kit 해시** — 지식 레포의 `.claude/skills/cdp-*` 와 `work-repo/CLAUDE.md` 내용을
  sha256 해서 앞 6자리. **무엇을 심었는지 말할 수 있어야 한다** — 지금은 "설치했다"
  까지만 알고 *어느 판을* 심었는지 아무도 모른다.

> **드리프트 판정은 해시로 하지 않는다.** 판정은 `sameTree` 내용 비교가
> 그대로 한다(`core/setup.js`). 해시는 **이력에 적는 이름표**일 뿐이다.
> 판정을 두 곳에 두면 갈라진다 — 불변조건과 같은 이유다.

### 3.5 진단 · 정보

| 줄 | 값 |
|---|---|
| 앱 버전 | `package.json` 의 version |
| **번들 시각** | 앱이 든 `ctx` 와 레포가 든 `bin/ctx.mjs` **둘 다.** 다르면 ⚠ |
| 데이터 폴더 | 경로 + `[폴더 열기]` — 포터블이면 그 사실도 |
| 로그 파일 | `logs/app.log` + `[열기]` · 회전 3개 |
| 서버 | `127.0.0.1:7373` · loopback 아니면 상시 경고(이미 있다) |
| 실행 형태 | exe(SEA) / node · 트레이 켜짐·꺼짐 · 유휴 종료 90초 · `탭 닫아도 계속 실행` 상태 |
| git · node | `git --version` · `process.version` |
| 감시 | 켜짐·꺼짐 / 살아 있음·끊김 · 마지막 스캔 ms |

**로그 열기는 `/api/open` 을 쓴다** — 실행 확장자 거부와 존재 확인이 이미 붙어 있다.

## 4. 서버 · core 변경

### 4.1 새 API

| 메서드 · 경로 | 하는 일 | 비고 |
|---|---|---|
| `GET /api/sync` | 현재 단계 · 직전 결과 · 최근 이력 | 네트워크를 치지 않는다 |
| `POST /api/sync` | fetch → (behind면) ff pull → rescan | **한 번에 하나.** 겹치면 409 |
| `GET /api/git/config` | remote · upstream · hooksPath · credential.helper · user.* | 읽기만 |
| `POST /api/git/hooks` | `git config core.hooksPath .githooks` | **레포 로컬 설정만.** `--global` 금지 |
| `GET /api/workrepos` | 등록된 작업 레포 전부의 설치 상태 | 각각 `planSetup` dry |
| `GET /api/diag` | 버전 · 경로 · 포트 · 실행 형태 · 번들 시각 | 값만. 행동 없음 |

기존 `POST /api/setup` 은 그대로 두고, **apply 성공 시 서버가 이력을 적는다**
(지금은 아무 데도 안 남는다).

### 4.2 core

| 파일 | 변경 |
|---|---|
| **`core/sync.js`** (신설) | `runSync(root, { onPhase })` — fetch/pull/rescan 오케스트레이션. **`ctx sync` 도 이것을 쓴다.** 지금은 CLI 와 화면이 각자 순서를 들고 있다 |
| `core/git.js` | `readConfig(root)` · `setHooksPath(root)` · `remoteUrl(root)` 추가. **merge·rebase·reset 은 여전히 없다** |
| `core/setup.js` | `inspect(kn, wk)` — `planSetup` 을 감싸 상태 한 글자로. `kitHash(kn)` 추가 |
| `core/appstate.js` | 스키마 확장 + 마이그레이션 (§5) |

**`core/` 는 여전히 HTTP 를 모른다.** 새 함수도 전부 경로와 값만 받는다.

### 4.3 화면

| 파일 | |
|---|---|
| `viewer/src/components/admin/AdminView.jsx` | 셸 + 메뉴 |
| `.../admin/Overview.jsx` `Repo.jsx` `Sync.jsx` `WorkRepos.jsx` `Diag.jsx` | 다섯 화면 |

**순증가는 크지 않다** — `App.jsx` 에서 300행 가까이 빠진다.

## 5. 상태 스키마

```jsonc
{
  // 지금
  "repoPath": "C:/knowledge",
  "workRepos": ["C:/gdi", "C:/other"],        // ← 문자열 배열

  // 바뀐 뒤
  "workRepos": [
    { "path": "C:/gdi", "addedAt": "2026-09-14T02:20:00Z",
      "lastApplied": { "at": "…", "kit": "3f9c1a", "ops": { "create": 7, "update": 1 } } }
  ],
  "syncLog":  [ { "at": "…", "ok": true, "phase": "done",
                  "behind": 3, "ahead": 0, "ms": 4100, "message": null } ],
  "setupLog": [ { "at": "…", "path": "C:/gdi", "kit": "3f9c1a", "actions": ["skill:cdp-work …"] } ]
}
```

**마이그레이션** — `AppState.load()` 에서 한 번. `workRepos` 의 원소가 문자열이면
`{ path }` 로 감싼다. `appstate.js` 에 **이미 같은 성격의 코드가 있다**(`ctx-view` →
`cdp` 폴더 이관) — *"이름을 바꾸면 설정이 사라진다"* 는 그때의 교훈을 여기서도 지킨다.

두 로그는 **각각 20건에서 자른다.** 무한히 자라면 `state.json` 이 커지고, 그 파일은
4초마다 통째로 쓰인다.

## 6. 지키는 것 / 새로 여는 것

### 그대로 지킨다

| | |
|---|---|
| 레포에 아무것도 안 쓴다 | 이력·설정·로그 전부 `%LOCALAPPDATA%\cdp\` |
| merge · rebase · 충돌 해결 안 한다 | ff 아니면 **git 문장 그대로** 보여 주고 손 뗀다 |
| 자동 push 안 한다 | 보내기는 사람이 누른다 |
| 자격 증명 안 다룬다 | 값 표시 + 명령 복사까지. 입력칸을 만들지 않는다 |
| 판정은 `core/` 한 곳 | 설치 상태도 동기화 결과도 화면이 따로 계산하지 않는다 |
| 알림 안 한다 | 열었을 때 말한다. 띄우지 않는다 |
| 정상은 조용하다 | 최신·설치됨은 무채색. 색은 이상에만 |

### 새로 여는 경계 — **하나뿐이다**

**`git config core.hooksPath` 쓰기.** 지금까지 앱이 실행한 git 은 읽기와
fetch/pull/push 뿐이었다. 설정 쓰기가 처음 들어온다.

| 왜 여나 | 안 돼 있으면 **커밋이 검사 없이 통과한다.** 조용한 실패이고 손해가 가장 크다 |
|---|---|
| 얼마나 여나 | **그 한 키만.** 지식 레포 로컬 config 만. `--global` 은 절대 안 쓴다 |
| 어떻게 여나 | 누르기 전에 실행할 명령을 그대로 보여 준다. 되돌리는 명령도 같이 적는다 |

## 7. 안 하는 것

| | 왜 |
|---|---|
| **clone · 레포 만들기** | 레포는 이미 규약대로 존재한다(설계서 §2.2 ③). 마법사는 v0.4 에서 이미 지웠다 |
| **읽기 설정 복제** | `⋯` 에 있다. 같은 값을 고치는 자리를 둘로 만들지 않는다 |
| **작업 레포 자동 탐색** | 디스크를 훑어 `.git` 을 찾아 목록에 넣지 않는다. 경로는 **사람이 입력한 것만** 온다(`http.js` 규칙) |
| **주기적 자동 pull** | pull 은 작업 트리를 바꾼다. 조용히 하면 편집 중인 파일과 충돌한다 |
| **설치 되돌리기(rollback)** | 심은 파일을 앱이 지우면 사용자가 그 뒤 손댄 것까지 날아간다. `remove` 는 정본에서 사라진 `cdp-*` 에만 |
| **원격 브랜치 전환·생성** | 브랜치는 터미널의 일이다 |
| **설치 결과를 지식 레포에 기록** | 레포에 안 쓴다는 불변조건이 먼저다 |
| **사용 통계** | 열람 시간·클릭 수를 로컬에도 안 남긴다(설계서 §27.6) |

| 10 | CLI | `ctx sync` 가 `core/sync.js` 를 쓴다. 화면과 같은 순서·같은 문장 |

### 설계와 달라진 것 셋

**① 화면이 "모르는 것" 과 "없는 것" 을 구별한다.**
실측에서 `git 설정` 여섯 줄이 **읽는 동안 전부 "없음 · 미설정"** 으로 떴다.
멀쩡히 설정된 레포인데 한순간 아무것도 안 돼 있는 것처럼 보인다 — 설계서가
경계한 *"근거 없는 경고"* 와 같은 종류의 거짓말이다. 로딩과 미설정을 갈랐다.

**② `fetch` 실패를 성공으로 접지 않는다.**
옛 `syncNow()` 는 fetch 가 실패해도 그냥 `이미 최신입니다` 로 흘렀다. 최신인
것과 **최신인지 모르는 것**은 다르다. `core/sync.js` 는 fetch 실패를 실패로
낸다.

**③ 409 가 삼켜지던 것을 고쳤다.**
`api.js` 의 `req()` 가 `res.ok` 가 아니면 본문의 `error` 만 보고 던졌다. 그런데
`git/pull` 이 ff 불가로 낼 때 본문에 있는 것은 `reason` 과 `message` 다 — 그래서
화면에는 **`HTTP 409`** 만 떴고, *"원격이 N건 앞서 있고 로컬에도 M건이 있습니다.
터미널에서 `git pull --rebase`"* 라는 서버의 안내는 한 번도 사용자에게 닿은 적이
없다. `allowStatus` 를 두어 **실패가 결과인 호출**은 본문을 그대로 받는다.
