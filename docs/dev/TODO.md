**시드가 실패해서 `.claude/skills` 네 개와 `bin/`·`tools/` 를 잃었다.**

원인은 보존 방식이었다. 레포를 통째로 지우고 세 폴더를 임시 위치로 **옮겼다가
되돌리는** 구조였는데, 옮긴 뒤 되돌리기 전에 죽으면 잃는다. 게다가 다음 실행이
맨 앞에서 그 임시 폴더를 지워 **복구 가능성까지 없앴다.**

```
잃은 것    cdp-save · cdp-managed (다시 씀)
복구한 것  cdp-work · cdp-load (_old/sample-repo-gdi 사본에서 + 패치 재적용)
```

**고친 방식** — 옮기지 않는다. 시드가 **자기가 만든 것만** 명시적으로 지운다.

```python
OWNED_DIRS  = ('work', 'docs', 'design')
OWNED_FILES = ('_vocab.md', '_managed.md', 'INDEX.md', ..., '.gitignore')
```

**옮기지 않으면 잃을 수 없다.** 그리고 무엇을 남겼는지 출력한다 —
조용히 남기면 지워졌는지 남았는지 알 수 없다.

```
kept (not seed) : .claude, bin, tools
```

### `.gitattributes` 가 필요했던 이유

첫 커밋에서 CRLF 경고가 44건 나왔다. **`.githooks/pre-commit` 과 `bin/ctx` 는
sh 스크립트다** — CRLF 로 체크아웃되면 shebang 줄 끝에 캐리지리턴이 붙어
훅이 실행되지 않고, **그것은 조용히 실패한다.** 커밋은 통과하고 검사는 안 돈다.

`core.autocrlf=true` 인 PC 에서만 깨지므로 **폐쇄망에 옮긴 뒤에야 발견된다.**
그때는 물어볼 사람이 없다. `* text=auto eol=lf` 로 고정했다.

### 잡은 것 ① — **폐쇄망에서 아무도 커밋을 못 했다**

git 은 있고 Node·exe 가 없는 PC 에서 **커밋이 전부 막혔다.**

```
ctx: node 도 cdp.exe 도 없습니다.
[pre-commit] 커밋을 중단했습니다.
             고친 뒤 다시 커밋하세요.
```

훅은 `bin/ctx` **파일이 없으면** 건너뛰게 돼 있었는데, 파일은 있고 **실행기가
없는** 경우를 구분하지 못했다. 그리고 메시지가 *"고친 뒤 다시 커밋하세요"* 라
사용자는 **자기 문서가 잘못된 줄 안다.**

> 훅 주석에 *"검사를 못 하는 것과 검사에 실패한 것은 다르다"* 고 적어놓고
> **구현이 그것을 못 지켰다.**

**고침 — 실행기 없음을 `exit 127` 로 구분한다.**

```sh
sh "$ctx" check --repo "$repo"; rc=$?
if [ "$rc" -eq 127 ]; then     # 셸 관례 "command not found"
  echo "[pre-commit] 검사를 건너뜁니다 -- ctx 를 실행할 수 없습니다." >&2
  echo "             **커밋은 통과하지만 검사는 돌지 않았습니다.**" >&2
  exit 0
fi
```

**개발 PC 에서는 절대 안 보이는 버그다.** 거기엔 Node 가 있다.

### 잡은 것 ② — **두 실행기가 다른 답을 냈다**

낡은 exe 로 `ctx stale` 을 돌리니 **밀림 4곳**, 새 `bin/ctx.mjs` 로는 **3곳**.
exe 에 "같은 날짜는 이후가 아니다" 수정이 안 들어가 있었다.

그리고 하필 `ctx version` 이 그 exe 에 없어서 **낡았는지 확인할 수단도 없었다** —
`모르는 명령 "version"` 이라는 증상만 남는다.

> *"앱과 ctx 가 다른 답을 내면 사용자는 어느 쪽을 믿을지 알 수 없다"* 는 것이
> `core/repo.js` 를 만든 이유였는데, **빌드 단계에서 같은 일이 일어났다.**

**고침 두 가지.**

| | |
|---|---|
| `build-exe.mjs` 가 **`build-ctx.mjs` 를 먼저 부른다** | 하나만 갱신될 수 없다. 실패하면 exe 를 안 만든다 |
| 번들 시각을 **exe 에도 심는다** | `bin/ctx.mjs` 와 같은 값. 그래야 대조할 수 있다 |

`npm run release` = `build` → `build:exe`(ctx 포함) → `sample`.

### 잡은 것 — **CRLF 하나로 레포 전체가 커밋 불가가 된다** ★

용어를 바꾸며 `_vocab.md` 를 저장했더니 `ctx check` 가 **미등재 좌표 59건**을
냈다. 파일 내용은 두 줄만 바뀌었는데 좌표가 **하나도** 안 잡혔다.

원인은 용어가 아니라 **줄바꿈**이었다. 파서들이 `split('\n')` 을 쓰는데 CRLF
파일이면 줄 끝에 `\r` 이 남고, **JS 정규식의 `.` 은 `\r` 을 안 먹는다.**
`_vocab.md` 의 좌표 항목 패턴이 하필 `...(.*)$` 로 끝난다.

```
- `term:최신성` — 같은 좌표에 후속이 더 없는 상태\r
                                              ^^ 여기서 (.*)$ 가 실패한다
```

**증상이 고약하다.** 어휘가 통째로 비면 모든 좌표가 미등재로 잡히고, **미등재는
훅이 커밋을 막는 유일한 항목**이다(수행 §6.2). 파일은 멀쩡해 보이는데 아무도
커밋을 못 한다.

> `core.autocrlf=true` 로 clone 한 Windows PC, 또는 `_vocab.md` 를 메모장으로
> 한 번 저장한 것만으로 재현된다. **LF 로 개발하는 기계에서는 절대 안 보인다** —
> 8단계의 "Node 없는 PC" 와 같은 부류다.

**고침 — 읽기 경계에서 한 번만 없앤다.** `scan.js` 에 `readText()` 를 두고
`scan()` 의 본문 읽기와 `repo.js` 의 `readOr()`(= `_vocab.md`·`_managed.md`·
`INDEX.md`)가 전부 통과하게 했다. 층마다 `\r` 을 지우면 반드시 한 곳을 빠뜨린다.

지금 `C:\cdp\_vocab.md` 는 **CRLF 인 채로** 세 실행기가 전부 오류 0 을 낸다.

### 잡은 것 ① — `stale` 한 낱말이 세 뜻이었다

관계 패널이 이 문서를 가리키며 *"2026-0821 까지만 반영돼 있습니다"* 라고 했다.
**그 문서가 2026-0821 이었다.**

같은 `stale` 이라도 문서 쪽에서 보면 셋으로 갈린다.

| | 섹션이 | 할 말 |
|---|---|---|
| `mine` | 이 작업까지는 실었다 | 반영됨 — **그 뒤** 후속 N건이 안 실렸다 |
| `behind` | 이 작업 앞에 머물렀다 | 밀림 — **이 작업이** 아직 안 실렸다 |
| 그밖 | 더 나중 작업에 있고 그것도 밀렸다 | 밀림 — 지금은 X 까지 |

하나로 쓰면 첫째가 **자기 자신을 가리킨다.**

### 잡은 것 ② — `behind` 가 미작성 섹션을 전부 먹었다

`behind` 를 `items.some(x => x.id === 이 작업)` 으로만 판정했더니 `code:PS130`
같은 **미작성** 섹션이 걸린 작업마다 "이 작업이 아직 안 실렸습니다"가 붙었다.

`applied` 가 없으면 `later(null, 좌표)` 가 그 좌표의 작업을 **전부** items 로
내놓는다. 미작성은 "안 실렸다"가 아니라 "아직 아무것도 안 적혔다"다 —
`state === 'stale'` 로 한정했다.

> 날짜를 다시 비교하지 않고 `items` 로 판정한 것은 맞았다. §6.1 의
> **"같은 날짜는 후속이 아니다"** 를 공짜로 물려받는다. 거친 날짜 비교로 세었을
> 때 8건이던 것이 `items` 기준으로 **3건** — `ctx stale` 의 밀린 섹션 3곳과 정확히 같다.

### 잡은 것 ③ — 관리 문서를 열면 패널이 늘 비었다

`openDocData.id === docId` 로만 맞춰 봤는데 **관리 문서는 `docId` 에 경로가
들어온다** (`openDoc(path)`). 정작 섹션 목록이 가장 필요한 화면에서 패널이
빈 채로 섰다. `id` 와 `path` 를 둘 다 본다.

### 잡은 것 ④ — 접기 신호를 이벤트 하나에 맡기면 엇갈린다

`<=1100px` 판정을 `matchMedia` 의 change 로만 들었는데, 뷰포트를 코드로 줄이는
경로에서는 change 도 `resize` 도 **안 왔다.** 그러면 CSS 는 접었는데 React 는
안 접은 상태가 되어 **관계 패널이 열로도 안 서고 본문 아래로도 안 붙는다** —
관계 정보에 닿을 길이 통째로 사라진다.

`ResizeObserver` + `resize` 둘 다 건다. 박스가 실제로 바뀌는 것은 어느 경로에서나
같다.

> 검증 자체도 이것 때문에 한 번 막혔다. 창이 안 그려지는 환경에서는 rAF 가
> 안 돌아 `ResizeObserver` 콜백도 안 온다 — 수동으로 `resize` 를 쏴서 확인했다.

### 잡은 것 — **렉의 원인은 드래그마다 서버로 저장한 것**

```
전   mousemove 25번 → patch() 25번 → 리렌더 25번 + POST /api/state 25번
후   mousemove 25번 → CSS 변수 25번 · 저장 0번,  놓을 때 저장 1번

실측으로 **드래그 중 저장 호출 0회 · 놓은 뒤 1회.** 화면은 CSS 변수 하나면

### 왜 가로인가

세로로 쌓으면 레벨이 깊어질수록 시작점이 화면 밖으로 나가고 **지금 어디쯤인지

0/226/452/678 에 나란히 서고 가로 스크롤이 잡힌다 — 새 열이 붙으면 자동으로
그쪽으로 민다.

### 발광 룩 — three.js 를 쓰지 않는다

레퍼런스(`cortex_din_mico.html`)는 three.js + `UnrealBloomPass` 로 20,000
파티클을 태우고 `unpkg.com` importmap 을 쓴다. **둘 다 못 쓴다** — 폐쇄망이라
CDN 이 없고, three.js + postprocessing 을 번들하면 exe 가 크게 는다.

**블룸은 결국 밝은 점 주변에 헤일로를 더하는 것**이고 노드가 55개면 Canvas 의
가산 합성으로 같은 인상이 나온다.

| 레퍼런스 | 여기 |
|---|---|
| `UnrealBloomPass` | `globalCompositeOperation = 'lighter'` + 방사형 그라디언트 |
| 링+코어 셰이더 | 색마다 한 번 구운 스프라이트 (`drawImage`) |
| `FogExp2` | 원근 스케일에 알파를 물린다 |
| 20,000 파티클 | 노드 55 + **먼지 220** (시차 기준점. 아무 뜻 없다) |
| `OrbitControls` autoRotate | 기존 회전 그대로 |

**번들 증가 0** — 342KB 로 오히려 이전보다 작다(죽은 코드가 같이 빠졌다).
스프라이트를 매 프레임 굽지 않고 색마다 한 번만 굽는다 — 55개 × 60fps 면
초당 3,300번이 될 뻔했다.

**상태는 색으로 계속 말한다.** 발광은 장식이 아니라 밝기 = 작업 건수다.
`prefers-reduced-motion` 이면 맥동과 자동 회전이 멈춘다.

> 패널만 어둡다. 밝은 앱 안의 어두운 스코프는 계기판에서 흔한 배치이고,
> 발광은 어두운 바탕에서만 성립한다.

### 잡은 것 — **테마 변경이 프레임을 기다리고 있었다**

`draw()` 가 그리고 곧바로 다음 프레임을 예약하는 구조라, **테마가 바뀌어도
다음 rAF 가 와야** 다시 칠했다. 배경 탭처럼 rAF 가 멎은 상태에서는 어두운
바탕이 밝은 테마 위에 그대로 남는다.

실측에서 밝은 테마로 되돌렸는데 캔버스가 `#1e2023` 인 채로 남아 드러났다.
그리기(`paint`)와 예약(`draw`)을 쪼개고 `data-theme` 변화와
`prefers-color-scheme` 를 관찰해 **즉시 다시 칠한다.**

> 테마는 프레임을 기다릴 일이 아니다.

### 곁가지 — exe 빌드가 실패해 깨진 바이너리를 남겼다

`build/` 를 지우는데 `cdp.exe` 가 떠 있어 `EBUSY` 로 죽었고, **SEA blob 이 없는
맨 node 바이너리**가 남았다. 그 상태로 `ctx check` 를 부르면
`Cannot find module 'ctx'` 가 난다 — 실패했는데 파일은 있어서 성공처럼 보인다.
프로세스를 정리하고 다시 빌드해 복구했다. **20단계에서 빌드가 스스로 막게
했다.**

## 20단계 — 그래프 마무리 · 빌드 하드닝 · **완료** (2026-09-07)

19단계의 무채색 그래프에 남은 요청 넷과, 세 번 반복된 빌드 실패를 잡았다.

- [x] **노드 축소** — 반지름 계수를 줄여 55개가 겹치지 않는다
- [x] **라벨 폰트 = 구글폰트** — Roboto Mono
- [x] **색상 농도 상향** — 무채색인 채로 더 진하게
- [x] **공간 이동(pan)** — 회전만으로는 가장자리 노드에 못 간다

### 구글폰트를 링크로 가져올 수 없다

`fonts.googleapis.com` 은 폐쇄망에서 안 열린다. 그리고 **그 실패는 조용하다** —
`@import` 가 막히면 브라우저는 아무 말 없이 대체 폰트로 그린다. 개발 PC 에서는
정상으로 보이고 이관한 뒤에야 다르게 보인다.

latin 서브셋을 **base64 로 CSS 안에 넣었다**(`src/styles/font.css`, 43.5KB).
네트워크를 타지 않으므로 폐쇄망에서도 같은 글자가 나온다.

> **캔버스는 웹폰트를 알아서 안 불러온다.**
> `ctx.font` 에 이름만 적으면 아직 안 받아진 폰트는 **조용히** 기본 폰트로
> 떨어진다. `document.fonts.load()` 로 명시적으로 받고 나서 그린다.

### 회전만으로는 못 가는 곳이 있다

가장자리 노드는 줌아웃해도 화면 밖에 남았다. 회전은 원점을 중심으로 돌 뿐이라
**시야의 중심을 옮기지 못한다.** 드래그를 둘로 갈랐다 —

| 조작 | 결과 |
|---|---|
| 왼쪽 드래그 | 회전 |
| `Shift` + 드래그 · 가운데·오른쪽 버튼 | **공간 이동** |
| 휠 | 줌 (35%~500%) |
| `맞춤` | 이동·줌 원위치 |

### 잡은 것 — **상호작용이 애니메이션 프레임에 얹혀 있었다**

`prefers-reduced-motion` 이거나 자동 회전이 꺼져 있으면 rAF 루프가 멎는다.
그 상태에서 끌거나 줌하면 **계산은 되는데 화면이 안 바뀌었다.** 19단계에서
테마가 같은 이유로 안 따라온 것과 **같은 뿌리다** — 그때는 테마만 고쳤다.

`paint()`(즉시 그린다)와 `draw()`(그리고 다음 프레임을 예약한다)를 갈라 놓고,
**모든 입력은 `paint()` 를 직접 부른다.** 프레임 루프가 돌든 안 돌든 반응한다.

### 빌드 — **실패한 빌드가 성공처럼 보였다**

세 번 물렸다. 갓 복사한 66MB 실행 파일을 백신이 스캔하는 동안 잠기고,
`rcedit` 과 서브시스템 패치가 `EBUSY` 로 죽는다. **그 지점이 blob 주입
직전이라** 남는 것은 실행은 되고 `Cannot find module 'ctx'` 만 뱉는 파일이다.

```
전   잠김 → 즉시 죽음 → 반쪽 exe 가 build/ 에 남는다 (67MB · 그럴듯함)
후   잠김 → 최대 12회 재시도(0.5s 씩 증가) → 그래도 안 되면 지우고 멈춘다
```

세 가지를 넣었다.

| | |
|---|---|
| `retryBusy()` | `EBUSY` · `Unable to commit` 이면 기다렸다 다시 |
| `abort()` | **반쪽 파일을 지우고** 멈춘다 + `taskkill /F /IM cdp.exe` 안내 |
| 주입 후 검증 | `cdp.exe ctx version` 이 날짜를 내놓아야 빌드가 성공이다 |

> **없는 것과 깨진 것은 다르고, 깨진 쪽이 더 나쁘다.**
> 없으면 다시 만든다. 깨진 것은 다음 사람이 정상으로 믿는다.

아이콘 편집만은 실패해도 계속 간다 — 아이콘이 없어도 프로그램은 돈다.
멈춰야 할 실패와 아닌 실패를 가른다.

### 잡은 것 — **시드가 스스로 하는 말이 실제와 달랐다**

빌드 로그를 읽다가 나왔다. `npm run sample` 이 여전히 이렇게 말하고 있었다 —

```
work records   : 20  (미결 1 · 진행중 1 · ...)      ← 미결은 0 이다
managed docs   : 8                                  ← 16 이다
```

숫자가 **소스에 손으로 박혀 있었다.** 15단계에서 16종으로 이관했는데 보고만
8 로 남았다. docstring 도 걷어낸 fixture(밀린 섹션 4곳 · 미등재 좌표)를 아직
있다고 적고 있었다.

세어서 말하도록 고쳤다. 이제 시드가 바뀌면 보고도 따라 바뀐다.

## 21단계 — 없는 상태를 걷어냈다 · **완료** (2026-09-07)

14단계에서 **밀림·미작성은 상태가 아니다**로 정정했는데, 그 뒤로도 화면·CLI·
스킬·시드가 계속 그 말을 하고 있었다. 판정만 고치고 **어휘를 안 고쳤다.**

- [x] **뻗어나가기** — 계층이 섞이지 않게 다음 한 단계만
- [x] `이 섹션이 실은 작업` 제거 → `작업문서` 로 통합
- [x] **문구를 객체 이름으로** — 작업문서 · 관리문서 · 좌표 · 섹션
- [x] **정렬 규칙 통일**
- [x] **밀림·미작성 제거** — 그래프 · 목록 · 본문 배지 · CLI · 스킬 · 매뉴얼
- [x] **`확정` · `결정` 제거** — 기본값이라 아무것도 구별하지 않았다
- [x] **`제안` 제거** — `미결` 과 같은 것. 검사를 하나로 합치고 이슈 대장으로 이관

### 뻗어나가기 — 보고 있는 것에 따라 다음 한 계층만

| 지금 보는 것 | 다음 |
|---|---|
| 작업문서 | 관리문서 · 좌표 |
| 좌표 | 관리문서 · 작업문서 |
| 관리문서 | 섹션 |

전에는 좌표 열이 **네 그룹**이었다 — 지금 상태 · 이 섹션이 실은 작업 ·
아직 안 실린 작업 · 이 좌표를 바꾼 이전 작업.

```
전   좌표 →  지금 상태 — 관리 문서
             이 섹션이 실은 작업     ← 작업 1건
             아직 안 실린 작업       ← 밀림
             이 좌표를 바꾼 이전 작업 ← 나머지
후   좌표 →  관리문서
             작업문서               ← 전부 한 줄
```

**`applied` 를 따로 세우면 같은 목록이 둘로 갈라진다.** 섹션에 실린 작업도
결국 그 좌표를 바꾼 작업 중 하나인데, 위아래로 떼어 놓으면 읽는 사람이
"이 둘이 왜 다른가"를 먼저 풀어야 한다. 그리고 `아직 안 실린 작업` 은 밀림
그 자체라 애초에 있을 수 없는 줄이었다.

작업문서 열에서도 정정 2그룹(`이 기록이 정정한 문서` · `이 기록을 정정한
문서`)을 걷었다 — `supersedes` 는 판정이 아니고(§3), 계층도 아니다.

### 문구 — 관계를 문장으로 쓰지 않는다

```
전   이 작업이 바꾼 좌표 · 이 작업이 반영된 관리 문서 · 지금 상태 — 관리 문서
후   좌표 · 관리문서 · 작업문서 · 섹션
```

**열 머리에 시작점이 있으니 관계는 자리가 말한다.** 문장으로 쓰면 이미 아는
사실을 매번 다시 읽는다.

### 정렬 — 상태로 정렬하지 않는다

| 목록 | 기준 |
|---|---|
| **좌표** | 카테고리순 + 카테고리 안 이름순 |
| **작업문서** | 작성일자순 (최신 먼저) |
| **관리문서 · 섹션** | 섹션 순서 |

카테고리 순서는 `_vocab.md` 의 **선언 순서**다 — 팀이 어휘를 적은 순서가 곧
팀이 정한 순서다. 알파벳순으로 다시 매기면 팀의 결정을 덮는다.

`this.sections` 는 **상태 급한 순**으로 정렬돼 있었다. 그대로 내면 목차가
아니라 할 일 목록이 되고, **같은 것을 두 번 봐도 자리가 달라진다.**

### 밀림·미작성을 걷어낸 자리

| 어디 | 전 | 후 |
|---|---|---|
| **그래프 노드** | 농도·링으로 4상태 (빈 원 = 미작성, 링 = 밀림) | 원 하나. **크기만 다르다 — 작업 건수** |
| 그래프 범례 | 정상 · 미작성 · 밀림 · 섹션/문서 없음 | 없음 (구별할 상태가 없다) |
| 뻗어나가기 배지 | `밀림` `미작성` `끊김` … | 없음 |
| 좌표·문서 목록 | `밀림 N` 배지 | 없음 |
| 본문 섹션 머리 | `밀림 3건` 배지 | 없음 |
| 본문 좌표 | `⚠` `·` `⛔` 첨자 | 없음 |
| 문서 머리 | ⚠ 확인이 필요한 좌표 N곳 | 후속 작업이 있는 좌표 N곳 |
| CLI | `ctx stale` — 밀린 섹션 목록 | **`ctx derive`** — 파생 남은 섹션 |
| `ctx where` | `상태 밀림 2건` | `상태 반영 <작업 id>` |
| 검사 | `stale-section`(error) + `unwritten-section`(info) | **`derive-missing`(error) 한 건** |

> **없는 상태를 그림으로 그리면 화면이 없는 구분을 있는 것처럼 말한다.**
> 파생은 필수이므로 안 된 섹션은 상태가 아니라 **오류**다.

### 잡은 것 — **오류 절반이 info 로 숨어 있었다**

`stale`(applied 뒤에 후속이 있다)은 error 였고 `unwritten`(applied 가 아예
없다)은 **info** 였다. 둘은 같은 위반이다 — 파생을 안 했다.

한 건으로 합쳐 error 로 올리자 **두 레포에서 8곳이 튀어나왔다.**

```
module:acl-a10-adapter   프로그램사양서   작업 3건   applied 없음
module:grid-common       프로그램사양서   작업 2건   applied 없음
module:code-help · module:date-range · batch:project-status-nightly
code:PS130               코드정의서       작업 1건   applied 없음
table:rp_rsch_prj_mst · table:rp_wrk_hst_stat_info
```

전부 **옛 시드가 심은 미작성 fixture** 였다 — `<!-- applied: null -->` 아래
`> ⚠ 아직 정리되지 않았습니다.` 가 붙은 자리. 14단계에서 개념을 없앴는데
데이터에는 그대로 남아 있었고, **info 등급이 그것을 가려 주고 있었다.**

시드에 `fill_applied()` 를 넣어 작업 기록이 있는 섹션은 그 좌표의 **최신**
작업으로 채우게 했다(옛것을 실으면 그 뒤 후속이 남아 또 오류다).
`C:\cdp` 는 같은 규칙으로 8곳을 채웠다.

작업 기록이 **없는** 섹션(`empty`)은 그대로 둔다 — 실을 것이 없는 것은
위반이 아니다. `ctx derive` 도 그것을 내지 않는다.

### `확정` · `결정` — 값이 아니라 기본값이었다

30건 중 **28건이 `status: 확정`** 이었다. 프로그램은 그 값으로 분기한 적이
없다. 뜻이 남은 값은 `진행중`(점유 · 최신성 계산에서 빠진다) 하나다.

```
전   status: 확정      (필수 필드. 28/30 이 같은 값)
후   (적지 않는다)      읽는 경계에서 `확정` → null 로 지운다
```

`frontmatter.js` 에서 지우므로 **이미 적힌 기존 기록도 고치러 다니지
않는다.** `check.js` 의 필수 필드에서 `status` 를 뺐다.

`결정 2026-09-03` → **`작성 2026-09-03`.** 지식공유문서는 결정을 담는 문서가
아니라 **작업의 완료에서 발생하는 문서**다. 날짜는 그것을 적은 날이다.

### `제안` 도 없앴다 — `미결` 과 같은 것이었다

`확정` 을 걷은 뒤 각 레포에 `status: 제안` 이 1건 남아 있었다. **코드 경로가
전혀 없었다** — 어디서도 그 값으로 분기하지 않는다.

`미결` 과 같은 것이다: **결정이 안 났다.** 이름이 둘이면 한쪽만 막히고 다른
쪽으로 흘러 들어간다. 검사를 하나로 합쳤다.

```
전   legacy-pending   status: 미결 —  … (제안은 아무도 안 잡는다)
후   agenda-status    status: 미결·제안 — 지식공유문서가 아니라 아젠다입니다
```

**그 1건을 어떻게 옮겼나** — 반은 지식이고 반은 아젠다였다.

```
work/2026-0902-결의서-작성자고정.md   status: 제안
  본문: 왜 작성자를 "과제연동" 으로 고정하는가        ← 판단 끝남
  꼬리: "남은 일 — A10 측 계정 생성 요청. 회신 대기"  ← 아젠다
```

**판단이 끝난 부분과 안 끝난 부분을 갈랐다.** 작업 기록은 상태 없이 그대로
남기고(그 판단은 지식이다), 회신 대기만 `issue:ISS-002` 로 이슈 대장에
올렸다. 통째로 옮기면 **"왜 고정하는가"가 아젠다에 묻힌다.**

ISS-001 이 `미결` 에서 옮겨 간 것과 같은 모양이고, 어휘에도 등재했다.

| | 전 | 후 |
|---|---|---|

### ③ git 로그인은 넣지 않았다

**자격 증명을 앱에 넣을 자리를 만들지 않는 것이 판단이다.** 인증은 git 이 OS
자격 증명 관리자로 처리한다 — 앱이 아이디·토큰을 들고 있으면 **그것을 저장할
자리가 하나 더 생기고, 그 자리가 가장 약한 곳이 된다.**

설정에는 지금 연결된 원격(`origin/main`)과 한 줄 안내만 둔다.

```
git config --global credential.helper manager
```

레포 경로는 넣었다 — **전에는 최초 지정 화면에만 있어서** 한 번 지정하면 바꿀
데가 없었다. 입력하면 지식 레포인지(`_vocab.md` 가 있나) 바로 확인해 준다.

### ④ 동기화 — 받는 것만

상단 **⭮** 하나가 fetch → (뒤처졌으면) ff pull → 재스캔을 한다. 전에는 상태바의
`⬇ 원격 N건 받기` 뿐이었고, **그 버튼은 fetch 가 이미 돌아 뒤처짐을 알아낸
뒤에만 나타났다** — "지금 최신인가"를 확인하려면 5분 주기 fetch 를 기다려야 했다.

**push 는 상단에 두지 않았다.** 커밋은 되돌릴 수 있지만 push 는 남의 눈에
들어간다 — 받는 것과 보내는 것을 같은 자리에 두지 않는다.

ff 가 안 되면 그대로 알린다. 기계가 merge 하지 않는다.

### ⑥ 탭 넷 — 층을 섞지 않는다

```

후   [관리문서] [작업문서] [좌표] [그래프]
```

관리문서는 **지금 상태**, 작업문서는 **사건**이다. 한 탭에 두면 성질이 다른 둘을
스크롤로 가르게 된다 — **뻗어나가기가 계층을 섞지 않는 것과 같은 이유다.**

**그게 이 반영의 값어치다.**

> **백틱을 쓰면 안 걸린다.** 처음에 `` `screen:PLA021` `` 로 적었더니 링크가
> 0개였다 — 본문 좌표 링크는 `CODE` 안을 건너뛴다(코드 스팬은 글자 그대로여야
> 하니 맞는 동작이다). 좌표처럼 보이기만 하고 눌러도 아무 일이 없었다.

실측 — 좌표 링크 11개 · 표 3개 · 201행 · `ctx check: 이상 없음`.

### 잡은 것 — **그래프가 좁은 창에서 열리면 영원히 빈 캔버스였다**

⑥을 확인하다 나왔다. `paint()` 는 폭·높이가 4px 미만이면 아무것도 안 하고

```

창을 넓힌다               → 다시 그릴 계기가 없다
결과                      → 캔버스 속성이 300x150(기본값) 그대로, 픽셀 0

`ResizeObserver` + `resize` 리스너를 넣었다. 관찰 대상은 **캔버스가 아니라
부모다** — 콜백에서 `cv.width` 를 쓰므로 캔버스를 관찰하면 자기가 만든 변화를

> 옵저버로도 이벤트 0). 그래서 그 환경 검증은 `resize` 폴백으로 했다:

이름만 `맞춤` 이고 하는 일은 **회전과 줌을 상수로 되돌리는 것**이었다.

요청할 때만 도니 한 번 더 도는 비용은 없는 것과 같다.

크기가 바뀌면 다시 맞추는데, **사용자가 줌·이동을 손댔으면 지킨다**(`touched`).

## 25단계 — 그래프 배율 기준 · 카테고리 색 · **완료** (2026-09-07)

### 배율에 기준이 없었다

`맞춤` 이 정한 값을 그대로 `zoom` 에 넣었더니 **열자마자 57% 같은 숫자가
떴고, 그 숫자는 아무것도 가리키지 않았다.** 100% 가 무엇인지 알 수 없으면
57% 도 143% 도 뜻이 없다.

```
전   zoom          = 맞춤 결과            → 열면 57%
후   base(내부)    = 맞춤 결과
     zoom(사용자)  = 1                    → 열면 100%
     화면 배율     = base × zoom
```

**맞춘 상태가 늘 100% 다.** 사용자가 보는 숫자는 "맞춤에서 얼마나 더/덜"이
된다.

### 왜 150% 가 보기 좋았나 — 고립 노드가 배율을 정하고 있었다

여백 탓인 줄 알고 재 봤더니 **전체 맞춤은 이미 프레임을 폭 99% · 높이 96% 로
꽉 채우고 있었다.** 문제는 다른 데 있었다.

```
노드 57 · 간선 64 · 덩어리 25 · 고립 21     ← 고립이 3분의 1 이 넘는다
```

힘 배치가 고립 노드를 바깥으로 밀어내고, **그 바깥 것들이 배율을 정한다.**
그래서 정작 볼 덩어리는 가운데에 작게 뭉쳤다 — **중앙 절반에 잉크가 39%.**

기본 배율을 전체 맞춤의 **1.5배**로 조였다(`SNUG`). 바깥 몇 개는 프레임을
벗어나지만 `−`·끌기로 닿고, **처음 보이는 화면이 읽힌다.**

| | 전 | 후 |
|---|---|---|
| 열었을 때 표시 | 57% (기준 없음) | **100%** |
| 중앙 절반의 잉크 | 39% | **52%** |
| 전체 보기 | 기본 | `−` 두 번 (59%) |

### 카테고리 색 — 원칙과 충돌하지 않는다

왼쪽에 타입 레일을 세웠다. 고르면 그 좌표만 강조색이 되고 나머지는 옅어진다.

```
table 18 · screen 18 · api 3 · module 4 · code 3 · term 3 · batch 1 · domain 5 · issue 2
```

**"상태로 색을 쓰지 않는다"와 어긋나지 않는다.** 이건 상태가 아니라 **지금
무엇을 고르고 있나**이고, 그것이 색 예산의 파랑(상호작용)이 하는 일이다.
아무것도 안 고른 기본 상태는 여전히 **채도 0** 이다.

- 있는 타입만 낸다 — 0건인 줄은 고를 수 없는 줄이다
- 순서는 어휘 선언 순서. 화면마다 다르면 눈이 자리를 기억할 수 없다
- 색과 함께 **테두리 한 겹**을 더한다 — 색을 못 보는 사람에게도 구별이 남는다

| 작업 할당 · 이슈 트래커 | 조직 구조와 얽힌다. CDP 가 답할 문제가 아니다 (작업환경 §2) |

| **하네스 훅** | skill `description` 이 발동 규칙이고, 그 뒤에 git 훅이 있다. 비결정을 비결정으로 덮지 않는다 |
