# v1.0 실서버 이행 절차 — gdi 제자리 · dpms_wiki 다시 세우기

> 짝 문서 — 계획 [`../design/CDP_v1.0_개편안.md`](../design/CDP_v1.0_개편안.md) §9 · 절차와 결정 [`v1.0_개편_TODO.md`](v1.0_개편_TODO.md) · 서버 일반 절차 [`../../ops/deploy/설치절차.md`](../../ops/deploy/설치절차.md) 10장 「v0.x → v1.0」.
> **사람이 한다** — push · 태그 · 실서버 upgrade · GitLab 프로젝트 정리 · 토큰은 운영자의 일이다. 아래의 `<서버>` 는 실서버 주소, `CTX` 는 `sudo -u cdp -H node /opt/cdp/bin/ctx.mjs`.

리허설(개발 PC · `ops/out/v1-rehearsal`)에서 같은 순서를 최신 코드로 돌렸다 — 결과는 TODO §5 마지막 줄들(gdi 사본 · 다시 세운 dpms_wiki).

## 0. 올리기 전에

| | |
|---|---|
| 태그 | `v1.0.0` 을 붙이고 push → GitHub Release 의 `cdp-server-v1.0.0.tar.gz` · `SHA256SUMS` 를 받는다 |
| 백업 | `/opt/cdp/repos` 디스크 스냅샷 한 번(이행은 커밋을 더하지만 지우지는 않는다 — 그래도) |
| 알림 | 이행하는 동안(10~20분) save 가 멈춘다 — 작업 레포 사용자에게 미리 |

## 1. 서버 판 올리기

```bash
sudo bash /opt/cdp/deploy/upgrade.sh /tmp/cdp-server-v1.0.0.tar.gz
$CTX serve doctor --root /opt/cdp/repos --auth /opt/cdp/auth.json --data /opt/cdp/data --web /opt/cdp/web --bind <서버 IP> --port 7374
```

**확인** — `doctor` 에 `kit` · `forms` 가 ok, 그리고 「레포 gdi 도구 층」 · 「레포 dpms_wiki 도구 층」 warn 둘. 이 둘이 v0.x 레포다. 아직 쓸 수는 있다(save 는 훅을 타지 않는다) — 이행이 끝날 때까지 큐레이션은 하지 않는다.

## 2. gdi — 제자리 이행

```bash
sudo systemctl stop cdp-serve
$CTX migrate /opt/cdp/repos/gdi --dry --by <관리자>      # 반영됨 · 기록으로 둠 · 대기 수 · 걷을 도구 층
$CTX migrate /opt/cdp/repos/gdi --by <관리자>            # 커밋 둘(전환 기록 · 도구 층) — 서식 예시가 남았으면 셋
sudo systemctl start cdp-serve
```

- 이행 커밋은 서버 밖에서 만들었으니 origin 에 아직 없다 — 콘솔 › 지식 레포 › gdi › 「다시 보내기」(또는 다음 save 가 같이 보낸다).
- 리허설(gdi 사본) — 전환 기록 85건(반영됨 78 · 기록으로 둠 7 · 대기 0) · 검사 오류 0. README 의 MANUAL 고리 2줄은 손으로 고친다(이행이 알린다).
- 옛 `## rp_plnd_mst` 중복은 이제 다른 save 를 막지 않는다(V21) — 큐레이터가 `cdp-registry` 로 고친다.
- 서식 그대로인 관리 문서(gdi 는 10종) · `## 작성지침` · 머리 표의 관리번호 칸은 이행이 건드리지 않는다 — 큐레이터가 화면 「관리 문서」 탭(지우기)과 `cdp-registry` 로.

## 3. dpms_wiki — 다시 세우기(빈 레포 + 작업 기록만)

### ① GitLab — 옛 이력을 보존하고 빈 프로젝트를 만든다

새 레포는 이력이 새로 시작하므로 **옛 origin 에 그대로 밀 수 없다**(non-ff · 서버는 강제로 밀지 않는다). 권장 —

1. GitLab 에서 `dpms_wiki` 프로젝트 이름 · 경로를 `dpms_wiki_old` 로 바꾼다(옛 이력이 거기 남는다).
2. 빈 `dpms_wiki` 프로젝트를 새로 만든다(README 없이).

### ② 서버 — 옛 레포를 옆으로

```bash
sudo systemctl stop cdp-serve
sudo -u cdp mv /opt/cdp/repos/dpms_wiki /opt/cdp/repos/dpms_wiki_old
sudo -u cdp -H git -C /opt/cdp/repos/dpms_wiki_old remote set-url origin <GitLab>/<그룹>/dpms_wiki_old.git
sudo systemctl start cdp-serve
```

### ③ 새 레포 — 콘솔 「새 지식 레포」

콘솔 › 지식 레포 › [새 지식 레포] — 이름 `dpms_wiki` · **기록만 옮겨 오기** `dpms_wiki_old` · origin `<GitLab>/<그룹>/dpms_wiki.git` · 볼 수 있는 사람(옛 레포와 같게). 셸로는 —

```bash
$CTX repo new /opt/cdp/repos/dpms_wiki --records-from /opt/cdp/repos/dpms_wiki_old \
     --title "합천군 배수펌프장 통합운영관리(DPMS) 사업의 지식 레포" --origin <GitLab>/<그룹>/dpms_wiki.git --push
```

**확인** — 첫 커밋에 작업 기록 13 · 첨부 2곳 · 어휘 ≈100줄, 도구 층 0. 화면 큐레이션 › 대기열에 13건.

### ④ 기준선 — 옛 문서에서 기계로 뽑은 사실만 옮긴다

옛 문서 다섯의 「기준선」 내용만 새 레포의 깨끗한 문서로 — 테이블정의서 · 코드정의서 · 화면설계서 · 프로그램사양서(서식 문서)와
**사업분석**(발주처 계획서 HWP 를 옮긴 것 · 서식집에 맞는 서식이 없어 제목만). 큐레이터 토큰으로 —

```bash
cd /tmp
$CTX baseline extract /opt/cdp/repos/dpms_wiki_old --doc "docs/2.개발/DE_431_테이블정의서.md" --form public-si/DE_431 --src "옛 dpms_wiki 테이블정의서 — GDI 개발 DB 추출" --asof 2026-10-06 > bl-tables.json
#   코드정의서 public-si/DE_441 · 화면설계서 public-si/DE_331 · 프로그램사양서 public-si/EC_201 도 같은 모양
$CTX baseline extract /opt/cdp/repos/dpms_wiki_old --doc "docs/2.개발/AN_201_사업분석.md" --src "발주처 사업계획서(1.사업계획서(수정)260430.hwp) — HWP 본문 추출" --asof 2026-09-30 > bl-biz.json
```

**사업분석은 두 군데 손질한다** — 확인필요사항은 계획서 원문이 아니라 분석 · 회의 결정이라 큐레이터가 쓰고(블록에서 뺀다),
보안성검토요청은 계획서 원문(문의 둘 · 요구 아홉)까지만 블록이다(「해석(확정)」 은 회의 결정 — 큐레이터의 글). 등록부 행은 서식 없이 제목만 —

```bash
node -e "const f='bl-biz.json',fs=require('fs'),j=JSON.parse(fs.readFileSync(f));j.items=j.items.filter(i=>i.coord!=='사업분석:확인필요사항');const s=j.items.find(i=>i.coord==='사업분석:보안성검토요청');s.body=s.body.slice(0,s.body.indexOf('**해석(확정)**')).trimEnd();j.vocab=j.vocab.filter(v=>v.coord!=='사업분석:확인필요사항');j.managed=[{op:'add',pattern:'사업분석:*',doc:'docs/사업분석.md',title:'사업분석'}];fs.writeFileSync(f,JSON.stringify(j,null,2))"
export CDP_TOKEN=<큐레이터 토큰>
for f in bl-tables bl-codes bl-screens bl-progs bl-biz; do node /opt/cdp/bin/ctx.mjs baseline push $f.json --server http://<서버 IP>:7374 --repo dpms_wiki; done
```

> **서버 판이 v1.0.0 이면 사업분석은 개발 PC 에서 뽑는다** — v1.0.0 의 `baseline extract` 는 옛 이력 한 줄(`**신설** · …`)을 걷지 못하고
> 본문 그림 링크를 옛 자리(`../../work/assets/…`)로 둔다(main 29dd170 에서 고쳤다). 옛 레포 사본(GitLab `dpms_wiki_old` clone)에서
> main 의 `ctx baseline extract` 로 뽑아 위처럼 `push --server` 로 올린다. 넷(테이블 · 코드 · 화면 · 프로그램)은 그런 줄이 없어 v1.0.0 으로도 같다.

리허설 값(2026-10-08 · 최종 코드) — 기준선 블록 테이블 29 · 코드 6 · 화면 20 · 프로그램 3 · 사업분석 11.
