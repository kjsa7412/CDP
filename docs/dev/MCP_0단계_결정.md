## 만들되 이번엔 검증되지 않는 것

**레포가 하나라 §2.9 다중 레포가 실전에서 돌지 않는다.** 그래도 **만든다** —

- `repo?` 인자 · 출력의 `repo` 필드 · `repos` 도구 · `E_REPO`
- `cdp://{repo}/…` 리소스 URI
- 레포별 캐시(§2.6)
- 뷰어의 `/api/<repo>/…` · `/r/<repo>/…` 경로

나중에 `dpms` 를 붙일 때 **서버 `<root>` 에 폴더만 두면 되게** 하려면 지금 넣어야 한다.
빼고 갔다가 나중에 넣으면 도구 12개 · 리소스 · 뷰어 경로를 전부 다시 만진다.

대신 화면에서는 §6.6.2 대로 **레포가 하나면 전환 UI 를 내지 않는다.** 만들어 두고 숨긴다.

URL 은 `POST /mcp/gdi`(고정)를 쓴다 — 레포 하나면 이쪽이 단순하고, 기본 레포가 URL 에서
정해져 `E_REPO` 가 날 자리가 없다(§4.3).

검증 항목 중 다음은 **레포 둘을 임시로 만들어** 돌린다(§10). 실운영은 하나여도 코드는
둘을 다뤄야 한다.

```
□ 두 레포에 같은 좌표가 있을 때 match 가 둘 다 낸다
□ 기본 레포가 없는 서버에서 repo 생략 → E_REPO
□ repos 가 권한 밖 레포를 내지 않는다
□ 레포를 바꾸면 화면 상태가 초기화된다
```

## 명부 초안

2~5명이므로 `auth.json` 한 파일로 간다. 실명과 권한은 서버를 세울 때(4.2단계) 채운다.

```json
{
  "users": [
    { "name": "kjsa", "label": "사경진 · 개발", "active": true, "repos": ["*"], "write": true }
  ],
  "tokens": []
}
```

- [ ] 나머지 1~4명의 `name` · `label` · `repos` · `write` 를 정한다
- [ ] **`write` 를 누구까지 줄지**가 실제 결정이다 — `save` 가 커밋을 만든다(§4.5)
- [ ] `repos` 는 당분간 전원 `["gdi"]` 또는 `["*"]` — 레포가 하나라 차이가 없다.
      `dpms` 가 붙는 순간 갈린다
