### 4.1 전송 · 레포 저장소

- [x] `viewer/bin/ctx-mcp-serve.mjs` · Streamable HTTP · **stateless**(§4.3 · §7)
- [x] `POST /mcp`(레포 미고정) · `POST /mcp/<name>`(고정) · GET·DELETE 405
- [x] `<root>/<name>/` 스캔 · 폴더 목록 60초 갱신 · 재시작 없이 인식(§4.2)
- [x] `GET /healthz` — **레포 이름을 싣지 않는다.** 집계까지(§4.3)

- [x] 요청 본문 상한 2MB → 초과 413 · `X-Forwarded-For` 는 로그용만
- [x] `--bind` 기본 루프백 · `0.0.0.0` 이면 시작 시 stderr 경고
- [x] `serve.log` 회전 3×1MB — 본문 · 검색어 안 남김(§2.8)

**4.1 에서 나온 것**

| | |
|---|---|
| SDK 가 해 준 것 | `createMcpHandler(factory, { legacy: 'stateless' })` 가 `{ fetch }` 를 준다. **GET·DELETE 405 는 SDK 가 이미 낸다** — 직접 짤 것이 없었다. 팩토리는 `requestInfo.url` 과 `headers` 를 받아 레포 경로와 토큰을 거기서 꺼낸다 |
| 직접 이어야 했던 것 | 팩토리는 SDK 가 부르므로 **요청별 인증 결과와 레포 목록을 실을 자리가 없다.** 전역은 동시 요청이 서로 덮는다 → `AsyncLocalStorage` |
| 413 이 까다로웠다 | ① 넘는 순간 `destroy` 하면 "other side closed" 로 보여 거절인지 죽음인지 구별이 안 된다 ② 큰 몸통은 `Expect: 100-continue` 를 먼저 보내고 그때는 `request` 가 아니라 `checkContinue` 가 난다. **`content-length` 로 미리 끊는 것**이 둘 다의 답이다 |

| 모드를 묻지 않는다 | §6.8 은 `GET /api/mode` 로 판정한다고 했는데, **주소가 이미 말해 준다** — 화면이 `/r/<repo>/` 로 서빙되므로 `location.pathname` 한 줄이면 된다. 왕복이 없어지고 라우트도 안 는다. 대신 껍데기가 한 번에 필요한 것(`user` · 볼 수 있는 레포)을 `GET /me` 하나로 |
| 전환 = 주소 이동 | `location.href = '/r/<name>/'`. **화면 상태 초기화가 저절로 된다**(§6.6.2) — 지울 것을 열거하지 않아도 된다 |
| ⌘K 도 저절로 | 모든 호출이 `/api/<repo>` 를 기준으로 하므로 다른 레포의 좌표가 나올 길이 없다 |
| 잡은 버그 둘 | ① 자산(`/assets/…`)이 인증 뒤에 있어 401 → 화면이 통째로 안 떴다. 빌드 산출물이라 숨길 것이 없으므로 **인증 앞**으로 ② `read-api` 의 MIME 표에 `.js` 가 없어 `application/octet-stream` — 브라우저가 모듈 실행을 거부한다 |
| SSE · 하트비트 | 서버 모드에서 끈다. 하트비트는 **탭이 닫히면 서버를 끄는** 장치라, 상주 서버에서 보내면 남의 화면까지 끈다 |

**끝났다고 보는 기준** — 브라우저로 실측. 로그인 화면 → 토큰 → `/r/alpha/` 에 화면이
그대로 뜬다 · 전환 메뉴에서 `beta` 로 가면 주소와 제목이 바뀐다 · 관리 메뉴가
**5개 → 3개**(지식 레포 · 작업 레포 빠짐) · 동기화 버튼 없음 · `kjsa` 와 로그아웃 ·
**레포 하나인 `qa` 로 들어가면 전환 UI 가 안 나온다** · 로컬 뷰어는 5개 · 전환 메뉴
없음 · 동기화 버튼 있음 — **그대로다**

### 6.3 설치 관리 (§6.7)

**브라우저는 사용자 PC 에 파일을 못 쓴다.** 관리 서비스가 맡는 것은 설치 행위가 아니라
등록 · 꾸러미 발급 · 결과 추적이다(§6.7.1).

- [x] 설치 대장 `<data>/workrepos.json` — `{ id, name, knowledge, owner, applied }`(§6.7.2)
- [x] `GET · POST /workrepos` — `owner` 가 **명부에 없으면 `E_INPUT`**(§4.4 의 `users[]`)
- [x] `GET /kit/<name>?workrepo=<id>` — kit + 그 레포용 `.mcp.json` · `cdp.json` · `설치.md` 를 **그 자리에서 조립**
- [x] **꾸러미에 토큰을 넣지 않는다** · 화면에도 내지 않는다(§4.4.1 — HTTP 발급 경로를 만들면 안 된다)
- [x] `POST /workrepos/<id>/applied` — `{ kit }` 만 받고 `at` · `by` 는 토큰에서 채운다
- [x] 관리 > 작업 레포 화면 — 목록(최신 · 낡음 · 미설치) · `[+ 등록]` · `[설치 방법]` 패널(§6.7.3)
- [x] `ctx setup` 이 `CLAUDE.md` 블록에 `<!-- cdp:kit <hash> -->` 를 박는다(§6.7.4)
- [x] `sync` 도구 출력에 `kit: { hash, skills }` · 스킬이 `cdp:kit` 과 비교해 답에 적는다(§2.2)
- [x] `ctx setup --server --check` — 받지 않고 비교만. `inspect()` 는 로컬 전제라 못 쓴다(§4.7)
- [x] **보고는 관문이 아니다** — 보고 없이도 설치는 된다. 대장만 미설치로 남는다

**6.3 에서 나온 것**

| | |
|---|---|
| §6.7.1 이 실제로 성립한다 | **`bin/ctx` 없이 zip 만 풀어도 연결된다.** 꾸러미를 손으로 풀고 그 `.mcp.json` 으로 붙여 `sync` 를 불러 확인했다 — 설치 부트스트랩이 사라진다 |

| 비교의 한쪽을 들고 오게 | 서버는 클라이언트의 `.claude/skills` 를 볼 수 없다. `kitHash()`·`inspect()` 가 로컬 지식 레포 전제라 그대로는 못 쓴다 — `CLAUDE.md` 블록 첫 줄에 해시를 박는 것이 그 답이다 |

`E_INPUT` · 등록/목록/삭제 · `by` 를 보내면 `E_INPUT` · 없는 등록에 보고 404 ·

`설치.md`) · **손으로 풀어 연결까지** · 서버 kit 을 고치면 세 곳 모두 `낡음` ·
화면에 4단계와 내려받기 링크 · **로컬 뷰어는 메뉴 5개 · 로컬판 그대로**

## 하지 않는 것

여기 적힌 것을 구현 중에 "겸사겸사" 넣지 않는다. 넣어야 하면 **설계서를 먼저 고친다.**

| | 왜 |
|---|---|
| 레포 간 조인 | 어휘 · 등록부 · 파생 규칙이 레포마다 다르다. 섞으면 판정 근거가 무너진다(§0) |
| 뷰어에서 편집 | 작성자가 둘이 된다. 쓰기는 `save` 하나(§6.5) |
| 뷰어의 코멘트 · 알림 · 구독 | git 밖 상태가 생긴다 — "명부뿐"이 깨지고 DB 가 따라온다(§6.6.4) |
| OAuth 서버 | 범위 밖(§0). 사람이 수십 명을 넘으면 그때 프록시 앞단에 |
| 문서별 권한 | 범위 밖(§0). 권한 단위는 레포다 |

**미검증으로 남기는 것** — claude.ai 커넥터에 정적 Bearer 가 받아들여지는가(§5.3).
공개 HTTPS 가 필요하고 UI 가 버전마다 다르다. 4단계 뒤에 한 번 찔러 보고 결과만 적는다.

## 왜 이 순서인가

```
0 전제 ──▶ 1 코어(관문) ──┬──▶ 2 모드 A ──▶ 3 스킬
                          │
                          └──▶ 4 모드 B ──┬──▶ 5 설치 ──▶ 7 폐쇄망
                                          └──▶ 6 뷰어
                                                        ──▶ 8 검증
```

- **1 이 관문이다.** 도구 · 명함 · 판정은 두 모드가 같다(§1). 전송보다 먼저 굳힌다.
- **2 를 4 보다 먼저** — 인증 · HTTP 없이 명함과 재스캔을 턴다. 여기서 놓친 것은 4 에서 두 배다.
- **4.2 를 4.3 보다 먼저** — `save` 가 명부에 의존한다.
- **6 은 4 뒤에만** — 뷰어가 `ctx serve` 의 레포 캐시에 얹힌다. 반대는 아니다.
- **3 은 2 뒤 언제든** — 다만 모드 B 문장이 5 에서 한 줄 더 붙는다.

모드 A 만 쓸 계획이면 **0 → 1 → 2 → 3 → 7** 에서 멈춘다. 4 · 5 · 6 은 서버를 세울 때 시작한다.
