## 1. `ctx-mcp` 코어 — 도구 12종 (관문)

**두 모드가 공유하는 것 전부가 여기 있다. 전송은 아직 없다.** 이 단계가 끝나면 모드 A 와 B 는
전송을 갈아끼우는 일만 남는다. 먼저 손대고 싶은 `ctx mcp` 를 2단계로 미룬 이유다.

- [ ] `core/` 승격 — 섹션 범위 잘라내기(`section`) · 작업 기록 파싱(`work`). 뷰어가 쓰던 것을 끌어올린다
- [ ] `viewer/bin/ctx-mcp.mjs` 신설 — `buildServer({ repos, fallback, mode, prompts, user, allow })` (부록 A)
- [ ] 레포 캐시 — 레포마다 하나 · 스탬프 재스캔 · 객체 통째 교체 · 감시 안 씀(§2.6)
- [ ] 도구 12종 등록 · 명함 문구를 §2.2 표에서 그대로 옮긴다 (**요약하지 않는다**)
- [ ] `repo?` 인자를 전 도구에 · 출력에 `repo` 필드 · 기본 레포 없으면 `E_REPO`(§2.9)
- [ ] `match` 만 레포를 가로지른다 · 결과마다 `repo` · 두 레포에 다 있으면 둘 다 보고(§2.9)
- [ ] `repos` 도구 — `allow` 로 거른다
- [ ] **레포는 실운영 하나지만 코드는 N 개를 다룬다**(0단계 결정). 검증은 임시 레포 둘로 돌린다
- [ ] 결과 형식 `content[]` + `structuredContent` · 오류 코드 9종(§2.3)
- [ ] 입력 검증 — `coord` 정규식 · `id` 정규식 · `..` 거부 · `path.resolve` 후 `root` 접두 검사(§2.7)
- [ ] 리소스 — `cdp://{repo}/…` 템플릿 둘 + 정적. 레포 6개 이상이면 `doc` 만 템플릿(§2.4)
- [ ] `prompts` — `load` · `brief`. 절차 문장은 **스킬 파일을 읽어서** 낸다(§2.5)
- [ ] 응답 상한 512KB — 넘으면 `E_INPUT` 로 `cdp://doc` 안내(§8)

**끝났다고 보는 기준** — `where · match · derive · check · brief · version` 의 결과가
`ctx <명령> --json` 과 **바이트까지 같다**(§10).

## 4. 모드 B — 서버

### 4.1 전송 · 레포 저장소

- [ ] `viewer/bin/ctx-mcp-serve.mjs` · Streamable HTTP · **stateless**(§4.3 · §7)
- [ ] `POST /mcp`(레포 미고정) · `POST /mcp/<name>`(고정) · GET·DELETE 405
- [ ] `<root>/<name>/` 스캔 · 폴더 목록 60초 갱신 · 재시작 없이 인식(§4.2)
- [ ] `GET /healthz` — **레포 이름을 싣지 않는다.** 집계까지(§4.3)
- [ ] `GET /repos` — 권한 안의 레포 + `mirror` · `head`
- [ ] 요청 본문 상한 2MB → 초과 413 · `X-Forwarded-For` 는 로그용만
- [ ] `--bind` 기본 루프백 · `0.0.0.0` 이면 시작 시 stderr 경고
- [ ] `serve.log` 회전 3×1MB — 본문 · 검색어 안 남김(§2.8)

### 4.2 명부 · 인증 — `save` 보다 먼저

**`save` 가 `users[].write` 에 의존한다.** 순서를 바꾸면 권한 판정을 두 번 짠다.

- [ ] `auth.json` = `users[]` + `tokens[]`. **권한은 `users[]` 에만**(§4.4)
- [ ] 판정 5단계 — 토큰 조회 → 만료 → 명부 조회(**고아 토큰 401**) → `active` → `repos`·`write`
- [ ] `serve user add|set|list` · `list --repo <name>` 이 "이 레포를 볼 사람 전원"에 답한다(§4.4.0)
- [ ] `serve token --user` 가 **명부에 없는 이름을 거부**한다(`E_INPUT`)
- [ ] `--expires` **기본 90일** · `never` 는 명시해야 붙는다 · 만료 7일 전 `brief` 경고(§4.4.2)
- [ ] `serve token list` · `revoke` · `<data>/logs/auth.log`(명부 변경 포함 · 원문 없음)
- [ ] 마지막 사용은 `serve.log` 집계 — `auth.json` 을 매 요청 쓰지 않는다
- [ ] `auth.json` 0600 · 토큰 해시만 저장

### 4.3 `save`

- [ ] `repo` **필수**(§2.9) · 레포 뮤텍스로 직렬화(§2.6)
- [ ] 처리 0~11 순서대로(§4.5) — 권한 → 스키마 → 존재 → 어휘 → 좌표 → 섹션 → 기록 → 검사 → 인덱스 → 커밋 → 미러
- [ ] `applied` 불일치 → `E_CONFLICT { coord, expected, current }`
- [ ] `runBuiltinCheck` 오류 → **파일 복원 후** `E_CHECK` · 커밋 0
- [ ] `author` 는 `users[].name` 으로 서버가 채운다 · 클라이언트 값은 `E_INPUT`
- [ ] 기존 `work/*.md` 수정·삭제 없음 · 어휘 삭제 없음 · `_managed.md` 안 건드림

### 4.4 미러 · 배포

- [ ] **서버가 `10.10.20.250:2900` 에 닿는지 먼저 확인한다** — 안 닿으면 `--mirror` 가 계속 `lag`(0단계 결정)
- [ ] 서버에는 `C:\cdp` 를 옮기지 않고 **새로 clone** 한다 — 서버가 유일한 작성자다(§4.2)
- [ ] `--mirror` 비동기 push · 실패는 로그 + `sync.mirror = lag`
- [ ] LaunchAgent / systemd · Caddy 또는 Cloudflare Tunnel(§9.4)
- [ ] 운영 항목 등록 — `/healthz` 감시 · 로그 회전 · 분기 토큰 회전 · 디스크 스냅샷

## 6. 관리 서비스

**4단계가 서야 붙는다.** 의존은 한 방향이고, 먼저 만들어도 얹힐 데가 없다.
"뷰어"가 아니라 **관리 서비스**다 — 읽기 · 레포 전환 · 작업 레포 설치 관리까지 한다(§6.1).

### 6.1 서버

- [ ] `/api/<repo>/…` 로 경로 조각 · 레포 캐시를 MCP 와 **공유**(§6.3)
- [ ] 로컬 전용 라우트 **404** — `/repo`(POST) · `/git/hooks` · `/git/pull|push` · `/open` · `/quit` · `/rescan`(§6.2)
- [ ] `/setup` · `/workrepos` 는 404 가 아니라 **다시 정의한다**(§6.2 셋째 줄 · §6.7)
- [ ] `GET·POST /login` · `GET /r/<repo>/…`(같은 정적 파일) · `GET /` → 기본 레포로
- [ ] **서명 쿠키** — `HttpOnly` · `Secure` · `SameSite=Lax` · 12시간 · `<data>/secret` 0600(§6.4)
- [ ] 쿠키 검증이 §4.4 의 3~5 단계를 탄다 — `active:false` 가 **열린 화면도** 끊는다
- [ ] `security.js` 를 원격용으로 새로 — **`Host` 검증은 여기서 안 먹는다.** `Origin` 검사 + 쓰기에 CSRF 토큰(§6.4)

### 6.2 화면

- [ ] 로그인 — **입력 한 칸**(아이디 없음) · 마스킹 + 보기 · 실패 문구 **하나로**(구분은 로그에만)(§6.6.1)
- [ ] 로그인 후 원래 경로 복귀 · 401 이면 보던 경로를 들고 `/login`
- [ ] `repos` 가 빈 사용자 — 로그인은 되고 "볼 수 있는 레포가 없다" 화면(401 아님)
- [ ] 레포 전환 — 토프바 이름표가 메뉴로 · `GET /repos` · **권한 밖은 회색으로도 없다**(§6.6.2)
- [ ] 전환하면 문서 · 그래프 뿌리 · 찾기 결과 **초기화** · ⌘K 는 현재 레포 안에서만
- [ ] 레포 하나면 전환 UI 를 내지 않는다
- [ ] 관리 메뉴 분기 — 지식 레포 ✗ · 작업 레포 ✗ · 동기화 읽기만 · 진단 일부(§6.6.3)
- [ ] `loopback 아님` 경고 제거 · 그 자리에 `user` · 로그아웃
- [ ] `firstRun` 분기 없음 — 로그인 뒤 바로 문서

### 6.3 설치 관리 (§6.7)

**브라우저는 사용자 PC 에 파일을 못 쓴다.** 관리 서비스가 맡는 것은 설치 행위가 아니라
등록 · 꾸러미 발급 · 결과 추적이다(§6.7.1).

- [ ] 설치 대장 `<data>/workrepos.json` — `{ id, name, knowledge, owner, applied }`(§6.7.2)
- [ ] `GET · POST /workrepos` — `owner` 가 **명부에 없으면 `E_INPUT`**(§4.4 의 `users[]`)
- [ ] `GET /kit/<name>?workrepo=<id>` — kit + 그 레포용 `.mcp.json` · `cdp.json` · `설치.md` 를 **그 자리에서 조립**
- [ ] **꾸러미에 토큰을 넣지 않는다** · 화면에도 내지 않는다(§4.4.1 — HTTP 발급 경로를 만들면 안 된다)
- [ ] `POST /workrepos/<id>/applied` — `{ kit }` 만 받고 `at` · `by` 는 토큰에서 채운다
- [ ] 관리 > 작업 레포 화면 — 목록(최신 · 낡음 · 미설치) · `[+ 등록]` · `[설치 방법]` 패널(§6.7.3)
- [ ] `ctx setup` 이 `CLAUDE.md` 블록에 `<!-- cdp:kit <hash> -->` 를 박는다(§6.7.4)
- [ ] `sync` 도구 출력에 `kit: { hash, skills }` · 스킬이 `cdp:kit` 과 비교해 답에 적는다(§2.2)
- [ ] `ctx setup --server --check` — 받지 않고 비교만. `inspect()` 는 로컬 전제라 못 쓴다(§4.7)
- [ ] **보고는 관문이 아니다** — 보고 없이도 설치는 된다. 대장만 미설치로 남는다

## 7. 폐쇄망 실측 ⏸ — 이번 범위 밖

0단계에서 **일반망**으로 확정됐다. 지우지 않고 둔다 — 폐쇄망 반입이 생기면 그대로 살아난다.

- [ ] ⏸ 인터넷이 끊긴 PC 에서 반입 묶음만으로 설치 → 연결까지 (`npm` · 다운로드 **0회**)
- [ ] ⏸ Node 없는 PC — shim → `cdp.exe ctx mcp` 로 stdio 가 열린다
- [ ] ⏸ git 원격이 없는 레포 — `sync` 가 `remote: null` 로 답하고 죽지 않는다
- [ ] `version.built` 90일 경과 → `brief` 경고 줄  ← **이것만 살린다**(일반망에서도 번들은 낡는다)

## 하지 않는 것

여기 적힌 것을 구현 중에 "겸사겸사" 넣지 않는다. 넣어야 하면 **설계서를 먼저 고친다.**

| | 왜 |
|---|---|
| 레포 간 조인 | 어휘 · 등록부 · 파생 규칙이 레포마다 다르다. 섞으면 판정 근거가 무너진다(§0) |
| 뷰어에서 편집 | 작성자가 둘이 된다. 쓰기는 `save` 하나(§6.5) |
| 뷰어의 코멘트 · 알림 · 구독 | git 밖 상태가 생긴다 — "명부뿐"이 깨지고 DB 가 따라온다(§6.6.4) |
| OAuth 서버 | 범위 밖(§0). 사람이 수십 명을 넘으면 그때 프록시 앞단에 |
| 문서별 권한 | 범위 밖(§0). 권한 단위는 레포다 |

**미검증으로 남기는 것** — claude.ai 커넥터에 정적 Bearer 가 받아들여지는가(§5.3).
공개 HTTPS 가 필요하고 UI 가 버전마다 다르다. 4단계 뒤에 한 번 찔러 보고 결과만 적는다.

## 왜 이 순서인가

```
0 전제 ──▶ 1 코어(관문) ──┬──▶ 2 모드 A ──▶ 3 스킬
                          │
                          └──▶ 4 모드 B ──┬──▶ 5 설치 ──▶ 7 폐쇄망
                                          └──▶ 6 뷰어
                                                        ──▶ 8 검증
```

- **1 이 관문이다.** 도구 · 명함 · 판정은 두 모드가 같다(§1). 전송보다 먼저 굳힌다.
- **2 를 4 보다 먼저** — 인증 · HTTP 없이 명함과 재스캔을 턴다. 여기서 놓친 것은 4 에서 두 배다.
- **4.2 를 4.3 보다 먼저** — `save` 가 명부에 의존한다.
- **6 은 4 뒤에만** — 뷰어가 `ctx serve` 의 레포 캐시에 얹힌다. 반대는 아니다.
- **3 은 2 뒤 언제든** — 다만 모드 B 문장이 5 에서 한 줄 더 붙는다.

모드 A 만 쓸 계획이면 **0 → 1 → 2 → 3 → 7** 에서 멈춘다. 4 · 5 · 6 은 서버를 세울 때 시작한다.
