## 2. 서버 — 이벤트 루프가 멈춘다

node 는 한 줄로 돈다. 그 줄이 무엇을 붙잡고 있으면 **모든 요청이 기다린다** —
문서 하나 여는 것도, 검색 한 글자도.

### 2.1 git 프로세스를 띄우는 것 자체가 멈춤이다 — **가장 컸다**

`--cpu-prof` 에서 `load()` 4회의 자체 시간 1위가 `ChildProcess.spawn` **2,062ms** 였다.
Windows 에서 프로세스 생성은 node 의 메인 스레드에서 동기로 일어난다 — 실측 한 개에 80ms 남짓.

`git.status()` 한 번이 git 을 **5~7개** 띄웠다(rev-parse 셋 · status · config · rev-list · log).
그리고 이것이 불리는 곳 —

| 언제 | 몇 번 |
|---|---|
| 파일이 하나 바뀔 때마다(감시 → 재스캔 → `load()`) | 1 |
| 창에 포커스가 올 때마다(상태바 `local()` · `remote()`) | 2 |
| 동기화 · pull · push | 1~2 |

에디터와 뷰어를 오가는 것이 이 도구의 일상이므로, **창으로 돌아와 누르는 순간** 서버는
0.5~1초 동안 git 을 띄우고 있었다. 사람이 느끼는 것은 "눌렀는데 한 박자 늦게 열린다" 다.

### 2.2 전문 색인을 매번 새로 지었다

MiniSearch 의 색인은 기수 트리이고 낱말을 넣을 때마다 **노드의 자식을 처음부터 훑는다.**
한글 바이그램은 첫 글자가 음절이라 뿌리 자식이 수백 갈래가 된다 — 관리문서 패키지
하나(13만 자)에서 **718개**, 등장 6만 번마다 그것을 훑었다. 한 번 짓는 데 100~700ms.

그것을 `load()` 가 **매번** 지었다. 그런데 전문 검색은 이름에서 못 찾았을 때만 도는
폴백이다. `ctx search` 와 MCP `search` 는 부를 때마다 지었다(관리 서비스에서는 그동안
모든 사용자의 요청이 멈춘다).

### 2.3 원격이 안 닿을 때 fetch 가 겹겹이 뜬다

포커스마다 `/api/git?fetch=1` 이 갔다. 원격이 안 닿으면 한 번에 21초(TCP 연결 제한 ·
실측)인데, 그 사이 창을 몇 번 오가면 fetch 가 여러 개 겹쳐 떴다(앱 안 브라우저 실측
11개 동시). 요청마다 브라우저 연결을 하나씩 물고 있고, Chrome 은 HTTP/1.1 에서
호스트당 여섯 개다(하나는 SSE). **다 차면 문서 여는 요청도 줄을 선다.** 겹친 fetch 는
같은 `.git` 을 두고 잠금을 다툰다.

## 3. 화면 — 큰 문서 한 장이 통째로 멈춘다

테이블정의서(표 292 · DOM 노드 4만 6천)를 여는 데 **long task 2~4초.** `Profiler` 로 쪼갠 것 —

| 자리 | 시간 | 무엇 |
|---|---:|---|
| 첫 레이아웃 | ~465ms | `useLayoutEffect` 의 `scrollTop = 0` 이 표 292개 전부의 레이아웃을 그 자리에서 강제한다 |
| 렌더 + 살균 | ~283ms | 그중 DOMPurify 248ms. **같은 문서를 다시 열어도 매번** |
| HTML 파싱 | ~100ms | React 의 `innerHTML` |
| 좌표 링크 | ~70ms | 글자 노드 3만 개마다 부모를 뿌리까지 거슬러 올라가 확인 |
| (그 밖의 브라우저 일) | 수백 ms | 스타일 · 레이아웃 · 페인트 |

**레이아웃 한 번이 문서 전체를 다시 잰다.** 전체 레이아웃 한 번이 ~300ms 였고, 목차의
현재 표시(`data-current`) 하나만 바꿔도 ~30ms 가 걸렸다(표를 숨기면 2ms). 그래서 —

- 목차 접기·펴기 0.2초
- 스크롤하다 **섹션 경계를 넘을 때마다** 목차 갱신 + `scrollIntoView`(조상 스크롤 전부를
  건드리고 레이아웃을 강제한다)로 한 번씩 걸림
- 그래프에서 문서로 돌아오기 3~7초(문서를 처음부터 다시 렌더)

그래프는 누를 때마다 배치를 새로 풀었다 — 좌표 300개 O(N²)·140틱, 0.4~1초.

## 4. 무엇을 고쳤나

| # | 자리 | 고친 것 |
|---|---|---|
| S1 | `core/git.js` | `status()` 가 git 을 **한 번만** 띄운다 — `status --porcelain=v2 --branch` 한 줄이 브랜치·upstream·앞섬/뒤처짐·HEAD·변경 수를 다 낸다. `core.hooksPath` 는 설정 파일 시각이 바뀔 때만 묻는다. 앞선 커밋이 있을 때만 `log` 하나 더. **옛 결과와 필드까지 같다**(빈 레포 · 떨어진 HEAD · 앞섬/뒤처짐 · 변경 · 레포 아님) |
| S2 | `core/search.js` | MiniSearch 를 걷고 `Map` 색인으로. **점수 규칙은 그대로 옮겼다**(BM25+ · 접두 가중 · AND · 필드 가중) — 실레포 넷 · 질의 24개에서 경로와 점수가 같다(동점끼리 순서만 다름). 의존성 하나가 빠졌다 |
| S3 | `core/store.js` | 전문 색인을 `load()` 에서 짓지 않는다 — **쓸 때 짓는다** |
| S4 | `core/store.js` | fetch 는 **한 번에 하나** · 방금(60초) 했으면 다시 안 한다 · 돌고 있으면 기다리지 않고 로컬 상태를 돌려준다. 사람이 누르는 동기화(`/sync`)는 이것을 거치지 않는다 |
| C1 | `doc.css` | 본문의 표와 코드 블록에 `content-visibility: auto` — **화면 근처에 온 것만 잰다.** 인쇄에서는 끈다 |
| C2 | `markdown.js` | 렌더 결과를 원문을 키로 8장 기억한다 |
| C3 | `markdown.js` | 좌표 링크 — 건너뛸 요소에서 가지째 돌아선다(부모 거슬러 오르기 없음) |
| C4 | `SectionRail.jsx` | 현재 섹션은 한 프레임에 한 번 · 제목 노드는 문서마다 한 번 찾는다 · `scrollIntoView` 대신 목차 목록만 옮긴다 · `memo` |
| C5 | `SectionRail` · `DocView` | 섹션 이동은 컨테이너를 직접 옮기고 두 프레임 뒤 한 번 더 맞춘다 — 어림 높이로 선 표가 그려지며 제목이 밀릴 수 있어서다. **목차 이동이 부드러운 스크롤에서 즉시 이동으로 바뀌었다**(도중에 표가 그려지며 목표가 움직인다) |
| C6 | `DocView.jsx` | 진행률은 한 프레임에 한 번 |
| C7 | `CoordGraph.jsx` | 배치를 컴포넌트 밖에 기억한다 — 같은 레포 상태면 같은 배치(난수 씨앗 고정) |
| C8 | `StatusBar.jsx` | 포커스로 git 을 묻는 것은 15초에 한 번 |

**살균은 빼지 않았다.** 뷰어 설계서 v0.2 가 *"로컬이라고 렌더 전 살균을 빼지 않는다"* 로
정했다 — 대신 C2 로 한 번만 한다.

## 5. 얼마나 나아졌나

같은 레포 · 같은 기계 · 운영 빌드(minify). **long task 합**(ms, 두 번 잰 것).

| 행동 | 전 | 후 |
|---|---:|---:|
| 테이블정의서 열기 | 1,992 · 3,830 | **318 · 284** |
| 화면설계서 열기 | 282 · 727 | 88 · 59 |
| 그래프로 | 1,055 | 292 · **103**(두 번째부터 배치 재사용) |
| 그래프에서 문서로 | 7,309 | **481 · 269** |

서버(같은 레포, `load()` 네 번):

| | 전 | 후 |
|---|---:|---:|
| 이벤트 루프 최장 정지 | 251 · 267 · 304 · 644 ms | **25 · 22 · 21 · 21 ms** |
| `git.status()` 한 번 | 220~380 ms · 프로세스 5~7 | 73~180 ms · 프로세스 1~2 |
| 전문 색인 짓기 | 65~141 ms(식은 때 ~700) · **load 마다** | 16~31 ms · **쓸 때 한 번** |
| 동시 fetch 6건 | 6개가 각자 21초 | 1개만 돌고 나머지는 ~1초에 답 |

확인 — `npm test` 77 · `npm run verify` ✓ 60 ✗ 0 · `check:packages` ok ·
목차 이동이 제목에 닿는다(5곳 모두 12px) · 휠 스크롤 뒤 현재 섹션이 맞다 · 인쇄에서 표가 다 그려진다.

## 6. 남은 것 — 고치지 않은 자리

| | 왜 남겼나 |
|---|---|
| 큰 문서 첫 열기 ~0.3초 | 살균(DOMPurify)이 그 대부분이다. 빼지 않기로 한 것이다. 두 번째부터는 C2 로 없다 |
| 좌표 정규식 | 어휘 900 낱말을 한 정규식으로 건다. 지금은 30ms 안이다 — 좌표가 수천이 되면 다시 본다 |
| 스크롤 멈출 때 앱 전체가 다시 그려진다 | 읽던 위치 저장(`patch`)이 앱 상태를 바꾼다. 측정에서 long task 가 없어 두었다 |
| `/api/docs/:id` 가 본문을 두 번 싣는다(`text` · `raw`) | 1MB 문서면 2MB. 파싱이 수 ms 라 두었다 |
