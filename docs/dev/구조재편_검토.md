# 구조 재편 검토 — `viewer` · `agent` · `ops` · `docs`
> **v1.0 이후** — 폴더의 지금은 [`CDP_시스템설계서_v2.0.md`](../design/CDP_시스템설계서_v2.0.md) §4(모듈 배치) — `agent/packages/` 와 `viewer/server/` 의 로컬 뷰어는 없다.

2026-09-14 · 제안: 상위 폴더를 넷으로 두고 현재 파일을 하위에 배치한다

> **실행됐다 (2026-09-14).** 아래 §5 넓은 읽기대로 옮겼고, 산출물(`out/`
> `release/`)도 `ops/` 아래로 내렸다. **루트에 남은 폴더는 넷 + `node_modules/`
> 뿐이다** — 그 하나는 못 옮긴다(§9). 설계서 §2.8 에 정정을 남겼다.

## 0. 한 줄

**제안은 성립한다 — 단, `agent` 를 어떻게 읽느냐에 따라 갈린다.**

| 읽기 | 결과 |
|---|---|
| **좁게** — `kit/agent/` 만 올린다 | **다섯이 갈 곳을 잃고**, 2026-09-08 에 고친 문제가 되돌아온다 |
| **넓게** — `kit/` 전체를 `agent/` 로 | **깨끗하게 넷이 된다.** 남는 문제는 이름뿐이다 |

권고는 **넓은 읽기**다. §6.

## 1. 지금 무엇이 있나

| 폴더 | 추적 | 무엇 | 받는 사람에게 가나 |
|---|--:|---|:--:|
| `viewer/` | 42 | 뷰어 프로그램 · `ctx` 소스 | 빌드 산출물만 |
| `kit/` | 16 | agent · hooks · manual · install.md | **간다** |
| `ops/` | 14 | 사람이 실행하는 `.cmd` 와 그 구현 | 아니다 |
| `docs/` | 50 | design · dev · 이관 · 관리문서패키지 | `design/` 만 |
| `packages/` | 53 | 문서 골격 · 등록부 · 어휘 | **간다** |
| `sample-repo/` | 56 | **뷰어 개발용 fixture** | 아니다(방금 뺐다) |
| `attic/` | 4 | 한 번 돌고 끝난 스크립트 | 아니다 |

**추적되는 상위 폴더가 일곱이다.** 줄일 값이 있다는 판단에 동의한다.

### 지금 구조의 판정 기준

`kit/README.md` 가 명시한다 — **"받는 사람에게 가는가."**
도구를 만드는 사람만 보는 것은 `docs/` 에 있다.

## 2. 제안을 **좁게** 적용하면 — 다섯이 뜬다

| 현재 | → | 판정 |
|---|---|---|
| `viewer/` | `viewer/` | ✔ |
| `ops/` | `ops/` | ✔ |
| `docs/` | `docs/` | ✔ |
| `kit/agent/` | `agent/` | ✔ 이름이 맞다 |
| `kit/hooks/pre-commit` | ? | **에이전트가 아니다.** git 이 부른다 |
| `kit/manual/` | ? | 문서인데 **받는 사람에게 간다** |
| `kit/install.md` | ? | 같은 문제 |
| `packages/` | ? | 넷 중 어디도 아니다 |
| `sample-repo/` | ? | 뷰어 fixture 니까 `viewer/` 밑? |
| `attic/` | ? | 넷 중 어디도 아니다 |

### `pre-commit` 이 `agent/` 에 못 가는 이유

설계서 불변조건 5 — **"결정론적 보증은 git 훅뿐"**. 그 이유가
*"LLM 선의에 의존하는 층이 생긴다"* 이다. 훅은 **에이전트를 못 믿어서 두는
층**이라 좁은 뜻의 `agent/` 와는 반대편에 선다.

### `manual/` 을 `docs/` 로 보내면 안 되는 이유

그러면 `docs/` 안에 **받는 사람에게 가는 것과 안 가는 것이 섞인다.**
릴리스가 `docs/` 를 통째로 담을 수 없게 되고, 무엇을 담는지 사람이 기억해야
한다. **그 상태를 이미 한 번 겪었다** — §3.

---

## 3. `agent/` 는 2026-09-08 에 **해체한** 이름이다

설계서 §2.8 에 기록이 있다.

> **정정 (2026-09-08)** — 전에는 `agent/` 와 `repo-kit/` 이 따로 있었다.
> 둘 다 "지식 레포로 들어가는 것" 인데 *에이전트 세팅이냐 문서·훅이냐*로
> 나눠 두어서, **릴리스가 두 폴더를 다 알아야 했고** `repo-kit/` 안에는
> **repo-kit 으로 안 가는 파일**(설치 문서)이 섞여 있었다.
>
> `kit/` 하나로 합치고 판정 기준을 **"받는 사람에게 가는가"** 로 바꿨다.

**좁은 읽기는 이것을 그대로 되돌린다.** 같은 값을 두 번 치를 이유가 없다.

> 다만 **제안이 그 실수는 아니다.** 그때 문제는 *쪼갠 것*이었고, 제안은
> *이름을 바꾸는 것*일 수 있다. 둘은 다르다 — §4.

---

## 4. 두 축이 충돌하는가 — 아니다. 겹친다

| | 축 | 묻는 것 |
|---|---|---|
| 현재 | `kit` | **받는 사람에게 가는가** |
| 제안 | `agent` | **무엇을 위한 것인가** |

`kit/` 에 든 것을 "무엇을 위한 것인가" 로 다시 물으면 답이 하나로 나온다 —
**에이전트 작업 환경을 세우는 것.**

| | |
|---|---|
| `skills/` `CLAUDE-*.md` | 에이전트가 따르는 절차와 규약 |
| `hooks/pre-commit` | 에이전트를 **믿지 않고** 검사하는 층 |
| `manual/` | 그 환경을 사람에게 설명하는 것 |
| `install.md` | 그 환경을 세우는 순서 |
| `packages/` | 그 환경이 다룰 문서의 서식 |

**다섯이 한 목적을 향한다.** 훅이 에이전트를 불신하는 층이라는 것은 그 환경의
일부라는 사실과 모순되지 않는다 — 오히려 그래서 같이 배포된다.

**그러니 `kit/` → `agent/` 는 쪼개기가 아니라 이름 바꾸기다.** 2026-09-08 의
교훈("쪼개지 마라")을 어기지 않는다.

---

## 5. 넓은 읽기 — 정확히 넷이 된다

```
viewer/                  뷰어 프로그램
  server/ src/ bin/ index.html vite.config.js
  fixture/               ← sample-repo/     (뷰어 개발용이므로 여기가 맞다)

agent/                   **받는 사람에게 가는 것 전부**   ← kit/
  skills/                ← kit/agent/skills/
  CLAUDE-지식레포.md      ← kit/agent/
  CLAUDE-프로젝트레포.md   ← kit/agent/
  TEMPLATE-work.md       ← kit/agent/
  hooks/pre-commit       ← kit/hooks/
  manual/                ← kit/manual/
  packages/              ← packages/
  install.md             ← kit/install.md

ops/                     명령 (그대로)

docs/                    **우리만 보는 것**
  design/ dev/ 이집이지_이관/ 관리문서패키지/
  attic/                 ← attic/
```

**`kit/agent/` 의 한 단계가 없어진다.** `agent/skills/` · `agent/hooks/` ·
`agent/manual/` 이 나란히 선다 — 지금은 `kit/agent/skills/` 로 한 겹 깊다.

**`sample-repo/` 가 `viewer/fixture/` 로 간다.** 방금 "뷰어 개발용 fixture
한 가지 용도" 로 정리했으므로 이름과 자리가 그 판단을 말하게 된다.

**`attic/` 이 `docs/attic/` 으로 간다.** 한 번 돌고 끝난 것이라 상위 자리를
차지할 이유가 없다.

---

## 6. 이름 — `agent` 가 `kit` 보다 나은가

| | 장점 | 약점 |
|---|---|---|
| `kit` | 판정 기준이 `README` 에 적혀 있다 | **이름이 아무것도 말하지 않는다.** 열어 봐야 안다 |
| `agent` | **무엇을 위한 것인지** 말한다 | `agent/manual/` 은 사람이 읽고, `agent/packages/` 는 문서 서식이다 |

**`agent` 를 권한다.** 이름이 목적을 말하는 쪽이 낫고, 약점은 `README` 한 줄로
덮인다 — 지금 `kit` 은 `README` 없이는 **아무 뜻도 없다.**

단 **판정 기준은 이름과 함께 옮겨야 한다.** `agent/README.md` 첫 줄은 계속
*"받는 사람에게 가는가"* 여야 한다. 그 문장이 사라지면 `agent/` 에 개발용
파일이 섞이기 시작한다.

## 7. 이동 비용 — 경로를 든 곳 9군데

| 옮기는 것 | 코드·설정 | 어디 |
|---|--:|---|
| `kit/` → `agent/` | 2 | `ops/lib/release.mjs` · `ops/lib/seed_repo.py` |
| `sample-repo/` → `viewer/fixture/` | 6 | `package.json` · `ops/check.cmd` · `ops/seed.cmd` · `ops/lib/{build-ctx,release,seed_repo}` · `.gitignore`(5줄) |
| `packages/` → `agent/packages/` | 1 | `ops/lib/release.mjs` |
| `attic/` → `docs/attic/` | 0 | 없다 |

문서는 `README.md` · `kit/README.md` · `kit/install.md` · `kit/manual/admin.md` ·
`docs/design/CDP_시스템설계서_v1.0.md` 다섯이 §2.8 · 구조 절 · 배포본 목록을
들고 있다.

**`sample-repo` 이동이 제일 비싸다(6곳).** `.gitignore` 의 `bin/*` 예외 4줄이
포함돼 있고, 그 파일은 **이미 규칙과 사실이 어긋나 있다**(`.claude/` 4건이
추적 중 — 별건으로 띄워 둔 그 항목이다). 옮기면서 같이 정리하는 것이 맞다.

## 8. 권고

```
1  agent/ 로 이름을 바꾸고 packages/ 를 그 아래로      ← 값이 크고 싸다 (3곳)
2  attic/ → docs/attic/                              ← 공짜 (0곳)
3  sample-repo/ → viewer/fixture/                     ← 제일 비싸다 (6곳)
```

**1·2 를 먼저 하고 3 은 따로 한다.** 3 은 `.gitignore` 정리와 묶이므로 같이
커밋하면 무엇 때문에 깨졌는지 알기 어려워진다.

### 하지 말 것

| | |
|---|---|
| `kit/agent/` 만 올리기 | §2 — 다섯이 뜨고 §3 을 되돌린다 |
| `manual/` 을 `docs/` 로 | `docs/` 에 가는 것과 안 가는 것이 섞인다 |
| 한 번에 다 옮기기 | 깨지면 어디서 깨졌는지 모른다 |

### 이름을 안 바꾸는 선택지도 있다

`kit/` 을 그대로 두고 `packages/` 와 `attic/` 과 `sample-repo/` 만 옮겨도
**상위 폴더는 넷이 된다**(`viewer` `kit` `ops` `docs`). 목표가 *개수*라면
이것이 제일 싸다 — 코드 7곳, 이름 논쟁 없음.

**목표가 개수인지 이름인지에 따라 갈린다.**

## 9. 실행 결과

```
viewer/   server · src · bin · fixture        ← sample-repo
agent/    skills · CLAUDE-*.md · hooks · manual · packages · install.md   ← kit
ops/      *.cmd · lib · out · release        ← out/ release/ 가 여기로
docs/     design · dev · attic · …           ← attic
```

### `node_modules/` 는 못 옮겼다

| | |
|---|---|
| npm | `package.json` **옆에** 만든다 |
| node | 파일 위치에서 **위로 올라가며** 찾는다 |
| 그래서 | `viewer/`(js-yaml · chokidar)와 `ops/lib/`(rcedit)가 **둘 다** 외부 의존을 쓰므로 어느 한쪽으로 내리면 다른 쪽이 못 찾는다 |

워크스페이스로 묶어도 루트로 끌어올려진다. **하나뿐인 예외로 두고 그 이유를
`README.md` 와 설계서 §2.8 에 적었다.**

### 함께 정리한 것

| | |
|---|---|
| `viewer/fixture/.claude/` | `.gitignore` 가 무시하라는데 **4건이 추적 중**이었다. `git rm --cached` 로 뺐다 |
| `.gitignore` | `bin/` 은 추적, `.claude/` 는 추적 안 함 — **반대 결정인 이유**를 나란히 적었다 |
| `agent/` 한 겹 | `kit/agent/skills/` → `agent/skills/` |
| **`.gitattributes` 의 죽은 규칙** | `repo-kit/pre-commit text eol=lf` 이 **없는 경로**를 가리키고 있었다(2026-09-08 재편 때부터). `core.autocrlf=true` 인 PC 가 clone 하면 훅을 CRLF 로 받고 **커밋은 통과하는데 검사만 사라진다** — 문서가 경고하던 바로 그 결함이 실제로 열려 있었다. `**/pre-commit` 으로 **이름에 걸어** 다음에 옮겨도 따라오게 했다 |

### 검증

```
npm run seed        viewer/fixture 재생성 — work 20 · docs 16 · table 32
npm run build:ctx   ops/out/ctx/ 에 생성 + fixture/bin 갱신
npm run build       ops/out/web/ 에 생성
ctx check           오류 없음 (경고 2건 — 샘플의 의도된 상태)
루트                 폴더 4 + node_modules
```

`npm run build:exe` 와 `npm run release` 는 **아직 안 돌렸다** — 수 분이
걸리고 경로는 정적으로 확인했다.
