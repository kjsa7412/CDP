## 1. 계약 — 갈래 사이의 모양

### 1.1 작업 기록 프론트매터(개편안 §4.2)

```yaml
curates:                       # 큐레이션 기록 — 키가 있으면 큐레이션 기록
  - { id: 2026-1001-SCADA-프레임규격-초안, verdict: new, into: [인터페이스:SCADA-조회] }
  - { id: 2026-0917-PLC-CIMON-SCADA-구조및데이터흐름, verdict: keep, reason: 사전지식 — 기록이 원천 }
baseline: { source: "운영 DB sy_pgm_info", asof: "2026-10-02" }   # 기준선 기록
```
`verdict` ∈ `reflect` · `new` · `keep`. `into` 는 reflect · new 에서 1개 이상, keep 에서 없음.

### 1.2 계산값(`core/curation.js` · 개편안 §4.4)

| 이름 | 모양 |
|---|---|
| `curationOf(id)` | `{ state: 'queued' \| 'reflected' \| 'kept' \| 'system', into: [좌표], reason, by: 큐레이션 기록 id, at: 날짜 }` — `system` 은 큐레이션 · 기준선 · registry · docs-prune · derive 기록 자신 |
| `queue` | `[{ id, title, date, author, ageDays, zero: bool, coords: [{ coord, cls: 'section' \| 'anchor' \| 'unregistered' }] }]` 오래된 순 |
| 섹션 `pending` | `[{ id, title, date, author, excerpt }]` — `later(applied) ∪ (대기열 ∩ 그 좌표)` · 날짜 오름차순 · `excerpt` 는 본문 첫 문단 160자 |
| 섹션 `state` | `ok` · `pending` · `missing` |

### 1.3 HTTP(개편안 §5.4) — V 가 읽는 것

| 엔드포인트 | 응답에 더해지는 것 |
|---|---|
| `GET /api/<r>/repo` | `curation: { queue, oldestDays, pendingSections, last: { id, date, author } \| null }` |
| `GET /api/<r>/docs` | 작업 기록 행마다 `curation: { state }` |
| `GET /api/<r>/docs/<id>` | 관리 문서: `form`(서식 id 또는 null) · `sectionStates[]` 마다 `cstate`(ok · pending · missing) · `pending[]` / 작업 기록: `curation`(1.2 의 모양) |
| `GET /api/<r>/queue` | `{ items: queue, total, oldestDays }` |
| `GET /api/<r>/queue/<id>` | `{ record, coords: [{ coord, cls, doc, state, applied }], unregisteredTypes: [{ type, forms: [{ id, title }] }], bodyOnly: [좌표], canonical: [{ coord, also: [좌표] }] }` — curate 만 |
| `GET /api/<r>/curations` | `{ items: [{ id, date, author, judgments: curates, sections: n, newDocs: [경로] }] }` |
| `GET /api/<r>/forms` | `{ groups: [{ name, title, version }], forms: [{ id, group, number, title, kind, registry: [{ pattern, anchor }], used: bool }] }` |
| `GET /api/<r>/forms/<group>/<id>` | `{ id, title, kind, head, guide, example, stamp }` — `stamp` 은 서버가 찍을 빈 문서 그대로 |
| `POST /api/<r>/curate` | 입력 `{ verdict: 'keep', ids: [...], reason }` → save 결과 — curate 만 |
| `GET /me` · `/site/info` | `curate: ['*' \| 레포…]`(admin 은 `['*']`) |
| `GET /admin/repos` | 행마다 `curation: { queue, oldestDays }` · 응답의 `packages` 는 v0.27 에서 빠진다 |

화면은 이 값이 **없을 때도 그린다**(옛 서버) — 없으면 칩 · 배지를 그리지 않는다.

### 1.4 서식 파일(개편안 §8.1) — F 가 만들고 C 가 읽는다

`agent/forms/<묶음>/_묶음.json`(`{ name, title, version, description }`) · `agent/forms/<묶음>/<번호>_<제목>.md`:

```markdown
---
form: public-si/DE_431
title: 테이블정의서
number: DE_431
due: 설계완료
required: false
kind: 대상            # 대상 · 대장 · 정의 · 사건 · 서술
registry:
  - { pattern: "테이블정의서:*", anchor: "## {값}" }
coordValue: 테이블 물리명(소문자)
---
<!-- form:head -->
(새 문서로 가는 첫 문단)
<!-- form:guide -->
(큐레이터가 읽는 것)
<!-- form:example -->
(큐레이터가 읽는 것 — 예시는 ### 아래)
```

`core/forms.js`(순수 · I/O 없음):
- `parseForm(text, { group, file })` → `{ id, group, number, title, due, required, kind, registry, coordValue, head, guide, example, errors }`
- `stampDoc(form, { title? })` → 새 관리 문서 글 — `# <title>` · `<!-- cdp:form <id> -->` · 빈 줄 · head · 끝 개행. 예시 · 작성지침 · applied 없음
- `formIdOf(docText)` → `<!-- cdp:form … -->` 의 id 또는 null(H1 바로 아래 3줄 안)
- `lintForm(form)` → 문제 목록(머리 필드 · 세 덩어리 · kind 값 · registry 모양)
