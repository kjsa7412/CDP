# 어휘를 큐레이터가 고친다 — 검토 v0.1

2026-10-15 · 요청: 「CDP 서버 수정 요청 — 큐레이터가 어휘(`_vocab.md`)를 고치지 못하는 문제」(dpms_wiki 큐레이션 `0a0da50` 뒤 어휘 정리가 셋 다 막힘)

## 지금

| 자리 | 동작 | 문제 |
|---|---|---|
| `save` 의 `vocab[]` | `addVocab` — 문서에 `` `좌표` `` 글자가 있으면 `continue` · 응답 `vocab: 0` | **조용한 무시**(V1). 기존 좌표의 label · aliases 를 바꾸려는 호출이 성공처럼 끝난다 |
| `edits` 로 `_vocab.md` 어휘 줄 | `guarded` 가 거절 — 「폐기 표시는 admin 이」 | admin 도 이 길로는 못 고친다(가드는 역할을 보지 않는다). 문구가 틀렸다 — 사실상 **누구도** 도구로 못 고친다(V2) |
| 폐기 표시 | `parseVocab` 가 `deprecated: 날짜 → 좌표` 를 읽고 `match` 가 `successor` 를 낸다 | 쓰는 연산이 없다(V3) |
| `where` | 폐기 여부를 싣지 않는다 | 옛 기록의 `touches` 로 온 사람이 폐기를 모른다(V4) |
| 이름 바꾸기 | 없다. `managed.rename` 은 문서 파일만 | 새 좌표 · 섹션 헤딩 · 참조 · 옛 좌표 폐기를 손으로 넷(V5) |
| `check` deprecated-coord | 폐기 좌표를 `touches` 한 **모든** 기록에 경고 | 폐기하면 그 전의 불변 기록 전부가 영원히 경고 — 폐기를 쓰면 소음이 된다(V6) |
| alias 색인 | 먼저 온 좌표가 이긴다 · 겹침 검사 없음 | `링크` 가 `term:SCADA링크` · `term:PLC링크` 둘에 걸려 순서가 답을 정한다(V7) |
| 스킬 `cdp-registry` | 「행 폐기」 만 있고 「어휘 줄 · 타입 지우기 — 관리자에게」 | 등록부 행과 좌표가 헷갈린다(V8) |

## 권장안

| # | 결정 | 왜 |
|---|---|---|
| R1 | `vocab[]` 에 `op` — `add`(기본) · `update` · `retire` · `restore` · `rename` | 한 입력 한 갈래. 새 필드(`vocabOps`)를 따로 두면 같은 좌표를 두 곳에서 다룬다 |
| R2 | `update` · `retire` · `restore` · `rename` 은 **큐레이터**(`curate`) — `curatorOnly` 에 `vocab(op)` | 좌표 체계는 큐레이터의 일. admin 에는 레포 단위 일만 |
| R3 | 폐기는 줄을 지우지 않고 `deprecated: YYYY-MM-DD → <후속> — <사유>` 한 줄 | 기존 파서 · `match` 가 이미 읽는 모양. 작업 기록의 `touches` 가 끊기지 않는다 |
| R4 | 후속은 저장 뒤 어휘에 있어야 하고 사슬에 고리가 없어야 한다 — 아니면 `E_INPUT` | 요청 그대로 |
| R5 | `restore` 를 같이 둔다(폐기 표시 걷기) | 잘못 폐기하면 되돌릴 길이 없다(`edits` 는 누구에게나 막혀 있다) |
| R6 | `rename` 한 커밋: 새 좌표 등재(label · aliases 옮김) · 섹션 헤딩의 값 · `_seed.json` sections · 다른 문서의 `` `옛 좌표` `` 참조 · 옛 좌표 폐기 + 후속 | 요청 그대로. **작업 기록은 고치지 않는다**(불변 — 옛 `touches` 는 폐기 좌표 → 후속으로 따라간다) |
| R7 | `rename` 은 타입이 달라도 된다 — 단 옛 좌표에 섹션이 있으면 새 좌표가 **같은 문서 · 같은 레벨**에 걸려야 한다 | 오타 타입을 옮길 길(섹션 없음)은 열고, 섹션이 문서 사이를 몰래 건너가는 일은 막는다 |
| R8 | op 없이 기존 좌표를 보내면 **경고**(`warnings` + `vocabSkipped`) — 거절하지 않는다 | writer 의 save · `source update` 초안 · 세우기 재실행이 이미 있는 좌표를 같이 보내는 것은 정상이다. 거절하면 기록이 막힌다. label 이 다르면 경고에 「op: update(큐레이터)」 를 적는다 |
| R9 | alias 겹침 — `update` · `rename` 은 `E_INPUT`(겹친 좌표를 싣는다) · `add` 는 경고 | 요청은 update 의 검사. add 까지 거절하면 세우기 · 편입이 실레포의 옛 겹침으로 막힌다 |
| R10 | alias 색인은 **살아 있는 좌표가 먼저** — 폐기 좌표는 그 뒤 | 같은 열쇠면 살아 있는 쪽이 답이다 |
| R11 | `where` 도 `deprecated` · `successor` 를 싣고, 사슬이면 `match` · `where` 둘 다 `successorLatest` | 「폐기 좌표면 후속을 준다」 를 두 도구가 같게 |
| R12 | deprecated-coord 경고는 **폐기일 뒤에 쓴 기록**만 | 폐기 전의 불변 기록은 고칠 수도 없다(V6) |
| R13 | 어휘 연산 save 의 기록 — 큐레이션이 아니면 서버가 태그 `registry` 를 붙인다(대기열에 서지 않는다). `touches` 는 바꾼 좌표를 적기를 권한다(`where` 가 그 기록을 찾는다) | 새 태그 `vocab` 을 시스템 태그로 만들면 실레포에 이미 `vocab` 태그를 단 사람 기록이 대기열에서 빠진다 |
| R14 | viewer(쓰기 없음)가 큐레이터 입력을 보내면 `E_FORBIDDEN` 에 `need: curate` | 완료 기준 — viewer · writer 모두 같은 답 |
| R15 | `edits` 의 거절 문구 · 새 타입 경고 · 스킬 · 도구 설명을 새 연산으로 | V2 · V8 |

## 하지 않는 것

- 어휘 줄 **지우기** — 폐기가 그 자리다(기록의 `touches` 를 지키려고).
- 타입 머리글(`## 타입`) 지우기 · 이름 바꾸기 — 좌표를 전부 `rename` 한 뒤 빈 머리글은 남는다(해가 없다).
- 작업 기록 본문 · `touches` 고치기 — 불변.
