검사

좌표를 건드린 작업은 그 정본 섹션을 채워야 커밋된다. 서버형은 save 가, 로컬형은 git 훅이 같은 계산으로 막는다.

어떻게 쓰나

에이전트

Claude Code 가 MCP 로 붙는다. 읽기 도구 12종 + save. 스킬 7종이 절차를 든다 — 검토 → 주입 → 기록.

화면

찾기 → 뻗어나가기 → 읽기. 좌표 그래프. 갱신이 남은 곳은 현황에 있다. 편집은 없다 — 쓰기는 save 하나다.

CLI

ctx check · derive · where · match. 화면과 같은 계산이라 답이 갈리지 않는다.

6. 사람 관리 — 콘솔

서버형에만 있다. 로컬형은 git 원격의 권한이 곧 권한이다. 사람을 붙이는 일은 콘솔 (http://<서버>:7374/console)에서 한다 — 관리자(admin)만 들어간다. 셸에서도 같은 것이 된다(부록 B).

6.1 모델 — 권한은 사람에게, 토큰은 신원만

auth.json
  users[]    name · label · repos(볼 수 있는 레포) · role(viewer · writer · admin) · active
  tokens[]   id · sha256 · user · issued · expires · note · status        ← 원문은 없다
할 수 있는 것viewerwriteradmin
볼 수 있는 레포 읽기 · MCP 읽기 도구○○○
save · 레포 세우기 · 작업 레포 등록○○
콘솔 — 사용자 · 토큰 · 레포 전부 · 진단 · 감사○
토큰 원문은 저장되지 않는다. SHA-256 만 남는다. 잃으면 복구가 아니라 재발급이다 — 콘솔 > 토큰 > 그 행의 [재발급] 한 번. 권한은 사람에 붙어 있어 잃는 것이 없다.

6.2 사용자를 추가한다

콘솔 > 사용자 > [+ 사용자]. 이름(영문 · 숫자 · . _ - — 커밋의 author 로 남는다) · 라벨 · 역할 · 볼 수 있는 레포를 고른다. 쓰기 동작은 재인증을 요구한다 — 자기 토큰을 한 번 더 넣으면 15분 동안 통한다.

셸에서는 —

$CTX serve user add --auth $A --data $D --name <아이디> --label "<소속 · 역할>" --repos gdi --role writer

6.3 토큰 — 발급 · 재발급 · 폐기

콘솔 > 토큰 > [+ 발급]. 원문은 모달에 한 번 보인다 — 닫으면 다시 볼 수 없다. 본인에게 직접 전한다. 관리자의 토큰은 기본 30일, 나머지는 90일이다.
