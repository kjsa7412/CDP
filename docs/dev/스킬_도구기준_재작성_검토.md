## 왜 지금인가

`ctx setup` 이 `.mcp.json` 을 쓰게 되면서(`da4f13a`) **모드 A 도 MCP 로 붙는다.**
그 전까지는 로컬에서 에이전트가 bash 로 `ctx` 를 직접 불렀고, 스킬이 CLI 기준으로
쓰인 것이 그 현실과 맞았다. 이제 안 맞는다.

지금 스킬이 말하는 것과 실제로 일어나는 일 —

```
스킬 본문        $ C:/cdp/bin/ctx match "면접심사의견등록"
실제 모드 A      match(["면접심사의견등록"])          ← MCP · stdio
실제 모드 B      match(["면접심사의견등록"])          ← MCP · HTTP
```

**세 줄이 같은 일이고, 정본으로 적힌 것만 아무도 안 쓰는 형태다.**

머리 블록이 *"도구가 있으면 도구로"* 라고 덮고 있어서 동작은 한다. 그런데 그
덮개는 읽는 사람에게 **CLI 가 정본이고 도구가 예외**라고 말한다 — 사실과 반대다.
그리고 예시는 덮이지 않는다: `$ C:/cdp/bin/ctx` 는 그 경로가 존재하지도 않는
작업 레포에서 그대로 치라고 보인다.

## 결정

| 무엇 | 답 | 그래서 |
|---|---|---|
| **정본 형태** | **도구 호출** (`match([...])`) | 모드 A·B 가 둘 다 MCP 다. 정본이 주 경로와 달라서는 안 된다 |
| `ctx` 의 자리 | 스킬 끝 **「도구가 없을 때」** 한 절 | 훅(`ctx check`)과 사람이 터미널에서 칠 때는 그대로 남는다. 없애는 것이 아니라 **주에서 종으로** 내린다 |
| 출력 예시 | **읽기 좋은 요약 유지.** JSON 로 바꾸지 않는다 | 스킬이 가르치는 것은 *무엇이 오는가*지 *어떤 바이트인가*가 아니다. 전부 JSON 으로 펴면 길이가 배가 되고 읽기가 나빠진다 |
| 경로 예시 | `C:/cdp` 를 **지운다** | 작업 레포에서 그 경로는 없다. 모드 A 도 도구로 부르므로 지식 레포 경로를 스킬이 알 이유가 없다 |
| 범위 | 6종 (`cdp-push` 제외) | `cdp-push` 는 **코드 레포**를 다룬다. 거기의 `git -C` 는 지식 레포와 무관하고 그대로 맞다 |
| 머리 블록 | **남긴다.** 문장만 뒤집는다 | 지금은 *"도구가 있으면 도구로"*. 앞으로는 *"본문은 도구다. 도구가 없으면 …"* |

### 하지 않는 것

- **도구 이름을 바꾸지 않는다.** `match` · `where` · `section` … 그대로다.
  이름이 CLI 와 같은 것이 이 전환이 싼 이유다.
- **절차를 바꾸지 않는다.** ①②③④ 의 판단은 글자 하나 안 건드린다.
  바뀌는 것은 *어떻게 부르나* 뿐이다.
- **`cdp-managed` 의 모드 B 공백을 여기서 메우지 않는다**(§4.8). 그것은
  `save` 의 모양을 바꾸는 일이라 별건이다.

## 무엇이 바뀌나 — 대응표

이 표가 작업의 전부다. 본문의 각 호출을 왼쪽에서 오른쪽으로 옮긴다.

| 지금 | 도구 |
|---|---|
| `ctx match "a" "b"` | `match(["a","b"])` |
| `ctx where <좌표>` | `where("<좌표>")` |
| `ctx where` 뒤에 섹션을 Read | **`section("<좌표>")`** — 파일을 열지 않는다 |
| `ctx apply <좌표>` | `apply("<좌표>")` |
| `ctx derive` | `derive()` |
| `ctx check` | `check()` |
| `ctx sync` | `sync()` |
| `ctx brief` | `brief()` |
| `ctx search "말"` | `search("말")` |
| `git -C <repo> pull` | **모드 A 만.** 모드 B 는 없다 |
| `git -C <repo> commit` | 모드 A 만. 모드 B 는 `save({...})` |

**두 번째 줄이 단순 치환이 아니다.** `where` 뒤에 파일을 Read 하던 자리는
`section` 하나로 바뀐다 — 모드 B 에는 그 파일이 없고, 모드 A 에서도 문서
전체를 읽을 이유가 없다. 여기만 사람이 판단해서 고친다.

## 위험과 그 대응

| | |
|---|---|
| **스킬은 에이전트 행동을 직접 바꾼다.** 6개를 한꺼번에 고치면 무엇이 깨졌는지 모른다 | 한 종씩. `cdp-save` 를 먼저 하고 그 모양을 나머지에 적용한다 |
| 없는 도구 이름을 적는다 | **기계로 막는다.** 본문의 호출 이름을 실제 도구 목록과 대조하는 검사를 `ops/verify` 에 넣는다 |
| 모드 A 사용자가 `ctx` 를 못 찾게 된다 | 「도구가 없을 때」 절에 대응표를 남긴다. 훅은 원래 `ctx check` 를 부르고 그건 스킬과 무관하다 |
| 지식 레포에 붓는 것을 잊는다 | 오늘 한 번 당했다. 작업 끝에 **붓기와 서버 pull 까지**를 TODO 항목으로 둔다 |

## 끝났다고 보는 기준

- 6종 본문에 `bin/ctx` · `C:/cdp` 가 **0건**
- 「도구가 없을 때」 절이 6종에 있고 대응표가 같다
- `ops/verify` 의 새 검사가 통과 — 본문이 부르는 이름이 전부 실제 도구다
- `agent/skills/` → 지식 레포 → 서버 `pull` 까지 마치고 꾸러미가 새 스킬을 낸다
