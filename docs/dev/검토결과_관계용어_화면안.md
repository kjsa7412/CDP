## 0. 검토에서 새로 잡힌 것

NEXT 문서에 없던 것들이다. **이 일곱 개가 아래 확정안의 근거다.**

### ① `[결착]` 은 화면 문구가 아니라 주입 신호다

`src/lib/format.js:87,90` 이 내는 것은 프로토콜 v1.1 §12.3 의 주입 형식이다.

```
[유효] 현재 유효함 (덮은 문서 없음)
[나이] 결정 2026-08-19 · 3주 전
[결착] table:rp_plnd_mst 에 이후 문서 2건 (…)
```

사람이 ⇧C 로 복사해 **다른 AI 세션에 붙여넣는 텍스트**다. 화면 라벨만 바꾸고
이걸 두면, 화면에서 "후속 2건"을 본 사람이 붙여넣은 프롬프트에서는 "[결착]"을
읽게 된다. **이름을 바꾸면 프로토콜 §12.2 의 4개념 표(나이·유효성·결착도·절단)가
같이 바뀐다 — 설계 변경 1건이다.**

**다만 지금이 가장 싸다.** skill 4종을 훑어보니 소비하는 신호는 `[절단]` 뿐이고
`[결착]` 을 읽는 곳은 없다.

### ② `term:결착` 이 좌표로 등재돼 있다

```
_vocab.md:115   - `term:결착` — 같은 대상에 이후 변경이 더 없는 상태
                  aliases: 결착도
```

`C:\cdp` · `sample-repo` 둘 다. 생성원은 `tools/seed_repo.py:164`.
**이 좌표를 touches 에 쓴 작업 기록은 0건이다** — 시드 잔재다.
NEXT 문서가 센 "코드·화면 16" 밖에 있는 세 번째 서식지다.

### ③ 반응형 분기는 1440/1000/800/620 이 아니다

실제 `@media` 는 **1200 / 900 / 720** 세 개뿐이다 (`src/styles/app.css:671,679,688`).
관계 패널이 들어가면 열이 넷이 되므로 어차피 다시 짜야 한다 (§B-3).

### ④ 관계 정보는 작다 — 패널이 빌 위험이 크다

관계 패널에 들어갈 총 행 수 (좌표 + 반영된 섹션 + 정정 + 백링크):

| | 최소 | 중앙 | 최대 |
|---|---:|---:|---:|
| 행 수 | **0** | **3** | **10** |
| 좌표 이력까지 다 펴면 | 0 | 3 | 13 |

백링크는 평균 0.1건 · **31건 중 28건이 0건**이다.

**340px 패널을 상시로 두면 세로의 70%가 빈다.** 그래서 "관계를 오른쪽으로
옮긴다"만으로는 설계가 안 된다 — 본문 하단의 좌표 타임라인을 패널로 끌어
올려 세로를 채워야 한다 (§B-2).

### ⑤ 역참조는 실제로 신호를 낸다

```
applied 로 지목된 작업 21건 / 전체 31건
반영 섹션 수 분포:  1곳=15건 · 2곳=4건 · 3곳=1건 · 4곳=1건
```

**10건은 어느 관리 문서에도 근거로 실리지 않았다.** 그리고 작업×좌표 69쌍을
가르면 —

| | 쌍 |
|---|---:|
| 반영됨 | 30 |
| 계산 제외 (`domain:`) | 10 |
| **미반영 — 섹션이 이 작업 앞 작업에 머묾** | **8** |
| 등록부에 좌표 없음 | 8 |
| 지나감 — 섹션이 더 나중 작업을 싣고 있다 | 7 |
| 섹션 미작성 | 6 |

미반영 8건 중 4건은 **같은 날짜**라 순서가 모호하다(0단계의 "같은 날짜는 이후가
아니다" 규칙과 같은 자리). 날짜가 실제로 갈리는 것은 4건이고, 그 4건은
**누가 밀어냈는지 이름을 댄다** —

```
2026-0902-EXA021-외부심의위원  table:ps_ext_emp_mst
    → 테이블정의서는 아직 2026-0821-면접심사의견-개편 에 머물러 있다
```

지금 화면에는 이 줄이 없다.

### ⑥ 8쌍은 등록부에 좌표 자체가 없는데, 화면이 침묵한다

`module:grid-common` · `batch:project-status-nightly` · `module:date-range` 같은
것들이다. `ValidityBlock` 의 `SectionMark` 는 섹션이 없으면 `null` 을 낸다 —
그래서 **"관리 문서가 없는 종류"인지 "등록부에 빠뜨린 것"인지 구분이 안 된다.**

### ⑦ 문서 노드 그래프는 간선이 1개다

| 노드 단위 | 노드 | 간선 |
|---|---:|---:|
| **문서** | 31 | **1** (supersedes) |
| **좌표** | 55 | **65** (같은 작업에 동반 등장) |
| 이분 (좌표+작업) | 86 | 69 (touches) |

**노드 단위는 실측이 이미 답했다** (§C-1).

# A. 관계 용어 확정안

## A-1. 원칙 세 줄

1. **뜻이 다른 것은 합치지 않는다.** 이름만 하나로 못박는다
2. **화면어와 코드 식별자를 1:1로 고정한다.** 표에 없는 말은 화면에 쓰지 않는다
3. **한 사실을 두 이름으로 부르지 않는다.** 주체가 달라도 이름은 하나다 (§A-4)

## A-2. 확정 표

### 시간 축 — 뒤에 무엇이 왔나

| 개념 | **확정 이름** | 코드 식별자 | 색 | 주체 | 지금 이름 |
|---|---|---|:--:|---|---|
| `later(D,C)` — 이 좌표를 나중에 또 바꾼 작업이 있다 | **후속** | `later` · `laterCount` | amber | (작업, 좌표) 쌍 | 후속 / **이후** |
| 관리 문서 섹션이 `applied` 이후를 못 싣고 있다 | **밀림** | `stale` | amber | 섹션 | 밀림 / stale |
| **기록 자체가 틀려서** 다른 기록이 바로잡았다 | **정정** | `supersedes` · `superseded` | red | 작업 | **덮임** |

**셋은 다 "더 새로운 것이 있다"인데 주어가 다르다.** 그래서 이름이 셋이어야 한다.
후속·밀림은 `later()` 하나에서 기준점만 바꿔 나온다 (수행 v1.0 §6.1).
정정은 계산이 아니라 사람이 선언한 것이라 색이 다르다.

> **"덮임"을 "정정"으로 바꾸는 이유.** `supersedes` 는 오기재 정정 전용인데
> (수행 §6.3), "덮임"은 "밀림"과 소리도 뜻도 붙는다. 화면에서 ⛔덮임 과
> ⚠밀림 이 한 줄 안에 같이 나오면 사용자는 둘을 정도 차이로 읽는다.
> **정정은 정도가 아니라 종류가 다르다** — 그건 틀린 기록이다.

### 반영 축 — 관리 문서에 실렸나

| 개념 | **확정 이름** | 코드 식별자 | 색 |
|---|---|---|:--:|
| 섹션의 `applied` 가 이 작업이다 | **반영됨** | `applied` | 없음 |
| `applied` 가 비어 있다 | **미작성** | `unwritten` · `empty` | amber |
| 등록부가 가리키는데 섹션이 없다 | **섹션 없음** | `anchor-missing` | red |
| 등록부가 가리키는데 파일이 없다 | **문서 없음** | `doc-missing` | red |
| `applied` 가 없는 id 를 가리킨다 | **끊김** | `orphan` | red |
| 등록부에 그 좌표가 없다 | **관리 대상 아님** | `section === null` | 없음 |

**"관리 대상 아님"이 새로 생긴 칸이다** (§0-⑥). 지금은 아무 표시도 없어서
빠뜨린 것과 구분이 안 된다. 무채색 한 줄로 적는다 — 색 예산을 쓰지 않는다.

### 나머지

| 개념 | **확정 이름** | 코드 식별자 | 색 |
|---|---|---|:--:|
| 어휘에 등재되지 않은 좌표 | **미등재** | `unregistered` | amber |
| 주입 시 일부만 실었다 | **절단** | — (신호 `[절단]`) | — |

## A-4. 미반영을 새 용어로 만들지 않는다

§0-⑤ 의 8쌍을 "미반영"이라 부르고 싶어지는데, **그건 밀림을 작업 쪽에서 본
것일 뿐 다른 사실이 아니다.** 용어를 하나 더 만들면 같은 계산에 이름이 둘이
되고, 그게 지금 고치려는 병이다.

**주어를 섹션으로 고정하고 설명절을 붙인다.**

```
관계 패널 (작업 기록 화면)
  table:ps_ext_emp_mst      후속 1건
    테이블정의서 밀림 — 이 작업이 아직 안 실렸습니다
                          지금은 2026-0821-면접심사의견-개편 까지
```

패널의 제목으로는 "아직 반영 안 된 것"을 써도 된다 — **제목은 묶음 이름이지
용어가 아니다.**

# B. 문서 화면 2분할 — 본문 | 관계

## B-1. 무엇이 어디로 가나

```
지금 (한 열)                   확정안 (두 열)
─────────────────────         ──────────────────┬──────────────────
유효성 1단 · 2단 · 3단          유효성 1단 · 2단   │  좌표 · 후속 · 섹션
목차 레일                      목차 레일          │  반영된 섹션  ← 신규
본문                          본문               │  좌표 이력
첨부                          첨부               │  정정
이어 읽기                      복사               │  참조하는 문서
백링크                                          │  이어 읽기
좌표 타임라인
복사
```

| 남는다 | 왜 |
|---|---|
| 유효성 **1단** (정정·깨짐) | **읽기 전 판단**이다. "이 문서를 읽어도 되는가"는 본문 위에 있어야 한다 (§17.6) |
| 유효성 **2단** (날짜·작성자·상태) | 문서 자신의 정보다. 관계가 아니다 |
| 목차 레일 · 본문 · 첨부 · 복사 | 문서로서의 정보 |

| 나간다 | 왜 |
|---|---|
| 유효성 **3단** (좌표별 표) | 관계다. 좌표마다 최대 6행이라 본문을 가장 많이 밀어낸다 |
| 좌표 타임라인 | 관계다. 그리고 **패널의 세로를 채운다** (§0-④) |
| 백링크 · 이어 읽기 | 관계다 |

**62px 예산은 지켜진다.** 지금 정상 문서는 1단+3단을 한 줄로 합치고 2단을 더해
2줄 62px 이다. 3단이 나가면 1단+2단 그대로 2줄 — **같은 62px 이고, 합치느라
"모든 좌표에서 최신"이라고 뭉뚱그리던 문장이 없어진다.**

## B-2. 관계 패널의 모양

### 작업 기록을 열었을 때

```
┌─ 관계 ──────────────────────────────┐
│                                     │
│ 좌표 4                              │
│   screen:PSC043              최신    │
│     화면정의서_인사 · 반영됨            │   ← 역참조 (신규)
│   table:ps_ext_emp_mst    후속 1건   │
│     테이블정의서 · 밀림                │
│     이 작업이 아직 안 실렸습니다         │
│   code:PS130                 최신    │
│     코드정의서 · 미작성                │
│   domain:인사채용        계산 제외     │
│                                     │
│ 이력   table:ps_ext_emp_mst  ▾       │   ← 좌표를 고르면 여기가 바뀐다
│   08-21 ● 면접심사의견 개편           │
│   09-02   EXA021 외부심의위원         │
│                                     │
│ 정정  —                              │
│ 참조하는 문서  2건                     │
│ 이어 읽기  table:… 의 다음 문서 →      │
└─────────────────────────────────────┘
```

**"반영된 섹션" 이 이번 작업의 본체다** — `sections.filter(r => r.applied === id)`.
좌표 행 아래 한 줄로 붙인다. 별도 블록으로 두지 않는 이유는, 좌표와 섹션이
1:1이라 두 곳에 나누면 눈이 오간다.

### 관리 문서를 열었을 때 — 역할이 다르다

```
┌─ 관계 ──────────────────────────────┐
│ 섹션 18   밀림 1 · 미작성 9           │
│                                     │
│   ## rp_plnd_mst                    │
│     ← 09-03 계획서 상태값추가          │
│   ## ps_ext_emp_mst        밀림 1    │
│     ← 08-21 면접심사의견 개편          │
│       09-02 EXA021 이 아직 안 실림    │
│   ## rp_rdc_mst           미작성      │
│   …                                  │
└─────────────────────────────────────┘
```

**섹션 목록 + 출처.** 클릭하면 본문의 그 섹션으로 스크롤한다.
테이블정의서는 섹션행이 18개라 이 패널이 세로를 다 쓴다 — 여기서는 빌 걱정이 없다.

| 제약 | 어떻게 |
|---|---|
| 색 예산 4개 | 후속·밀림·미작성 amber · 정정·없음·끊김 red · 미결 purple · 링크 파랑. **"관리 대상 아님"은 무채색** |
| 정상이면 표시가 사라진다 | 좌표 행은 `최신` 만 남고 섹션 줄이 없어진다. 정정·참조·이어읽기 블록은 0건이면 제목째 사라진다 |
| 유효성 블록 62px | §B-1 |
| 좁아지면 접힌다 | §B-3 |

## B-3. 폭 — 이것이 이번 화면안의 진짜 제약이다

```
현재   사이드바 264 │ 목록 360 │ 본문(나머지, 읽기폭 760)
확정   사이드바 264 │ 목록 360 │ 본문 760 │ 관계 340   =  1724px 필요
```

**1440 노트북에서는 네 열이 안 들어간다.** 그래서 접는 순서를 다시 짠다.

| 폭 | 열 | |
|---|---|---|
| ≥ 1700 | 사이드바 · 목록 · 본문 · 관계 | 큰 모니터 |
| 1360 ~ 1700 | **사이드바** · 본문 · 관계 | **목록이 먼저 접힌다** |
| **1100 ~ 1360** | **본문 · 관계** | **사용자가 말한 2분할. 여기가 주 레이아웃이다** |
| 900 ~ 1100 | 본문, 관계는 본문 아래로 | 지금 모양 |
| < 900 | 단일 열 | 목록↔본문 전환 |

현행 `1200 / 900 / 720` → `1700 / 1360 / 1100 / 900` 으로 바꾼다.

> **목록을 사이드바보다 먼저 접는 이유.** 수행 v1.0 §15.1 이 좌표 트리를
> *"주인공"* 으로 올리고 **목록 패널을 아예 없애는** 그림을 그렸다. 지금 현행
> 분기는 반대로 사이드바(좌표 트리)를 1200 에서 먼저 접는다 — §15.1 과 어긋나
> 있었고, 열이 넷이 되면 그 어긋남이 커진다.

> 뷰어 §15.3 이 *"이 앱의 실제 두 번째 레이아웃은 에디터 옆에 반쪽으로 붙여둔
> 창"* 이라고 했다. 1100~1360 이 정확히 그 폭이고, 거기서 **본문 | 관계** 가
> 온전한 2분할로 선다. 네 열은 큰 모니터의 덤이다.

| | |
|---|---|
| 관계 패널 폭 | 사이드바·목록과 같이 gutter 로 조절. 기본 340 |
| 토글 | **⌘3**. 읽기 모드(⌘.)는 관계도 접는다 — 읽기 모드의 정의가 "본문만"이다 |
| 좌표 클릭 | 패널 안에서 이력이 펴진다. **좌표 뷰로 튀지 않는다** — 본문을 잃지 않는다. 좌표 이름을 한 번 더 누르면 좌표 뷰 |

## B-4. 서버가 더 내야 하는 것

`store.detail()` 에 두 필드를 더한다. 계산은 이미 다 있다.

```js
appliedIn: this.sections.filter(r => r.applied === d.id)   // 역참조
```

그리고 `coords[]` 의 각 항목에 `section.applied` 가 이 문서보다 앞인지
(= 밀림인데 이 작업이 안 실림) 판정을 붙인다. **`later()` 를 새로 부르지 않는다** —
`sections` 가 이미 들고 있는 값이다.

# C. 좌표 그래프 뷰 (부가 · 13단계)

## C-1. 노드는 **좌표**로 — 실측이 결정했다

| 노드 단위 | 노드 | 간선 | 판정 |
|---|---:|---:|---|
| 문서 | 31 | **1** | **그릴 것이 없다.** supersedes 가 1건뿐이다 |
| **좌표** | 55 | 65 | 성분 22개 · 최대 성분 23개 |
| 이분 (좌표+작업) | 86 | 69 | 옵션. 좌표 그래프에서 노드를 열면 작업이 붙는 형태로 |

옵시디언식 문서 그래프가 **여기서는 성립하지 않는다.** 옵시디언은 본문의
`[[링크]]` 가 간선인데, CDP 의 문서는 서로를 링크하지 않는다 — 좌표를 통해서만
만난다. 문서를 노드로 두면 점 31개가 흩어진 그림이 나온다.

## C-2. 3D 를 하지 않는다 — 2D 로 만든다

3D 는 노드가 수백~수천일 때 **겹침을 푸는** 수단이다. 여기 겹침은 문제가 아니다.

```
연결 성분 22개 — 크기 23 · 7 · 5 · 2 · 그리고 1이 18개
고립 노드 18개 (33%)
```

**노드 셋 중 하나가 고립점이다.** 3D 로 만들면 회전할 때마다 이 점들이 앞뒤로
흩어져 읽기가 더 어려워진다. 회전 조작 비용만 는다.

**3D 는 옵션으로도 넣지 않는다.** 넣으면 유지 비용이 두 배가 되고, 55노드에서
그 비용을 정당화할 이득이 없다. 규모가 수백으로 커지면 그때 항목으로 올린다.

## C-3. 힘 그래프만으로는 값이 안 난다

성분 분포가 위와 같으면 순수 force layout 은 **떠다니는 점 구름**이 된다.
그래서 배치에 두 가지를 더한다.

| | |
|---|---|
| **타입별 시드 배치** | `table` 18 · `screen` 18 · `api` 3 · `module` 4 · `term` 3 · `code` 3 · `batch` 1 · `domain` 5 를 영역으로 나눠 초기 위치를 준다. force 는 그 위에서 푼다 |
| **색은 상태** | 밀림 amber · 없음/끊김 red · 미작성 purple · 정상 무채색 — **색 예산 그대로** |
| **크기는 작업 건수** | 최대 5건(`domain:심의`). 반지름 차이를 크게 두지 않는다 |
| 간선 | 같은 작업에 동반 등장. 굵기는 동반 횟수 |

그래프의 값은 "무엇이 연결됐나"가 아니라 **"어디에 몰렸나"** 다.
최대 성분 23개가 심의 업무 하나에 몰려 있고 밀림 2 · 미작성 2 가 거기 있다 —
그 한 장면이 이 뷰의 존재 이유다.

## C-4. 의존성 — 자체 구현

**폐쇄망 단일 exe 라 CDN 은 애초에 불가**다 (`tools/build-exe.mjs`).

| | |
|---|---|
| **권고 — 자체 구현** | 55~수백 노드짜리 force 는 약 80~150행이다. **의존성 0.** exe 크기가 안 는다 |
| 대안 — `d3-force` | 순수 JS 라 번들된다. 잘 검증돼 있다. 다만 `d3-dispatch`·`d3-timer`·`d3-quadtree` 를 끌고 온다 |

착수 시 자체 구현으로 먼저 하고, 노드가 수백을 넘어 quadtree 가 필요해지면
그때 `d3-force` 를 항목으로 올린다.

## 이 문서가 예측하지 못한 것

**§0-④ 에서 "관계 패널의 70%가 빌 것"이라 했고, 그래서 타임라인을 패널로
끌어올려 세로를 채우기로 했다.** 그 판단은 맞았다 — 좌표 3행 + 이력 2~5행이
패널의 대부분이다.

다만 **관리 문서 쪽은 정반대**였다. 테이블정의서는 섹션행이 18개라 패널이
세로를 다 쓰고도 넘친다. 같은 패널이 두 층에서 반대 문제를 갖는다는 것을
이 문서는 보지 못했다.

## 검토가 놓쳤던 것 — CRLF

용어를 바꾸며 `_vocab.md` 를 저장했더니 좌표가 **하나도** 안 잡혔다.
파서가 `split('\n')` 을 쓰는데 CRLF 면 줄 끝에 `\r` 이 남고 JS 정규식의 `.` 이
그것을 안 먹는다. 어휘가 통째로 비면 모든 좌표가 미등재로 잡히고,
**미등재는 훅이 커밋을 막는 유일한 항목**이라 레포 전체가 커밋 불가가 된다.

용어 통일과 아무 상관 없는 버그인데 **용어 통일을 하지 않았으면 안 나왔다.**
실측을 절차에 넣은 값이 여기서 나왔다 (TODO 11단계).
