## 0. 한 줄

**쓰는 사람과 다듬는 사람을 가른다.** 사용자(writer)는 작업 기록만 `save` 한다 — 파생 때문에 막히지 않는다. 기록은 **큐레이션 대기열**에 들어가고, 큐레이터(admin + 에이전트 `cdp-curate`)가 대기열을 오래된 것부터 읽어 기록마다 **반영 · 새 문서 · 기록으로 둠** 셋 중 하나를 정하고 한 번의 `save` 로 섹션 · 등록부 · 새 문서 · 「큐레이션 기록」 을 같이 넣는다. 새 관리 문서는 **서식집**의 서식을 골라 만들되 서버가 **제목 · 머리말만 있는 빈 문서**로 찍는다(작성지침 · 예시는 서식집에 남는다). 늦게 오는 반영이 정보를 새게 하지 않도록 **주입(`section` · `load`)과 화면은 섹션 뒤의 미반영 기록을 반드시 같이 싣는다** — 이것이 「파생 누락 = 오류」 를 대신하는 보증이다. 레포는 언제나 빈 상태로 세운다.

## 1. 왜 — 앞 검토의 원인 넷이 어떻게 풀리나

| 앞 검토의 원인 | 큐레이터 모델 |
|---|---|
| **C3** 세션이 기록과 섹션을 같은 순간 써서 기록이 요약이 된다 | 사용자는 기록만 쓴다. 큐레이터는 **기록만 보고** 쓴다 → 기록이 원천이어야만 반영이 된다 |
| **C2** 「섹션은 홀로 서야 한다」 를 복제로 풀었다 | 큐레이터가 기록 여럿을 한 번에 보고 정본 자리를 정한다 · 주입이 미반영 기록과 정본 좌표를 따라 싣는다(§6) |
| **C1** 규칙이 문서 종류를 모른다 | 종류 · 모양은 서식의 작성지침이 말하고 그것을 읽는 사람이 하나다 |
| **C4** 좌표가 있는 자리로만 흐르고 빈 서식은 영영 빈다 | 서식을 붓지 않는다. 기록이 쌓인 주제만 문서가 된다 — 구조가 기록에서 자란다 |

## 2. 원칙이 바뀌는 자리

| | 전 (v0.24) | 후 |
|---|---|---|
| 파생 누락 | `check` **error** `derive-missing` — `save` · 훅이 막는다 | **상태**다. `check` info `curation-pending`(건수 · 가장 오래된 나이), 14일을 넘기면 warn `curation-stale` |
| 보증 | 「섹션이 최신이다」 | **「섹션과 함께 그 뒤의 미반영 기록이 반드시 실린다」** — `section` · `load` · 화면(§6) |
| 섹션을 쓰는 사람 | 작업한 사람(writer) | **큐레이터(admin)** — writer 의 `save` 에 `sections` · `managed` 가 오면 `E_FORBIDDEN { need: 'admin', hint: '기록만 남긴다 — 큐레이터가 반영한다' }` |
| 기록의 자격 | 섹션에 옮겼으면 기록은 짧아도 됐다 | **기록이 홀로 선다** — 값 · 표 · 결정 · 제약은 기록에. 큰 추출물(DDL · 덤프)은 첨부 |
| 관리 문서가 생기는 때 | 패키지를 부을 때(40종) | 큐레이터가 「새 문서」 로 판정할 때만 |

> 「안 채운 섹션은 최신인 척한다」(cdp-managed) 는 여전히 참이다. 그래서 막는 대신 **최신인 척을 못 하게** 한다 — 미반영이 있는 섹션은 어디서 보든 그 사실과 그 기록을 같이 보인다.

## 3. 역할 · 흐름

```
writer    작업 → save({ work, vocab?, assets? })            막히지 않는다(파생 판정 없음)
              │
server    큐레이션 대기열 = 아직 어떤 큐레이션 기록의 curates 에도 없는 작업 기록 (오래된 순)
              │
curator   cdp-curate (admin 세션)                            화면: 레포 관리 › 큐레이션
          ① queue()        대기열 · 기록마다 걸린 좌표의 등록부 상황
          ② 기록을 읽는다    오래된 것부터 · 같은 좌표 묶음으로
          ③ 판정            반영 │ 새 문서(서식 고름) │ 기록으로 둠
          ④ 보이고 승인      판정표 + 섹션 diff
          ⑤ save({ work: 큐레이션 기록, sections, managed, vocab })   한 커밋
```

- **큐레이터는 admin 이다**(K1). 화면은 대기열 · 이력을 보이고 「기록으로 둠」 만 직접 한다 — 반영 · 새 문서는 글을 써야 하므로 에이전트 세션이 한다(화면은 「에이전트 지시 복사」).
- **writer 는 섹션을 못 쓴다**(K2). 정본 층의 작성자가 하나여야 복제 · 이름 갈림이 안 생긴다. 모드 A(셸 · 훅)는 git 이라 강제할 수 없다 — 훅은 「작업 기록 없이 docs/ 섹션이 바뀌었다」 를 warn 한다.

## 4. 데이터 — 새로 생기는 것은 큐레이션 기록 하나

### 4.1 큐레이션 기록

`work/` 의 작업 기록이다(불변 · 한 커밋 · 이미 있는 틀). 표식은 태그와 필드 하나.

```yaml
id: 2026-1007-큐레이션-SCADA연계
title: 큐레이션 — SCADA 연계 기록 4건
date: 2026-10-07 10:20
author: kjsa
tags: [curate]
touches: []
touchesEmpty: 큐레이션
curates:
  - 2026-1001-SCADA-외부인터페이스-사전조사
  - 2026-1001-SCADA-프레임규격-초안
  - 2026-1002-SCADA-데이터종류-수집경로-검토
  - 2026-1006-SCADA-연계게이트웨이-방향결정
```

본문은 판정표다 — 기록마다 「반영 → 좌표들」 · 「새 문서 → 문서 · 서식 · 등록부 패턴」 · 「기록으로 둠 → 사유」. 정본을 어디로 정했는지(같은 사실이 여러 좌표에 걸릴 때)도 여기 적는다.

| 규칙 | |
|---|---|
| `curates` 의 id 는 있어야 하고 · 큐레이션 · 등록부 · 문서정리 기록이 아니어야 한다 | 아니면 `E_INPUT` |
| 이미 다룬 id 를 다시 넣으면 | 경고(재큐레이션 — 막지 않는다. 섹션을 고쳐 쓸 때 정상이다) |
| `sections` 의 `applied` | 그 섹션에 반영한 기록 중 **가장 최신 기록의 id**(큐레이션 기록 id 가 아니다) — 지금 `applied` 의미 그대로 |
| 큐레이션 기록 자체 | 대기열에 안 들어간다 · `where` 의 기록 목록에서 거른다(`derive` · `registry` 태그와 같은 대우) |

### 4.2 대기열

`queue = 작업 기록 − (curate · registry · docs-prune · derive 태그) − ⋃ curates`. 기록마다 걸린 좌표를 셋으로 나눠 보인다 — **섹션 있음**(반영 후보) · **등록부 있음 · 섹션 없음** · **등록부 없음**(새 문서 후보 · 또는 기록으로 둠). 순수 계산이라 `core/curation.js` 한 곳(불변조건 1).

### 4.3 섹션 상태

`validity` 의 다섯은 그대로 두고 밖으로 나가는 셋을 바꾼다.

| 전 | 후 | 뜻 |
|---|---|---|
| `ok` | `ok` | |
| `derive-pending` | **`pending`** + `pending: [{ id, date, title, author }]` | 섹션 `applied` 뒤에 그 좌표를 건드린 기록 |
| `missing` | `missing` | |

`pending` 은 대기열과 다르다 — 기록이 큐레이션돼 「기록으로 둠」 이 됐어도 섹션 뒤에 있으면 `pending` 이다(섹션이 그 내용을 안 담았으니까). 큐레이터가 「반영할 것 없음」 이면 `applied` 만 올리는 반영을 한다(지금 「바뀐 게 없으면 그렇게 적는다」 와 같다).

### 4.4 기존 레포 — 기준선

전환 때 기존 기록 전부가 대기열에 쏟아지지 않게 한다. upgrade 후 첫 큐레이션에서 **기준선 큐레이션 기록**(`tags: [curate, baseline]`)을 서버가 제안한다 — 섹션 상태가 `ok` 인 좌표만 건드린 기록은 `curates` 에, `pending` 이 남는 기록은 빼고. admin 이 화면의 [기준선 잡기] 로 한 번 남긴다(K6).

## 5. `save` · `check` · 훅

| 자리 | 바뀌는 것 |
|---|---|
| `save` (writer) | `work` · `vocab` · `assets` · `edits`(섹션 밖 · 지금처럼) 만. `sections` · `managed` · `examples` 는 `E_FORBIDDEN need admin` |
| `save` (admin) | 지금 그대로 + `work.curates` 검사(§4.1) · `managed.add` 에 `form`(§7.3) |
| `save` 의 검사 | `derive-missing` 이 error 가 아니므로 기록만의 save 가 막히지 않는다. `needSections`(새 등록부 행이 기존 좌표를 덮을 때 섹션 강제)는 **admin save 에만** 남는다 |
| `check` | `derive-missing` → info `curation-pending` · warn `curation-stale`(가장 오래된 대기 > 14일 · K5) · `derive-sameday` 는 지운다(큐레이터가 기록을 묶어 읽는다) |
| `check` 새 경고(앞 검토 §4 ④ 중 둘) | `section-journal`(본문에 날짜 덩어리 3개 이상) · `derive-outgrows-source`(섹션 합 > 근거 기록 합의 3배 · 섹션에 `출처:` 줄이 있으면 넘어간다) — **큐레이터에게 보이는 경고**다 |
| 훅(모드 A) | 파생 누락으로 막지 않는다. docs/ 의 좌표 섹션이 바뀌었는데 같은 커밋에 `curate` 기록이 없으면 warn |
| `derive` · `apply` 도구 | `queue` 로 바꾼다 · `apply` 는 그 좌표의 미반영 기록 + 섹션 + 문서의 서식 id 를 준다 |

## 6. 주입 — 미반영 기록을 같이 싣는다 (보증)

| 도구 | 바뀌는 것 |
|---|---|
| `section` | `state` · `pending[]`(기록 id · 날짜 · 제목 · 작성자) · 문서의 `form` 을 같이 낸다 |
| `where` | 섹션 블록에 `pending` 수 |
| `load`(스킬 `cdp-load`) | 섹션을 실을 때 **`pending` 기록의 본문을 함께 싣는다**(오래된 순 · 기록당 상한 · 넘치면 목차와 id). 답에는 「섹션 이후 반영 안 된 기록 n건을 함께 봤다」 를 적는다 |
| `load` — 정본 따라가기 | 섹션 본문의 `좌표` 참조(백틱 좌표)를 **한 단계** 따라가 그 섹션을 같이 싣는다(상한 5). 큐레이터가 복제 대신 좌표를 걸 수 있게 하는 짝이다 |

> 지금 `cdp-load` 는 「후속 n건 — 이 부분은 갱신됐을 수 있다」 를 **문구로만** 붙인다. 바뀐 뒤에는 그 후속의 **내용**을 싣는다. 섹션이 늦어도 주입받은 쪽이 아는 것은 늦지 않다.

## 7. 서식집 — 패키지 다섯이 가는 곳

### 7.1 자리와 모양

```
agent/forms/                     ← agent/packages/ 를 옮긴다. 레포에 붓지 않는다
  README.md                      서식집 쓰는 법 (큐레이터용)
  public-si/                     묶음 = 옛 패키지 이름
    _묶음.json                    name · title · version · description (옛 _package.json)
    DE_431_테이블정의서.md         서식 하나 = 파일 하나
    …
  agile-product/ · ai-service/ · cloud-native/
```

`blank` 는 없어진다 — 모든 레포가 blank 다. `_managed.md` · `_vocab.md` 는 서식 파일의 머리로 흡수된다(서식이 「이런 좌표 타입 · 이런 앵커」 를 제안).

**서식 파일 하나의 모양** — 세 덩어리. **문서로 가는 것은 첫 덩어리뿐이다.**

```markdown
---
form: public-si/DE_431
title: 테이블정의서
number: DE_431            # 관리번호 — 내보내기 틀이 쓴다
due: 설계완료              # 제출시기 — 내보내기 틀이 쓴다
coordType: 테이블정의서     # 제안. 큐레이터가 바꿀 수 있다
anchor: "## {값}"
---

<!-- form:head -->            ← 이것만 새 문서로 간다
테이블의 지금 상태. 섹션 하나가 테이블 하나다.

<!-- form:guide -->           ← 큐레이터가 읽는다. 문서로 가지 않는다
## 작성지침
…(섹션 모양 · 칸 · 쓰는 때 · 여기 적지 않는 것)

<!-- form:example -->         ← 큐레이터가 읽는다. 문서로 가지 않는다
### 예시 — ex_plan_mst
…
```

- 예시는 **`###` 아래 · 서식 파일 안에만** 있다. 서식 파일은 `docs/` 밖이라 스캔 · 좌표 판정에 안 걸린다. `example:` 어휘 · `(예시)` 섹션 · `applied: null` 은 서식집에서 사라진다.
- 「여기 적지 않는 것 → 어디로」 표는 **guide 로 내린다** — 문서로 가져오면 그 레포에 없는 문서를 가리킨다(앞 검토 `BM_111` dangling 의 원인).

### 7.2 묶음은 고르지 않는다 — 큐레이터가 찾는다

서식집은 묶음 넷(public-si · agile-product · ai-service · cloud-native)을 다 싣고 나간다. 큐레이터는 「테이블을 받을 문서」 가 필요할 때 `forms({ q: "테이블" })` 로 묶음을 가로질러 찾고 고른다. 한 레포가 여러 묶음의 서식을 섞어 써도 된다. **맞는 서식이 없으면 서식 없이** 만든다(`form` 생략 → `# 제목` 한 줄 · 지금 `add` 그대로).

### 7.3 서식에서 문서를 만든다 — 깨끗한 빈 문서

`save.managed: [{ op: "add", pattern: "테이블정의서:*", doc: "docs/테이블정의서.md", form: "public-si/DE_431" }]`

서버가 찍는 것 — **이것이 전부다.**

```markdown
---
form: public-si/DE_431
---
# 테이블정의서

테이블의 지금 상태. 섹션 하나가 테이블 하나다.

| | |
|---|---|
| 등록부 | `테이블정의서:*` → `## {값}` |   ← v0.21.0 머리 표 칸(등록부 사본) — 서버가 찍는다(regen.js)

## sy_user_info — 사용자정보     ← 같은 save 의 sections 가 여기부터
<!-- applied: 2026-1006-GDI-CLEAN-베이스 -->
…
```

| 들어간다 | 안 들어간다 |
|---|---|
| 제목 · `form:head` 한두 문단 · 머리 표의 `등록부` 칸 하나 · 같은 save 의 섹션 | 작성지침 · 예시 · 관리번호 표 · 제출시기 · 「여기 적지 않는 것」 표 · `applied: null` 섹션 |

- 문서 이름 · 위치는 큐레이터가 정한다 — 서식의 `title` 이 기본, 관리번호 접두(`DE_431_`)는 **붙이지 않는다**(K4 · 내보내기 때 붙인다).
- `form:` 줄이 남아 `section` · `apply` 가 그 문서의 서식을 알려 준다 → 다음 큐레이터가 같은 작성지침을 읽는다.

### 7.4 도구

| 도구 | 하는 것 |
|---|---|
| `forms({ q? })` | 서식 목록(묶음 · id · 제목 · 제안 좌표 타입 · 한 줄) |
| `forms({ form })` | 그 서식의 head · guide · example 전문 |

서식집은 서버 설치본에 있다(`ctx serve` 가 `agent/forms` 를 읽는다 — 지금 `--packages` 자리). 모드 A 는 도구 층에 같이 깔린다.

### 7.5 옛 기계 — 지우거나 남기거나

| | |
|---|---|
| `ctx repo new --package · --no-examples · --drop` | 지운다 — 생성은 빈 레포 하나 |
| 콘솔 「새 지식 레포」 의 패키지 · 문서 고르기 · 서식 예시 | 지운다 |
| `ctx package list · show · check · new` | `ctx forms list · show · check` 로 — check 는 서식 파일 모양(세 덩어리 · 머리 필드) |
| `examples` purge · `example-coord` 경고 | **남긴다** — 옛 레포(dpms_wiki · gdi)를 치우는 데 쓴다. 새 레포에는 걸릴 것이 없다 |
| `ops/lib/assemble.mjs` 의 `knowledge-repo-<패키지>/` | 하나로 — `knowledge-repo/`(도구 층 + 빈 `_managed.md` · `_vocab.md` + README) + `forms/` |
| `docs/관리문서패키지/` | 서식집의 설계 기록으로 남긴다 · 07 사용방법은 「큐레이터」 로 고친다 |

## 8. 스킬

| 스킬 | 바뀌는 것 |
|---|---|
| `cdp-save` | ④ 파생 갱신을 **지운다.** 대신 「기록은 홀로 선다」 — 값 · 표 · 결정 · 제약은 본문에, 섹션에 옮길 생각으로 줄이지 않는다. 끝 보고에 「큐레이션 대기 n번째」 |
| `cdp-managed` → **`cdp-curate`** | 대기열 → 기록 묶기(같은 좌표 · 같은 주제) → 판정(반영 · 새 문서 · 기록으로 둠) → 서식 고르기(`forms`) → 섹션 쓰기 규칙 → 판정표 승인 → `save`. 쓰기 규칙은 앞 검토 §4 를 옮긴다: **정본 한 곳 · 나머지는 좌표를 건다 · 본문은 현재형 · 경과는 끝 목록 한 줄씩 · 문서 종류(대상 · 대장 · 정의 · 사건)는 서식의 guide 를 따른다.** 구조 정리(rename · merge · retire · drop)는 그대로 이 스킬에 |
| `cdp-load` | §6 — `pending` 기록 본문 · 정본 좌표 한 단계 |
| `cdp-import` | 들인 문서를 **작업 기록으로만** 남긴다(섹션은 큐레이터). admin 이 부를 때만 그 자리에서 큐레이션까지 |
| `cdp-work` · `cdp-edit` | 섹션 수정 안내를 「큐레이터에게」 로 |

## 10. dpms_wiki 를 옮기는 길 (시범)

1. 새 판 upgrade(도구 층) — docs/ 는 안 바뀐다.
2. admin: [기준선 잡기] — `pending` 이 없는 기록을 `curates` 로.

## 11. 호환 · 위험

| | |
|---|---|
| 옛 클라이언트(writer 세션이 옛 스킬로 `sections` 를 보냄) | `E_FORBIDDEN` 이 사유와 「`work` 만 다시 보낸다」 를 준다 — 기록은 잃지 않는다 |
| 큐레이터 병목 | 대기 · 나이가 화면 세 곳(S3 · S6 · S7)과 `check` warn 에 보인다. 주입이 미반영을 싣는 한 지연은 정보 손실이 아니다 |
| 기록이 얇아 큐레이터가 옮길 재료가 없다 | `thin-body` info 를 writer save 응답에 경고로 올린다 · `cdp-save` 「기록은 홀로 선다」 |
| 동시 기록 | writer 가 섹션을 안 쓰므로 섹션 `E_CONFLICT` 는 큐레이터끼리만 — 지금 틀 그대로 |
| 모드 A | 훅이 막던 파생 누락이 사라지고 warn 만 남는다. 모드 A 는 원래 「정본 층 작성자 하나」 를 강제할 수 없다 |

## 12. 결정 — 권장으로 닫는다

| # | 물음 | 정한 것 | 왜 |
|---|---|---|---|
| K1 | 큐레이터는 누구 | **admin** · 별도 역할은 나중 | 이미 `managed` 연산이 admin 이다. 역할을 하나 더 만들 근거(병목 실측)가 아직 없다 |
| K2 | writer 가 섹션을 써도 되나 | **안 된다**(서버형) · 모드 A 는 warn | 작성자가 둘이면 복제 · 이름 갈림이 다시 생긴다 |
| K3 | 큐레이션 흔적을 어디에 | **작업 기록**(`tags: [curate]` · `curates:`) | 불변 · 한 커밋 · 이미 있는 틀. 별도 파일은 갈라진다 |
| K4 | 서식에서 만든 문서 이름 | 서식 `title` · 관리번호 접두 없음 | 번호는 제출 산출물의 것이다 — 내보내기 틀이 붙인다 |
| K5 | 대기 경고 기준 | 가장 오래된 대기 **14일** | 주간 회의 두 번 — 한 번 놓쳐도 경고 전에 볼 수 있다 |
| K6 | 기존 레포 전환 | **기준선 큐레이션** 한 번 · admin 이 누른다 | 기록 전부를 대기열에 쏟으면 첫날부터 대기열을 안 믿는다 |
| K7 | 묶음을 고르나 | 고르지 않는다 · 서식집 전체를 가로질러 찾는다 | 운영자: 고정 목록은 범용적이지 않다 |
| K8 | 서식 없는 새 문서 | 허용 — `# 제목` 한 줄 | 서식집이 모든 도메인을 덮지 못한다 |
| K9 | `derive-sameday` | 지운다 | 큐레이터가 기록을 묶어 읽는다 — 같은 날 순서 문제가 판정 밖으로 나간다 |
| K10 | 정본 따라가기 깊이 | 한 단계 · 상한 5 | 주입이 불어나지 않게. 두 단계가 필요하면 정본이 잘못 정해진 것이다 |
| K11 | 판 | **v0.25.0** — 원칙이 바뀌는 판 | 스킬 · 검사 · 생성이 같이 바뀐다 |
