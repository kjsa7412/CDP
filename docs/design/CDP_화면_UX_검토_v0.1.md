## 0. 한 줄

운영자의 말이 맞다. **얼굴 셋(소개 · 설명서 / 레포 / 콘솔)이 상단 바를 세 부품으로 따로 그리고, 얼굴 넷을 잇는 링크 묶음이 어느 얼굴에도 없다.** 표식(왼쪽 위 파란 사각)은 얼굴마다 다른 일을 하고(소개 · 콘솔 홈 · 레포 메뉴), 상단 바 높이는 34 · 56 · 48 · 30 · 25px 로 흔들리며, 같은 목적지를 다섯 이름(들어가기 · 내 레포로 · 문서로 · 열기 · 문서로 돌아가기)으로 부른다. 소개로 돌아가는 길은 레포 · 콘솔에 **없다**(로그아웃뿐). **권장안은 부품 하나 — 높이 48px 의 공통 상단 바에 표식(→ 소개)과 얼굴 스위처 넷(소개 · 설명서 · 레포 · 콘솔)을 두고, 얼굴 고유 도구는 가운데 슬롯에만 둔다.** 있는 토큰 · 클래스(`.topbar` · `.seg` · `.who` · `.repomenu` · `.menu`)로 되고, 새 부품은 셋을 합친 `TopBar.jsx` 하나다.

## 1. 운영자의 말 · 검토의 틀

> 지금 화면을 간단하게 검토해보니까 소개, 문서, 콘솔 크게 3개 축인데 각각 화면에서 어떻게 이동하는지 모르겠다. 화면의 통일성이 없다.

| 축 | 무엇을 봤나 | 원칙 |
|---|---|---|
| **내비게이션 모델** | 얼굴 넷을 잇는 전역 장치가 있나 · 표식 클릭의 뜻 · "지금 어디" 표시 · 돌아오는 길 | Nielsen N1 상태 가시성 · N3 통제와 자유 · N6 재인식 |
| **일관성** | 상단 바 높이 · 표식 · 링크 자리 · 이름 · 글자 크기 · 단추 모양 · 칩 · 제목 | N4 일관성과 표준 · Gestalt 유사성 |
| **정보 구조 · 상태** | 얼굴의 역할 분담을 화면이 말하나 · 로그인 뒤 첫 화면 · 빈 상태 · 오류 · 권한 밖 문장 | N2 실세계 언어 · N9 오류 인식 · 복구 · N10 도움말 |
| **효율** | 흔한 여정의 클릭 수와 전체 새로고침 수 | 인지 부하 · Hick |
| **접근성 · 반응형** | 포커스 · 이름 · 대비 · 900px 에서 잘리는 것 | WCAG 1.4.3 · 4.1.2 |

심각도 — **상**: 매일 쓰는 길이 없거나 사용자가 길을 잃는다 · **중**: 돌아갈 수는 있지만 한 번 더 생각하거나 클릭한다 · **하**: 눈에 거슬리거나 접근성 잔손.

**실측만 적었다.** 열어 보지 않은 화면은 없다. 스크린숏 번호는 `../dev/화면_UX_검토_그림/NN_*.png` 의 NN 이다. 계산값(높이 · 폭 · 대비)은 브라우저의 `getComputedStyle` · `getBoundingClientRect` 로 잰 것이다.

### 3.2 이동 지도 — 얼굴 넷 사이의 모든 링크

`a[href]` 와 단추를 화면에서 긁어 모은 것이다(본문 링크 제외). **굵게** 는 끊긴 곳.

| 어디서 → | 소개 `/` | 설명서 `/manual` | 로그인 `/login` | 레포 `/r/<x>/` | 콘솔 `/console` |
|---|---|---|---|---|---|
| **소개(비로그인)** | 표식 · 「소개」(현재) | 「설명서」 상단 · 히어로 · 카드 셋 · 바닥글 | 「로그인」 상단 · 바닥글 · 「들어가기」 히어로 | (로그인 경유) | (로그인 경유) |
| **소개(로그인)** | 표식 · 「소개」 | 「설명서」 | — | 「내 레포로」 상단(파란 단추) · 히어로 · 바닥글 → `/r` = **첫 레포** | 「콘솔」 상단(테두리 단추 · 관리자만) |
| **설명서** | 표식 · 「소개」 | 「설명서」(현재) · 책 3~4 · 목차 | 「로그인」(비로그인) | 「내 레포로」(로그인) → **첫 레포** | 「콘솔」(관리자) |
| **로그인** | 「← 소개」 · 표식 · 「소개」 | 「설명서」 상단 · 아래 · 바닥글 | — | 성공 → `next`(기본 `/r`) | 성공 → `next=/console` |
| **레포** | **없음** — 표식은 레포 메뉴 · 로그아웃(→ `/`)이 유일 | 「설명서」 who 링크 · 도움말 「제품 설명서」 | 로그아웃 → `/` | 레포 메뉴(볼 수 있는 레포 · 쓰기/읽기) | 「콘솔」 who(관리자) · 관리 메뉴 「콘솔로 →」 · 레포 메뉴 「콘솔 › 지식 레포」 |
| **콘솔** | **없음** — 표식은 `/console` | 「설명서」 상단(900px 에서 **사라짐**) | 로그아웃 → `/` | 「문서로」 상단(900px 에서 **사라짐**) · 왼쪽 아래 「문서로 /r」(900px 에서 **이름 없는 아이콘**) → **첫 레포** · 지식 레포 표 「열기」 → 그 레포 | 표식 · 왼쪽 메뉴 일곱 |

**A 의 세부** (목업 [80](../dev/화면_UX_검토_그림/80_목업_지금_상단바셋_vs_권장.png)~[85](../dev/화면_UX_검토_그림/85_목업_권장_권한밖_없는주소.png))

- **한 부품 · 한 높이.** `viewer/src/components/TopBar.jsx` 하나. `height: var(--topbar-h)`(48px) · `flex: none`. 슬롯 셋 — `left`(표식 · 스위처 · 고정) · `center`(얼굴 고유) · `right`(who). `.site-top` · `.con__brand` · `.con__links` 는 사라진다.
- **표식 = 제품 = 소개.** 마크 글자는 언제나 `C`. 레포 첫 글자를 마크에 두던 이유("창을 둘 열면 이름만으로 못 고른다")는 탭 제목 `alpha · CDP` 와 「레포 · alpha」 탭이 받는다.
- **스위처 넷.** 「소개」 「설명서」 「레포」 「콘솔」 — 명사 넷. 「레포」 는 **마지막에 보던 레포**로 가고(§5.2) 누르면 지금의 레포 메뉴가 그대로 열린다(볼 수 있는 레포 · 쓰기/읽기 · 관리자 절). 비로그인은 「소개」 「설명서」 + [로그인]. writer · viewer 에게 「콘솔」 은 없다 — 지금 규칙 그대로.
- **현재 얼굴 표시.** `aria-current="page"` + 액센트 밑줄. 세그(`.seg`)의 "떠 있는 칸" 과 다른 문법이라 얼굴(전역)과 화면 모드(레포 안)가 섞이지 않는다 — 설명서 목차의 현재 절과 같은 선이다.
- **얼굴 고유 도구는 가운데만.** 레포 — 문서 · 그래프 · 관리 세그 · 검색 · 검증. 콘솔 · 사이트 — 비어 있다.
- **who 는 이름 · 역할 · 로그아웃.** 설명서 · 콘솔 링크는 스위처로 갔다. 로그아웃에 `aria-label`.
- **탭 제목 규칙.** `<페이지> · CDP` — `소개 · CDP` · `관리자 설명서 · CDP` · `alpha · CDP` · `콘솔 — 사용자 · CDP`.
- **900px.** 스위처가 표식 메뉴(`C CDP ▾` → 소개 · 설명서 · 레포 gamma · 콘솔 · 로그아웃)로 접힌다 — 라벨이 남는다. 콘솔 왼쪽 아이콘에 `title` · `aria-label`. 레포의 더보기 단추 `flex: none`.
- **로그인 · 마법사 페이지의 바.** 표식 + 「소개」 「설명서」 만. 로그인 중에는 [로그인] 단추를 내지 않는다(지금과 같다).

### 5.2 「문서로」 · 「내 레포로」 의 정의 — 마지막 레포 (P4 · P7) — **권장 A**

| 안 | 무엇 | 값 |
|---|---|---|
| **A · 브라우저가 기억** (권장) | `App` 이 열릴 때 `localStorage['cdp.lastRepo'] = <레포>`. 스위처 「레포」 · 콘솔 · 소개 · 설명서의 레포 링크가 `/r/<last>/`, 없으면 `/r`(서버가 첫 레포). 로그아웃해도 남는다(이름뿐 · 비밀 아님). 볼 수 없게 된 레포면 서버가 §5.3 의 문장으로 받는다. | 서버 손 없음 · 같은 origin 의 세 얼굴이 같은 저장소를 본다 |
| B · 서버가 쿠키로 기억 | `/r/<x>/` 를 열 때 `cdp_last` 쿠키 → `/r` 이 그리로. | 서버 변경 · 효과는 A 와 같다(쿠키도 브라우저별) |
| C · 「문서로」 를 레포 목록으로 | `/r` 을 목록 페이지로. | §5.1 C 와 같은 이유로 하지 않는다 |

로그인 뒤 첫 화면은 **레포 그대로**(설계 "로그인 뒤 바로 문서") — 다만 A 로 마지막 레포다. 관리자에게 콘솔 경고를 레포 상단에 배지로 내는 것은 하지 않는다(§4.7 "이 화면은 사람이 열었을 때만 말한다").

### 5.3 없는 주소 · 권한 밖 레포 (P5 · P6) — **권장: 문장 페이지**

- **서버.** `Accept: text/html` 인 GET 의 **미지 경로** → `index.html`(화면의 「없는 주소입니다」 — 소개 · 설명서 · 레포 · 콘솔 링크 넷). API 접두(`/api` · `/admin` · `/site` · `/mcp` · `/kit` · `/workrepos` · `/repos` · `/packages` · `/me`)는 그대로 JSON.
- **권한 밖 · 없는 레포.** `/r/<x>/…` 가 볼 수 있는 레포가 아니면 조용한 302 대신 `/r?from=<x>` 로 보내고, 화면이 "**그 주소의 레포는 열 수 없습니다** — 없거나 이 계정에 할당되지 않았습니다" + 볼 수 있는 레포 단추(목업 [85](../dev/화면_UX_검토_그림/85_목업_권장_권한밖_없는주소.png)). 없는 것과 권한 밖에 **같은 문장**을 쓰므로 D4 · §4.6(존재를 알리지 않는다)은 그대로다.
- 대안 — 조용한 리다이렉트 + 토스트. 얼굴을 새로 여는 순간이라 토스트를 쿼리로 넘겨야 하고, 3초 뒤 사라진 문장은 나중에 "왜 alpha 지" 를 설명하지 못한다 → 문장 페이지.
- `/console/<없는 페이지>` 는 현황으로 `replace` 하고 메뉴 현재 표시를 맞춘다.

### 5.4 상단 바 높이 · 설명서 레이아웃 (P8 · P13) — CSS 만

```css
/* site.css */
:root[data-face='site'] #root { height: auto; }          /* 헤더 · 바닥글이 눌리지 않게 */
.site-top, .site-foot { flex: none; }                    /* TopBar 로 합치기 전이라도 이것만으로 34 → 56 */
.man__nav { position: sticky; top: var(--topbar-h); max-height: calc(100vh - var(--topbar-h)); overflow-y: auto; align-self: start; }
/* console.css */
.con .topbar { height: var(--topbar-h); flex: none; }    /* 30 · 25 → 48 */
```

높이는 **48**(레포 기준 · 권장). 대안 56(소개 기준)은 문서 · 그래프에 세로가 귀한 레포 화면에서 8px 을 매일 잃는다. 사이트에서 바는 `position: sticky` — 긴 설명서를 읽는 동안 스위처가 보인다.

### 5.6 900px · 접근성 · 대비 (P19 · P20 · P21 · P22)

- 스위처 → 표식 메뉴(§5.1). 콘솔 왼쪽 아이콘에 `title` · `aria-label`(`.astep__txt` 를 `display:none` 대신 시각적으로만 숨기거나 `aria-label` 을 준다). 「문서로」 아이콘 항목은 스위처가 있으니 뺀다.
- **부제 대비** — 안 A(권장): 12px 미만 글자(`.astep__s` · `.acard__hint` · `.field__h` · `.site-foot` · `.man__crumb` · `.sub`)를 `--text-2`(6.3:1)로. 토큰 값은 손대지 않는다. 안 B: `--text-3` 자체를 `#68717f`(4.4:1) 부근으로 — 그래프 · 상태바 · 세그 비활성 등 `--text-3` 를 쓰는 모든 자리가 같이 어두워진다 → A.
- 더보기 단추 `flex: none`. 로그아웃 `aria-label="로그아웃"`. 마법사 입력은 콘솔의 `Field` 부품(`htmlFor` 를 묶는다)을 쓴다.
- 테마 키 하나 `cdp.theme` — 세 얼굴이 같이 읽는다(`main.jsx`). 레포 설정의 테마 세그가 그 키를 쓴다.

### 5.7 첫 설정 여정 (P16 · P17 · P18)

- 마법사 ③ 의 상단 — 레포 0 이면 「레포」 를 내지 않는다(`info.repos === 0`). 「콘솔」 하나만.
- `POST /setup` 응답에 재인증 쿠키(`cdp_su` · 15분)를 함께 — 방금 원문을 본 사람이다. D5 의 취지(세션 탈취 한 번으로 명부가 바뀌지 않게)와 어긋나지 않는다.
- 새 레포 뒤 `load()` 가 서버 캐시 갱신 뒤에 오게(서버가 `store.ensure(name)` 뒤 응답) — 표가 바로 채워진다.

## 부록 B. 실측 방법

- Playwright(chromium headless) 1280×800 라이트 · 900×760 다크. 실서비스는 GET 과 잘못된 토큰 한 번뿐 — 운영자 토큰은 넣지 않았다. 개발용 서버 토큰은 `ctx serve token` 으로 새로 발급했고 문서에 적지 않았다.
- 링크 목록은 각 화면의 `a[href]` · `button` 을 자리(상단 · 왼쪽 메뉴 · 바닥글 · 오버레이)로 갈라 모은 것. 상단 바 계산값은 `getBoundingClientRect` · `getComputedStyle`. 높이 원인은 `flex: none` 을 임시로 주고 다시 재서 확인했다.
- 대비는 WCAG 상대 휘도 공식으로 토큰 값에서 계산했다.
- 스크립트는 세션 스크래치패드에 두었고 레포에 넣지 않았다 — 재현은 TODO ⑨ 의 재촬영 항목에 절차로 적는다.
