## 0. 한 줄

**지식이 생기는 출처는 셋이다. ① 세션에서 작업하고 바로 save ② 이미 써 둔 문서 파일 ③ 작업 문서가 모인 폴더 · 레포. 지금 CDP 가 제품으로 받쳐 주는 것은 ① 하나뿐이다.**

②는 세션 스킬(cdp-save 편입)로 한 건씩 손으로 들여야 한다. ③은 `ctx import-dir`(md 만 · 좌표 없음 · **save 를 우회해 로컬에 직접 쓴다**)와 `ctx seed`(git 문서 레포를 관리 문서로 세움 · 큐레이터 전용 · 한 번 쓰는 도구)로 갈라져 있다. md 가 아닌 문서의 본문을 뽑는 곳은 없다. 같은 원본을 두 번 넣는 것을 막는 장치도 없다.

**권장안의 뼈대**

- **②와 ③은 같은 파이프라인 `ctx ingest` 의 입력 크기 차이다.** 결정론 단계(목록 · 변환 · 해시 · id · 적용)와 진행 상태는 `ctx` 가 맡는다. 판단 한 단계(성격 · 나눔 · 날짜 · 좌표 후보)만 **사용자가 직접 로그인한 `claude -p`** 를 자식 프로세스로 부른다.
- **결과는 언제나 작업 기록이다.** save 로 들어가 대기열에 서고, 관리 문서 반영은 큐레이터가 한다.
- **서버는 LLM 을 부르지 않는다.** 서버는 진행 보고를 받아 보여 주기만 한다.
- **화면은 보기 · 작업실 · 서버 세 영역으로 나눈다.** 보기에는 쓰는 단추가 하나도 없다. 「지식 생성」 은 작업실의 첫 메뉴다.

## 3. 생성 경로 — 「CLI」 를 어떻게 읽나

### 3.1 세 해석

| | (a) ctx 가 `claude -p` 를 불러 save 까지 | (b) 사용자 세션의 스킬(cdp-ingest) | **(c) 결합 — 권장** |
|---|---|---|---|
| 누가 도나 | ctx 하나가 끝까지 | 사용자의 Claude Code 대화 | ctx 가 목록 · 변환 · 상태 · 미리보기 · save. LLM 한 단계만 `claude -p` |
| 결정론 | LLM 이 섞여 재실행 결과가 흔들린다 | 세션 기억에 기댄다 | 결정론 단계와 LLM 산출을 파일로 고정한다 |
| 중단 재개 | 직접 짜야 한다 | 세션이 끊기면 처음부터 | 단계 산출물 파일로 이어 간다 |
| 승인 | 끼울 자리가 애매하다 | 대화 안(지금의 cdp-save) | 미리보기 표를 사람이 승인한 뒤에만 적용 |
| 200건 규모 | 된다 | 컨텍스트와 피로로 무너진다 | 파일마다 자식 프로세스 하나 · 컨텍스트가 섞이지 않는다 |

**「CLI 로그인은 사용자가 진행」 은 LLM CLI(Claude Code) 의 로그인으로 읽는다.** ctx 는 그 자격 증명을 읽지도 넘기지도 않는다. `doctor` 가 「로그인되어 있지 않다 — `claude` 를 한 번 실행해 로그인」 이라고 말할 뿐이다. CDP 서버 토큰은 별개로 `ctx login` 이 다룬다(§4.6).

### 3.2 원칙과의 정합

| 원칙 | (c) 에서 |
|---|---|
| I11 서버는 LLM 을 부르지 않는다 | LLM 은 사용자 PC 의 `claude` 가 부른다. 키 · 비용 · 로그인은 그 사람 것이다 |
| I2 쓰는 길은 save 하나 | 자식 `claude` 에는 save 를 허용하지 않는다(허용 목록 `match` · `where` · `docs` · `search` · `Read`, 금지 목록 `save` · `Edit` · `Write` · `Bash`). 쓰기는 ctx 가 승인된 초안으로 한다 |
| R8 좌표를 추측하지 않는다 | LLM 이 내는 것은 **후보와 근거 인용**이다. touches 로 올리는 것은 사람의 승인이고(cdp-save ④ 와 같다), 관리 문서 반영은 큐레이터다 |
| I6 writer 는 기록만 | ingest 는 writer 권한으로 충분하다. 보내는 것은 기록 · 첨부 · 어휘 add 뿐이다 |
| I9 레포에는 지식만 | 상태 폴더는 지식 레포 밖에 둔다. 원천 폴더 · 레포에도 쓰지 않는다 |
| **M1 에이전트는 ctx 를 부르지 않는다** | 방향이 반대다 — **사람이 ctx 를 부르고, ctx 가 에이전트를 부르며, 에이전트는 MCP 읽기만 한다.** M1 문구에 이 예외를 한 줄 적는다(G18) |
| S8 기계는 판정하지 않는다 · S13 세우는 흔적은 `_seed.json` | ingest 기록은 대기열에 선다. `_seed.json` 에 넣지 않는다 — 넣으면 「판정 없이 반영됨」 이 되어 대기열을 건너뛴다(`curation.js:26`) |

### 3.3 ③ 의 두 갈래

| ③ 의 모양 | 길 | 결과 |
|---|---|---|
| PC 의 폴더 · 아무 git 레포의 작업 문서 | **`ctx ingest`**(새것) | 작업 기록 → 대기열 |
| git 서버의 **문서 레포**를 관리 문서로 옮겨 세우기 | 지금의 `ctx seed` · MCP `source` — **유지** | 관리 문서 + 반영된 기록 |

ingest 가 「정의서 성격(대상의 지금)」 문서를 많이 보면 끝 출력에 「세우기(출처)가 맞을 수 있다」 를 한 줄 낸다. 대상이 git 원격을 가진 레포면 계획 보고에 `git.remote` 를 실어 화면도 같은 안내를 띄운다.

## 4. 파이프라인 `ctx ingest`

### 4.1 단계

| # | 단계 | 누가 | 산출물 | 위치 | 멱등 · 재개 |
|---|---|---|---|---|---|
| 1 | 대상 지정 | 사람 | `run.json` — 경로(파일 · 폴더 · git) · glob · 제외 · 브랜치/커밋 범위 · 지식 레포 · 상한 | 상태 폴더 | runId = 대상과 설정의 해시 |
| 2 | 목록(plan) | ctx · 결정론 | `files.json` — 상대 경로 · 크기 · **git blob sha** · 형식 · 날짜/작성자 근거(importdir 재사용) · 건너뜀 사유 | 상태 폴더 | 같은 blob 이 서버에 있으면 `done` |
| 3 | 변환 | ctx + 외부 도구 | `conv/<sha>.md` · 뽑은 그림 · 변환 경고 | 상태 폴더 | 원본 해시가 키 |
| 4 | 판단 | `claude -p` | `draft/<sha>.json`(§4.3) | 상태 폴더 | 파일이 있으면 건너뛴다 · `--redo <file>` 로만 다시 |
| 5 | 미리보기 · 승인 | ctx + 사람 | 파일마다 【좌표 판정】 표 · 기록 미리보기 · 승인 표시 | 상태 폴더(`review.md`) | 승인은 draft 안의 값 |
| 6 | 적용 | ctx → 서버 | 첨부 업로드 → `save(dryRun)` → 묶음 `save`(§5.1) | **서버** work/ | blob 중복은 서버가 거절(§5.2) |
| 7 | 대조 · 재실행 | ctx | `status` — 원본 바뀜 · 새 파일 · 서버에 없음 · 대기 · 반영 | 상태 폴더 + 서버 읽기 | `--resume` · `--refresh` |

**상태 폴더**는 기본값을 지금 폴더의 `.cdp-ingest/<runId>/` 로 하고, 그 안에 `*` 한 줄짜리 `.gitignore` 를 둔다. 지식 레포 클론 안에서 부르면 거절한다(I9). `--state <dir>` 로 바꿀 수 있다.

> **구현에서 바꿨다(v1.7.0)** — 상태 폴더는 **이 PC 의 `~/.cdp/ingest/<run 해시>/`**(환경변수 `CDP_INGEST_DIR`)다. 지금 폴더에 두면 원천 폴더 안에서 `ctx ingest .` 를 돌리는 흔한 경우에 원천을 더럽힌다 — 집 폴더면 원천에도 지식 레포에도 쓰지 않는다. 지식 레포를 대상으로 주면 거절한다. run 해시는 대상 · 거름 · 레포로 정해 다시 돌리면 같은 폴더를 찾는다. `--state` 는 두지 않았다.

### 4.2 변환

ctx 번들에는 의존성을 더하지 않는다는 원칙이 있다(`core/zip.js` 머리말). 그래서 두 층으로 나눈다.

| 형식 | 1순위 | 없으면 |
|---|---|---|
| md · txt | 그대로 | — |
| docx · pptx · xlsx · hwpx | zip + XML 본문을 Node 에서 직접 추출 — `core/zip.js` 에 읽기를 더한다. 표는 md 표, xlsx 는 시트마다 표 | `pandoc` · `soffice --headless` 를 감지하면 쓴다 |
| pdf | `pdftotext -layout`(poppler) | LLM 단계에서 `claude` 가 직접 읽는다. 원본 pdf 는 첨부로 보존할 수 있다 |
| hwp(바이너리) | `soffice` → docx → 위의 길 | 「변환 불가 — 사람이 md 로」 경고 후 건너뛴다 |
| 스캔 pdf · 이미지 | OCR 은 하지 않는다 | 경고 |

원본 오피스 파일은 레포에 넣지 않는다. 출처 문자열(§5.2)로 되짚는다. 이로써 세우기 검토 §6 의 「xlsx · hwp 내용은 사람이 md 로」 결정을 다시 연다 — 변환은 하되, **변환 경고를 미리보기 맨 위에 두고, 변환에 실패한 파일은 들이지 않는다.**

### 4.3 판단 단계의 계약 — 본문은 쓰지 않는다

편입 규칙은 「원문 보존 · 요약 금지」 다. 그래서 **LLM 은 본문을 생성하지 않는다.** 변환된 md 에서 나눌 자리를 **줄 범위**로만 지정하고, ctx 가 그 범위를 잘라 본문을 만든다. 머리에는 `원문 작성: … · 편입: …` 한 줄과 원문 제목을 붙인다. 본문에 환각이 들어갈 자리가 없다.

```
claude -p "<kit/ingest/prompt.md + 파일 경로>" \
  --output-format json --max-turns 8 \
  --mcp-config <ctx 가 만든 임시 설정: CDP 서버 · Bearer 토큰> \
  --allowedTools "mcp__cdp__match,mcp__cdp__where,mcp__cdp__docs,mcp__cdp__search,Read" \
  --disallowedTools "mcp__cdp__save,Edit,Write,Bash"
```

```json
{ "nature": "결정|정의|혼합|아젠다|제외", "records": [{
   "lines": [12, 88], "title": "…", "date": "2026-08-14", "dateEvidence": "본문 '일시 2026년 8월 14일'",
   "touches": [{ "coord": "screen:BZA021", "verb": "변경", "quote": "소속 컬럼을 추가하기로", "registered": true }],
   "excluded": [{ "coord": "screen:BZA022", "why": "이번 범위 아님" }],
   "vocab": [{ "coord": "code:HR130", "label": "업무구분", "aliases": ["업무구분코드그룹"] }],
   "open": ["외부 ERP 결재 취소 자동 반영 — 회신 대기"] }] }
```

- ctx 가 스키마를 검증한다. 틀리면 한 번만 다시 시도하고, 그래도 틀리면 그 파일을 실패로 기록한다.
- 프롬프트 `kit/ingest/prompt.md` 는 `편입.md` 를 **포함해서** 만든다. 규칙 원문은 한 곳에 둔다.
- 나눔은 최상위 헤딩에서만 한다. 안 나누는 것이 기본이다. 조각마다 문서 제목과 출처 위치 머리줄을 단다.

### 4.4 미리보기 · 승인 기본값

| 후보 | 기본 |
|---|---|
| `registered: true` + 인용 있음 | 「넣는다」 미리 체크 |
| 미등재 좌표 · 새 타입 · 어휘 이름 제안 | 체크 **안 함**. 사람이 고르지 않으면 `tags: touches?/<좌표>` 로 보존한다 |
| 좌표 0개 | `touchesEmpty: "들이기 — 큐레이터 판정"` + 경고 |
| 일괄 승인 | `--approve registered` 만 있다. 전부 승인하는 옵션은 두지 않는다 |

큐레이터 스킬에 `touches?/` · `touches/` 태그를 읽고 좌표를 정하는 절차를 더한다(E4).

### 4.5 비용 통제

| 장치 | 기본 |
|---|---|
| `--plan`(1~3단계 · LLM 없음) | **기본 동작.** 파일 수 · 변환 뒤 글자 수 · 추정 토큰을 낸다 |
| `--max-files` · `--max-chars` | 50 · 200k 자/파일. 넘으면 「나눠 들임」 후보로 표시 |
| `--budget <토큰>` | 누적 추정이 넘으면 멈추고 기록한다 |
| `--concurrency` | 2(LLM 단계만 · 적용은 언제나 하나씩) |
| `--no-llm` | 3단계 뒤 곧바로 5단계. 좌표를 비운다(옛 import-dir 동작) |

## 5. 데이터 · 동시 기록

### 5.1 묶음 save — `records[]`

- `core/save.js` 한 곳에 **기록 묶음 입력**을 더한다.
  - 받는 것은 기록 · 첨부 · 어휘 add 뿐이다. `sections` · `managed` · `edits` · `vocab op` 는 거절한다. applied 대조가 생기지 않아 낙관 잠금 의미론이 그대로다.
  - 뮤텍스를 한 번 잡고, `loadRepo` 2회와 커밋 하나로 N 건을 쓴다.
- **한 묶음은 20건 이하.** 남의 save 가 기다리는 시간의 상한이 묶음 하나의 길이가 된다.
- **전부 또는 전무.** 검사 오류는 기록 id 별로 돌려주고, CLI 가 그 기록만 빼고 다시 보낸다.
- **CLI 는 묶음을 하나씩 순서대로 보낸다.** 병렬로 보내지 않는다.
- ingest 는 미러 결과를 기다리지 않는다(`save.js:493` 의 1.5초 대기를 묶음에서는 건너뛴다).

### 5.2 id · 출처 · 중복

| 항목 | 결정 |
|---|---|
| id | 원본에서 정한다 — `YYYY-MMDD-<출처조각>-<이름>-<blob 앞 7자>`. LLM 출력은 id 에 섞지 않는다 |
| source | 정형 문자열 `<레포 또는 폴더 이름>@<commit 또는 ->/<경로>#blob:<git blob sha>`. git 이 아닌 파일도 `git hash-object` 로 blob sha 를 계산해 키를 한 종류로 둔다. 프론트매터 스키마는 바꾸지 않는다 |
| 잡 표시 | `tags: [ingest/<runId>]`. LLM 을 거쳤으면 `ingest-llm` 도 단다 |
| 중복 판정 | **save 가 뮤텍스 안에서** 같은 blob 을 가진 기록을 찾으면 `E_EXISTS` 와 그 id 를 돌려준다. 두 사람이 같은 폴더를 동시에 넣어도 여기서 막힌다. 판정은 core 한 곳이다 |
| 원본 갱신 | 경로가 같고 blob 이 다르면 **새 기록**을 쓴다. 머리줄에 `이전 판: <id>` 를 남긴다. `supersedes` 는 쓰지 않는다 — supersedes 는 「틀린 기록의 정정」 이고, 이전 판은 그때의 사실이었다 |
| git 레포 원천 | `core/sourcerepo.openSource`(ls-tree · show)를 다시 써서 정해진 commit 을 기준으로 읽는다 |

### 5.3 진행 상태 — 둘로 나눈다

| | 어디 | 무엇 | 정본인가 |
|---|---|---|---|
| **로컬 상태 폴더** | 사용자 PC `.cdp-ingest/<runId>/` | 목록 · 변환본 · draft · 승인 | **실행의 정본** — 재개는 여기서 |
| **서버 잡 레코드** | `<data>/jobs/<레포>/<runId>.json`(git 밖) | 단계 · 파일별 결과(draft/skip/fail) · 수 · 마지막 보고 시각 | 보고일 뿐. 없어져도 「무엇이 들어갔나」 는 기록의 source · 태그에서 다시 센다 |

- 보고 한 번이 하트비트다. 끝나지 않은 잡이 **15분** 넘게 조용하면 화면은 「멈춤(마지막 보고 시각)」 으로 그린다. 진행률은 짐작하지 않는다(불변조건 7).
- 잡끼리는 막지 않는다. 순서는 뮤텍스가, 중복은 blob 이 막는다.
- 재개는 같은 명령을 다시 돌리는 것이다. 들어간 것은 blob 판정이 건너뛴다. 서버 잡에 커서를 두지 않는다.

### 5.4 대기열 홍수

| 문제 | 결정 |
|---|---|
| 원문 날짜 때문에 맨 앞에 선다 · 거짓 stale 경고 | ingest 기록의 대기 나이는 **들어온 커밋 시각**으로 잰다. 계산이고, 저장하는 값은 없다(I8) |
| 수백 줄이 한 번에 선다 | 대기열에서 `ingest/<runId>` 로 접은 한 줄(「수집 X · 312건 · 10-20」)을 보인다. 기본 정렬은 사람의 세션 기록이 먼저다 |
| 일괄 「기록으로 둠」 | 상한 50(`ctx-mcp-serve.mjs:1825`)은 그대로 두고 화면이 잡 단위로 50건씩 나눠 보낸다 |
| 반영 | 묶음 「반영」 단추는 만들지 않는다. 반영은 세션의 cdp-curate 가 좌표별로 한다 |

### 5.5 권한 · 용량

- 수집은 **writer 이상**이 돌린다. 사람의 토큰을 쓴다 — author 가 사람이어야 기록의 책임이 선다. 수집 전용 토큰 범위는 만들지 않는다.
- 자식 `claude` 에 넘기는 토큰도 writer 토큰이다. 도구 허용 목록과 금지 목록 두 겹으로 save 를 막는다. 읽기 전용 토큰(토큰 scope)은 열린 질문이다(§9 Q3).
- staging 에 **사용자별 총량 상한(500MB)**을 두고, 넘으면 413 을 낸다. 대용량 바이너리는 목록 단계에서 기본으로 건너뛰고 사유를 남긴다. 크기 상한(본문 2MB · 첨부 10MB · 묶음 30MB · 20개)은 목록 단계에서 미리 거른다.

  상태는 보고된 것만 그린다 — 대기(명령을 안 돌림) · 실행 중 · 승인 대기 · 저장됨 · 일부 실패 · 멈춤. 「대기」 열은 저장된 기록의 지금 큐레이션 상태를 읽을 때 센다.
- **상세** — 파일별 결과(초안 · 첨부 · 건너뜀 · 실패) · 좌표 판정 요약 · 사유 · 재실행 명령(`--only failed`). 줄을 펴면 초안 본문 · 넣은 좌표와 뺀 좌표 · dryRun 경고가 나온다.
- 남의 잡은 큐레이터만 본다. writer 가 남의 잡 주소를 열면 **404** 다(PC 경로를 흘리지 않는다).

### 6.4 잡 API(`/api/<레포>/jobs`)

> **구현에서 바꿨다(v1.8.0)** — 파일마다 따로 부르는 `plan` · `files/<n>` 대신 **`POST /jobs/<id>/report { phase, files: [{ rel, status, … }] }` 하나**로 모았다(한 번에 여럿 · 같은 rel 은 나중 것이 이긴다).
> 파일 상태는 planned · drafted · saved · exists · have · skipped · asset · failed. 승인(`approve`)은 v1.9 그대로다 — 지금 승인은 CLI 의 `review.md`.
> 잡은 `ctx ingest --analyze · --apply` 가 처음 돌 때 스스로 만들고(run.json 에 기억), 화면 「새 들이기」 가 만든 잡은 `--job <id>` 로 잇는다.

| 요청 | 누가 | 하는 것 |
|---|---|---|
| `POST /jobs` `{ kind, path, options }` | write | `{ id }` |
| `GET /jobs[?mine=1]` · `GET /jobs/<id>` | 본인 · curate | 남의 것이면 404 |
| `POST /jobs/<id>/plan` `{ files:[{rel,size,sha}], cli:{llm,version}, git? }` | 주인 | running |
| `POST /jobs/<id>/files/<n>` `{ status: draft\|skip\|fail, draft?, error? }` | 주인 | 보고 = 하트비트 |
| `POST /jobs/<id>/done` · `/cancel` | 주인 · (cancel 은 curate 도) | — |
| `POST /jobs/<id>/approve` `{ files:[n] }` | 주인 · **2차(v1.9)** | 서버가 묶음 save 로 쓴다. 파일마다 기록 id 또는 오류를 낸다 |

## 8. 갈래끼리 어긋난 곳 · 닫은 방법

| 쟁점 | 갈래 의견 | 닫음 |
|---|---|---|
| 명령 이름 | `ctx ingest`(②) · `ctx collect`(③) | **`ctx ingest`**. 화면 이름은 「지식 생성」 |
| 진행 상태 자리 | 사용자 PC 에만 두고 화면은 기록에서 계산(②) · 서버 `data/jobs`(③ ④) | **둘 다** — 실행의 정본은 로컬, 서버 잡은 보고(§5.3) |
| 승인 자리 | CLI `--review`(②) · 화면 승인(③) | **v1.7~v1.8 은 CLI, v1.9 에 화면 승인을 더한다.** 승인은 판단이 아니라 writer 의 save 다 |
| 원본 갱신 | `supersedes`(④) · 새 사건(②) | **새 기록 + 머리줄의 이전 판 id.** supersedes 는 정정 전용이다 |

| 묶음 크기 | ≤20(④) | 그대로 |

| G1 | 화면은 보기 · 작업실 · 서버 세 영역이다. 스위치는 왼쪽 메뉴 안에 두고 주소는 바꾸지 않는다 |
