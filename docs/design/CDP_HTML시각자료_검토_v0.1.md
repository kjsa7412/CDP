# CDP HTML 시각 자료 검토 v0.1
> **v1.0 이후** — HTML 시각 자료의 규칙(sandbox CSP · 테마)은 그대로다 — [`CDP_시스템설계서_v2.0.md`](CDP_시스템설계서_v2.0.md) §5 · [`CDP_화면_설계서_v1.0.md`](CDP_화면_설계서_v1.0.md) §9.

> 운영자 질문(2026-10-06): 클로드 코드는 문서를 쓰면서 시각 자료를 **HTML 한 장**으로 내놓는다(예:
> `C:\dpms\SCADA_연계_구성도.html`). 그 한 장이 설명과 도면을 함께 담고 있어서, 어떤 부분은 md 보다 이해가 빠르다.
> 이것을 지식 문서로 쓰려면 어떻게 해야 하나? 문서의 asset 을 화면에서 고를 수 있게 하는 것이 좋은가?
> 결정은 전부 권장안이다(운영자 규칙). 검토만 한다. 구현은 TODO md 를 쓴 다음에 한다.

---

## 0. 결론 먼저

- **HTML 을 문서(층)로 받지 않는다. 그림 · PDF 와 같은 첨부로 받고, 화면 안에서 연다.**
  좌표 · 섹션 · 파생 · 검색 · AI 읽기는 지금처럼 md 가 맡는다. HTML 은 그 md 에 딸린 **「보는 자료」**다.
- **asset 을 화면에서 고를 수 있게 하는 것은 맞다.** 다만 트리에 따로 두지 않고 **문서 머리의 탭 줄**에 둔다.
  탭 줄은 「본문 | SCADA 연계 구성도」 모양이다. 자료는 그것을 들인 기록에 딸려 있어야 「왜」 가 같이 남는다.
- **지금 이미 구멍이 하나 있다(H0).** 레포에 들어간 `.html` 을 파일 API 가 아무 보호 없이 같은 출처로 낸다.
  HTML 을 받든 안 받든 이것은 먼저 막는다.

## 1. 실물 — `SCADA_연계_구성도.html`

| 항목 | 값 |
|---|---|
| 크기 | 82 KB · 파일 하나(그림 · 스크립트 외부 파일 없음) |
| 스크립트 | **없음.** 인터랙션은 CSS `:hover` 한 곳과 넓은 도면의 가로 스크롤 |
| 내용 | 인라인 SVG 도면 3장 · 표 18개 · h2 13절(네트워크 구성도 · 연결 구간 · 통신 규칙 · 제어 시퀀스 · 장애 판정 · 프레임 규격 초안 · 보안성 검토 대응 · **확인 목록** …) |
| 외부 자원 | Google Fonts(IBM Plex) — 닿지 않으면 맑은 고딕으로 떨어진다 |
| 테마 | `prefers-color-scheme` + `:root[data-theme]` 로 밝게 · 어둡게 둘 다 |
| 자리 | 작업 레포(`C:\dpms`) 루트 · 커밋 안 됨(`??`). 옆의 md 두 개(사전조사 · 프레임규격 초안)가 이 파일을 가리키지 않는다 |

이것이 클로드 코드가 내놓는 시각 자료의 보통 모양이다. **파일 하나, 스타일과 SVG 가 인라인, 테마가 둘,
외부는 CDN 몇 곳뿐이다.** 스크립트가 있는 것(d3 · Chart.js · 접기 · 탭)도 흔하므로 스크립트를 받는 것을 기본으로 설계한다.

이 파일은 「자료」 이면서 **지식**도 담고 있다. 프레임 규격 초안 · 책임 구간 · 확인 목록은 좌표에 붙어 다른
문서로 파생돼야 하는 내용인데, HTML 안에 있으면 검색 · `load` · 파생 어디에도 걸리지 않는다. 그래서 2절과 4절이 필요하다.

## 2. HTML 을 어디에 두나 — 후보

| | 방법 | 판정 |
|---|---|---|
| ㉠ | HTML 을 **세 번째 층**(문서)으로 받는다 — `work/*.html` · `docs/**/*.html` | ✗ — 문서 판정(`layerOf`) · YAML 프론트매터 · `#` 제목 섹션 · save/edits · docrefs · 렌더/살균이 전부 md 를 전제로 한다. 프론트매터 자리 · 섹션 경계 · 섹션 고치기를 HTML 용으로 새로 만들어야 하고, AI 가 섹션을 고칠 때 태그가 깨진다. git diff 도 읽기 어렵다 |
| ㉡ | HTML 을 **md 로 바꿔** 넣는다(SVG 는 그림으로 떼고 표는 md 표로) | △ — 검색 · 파생에는 좋다. 그러나 이번 질문의 요점인 「한 장으로 보는 이해」 가 사라진다. 도면 · 색 구분 · 가로 스크롤 판이 표와 그림 조각으로 흩어진다 |
| ㉢ | **첨부로 받는다** — 그림 · PDF 와 같은 길(`work/assets/<id>/<이름>.html`). 화면은 **격리된 틀(sandbox)** 안에서 그대로 연다. 지식(요지 · 결정 · 확인 목록)은 같은 기록의 md 본문에 적는다 | ○ — 이미 있는 길(v0.20.0 올리기 API · `save assets[]` · 첨부 목록)에 종류 하나를 더하는 정도다. 보는 맛은 HTML 이, 찾고 엮는 일은 md 가 맡는다 |
| ㉣ | 레포 밖(Artifact · 사내 웹)에 올리고 링크만 둔다 | ✗ — 폐쇄망 반입 · zip 내려받기 · clone 에 따라가지 않는다. 그림 첨부 검토 ㉤ 과 같은 이유다 |

**결정 — ㉢.** ㉡ 은 버리지 않는다. 4절의 「요지 md」 가 ㉡ 의 가벼운 판이다. 지식이 되는 부분만 md 로 옮겨 적고,
나머지 도면과 맥락은 HTML 이 들고 간다.

## 3. 보안 — HTML 은 「문서」 다

SVG 를 거절한 이유(그림 첨부 G5 · A4)가 HTML 에는 그대로, 더 크게 걸린다. HTML 은 스크립트를 담는 문서다.
**이 출처에서 열리면 그 스크립트가 보는 사람의 세션으로 돈다.** viewer 가 연 자료가 writer · admin 의 API 를 부를 수 있다는 뜻이다.

### 3.1 지금 있는 구멍 — H0

`GET /api/<repo>/file?path=x.html` 은 `content-type: text/html` 로 낸다. CSP 는 `.svg` 에만 붙는다
(`viewer/server/adapter/read-api.js:152`). 본문의 상대 링크 `[구성도](x.html)` 를 누르면 G4 규칙대로
**새 탭에서 파일 API 로** 열린다(`DocView.jsx:114`).

→ git push · 「origin 과 맞추기」 · `importdir` 처럼 save 를 거치지 않는 길로 레포에 `.html` 이 들어가면,
**그것을 연 사람의 세션 쿠키로 같은 출처 스크립트가 돈다.** writer 가 admin 화면을 여는 것과 같다(권한 상승).
이번 기능과 상관없이 막아야 한다.

### 3.2 결정 — 두 겹 격리

| | 결정 | 왜 |
|---|---|---|
| S1 | 파일 API 가 `.html` · `.htm` 에 **`content-security-policy: sandbox allow-scripts allow-popups allow-popups-to-escape-sandbox`** 를 붙인다. `allow-same-origin` · `allow-forms` · `allow-top-navigation` 은 주지 않는다. `.htm` 은 MIME 표에도 넣는다 | 응답 헤더로 거는 sandbox 는 **어떻게 열든**(틀 안 · 새 탭 · 주소 직접) 문서를 불투명 출처로 만든다. 스크립트는 돌지만 이 서버의 쿠키 · 저장소 · DOM 에 닿지 못한다. H0 이 이것으로 닫힌다 |
| S2 | 같은 헤더에 자원 규칙을 둔다 — `default-src 'none'; script-src 'unsafe-inline' <CDN>; style-src 'unsafe-inline' https://fonts.googleapis.com <CDN>; font-src data: https://fonts.gstatic.com <CDN>; img-src data: blob:; connect-src 'none'; frame-ancestors 'self'`. `<CDN>` = `cdnjs.cloudflare.com` · `cdn.jsdelivr.net` · `unpkg.com` | 클로드 코드가 내놓는 시각 자료가 쓰는 곳이 이 몇 곳뿐이다(아티팩트 규약과 같은 목록). `connect-src 'none'` · `img-src` 를 좁혀서 **밖으로 내보내는 길**을 막는다. `frame-ancestors 'self'` 이므로 남의 사이트가 이 자료를 틀로 싸지 못한다 |
| S3 | 화면의 틀(`<iframe>`)에도 `sandbox="allow-scripts allow-popups allow-popups-to-escape-sandbox"` · `referrerpolicy="no-referrer"` · `loading="lazy"` 를 건다 | 헤더를 빠뜨린 서버(옛 판 · 프록시가 지운 경우)에서도 한 겹이 남는다 |
| S4 | 올리기(`POST /assets`)는 HTML 을 **바이트로 가린다** — BOM · 공백 · 주석 뒤 첫 태그가 `<!doctype html` 또는 `<html` 이고, UTF-8 로 풀린다. 상한은 그대로 10 MB | 그림과 같은 규칙(A4)이다. 다른 것을 `.html` 이라 부르며 올리지 못한다 |
| S5 | 로컬 뷰어는 파일 주소에 토큰(`&t=`)이 붙는다. 틀 안 스크립트는 자기 `location` 을 읽을 수 있다. **남는 위험으로 적어 둔다** — 밖으로 나가는 길이 S2 로 좁고, 토큰은 그 PC 의 localhost 에서만 쓸모가 있다 | 서버형은 쿠키라서 주소에 비밀이 없다. 로컬에서 HTML 만 따로 1회용 주소로 내는 방법도 있지만 이번 판에서는 하지 않는다 |

**외부 자원을 막지 않는 이유:** 불투명 출처라 읽어 갈 것이 자료 자신뿐이다. 폐쇄망에서는 CDN 이 안 닿아서
글꼴이 바뀌거나 차트 하나가 비는 정도다. 그러니 save 가 **경고**만 낸다(4.2 W3).

## 4. 지식으로 쓰기 — HTML 과 md 의 나눔

### 4.1 원칙

> **HTML 은 보는 것, md 는 찾고 엮는 것.**

| 맡는 것 | HTML(첨부) | md(작업 기록 본문 · 관리 문서 섹션) |
|---|---|---|
| 도면 · 색 구분 · 시퀀스 그림 · 넓은 표 | ○ | 링크 한 줄 |
| 좌표(`touches`) · 파생 · 정정 | ✗ | ○ |
| 검색 · MCP `load` · `search` | ✗(4.3 은 다음 판) | ○ |
| 결정 · 확인 목록 · 수치(프레임 규격 같은 것) | 원문이 있다 | **요지를 옮긴다** — 다른 문서가 인용할 단위이기 때문이다 |

### 4.2 들이는 길 — `save`

| | 결정 | 왜 |
|---|---|---|
| W1 | 받는 종류에 `text/html`(`.html` · `.htm`)을 더한다. 자리는 그림과 같은 **`work/assets/<작업 기록 id>/<이름>.html`** 이다. 모드 A 는 복사 + git, 모드 B 는 `curl` → `assets[]` | 길을 새로 만들지 않는다(A1 · A2 · A5). 자료는 그것을 들인 기록에 딸리고, 커밋에 「왜」 가 같이 남는다 |
| W2 | 고칠 때는 **새 기록 · 새 경로**에 둔다. 관리 문서 섹션의 링크를 새 경로로 바꾸고, 옛 파일은 남긴다 | work 층은 append-only 다. 판이 바뀐 도면을 덮어쓰면 옛 기록이 가리키던 것이 몰래 바뀐다 |
| W3 | 경고(거절하지 않음) — ① HTML 첨부가 있는데 본문이 짧으면(제목 · 링크뿐) 「요지를 본문에 — 검색 · 파생은 md 만 본다」 ② 외부 자원(S2 의 CDN 밖 · `http:`)을 부른다 ③ `<script src>` 가 CDN 을 부른다 → 「폐쇄망에서 빌 수 있다」 | 지식이 HTML 안에만 갇히는 것을 쓰는 순간에 알린다. 그림 첨부 A7 과 같은 층의 경고다 |
| W4 | 스킬 `cdp-save` 「그림 · 첨부」 절에 HTML 을 더한다 — 본문에 **요지(무엇 · 결정 · 확인 목록)** 를 md 로 적고 `[SCADA 연계 구성도](assets/<id>/SCADA_연계_구성도.html)` 로 건다. 관리 문서 섹션에서는 `../work/assets/…` | 에이전트가 HTML 만 올리고 끝내지 않게 한다. 이 파일의 「확인 목록」 13절 같은 것은 md 로 옮겨야 대장 · 정의서로 파생된다 |

### 4.3 남는 것 — 검색

HTML 의 글(태그를 뺀 것)을 검색 색인에 넣으면 「자료 안의 말」 도 찾힌다. 이번 판에서는 하지 않는다 —
W3 · W4 로 요지가 md 에 오면 대부분 거기서 걸린다. 운영해 보고 빠지는 것이 보이면 다음 판에서 넣는다.

## 5. 화면 — 「asset 을 고를 수 있게」

### 5.1 어디에 두나

| | 방법 | 판정 |
|---|---|---|
| ㉮ | 왼쪽 트리에 「자료」 노드를 따로 둔다 | ✗ — 자료가 기록 · 섹션과 떨어져 「왜 · 어디에 쓰이나」 가 안 보인다. 트리 층이 셋이 된다 |
| ㉯ | 본문 안에 틀을 바로 박는다(링크 자리에 iframe) | △ — 틀의 높이를 자료에 맞출 수 없다(불투명 출처는 크기를 알려 주지 않는다). 82 KB 짜리 도면철이 본문 중간에 고정 높이로 끼면 둘 다 읽기 어렵다 |
| ㉰ | **문서 머리 탭 줄** — 문서에 HTML 첨부 · 링크가 있으면 본문 위에 「본문 \| SCADA 연계 구성도」 탭이 생긴다. 탭을 고르면 본문 자리가 **틀 하나로 꽉 찬다** | ○ — 운영자가 말한 「화면에서 고르기」 가 이것이다. 문서를 떠나지 않으므로 「‹ 이전」 · 열린 문서 탭(v0.24.0)과 다투지 않는다 |

**결정 — ㉰.** 본문 링크와 첨부 목록은 그 탭으로 가는 입구다.

### 5.2 결정

| | 결정 | 왜 |
|---|---|---|
| V1 | 문서가 가진 HTML 을 모은다. **모으는 곳은 둘이다:** 프론트매터 `attachments` 의 `.html`, 그리고 본문의 상대 링크 중 `.html`(레포 안 · 있는 파일). 관리 문서는 섹션 링크로 자료를 가지므로 뒤쪽이 필요하다 | 관리 문서에는 `attachments` 가 없다. 섹션이 `../work/assets/…html` 을 가리킬 뿐이다 |
| V2 | 탭 줄 — 「본문」 + 자료마다 하나. 이름은 HTML 의 `<title>` 을 쓰고, 없으면 파일 이름에서 확장자를 뺀다. 자료가 0개면 줄을 그리지 않는다 | 탭이 하나뿐인 줄은 소음이다. `<title>` 은 서버가 읽어 문서 응답에 싣는다(틀 안은 불투명 출처라 화면이 읽을 수 없다) |
| V3 | 자료 탭 = 본문 자리 전체를 차지하는 틀 하나(S3). 위에 얇은 줄: **새 탭에서 · 내려받기 · 경로**. 틀 안이 스스로 스크롤한다 | 높이 문제(㉯)를 「자리를 통째로 준다」 로 푼다. 새 탭으로 열어도 S1 덕에 안전하다 |
| V4 | 주소에 싣는다 — `/d/<id>?v=<자료 경로>`. 「‹ 이전」 · 브라우저 뒤로 가기 · 열린 문서 탭이 탭 고름까지 기억한다 | v0.24.0 에서 문서를 주소에 실은 것과 같은 결이다. 링크로 자료를 공유할 수 있다 |
| V5 | 본문의 `.html` 링크는 새 탭으로 열지 않고 **그 자료 탭으로** 간다. 링크 옆에 작은 「자료」 표시를 붙인다. 첨부 목록 HTML 행에는 「보기」 단추(지금의 「원문」 옆) | 지금은 G4 규칙대로 새 탭으로 빠진다. 앱 안에 머물러야 돌아갈 길이 산다 |
| V6 | 테마 — 틀 요소에 `color-scheme` 을 앱 테마로 건다. CSS 규약상 틀 안의 `prefers-color-scheme` 이 그것을 따른다. **구현 때 브라우저로 실측한다** | 이 자료처럼 `prefers-color-scheme` 을 쓰는 HTML 은 앱을 어둡게 두면 따라 어두워진다. 불투명 출처라 `data-theme` 은 건드릴 수 없다 |
| V7 | 왼쪽 트리의 문서 행에 작은 자료 표시(아이콘 하나) | 「도면이 있는 문서」 를 열기 전에 알 수 있다. 고르기 자체는 탭에서 한다 |

### 5.3 그림으로
