## 3. 기능 결함 · 불편 — F

### 무거운 것

**F1 ✗ 관리 › 작업 레포가 레포로 거르지 않는다 — 설치 명령이 다른 지식 레포로 나간다**
- 본 것: gdi · dpms_wiki · 새로 세운 zz-test 의 「관리 › 작업 레포」 가 셋 다 같은 목록(gdi · dpms)을 낸다. 콘솔 대장은 `dpms → dpms_wiki` 인데
  **gdi 화면에서 dpms 의 「설치 방법」 = `node … --repo gdi --workrepo wr_4e0e8b .`** — 따라 치면 dpms 작업 레포가 gdi 에 붙는다.
  같은 화면의 「관리 › 현황」 카드는 「등록 1곳」 이라 서로 어긋난다.
- 원인: `GET /workrepos` 가 권한으로만 거른다 — `viewer/bin/ctx-mcp-serve.mjs:1535`. 설치 명령의 레포는 행이 아니라 `currentRepo()` —
  `viewer/src/components/admin/WorkReposServer.jsx:193`(꾸러미 zip 링크 `api.kitUrl` 도 같다).
- 개선: 화면이 `knowledge === currentRepo()` 인 행만 그린다(또는 `?repo=`). 명령 · zip 은 `row.knowledge` 로 만든다. 이미 이렇게 설치된
  작업 레포가 있는지 대장의 `applied` 로 한 번 훑는다 — F2 의 기록이 그 흔적일 수 있다.

**F2 ✗ 콘솔 「최근 기록」 · serve.log 의 레포 칸이 실제 저장 레포가 아니다**
- 본 것: 현황 「최근 기록」 에 `gdi · 2026-1002-SCADA-데이터종류-수집경로-검토 · 기록됨` 등 SCADA · DPMS 기록 다섯이 **gdi** 로 나온다.
  gdi 목록에는 없고 **dpms_wiki 에 있다**. 로그도 `kjsa · gdi · tools/call · save · 2026-1002-SCADA-…`.
- 원인: 로그 줄의 레포 = 주소 `/mcp/<레포>` — `ctx-mcp-serve.mjs:1850`. 도구가 `repo` 인자로 다른 레포에 쓰면(`ctx-mcp.mjs:139` 의 `want || fallback`)
  로그는 그것을 모른다. 이 작업 레포의 `.mcp.json`(gdi)과 `.claude/cdp.json`(dpms_wiki)이 갈라진 정황이다 — `ctx-mcp.mjs:190` 이 경고하는 바로 그 모양.
- 개선: `saver` 가 `ctxStore.outcome.repo = name` 을 남기고 로그가 그것을 쓴다(주소 레포와 다르면 `gdi→dpms_wiki` 로). 콘솔이 「주소와 저장 레포가
  다른 기록」 을 경고로 띄우면 F1 같은 잘못 설치를 사람이 본다.

**F3 ✗ 토큰 발급 창이 닫아도 다시 뜬다**
- 본 것: 사용자 화면의 [발급] → `/console/tokens?user=zz-test-writer` 에서 발급하고 「확인 — 전했다」 를 눌러도 **발급 창이 그대로 남고**, 재발급 ·
  만료 창을 닫을 때마다 또 뜬다. 한 번 더 누르면 토큰이 하나 더 생긴다.
- 원인: `?user=` 를 읽는 효과가 `data` 가 바뀔 때마다 다시 돈다 — `viewer/src/console/Tokens.jsx:29-32`. 쿼리를 지우지 않는다.
- 개선: 한 번 열고 `history.replaceState` 로 `?user=` 를 지운다(또는 「이미 열었음」 표지).

**F4 ✗ 서버 · PC 시계가 2시간 넘게 어긋나고, 화면의 「N시간 전」 이 브라우저 시계로 계산된다**
- 본 것: 「다시 검사」 직후 「진단 **2시간 전** · 10-02 08:37」. 지금 쓰는 kjsa 도 「마지막 사용 2시간 전」. 에이전트가 쓴 기록 프론트매터는 10:15 인데
  서버 로그는 08:04 — **PC 가 약 2시간 10~20분 앞선다**(어느 쪽이 맞는지는 이 시험으로 모른다).
- 개선: 운영 — 두 기계의 NTP 를 본다(`timedatectl` · `w32tm /query /status`). 화면 — 응답의 `Date` 로 서버 시각과의 차를 재서 상대 시각을 서버 기준으로
  내고, 차가 5분을 넘으면 콘솔 현황에 한 줄 경고. 기록 id 의 날짜가 PC 와 서버에서 갈리는 것도 같은 뿌리다.
