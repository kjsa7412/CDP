## 0. 한 줄

**서식은 문서가 아니라 문서를 세우는 재료다.** 옛 패키지 넷(공공 SI · 애자일 제품 · AI 서비스 · 클라우드 네이티브)이 **묶음 넷 · 서식 79종**의 서식집이 됐다. 레포를 세울 때 붓지 않는다 — 레포는 빈 틀로 서고, 큐레이터가 기록이 쌓인 주제에서만 서식을 골라 문서를 세운다. 서버는 그 문서를 **제목 · 서식 표지 · 첫 문단만 있는 깨끗한 빈 문서**로 찍는다 — 작성지침과 예시는 서식집에 남아 큐레이터가 읽는다. 그래서 예시가 섹션으로 잡혀 문서가 지저분해지는 일이 구조적으로 없다.

## 1. 자리

| 자리 | 무엇 | 찾는 순서 · 규칙 |
|---|---|---|
| **번들 서식집** | 서버 산출물의 `forms/<묶음>/` — 제품 판을 따른다(upgrade 가 비우고 넣는다) | `--forms` → 환경변수 `CDP_FORMS` → 번들 옆 `<bin>/../forms` → 소스 `agent/forms`(`findFormsDir` — 앞에서부터 있는 곳 하나) |
| **팀 서식** | `<data>/forms/<묶음>/` — **upgrade 가 덮지 않는다** | 번들 위에 얹는다. **같은 id 면 팀 서식이 이긴다** · 같은 이름의 묶음은 팀 것의 머리가 이긴다(`loadForms`) |

- 서버는 서식집을 **프로세스에서 한 번** 읽어 들고 있다(`formsLib` 캐시) — 팀 서식을 고치면 서버를 다시 띄운다.
- 목록의 행마다 `origin` 이 `bundle` · `team` 을 말한다.
- `ctx serve doctor` 가 번들 서식집이 없으면 warn 한다 — 없어도 서버는 돈다(서식 없이 `# 제목` 한 줄로는 세울 수 있다).

## 3. 서식 파일

### 3.1 이름

`<묶음>/<번호>_<제목>.md` — 파일 이름은 `<번호>_` 로 시작해야 한다(`parseForm` 이 본다). 번호는 관리번호다(`DE_431` · `PD_301`).

### 3.2 모양 — 머리말 하나 · 덩어리 셋

```markdown
---
form: public-si/DE_431
title: 테이블정의서
number: DE_431
due: 설계완료
required: false
kind: 대상
registry:
  - { pattern: "테이블정의서:*", anchor: "## {값}" }
coordValue: 테이블 물리명(소문자)
---
<!-- form:head -->
테이블의 지금 상태. 섹션 하나가 테이블 하나다.

<!-- form:guide -->
**무엇** — … **언제** — … **누가** — …
**여기 적지 않는 것** — (표) … 작성지침 …

<!-- form:example -->
<!-- 분류는 이런 주석으로 표시한다. 제목으로 쓰면 좌표로 잡힌다 -->
### 예시 — ex_plan_mst — 계획서마스터
…
```

### 3.3 머리말 필드

| 필드 | 필수 | 뜻 | 코드가 쓰는 곳 |
|---|:--:|---|---|
| `form` | O | 서식 id `<묶음>/<번호>` — 주석 안에 들어가므로 공백 · `>` · `--` 를 받지 않는다 | 서식집의 열쇠 · 서식 표지 · `managed.add { form }` |
| `title` | O | 관리번호 접두를 뗀 이름 — 서식에서 세운 문서의 제목이 된다(K4 — 번호는 제출 산출물의 것이다) | `stampDoc` 의 H1 |
| `number` | O | 관리번호 — `form` 의 번호와 같아야 한다 | 찾기 · `ctx baseline extract` 가 옛 문서의 번호로 서식을 찾는다 |
| `due` | O | 제출시기 — `public-si` 는 단계(설계완료 · 구현완료 …), 나머지는 「언제」 를 문장으로 | 목록 표시 |
| `required` | O | 필수 제출 — `true` · `false`(지금 `true` 는 셋 — `BM_111` · `BM_112` · `BM_201`) | 목록 표시 |
| `kind` | O | 문서 종류 다섯 — §4 | 목록 · 명함 · 큐레이터 guide. **문서에는 적지 않는다**(V7) |
| `registry` | — | 이 문서에 걸리는 등록부 행 `[{ pattern, anchor }]` — 패턴이 여럿인 문서가 있다(`DE_501` 의 `인터페이스:*` · `배치:*`). 없으면 등록부 비대상(날짜축 · 서술 문서) | 목록 · 화면의 칩 · 판정 재료의 「비슷한 서식」 찾기. **행을 더하는 것은 큐레이터의 `managed.add` 다** — 서식의 `registry` 가 저절로 행이 되지 않는다 |
| `coordValue` | registry 가 있으면 O | 좌표 값이 무엇인가(「테이블 물리명(소문자)」) | 안내 — `forms({ form })` · 화면 |
| `fixed` | — | 팀이 미리 등록하는 고정 좌표 값(`DE_101` 의 `hw` · `db` · `sw` · `link`) — 지금 5종 | 안내 |

### 3.4 덩어리 셋

| 표지 | 누가 읽나 | 문서로 가나 |
|---|---|:--:|
| `<!-- form:head -->` | 새 문서 — 첫 문단(대장이면 빈 표 머리) | **간다** — 이것만 |
| `<!-- form:guide -->` | 큐레이터 — 무엇 · 언제 · 누가 · 여기 적지 않는 것 · 골격 · 작성지침 | 안 간다 |
| `<!-- form:example -->` | 큐레이터 — (예시) 섹션 · 표 속 예시(예시 제목은 `###` 아래) | 안 간다 · 좌표로 잡히지 않는다 |

- 표지는 줄 하나에 그것만 — 순서는 head · guide · example 이고 셋 다 있어야 한다. 첫 표지 앞에 글이 있으면 안 된다.
- **코드 펜스 안의 표지는 표지가 아니다** — 예시가 서식을 보일 수 있다.
- 읽는 경계에서 BOM · CRLF 를 맞춘다(I13) — CRLF 로 받은 서식도 같은 값을 낸다.

## 4. 문서 종류 다섯

**종류는 등록부 대상인지와 다른 축이다**(개편안 §8.1). 대상 · 대장 · 정의는 대개 등록부 행이 있고, 사건 · 서술은 대개 없다. 종류별 섹션의 모양은 큐레이터 스킬의 참고 파일 [`agent/skills/cdp-curate/종류별.md`](../../agent/skills/cdp-curate/종류별.md) 가 전후 예시로 보인다.

| 종류 | 무엇 | 섹션 모양 | 서식 수 |
|---|---|---|---:|
| **대상** | 테이블 · 화면 · API · 서비스처럼 **상태를 갖는 것** — 섹션 하나가 대상 하나 | 사건이 아니라 지금 상태 · 현재형 · 컬럼 표 같은 추출물은 기준선 블록 · 끝에 경과 | 33 |
| **대장** | 이슈 · 위험 · 플래그처럼 **아직 끝나지 않은 것**의 목록 | 고정 표 + 결론 한 줄 + 경과 — 일지를 결론으로. 끝난 판단의 내용은 기록과 정본 섹션에 | 10 |
| **정의** | 용어 · 도메인 어휘 — **뜻만** | 뜻 · 쓰임 · 관련 좌표. 판단 · 선례는 그 정본에 두고 건다 | 1(`DE_421`) |
| **사건** | 회의록 · 보고서 · 회고처럼 **날짜축** | 결정 · 할 일 · 이어지는 곳만 — 원문은 그것을 들인 작업 기록이다. 등록부가 없으면 `edits` 로 쓴다 | 16 |
| **서술** | 가이드 · 계획서 · 매뉴얼 — **문서 전체가 내용** | 규칙이 바뀌면 그 절을 지금 규칙으로 고쳐 쓴다(`edits`) · 날짜별 덧붙이기 · 「변경 이력」 절을 만들지 않는다 | 19 |

79종 중 등록부 행이 있는 서식은 36종(행 37 — `DE_501` 이 둘) · 없는 서식 43종. 행의 앵커는 전부 `## {값}` 이다.

## 5. 찍는 규칙 — `stampDoc`

**새 관리 문서는 `stampDoc(form, { title })` 하나가 찍는다** — `managed.add { form }` 과 화면 · 도구의 미리보기(`forms({ form })` 의 `stamp` · `GET /api/<r>/forms/<묶음>/<번호>` 의 `stamp`)가 같은 함수를 부른다(I1). 미리보기가 실제와 갈라지지 않는다.

```markdown
# <title>
<!-- cdp:form <묶음>/<번호> -->

<head>
```

| 규칙 | |
|---|---|
| 제목 | `managed.add` 의 `title` 이 있으면 그것, 없으면 서식의 `title`(한 줄로) |
| 표지 | H1 바로 다음 줄 — §6 |
| 본문 | `head` 덩어리 그대로(앞뒤 빈 줄을 걷는다). head 가 비면 제목과 표지뿐 |
| 가지 않는 것 | 예시 · 작성지침 · 관리번호 표 · 제출시기 · `applied: null` · 섹션 |
| 그다음 | 같은 save 의 `sections` 가 그 아래에 섹션을 붙인다 — 「여기부터 큐레이션 save 의 섹션이 붙는다」 |

**세우는 길** — 큐레이터의 save:

```jsonc
{
  "managed": [{ "pattern": "테이블정의서:*", "doc": "docs/테이블정의서.md", "form": "public-si/DE_431", "title": "테이블정의서" }],
  "sections": [{ "coord": "테이블정의서:sy_user_info", "applied": null, "heading": "sy_user_info — 사용자정보", "body": "…" }],
  "work": { "curates": [{ "id": "…", "verdict": "new", "into": ["테이블정의서:sy_user_info"] }], … }
}
```

| 경우 | 결과(`managedops.planManaged` add) |
|---|---|
| 문서가 없다 · `form` 이 있다 | 서식의 빈 문서를 찍고 등록부 맨 끝에 행(`서버 추가 · <work.id>`) |
| 문서가 없다 · `form` 이 없다 | `# <title 또는 파일 이름>` 한 줄 — 서식집이 모든 도메인을 덮지 못한다(K8) |
| 문서가 이미 있다 · `form` 이 있다 | 행만 더하고 경고 — 「서식은 새 문서에만 찍는다」 |
| `form` 이 서식집에 없다 | `E_INPUT { field: managed[i].form }` — 「forms 로 찾아 id 를 그대로 쓴다」 |

- 패턴 · 경로 · 겹침 · 레벨 규칙은 `managed.add` 의 것 그대로다 — 같은 패턴이 다른 자리에 있으면 `E_CONFLICT { kind: 'managed', current }` · 같은 자리면 멱등(경고) · 앞 행이 완전히 덮으면 `E_INPUT` · 일부 겹치면 경고 · 한 문서는 한 레벨([시스템설계서 §5](CDP_시스템설계서_v2.0.md#5-save-v10)).
- **서식을 고쳐도 이미 세운 문서는 안 바뀐다** — 찍는 것은 세우는 때 한 번이다. 서식집 판이 문서 판이 아니다.
- 옛 레포의 문서에서 대상형 섹션을 옮겨 올 때는 `ctx baseline extract` 가 관리번호로 서식을 찾아 `managed: [{ op: 'add', pattern, doc, form }]` 를 JSON 에 싣는다(공공 SI 를 먼저 본다 · [시스템설계서 §10.4](CDP_시스템설계서_v2.0.md#104-옛-섹션을-기준선으로)).

## 6. 서식 표지

```markdown
# 테이블정의서
<!-- cdp:form public-si/DE_431 -->
```

| 규칙 | 왜 |
|---|---|
| **YAML 이 아니라 주석이다**(V6) | 관리 문서에 YAML `form:` 을 달면 섹션 줄(프론트매터 뒤 기준)과 자르기(전체 기준)가 어긋나 `section` · `E_CONFLICT.content` · 검색이 조용히 틀린다(개편안 H4). `—` 문서 치환은 프론트매터를 지운다 |
| H1 바로 아래 3줄 안 | 본문 중간의 같은 글(예시 · 설명)을 표지로 읽지 않는다 |
| 한 줄에 그것만 · id 는 공백 없이 | 화면은 이 줄을 칩으로 그리고, 서식집 미리보기는 「서식 표지 — 이 문서를 세운 서식」 으로 칠한다 |
| 문서 종류 · 관리번호는 적지 않는다 | 서식 머리에서 온다 — 문서가 늘 같은 말을 하지 않게 |

읽는 자리 — `section` 의 `form` · 화면 `/api/<r>/docs/<id>` 의 `form` · 서식 목록의 `used`(이 레포가 그 서식으로 세운 문서가 있나). 읽는 함수가 둘이다(§12).

## 7. lint — `lintForm(form)`

문제 목록을 낸다 — 비면 쓸 수 있다. `parseForm` 이 읽으며 본 구조 문제(`errors`)에 값의 검사를 더한다.

| 갈래 | 규칙 |
|---|---|
| 구조(`parseForm`) | 머리말(`--- … ---`)이 있다 · YAML 이 객체다 · 덩어리 셋이 다 있고 순서대로 · 표지가 둘이 아니다 · 모르는 표지가 없다 · 첫 표지 앞에 글이 없다 · `form` 의 묶음 = 폴더 · 파일 이름이 `<번호>_` 로 시작 · `registry` · `fixed` 는 목록 |
| 머리 필드 | `form` 이 `<묶음>/<번호>` 모양(`[A-Za-z0-9가-힣][A-Za-z0-9가-힣._-]*` 둘 · `--` 없음) · `form` 의 번호 = `number` · `number` · `title` · `due` 가 있다 · `required` 는 boolean · `kind` 는 다섯 중 하나 |
| 등록부 | 패턴이 등록부 행으로 쓸 수 있다(`managed.patternProblem` — 구체적 타입 · 값에 공백 · `|` · 백틱 · `..` 없음) · 서식 안에서 패턴이 겹치지 않는다 · `anchor` 는 `## {값}` 또는 `—` 뿐(V8 — `###` 는 서식에서 뺐다) · `registry` 가 있으면 `coordValue` 가 있다 |
| fixed | `registry` 없이 `fixed` 만 있으면 안 된다 · 빈 값이 없다 |
| head | 비어 있지 않다 · **제목(헤딩)이 없다**(섹션은 큐레이션이 세운다) · `applied` 주석이 없다 · `cdp:` · `form:` 표지가 없다 · `(예시)` 가 없다 · `작성지침` 이 없다 — 새 문서로 그대로 가는 덩어리라서다 |

- **도는 자리** — 단위 시험 [`test/forms.test.mjs`](../../test/forms.test.mjs) 가 `agent/forms/**` 전부를 lint 하고 찍은 문서의 표지를 되읽는다. 2026-10-07 현재 79종 모두 문제 0.

## 10. 서식 만들기 · 고치기

| 하려는 것 | 길 |
|---|---|
| 제품 서식을 고친다 | `agent/forms/<묶음>/` 에서 고치고 `node --test test/forms.test.mjs` — 판을 올리면 서버 산출물의 `forms/` 로 나간다. 고친 묶음의 `_묶음.json` `version` 을 올린다 |
| 팀만의 서식을 둔다 | 서버의 `<data>/forms/<묶음>/<번호>_<제목>.md`(같은 모양) — 서버를 다시 띄운다. 같은 id 면 번들 서식을 덮는다 |
| 새 묶음을 둔다 | 폴더 하나 + `_묶음.json` · 서식 파일들. id 의 묶음은 폴더 이름과 같아야 한다 |

- head 에는 **새 문서의 첫 문단만** 둔다 — 섹션 · 예시 · 작성지침을 넣으면 lint 가 막는다.
- guide 는 「여기 적지 않는 것 → 어디로」 표를 둔다 — 정본 한 곳(I5)을 서식이 먼저 말한다. 문서 이름을 박을 때는 그 문서가 레포에 없을 수 있다는 것을 안다(개편안 A7).
