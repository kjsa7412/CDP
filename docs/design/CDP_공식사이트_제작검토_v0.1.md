## 0. 한 줄

**공식 사이트는 서버의 소개 얼굴(`/`)과 다른 물건이다.** 소개 얼굴은 서버 하나의 앞문이다(`/site/info` 로 그 서버의 판 · 레포 수를 그린다). 공식 사이트는 어느 서버에도 붙지 않는다. 설치 전인 사람에게 CDP 가 무엇이고 어떻게 생겼는지 보여 주는 **정적 SPA** 다. 서버도 API 도 폼도 없다.

권장안은 네 가지다.

1. 레포 최상위에 `site/` 를 새로 두고 제품의 `tokens.css` · `Icon.jsx` · `McpFlow.jsx` 를 가져다 쓴다.
2. 화면은 **가상 데모 레포**를 진짜 서버로 띄워 새로 찍는다. 기존 스크린숏 99장은 쓰지 않는다.
3. 예제는 데모 레포에서 **진짜 ctx · MCP 를 돌려 녹화한 출력**을 단계별로 재생한다.
4. 산출물 전체에 **누출 검사**를 걸어 사내 이름이 하나라도 있으면 빌드를 실패시킨다.

**가장 큰 발견은 재료가 공개할 수 없는 것뿐이라는 점이다.** fixture 는 실제 고객 프로젝트의 작업 기록에서 만들었다(`ops/lib/seed_repo.py` 머리). 스크린숏에는 kjsa · hong · `10.10.20.188` · 토큰 id 앞자리 · 사내 테이블 이름이 찍혀 있다. 설명서 세 권에는 내부 IP 가 박혀 있다. 그래서 사이트의 절반은 **공개해도 되는 재료를 새로 만드는 일**이다.

## 1. 운영자의 말 · 검토의 틀

> CDP 제품 공식 사이트를 SPA로 하나 만들어라. 해당 페이지에서 바로 무언가를 할 수는 없고 제품을 소개하는 페이지이다. 실사용 화면과 예제는 당연히 필요하다.

## 4. 구조 — 어디에 무엇으로 만드나

### S1 · 서버 없는 정적 SPA

- 산출물은 `index.html` · JS · CSS · PNG · SVG 뿐이다. 어느 정적 호스트에 올려도 돈다.
- **런타임에 나가는 요청은 같은 출처의 자기 파일뿐이다.** 폰트 CDN · 분석 스크립트 · 외부 이미지를 쓰지 않는다. 폐쇄망 제품의 사이트가 밖으로 부르는 것이 있으면 말과 행동이 어긋난다. 글꼴은 제품과 같이 시스템 글꼴로 떨어진다(`--font-sans` 의 Pretendard 는 번들되지 않는다).
- **상호작용은 보기만 한다.** 예제의 단계 넘김 · 화면 확대 · 라이트/다크 전환 · 목차 이동이 전부다. `fetch` 는 빌드 때 고정한 JSON 을 자기 출처에서 읽을 때만 쓴다. 번들에 넣으면 그것도 없다.

### S2 · 소스는 `site/`, 제품 번들과 가른다

```
site/
  index.html              테마 인라인 스크립트(제품 index.html 과 같은 방식) · 메타
  vite.config.js          root: site/ · outDir: ../ops/out/site · base: $CDP_SITE_BASE || '/'
  src/
    main.jsx · App.jsx    라우터 · 상단 바 · 바닥글
    router.jsx            base 를 아는 40줄 라우터(아래 S3)
    pages/                Home · Concept · Screens · Examples · Agent · Deploy · Releases
    data/                 screens.js(목록 · 설명) · examples/*.json(녹화) · releases.json(빌드 생성)
    site.css              사이트 고유 배치. 색 · 간격은 전부 tokens.css 변수
  public/shots/           라이트 · 다크 PNG(§5, 커밋한다)
  public/fig/             docs/그림/*.svg 복사(빌드 때)
  demo/                   데모 레포 시드 · 명부 · 녹화 스크립트(§5 · §6)
  tools/                  capture.mjs · record.mjs · check-leaks.mjs · prerender.mjs
```

- **가져다 쓰는 것**: `../viewer/src/styles/tokens.css` · `../viewer/src/components/Icon.jsx` · `../viewer/src/site/McpFlow.jsx`. 상대 import 로 끌어온다. 제품이 색이나 아이콘을 바꾸면 사이트도 따라 바뀐다. 사이트 전용 사본을 두면 스크린숏과 사이트의 색이 서서히 갈라진다.
- **제품 번들에는 들어가지 않는다.** `ops/out/web` · 서버 tar · exe 는 그대로다. vite 설정 파일을 따로 두는 까닭은 제품 설정이 `emptyOutDir: true` 로 `ops/out/web` 를 비우기 때문이다.
- `npm run build:site` → `ops/out/site/`. `npm run dev:site` → 5174 번 포트.

### S3 · 라우팅은 history + 주소별 정적 사본

| 안 | 장점 | 단점 | 판정 |
|---|---|---|---|
| hash(`#/screens`) | 어느 호스트든 돈다 | 제품 설명서 · 사이트 안 앵커(`#…`)와 부딛힌다. 공유 주소가 못생겼다. 크롤러가 한 쪽만 본다 | X |
| history + 호스트 재작성 규칙 | 주소가 깨끗하다 | 호스트마다 설정해야 한다. 정적 호스트가 정해지지 않았다(Q1) | X |
| **history + 빌드 때 주소마다 `index.html` 사본** | 재작성 규칙 없이 `/screens/` 를 새로 열어도 돈다. 사본마다 `<title>` · `description` 을 박아 JS 없이도 제목이 보인다. 없는 주소는 `404.html`(홈 사본 + 「없는 주소」) | 빌드 스크립트 하나(`prerender.mjs`, 30줄) | **O** |

- base(`/` 또는 `/cdp/` 같은 하위 경로)는 빌드 변수 하나로 바꾼다. 라우터와 링크는 base 를 붙여 만든다. 제품 `lib/router.jsx` 는 절대경로 `/` 전제라 가져다 쓰지 않는다.
- 페이지를 넘기면 맨 위로 가고, 앵커가 있으면 그 자리로 간다. 뒤로가기는 보던 스크롤로 돌아간다.

### S4 · 호스팅은 정하지 않고 산출물로 끝낸다

> **구현에서 바뀜** — Q1 = Vercel. 레포 루트 `vercel.json`(빌드 명령 · 출력 폴더 · CSP 헤더). 릴리스 zip 은 그대로 만든다.

- 레포는 비공개이고 공개 여부 · 주소 · 도메인은 사람이 정할 일이다(Q1 · Q2). 이 작업은 **어디에나 올릴 수 있는 폴더와 zip** 까지 만든다.
  - `ops/out/site/`
  - 릴리스에 붙는 `cdp-site-v<판>.zip`. `release.yml` 에 한 단계를 더하고, 태그와 판이 다르면 실패하는 규칙을 그대로 따른다.
- GitHub Pages 워크플로는 **만들지 않는다.** 비공개 레포의 Pages 는 요금제가 필요하고 주소에 계정 이름이 들어간다. Q1 이 Pages 로 정해지면 `pages.yml` 은 20줄이다(§9 의 ⑩).
- CDP 서버가 공식 사이트까지 내게 하지 않는다. 서버에는 이미 자기 소개 얼굴이 있고, 둘을 섞으면 「이 서버」 카드와 「제품」 문장이 한 화면에서 부딛힌다.

### S5 · 설명서는 링크도 복사도 하지 않는다

위 §3 의 끝을 보라. 사이트는 설명서가 **있다는 것과 무엇을 다루는지**(세 권의 대상 · 장 제목)만 싣는다. 장 제목에 내부 주소가 들어간 것(「서버 설치 절차 — <IP>」)은 일반 이름으로 바꿔 적는다.

## 5. 실사용 화면 — 새로 찍는다

### S6 · 가상 데모 레포를 진짜 서버로 띄운다

**화면은 진짜이고 내용은 가상이다.** 목업이나 그림으로 그리지 않는다. 판 v0.19.0 의 서버를 그대로 띄우고, 가상 프로젝트로 채운 지식 레포를 붙여서 찍는다.

| 항목 | 권장안 |
|---|---|
| 가상 프로젝트 | **「도서관 대출 관리 시스템 개편」.** 누구나 아는 업무라 좌표를 설명 없이 읽는다. 공공 SI 모양이라 `dpms` 서식 패키지(제품과 함께 나가는 것)가 어울린다 |
| 만드는 법 | 제품의 길 그대로 — `ctx repo new --package dpms` 로 세우고, 작업 기록은 **`save` 로 넣는다.** 시드가 파일을 직접 쓰지 않는다. 그래야 화면의 커밋 이력 · `applied` · 미러가 진짜다 |
| 분량 | 작업 기록 약 12건 · 좌표 약 25(table · screen · api · code · term · domain) · 관리 문서는 패키지 기본에서 섹션 20여 개를 채운다 · 정정 1쌍 · 좌표 0개 기록 1 · 이슈 1 · **일부러 남긴 파생 누락 1**(검증 N 과 현황이 비지 않게, 기록은 찍은 뒤 되돌린다) |
| 좌표 예 | `dpms` 패키지의 타입 그대로 — `테이블정의서:bk_loan_mst`(대출마스터) · `화면설계서:LN010`(대출 등록) · `화면설계서:LN030`(연체 현황) · `코드정의서:LN02`(회원등급) · `도메인용어:연체일수` · `이슈:LIB-ISS-01` (구현 때 `table:` 식 16종 타입에서 바꿨다 — 패키지가 한글 타입이다) |
| 사람 | 명부 셋 — `lead`(admin) · `dev.a`(writer) · `dev.b`(viewer). 실명처럼 읽히는 이름을 쓰지 않는다. 작성자는 서버가 토큰에서 채우므로 기록에도 이 셋만 남는다 |
| 서버 · 레포 이름 | 레포 `library` · `library-ops`(둘이어야 레포 메뉴 · 콘솔 표가 빈약하지 않다). 서버는 `127.0.0.1` — 주소 칸은 찍기 전에 `cdp.example` 로 바꾸지 않는다. **보이는 그대로가 진짜다** |
| 재현 | `npm run site:demo` 한 줄이 임시 폴더에 명부 · 레포를 세우고 서버를 띄운다. 스크래치가 아니라 레포 안의 스크립트다. 판이 오르면 다시 찍을 수 있어야 한다 |

### S7 · 찍는 도구 — `playwright-core` + 깔려 있는 Edge

- `devDependencies` 에 `playwright-core` 하나를 더한다. 브라우저를 내려받지 않고 `channel: 'msedge'`(없으면 `chrome`)를 쓴다. CI 에서는 돌리지 않는다. **찍기는 사람이 판을 올릴 때 한 번 돌리고 PNG 를 커밋한다.** 사이트 빌드는 브라우저 없이 돈다.
- 1440×900 라이트 · 다크 두 벌에 DPR 2 로 찍는다. 최종 PNG 는 폭 1440 으로 줄인다. 한 장 150KB 안팎이고 14장 × 2 = 약 4MB 다.
- 로그인은 데모 명부를 만들 때 생긴 토큰으로 `/login` 을 부른다. 이 세션에서 만든 시험 값이고 레포에 남기지 않는다(데모 폴더는 임시).
- **찍기 전에 검사한다.** 화면의 텍스트와 **속성값**(`placeholder` · `title` · `value`)을 누출 패턴(S12)으로 훑는다. 걸리면 그 장을 찍지 않고 멈춘다. `placeholder="예: gdi"` 가 바로 이것에 걸린다. 그래서 제품 쪽 예시를 `예: alpha` 로 바꾸는 작은 수정이 같이 간다(§9 의 ①).

### 5.2 화면 페이지의 모양

- 얼굴별 묶음(레포 8 · 콘솔 3 · 사이트 · 설명서 3). 한 장마다 제목 · 두 줄 설명 · 「이 화면에서 하는 일」 점 셋이 붙는다.
- 사이트 테마를 따라 라이트/다크 PNG 가 바뀐다(`<picture>` + `prefers-color-scheme`, 수동 전환은 `data-theme`).
- 누르면 확대(같은 페이지의 오버레이 · 화살표로 다음 장 · Esc 로 닫힘). 확대는 주소에 `?shot=4` 로 남아 공유된다.
- 모든 이미지에 `width` · `height` · `alt`(무엇이 보이나)를 단다. 첫 화면 밖의 이미지는 `loading="lazy"`.

## 6. 예제 — 실행이 아니라 재생

### S8 · 녹화한 진짜 출력을 단계로 넘긴다

- `site/tools/record.mjs` 가 데모 레포에 **진짜 `ctx` CLI 와 MCP(`tools/call`)** 를 돌린다. 각 단계의 요청 · 응답 · 파일 변화(diff)를 `site/src/data/examples/<시나리오>.json` 으로 고정한다. 사이트는 그 JSON 을 재생만 한다.
- 손으로 쓴 예시 출력은 판이 바뀌면 거짓말이 된다. 녹화는 판마다 다시 돌리면 된다. 그리고 **녹화 결과를 테스트가 대조한다**(S13). 예컨대 시나리오 ③의 마지막 걸음은 반드시 `E_CHECK` 여야 한다.
- 화면은 세 칸이다. 왼쪽이 **에이전트의 말**(사람 말 한 줄 · 어떤 도구를 왜 부르는지), 가운데가 **요청 · 응답**(JSON 또는 CLI 출력, 줄 강조), 오른쪽이 **레포에 생긴 것**(작업 기록 md · 섹션 diff). [이전] [다음] · 키보드 ← → · 단계 점. 좁은 화면에서는 세 칸이 위아래로 쌓인다.

### 6.1 시나리오 다섯

| # | 이름 | 걸음 | 보여 주는 것 | 끝 |
|---|---|---|---|---|
| ① | **이름으로 좌표를 찾는다** | 「대출 등록 화면 연체 표시 어디서 정했지?」 → `match 대출등록` → `screen:LN010` → `where` → `section` → `work` 둘 | 검색이 「비슷한 것」을 내는 자리에서 좌표는 **그것**을 낸다 · 주입은 그 섹션만(줄 수 · 글자 수) | 섹션 본문 + 왜 그렇게 정했는지 |
| ② | **작업하고 기록한다** | 연체 기준을 「반납 예정일 다음날」로 바꾼다 → `derive` 가 채울 섹션 둘을 낸다 → `apply` 초안 → `save`(기록 1 + 섹션 2) | 기록과 정본 갱신이 **한 커밋**이다 · `applied` 주석이 따라온다 · author 는 서버가 채운다 | 커밋 해시 · 미러 `ok` |
| ③ | **갱신 누락은 커밋되지 않는다** | 같은 작업을 섹션 없이 `save` → 거절 → 섹션을 채워 다시 | 「밀림」이 없는 이유. 로컬형에서는 같은 계산을 훅이 한다(`ctx check` 출력 · exit 1) | `E_CHECK` → 고친 뒤 통과 |
| ④ | **같은 섹션을 둘이 고친다** | dev.a 와 lead 가 같은 섹션을 읽고 각자 `save` → 둘째가 `E_CONFLICT`(재료: 지금 `applied` · 누가 먼저) → 다시 읽고 합쳐 저장 | 동시 기록은 줄을 서고, 같은 곳은 거절하되 무엇을 다시 읽을지 알려 준다 | 둘 다 커밋 |
| ⑤ | **잘못 적은 것을 정정한다** | 기록의 테이블 이름 오기 → 새 기록 `supersedes` → 화면에 정정 표시 | work/ 는 불변이다 · 고치는 것도 사건이다 | 두 기록 · 한 섹션 |

- 홈에는 ①의 앞 세 걸음만 싣는다. 끝까지 보려면 예제 페이지로 간다.
- 시나리오마다 끝에 **작업 기록 md 전문**과 **정본 섹션 전문**을 나란히 편다. 「두 층」이 실제로 어떻게 생겼는지는 이 둘을 보는 것이 가장 짧다.
- 스킬(`cdp-work` 등)이 부른다는 것은 에이전트의 말 칸에 적는다. 모델의 응답 문장을 지어내지 않는다. 사람 말과 도구 선택 까닭은 **한 줄 해설**이고, 그 칸에는 「해설」 딱지를 붙인다. 녹화한 것과 해설한 것을 섞지 않는다.

## 7. 문구 · 디자인 · 공개 규칙

### S9 · 문구

- **광고 문구를 쓰지 않는다**(`Landing.jsx` 의 규칙을 잇는다). 「혁신적」 「강력한」 「AI 로 모든 것을」 같은 말이 없다. 이 레포의 말(좌표 · 두 층 · 검사 · 파생 누락 · 정정)을 그대로 쓰고, 처음 나올 때 한 줄로 풀어 준다.
- 숫자는 레포에서 잰 것만 쓴다. 도구 13 · 스킬 7 · 콘솔 일곱 · 역할 셋 · 다섯이 동시에 눌러도 전부 커밋(건당 약 2초 · 동시 기록 실측) · exe 약 68MB · 네이티브 모듈 0.
- 한국어 한 벌이다. 영어판은 만들지 않는다(Q5).

### S10 · 디자인

- 색은 `tokens.css` 넷뿐이다. 파랑은 링크 · 선택 · 포커스, 앰버 · 적 · 보라는 예제 속 경고 · 오류 · 미결에만 쓴다. **초록 없음**을 사이트도 지킨다. 「정상은 조용하다」가 제품의 원칙이고, 사이트가 체크 표시를 초록으로 칠하면 스크린숏과 어긋난다.
- 상단 바 높이 48px(`--topbar-h`)는 제품과 같다. 표식 「CDP」 는 → 홈이다. 오른쪽에 판 번호와 테마 전환이 온다. 좁으면 메뉴가 접힌다.
- 폭은 본문 최대 1120px, 화면 갤러리는 1280px. 900px 과 390px 에서 가로 스크롤이 없다.
- 그림 SVG 8장은 라이트 전제로 그려졌다. 다크에서는 흰 카드 위에 얹는다(색을 뒤집지 않는다). 다크용으로 다시 그리는 일은 범위 밖이다.

### S11 · 메타 · 접근성

- 주소마다 사본 `index.html` 에 `<title>`(「화면 · CDP」 식) · `description` · `og:title` · `og:image`(홈 스크린숏 한 장)를 넣는다. `robots` 는 Q3 에 따른다. 사외 공개가 아니면 `noindex`.
- 대비 WCAG 1.4.3 AA. 단계 넘김 · 확대 오버레이는 키보드로 다 된다(포커스 가둠 · Esc). 페이지를 넘기면 `<h1>` 으로 포커스가 간다.

### S12 · 누출 검사 — 빌드를 실패시킨다

`site/tools/check-leaks.mjs` 가 `ops/out/site/` 의 모든 텍스트 파일(html · js · css · json · svg)을 훑는다. 캡처 때는 DOM 텍스트와 속성값을 같은 규칙으로 본다(S7).

| 묶음 | 패턴(대소문자 무시) |
|---|---|
| 사내 주소 | `10\.10\.` · `\b192\.168\.` · 사내 도메인 |
| 사람 | kjsa · hong(단어) · 설명서 · fixture · 스킬에 나온 실명 목록(`site/tools/leak-names.txt` 에 두고, 이 파일 자체는 산출물에 안 들어간다) |
| 고객 · 프로젝트 | gdi · dpms_wiki · 고객사 이름 · 사내 git 그룹 경로 · fixture 의 실물 테이블 접두 `rp_` · `ps_` |
| 비밀 모양 | 43자 base64url 덩어리(토큰 원문 모양) · `cdp_su=` |
| 허용 | `dpms` — 제품과 함께 나가는 서식 패키지의 이름이라 허용한다(`dpms_wiki` 는 막는다) |

- 걸리면 파일 · 줄 · 패턴을 찍고 exit 1. CI 에서 돈다.
- PNG 는 글자를 읽지 않는다. 대신 **데모 서버만 찍는다**는 구조와 찍기 전의 DOM 검사로 막는다. 화면 14장은 커밋 전에 사람이 한 번 넘겨 본다(TODO 의 확인 칸).

### S13 · 테스트가 지키는 것

- 라우트 목록(`site/src/routes.js`) ↔ 산출물 사본 ↔ 상단 바 링크가 셋 다 같다.
- `screens.js` 의 파일이 `public/shots/` 에 라이트 · 다크 둘 다 있다. 없는 장을 그리지 않는다(`Landing.jsx` 의 「깨진 그림을 그리지 않는다」).
- 예제 JSON 의 판이 `package.json` 판과 같다. 다르면 경고한다(빌드는 된다). 판을 올리고 다시 녹화하지 않은 것을 드러내기 위해서다.
- 도구 13 · 스킬 7 같은 숫자가 코드와 같다. `ctx-mcp.mjs` 의 등록 수와 `agent/skills/*/` 수를 센다. 사이트에 박힌 숫자가 거짓말이 되는 것을 막는다.

### S14 · 판을 따라가는 법

- 사이트 머리의 판은 빌드 때 `package.json` 에서 온다.
- 판 이력은 빌드 때 CHANGELOG 절 제목과 첫 줄을 뽑아 `releases.json` 으로 만든다. 누출 검사를 통과해야 한다.
- 판을 올릴 때 사람이 할 일은 둘이다. `site:record` · `site:shots` 를 다시 돌리고, 바뀐 PNG 를 넘겨 본다. 개발자 설명서의 릴리스 절에 한 줄 더한다.

## 부록 A. 조사 방법

- 코드 · 문서는 읽기만 했다. 숫자(스크린숏 99장 · fixture 작업 기록 21건 · 아이콘 43 · 도구 13 · 스킬 7 · CHANGELOG 절 27)는 파일을 세어 얻었다.
