## 0. 한 줄

**메뉴는 한 겹이다.** 상단 바의 얼굴 스위처 · 레포 세그 · 관리와 콘솔의 안쪽 메뉴 둘 — 「어디로 가나」 를 세 군데서 고르던 것을 **접히는 왼쪽 메뉴 하나**로 폈다. 위에 레포 고르기, 그 아래 묶음 넷(**지식 · 큐레이션 · 레포 관리 · 서버**), 맨 아래 설명서와 내 계정. 메뉴의 항목은 **표 하나**(`nav.js`)에 있고, 항목마다 `need`(read · write · curate · admin)를 달아 **판정 함수 하나**(`can`)가 보일지 정한다. 주소가 상태다 — 링크 · 새로고침 · 뒤로 가기가 그 화면으로 돌아온다. 숨기는 것은 예의이고 **막는 것은 서버다**.

## 1. 한 번들 · 얼굴 넷

같은 `index.html` 하나가 모든 화면을 낸다. 얼굴은 **주소가 말해 준다**(`routes.faceOf`) — `Shell` 이 매 렌더 고르고, 얼굴을 넘는 이동도 `pushState` 다(문서 교체 0).

| 얼굴 | 주소 | 메뉴 | 무엇 |
|---|---|---|---|
| **사이트** | `/` · `/manual/*` · `/login` · `/setup` · `/r`(빈 상태) · 없는 주소 | 없다 — 상단 바(`TopBar`) | 로그인 전에도 보는 공개 화면 — 소개 · 설명서 · 로그인 · 처음 설정 |
| **레포** | `/r/<레포>/…` | 왼쪽 메뉴 | 레포 하나 — 지식 · 큐레이션 · 레포 관리(+ admin 이면 서버 묶음) |
| **콘솔** | `/console/…` | 왼쪽 메뉴 — 같은 메뉴 | 서버 전부(admin). 레포 고르기는 마지막으로 본 레포를 보인다 |

- 얼굴은 **주소 하나로** 가린다 — `/r/<레포>/` 레포 · `/console` 콘솔 · 나머지 사이트(vite 개발 서버의 `/` 도 소개). 화면은 서버 표식(`window.__CDP_SERVER__`)을 더 읽지 않는다(4ab6acc · 서버는 아직 심는다 — 하네스 79 · 89 · 102 가 본다). 인라인 스크립트가 첫 페인트 전에 `<html data-face>` 를 붙인다.
- 서버는 `/r/<레포>/` 아래 **아무 주소에나** 같은 `index.html` 을 낸다 — 새 화면 주소에 서버를 고칠 것이 없다. 볼 수 없는 레포는 서버가 `/r?from=<이름>` 으로 보내고(없는 레포와 같은 길 · D4), 화면이 「없거나 할당되지 않았다」 한 문장과 볼 수 있는 레포를 낸다(`NoRepo`).

## 3. 메뉴 표 — `shell/nav.js`

항목 하나 = `{ key, group, label, icon, need, scope, to(repo), match(rest, ctx), tab?, page?, badge? }`. SideNav · 빵부스러기 · 없는 주소 · 권한 밖 주소 · 탭 제목이 전부 이 표 하나를 본다.

| 묶음 | 항목 | need | 주소 | 그리는 것 |
|---|---|:--:|---|---|
| **지식** | 읽기 | read | `/r/<레포>/` · `/w[?only=pending\|mine]` · `/d/<id 또는 경로>` | 왼쪽 목록 위 **세그**(문서 · 기록 — 기록 쪽에 대기 n) · 거름 · 문서 |
| | 좌표 · 그래프 | read | `/r/<레포>/graph` | 좌표 그래프 |
| **큐레이션** | 대기열 · 배지 **대기 n** | curate | `/r/<레포>/manage/curation` · 탭 **이력** `…/curation/log[/<id>]` | `Queue`(S3) · `Log`(S4) |
| | 진단 | curate | `/r/<레포>/manage/drift` | `Drift` |
| **레포 관리** | 현황 | read | `/r/<레포>/manage[/overview]` | 「시작하기」 · `admin/Overview`(S6) |
| | 관리 문서 | read | `/r/<레포>/manage/docs` · 탭 **문서 추가 › 서식집** `…/manage/forms[/<묶음>/<번호>][?tab=]`(curate) | `admin/Docs` — 지우기 단추는 curate · `FormLibrary`(S5) |
| | 연결된 작업 레포 | read | `/r/<레포>/manage/work` | `admin/LinkedWorkRepos` — 등록 · 삭제는 write |
| **서버** | 현황 · 지식 레포 · 사람 · 서버 | admin | `/console` · `/console/{repos,people,server}` | `console/*` |

**메뉴 수 — viewer 5 · writer 5 · curator 7 · admin 11**(제품화 2 D6 · 화면 22 → 16 — 레포 10 → 7 · 콘솔 7 → 4 · 사이트 5). `test/nav.test.mjs` 가 고정한다.
겹치던 것은 화면 안으로 들어갔다 — 문서 ↔ 작업 기록은 세그 · 대기열 ↔ 이력은 탭 · 관리 문서 ↔ 서식집은 탭 · 사용자 ↔ 토큰은 한 페이지(서버 › 사람 · [발급] 은 사람 줄 한 곳) · 작업 레포 대장은 서버 › 지식 레포의 펼침 열(`?wr=1` 이면 전부) · 감사 · 로그는 서버 › 서버의 접힘.
**옛 주소는 열린다** — `/w` · `manage/curation/log` · `manage/forms` 는 그대로 탭 · 거름 주소다. 콘솔의 옛 페이지는 셸이 바꿔 쓴다(`routes.CONSOLE_ALIAS` · replace · `#` 를 들고 간다) — `workrepos` → `repos?wr=1` · `users[?repo=]` → `people[?repo=]` · `tokens[?user=]` → `people?user=`(발급 창) · `people#tokens` · `audit` → `server#audit`. `manage/docs?add=forms`(다음 할 일의 주소) → `manage/forms`. 서식집 탭은 curate 가 아니면 `manage/docs` 로.

- 로컬 항목(지식 레포 · 동기화 · 진단 · 정보)과 `server` · `local` 표지는 걷었다(4ab6acc). 옛 주소 `/r/<레포>/manage/{sync,repo,diag,info}` 는 현황으로 바꿔 연다.
- **묶음은 보이는 항목이 하나라도 있을 때만** 제목째 그린다. 권한 밖 묶음을 회색으로 보이지 않는다(D4). 묶음 제목 옆 작은 표시는 전부 admin 항목이면 「admin」 · 전부 curate 면 「큐레이터」 다.
- **배지**(`badge: 'queue'`) — 대기열 항목에만. 읽는 사람의 대기 수는 읽기 화면의 「기록」 세그가 든다. 레포 얼굴은 `/api/<레포>/repo` 의 `curation.queue`(App 이 읽는 것과 같은 캐시 키), 콘솔은 `/admin/repos` 의 그 레포 행. 창 초점이 돌아오고 60초가 지났으면 다시 읽는다. **값이 없으면 그리지 않는다**(옛 서버).
- 이름은 v1.0 에서 고쳤다 — 관리 › 작업 레포 → **레포 관리 › 연결된 작업 레포** · 콘솔 › 작업 레포 → **서버 › 작업 레포 대장** · 콘솔 › 서버 → **서버 › 서버 설정** · 「콘솔」 은 묶음 「서버」(주소는 `/console/…` 그대로 · L2) · 작업문서 → 작업 기록(cb23d1e).

## 4. 역할 × 얼굴

### 4.1 판정 — `lib/roles.js` 의 `can(me, need, repo)` 하나

| need | 참일 때 |
|---|---|
| `read` | 그 레포가 `/me` 의 `repos` 에 있다 — admin 도 할당된 레포만 |
| `write` | read + `me.write`(writer · admin) |
| `curate` | read + admin 이거나 `me.curate` 에 그 레포 · `*` 가 있다(admin 은 옛 서버여도 모든 레포의 큐레이터) |
| `admin` | `me.admin` — 레포와 무관 |

**모르는 값은 거짓이다** — 세션이 없거나 · 레포를 못 보거나 · 서버가 `curate` 를 안 내면(옛 서버) 그 항목을 그리지 않는다. 서버 판정은 `core/auth.js` 의 `grantOf` 가 같은 규칙으로 한다(시스템설계서 §2.2).

### 4.2 보이는 묶음 — 시험이 고정한 것

| 사람 | 레포 얼굴 `/r/alpha/` | 콘솔 얼굴 |
|---|---|---|
| viewer(alpha) | 지식 · 레포 관리 — 항목 5 | — (「관리자 권한이 필요합니다」 한 장) |
| writer(alpha · gamma) | 지식 · 레포 관리 — 항목 5 | 같다 |
| 큐레이터(writer + `curate: [alpha]`) | 지식 · **큐레이션** · 레포 관리 — 항목 7 · gamma 에서는 큐레이션 없음 | 같다 |
| 큐레이터(`curate: [*]`) | 볼 수 있는 레포 전부에 큐레이션 — 볼 수 없는 레포는 `*` 여도 아니다 | 같다 |
| admin | 지식 · 큐레이션 · 레포 관리 · **서버** — 항목 11 | 서버만(마지막 본 레포가 있으면 넷 다) |
| 세션 없음 | 아무것도 | — |

레포 관리는 **읽기면 보인다** — 쓰는 단추만 그 화면 안에서 `write` · `curate` 로 가린다(개편안 V18 · 셸 설계 §2.1 의 묶음 단위 권한을 바꿨다). writer 가 쓰던 기능(작업 레포 등록 · 설치 한 줄 · 내려받기 · 관리 문서 사용 현황)이 갈 곳을 잃지 않게.

## 5. 주소 체계 — `shell/routes.js`

| | `/r/<레포>/w[?only=pending\|mine]` | 작업 기록 — 거름은 주소다(대기 · 내 기록). 모르는 거름은 전체 |
| | `/r/<레포>/graph` | 좌표 · 그래프 |
| | `/r/<레포>/manage[/overview\|docs\|work]` | 레포 관리 |
| | `/r/<레포>/manage/curation[/log[/<id>]]` | 큐레이션 › 대기열 — 탭 대기열 · 이력(펼친 기록이 주소다) |
| | `/r/<레포>/manage/drift` | 큐레이션 › 진단 |
| | `/r/<레포>/manage/forms[/<묶음>/<번호>][?tab=]` | 레포 관리 › 관리 문서 › 문서 추가 › 서식집(탭 · curate · 서식 탭 `stamp` · `guide` · `example`, 모르는 탭은 첫 탭) |
| 콘솔 | `/console[/repos\|people\|server]` | 서버 묶음 넷 · 옛 페이지는 바꿔 쓴다(§3) |
| 사이트 | `/` · `/manual[/<책>]` · `/login[?next=]` · `/setup` · `/r[?from=]` | 소개 · 설명서 · 로그인 · 처음 설정 · 빈 상태 |

| 함수 | 규칙 |
|---|---|
| `screenOf({ path, query, hist })` | 주소 하나 → `{ face, repo, rest, item, finder, tab, page, sub, logId, form, formTab, alias }` — 셸 · App · 관리 화면 · 콘솔이 **같이** 읽는다. `sub` 는 화면 안의 탭(대기열 `queue` · `log` / 관리 문서 `list` · `forms`) · `alias` 는 옛 · 별칭 주소의 새 자리 |
| `redirectOf(s, me)` | **그리지 않고 바꿔 쓴다**(replace · D4) — 옛 · 별칭 주소 → `alias` · 서식집 탭의 비큐레이터 → 관리 문서 목록 · 없는 관리 주소 → `…/manage` · 그 밖의 없는 주소 → 문서 · 권한 밖 → 문서 · 없는 콘솔 페이지 → `/console`. 볼 수 없는 레포는 고치지 않는다(서버의 404 → `/r?from=`) · 세션 전에는 고치지 않는다 · 바꿔 쓰는 렌더에서는 얼굴을 그리지 않는다(권한 밖 화면이 한 프레임도 서지 않게 · 권한 밖 API 를 부르지 않게) |
| `crumbOf(s)` | 레포 › 묶음 › 화면(› 탭 › 이력 id · 서식 id) · 읽기는 왼쪽 목록의 이름(문서 · 작업 기록) · 콘솔은 서버 › 화면 |
| `titleOf(s)` | `<화면 또는 탭> · <레포> · CDP` · 콘솔 `서버 › <화면> · CDP` |
| `navRepoOf(face, repo, me, last)` | 메뉴가 가리키는 레포 — 레포 얼굴은 주소의 레포, 콘솔은 **마지막으로 본 레포**(볼 수 있을 때만 · 없으면 첫 레포) |

- 로그인 뒤 갈 곳은 역할이 정한다 — admin 은 콘솔, 나머지는 마지막에 보던 레포의 마지막 경로(`landingFor` · 서버의 `landingOf` 와 같은 규칙). `next` 는 그 역할이 갈 수 있을 때만 따른다.
- 서버의 302 는 셋만 남았다 — 세션 없음 → `/login?next=` · `/r` → 첫 레포 · 볼 수 없는 레포 → `/r?from=`. 직접 진입 · 새로고침 · 북마크의 것이다.
- 로그아웃은 `POST /logout`(JSON) → 세션 · 캐시를 비우고 `navigate('/')` — 서버 왕복이 필요한 유일한 전환도 문서를 갈지 않는다.

## 7. 권한 경계 — 화면이 숨기고 서버가 막는다

| 화면 · 단추 | 화면 need | 서버 판정 |
|---|:--:|---|
| 지식 전부 · 검증 · 현황 · 관리 문서 보기 · 내려받기 | read | `/api/<레포>/*` — 볼 수 없는 레포는 **404**(없는 것과 같다) |
| 대기열(· 이력 탭) **메뉴** · 서식집 **탭** | curate | 목록 API(`GET /queue` · `/curations` · `/forms`)는 볼 수 있으면 열린다 — 숨길 비밀이 아니다 · 판정 재료(`GET /queue/<id>`)만 curate(403). **화면 숨김 ≠ 막힘** — writer 의 `/queue` · `/curations` · `/forms` 200 은 의도된 공개다(제품화 2 D9) |
| [기록으로 둠] | curate | `POST /api/<레포>/curate` — curate(403) · write |
| 관리 문서 [지우기] | curate | `POST /api/<레포>/docs-drop` — curate(403) |
| 연결된 작업 레포 — 보기 · 설치 한 줄 · 꾸러미 | read | `GET /workrepos` · `GET /kit/<레포>` — 볼 수 있으면. 담당자 후보(명부 이름)는 write 에게만 |
| 연결된 작업 레포 [등록] · [삭제] | write | `POST · DELETE /workrepos` — write(403) · 지우기는 그 레포를 볼 수 있어야(아니면 404) |
| 서버 묶음 전부 · 레포 메뉴의 「관리자만 — 이 서버의 레포」 | admin | `/admin/*` — admin(403) · `--admin-from` 대역 · 쓰기는 재인증(401 `E_REAUTH`) |
| 레포 메뉴의 권한 칩(쓰기 · 읽기) | write | — |

- **권한 밖은 존재를 알리지 않는다**(D4) — 권한 밖 주소는 문서로 바꿔 쓰고 「권한이 필요합니다」 를 그리지 않는다. 볼 수 없는 레포는 없는 레포와 같은 길이다. 콘솔에 들어온 비관리자에게만 서버의 403 과 같은 문장 한 장(관리자 0명인 서버를 세우는 길은 설명서 절 — 셸 명령 · 경로를 화면에 박지 않는다).
- **권한 밖 일은 안내하지 않는다**(안내 글 규칙 ③) — viewer 에게 등록 카드 · 「아래에서 등록하세요」 · 「큐레이터에게 지우기를 요청하라」 가 없다. 미러를 푸는 길(서버 › 지식 레포)은 admin 에게만 보인다.

| 줄 | 사실 한 문장 + 할 일 하나(`go` — 화면 주소 → 단추 · `cmd.args` — 설치기 인자 → [설치 한 줄] 이 셸 셋 탭과 명령을 편다 · `installCommand(shell, { args })` 한 곳) + `?`(설명서 절 — `help` 주제 → `/manual/<책>#<절>`) |
| 빈 배열 | 카드가 없다 — 끝난 줄 · 권한 밖 줄은 서버가 이미 뺐다. 그 자리에 `empty`(한 문장 · 또는 없음) |
| 읽는 동안 | 아무것도 그리지 않는다(「읽는 중…」 으로 자리를 잡았다 사라지면 깜빡임) · 30초 캐시(`/next…`) · 등록 · 판정 · 지우기 · 스냅샷 · 레포 세우기 뒤 `invalidate('/next')` |
| 실패 | 옛 서버(404)는 카드 없음 · 그 밖은 한 줄로 말한다 |
| 큐레이터 폴더 | 설치 한 줄은 **이 카드 한 곳에만**(옛 대기열 · 연결된 작업 레포의 두 카드를 걷었다) |

## 7.2 안내 글 규칙(제품화 2 ⑦ · 검토 §5.6)

1. **화면 하나에 한 줄** — 카드 `hint` 는 40자 안. 「왜」 는 설명서 절 링크 `?`(`components/HelpLink.jsx`)로
2. **빈 상태는 한 문장 + 다음 할 일 하나**, 아니면 그리지 않는다 — 0 인 숫자 카드 · 대상 없는 단추 없음(대기 0 · 신호 0 · 관리 문서 0 · 빈 레포)
3. **권한 밖 일은 안내하지 않는다** — 「권한이 필요합니다」 는 콘솔 진입 하나만
4. **설계 근거는 화면에서 뺀다** — 「알림을 띄우지 않는다」 · 「서버는 LLM 을 부르지 않는다」 · 상태 칩 범례 표는 설계서 · 설명서로
5. **숫자 · 장 번호 · 경로는 손으로 쓰지 않는다** — 서버가 준 값(설명서 앵커 `/site/info` 의 `help` · 설치 자리 `/admin/server` 의 `data` · 빌드 시각은 자리표 `__…` 면 안 그림 — `format.builtOf`)
6. **설명서와 같은 글은 지우고 절 링크로** — 설치 안내는 명령 한 줄 + 두 줄 + 절 링크

`test/screen-text.test.mjs` 가 지킨다 — 화면 소스(주석 밖)에 「N장」 · 「다섯」 · `/opt/cdp` · 도구 · 스킬 개수 리터럴 0 · 카드 `hint` 리터럴 40자 안 · 설계 근거 문장 0.

## 8. 데이터 읽기 · 캐시

| | 규칙 |
|---|---|
| 세션 | `SessionProvider` 가 `/site/info` · `/me` 를 한 번에 읽는다 — 로그인 · 로그아웃 · 마법사가 갱신한다 |
| 캐시 | `lib/cache.js` `useResource(key, fetcher, { ttl })` — 키는 `api:<레포>/<경로>` 또는 절대 경로. **마운트 때 캐시가 있으면 즉시 그리고 뒤에서 갱신**(stale-while-revalidate) · 같은 키는 요청 하나를 나눠 받는다 · 「읽는 중…」 은 캐시가 없을 때만 · 쓰기 뒤 `refresh()` 또는 `invalidate(키 · 접두)` · 로그아웃은 `clearAll()` |
| 레포 | `lib/api.js` 의 `req()` 가 **부르는 시점**의 주소에서 레포를 읽는다. 얼굴을 넘어 살아남는 부품(메뉴의 배지)은 `repoApi(name)` 으로 이름을 박아 부른다 |
| 갱신 | 서버 모드에 SSE · 알림은 없다 — 마운트 · 창 초점 · 쓰기 뒤에만. 실시간이 아니라 **다시 열면 새것**이다. 세션은 레포 화면을 열 때 30초가 지났으면 뒤에서 한 번 더 |
| 옛 서버 | 값 · 엔드포인트가 없으면 칩 · 배지를 그리지 않는다(「대기 0」 과 「모름」 을 섞지 않는다). 화면 전용 자리(큐레이션 · 서식집)만 「이 서버는 아직 … 을 내지 않는다 — v0.27 이상」 한 줄 |
| 라우트 전환 | `startTransition` — 새 화면의 첫 렌더가 끝날 때까지 이전 화면이 남는다 |

## 10. 색 예산 — V19

**정상은 조용하고 이상만 소리를 낸다.** 색은 넷뿐이고 `--success`(초록) 토큰은 정의하지 않는다 — 정의해 두면 누가 「유효」 에 쓰고, 화면의 90% 가 초록이 되어 색이 뜻을 잃는다.

| 색 | 토큰 | 뜻 | 큐레이션에서 |
|---|---|---|---|
| 파랑 | `--accent` | 상호작용 — 링크 · 선택 · 포커스 · 새 표지 | 「등록부 없음」(새 문서 후보) 칩 · 서식집의 등록부 칩 |
| 보라 | `--pending` | **행동 대기** | 「대기」 칩 · 「미반영 n」 칩과 블록 · 상태 표시줄 「대기 n」 |
| 앰버 | `--warn` | 경고 | 14일 넘은 대기(가장 오래된 · 상태 표시줄) |
| 적 | `--danger` | 무효 — 깨진 참조 · 섹션 · 문서 없음 | — |
| (무채색) | — | 정상 | 「반영됨」 · 「기록으로 둠」 · 최신 |

목업이 그렸던 초록(22곳) · 주황(10곳)은 쓰지 않는다 — 목업도 이 예산으로 고쳤다(28c9b50). 그래프의 노드도 상태로 색을 쓰지 않는다 — 카테고리를 고를 때만 파랑(지금 무엇을 고르고 있나)이다.
