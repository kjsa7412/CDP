## 0. 한 줄

**패키지는 40종을 붓는데 한 프로젝트가 다 쓰지 않는다. 그런데 「안 쓰는 문서를 지운다」 는 지금 셸에서 사람이 파일을 지우는 일이고, 서버형 레포에는 그 길이 아예 없으며, 셸에서 지워도 검사가 아무것도 말하지 않는다.** 등록된 문서(`TE_202`)를 지워도 `ctx check` 는 「오류 없음」 이고 그 타입에 작업 기록이 닿는 순간 레포 전체의 커밋이 막힌다. 지운 문서를 가리키는 자리 — 형제 문서의 「여기 적지 않는 것 → 어디로」 표 · `README.md` 목록 행(링크) · `_vocab.md` 판정표 · `관리번호.md` — 는 그대로 남는다(TE_202 하나에 9곳). **권장안은 셋이다 — ① `core` 가 문서마다 「쓰는가」 를 재고(사용 현황) ② `save.managed[]` 에 `drop`(admin)을 더해 파일 · 그 문서를 가리키는 행 · 그 문서만 받던 예시 좌표를 한 커밋에 지우며 ③ 그 문서를 가리키는 나머지 자리는 v0.21.0 의 `E_INPUT lines` 와 같은 틀로 「같은 save 의 `edits` 로 고치거나 `reviewed` 로 넘긴다」 를 강제한다.** 화면은 레포 관리에 「관리 문서」 탭(목록 · 사용 현황 · 미리보기 · 지우기)을, 새 레포 화면에 「문서 고르기」 를 둔다. 지우기는 둘 다 같은 `save` 를 탄다 — 화면이 파일을 따로 만지지 않는다.

## 1. 운영자의 말 · 검토의 틀

> 프로그램내에서 관리문서 관리가 가능해야 할 듯하다. 예를들어 현재 필요한 부분은 패키지를 써서 관리문서를 가져왔는데 안쓰는 애들이 존재한다. 이때 삭제했으면 하고 연결관계도 잘 정리해줬으면 한다.

말을 셋으로 나눠 본다.

| 축 | 질문 | 깊이 |
|---|---|---|
| **A 보기** | 어느 문서가 「안 쓰는」 문서인가 — 그 판단의 재료가 프로그램 안에 있나 | 깊게 |
| **B 지우기** | 서버형 · 셸 · 화면에서 문서를 지울 수 있나 · 지울 때 무엇이 같이 가야 하나 · 무엇은 지우면 안 되나 | 깊게 |
| **C 연결 정리** | 「연결관계」 가 실제로 어디 박혀 있나 · 무엇을 기계가 닫고 무엇을 사람이 닫나 · 지운 뒤 끊긴 것을 누가 알려 주나 | 깊게 |
| D 세울 때 | 처음부터 안 쓸 문서를 빼고 세울 수 있나 | 보통 |
| E 에이전트 · 설명서 | 스킬 · 패키지 README 의 「첫날 5단계」 가 서버형에서 거짓이 되지 않나 | 보통 |

심각도 — **P0** 데이터가 조용히 틀어진다 · **P1** 막히거나(또는 나중에 레포가 잠기거나) 풀 길이 안 보인다 · **P2** 되지만 손이 많이 간다 · **P3** 잔손.

## 4. 개선안 — 대안과 권장

### 4.1 「연결관계」 가 어디 있나 — 다섯 종류로 나눈다

지울 때 같이 닫아야 하는 것을 먼저 정한다. **기계가 확실히 닫을 수 있는 것과 사람의 판단이 드는 것이 갈린다.**

| 종류 | 예(TE_202) | 누가 닫나 | 왜 |
|---|---|---|---|
| **R1 등록부 행** | `_managed.md` `시험시나리오:PT-*` | **기계** — `drop` 이 같이 지운다 | 지운 파일을 가리키는 행은 K2 의 시한폭탄이다. 남길 이유가 없다 |
| **R2 생성 블록** | `_vocab.md` `cdp:registry` 블록 · 각 문서 머리 표 `등록부` 칸 | **기계** — save 9.5 가 다시 찍는다(v0.21.0) | 이미 사본이 아니라 찍은 것이다 |
| **R3 예시 좌표** | `_vocab.md` `시험시나리오:PT-EXA010`(example:) | **기계** — 그 좌표가 지운 문서로만 가던 것이면 같이 지운다 | 예시는 「좌표로 세지 마라」 는 표시다. 짝 섹션이 사라지면 뜻이 없다(`ctx examples` 의 「둘을 같이 지워라」) |
| **R4 링크 · 목록 행** | `README.md` `[성능테스트시나리오](docs/…TE_202….md)` 목록 행 · `관리번호.md` 표 | **기계가 제안 · 사람이 고른다** | 행 하나에 그 문서만 있으면 행을 지우면 되지만 `관리번호.md` 의 「`TE_201` `TE_202` `TE_203`」 처럼 **여럿을 담은 행**은 글을 고쳐야 한다 |
| **R5 산문 · 「어디로」 표** | `TE_201` 「밟을 절차 \| `성능테스트시나리오`」 · `TE_203` 본문 · `_vocab` 판정표 | **사람(또는 에이전트)이 고친다** | 그 정보를 **어디로 보낼지**는 판단이다 — 성능시험을 안 하면 그 행 자체가 필요 없고, 통합시험으로 합쳤으면 「어디로」 가 바뀐다 |
| (닫지 않는 것) `work/` 의 언급 | 작업 기록 본문 · `touches` | **안 닫는다** | 불변조건 3. 지운 문서로 가던 좌표는 「등록부 없음」 이 되어 작업 기록이 원천으로 돌아간다(retire 와 같다) |

**권장: R1~R3 은 `drop` 한 번이 한 커밋에 닫고, R4 · R5 는 v0.21.0 과 같은 틀로 「같은 save 에서 `edits` 로 고치거나 `reviewed` 로 넘긴다」 를 강제한다.** 기계가 산문을 고쳐 쓰지 않는다 — 대신 **어디를 고쳐야 하는지는 한 줄도 빠짐없이** 서버가 찾는다.

### 4.2 지우는 자리 — `managed[]` 에 `drop` vs 별도 도구 vs 사람에게 — **권장 A**

| 안 | 모양 | 장 | 단 |
|---|---|---|---|
| **A `managed: [{ op: "drop", doc }]`** | 동적생성 M1 의 같은 자리. 파일 · R1 · R3 이 한 계획(`planManaged`)에 든다 | 한 커밋 · 한 작업 기록(사유) · 한 `Snap` 롤백 · 권한 검사 자리 · 명함 그대로(MCP 도구 14 유지). `edits` · `reviewed` 와 같은 입력에 같이 탄다 | 입력이 또 커진다 |
| B 별도 도구 `docs_drop` | | 입력이 짧다 | R4 · R5 를 고치는 `edits` 와 **다른 커밋**이 된다 — 중간 상태(파일은 없고 링크는 남은)가 커밋된다. 도구 수를 세는 곳 여덟이 바뀐다 |
| C `retire` 가 파일도 지우게 | | 새 op 없음 | `retire` 는 「행만 · 내용은 남는다」 로 이미 문서화 · 시험됐다. 뜻을 바꾸면 이미 쓴 스킬 · 설명서가 거짓이 된다. 비대상 문서는 행이 없어 여전히 못 지운다 |

**A.** 세 동작의 뜻을 표로 못박는다 — 스킬 · 설명서 · 화면이 이 표를 그대로 쓴다.

| | 행 | 파일 | 내용 | 언제 |
|---|---|---|---|---|
| `retire` | 지운다 | **남긴다** | 남는다(등록부 밖 문서) | 좌표 판정만 끄고 문서는 읽을거리로 둔다 |
| `merge` | `into` 로 돌린다 | 지운다 | `into` 로 **옮긴다** | 두 문서를 하나로 |
| **`drop`** | 지운다 | **지운다** | **git 이력에만** 남는다 | 이 프로젝트에 **필요 없는** 문서 |

### 4.3 `drop` 의 규칙 — **권장: 내용을 잃는 drop 은 거절 · 나머지는 admin 판단**

| 조건 | 결과 | 왜 |
|---|---|---|
| 권한 | **admin**(`retire` · `merge` 와 같은 자리 · 파일을 만지기 전) | 문서를 없애는 일이다. writer 는 요청문을 만든다(스킬) |
| 문서에 **실제 좌표 섹션**이 있다(예시가 아닌 · 그 문서의 행이 받는 섹션) | **거절** `E_INPUT { realSections: [coord…] }` — 「내용이 있다 — 보존하려면 `merge`, 판정만 끄려면 `retire`」 | 지우면 그 좌표의 정본이 사라진다. 이 경우는 「안 쓰는 문서」 가 아니다 |
| 작업 기록이 그 문서의 좌표를 `touches` 한 적이 있다 | **거절** `E_INPUT { touchedBy: [work id…] }` — 같은 안내 | 파생이 한 번이라도 돈 문서다. 「안 쓴다」 가 아니다 |
| 비대상 문서(행 없음) | **허용** — 내용 판정은 하지 않는다. 응답 · 미리보기가 `lastChange`(그 파일을 마지막으로 바꾼 커밋 · 작업 기록)를 같이 보여 준다 | 비대상 문서의 「내용」 을 기계가 가를 수 없다(서식 골격과 쓴 글이 같은 모양). 지워도 git 에 있고, **판단은 admin 이 미리보기를 보고** 한다 |
| 머리 표 `필수 제출 \| 예` | **경고**만 | 필수인지는 계약이 정한다 — 서식이 정하지 않는다 |
| 그 문서를 가리키는 R4 · R5 가 있고 이 save 의 `edits` · `reviewed` 가 덮지 않는다 | **거절** `E_INPUT { refs: [{ file, line, text, kind, suggest }] }` — v0.21.0 의 `lines` 와 같은 모양 | K3 — 끊긴 연결을 남긴 채 커밋하지 않는다. 다만 「알고 둔다」 는 `reviewed: ["파일:행"]` 로 허용 |
| 여러 문서를 한 번에(묶음) | 허용 — `managed` 최대 10건 그대로. **같은 drop 묶음 안의 문서끼리 가리키는 참조는 refs 에서 뺀다** | 시험 3벌 · 이관 3벌을 같이 지울 때 서로의 「어디로」 표를 고치라고 하는 것은 소음이다(Q2'') |
| 검사에서 걸렸다 | 기존 그대로 — `Snap` 이 지운 파일 · 행 · 어휘를 전부 되돌린다 | `Snap.remove` 가 이미 있다(merge) |

`suggest` 는 화면이 한 번에 고를 수 있게 서버가 붙이는 제안이다 — `drop-row`(표 행에 그 문서만 있다 → 행을 지운다) · `unlink`(링크 → 링크 글자만 남긴다) · `review`(산문 · 여럿을 담은 행 → 사람이). **서버는 제안만 하고 고치는 것은 `edits` 로 들어온 것만이다** — 같은 입력이 셸 · MCP · 화면에서 같다.

### 4.9 화면 — 레포 관리에 「관리 문서」 탭 · 새 레포에 「문서 고르기」 (K4 · K5) — **권장**

**어디에.** 화면 · 권한 검토 R 의 분담 그대로 — 레포 하나의 일이므로 **레포 관리**(`AdminView` 메뉴)에 탭 하나. 콘솔(서버 전부)이 아니다. writer · viewer 는 **보기만**, admin 은 지우기까지.

```
관리 문서                                                  40종 · 좌표 14 · 비대상 26
 [쓰는 중만] [서식 그대로만] [필수]                              검색 ____________
 ┌──┬────────┬────────────────┬──────┬────┬───────┬──────┬──────┬────────────┐
 │☐ │ 번호   │ 문서            │ 유형 │필수│ 섹션  │ 작업 │ 참조 │ 마지막 변경  │
 ├──┼────────┼────────────────┼──────┼────┼───────┼──────┼──────┼────────────┤
 │☐ │ TE_201 │ 성능테스트계획서 │ 비대상│    │   —   │  0   │  4   │ 세움 09-12 │
 │☐ │ TE_202 │ 성능테스트시나리오│ 좌표 │    │ 0 · 예1│  0   │  6   │ 세움 09-12 │

 └──┴────────┴────────────────┴──────┴────┴───────┴──────┴──────┴────────────┘
                                                [선택한 3종 지우기 미리보기]
```

**미리보기 → 지우기.** 미리보기는 `save` 를 **`dryRun: true`** 로 부른다(새 입력 — 계획 · 거절 · `refs` 까지 전부 돌고 파일은 안 만진다). 화면이 보여 주는 것 —

1. 지울 파일 · 지울 등록부 행 · 지울 예시 좌표
2. **고칠 자리** — `refs` 줄마다 `suggest` 를 기본값으로 고른 라디오: 「행 지우기」(`drop-row`) · 「링크만 풀기」(`unlink`) · 「알고 둔다」(`reviewed`). `review` 제안 줄은 「알고 둔다」 가 기본이고 **산문은 화면이 고쳐 쓰지 않는다** — 고쳐 쓰려면 에이전트(`cdp-managed`)에게
3. 사유 한 줄(필수) → 작업 기록 본문

「지운다」 는 같은 입력으로 `save` 를 한 번 부른다 — 작업 기록 `work: { title: "관리 문서 정리 — <n>종", body: 사유 + 목록, tags: [docs-prune], touches: [] }` · `managed: [{op:"drop"}…]` · `edits`(화면이 고른 행 지우기 · 링크 풀기를 `old/new` 로) · `reviewed`. **화면이 파일을 따로 만지는 길은 만들지 않는다** — 불변조건 5(보증은 `save` 의 검사뿐).

**새 레포의 「문서 고르기」.** 패키지를 고르면 문서 목록(묶음별 접기 · 필수 표시 · 기본 전부 체크)이 펼쳐진다. 뺀 문서가 있으면 **세움 커밋 다음에 같은 `drop` save 를 한 번 더**(작성자 = 세운 admin · 사유 「세울 때 뺌」) — 세우는 길에 두 번째 지우기 코드를 만들지 않는다. 이때 `refs` 는 `suggest` 그대로 적용하고 `review` 줄은 `reviewed` 로 넘긴 뒤 **결과 화면에 「남은 언급 n줄」** 로 보여 준다(그리고 `doc-ref-dangling` 경고가 계속 말한다).

**모드 A(셸 · 로컬 뷰어).** 로컬 뷰어 · `ctx docs` 에 같은 사용 현황을 보인다. 지우기는 `ctx docs drop <문서…> [--dry-run]` — **같은 계획 함수**로 작업 트리를 고치고 커밋은 사람이 한다(훅이 검사). 패키지 README 의 첫날 5단계 1 · 2 가 이 한 줄이 된다.

### 4.10 에이전트 · 설명서 (E) — **권장**

- `cdp-managed` 에 「문서 정리」 절 — `docs({ repo })` 의 `usage` 로 후보 표를 만들고 **사람에게 고르게** 한다(묶음 단위로 제안) → `dryRun` → `refs` 의 `review` 줄은 **에이전트가 고쳐 쓸 `edits` 를 초안으로** 보인다 → 승인 → save. admin 이 아니면 요청문을 만든다(동적생성 §5.9 와 같다)
- `cdp-save` 의 【등록부 변경】 덩어리에 「지울 문서」 줄 · 「고칠 자리 n줄」 을 더한다
- 패키지 README 셋의 「첫날 5단계」 — 서버형(화면 「문서 고르기」 · 레포 관리 「관리 문서」)과 셸(`ctx docs drop`)을 나란히. **「2를 빠뜨리면 조용하지 않다」 문장을 고친다**(Q4 — 지금은 거짓) — 새 판에서는 `registry-missing` 경고가 말한다
- 설명서(`manual/` 관리자 · 사용자, `agent/manual`) — `retire` · `merge` · `drop` 표(§4.2)를 한 곳에

## 5. 하지 않을 것

| 안 하는 것 | 왜 |
|---|---|
| 실제 좌표 섹션이 있는 문서의 `drop` · 강제 옵션 | 내용이 있으면 「안 쓰는 문서」 가 아니다 — `merge` · `retire` 가 있다 |
| 산문 자동 교정 · 「어디로」 표 재작성 | 어디로 보낼지는 판단이다(R5). 기계는 찾기만 |

## 6. 전제 — 지키는 결정

- **한 커밋 · 전부 되거나 전부 안 된다** — 파일 · 행 · 어휘 · 생성 블록 · `edits` · 지운 기록 · 작업 기록이 같은 `Snap` · 같은 검사 · 같은 커밋.
- **판정은 `core/` 한 곳** — `findDocRefs` 를 `save`(거절) · `check`(경고) · `docusage`(참조 수)가 같이 쓴다. `drop` 계획은 `planManaged` 안에.
- **화면은 `save` 를 부른다** — 미리보기도 `dryRun` 의 `save` 다. 계획을 화면에서 따로 세우지 않는다.
- **권한은 명부** — `drop` 은 admin. `saver` 는 이미 `admin` 을 넘긴다(동적생성 ②).
- **`work/` 는 불변 · 읽기만.**
