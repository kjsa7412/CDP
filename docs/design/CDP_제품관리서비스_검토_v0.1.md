## 0. 한 줄

**관리 서비스는 이미 "레포를 보는 화면" 이고 관리자의 일은 대부분 셸에 남아 있다.** 소개 페이지도
설명서 페이지도 서버에 없다 — 설명서는 GitHub 의 `manual/` 에만 있고 서버 산출물에 들어가지 않는다.
사람을 붙이는 일(명부 · 토큰)은 전부 `sudo -u cdp node …` 다.

제품이 되려면 세 얼굴이 **한 서버 · 한 포트 · 한 번들**에서 나와야 한다 — `/` 소개, `/manual` 설명서,
`/console` 콘솔, 그리고 지금의 `/r/<레포>/`. 서버를 **세우는 것**(`install.sh` · root · 한 줄)만
셸에 남고, **첫 관리자부터**는 브라우저다 — `install.sh` 가 찍어 주는 일회용 코드로 설치 마법사가
명부를 만든다. 그 뒤 사람 · 토큰 · 레포 · 작업 레포 · 진단 · 감사가 전부 콘솔에 있다.
비밀(PAT)과 프로세스 자신을 갈아 끼우는 일(`upgrade.sh`)은 브라우저로 가지 않는다 — 그 둘이 "브라우저에서
전부" 의 정직한 예외다.

### 2.3 이어받는 결정 — 검토 v0.1 의 D1~D8

앞 검토가 관리자 역할과 화면 발급을 이미 정했다(**D1 허용 · D2 첫 관리자는 셸 · D3 원문 보관 안 함 · D4 재배정
안 함 · D5 삭제 없음 · D6 권한 밖 레포는 관리자에게만 · D7 재인증 · D8 순서**). 이 문서는 그것을 **그대로 이어받고**
둘을 정정한다 —

| 앞 결정 | 이 문서 | 왜 |
|---|---|---|
| D2 첫 관리자는 `serve init`(셸) | **셸 + 브라우저 마법사.** `install.sh` 가 일회용 부트스트랩 코드를 찍고, 브라우저 `/setup` 이 그 코드로 첫 관리자를 만든다. `init` 도 남는다 | 원칙("부트스트랩은 셸을 가진 사람")은 같다 — 코드를 읽으려면 셸이 필요하다. 다만 그 뒤가 브라우저다(R5) |
| `/admin/*` 는 admin 아니면 **404** | **403** `E_FORBIDDEN` | 404 는 레포 이름을 숨기는 규칙(§4.6)이다. 콘솔의 존재는 설명서에 적혀 있어 숨길 것이 아니고, 404 로 위장하면 "권한이 없다" 와 "주소가 틀렸다" 를 사람이 구분하지 못한다 |

앞 검토 §4.3 의 화면 그림(관리 > 사용자 · 토큰)은 **콘솔의 두 페이지**가 된다 — 레포 안이 아니라 서버 전체의 자리로.

## 3. 관리자 설명서를 걷는다 — 무엇이 브라우저로 가나

기준은 둘이다. **① 서버 프로세스가 자기 권한으로 할 수 있는가**(root · 다른 호스트의 파일 · 자기 자신의 교체는 못 한다)
**② 비밀이 브라우저를 건너야 하는가**(평문 HTTP 배치다 — 건너지 않게 한다).

| 장 | 관리자가 하는 일 | 지금 | 브라우저 | 왜 |
|---|---|---|---|---|
| 3.2 | `install.sh` — 계정 · 폴더 · 유닛 · 기동 | 셸 | **✗ 셸** | root 다. 브라우저는 그 서버 **안에서** 돈다 — 자기를 세울 수 없다. 대신 끝에 **부트스트랩 코드와 `/setup` 주소**를 찍는다 |
| 3.3 | git 자격 — PAT 를 `.git-credentials` 에 | 셸 | **✗ 셸** | 비밀이 평문 HTTP 를 건넌다. 콘솔은 **상태만**(doctor 의 `origin 도달 · push 자격`) 보이고 명령을 복사해 준다 |
| 3.4 | 지식 레포 — `repo new` · `git clone` | CLI · 화면(`repo new` 만 · 레포 안에서) | **○ 콘솔** | `POST /repos` 가 이미 있다. **clone 길**을 더한다 — 이미 있는 레포를 붙이는 것도 "폴더를 두는 것" 이다 |
| 3.5 · 6장 | 명부 · 토큰 — `init` · `user add/set/list` · `token …` | 셸 | **○ 콘솔** | 검토 v0.1 D1. 첫 관리자는 마법사 |
| 3.6 · 7.5 | `doctor` | 셸 | **○ 콘솔** | 읽기다. 함수로 빼서 같은 줄을 낸다 |
| 3.7 | 화면 확인 | 브라우저 | — | 그 자체 |
| 3.8 · 3.9 | Docker · 되돌리기 | 셸 | **✗ 셸** | 프로세스 밖의 일 |
| 5장 | 작업 레포 등록 · 꾸러미 | 화면(레포 안) | **○ 있음** · 콘솔은 **전 레포 한눈**에 | 이미 브라우저다. 콘솔은 서버 전체의 대장을 보인다 |
| 7.1~7.4 | 첫날 정리 · 어휘 · 등록부 편집 | 스킬 · git | **✗** | §6.5 — 지식 레포 **내용**은 `save` 만 쓴다. 등록부는 바깥에서 고쳐 origin 에 올리고 7.6 으로 맞춘다(열린 것 — §8) |
| 7.6 | 서버 트리를 origin 과 맞추기(`pull --ff-only`) | 셸 | **△ 뒤로** | ff-only 는 merge 가 아니라 불변조건 10 을 깨지 않는다. 다만 `save` 뮤텍스와 엮어야 해서 ⑦ 로 미룬다 |
| 8장 | `import-dir` | 개발 PC 셸 | **✗** | 원본이 사람 PC 에 있다. 서버 트리에 직접 돌리지 않는다는 규칙도 그대로 |
| 9.1 | `upgrade.sh` | 셸 | **✗ 셸** | 자기 자신(`ctx.mjs`)을 갈아 끼우고 재시작한다. 실패했을 때 복구 길이 셸뿐이라 브라우저에서 시작하면 안 된다. 콘솔은 **판 · 빌드 시각과 명령**을 보인다 |
| 9.3 · 9.4 | 작업 레포 낡음 · 만료 | 화면(레포 안) · `token list` | **○ 콘솔** | 현황 카드가 만료 임박 · 낡음을 모아 보인다 |

하나다 — 그것이 셸에 남는 유일한 반복 절차다.

## 4. 설계

### 4.1 한 프로세스 · 한 번들 · 세 얼굴

```
ctx serve  (한 프로세스 · 한 포트 · 같은 명부 · 같은 레포 캐시)
 ├─ /                    소개                 공개*        ┐
 ├─ /manual[/<책>]       설명서               공개*        │  사이트  (Site)
 ├─ /login · /setup      로그인 · 설치 마법사  공개(자체 인증) ┘
 ├─ /console[/<페이지>]  콘솔                 세션 + admin    콘솔  (Console)
 ├─ /r/<레포>/…          지식 레포 화면       세션            레포  (App — 지금 그대로)
 ├─ /api/<레포>/…  /repos  /packages  /workrepos*  /kit/*      (지금 그대로)
 ├─ /site/*              사이트 API           공개*
 ├─ /admin/*             콘솔 API             세션 + admin (+ 쓰기는 재인증)
 └─ /mcp*  /healthz                                          (지금 그대로)

 *  --private-pages 를 주면 소개 · 설명서도 세션을 요구한다
```

**"개별 서비스" 를 별도 프로세스로 만들지 않는다.** 콘솔이 다루는 것(명부 · 레포 · 패키지 · 대장)은 전부 `ctx serve`
가 이미 들고 있다. 프로세스를 나누면 `auth.json` 의 작성자가 둘이 되고 레포 캐시를 두 번 읽고 유닛이 둘이 된다 —
설치 · 갱신 · 방화벽이 전부 두 배다. 대신 **주소가 얼굴을 가른다**(§6.8 "모드는 주소가 말한다" 의 확장). 한 번들에서
`main.jsx` 가 경로 첫 조각으로 셋 중 하나를 띄운다.

로컬 뷰어(모드 A · `viewer/server/index.js`)는 **바뀌지 않는다.** `/` 가 그대로 문서 화면이다 — 서버가 `index.html` 을
낼 때 `window.__CDP_SERVER__` 한 줄을 심어 화면이 자기가 어디서 왔는지 알게 한다(왕복 없이).

### 4.2 라우트

**화면** (전부 같은 `index.html` · 라우팅은 화면이)

| 경로 | 얼굴 | 인증 | 무엇 |
|---|---|---|---|
| `/` | 사이트 | 공개* | 소개 · 이 서버(판 · 레포 수 · 미러 집계) · [들어가기] [설명서] · 세션이 있으면 [내 레포로] |
| `/manual` · `/manual/<책>` | 사이트 | 공개* | 세 권 + 설치절차. 왼쪽 목차 · 오른쪽 본문(`renderMarkdown` 재사용) |
| `/login` | 사이트 | — | 토큰 한 칸. 지금의 서버 HTML 을 SPA 로 옮긴다(`web/` 이 없으면 옛 HTML 이 폴백) |
| `/setup` | 사이트 | 부트스트랩 코드 | 명부가 비었을 때만. 코드 → 첫 관리자 → 토큰 한 번 → 콘솔 |
| `/r` | 사이트 | 세션 | 볼 수 있는 첫 레포로. 없으면 "볼 수 있는 지식 레포가 없습니다"(관리자면 콘솔로 가는 길) |
| `/console`, `/console/<페이지>` | 콘솔 | 세션 · admin | 현황 · 사용자 · 토큰 · 지식 레포 · 작업 레포 · 서버 · 감사 |
| `/r/<레포>/…` | 레포 | 세션 | 지금 그대로 |

**API**

| 메서드 · 경로 | 인증 | 무엇 |
|---|---|---|
| `GET /site/info` | 공개 | `{ version, built, repos: n, mirror, setupNeeded, privatePages, manuals[], user?, role? }` — 레포 **이름은 없다**(`/healthz` 와 같은 규칙). 쿠키가 살아 있으면 `user` · `role` 만 더한다 |
| `GET /site/manual/<파일>.md` | 공개* | `manual/` 폴더의 md 원문(+ `deploy/설치절차.md` · `manual/그림/*.svg`). 목록 밖 파일 · `..` 는 404 |
| `POST /setup` | 코드 | `{ code, name, label }` → 첫 관리자(`admin` · `repos:['*']`) + 토큰 → `{ user, raw, id, expires }` + 세션 쿠키. 명부가 있으면 409 · 코드가 틀리면 401 · 속도 제한 |
| `POST /login` | 토큰 | form 과 JSON 둘 다. JSON 이면 `{ ok, next }` · 실패 401 한 문장 |
| `GET /me` | 세션 | 지금 것 + `role · admin · sudo`(재인증 쿠키가 살아 있나) |
| `POST /admin/sudo` | admin | `{ token }` — 자기 토큰 원문을 한 번 더. 15분짜리 `cdp_su` 쿠키(서명 · user 포함) |
| `GET /admin/overview` | admin | 집계 — 사용자 · 관리자 · 토큰(활성 · 7일 내 만료 · 폐기) · 레포(수 · 미러) · 작업 레포(최신 · 낡음 · 미설치) · 마지막 doctor 요약 · 경고 목록 |
| `GET /admin/users` | admin | 이름 · 라벨 · 역할 · 레포 · 활성 · 토큰 수 · 마지막 사용 · `left` |
| `POST /admin/users` | admin · 재인증 | `{ name, label, role, repos }` |
| `PATCH /admin/users/<name>` | admin · 재인증 | `{ label? role? repos? active? }` — 마지막 admin 을 내리거나 끄면 409 `E_LAST_ADMIN` · 자기 자신의 역할 · 활성은 400 `E_SELF` |
| `GET /admin/tokens` | admin | id · 사용자 · 메모 · 발급 · 만료 · 남은 일수 · 마지막 사용 · 상태 · 폐기 정보. **원문 없음** |
| `POST /admin/tokens` | admin · 재인증 | `{ user, note, expiresDays? }` → `{ raw, id, expires }` — 원문은 이 응답 한 번. 기본 만료는 그 사람의 역할로(admin 30 · 나머지 90) |
| `POST /admin/tokens/<id>/reissue` | admin · 재인증 | 폐기 + 발급 한 동작 → `{ raw, id, old }` |
| `POST /admin/tokens/<id>/revoke` | admin · 재인증 | `status: revoked` — 줄을 지우지 않는다 |
| `PATCH /admin/tokens/<id>` | admin · 재인증 | `{ note?, expires? }`(`YYYY-MM-DD` · 일수 · `never`) |
| `GET /admin/repos` | admin | 서버의 레포 **전부** — 이름 · 제목 · head · branch · 미러 · 문서 수 · 볼 수 있는 사람 |
| `POST /admin/repos` | admin · 재인증 | `{ name, package, origin? }`(세운다) 또는 `{ name, clone }`(origin 에서 받는다) + `grant?: [이름]` — 세운 뒤 그 사람들의 `repos` 에 넣는다 |
| `GET /admin/workrepos` | admin | 대장 전부(레포 무관) + 상태 |
| `GET /admin/doctor[?fresh=1]` | admin | `doctor` 와 **같은 줄**(함수로 뺀다). 60초 캐시 — 레포마다 `ls-remote` · `push --dry-run` 을 친다 |
| `GET /admin/server` | admin | 판 · 빌드 · node · pid · 기동 · bind · port · 경로 다섯(root · auth · data · web · packages · manual) · mirror · publicUrl · adminFrom · privatePages |
| `GET /admin/audit?limit=200` | admin | `auth.log` 마지막 N 줄 |
| `GET /admin/log?limit=200` | admin | `serve.log` 마지막 N 줄(회전분 포함) |

`/admin/*` 은 **세션이 없으면 401 · admin 이 아니면 403 · `--admin-from` 밖이면 403 · 쓰기에 재인증이 없으면 401 `E_REAUTH`.**
모든 쓰기가 `auth.log` 에 `행위자 · 대상 · 바뀐 값` 으로 남는다(CLI 와 같은 줄 모양 · 토큰은 앞 8자).

### 4.3 인증 · 역할 — 검토 v0.1 §3.3 · §4 그대로

**명부 v1.2** — `users[].role: viewer | writer | admin`. 읽을 때 `write:true` → `writer`, 없으면 `viewer` 로 접는다(v1.1 파일이
그대로 읽힌다). 저장은 `role` 만 쓴다. 토큰에 `id`(sha256 앞 8자) · `status: active | revoked` · `revokedAt/By` 가 붙고,
폐기는 줄을 지우지 않는다. `decide` 는 `active` 만 통과시키고 `role · admin · write(= role ≥ writer)` 를 낸다.

| 할 수 있는 것 | viewer | writer | admin |
|---|:--:|:--:|:--:|
| 볼 수 있는 레포 읽기 · MCP 읽기 도구 · 작업 레포 조회 · 설치 보고 | ○ | ○ | ○ |
| `save` · 레포 세우기(`POST /repos`) · 작업 레포 등록 · 삭제 | | ○ | ○ |
| 콘솔 — 사용자 · 토큰 · 레포 전부 · 진단 · 감사 · 서버 정보 | | | ○ |
| 관리자 지정 | | | ○ (자기 해제 불가 · 마지막 admin 을 잃지 않게) |

**부트스트랩** — 서버가 뜰 때 명부가 비어 있으면 `<data>/bootstrap.code`(0600 · 24바이트 base64url)를 만들고 stderr 에
한 줄을 남긴다. `install.sh` 는 `/healthz` 확인 뒤 그 파일을 읽어 **`http://<bind>:<port>/setup` 와 코드**를 찍는다.
`POST /setup` 이 맞으면 첫 관리자를 만들고 파일을 지운다. 명부가 생기면 코드는 어디서도 통하지 않는다.
`serve init`(셸)은 그대로 남는다 — 같은 일을 한다. **마지막 관리자가 토큰을 잃으면 셸이 복구 길이다**(`serve token --user`).

**재인증(sudo)** — 콘솔의 쓰기는 세션 쿠키만으로 안 된다. 자기 토큰 원문을 한 번 더 넣으면 15분짜리 `cdp_su` 쿠키가
붙는다(HMAC · `{ user, exp }`). 세션이 탈취돼도 명부는 그 15분 밖에서 바뀌지 않는다. 화면은 `E_REAUTH` 를 받으면 확인
모달을 띄우고 성공하면 하던 동작을 이어 한다 — 관리자가 미리 재인증할 필요가 없다.

**출처 · 속도** — `--admin-from <CIDR,…>`(선택)이 있으면 `/admin/*` · `/console*` · `/setup` 을 그 대역의 **소켓 주소**로
좁힌다(`X-Forwarded-For` 는 보지 않는다 — 프록시 뒤라면 IP 제한은 프록시가 한다 · §4.4). `POST /login` · `/setup` · `/admin/sudo` 는
IP 당 분당 20회 — 넘으면 429. 실패는 `serve.log` 에.

**만료** — admin 의 토큰은 기본 30일(일반 90일). `doctor` 가 관리자 수 · 30일 넘게 남은 admin 토큰 · 부트스트랩 코드 유무를 한 줄씩 낸다.

### 4.4 소개 페이지 — `/`

파는 물건의 첫 화면이지만 **광고 문구를 쓰지 않는다.** 이 레포의 말 그대로 —

```

좌표로 찾고 사람이 본문을 읽는다                        │ 판 v0.10.0 · 빌드 …   │
프로젝트 지식을 작업 기록(사건)과 관리 문서(상태) 두 층으로  │ 지식 레포 3 · 미러 ok 3 │
두고, 좌표로 잇고, 커밋할 때 검사한다.                    │ [들어가기]  [설명서]    │
                                                     └──────────────────────┘
 ── 세 가지 ──   좌표 — 이름표 하나로 사건과 상태를 잇는다 · 두 층 — 사건은 불변 · 상태는 가변 · 검사 — 갱신 누락은 상태가 아니라 오류
 ── 어떻게 쓰나 ── 에이전트(MCP 도구 13 · 스킬 7) · 화면(찾기 → 뻗어나가기 → 읽기) · CLI(ctx)
```

`/site/info` 하나로 그린다. 레포 이름 · 사용자 이름은 싣지 않는다 — 인증 없는 자리다.

### 4.5 설명서 페이지 — `/manual`

- **원천은 `manual/` 그대로다.** 서버 산출물에 `manual/`(세 권 + `그림/`)이 들어가고(`release-server.mjs`), `install.sh` ·
  `upgrade.sh` · Dockerfile 이 `/opt/cdp/manual` 에 둔다. `ctx serve --manual <dir>` 기본은 `<bin>/../manual`.
  `deploy/설치절차.md` 는 산출물에 이미 있어 넷째 항목으로 붙인다.
- 렌더는 화면이 한다 — `lib/markdown.js` 의 `renderMarkdown` 그대로(살균 · 목차 · 코드 강조). 왼쪽에 그 책의 목차(h2 · h3),
  오른쪽 본문. `제목 앵커`는 **GitHub 규칙과 같은 slug** 로 만든다 — 세 권의 목차 링크(`#3-서버형-설치`)가 그 규칙이다.
- 링크 — `*.md` 는 `/manual/<이름>` 으로, `../docs/…` 처럼 소스 레포를 가리키는 것은 GitHub 의 그 파일로(개발자 설명서가
  설계서를 가리킨다). 깨진 링크를 조용히 두지 않는다.
- 도움말 오버레이(레포 화면 `?`)의 "매뉴얼" 은 그대로 두고 **"설명서 →" 한 줄**을 더한다.

### 4.6 설치 마법사 — `/setup`

```
① 코드        install.sh 가 마지막에 찍은 코드 (또는 서버의 <data>/bootstrap.code)
② 첫 관리자   이름(영문 · 숫자 · . _ - — 커밋 author 로 남는다) · 라벨
③ 토큰        원문 한 번 · [복사] · "닫으면 다시 볼 수 없다 — CDP_TOKEN 에 넣는다"    → [콘솔로]
```

명부가 이미 있으면 "이미 설정된 서버입니다 → 로그인". 마법사가 끝난 콘솔의 현황은 **"레포가 없다 → 지식 레포에서 세운다"**
로 시작하고, 지식 레포 페이지의 [새 레포] 가 다음 단계다 — 설치절차 4 · 5장이 그 순서다.

```
├──────────┬────────────────────────────────────────────────────────────────────────┤
│ 현황      │  사용자                                                   [+ 사용자]  │

│ 지식 레포 │  │ kjsa   사경진 · 개발  admin   *         1/1    09-23 14:02   ○     │ │
```

| 페이지 | 보이는 것 | 할 수 있는 것 |
|---|---|---|
| **현황** | 서버(판 · 빌드 · 기동 · 레포 · 미러) · 사람(사용자 · 관리자 · 토큰 활성/임박/폐기) · 작업 레포(최신 · 낡음 · 미설치) · 진단 요약 · 최근 감사 5줄 · **경고 목록**(관리자 0 · 만료 임박 · 미러 밀림 · doctor fail) | 각 카드의 [자세히] · [다시 검사] |
| **사용자** | 표 · 레포 × 사용자 매트릭스 | 추가 · 라벨 · 역할 · 레포 할당(매트릭스 체크) · 비활성/재활성 · [토큰 발급 →] |
| **토큰** | 표(폐기는 회색으로 남는다) · 활성만 보기 | 발급 · **재발급(한 동작)** · 만료 연장 · 메모 · 폐기. 발급 · 재발급 → 원문 모달 한 번 |
| **지식 레포** | 서버의 레포 전부 · 미러 · 문서 수 · 볼 수 있는 사람 | [새 레포] — 패키지에서 세우기 / origin 에서 clone · 세우면서 접근 부여 · [열기] |
| **작업 레포** | 대장 전부 — 이름 · 지식 레포 · 담당 · 상태 · kit · 보고 | 그 레포 화면(관리 > 작업 레포)으로 — 등록 · 꾸러미는 거기 |
| **서버** | 설정값(읽기) · 진단 줄 · 패키지 · 갱신 안내(`upgrade.sh` 명령 · 지금 판) · 로그 마지막 N 줄 · 파일 위치 | [다시 검사] · 명령 복사 |
| **감사** | `auth.log` 마지막 N 줄 · 걸러 보기 | — |

- **모달과 표.** 추가 · 발급 · 새 레포는 모달, 나머지는 행 안의 작은 동작이다. 못 할 일은 띄우지 않는다.
- **정상은 조용하다.** 역할 칩은 회색, 경고만 앰버 · 적. 초록은 없다(`tokens.css`).
- **토큰 원문은 모달 한 번.** 닫으면 다시 못 본다고 적고, 표에는 앞 8자만.
- **재인증은 끼어드는 모달**이다 — 쓰기 동작이 `E_REAUTH` 를 받으면 뜨고, 통과하면 하던 동작을 이어 한다.

### 4.8 레포 화면(`/r/<레포>/`)의 변화

- 상단 레포 이름표를 **항상 메뉴로** 낸다(검토 v0.1 D8 ①). 하나여도 `gdi ▾` — 메뉴에 볼 수 있는 레포와 내 권한(읽기 · 쓰기).
- 오른쪽 `who` 에 역할 칩 · **설명서 →** · 관리자면 **콘솔 →**.
- 관리 메뉴는 넷 그대로(현황 · 지식 레포 · 작업 레포 · 진단). 레포 하나의 것이다. 관리자에게 맨 아래 **콘솔로 →** 한 줄.
- 도움말 오버레이에 "설명서 →".

### 4.9 CLI — 짝을 맞춘다 · 마이그레이션

```
ctx serve user add  … --role viewer|writer|admin       (--write 는 --role writer 의 옛 이름)
ctx serve user set  … --role admin                     (마지막 admin 을 내리면 거절)
ctx serve token     … --user <이름> [--note] [--expires]   (admin 은 기본 30일)
ctx serve token reissue --id <앞 8자>                   폐기 + 발급 한 번
ctx serve token set     --id <앞 8자> --note … | --expires …
ctx serve token revoke  --name <이름> [--id]            status: revoked (줄을 지우지 않는다)
ctx serve init      …                                  첫 사용자는 admin
ctx serve doctor    …                                  관리자 수 · admin 토큰 만료 · 부트스트랩 코드 · manual/ 을 한 줄씩
```

**화면에서 되는 것은 전부 CLI 로도 된다** — 어느 한쪽만 되면 어느 쪽이 정본인지 묻게 된다.

이미 선 서버(v0.9.0 · 명부 v1.1)는 — 파일은 그대로 읽힌다(`write:true` → writer). **관리자가 0명**이라 콘솔에 아무도
못 들어간다. 셸에서 `ctx serve user set --name <이름> --role admin` 한 번이 그 길이다. 콘솔에 `writer` 로 들어가면 그
문장을 그대로 보여 준다.

## 8. 위험 · 열린 것

| 위험 | 어디서 | 막는 법 |
|---|---|---|
| 부트스트랩 코드가 journal 에 남는다 | `install.sh` · 서버 stderr | 명부가 생기면 코드는 어디서도 통하지 않는다 · 파일은 지운다. journal 을 읽는 사람은 이미 셸을 가진 사람이다 |
| 재인증 모달을 귀찮아 해 관리자 토큰을 브라우저에 붙여 둔다 | 콘솔 | 15분 창 · 자동 완성 끔. 그 이상은 사람의 규칙(설명서 6장) |
| 설명서가 사내 IP(`10.10.20.188` · `10.10.20.250`)를 예시로 든다 — 제품 문서에 한 고객의 값이 있다 | `manual/` · `설치절차.md` | 이번엔 그대로 싣는다(값이 아니라 예시다). **열린 것** — 자리표시자로 바꾸는 것은 문서 정리 때 |
| `doctor` 가 레포마다 `ls-remote` · `push --dry-run` 을 쳐 느리다 | `/admin/doctor` | 60초 캐시 · `?fresh=1` · 화면에 "검사 중" |
| `/` 가 랜딩이 되어 `http://<서버>:7374/` 를 북마크한 사람이 한 번 더 누른다 | 라우트 | 세션이 있으면 [내 레포로] 를 첫 자리에. `/r` 이 첫 레포로 보낸다 |
| 화면 자동 테스트가 없다(R12) — 콘솔 일곱 페이지가 사람의 눈에 걸린다 | 검증 | 하네스가 API 를 전부 덮고, 화면은 실측 표(TODO 「나온 것」)에 남긴다 |

**열린 것** — 운영자가 언제든 뒤집을 수 있게 남긴다.

1. 등록부(`_managed.md`) 를 서버형에서 고치는 길 — 지금은 바깥에서 고쳐 origin 에 올리고 7.6 으로 맞춘다. 콘솔의 "origin 과 맞추기"(⑦)가 그 절반이다.
2. `--private-pages` 의 기본을 닫음으로 할지 — 이번 배치는 사내망이라 공개가 맞다. 다른 배치가 정한다.
3. 소개 페이지에 그림을 더 싣나 — 셋으로 시작한다.
