# CDP 관리문서 동적 생성 검토 v0.1 — 지식 레포에 관리 문서가 없을 때, 서버가 만들고 · 붙이고 · 정리한다

> **판 v0.19.2 + d140164 실측 · 2026-09-30.** 임시 git 레포(어휘 · 등록부 · 관리 문서 하나)를 세우고 `core/save.js` · `core/managed.js` · `core/check.js` 를 **직접** 불러 잰 것이다([§2](#2-어떻게-봤나)). 실서비스와 dpms_wiki 는 읽지도 않았다 — 이 검토는 쓰기 경로라 임시 레포에서만 돈다.
> **상태 — 검토 완료 · 구현은 짝 문서 [`../dev/관리문서_동적생성_TODO.md`](../dev/관리문서_동적생성_TODO.md) 의 실측 상태를 본다.** 운영자 지시대로 결정은 전부 권장안으로 닫았다([§8](#8-결정-m1m12--권장으로-닫는다)). 물음표를 남기지 않는다.
> 전제로 두는 것: 시스템설계서 제3부 불변조건 — **1 판정은 `core/` 한 곳 · 2 좌표 하나에 정본 섹션 하나 · 3 `work/` 는 불변 · 5 결정론적 보증은 훅(서버형은 `save` 의 검사)뿐 · 7 없는 상태를 화면에 그리지 않는다** — 그리고 MCP 설계서 §4.5 「전부 되거나 전부 안 된 것이어야 한다」 · 동시 기록 검토 v0.1 의 D5(더러운 트리 거절) · D6(`E_CONFLICT` 재료).

## 0. 한 줄

**패키지가 깔아 준 관리 문서(`agent/packages/*`)는 프로젝트 전체를 덮지 못하는데, 서버형 레포에서는 그 바깥에 새 관리 문서 · 새 등록부 행을 만들 길이 없다.** 어휘 타입은 d140164 로 열렸지만(`_vocab.md` 끝에 `## term` 을 서버가 만든다) 그 타입의 좌표를 섹션으로 받아 줄 **관리 문서와 등록부 행**은 여전히 사람의 커밋을 기다린다 — `save` 는 `sections` 의 좌표가 등록부에 안 걸리면 `E_INPUT 등록부에 걸리지 않는 좌표다` 로 거절하고, 설계서 §4.5 는 「`_managed.md` 는 `save` 로 바꾸지 않는다」 고 못박는다. 지식 레포가 서버에만 있으면(dpms_wiki — 작업 기록 0건 · 좌표 4개) 사람이 커밋할 작업 트리가 없다. **권장안은 `save` 입력에 `managed[]` 를 더하는 것이다 — `add`(새 행 + 새 문서 · writer)는 한 커밋 · 한 작업 기록 안에서 어휘 · 섹션과 같이 받고, `rename` · `merge` · `retire`(정리)는 같은 자리에서 admin 만 한다.** 새 행은 **언제나 등록부 맨 끝**에 붙어(먼저 걸리는 행이 이긴다) 기존 행의 뜻을 바꾸지 못하고, 경로 · 패턴 · 레벨 · 겹침은 파일을 만지기 전에 거르며, 검사에서 걸리면 `Snap` 이 문서 · 등록부를 원래대로 돌린다. 패키지가 세운 행 · 문서는 **upgrade 가 원래 안 건드린다**(`toollayer` 는 도구 층만) — 그래서 서버가 더한 것이 덮이지 않게 할 조치는 필요 없고 시험 하나로 못박는다. 따로 새 도구를 만들지 않는다 — 도구를 나누면 「등록부 행은 있는데 섹션은 없는」 중간 상태가 한 커밋 밖에 생기고, 그 상태에서는 **그 타입을 건드린 다음 save 가 전부 E_CHECK 로 막힌다**(실측 P4).

## 1. 운영자의 말 · 검토의 틀

> 현재 관리문서는 패키지로 미리 세팅된 관리문서(agent/packages/dpms 등)를 기반으로 정보가 모이게 되어 있다. 그런데 이 패키지들은 프로젝트 전체를 덮지 못한다. 그러니 필요에 따라 관리문서가 생성되고 · 정리되고(이름 변경 · 합치기 · 폐기) · 그 관리문서에 좌표가 붙는 동작이 되어야 한다. 초기에는 새 좌표 · 새 어휘 타입 · 새 관리문서가 많이 생기는 것이 정상이다. 지금은 어휘 타입만 열렸고 관리문서(등록부)는 안 열렸다.

사건 — 2026-09-30 dpms_wiki 에 도메인 지식 문서(PLC · CIMON · SCADA 용어 10개)를 `cdp-import` 로 들이려다 `save` 가 `E_INPUT: 어휘에 "## term" 섹션이 없다` 로 거절됐다. 그것은 d140164 로 고쳤다. 고치고 나면 **다음 벽이 같은 모양으로 온다** — `term:*` 를 받을 등록부 행이 없다.

| 축 | 무엇을 봤나 | 기준 |
|---|---|---|
| **A 만들기 · 붙이기** (깊게) | `save` 6단계가 등록부를 어떻게 쓰나 · 등록부 행이 없는 타입의 `sections` · 새 행을 추가하면 이미 있는 좌표는 어떻게 되나 · 새 문서의 모양 | 불변조건 2 · 3 · 5 · MCP §4.5 |
| **B 통제** (깊게) | 겹치는 패턴 · 레벨 어긋남 · 경로 탈출 · 낙관 잠금 · 되돌림 · 권한 · 감사 흔적 | 동시 기록 D5 · D6 · 제품관리서비스 검토의 역할 모델 |
| **C 정리** | 이름 변경 · 합치기 · 폐기를 서버가 받아도 되나 · 받는다면 어디까지 | 불변조건 2 · 3 |
| **D 패키지와의 경계** | upgrade · 패키지 재부음이 서버가 더한 행 · 문서를 덮나 | `toollayer.js` · `packages.js` · `reponew.js` |
| **E 에이전트 · 화면** | 스킬의 판정표 · 승인 게이트 · 설명서 · 화면에 보일 것 | 스킬 `cdp-save` ⑤B-0 · `cdp-import` ③-6 |

심각도 — **P0**: 데이터가 조용히 틀어진다 · **P1**: 막히는데 왜인지 · 어떻게 풀지 보이지 않는다(또는 레포가 막힌다) · **P2**: 되지만 손이 더 간다 · **P3**: 잔손.

## 3. 실측 표

| # | 잰 것 | 결과 | 읽는 법 |
|---|---|---|---|
| P1 | `term:X` 섹션을 보낸다(등록부에 `term:*` 없음) | `E_INPUT 등록부에 걸리지 않는 좌표다 — 관리 문서가 없다` `{coord}` | 벽 그 자체. 메시지가 **풀 길을 안 말한다**(`touches` 로만 닿는다는 것도 · 행을 더할 수 있다는 것도) |
| P2 | 등록부에 `table:*` 다음 `table:a*` 를 둔다 | `resolveCoord('table:a')` → **`table:*` 의 행**. `check` 는 **조용하다** | 앞 행이 뒤 행을 **완전히 가린다**. 뒤 행은 죽은 행인데 아무도 모른다 — 「모두 열기」 가 만들 수 있는 사고를 **손 편집도 이미 만들 수 있다** |
| P3 | 한 문서에 `##` 행과 `###` 행을 둔다(코드 읽기 — `replaceSection` · `parseManagedSections`) | `##` 섹션은 「같은/상위 레벨의 다음 헤딩 전까지」 라 **`###` 소제목을 품는다** — `##` 섹션을 치환하면 `###` 섹션이 같이 지워진다 | 한 문서에 레벨이 둘이면 섹션이 겹친다. 새 행은 **그 문서의 레벨을 따라야 한다** |
| P4 | 작업 기록이 `term:X` 를 `touches` 로만 건드렸다(행 없음 · 커밋됨) → 이제 `term:*` 행 · 문서 `docs/g.md` 를 더한다(섹션 없이) → **다른** 좌표의 save | **`E_CHECK dangling-anchor` — `docs/g.md 에 ## X 섹션이 없음`**. 그 뒤 **그 레포의 모든 save 가 막힌다** | 행을 더하는 일은 **그 행이 새로 걸리는 기존 좌표의 섹션을 만드는 일과 한 커밋**이어야 한다. 도구를 둘로 나누면 중간 상태가 레포를 잠근다 |
| P5 | `_managed.md` 에 `../outside.md` 행을 손으로 넣고 그 좌표의 섹션을 save | 파일을 **레포 밖 경로에 썼다가** `E_CHECK`(`../outside.md 문서가 없음`)로 `Snap` 이 지웠다 | 지금도 **`resolveCoord` 가 준 `hit.doc` 를 경로 검사 없이 `path.join(root, …)`** 한다. 막은 것은 스캔이 레포 밖을 못 읽는다는 우연이다. 행을 서버가 쓰게 되면 **쓰기 전에** 막아야 한다 |
| P6 | `git.commitPaths(root, ['docs/t.md'])` 로 **지운** 파일을 | `ok: true` — 삭제가 커밋된다(`git add -- <경로>` 가 삭제를 스테이징) | 이름 변경 · 합치기가 **원본 파일을 지우는 한 커밋**으로 갈 수 있다 |
| P7 | `_managed.md` 의 4번째 칸(`note`) | `parseRegistry` 가 이미 읽는다(`rules[].note`). 렌더러는 **머리 행보다 긴 칸은 버린다**(GFM) | 감사 흔적을 행에 남길 자리가 이미 있다 — 머리 행을 안 고치고 |

코드에서 읽은 것(실측이 필요 없는 사실) —

- **패키지의 갱신 경계.** `core/toollayer.js` 의 `TOOL_FILES`(`CLAUDE.md` · `bin/ctx*` · `.githooks/pre-commit` · 설명서 셋 …) + `cdp-*` 스킬만 배포본 판으로 간다. 머리 주석이 「`_vocab.md` · `_managed.md` · `docs/` · `work/` 는 건드리지 않는다」 고 못박는다. 패키지가 지식 레포에 **부어지는 때는 `ctx repo new` / `ctx package` 로 세울 때 한 번**이다(`core/reponew.js` · `ops/lib/assemble.mjs`) — 이미 선 레포로 다시 흘러가는 길이 없다. **서버가 더한 행 · 문서는 upgrade 에 덮이지 않는다.**
- **권한.** `core/auth.js` 의 역할은 `viewer · writer · admin`. `saver` 는 `a.write` 만 넘기고(`viewer/bin/ctx-mcp-serve.mjs:626`) `a.admin` 은 넘기지 않는다. 구조를 바꾸는 일이 admin 이면 그 한 값을 더 넘기면 된다.
- **낙관 잠금의 자리.** `applied` 는 **섹션**에 있다. `_managed.md` 에는 `applied` 가 없다 — 그러나 `save` 는 레포 뮤텍스 안에서 **현재** 등록부를 읽고 그 위에서 판정하므로 행을 더하는 일에는 lost update 가 없다. 「읽은 뒤 바뀌었나」 가 의미를 갖는 것은 **같은 패턴이 그 사이 다른 문서로 생겼을 때**뿐이다.
- **화면.** `registry.rules` 를 그리는 화면이 뷰어 · 콘솔에 **없다**(`viewer/src` 에서 `rules` · `registry` 를 읽는 곳 0). 새 관리 문서는 `docs/` 트리 · `cdp://<repo>/doc/<name>` 에 **자동으로** 뜬다(스캔이 `docs/*.md` 를 관리 문서 층으로 읽는다 — `layerOf`).

## 5. 개선안 — 대안과 권장

### 5.1 받는 자리 — `save` 의 `managed[]` vs 별도 도구 vs 사람에게 남기기 (G1) — **권장 A**

| 안 | 모양 | 장 | 단 |
|---|---|---|---|
| **A `save.managed[]`** | 입력에 `managed: [{ op?, pattern, doc, level?, title? … }]`. 처리 순서에 **4.5 등록부**(어휘 뒤 · 좌표 대조 앞)가 들어간다 | 한 커밋 · 한 작업 기록 · 한 `Snap` · 한 E_CHECK. **행 + 문서 + 섹션 + 어휘가 원자적**(P4 가 요구한다). 승인 게이트(【좌표 판정】)가 이미 `save` 앞에 있다. 새 MCP 도구 0 | 한 입력이 커진다 |
| B 별도 도구(`managed_add` …) | 행을 먼저 더하고 나중에 섹션을 save | 입력이 갈린다 | **도구 둘 사이의 중간 상태가 레포를 잠근다**(P4). 행만 더하는 커밋에는 작업 기록이 없어(`save` 는 `work` 가 필수) 감사 흔적도 못 남긴다. MCP 도구 명함이 하나 는다 |
| C 사람에게 남김 | 지금 | 구현 0 | 서버에만 있는 레포는 **못 한다**(G1) |

**A.** `managed` 가 없으면 옛 입력 그대로다(호환). 모드 A(작업 트리가 있는 쪽)는 **바뀌지 않는다** — 사람이 `_managed.md` 를 고치고 훅이 검사한다.

### 5.2 `managed[]` 의 모양 — **권장**

```jsonc
"managed": [
  // 새 행 — 등록부 끝에 붙는다. 문서가 없으면 만든다 (writer)
  { "pattern": "term:*", "doc": "docs/용어집.md", "level": 2, "title": "용어집" },
  // 정리 (admin) — 이름 변경 · 합치기 · 폐기
  { "op": "rename", "doc": "docs/용어집.md",  "to": "docs/3.용어/용어집.md" },
  { "op": "merge",  "doc": "docs/용어메모.md", "into": "docs/용어집.md" },
  { "op": "retire", "pattern": "term:*" }
]
```

| 필드 | `add`(기본) | `rename` | `merge` | `retire` |
|---|---|---|---|---|
| `pattern` | 필수 — `type:glob` | — | — | 필수 — 지울 행의 패턴 그대로 |
| `doc` | 필수 — `docs/…md` | 필수 — 지금 문서 | 필수 — 합쳐져 사라질 문서 | — |
| `level` | 선택 · 기본 2 · `0` = `—`(문서 전체) | — | — | — |
| `title` | 선택 — 새 문서의 `# 제목`(기본 파일명) | — | — | — |
| `to` · `into` | — | `to` 필수 | `into` 필수 | — |
| 권한 | writer | **admin** | **admin** | **admin** |

**순서.** 한 save 안에서 `managed` 는 앞에서부터 차례로 적용한다(앞 행이 만든 문서에 뒤 행이 붙을 수 있다). 그 결과 등록부 위에서 `sections` 를 판정한다 — **새 행이 만든 자리에 같은 save 가 섹션을 쓰는 것이 정상 흐름**이다.

### 5.3 「모두 열기」 의 위험과 통제 (B) — **권장: 파일을 만지기 전에 거른다**

| 위험 | 통제 | 어디서 |
|---|---|---|
| 레포 밖 · 절대경로 · 제어문자 · `\` · Windows 예약 이름 · `docs/` 밖 · `.md` 아님 | 경로는 `docs/<세그먼트>/….md` 만(`..` · `.` 로 시작하는 세그먼트 · 예약 이름 · 끝 공백 · 한 세그먼트 80자 · 전체 200자 · 깊이 4 넘으면 `E_INPUT`). **그 위에 `path.resolve` 후 root 접두 검사를 한 번 더** — 좌표 `checkCoord` 와 같은 둘 다 규칙. 등록부에서 읽은 기존 행의 문서에도 같은 검사(G4) | 신규 `assertDocPath` · `save` 6단계 |
| 패턴이 표를 깨거나(`\|` · 백틱 · 공백) 타입이 `*` | 타입 부분은 `checkCoord` 와 같은 문자 집합의 **구체적 타입**, 값 부분은 공백 · `\|` · 백틱 · 제어문자 · `..` 없는 1~200자. `*:*` · `*` 타입 거절 | `checkPattern` |
| **겹침 — 새 패턴이 앞 행에 완전히 덮인다**(`table:*` 뒤의 `table:a*`, P2) | **거절** `E_INPUT` — 덮는 행을 `detail.shadowedBy` 에. 판정은 정확하다: 글롭 포함 검사(`*` 를 **패턴에 없는 글자 하나**로 바꿔 앞 행의 정규식에 넣는다) | `globContains` |
| 겹침 — 교차(`t:a*` 와 `t:*b`) | **경고** — 교차 좌표는 앞 행을 따른다 | `globIntersects` |
| 겹침 — **같은** 패턴이 이미 있다 | 같은 문서 · 레벨이면 **멱등**(경고 「이미 있다」 · 다시 붙이지 않는다 — 동시 save 둘이 같은 행을 더해도 한 줄). 다른 문서면 `E_CONFLICT { kind: 'managed', pattern, current }` | `planManaged` |
| 새 행이 기존 행의 **뜻을 바꾼다** | 새 행은 **언제나 맨 끝**(우선순위 최하). 먼저 걸리는 행이 이기므로 기존 좌표의 자리는 **바뀔 수 없다**. 기존 행은 `add` 로 고쳐지지 않는다(`rename` · `retire` 만, admin) | 삽입 위치 |
| **앵커 레벨 어긋남**(P3) — 한 문서에 `##` 와 `###` · `—` 와 섹션 | 새 행은 **그 문서의 레벨을 따라야** 한다(문서에 행이 이미 있으면 같은 레벨만). `—`(level 0)는 **그 문서에 다른 행이 없을 때 · 새 문서일 때만** — 이미 있는 문서를 `—` 로 붙이면 첫 섹션 쓰기가 파일 전체를 갈아 버린다 | `planManaged` |
| 이미 있는 좌표가 새 행에 **걸려 섹션이 없다**(P4 — 레포가 잠긴다) | 그 행이 걸리는 기존 좌표(작업 기록이 `touches` 한 것 · 이 save 의 `touches` · `sections`)의 섹션이 문서에 없고 이 save 가 안 보냈으면 **거절** `E_INPUT { needSections: [coord…] }` — 문구가 풀 길을 말한다(섹션을 같이 보낸다 · 처음 만드는 섹션은 `applied: null`). 50을 넘으면 패턴을 좁혀(`term:P*`) 나눠 붙인다 | `planManaged` 뒤 6단계 앞 |
| 한 save 가 등록부를 난사한다 | `managed` 는 최대 10건 | zod · `checkSchema` |
| 검사에서 걸렸다 | 기존 그대로 — `Snap` 이 `_managed.md` · 새 문서 · 옮긴 문서 · 합쳐 지운 문서를 **전부 원래대로**(지운 파일은 다시 쓴다) 돌리고 커밋 0 | `Snap.remove` 신설 |
| 더러운 트리 위에서 | 기존 그대로 — 3.5 단계가 거절(D5) | — |

### 5.4 `E_CONFLICT` 와 낙관 잠금 (B) — **권장: 등록부에는 `applied` 를 만들지 않는다**

등록부는 「읽은 뒤 바뀌었나」 를 대조할 **버전이 없다** — 만들 이유도 없다. 뮤텍스 안에서 **현재** 등록부를 읽고 그 위에서 판정하므로 행 추가 자체에는 lost update 가 없다. 남는 경합 둘은 이미 닫혀 있다.

| 경합 | 결과 |
|---|---|
| 두 save 가 **같은** 행(같은 패턴 · 같은 문서)을 더한다 | 먼저 든 쪽이 더하고 **뒤 쪽은 멱등**(행 · 문서를 다시 안 만든다 · 경고) — 어느 쪽이든 섹션은 `applied` 대조를 받는다(뒤 쪽이 `applied: null` 로 같은 좌표의 첫 섹션을 보내면 기존 `E_CONFLICT { expected: null }` 가 나온다 — 동시 기록 검토 §3.1) |
| 같은 패턴을 **다른 문서**로 더한다 | 뒤 쪽 `E_CONFLICT { kind: 'managed', pattern, current: { doc, level, note } }` — **`detail.current` 가 재료다**(`section` 을 다시 부르지 않는다). 그 문서에 붙이거나 다른 패턴을 고른다 |
| 이미 있는 섹션의 `applied` | 기존 그대로 — `rename` · `merge` 는 섹션 텍스트를 **그대로 옮기므로** `applied` 가 같이 간다. 클라이언트가 옛 경로로 읽은 `applied` 는 새 경로에서도 유효하다 |

### 5.5 정리 — 이름 변경 · 합치기 · 폐기 (C) — **권장: 같은 자리 · admin · 세 가지만 · 기계적으로 닫히는 것만**

| 동작 | 서버가 하는 것 | 안 하는 것 |
|---|---|---|
| **rename**(문서 이름 · 위치) | 파일을 새 경로로 옮기고(이미 있으면 `E_EXISTS` · 대소문자만 다른 것도 같은 파일) 그 문서를 가리키는 **모든 행**의 경로 칸을 바꾼다. 섹션 텍스트 · `applied` 는 그대로 간다 | **다른 문서 안의 링크는 안 고친다** — 경고 「링크는 사람이」 |
| **merge**(합치기) | `doc` 의 섹션을 `into` 끝에 **이어 붙이고**, 그 문서를 가리키던 행을 `into` 로 돌리고, `doc` 파일을 지운다. 조건 — 두 문서의 행 레벨이 같다 · `—` 문서가 아니다 · `doc` 머리(첫 앵커 헤딩 앞)가 **제목과 빈 줄뿐** · `into` 가 있다 | 같은 이름의 섹션이 양쪽에 있으면 **dup-anchor(E_CHECK)** 로 전부 되돌린다 — 이름을 고치고 다시. 내용 병합 · 요약은 하지 않는다 |
| **retire**(폐기) | 그 행을 **지운다.** 문서 파일은 **그대로 둔다**(내용은 사라지지 않는다) — 등록부에 안 걸린 관리 문서가 남는다(경고로 말한다). 그 행이 덮던 좌표는 「등록부 없음」(작업 기록이 유일한 근거) 상태로 돌아가 **파생 누락 · 앵커 없음 오류가 같이 사라진다** | **파일을 지우지 않는다.** 지우려면 merge 로 보관 문서에 넣거나 사람이 |

**왜 admin 인가.** 행 · 문서를 더하는 것은 **덧붙임**이다(맨 끝 · 기존 자리를 못 바꾼다). 정리는 **기존 좌표의 자리를 바꾼다** — 특히 `retire` 는 커밋을 막던 검사(파생 누락)를 **끄는 수단**이 될 수 있다. 「막혔으니 행을 지운다」 를 writer 가 스스로 하면 훅이 있는 이유가 사라진다. admin 만, 그것도 한 곳(`core/save.js`)에서.

**왜 이 셋만 · 더 안 하나.** 나누기(한 문서를 둘로) · 섹션 이름 바꾸기 · 섹션 하나 옮기기는 **내용을 자르는 판단**이 들어간다 — 사람이 한다. 지금 세 동작은 전부 「문서를 한 덩어리로 다룬다」 는 성질이라 기계가 틀릴 자리가 없다. 나머지는 **모드 A 의 셸이 있으면** 되고, 서버에만 있는 레포는 admin 이 서버 셸에서 한다(콘솔에 레포를 손으로 고치는 화면은 만들지 않는다 — 불변조건 5 는 훅 · `save` 의 검사뿐이다).

### 5.6 권한 · 감사 흔적 (B) — **권장: writer 는 더하고 admin 은 정리 · 흔적은 행 · 커밋 · 기록 · 응답 넷**

| | writer | admin |
|---|:--:|:--:|
| `add`(새 행 + 새 문서) | ✓ | ✓ |
| `rename` · `merge` · `retire` | ✗ `E_FORBIDDEN { need: 'admin' }` — **파일을 만지기 전에**(1단계 권한 바로 뒤) | ✓ |

흔적은 넷이다.

1. **행의 4번째 칸** — `| \`term:*\` | \`docs/용어집.md\` | \`## {값}\` | 서버 추가 · 2026-0930-용어집-신설 |`. `parseRegistry` 가 이미 `rules[].note` 로 읽는다. 머리 행을 안 고친다(렌더러는 넘치는 칸을 버린다 — P7) · 누가는 그 작업 기록의 `author`.
2. **커밋** — 작성자 = 토큰의 사용자 · 제목 = `work.title`. `rename` · `merge` · `retire` 는 행이 사라지거나 바뀌므로 **`work.body` 가 사유다**(스킬이 「왜 정리하나」 를 본문에 적게 한다).
3. **작업 기록 본문** — 불변이다(불변조건 3). 구조 변경은 **그것을 일으킨 지식공유문서 안에** 같이 남는다.
4. **응답** — `managed: <건수>` · `managedChanges: [{ op, pattern, doc, to?, into? }]` · `warnings` 줄마다 한 문장. `serve.log` 의 `save` 줄에도 **등록부 변경** 한 줄(누가 · 무엇을).

### 5.7 패키지와의 관계 (D) — **권장: 조치 없음 · 시험으로 못박는다**

- **패키지 행은 그대로.** 서버는 패키지 행을 못 고친다(`rename` · `retire` 는 admin 이 **의식하고** 한다).
- **upgrade 는 덮지 않는다.** `planToolLayer` 가 보는 것은 `TOOL_FILES` + `cdp-*` 스킬이고, 패키지의 지식(`_vocab.md` · `_managed.md` · `docs/`)은 **원래 대상이 아니다**(`toollayer.js` 머리 주석 · 코드). 서버가 더한 행 · 문서는 그 밖에 있다. → **`test/toollayer.test.mjs` 에 「서버가 더한 행 · 문서를 갖고 있어도 도구 층 갱신 계획에 `_managed.md` · `docs/` 가 안 든다」 를 더한다.**
- **미래의 패키지 재부음.** 지금 그런 기능은 없다. 생긴다면 **`서버 추가 ·` 로 시작하는 note 가 붙은 행은 레포의 것**이라는 표식이 있다 — 그 행과 그 문서는 패키지 판으로 덮지 않는다(TODO 의 상수 `ADDED_NOTE` 가 그 한 곳).
- **패키지 `_managed.md` 의 설명 표**(「CDP 16종 등록부에서 바뀐 것」)는 규칙이 아니다 — 새 행은 **마지막 규칙 행 바로 뒤**(같은 표)에 들어가고 설명 표에 붙지 않는다(`parseRegistry` 가 규칙 행의 줄 번호를 이미 준다).

### 5.8 검사 — 손 편집에도 같은 눈 (G3 · G4) — **권장: `check` 에 셋, 오류는 하나만**

| 새 검사 | 등급 | 이유 |
|---|:--:|---|
| `registry-path` — 등록부 행의 문서가 `..` · 절대경로 · 레포 밖이거나 `docs/` 밖 | `..` · 절대경로는 **error** · `docs/` 밖은 warn | 막을 것은 탈출이다. 기존 레포가 `docs/` 밖을 쓰는 일은 있어도 탈출하는 일은 없다 — 기존 레포를 잠그지 않는다 |
| `registry-shadowed` — 앞 행이 **완전히 덮는** 뒤 행(죽은 행) | warn | 훅이 막을 일은 아니고 **사람이 알아야 한다**(P2) |
| `registry-level-mix` — 한 문서에 레벨이 둘 | warn | P3 — 섹션이 겹친다 |

`save` 는 새 행에 대해서는 **거절**(5.3)이고, `check` 는 이미 있는 레포의 같은 상태에 대해 **말한다** — 같은 함수(`lintRegistry`)를 쓴다(불변조건 1). 패키지 셋의 등록부는 세 검사 모두 0건이어야 한다(시험).

### 5.9 에이전트 쪽 (E) — **권장: 같은 【좌표 판정】 승인에 한 덩어리를 더한다 · 별도 승인을 만들지 않는다**

`cdp-save` ② · ⑤B-0 · `cdp-import` ③-2 · ③-6 의 판정표에 **열 셋**을 더한다 — 승인이 한 번이어야 읽힌다. 새 타입 · 새 문서 · 행 추가 · 정리는 **표의 별도 덩어리 「등록부 변경」** 으로 보이고 같은 승인에 든다.

```
【좌표 판정】 …기존 그대로…

【등록부 변경】 — 있을 때만 (사람이 승인한다)
  신규 어휘 타입   term            (_vocab.md 끝에 ## term — 오타면 못 지운다)
  신규 관리 문서   docs/용어집.md   (새로 만든다 · 제목 「용어집」 · 레벨 ##)
  좌표 부착        term:*  →  docs/용어집.md ## {값}   (등록부 맨 끝 · 기존 행은 안 바뀐다)
  기존 좌표        term:X — 작업 기록 1건이 이미 닿았다 → 섹션을 이 save 에 같이 보낸다
  정리(admin)      없음
```

- **타입을 새로 만들기 전에** `match` · `where` 로 **이미 같은 것을 받는 타입 · 문서가 있는지** 본다(이름이 다른 중복이 이 기능의 첫 부작용이다).
- 패턴은 **타입 하나에 `type:*`** 를 기본으로 한다. 좁히는 것(`type:P*`)은 이유가 있을 때.
- 문서 경로는 **기존 문서들의 폴더 규약**(`docs/2.개발/…`) 을 따른다 — 없으면 `docs/<이름>.md`.
- 정리(rename · merge · retire)는 **`cdp-managed`** 의 새 절이 맡는다 — 사유를 `work.body` 에 적고, **admin 이 아니면 요청문을 만들어 admin 에게** 넘긴다(자기가 `retire` 로 검사를 끄지 않는다).
- **쓰기 전에** 같은 패턴 · 같은 문서가 이미 있는지 `where` 로 본다 — `E_CONFLICT` 를 만나면 `detail.current` 위에서 다시.

### 5.10 화면 (E) — **권장: 이번엔 없다 · 자동으로 뜨는 것만 확인한다**

| | 지금 | 이번 |

`cdp-screen-engineer` 는 쓰지 않는다 — 화면 경계를 건드리지 않는다.

## 7. 전제 — 지키는 결정

- **한 커밋 · 전부 되거나 전부 안 된다** — 행 · 문서 · 섹션 · 어휘 · 작업 기록이 같은 `Snap` · 같은 E_CHECK · 같은 커밋이다. 롤백이 지운 파일까지 돌린다.
- **판정은 `core/` 한 곳** — `lintRegistry` 는 `check` 와 `save` 가 같이 쓴다. 글롭 포함 · 교차도 한 곳(`core/managed.js`).
- **`work/` 는 불변** — `managed` 는 `docs/` · `_managed.md` 만 만진다.
- **클라이언트를 믿지 않는다** — 경로 · 패턴은 서버가 검사하고, `author` 처럼 **누가** 는 서버가 채운다(행 note 에 든 것은 작업 기록 id).
- **권한은 사람에게** — `role` 은 토큰이 아니라 명부에 있다(`auth.js`). `saver` 가 `admin` 한 값을 더 넘긴다.
