## 0. 한 줄

돌아가는 장치는 **있는데 보이지 않고, 반쯤만 돈다.** 문서를 열 때마다 메모리에 방문 이력을 쌓고 `Alt+←` · `Alt+→` 로 오간다
([App.jsx:333](../../viewer/src/App.jsx:333) · [App.jsx:424](../../viewer/src/App.jsx:424)) — 그러나 화면에 단추가 없고(설명서 단축키 표 한 줄뿐),
되돌아가도 왼쪽 「뻗어나가기」 의 뿌리는 그대로라 **왼쪽과 오른쪽이 다른 문서를 말하며**, 문서가 **주소에 없어서** 브라우저의
뒤로 가기는 이전 문서가 아니라 **앱 밖으로 나간다.** 권장은 ① 문서를 주소에 싣고(뒤로 가기 · 새로고침 · 링크가 문서 단위로 된다)
② 본문 머리에 「← 이전 문서 이름」 단추와 이력 목록을 두며 ③ 그 위에 **열린 문서 탭 줄**을 얹는 것 — ①②가 바닥이고 ③은 그 위에 선다.
③만 하면 브라우저 뒤로 가기는 여전히 앱을 나간다.

## 1. 화면의 영역 — 무엇이 왜 있나

```
┌ 상단 바 ─ 문서 · 그래프 · 관리 │ 검색(Ctrl+K) │ 동기화 · 검증 ───────────────────────────┐
├ 왼쪽 (340 / 560px) ───────────┬ 가운데 · 본문 ─────────────────────────┬ 오른쪽 · 목차 ─┤
│ [찾기] ▸ [뻗어나가기]           │ 경로 · 관리문서 표지                     │ 섹션 목록       │
│  찾기   관리문서 · 작업문서 · 좌표│ 제목 · 유효성 블록 · 본문                │ (지금 섹션 표시) │
│        에서 **시작점**을 고른다   │ 첨부 · 복사(id · 경로 · 원문 · 인쇄)      │ 접으면 28px 띠  │
│  뻗어나가기  고른 것에서 이어진  │                                       │                 │
│        좌표 · 문서로 한 칸씩     │                                       │                 │
└───────────────────────────────┴───────────────────────────────────────┴─────────────────┘
```

| 영역 | 하는 일 | 왜 있나(코드 머리말의 결정) |
|---|---|---|
| 왼쪽 「찾기」 | 관리문서 16종 · 작업문서(날짜순) · 좌표 중 하나를 고른다 | **시작점을 만든다.** 관계 · 이력은 여기서 답하지 않는다([Finder.jsx:1](../../viewer/src/components/Finder.jsx:1)) |
| 왼쪽 「뻗어나가기」 | 고른 것에서 좌표 → 그 좌표를 건드린 문서 → … 를 열로 펼친다 | 「이 문서와 붙어 있는 것」 을 따라간다. 찾기와 **같은 자리를 번갈아** 써서 각자 세로 전체를 받는다([App.jsx:1](../../viewer/src/App.jsx:1)) |
| 가운데 본문 | 문서 하나를 읽는다. 본문 안 링크 · 좌표를 누르면 이동한다 | 읽기 폭(`--doc-measure`)을 지킨다 |
| 오른쪽 목차 | 그 문서의 섹션 목록 · 지금 섹션 | 화면설계서처럼 섹션이 57개인 문서를 본문 스크롤 없이 건너뛴다. 가로 레일이던 것을 세로로 세웠다([SectionRail.jsx:1](../../viewer/src/components/SectionRail.jsx:1)) |

**빠진 것 — 「어디서 왔나」 를 맡은 영역이 없다.** 왼쪽은 「어디서 시작할까」(찾기) 와 「무엇과 붙어 있나」(뻗어나가기) 를,
오른쪽은 「이 문서 안 어디인가」(목차) 를 답한다. 「방금 무엇을 읽고 있었나」 는 어느 영역의 일도 아니다. 그래서 왼쪽에서 범위를
관리문서로 바꾸는 순간 작업문서 목록에서 하이라이트돼 있던 자리까지 화면에서 사라진다 — 운영자가 본 현상 그대로다.

## 3. 원인

1. **이력이 상태의 한 조각일 뿐 화면의 물건이 아니다.** 스택은 있으나 그리는 곳이 없다(H1 · H3).
2. **「문서를 연다」 가 한 함수인데 「문서로 돌아간다」 는 다른 길이다.** 그래서 돌아갈 때 왼쪽이 따라오지 않는다(H4).
3. **문서가 주소 밖에 있다.** 브라우저가 이미 가진 뒤로 · 앞으로 · 새로고침 · 북마크 · 「링크 보내기」 를 쓰지 못하고, 앱이 같은 것을
   손으로 다시 만들었다가 반만 만들었다(H2 · H5 · H6).

### 4.1 C(탭) 의 규칙 — 할 때의 기본값

- 문서를 **열면** 지금 탭을 바꾸지 않고 **탭을 더한다**(이미 있으면 그 탭으로). 업무 시스템의 「메뉴를 누르면 탭이 생긴다」 와 같다.
  `j` · `k` 훑기 · 「뻗어나가기」 열에서 연 문서는 **지금 탭을 바꾼다** — 훑을 때마다 탭이 생기면 탭 줄이 목록의 복사본이 된다.
- 탭마다 스크롤 위치를 가진다(지금도 문서별로 `scroll` 을 저장한다 — [App.jsx:380](../../viewer/src/App.jsx:380)).
- 탭 목록은 `state` 에 저장(사용자 · 레포별) — 내일 열어도 어제 펴 둔 참고 문서가 있다. 「모두 닫기」 하나.
- 지운 문서 · 권한 밖 문서의 탭은 회색 + 「없음」, 누르면 닫힌다.

## 5. 권장

**A + B 를 먼저, C 를 그 다음.** D 는 따로 검토.

- **A 가 바닥이다.** 「돌아간다」 를 앱이 손으로 흉내 내는 한 H4 같은 반쪽 동작이 또 생긴다. 주소에 실으면 브라우저 · 마우스 뒤로 단추 ·
  새로고침 · 링크 공유가 한꺼번에 오고, 라우터 머리말의 원칙(주소가 상태다)과도 맞는다.
- **B 가 운영자 문장에 직접 답한다** — 「이전에 봤던 문서가 뭔지 몰라서」. 단추에 **이름**이 있어야 한다(「←」 만 있으면 지금과 같다).
- **C 는 「곁에 펴 두기」 를 푼다** — 용어집 · 테이블정의서 · 화면설계서처럼 계속 오가는 참고 문서. 첨부 그림의 방식이고 운영자가 바란 것이다.
  다만 C 는 A · B 의 대신이 아니다 — 탭은 「열어 둔 것」, 이력은 「지나온 길」 이다.
- 같이 고친다 — H4(돌아가면 왼쪽도 따라온다 — A 로 자연히) · H7(입력칸에서 `Alt+←` 를 놓는다) · H8(`j`/`k` 는 이력에 안 쌓는다).
