# 관리 문서 등록부

좌표가 어느 관리 문서의 어느 섹션에 대응하는지 **여기에만** 적는다.
매핑이 두 곳에 있으면 반드시 어긋난다.

| 좌표 패턴 | 관리 문서 | 섹션 | 비고 |
|---|---|---|---|
| `table:*` | `docs/테이블정의서.md` | `## {값}` | |
| `code:*` | `docs/코드정의서.md` | `## {값}` | |
| `term:*` | `docs/용어집.md` | `### {값}` | |
| `api:*` | `docs/인터페이스정의서.md` | `## {값}` | |
| `screen:PS*` | `docs/화면정의서_인사.md` | `## {값}` | 인사·채용 |
| `screen:SE*` | `docs/화면정의서_연구.md` | `## {값}` | 연구과제 |
| `screen:*` | `docs/화면정의서_기타.md` | `## {값}` | 위에 안 걸리는 것 |

등록되지 않은 타입(`module:` `domain:` 등)은 관리 문서가 없다.
작업 기록에만 남고, 그것이 정상이다.

패턴은 **위에서부터** 먼저 걸리는 것을 쓴다.

> 이 fixture 에는 `docs/` 가 아직 없다. 등록부는 있고 대상 문서는 없는 상태 —
> `ctx check` 가 그것을 잡는지 확인하기 위한 것이다.
