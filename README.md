## 무엇을 하는가

```
work/   작업 기록 — 사건.  왜 그렇게 정했나.  불변
docs/   정본 문서 — 상태.  지금 어떻게 생겼나.  가변

좌표(table: screen: …)가 둘을 잇는다.
```

**"밀림"·"미결" 같은 상태는 없다.** 정본 문서 갱신은 필수이고, 안 했으면 그것은
상태가 아니라 커밋을 막는 **오류**다. 자세한 것은 설계서 §1.5.

## 실행

```bash
npm install && npm run build
npm start
```

**배포본을 만들려면 한 줄이다.** 둘이다 — 팀원 PC 용과 서버용.

```bash
npm run release                 # → ops/release/v<버전>/          exe + 완성된 지식 레포 폴더
npm run release:server          # → ops/out/server/cdp-server-v<버전>.tar.gz   bin · web · packages · deploy
```

태그 `v*` 를 push 하면 **GitHub Actions 가 둘을 만들어 Release 에 붙인다**(`.github/workflows/release.yml`).
태그와 `package.json` 버전이 다르면 실패한다.

`ops\release.cmd` 를 더블클릭해도 된다. **그 폴더를 통째로 옮기면 CDP 를 쓸 수
있다** — exe 와 **완성된 지식 레포 폴더**가 들어 있다. 설계서는 안 들어간다.

`viewer/fixture/` 로 뜬다 — **개발용 fixture 다. 배포본에는 안 들어간다.** 다른 레포를 보려면:

```bash
node viewer/server/index.js --repo "C:\work\knowledge-repo"
```

브라우저가 자동으로 열린다. 탭을 닫으면 90초 뒤 프로세스도 종료된다.

| 인자 | |
|---|---|
| `--repo <경로>` | 지식 레포 경로. 없으면 화면에서 지정하고 설정에 저장된다 |
| `--port <n>` | 기본 7373. 사용 중이면 +1 씩 20회 시도 후 임의 포트 |
| `--no-open` | 브라우저 자동 열기 끔 |
| `--no-watch` | 파일 감시 끔 (감시가 문제를 일으키는 환경의 비상 스위치) |
| `--tray` / `--no-tray` | 트레이 아이콘. 기본값은 **exe 실행이면 켜짐, `node` 실행이면 꺼짐** |
| `--host <addr>` | 기본 `127.0.0.1`. **다른 값은 화면에 상시 경고가 뜬다** |

**개발**

```bash
node viewer/server/index.js --repo <경로> --dev http://localhost:5173 --no-open
```

다른 터미널에서 `npm run dev` — Vite 가 화면을, node 가 API 를 맡고 `/api` 만
프록시된다.

## npm 스크립트

`ops/` 의 `.cmd` 들이 같은 것을 한다 — **npm 을 모르는 사람도 쓸 수 있게** 둔
껍데기다. 자세한 것은 [`ops/README.md`](ops/README.md).

| | |
|---|---|
| **`npm run release`** | **원클릭.** 화면 → ctx → exe → `ops/release/v<버전>/`. `-- --no-build` 는 조립만 |
| **`npm run release:server`** | 서버 산출물 `cdp-server-v<버전>.tar.gz` — `install.sh` · `upgrade.sh` 가 이것을 받는다 |
| **`npm test`** | 단위 테스트 (`node:test` · `test/`) |
| **`npm run verify`** | 검증 하네스 — MCP 설계서 §10 + 제품화 70~74 를 한 자리에서 |
| `npm run check:packages` | 패키지마다 부어서 `ctx check` (= `ctx package check --all`) |
| `npm run seed:kit` | fixture 의 `.claude/` 를 `agent/` 에서 (Python 없이) |
| `npm run dev` · `dev:server` | 화면 / 서버 개발 |
| `npm start` | 서버 (빌드된 화면 · viewer/fixture) |
| `npm run seed` | `viewer/fixture/` 재생성 |
| `npm run ctx -- check` | 소스로 CLI 실행 |
| `npm run build:ctx` | `ops/out/ctx/ctx.mjs` 번들. **`CDP_REPO` 가 있으면 그 레포도 갱신** |
| `npm run build:exe` | 단일 실행 파일 |
| `npm run test:tray` | 트레이 자체 시험 (클릭 없이) |

버전을 지정하려면 `npm run release -- 0.3.0`.

**CI** — `.github/workflows/ci.yml` 이 push 마다 `build · build:ctx · test · check:packages · verify` 를
돈다. 부르는 명령은 **전부 위 표의 스크립트**다 — CI 에만 있는 명령이 없다.

## 화면

**좌우 2분할이다.** 왼쪽에서 찾고 오른쪽에서 읽는다.
**왼쪽은 한 번에 하나만 한다** — 고르는 중이면 목록, 따라가는 중이면 뻗어나가기.

```
┌── 왼쪽 ──────────────────┬── 문서 ─────────────┬─────┐
│ [목록] [뻗어나가기]       │                     │ 목  │
│                          │       본문          │ 차  │
│  관리문서 · 작업문서 · 좌표 │                     │ ▸   │
└──────────────────────────┴─────────────────────┴─────┘
```

목차는 본문 오른쪽에 **세로로** 선다 — 섹션이 159개인 문서도 다 들어가고,
넘치면 목차만 스크롤된다. 머리를 누르면 접힌다.

**뻗어나가기가 핵심이다.** 고른 것에서 **다음 한 계층만** 펼친다 — 계층이 섞이지
않고, 루프를 허용한다(트리가 아니라 그래프다).

```
작업문서 → 관리문서 · 좌표      좌표 → 관리문서 · 작업문서
관리문서 → 섹션
```

정렬은 늘 같다 — 좌표는 카테고리순+이름순, 작업문서는 작성일자순, 관리문서와
섹션은 섹션 순서. **상태로 정렬하지 않는다.**

**좌표 그래프는 3D 다.** Canvas 2D 에 손으로 만든 force layout — three.js 를
쓰지 않는다(CDN 이 없고 번들하면 exe 가 크게 는다). 고정 시드라 **같은 레포는 늘
같은 그림**이고, 노드는 무채색 원 하나에 **크기만 작업 건수**다.

**이름은 전부 붙는다.** 겹치면 숨기지 않고 자리를 옮긴다 — 가까운 것부터 놓고,
좌우·위아래로 한 줄씩 밀며 캔버스 안에서 빈 자리를 찾는다. 글자마다 바탕색
테두리를 둘러 선·노드 위에 얹혀도 읽힌다.

**노드를 누르면 1단계로 이어진 노드와 그 이름이 진해지고** 나머지가 옅어진다.
마우스를 떼도 **고정**돼 남으므로 무엇과 무엇이 붙어 있는지 계속 보면서 그
이웃을 눌러 볼 수 있다. 강조할 이름이 자리를 먼저 고르므로 빽빽한 곳에서도
읽어야 하는 이름이 밀리지 않는다.

**왼쪽 카테고리 레일**에서 타입(`table` `screen` …)을 고르면 **그 좌표만 색이
붙는다.** 상태로 색을 쓰지 않는다는 원칙은 그대로다 — 이건 상태가 아니라
사용자가 지금 무엇을 고르고 있나이고, 그것이 색 예산의 파랑(상호작용)이 하는
일이다.

**100% 는 기본 배율**이고, 전체가 들어오는 배율의 1.5배다. 전체를 다 넣으면
바깥으로 밀린 고립 노드가 배율을 정해 정작 볼 덩어리가 가운데에 작게 뭉친다
(실측 — 프레임을 폭 99% 채우는데 중앙 절반에 잉크가 39% 뿐이었다).
바깥까지 보려면 `−`.

| 키 | |
|---|---|
| `⌘K` / `Ctrl+K` | 검색 · 이동. 이름 넷에 걸고 객체 셋으로 낸다(아래) |
| `⌘.` | **읽기 모드** — 왼쪽을 접고 본문만 남긴다 |
| `⌘+` `⌘-` `⌘0` | 본문 글자 크기 |
| `⌥←` `⌥→` | 방문 이력 |
| `j` `k` `x` | 목록 이동 · 읽음 토글 |
| `⇧C` | 요약 복사 (프로토콜 §12.3 주입 형식과 동일) |
| `\` | 왼쪽 전환 — 목록 ↔ 뻗어나가기 |
| `Esc` | 검사 결과 · 메뉴 닫기 · 그래프/관리에서 문서로 (위에서부터 하나씩) |
| `?` | 도움말 — 단축키 · 매뉴얼 |

**왼쪽은 한 번에 하나만 한다** — 목록(고른다) 또는 뻗어나가기(따라간다). 둘이
같은 자리를 쓰므로 각각이 세로 전체를 받고, 폭도 따로 기억한다.

상단 — `문서 | 그래프 | 관리` 화면 전환 · 검색 · **⭮ 동기화** · **⚠ 검증
N**(0건이면 조용하다) · **⋯**(매뉴얼 · 읽기 모드 · 글자 크기 · 본문 폭 · 테마).
**셋 다 창 전체를 쓴다** — 좌표 288개짜리 그림도, 작업 레포 여섯 곳의 설치
상태도 패널에 들어가지 않는다. `Esc` 로 문서로 돌아온다.

**동기화는 상단에 하나뿐이다.** 매일 누르는 것이고 **도는 동안 보여야 하는
것**이라 메뉴 안에 둘 것이 아니었다 — 단계(`원격 확인 중` · `받는 중` ·
`다시 읽는 중`)와 걸린 초가 그 버튼에 뜬다. 사내망 fetch 실측 19.5초 동안
화면이 조용하면 사람은 멎은 줄로 읽고 한 번 더 누른다. 받는 것만 여기 있다 —
`⬆ 미전송 N건 보내기`(push)는 상태바에 따로 있다.

## 검색 — 이름 넷, 객체 셋

```
거는 곳   관리문서명 · 작업문서명 · 좌표명 · 좌표 alias
나오는 것 관리문서 · 작업문서 · 좌표
```

왼쪽 목록이 다루는 객체가 셋인데 검색만 다른 갈래로 답하면 같은 레포를 **두
가지 이름 체계**로 보게 된다. 갈래는 *어디서 걸렸나*가 아니라 *무엇인가*로
정하고, **왜 걸렸는지는 줄마다 붙는다** — alias 로 걸렸으면 그 alias 를 그대로
보여준다(`alias · 결의서연동`).

띄어쓰기·대소문자·`_`·`-` 는 양쪽에서 지우고 맞춘다 — `RP_PLND_MST` 도
`rp plnd mst` 도 같은 것을 가리킨다. **질의하는 사람이 표기를 맞춰야 한다면
그건 검색이 아니다.**

**걸린 좌표는 문서를 끌고 온다.** `계획서마스터` 를 찾은 사람은 그 좌표를
건드린 작업문서와 그 좌표가 실린 관리문서를 보려는 것이다. 관리문서 줄은
**그 섹션 자리에서** 열린다.

이름에서 아무것도 못 찾았을 때만 **본문 전문 검색**이 폴백으로 돈다(`⇧⏎` 로
강제). 그 결과도 같은 세 갈래에 접히고, 본문에서 걸렸다는 사실은 줄과 바닥에
적힌다 — 이름으로 찾은 것과 본문으로 찾은 것은 믿을 수 있는 정도가 다르다.

대조 블록은 그대로다. 자유로운 표현이 어떤 정본 좌표로 정규화됐고 `_vocab.md`
몇 번째 줄이 근거인지 보여준다 — **몰래 해주면 사용자는 정본을 영원히 모른다.**
다만 좌표를 하나도 못 찾았을 때만 "대조 실패"를 말한다. 좌표가 이름으로 걸렸으면
아래 좌표 갈래가 이미 정본을 보여주고 있다.

## 관리 화면 — ⚙

**세팅과 현황이 구석의 팝오버에 있을 일이 아니다.** 메뉴 다섯이 **작업의
성격**으로 갈린다.

| | |
|---|---|
| **현황** | 지금 쓸 수 있는 상태인가 — 레포 · 동기화 · 검증 · 파생 남은 섹션 · 작업 레포. **읽기만 한다** |
| **지식 레포** | 경로 · 구조 검증 다섯 줄(**상시**) · 레포가 든 `bin/ctx` 번들 시각 · 설정 파일 위치 |
| **동기화** | 진행 단계 · 최근 20건 이력 · git 설정 점검 여섯 줄 |
| **작업 레포** | 레포별 설치 상태(최신·갱신 필요·미설치·오류) · 계획 미리보기 · 일괄 갱신 · 설치 이력 |
| **진단 · 정보** | 버전 · 번들 시각 · 데이터 폴더 · 로그 파일 · 포트 · 감시 |

**동기화의 순서는 서버가 갖는다**(`core/sync.js` — `ctx sync` 도 같은 것을 쓴다).
`fetch → (뒤처졌으면) ff pull → 다시 읽기` 를 돌면서 단계를 SSE 로 뿌린다.

```
받는 중이면 어느 탭에서 보든 같은 단계가 보이고, 끝나면 이력 한 줄이 남는다.
사내망 fetch 실측 19.5초 — 그 20초 동안 화면이 조용하면 멎은 줄로 읽는다.
```

기록에는 **건수와 사유 문장까지만** 남는다. 문서 내용·검색어·커밋 메시지는
쓰지 않는다. 20건에서 자른다.

**앱이 git 설정을 쓰는 자리는 하나뿐이다** — `core.hooksPath`. 훅이 없으면
커밋이 검사 없이 통과하는 **조용한 실패**라서 버튼을 준다. 그 키 하나, 레포
로컬 설정만, `--global` 은 쓰지 않는다. 나머지(자격 증명 · `user.name`)는
**명령을 복사해 줄 뿐**이다 — 앱이 아이디·토큰을 들고 있으면 그것을 저장할
자리가 하나 더 생기고, 그 자리가 가장 약한 곳이 된다.

작업 레포 상태는 **열어 보지 않고 안다** — `ctx setup` 과 같은 계획을 dry 로
돌려 계산한다. 설치하면 언제·어느 판(`kit` 해시)을 넣었는지 남는다.

`⬆ 미전송 N건 보내기`(push)는 상태바와 관리>동기화의 **다른 블록**에 있다 —
**받는 것과 보내는 것을 같은 자리에 두지 않는다.**

## 사이트 · 콘솔 — 서버형의 세 얼굴

서버(`ctx serve`)는 **한 프로세스 · 한 포트 · 한 번들**로 얼굴이 셋이다. 주소의 첫 조각이 고른다.

| 얼굴 | 주소 | 누가 | 무엇 |
|---|---|---|---|
| **사이트** | `/` 소개 · `/manual` 설명서 세 권 + 설치 절차 · `/login` · `/setup` | 누구나 (`--private-pages` 면 로그인 뒤) | 제품 소개 · 서버가 든 판의 설명서 · 토큰 한 칸 로그인 · **첫 관리자 마법사**(`install.sh` 가 찍는 부트스트랩 코드) |
| **콘솔** | `/console` — 현황 · 사용자 · 토큰 · 지식 레포 · 작업 레포 · 서버 · 감사 | `admin` | 사람 · 역할 · 레포 할당 · 토큰 발급 · 재발급 · 폐기 · 새 레포(패키지 · clone) · 대장 · 진단 · 로그 · `auth.log`. 쓰기는 **재인증**(내 토큰을 한 번 더 · 15분) |
| **레포** | `/r/<레포>/` | 그 레포를 볼 수 있는 사람 | 위 「화면」 — 상단 레포 메뉴에 볼 수 있는 레포와 쓰기/읽기, 관리자에게 콘솔 링크 |

콘솔에 **없는 것** — 문서 편집 · `git pull/push` · 갱신 · PAT · 재시작. 갱신은 `upgrade.sh`, 비밀은 셸이다.
설계와 결정은 [`docs/design/CDP_제품관리서비스_검토_v0.1.md`](docs/design/CDP_제품관리서비스_검토_v0.1.md) →
[`docs/dev/제품관리서비스_TODO.md`](docs/dev/제품관리서비스_TODO.md), 절차는 관리자 설명서 3.5 · 3.7 · 6장.

## CLI — `ctx`

앱과 **같은 계산**을 쓴다. 두 곳에 판정을 두면 화면과 커밋 판정이 갈라진다.

```
ctx check     커밋 가능한가.  error 있으면 exit 1     ← git 훅이 이것만 본다
ctx derive    갱신이 남은 섹션
ctx apply     그 섹션에 붙일 변경 줄 초안 (파일은 안 고친다)
ctx where     그 좌표의 상태가 어느 문서 어느 섹션에
ctx match     이름 → 정본 좌표 (대조)
ctx term      어휘 조회
ctx index     INDEX.md · INDEX-by-coord.md 재생성
ctx brief     두 줄 요약
ctx search    말 → 좌표 후보 (match 가 미등재를 낼 때의 폴백)
ctx sync      원격과의 차이 · 훅 설정 여부
ctx version   이 번들이 언제 만들어졌나
ctx setup     작업 레포에 규약과 skill 을 넣는다 (--dry 로 미리보기 · --also · --desktop)
ctx mcp       MCP 서버 (stdio) · ctx serve  MCP 서버 (HTTP) + 관리 서비스
ctx package   패키지 — list · show · check(부어서 검사) · new · rename(프로젝트 이름으로)
ctx repo      지식 레포 — new <경로> --package <이름> [--origin --push] · list --root
ctx import-dir  md 폴더를 work/ 로 들인다 (--dry 먼저)
ctx serve doctor · init   서버 준비물 검사 · 첫 사용자와 토큰
```

지식 레포는 `bin/ctx` 를 **자기 안에** 들고 있다(폐쇄망 자족). `node` 가 있으면
`bin/ctx.mjs`, 없으면 `cdp.exe ctx` 로 넘긴다 — **exit code 까지 같아서** git 훅이
어느 쪽에서도 돈다.

> **번들이 조용히 낡는다.** 도구를 고치면 레포마다 새 `bin/ctx.mjs` 를 넣어야
> 하고, 잊으면 그 레포만 옛 답을 낸다. `ctx version` 이 번들 시각을 찍는 이유다.

## 단일 실행 파일

```bash
npm run build:exe
```

`ops/out/exe/cdp.exe` (~68MB). **더블클릭 한 번으로 실행된다** — 콘솔 창이 뜨지 않고,
아이콘이 붙어 있고, 트레이에 올라온다. `ctx` 도 이 안에 있다.

Node SEA 로 만든다 — 공식 기능이라 서드파티 패커 의존이 없고, **네이티브 모듈을
하나도 안 쓰기 때문에 이 방식이 성립한다.** SQLite 를 넣었으면 여기서 막혔다.

빌드가 하는 일 네 가지가 더 있다.

| | |
|---|---|
| **아이콘** | `tools/make-icon.mjs` 가 16~256px `.ico` 를 의존성 없이 만든다(무압축 DIB). 트레이 마크와 같은 모양이라 탐색기·작업표시줄·트레이가 일치한다 |
| **콘솔 창 제거** | PE 서브시스템을 `CONSOLE(3) → WINDOWS(2)` 로 2바이트 패치한다. `node.exe` 를 그대로 복사하면 더블클릭 시 검은 창이 같이 뜬다 |
| **로그 파일** | 콘솔이 없어지므로 `<데이터폴더>/logs/app.log` 가 유일한 진단 수단이 된다. 회전 3개 × 1MB. **문서 내용·검색어·토큰은 쓰지 않는다** |
| **주입 후 검증** | `cdp.exe ctx version` 이 날짜를 내놓아야 성공이다. 아니면 **반쪽 파일을 지우고 멈춘다** |

마지막이 중요하다. 갓 복사한 68MB 파일은 백신이 스캔하는 동안 잠기고, 그 지점이
하필 blob 주입 직전이다. 그러면 **실행은 되고 `Cannot find module 'ctx'` 만 뱉는
파일**이 남는다 — 실패했는데 성공처럼 보인다.

> **없는 것과 깨진 것은 다르고, 깨진 쪽이 더 나쁘다.** 없으면 다시 만들지만,
> 깨진 것은 다음 사람이 정상으로 믿는다.

`EBUSY` 로 멈추면 `taskkill /F /IM cdp.exe`.

exe 옆에 빈 파일 `cdp.portable` 을 두면 설정·캐시·로그가 `%LOCALAPPDATA%` 대신
exe 폴더의 `data/` 로 간다. 공유 드라이브나 USB 에서 그대로 돌아간다.

**인자 없이 더블클릭하면** exe 가 든 지식 레포(`<레포>/tools/cdp.exe` — 부모에 `_vocab.md`)를 연다.
레포 밖에 있으면 저장된 설정, 그것도 없으면 경로 지정 화면이 뜨고 한 번 지정하면 기억한다.

```
cdp.exe --repo <지식 레포 경로>
```

## 트레이 (Windows)

exe 로 실행하면 트레이 아이콘이 뜬다. 우클릭 메뉴 — 열기 · 레포 폴더 열기 ·
**탭 닫아도 계속 실행** · 종료. 더블클릭하면 브라우저가 열린다.

**npm 트레이 패키지를 쓰지 않았다.** 전부 플랫폼별 헬퍼 바이너리나 네이티브
애드온을 붙이는데, 네이티브 모듈이 없다는 것이 SEA 단일 파일 빌드를 성립시킨
조건이다. 대신 Windows `NotifyIcon` 을 PowerShell 로 띄운다 — 의존성 0.

스크립트는 앱 데이터 폴더에 **읽을 수 있는 `tray.ps1` 로 쓰고 `-File` 로** 넘긴다.
`-EncodedCommand` 가 따옴표 문제는 없지만 base64 PowerShell 은 EDR 이 난독화로
보는 대표 신호라서, 검사받을 수 있는 형태를 택했다.

| | |
|---|---|
| 부모가 죽으면 | 헬퍼가 부모 PID 를 폴링하다 같이 종료한다. **유령 아이콘이 남지 않는다** |
| PowerShell 이 막히면 | 트레이 없이 그대로 동작한다. 앱이 죽지 않는다 |
| 탭 닫아도 계속 실행 | 유휴 종료(90초)를 끈다. **켜져 있으면 상태바에도 표시된다** — 안 보이면 켠 것을 잊는다 |

## 샘플 레포 — **뷰어 개발용 fixture 다**

`viewer/fixture/` 는 **뷰어를 개발할 때 읽을 지식 레포**다. 그 하나의 용도다.

| | |
|---|---|
| 쓰는 곳 | `npm start` · `npm run dev:server` · `ops\check.cmd` |
| **배포본** | **안 들어간다.** 받는 사람에게 가지 않는다 |
| **데이터 보관** | **아니다.** GDI 자료의 사본으로 의존하지 않는다 |

`npm run seed` 로 재생성한다. **릴리스는 seed 를 부르지 않는다** — 부르던
시절에 덤프 없는 PC 에서 릴리스 한 번이 테이블정의서 32섹션을 1섹션으로
줄인 적이 있다(`caa835a`).

**커밋 가능한 정상 레포를 만든다.** 전에는 밀림·미작성을 일부러 심어
시연했는데, 그것이 오류가 된 뒤로는 **clone 직후 커밋이 막히는 샘플**이
됐다 — 폐쇄망 반입 검증(clone 해서 커밋이 되는가)이 무의미해진다.

대신 **판정이 갈리는 것**은 남겼다 — 좌표별로 판정이 다른 문서, 좌표 0개,
등록부 없는 타입(`domain:`), 점유, 오기재 정정, 작업 기록이 없는 섹션.
목록은 `viewer/fixture/README.md`.

## 구조

**상위 폴더는 다섯이다** (+ `test/` · `.github/` · `manual/`).

```
core/                    **계산 — 정본.** 스캔 · 프론트매터 · 어휘 · 등록부
                         캐시 · 감시 · 최신성(later) · 검색 인덱스 · 내장 검증
                         git · **동기화 순서(sync)** · 작업 레포 설치(setup)
                         앱과 `ctx` 가 **같이** 쓴다 — 그래서 둘 중 하나의 밑이 아니다

viewer/                  뷰어 프로그램
  server/adapter/        HTTP + SSE · 트레이 · 토큰/Origin/경로 봉인
  src/                   화면. 마크다운 렌더는 전부 클라이언트가 소유한다
  bin/                   ctx CLI (소스) — 번들되어 레포 안으로 들어간다
  fixture/               **뷰어 개발용 지식 레포.** 배포본에 안 들어간다
  index.html  vite.config.js

agent/                   **받는 사람에게 가는 것의 원본**
  skills/                work · load · save · import · edit · managed · push
  CLAUDE-지식레포.md      지식 레포에 들어갈 규약
  CLAUDE-프로젝트레포.md   작업 레포에 **블록으로** 들어갈 규약
  TEMPLATE-work.md
  hooks/pre-commit       유일한 결정론적 보증 층
  manual/                system(정본) · user · admin
  packages/              프로젝트마다 골라서 붓는 문서 골격 · 등록부 · 어휘
  install.md             설치 시나리오 — 배포본 루트로 간다

ops/                     **명령** — 사람이 실행하는 것
  setup · dev · start · check · seed · release  (.cmd)
  lib/                   그 명령이 부르는 구현. 직접 실행하지 않는다 — assemble(조립 하나) · release · release-server
  deploy/                서버 — install.sh · upgrade.sh · 유닛 · Dockerfile · 설치절차
  verify/                검증 하네스
  out/                   중간 산출물 — web · ctx · exe · server   (추적 안 함)
  release/v<버전>/        배포본                          (추적 안 함)

test/                    단위 테스트 — core/ 의 순수 함수. `node:test` · 의존성 0
.github/workflows/       ci.yml · release.yml

docs/                    **우리만 보는 것**
  design/                설계서 — 보존 · CDP 개선 작업의 문서 더미
  dev/                   개발 메모 · TODO · 시나리오 · 검토 기록
  attic/                 **한 번 돌고 끝난 것** — GDI 재구성과 그 입력

manual/                  **제품 설명서 — 원천.** 사용자 · 관리자 · 개발자 세 권
```

**산출물이 `ops/` 아래에 있는 이유** — 만드는 쪽이 거기다. 루트에 두면
`out/` 과 `release/` 가 상위 폴더 행세를 하는데, 둘 다 추적되지 않는
부산물이다.

**루트에 남는 것은 도구가 요구하는 자리뿐이다** — `package.json` ·
`package-lock.json` 은 npm 이, `.gitattributes` · `.gitignore` 는 git 이
루트에서만 읽는다.

**`node_modules/` 는 못 옮긴다.** npm 은 `package.json` 옆에 만들고 node 는
파일 위치에서 **위로 올라가며** 찾는다. `viewer/` 와 `ops/lib/` 가 둘 다 외부
의존을 쓰므로(`js-yaml`·`chokidar` / `rcedit`) 어느 한쪽으로 내리면 다른 쪽이
못 찾는다. 워크스페이스로 묶어도 루트로 끌어올려진다. **하나뿐인 예외로 둔다.**

**`agent/` 가 원본인 이유** — 전에는 스킬 4개가 fixture 의
`.claude/skills/` 안에만 있었다. fixture 안의 사본이 사실상 원본이라, 고치려면
fixture 를 고치고 다른 레포에는 **손으로 복사**해야 했다. 레포가 셋이면 세
번이고, **실제로 세 번 갈렸다.**

그래서 fixture 의 `.claude/` 는 **추적하지 않는다** — `seed` 가 `agent/` 에서
만든다. `bin/` 은 반대로 추적한다(clone 만 하면 샘플이 바로 돌게). `.gitignore`
에 두 결정이 나란히 적혀 있다.

`core/` 는 HTTP 를 모른다. 보안 심사가 localhost 리스너를 막으면 `adapter/` 만
IPC 로 갈아끼우고 화면 코드는 그대로 쓴다.

**판정은 `core/` 한 곳뿐이다.** 이것을 두 곳에 두면 화면과 커밋 판정이 갈라지고,
그때 사람은 화면을 믿는다. 불변조건 전체는 설계서 제3부.

## 안 하는 것

| | |
|---|---|
| 문서 편집·생성 | 작성은 `cdp-save` skill 의 일이다. 뷰어가 하면 좌표 대조·훅 검증을 우회하는 경로가 생긴다 |
| **merge · rebase · 충돌 해결** | 사용자가 터미널에서 한다. 섹션 두 갱신을 기계가 섞으면 그 결과가 정본 자리에 앉는다 |
| **자동 push** | 커밋은 되돌릴 수 있지만 push 는 남의 눈에 들어간다. 사람이 누른다 |
| **본문 요약·AI TL;DR** | 프로토콜 §8.4 — *"왜에 담기는 제약과 트레이드오프는 필드로 쪼개는 순간 죽는다."* 요약도 같은 손실이다 |
| 낡음 추정 경고 | `fetch` 없이 "낡았을 수 있습니다"를 띄우는 것은 근거 없는 경고다 |
| **알림** | 무시되기 시작하면 되돌릴 수 없고, 그때 *"알림이 안 왔으니 없는 것"* 이라는 더 나쁜 오해가 자리 잡는다 |
| RAG · 임베딩 | 좌표가 답이다. 근사 검색은 **"없는 것"을 "비슷한 것"으로 채운다** |
| 레포에 쓰기 | 캐시·읽음 표시·설정 전부 `%LOCALAPPDATA%\cdp\` 에 있다 |

전체 목록과 이유는 설계서 제4부.

## 보안

로컬 리스너는 이 도구가 새로 만든 위험면이다. 가장 현실적인 사고는 **브라우저에
열린 임의의 외부 페이지가 `fetch('http://127.0.0.1:7373/api/docs')` 로 사내
문서를 전량 가져가는 것**이다. 실측으로 확인했다.

| 시나리오 | 결과 |
|---|---|
| 정상 (토큰 + Host) | 200 |
| 토큰 없음 · 틀림 | 401 |
| **Host 위조 (DNS 리바인딩)** | **연결 종료** — 응답조차 주지 않는다 |
| 외부 Origin | 403 |
| `Sec-Fetch-Site: cross-site` | 403 |
| 경로 순회 (`../../Windows/win.ini`) | 403 |

`--host` 로 loopback 이 아닌 주소를 열면 콘솔과 화면에 상시 경고가 뜬다.
