# ctx-view

지식 레포 뷰어. 좌표 기반으로 탐색하고 **사람이 본문을 읽는** 도구다.

설계서 — [`docs/지식레포_뷰어_설계서_v0.2.md`](docs/지식레포_뷰어_설계서_v0.2.md)
전제 문서 — [`docs/맥락배포프로토콜_설계서_v1.1.md`](docs/맥락배포프로토콜_설계서_v1.1.md)

```
문서는 PC 를 떠나지 않는다. 네트워크로 나가는 것이 아무것도 없다.
git 을 한 줄도 실행하지 않는다. 레포에 파일을 하나도 쓰지 않는다.
```

## 실행

```bash
npm install && npm run build
```

```bash
npm start
```

동봉된 샘플 레포(`sample-repo/`)로 뜬다. 다른 레포를 보려면:

```bash
node server/index.js --repo "C:\work\knowledge-repo"
```

브라우저가 자동으로 열린다. 탭을 닫으면 90초 뒤 프로세스도 종료된다.

| 인자 | |
|---|---|
| `--repo <경로>` | 지식 레포 경로. 없으면 화면에서 지정하고 설정에 저장된다 |
| `--port <n>` | 기본 7373. 사용 중이면 +1 씩 20회 시도 후 임의 포트 |
| `--no-open` | 브라우저 자동 열기 끔 |
| `--no-watch` | 파일 감시 끔 (감시가 문제를 일으키는 환경의 비상 스위치) |
| `--tray` / `--no-tray` | 트레이 아이콘. 기본값은 **exe 실행이면 켜짐, `node` 실행이면 꺼짐** |
| `--host <addr>` | 기본 `127.0.0.1`. **다른 값은 화면에 상시 경고가 뜬다** |

**개발**

```bash
node server/index.js --repo <경로> --dev http://localhost:5173 --no-open
```

다른 터미널에서 `npm run dev` — Vite 가 화면을, node 가 API 를 맡고 `/api` 만 프록시된다.

## 단일 실행 파일

```bash
npm run build:exe
```

`build/ctx-view.exe` (67MB). **더블클릭 한 번으로 실행된다** — 콘솔 창이 뜨지 않고,
아이콘이 붙어 있고, 트레이에 올라온다.

Node SEA 로 만든다 — 공식 기능이라 서드파티 패커 의존이 없고, **네이티브 모듈을
하나도 안 쓰기 때문에 이 방식이 성립한다.** SQLite 를 넣었으면 여기서 막혔다.

빌드가 하는 일 세 가지가 더 있다.

| | |
|---|---|
| **아이콘** | `tools/make-icon.mjs` 가 16~256px `.ico` 를 의존성 없이 만든다(무압축 DIB). 트레이가 그리는 마크와 같은 모양이라 탐색기·작업표시줄·트레이가 일치한다 |
| **콘솔 창 제거** | PE 서브시스템을 `CONSOLE(3) → WINDOWS(2)` 로 2바이트 패치한다. `node.exe` 를 그대로 복사하면 더블클릭 시 검은 창이 같이 뜬다 |
| **로그 파일** | 콘솔이 없어지므로 `<데이터폴더>/logs/app.log` 가 유일한 진단 수단이 된다. 회전 3개 × 1MB. **문서 내용·검색어·토큰은 쓰지 않는다** |

CLI 로 쓰는 경로는 `npx ctx-view` 쪽이고 그건 콘솔이 그대로 살아 있다.

exe 옆에 빈 파일 `ctx-view.portable` 을 두면 설정·캐시·로그가 `%LOCALAPPDATA%`
대신 exe 폴더의 `data/` 로 간다. 공유 드라이브나 USB 에서 그대로 돌아간다.

**인자 없이 더블클릭하면** 경로 지정 화면이 뜨고, 한 번 지정하면 그 뒤로 기억한다.
바로 열고 싶으면:

```
ctx-view.exe --repo <지식 레포 경로>
```

## 트레이 (Windows)

exe 로 실행하면 트레이 아이콘이 뜬다. 우클릭 메뉴 — 열기 · 레포 폴더 열기 ·
**탭 닫아도 계속 실행** · 종료. 더블클릭하면 브라우저가 열린다.

**npm 트레이 패키지를 쓰지 않았다.** 전부 플랫폼별 헬퍼 바이너리나 네이티브
애드온을 붙이는데, 네이티브 모듈이 없다는 것이 SEA 단일 파일 빌드를 성립시킨
조건이다. 대신 Windows `NotifyIcon` 을 PowerShell 로 띄운다 — 의존성 0.

스크립트는 앱 데이터 폴더에 **읽을 수 있는 `tray.ps1` 로 쓰고 `-File` 로** 넘긴다.
`-EncodedCommand` 가 따옴표 문제는 없지만 base64 PowerShell 은 EDR 이 난독화로
보는 대표 신호라서, 검사받을 수 있는 형태를 택했다.

| | |
|---|---|
| 부모가 죽으면 | 헬퍼가 부모 PID 를 폴링하다 같이 종료한다. **유령 아이콘이 남지 않는다** |
| PowerShell 이 막히면 | 트레이 없이 그대로 동작한다. 앱이 죽지 않는다 |
| 탭 닫아도 계속 실행 | 유휴 종료(90초)를 끈다. **켜져 있으면 상태바에도 표시된다** — 안 보이면 켠 것을 잊는다 |

## 샘플 레포

`sample-repo/` 는 동작 확인용 fixture다. GDI(경북연구원 연구관리 시스템) 실제 작업
자료에서 가져왔고 `npm run sample` 로 재생성한다.

**정상 문서만 있는 fixture 로는 이 뷰어가 무엇을 하는지 검증할 수 없다.** 그래서
이상 케이스를 일부러 심어뒀다 — `supersedes` 순환, 끊어진 참조, 미등재 좌표,
deprecated 좌표, '왜' 없는 문서, 좌표 8개 문서, 밀린 `INDEX.md`, 977행 첨부.
목록은 `sample-repo/README.md`.

## 구조

```
server/
  core/        스캔 · 프론트매터 · 4섹션 분해 · 캐시 · 감시
               유효성 · 최신성 · 검색 인덱스 · 내장 검증
  adapter/     HTTP + SSE. 토큰 · Host 검증 · 경로 봉인
src/           화면. 마크다운 렌더는 전부 클라이언트가 소유한다
```

`core/` 는 HTTP 를 모른다. 보안 심사가 localhost 리스너를 막으면 `adapter/` 만
IPC 로 갈아끼우고 화면 코드는 그대로 쓴다(설계서 §5.4 · §8).

## 안 하는 것

| | |
|---|---|
| 문서 편집·생성 | 작성은 `knowledge-share` skill 의 일이다. 뷰어가 하면 좌표 대조·훅 검증을 우회하는 경로가 생긴다 |
| **레포 최신화** (`fetch`·`pull`·`clone`) | 사용자가 터미널에서 한다. 뷰어는 지금 디스크에 있는 것을 정확히 보여줄 뿐이다 |
| **본문 요약·AI TL;DR** | 프로토콜 §8.4 — *"왜에 담기는 제약과 트레이드오프는 필드로 쪼개는 순간 죽는다."* 요약도 같은 손실이다 |
| 낡음 추정 경고 | `fetch` 없이 "낡았을 수 있습니다"를 띄우는 것은 근거 없는 경고다 |
| 레포에 쓰기 | 캐시·읽음 표시·설정 전부 `%LOCALAPPDATA%\ctx-view\` 에 있다 |

전체 목록은 설계서 §31.

## 보안

로컬 리스너는 v0.1 에 없던 위험면이다. 가장 현실적인 사고는 **브라우저에 열린
임의의 외부 페이지가 `fetch('http://127.0.0.1:7373/api/docs')` 로 사내 문서를
전량 가져가는 것**이다. 설계서 §7.2 의 대응을 실측으로 확인했다.

| 시나리오 | 결과 |
|---|---|
| 정상 (토큰 + Host) | 200 |
| 토큰 없음 · 틀림 | 401 |
| **Host 위조 (DNS 리바인딩)** | **연결 종료** — 응답조차 주지 않는다 |
| 외부 Origin | 403 |
| `Sec-Fetch-Site: cross-site` | 403 |
| 경로 순회 (`../../Windows/win.ini`) | 403 |

`--host` 로 loopback 이 아닌 주소를 열면 콘솔과 화면에 상시 경고가 뜬다.
