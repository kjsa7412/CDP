## 업무 맥락

이 프로젝트에는 **지식 레포**가 딸려 있다.

```
docs/   관리 문서 — 지금 어떤 상태인가
work/   작업 기록 — 무슨 일이 있었나
```

프로젝트의 테이블·화면·API·용어·코드 상태를 알아야 하는 작업 요청은
`.claude/skills/` 의 skill 로 처리한다. 절차는 그 skill 안에 있다.

### 지식 레포가 어디인가

**경로는 이 파일에 없다.** `.claude/cdp.json` 에 있다.

```json
{ "knowledgeRepo": "D:/work/cdp" }
```

이 파일은 **커밋하지 않는다** — 지식 레포를 어디에 두는지는 사람마다
다르다. 이 `CLAUDE.md` 는 팀이 함께 쓰는 규약이고, 경로는 각자의 것이다.

경로가 필요하면 `.claude/cdp.json` 을 읽는다. skill 안의 `<repo>` 가
그 값이다.

```
<repo>/bin/ctx brief          지금 레포 상태
<repo>/bin/ctx where <좌표>    그 좌표가 어느 문서 어느 섹션인가
<repo>/tools/cdp.exe          뷰어 (더블클릭)
```

`ctx` 는 이 레포 안 어디서 불러도 `.claude/cdp.json` 을 보고 지식 레포를
찾는다. 못 찾으면 그 파일이 없는 것이다 — `ctx setup` 을 다시 돌린다.

### 도구가 있으면 도구로

`.mcp.json` 에 `cdp` 가 있으면 같은 것을 **도구**로 부를 수 있다.

```
mcp__cdp__where     좌표의 지금 상태가 어느 문서 어느 섹션에
mcp__cdp__section   그 섹션 본문만 — 문서를 열지 않는다
mcp__cdp__work      작업 기록 하나 — "왜 그렇게 정했나"
mcp__cdp__match     말 · alias 를 정본 좌표로
```

**둘은 같은 함수다.** `ctx <명령> --json` 과 결과가 바이트까지 같고, 어느
쪽으로 불렀는지는 답에 영향을 주지 않는다. 도구가 없으면 `bin/ctx` 로 부른다 —
절차는 skill 이 갖고, 통로만 둘이다.

쓰기는 도구에 없다. 기록·파생·커밋은 skill 과 git 이 한다.

### 셸 없이 정본만 읽는 에이전트

서브에이전트에 `Bash` 를 주지 않고 정본만 읽히려면 `tools:` 를 이렇게 짠다.

```yaml
tools: Read, Grep, Glob, mcp__cdp__match, mcp__cdp__where, mcp__cdp__section, mcp__cdp__work
```

`Bash(ctx *)` 는 **셸이 할 수 있는 전부**를 여는 것이고 도구 이름은 그
도구만 여는 것이다 — 권한의 단위가 문자열 패턴에서 이름으로 바뀐다.
어느 에이전트에 무엇을 줄지는 각 프로젝트가 정한다.
