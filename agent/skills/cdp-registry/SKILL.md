# cdp-registry — 등록부와 관리 문서의 구조를 바꾼다

```
① 무엇을    행 더하기 · 이름 · 합치기 · 폐기 · 지우기 · 서식 예시 정리 · 섹션 밖 글
② 영향      match · where · docs 로 걸리는 좌표 · 가리키는 줄 · 어긋나는 문구를 센다
③ 미리보기   save({ …, dryRun: true }) — 【등록부 변경】 을 보이고 승인
④ save      승인받은 입력에서 dryRun 만 뺀다 — 기록 하나(사유) + 등록부 · 문서 한 커밋
⑤ 끝 보고    커밋 · 미러는 cdp-save 「끝 보고」 표 그대로
```

**큐레이터만 쓴다.** 큐레이터는 레포별 권한이다(admin 은 모든 레포의 큐레이터). `E_FORBIDDEN` `need: curate` 가 오면 멈춘다 — writer 는 **기록만 남기고**(cdp-save) 큐레이터에게 맡긴다. 그때는 요청문을 만들어 준다(무엇을 · 왜 · 영향받는 좌표).

**기록을 섹션에 반영하는 것은 cdp-curate 다.** 서식에서 새 문서를 세워 기록을 반영하는 판정(`new`)도 cdp-curate 가 하고, 그때 행 · 문서의 규칙은 아래 「행 더하기」 다.

## 공통 — 기록 하나가 사유다

구조만 바꾸는 save 도 작업 기록 하나와 같이 간다. 행은 사라지기도 하므로 **사유는 기록 본문에만 남는다.**

| `work.` | |
|---|---|
| `touches` · `touchesEmpty` | `[]` 와 사유 — 「등록부 정리만 했다」 · 「관리 문서 정리」 · 「서식 예시 정리」 |
| `tags` | `["registry"]` · 지우기는 `["docs-prune"]`. **이 태그가 있어야 대기열에 서지 않는다** — 없으면 좌표 0 의 작업 기록으로 대기열에 선다 |
| `body` | 사유와 결과 — 왜 · 무엇이 어디로 갔나 · 영향받은 좌표 수 |

새 문서를 세우며 기록을 반영하는 save 라면 이 기록 대신 cdp-curate 의 큐레이션 기록이 그 자리다.

승인 게이트는 cdp-save 「승인 게이트」 와 같다 — **승인 전에는 커밋하는 `save` 를 부르지 않는다.** 먼저 같은 입력에 `dryRun: true` 를 붙여 서버가 권한 · 계획 · 검사까지 돌게 하고, 걸리는 것을 고친 뒤 보인다. 충돌(`E_CONFLICT`)은 cdp-curate 「충돌 · 거절」 표 그대로다.

```
【등록부 변경】
  행 더하기     term:*  →  docs/용어집.md ## {값}   (새 문서 · 서식 <id> · 등록부 맨 끝 — 기존 행은 안 바뀐다)
  걸리는 좌표    term:PLC 외 n — 기록이 이미 닿았다 → 섹션을 같이 · 큐레이션으로(cdp-curate)
  어긋나는 문구  docs/용어집.md 머리말 1행 「…」 → edits 로 「…」 / 없음
  정리          rename · merge · retire · drop — 영향받는 좌표 n · 가리키는 줄 n · 알고 둘 줄 n
  dryRun        통과 · warnings 그대로
```

## 행 더하기 — `managed: [{ pattern, doc, form?, title?, level? }]`

- **먼저 있는지 본다** — `match` · `where` · `docs({ repo })`. 같은 것을 받는 타입 · 문서가 이름만 다르게 있으면 만들지 않고 그것을 쓴다. 이름만 다른 중복이 이 기능의 첫 부작용이다.
- **패턴은 타입 하나에 `type:*`** 가 기본이다. 타입은 기록이 쓴 좌표의 타입이다(서식의 `registry` 는 제안). 좁히는 것(`type:P*`)은 이유가 있을 때 — 한 번에 걸리는 섹션이 50 을 넘어 나눠 붙일 때.
- **문서 경로는 그 레포의 폴더 규약을 따른다** — `docs/2.설계/…` 면 그 아래, 없으면 `docs/<이름>.md`. `docs/` 밖 · `..` · 절대경로는 거절된다.
- **새 문서면 서식을 고른다** — `forms`(cdp-curate 「새 문서」). `form` 을 주면 서버가 제목 · 서식 표지 · 첫 문단만 찍는다. 이미 있는 문서면 행만 더하고 서식은 무시한다(경고). 맞는 서식이 없으면 `title` 만 — `# 제목` 한 줄.
- `level` 은 기본 2(`## {값}`)다. 한 문서에는 한 레벨만 둔다.
- **종류** — `kind`(대상 · 대장 · 정의 · 사건 · 서술)는 등록부 「종류」 칸에 적혀 drift 의 비대 잣대가 된다(대장 40 · 정의 25 · 대상 · 서술은 150줄 「큼」). 서식을 주면 서식의 kind 가 들어간다 — 서식 없이 세우는 문서는 `kind` 를 같이 준다. 이미 있는 행은 `{ op: "kind", pattern, kind }` 로 칸만 바꾼다(큐레이터 · 칸이 없는 옛 등록부는 머리에 칸을 더한다).
- **새 행이 걸리는 좌표는 섹션을 같이 보낸다** — 그 좌표를 이미 `touches` 한 기록이 있으면 서버가 `E_INPUT { needSections }` 로 거절한다(그 커밋부터 앵커 없음이 된다). 그 섹션을 쓰는 것은 기록을 반영하는 일이다 — cdp-curate 로 판정하며 한 save 에 넣는다(`applied: null` · `heading: "<값> — <설명>"`). 50 을 넘으면 패턴을 좁혀 나눈다.
- **덮인 패턴 · 같은 패턴** — 앞 행에 완전히 덮이는 패턴은 거절된다(`detail.shadowedBy` — 그 행의 문서에 붙인다). 같은 패턴이 이미 다른 문서에 있으면 `E_CONFLICT` `detail.kind: managed` · `detail.current` — 그 문서에 붙이거나 다른 패턴을 고른다.
- **어긋나는 문구를 먼저 본다** — 행을 더하면 그 문서 머리말의 「비대상 · 좌표-섹션이 1:1로 대응하지 않는다」, `_vocab.md` · `_managed.md` 의 「<타입> 타입이 없다」 같은 줄이 거짓이 된다. `docs({ repo, doc })` 로 읽어 고칠 문장을 【등록부 변경】 에 싣고 같은 save 의 `edits` 로 보낸다. 서버도 남은 줄을 `E_INPUT { lines: ["파일:행"] }` 로 막는다 — 맞는 줄이면(오탐) `managed[].reviewed: ["파일:행"]`.
- 머리 표의 등록부 칸 · `_vocab.md` 의 생성 블록은 서버가 찍는다 — 손대지 않는다. 한 save 에 `managed` 10건까지.

## 이름 · 합치기 · 폐기

| 하려는 것 | `managed` | 서버가 하는 것 | 안 하는 것 |
|---|---|---|---|
| 문서 이름 · 위치를 바꾼다 | `{ op: "rename", doc, to }` | 파일을 옮기고 그 문서를 가리키는 **모든 행**의 경로를 바꾼다 · 섹션 · applied 는 그대로 | 다른 문서 안의 링크(경고 — `edits` 로 고친다) |
| 문서 둘을 하나로 | `{ op: "merge", doc, into }` | `doc` 의 섹션을 `into` 끝에 잇고 행을 `into` 로 돌리고 `doc` 을 지운다 | 내용 병합 · 요약. 같은 이름의 섹션이 양쪽에 있으면 **전부 되돌린다** — 이름을 고치고 다시 |
| 행을 폐기한다 | `{ op: "retire", pattern }` | 그 행을 지운다 | 문서 파일은 지우지 않는다(등록부에 안 걸린 문서로 남는다) |

- 합치기는 두 문서의 섹션 레벨이 같고, 합칠 문서의 첫 섹션 앞에 머리말이 없을 때만 된다 — 아니면 먼저 `edits` 로 정리한다.
- **`retire` 는 검사를 끄는 수단이 아니다** — 「막혔으니 행을 지운다」 는 이유가 아니다. 그 타입의 섹션이 정말 더 안 쓰일 때만.
- 영향받는 좌표 수를 `where` 로 세어 【등록부 변경】 「정리」 줄에 적는다.

## 안 쓰는 문서 지우기 — `{ op: "drop", doc, reason }`

| | 행 | 파일 | 내용 | 언제 |
|---|---|---|---|---|
| `retire` | 지운다 | 남긴다 | 남는다 | 좌표 판정만 끄고 문서는 읽을거리로 |
| `merge` | `into` 로 | 지운다 | `into` 로 옮긴다 | 두 문서를 하나로 |
| **`drop`** | 지운다 | **지운다** | git 이력에만 | 이 프로젝트에 **필요 없는** 문서 |

1. **후보를 표로 보인다** — `docs({ repo })` 의 문서마다 `usage`(`state` · `sections` · `touchedBy` · `mentionedBy` · `refsIn` · `required` · `lastChange`). `state: 서식 그대로` 는 제안이다 — 「아직 안 썼다」 와 구별되지 않는다. **사람이 고른다.** 묶음(같은 번호 앞자리 `TE_201` · `TE_202` · `TE_203`)으로 제안한다 — 묶음째 지우면 서로의 참조가 고칠 목록에서 빠진다.
2. **미리보기** — `dryRun: true` 로 부르면 `dropped` 가 온다 — 지울 행 · 예시 좌표(`vocabRemoved`) · 남길 좌표(`vocabKept`) · **가리키는 줄**(`refs` — 줄마다 `suggest` 와 초안 `edit`).
3. **가리키는 줄을 판정한다** — 줄마다 하나. `drop-row`(표 행에 그 문서만) · `unlink`(링크)는 초안 `edit` 를 그대로 `edits` 에. `review`(산문 · 남는 문서와 같이 적힌 행)는 고쳐 쓸 문장을 만든다 — 그 정보가 이제 어디로 가나. 고칠 까닭이 없으면 `reviewed: ["파일:행"]`. 한 save 에 `edits` 20 · op 하나에 `reviewed` 50 — 넘으면 나눠 지운다.
4. **승인** — 「지울 문서 n · 행 · 예시 좌표 · 고칠 줄 n · 알고 둘 줄 n」 을 보이고 받는다.
5. **지운다** — 같은 입력에서 `dryRun` 을 빼고 `edits` · `reviewed` 를 싣는다. 기록은 `tags: ["docs-prune"]` · `touchesEmpty: "관리 문서 정리"` · 본문이 사유. `_managed.md` 「지운 관리 문서」 표에 남는다.

- **거절되면 안 쓰는 문서가 아니다** — 기록이 반영된 섹션이나 `touches` 이력이 있으면 서버가 거절한다. 내용을 남기려면 `merge`, 좌표 판정만 끄려면 `retire`.
- 필수 제출(`required`) 문서는 경고가 온다 — 계약상 필요 없는지 사람에게 묻는다.
- 남긴 줄은 `check` 의 「없는 관리 문서를 가리키는 줄」 이 계속 말한다(경고).

## 서식 예시 정리 — `examples: "purge"`

옛 패키지로 세운 레포에는 `example:` 이 붙은 어휘와 짝 섹션 · 「(예시)」 섹션이 남아 있다(`check` 의 example-coord 경고). `save({ repo, work, examples: "purge" })` 한 번이 어휘 줄과 짝 섹션을 같이 지운다 — 한쪽만 지우면 `where` 가 빈손이거나 앵커 없음이다.

- 기록이 이미 `touches` 로 쓴 예시 좌표는 지우지 않는다 — 그때는 진짜 좌표다. 표시만 떼고 `kept` 로 알린다.
- 응답 `examples.left` 는 표의 행으로 남은 예시다 — 지울지는 사람이 고르고 `edits` 로.
- 기록은 `tags: ["registry"]` · `touchesEmpty: "서식 예시 정리"`.

## 섹션 밖 글 — `edits: [{ file, old, new }]`

좌표 섹션은 `sections` 로 쓴다(cdp-curate). **그 밖** — 문서 머리말(첫 `##` 앞) · 등록부 밖 문서(회의록 같은 날짜축 · 가이드)의 본문 · `_vocab.md` · `_managed.md` 의 산문 — 은 `edits` 다.

```
docs({ repo, doc: "BM_411" })
```

`text`(원문) · `headings` · `registered` 가 온다. 관리번호 · 경로 · `_vocab.md` · `_managed.md` 를 받는다.

- `old` 는 `text` 에서 **그대로 뗀 글**이고 정확히 한 번 나와야 한다 — 두 번 이상이면 앞뒤 줄을 더 붙인다(`E_INPUT`). 없으면 읽은 뒤 바뀐 것이다(`E_CONFLICT` — `docs` 로 다시 읽는다). 지우려면 `new: ""`.
- **못 건드리는 자리** — 좌표 섹션(→ `sections`) · `<!-- applied -->` · 어휘 줄(→ `vocab`) · 등록부 행(→ `managed`) · 생성 블록. 서버가 `E_INPUT` 에 그 줄과 갈 곳을 적어 준다.
- 기록은 언제나 같이 간다 — 큐레이션의 일부면 그 큐레이션 기록이, 아니면 `tags: ["registry"]` 기록이.
- 한 save 에 20건까지. 작업 기록(`work/`)은 고치지 않는다 — 정정은 작성자의 정정 기록이다.
- 뷰어의 HTTP API(`/api/<repo>/docs` · `/file`)를 토큰으로 부르지 않는다 — 문서는 `docs` 로 읽는다.

## 레포를 다시 세우기 — admin 의 일

관리 문서가 엉망인 옛 레포를 기록만으로 다시 세우는 것은 이 스킬이 아니다 — admin 이 콘솔 「새 지식 레포」 의 「기록만 옮겨 오기」 로 한다. 작업 기록 · 첨부 · 그 기록이 쓴 어휘만 옮기고 관리 문서는 옮기지 않는다 — 옮긴 기록은 전부 대기열에 선다. 그다음이 큐레이터의 일이다 — cdp-curate 로 서식에서 문서를 세우며 반영한다.

## 하지 않는 것

| | 어디로 |
|---|---|
| 기록을 섹션에 반영 · 판정 | cdp-curate |
| 기준선 블록 안 | 프로젝트의 생성기(기준선 save) |
| 레포 세우기 · 이름 · 원격 · 사람 · 권한 | admin — 콘솔 |
| 어휘 줄 · 타입 지우기 | 연산이 없다 — 관리자에게 |
