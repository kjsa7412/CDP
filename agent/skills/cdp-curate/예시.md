`coords` — `이슈:ISS-007` section · state pending · 미반영 3 / `인터페이스:ERP-결의서전송` unregistered. `unregisteredTypes: [{ type: "인터페이스" }]`. `together` — `이슈:ISS-007` 에 사전조사 · 방향결정, `인터페이스:ERP-결의서전송` 에 방향결정.

```
work({ repo: "alpha", id: "2026-0901-ERP-연계-사전조사" })
work({ repo: "alpha", id: "2026-0903-ERP-전문규격-초안" })
work({ repo: "alpha", id: "2026-0908-ERP-연계방식-결정" })
```

오래된 것부터 읽는다. 사전 조사는 두 방식의 장단 · 초안은 전문 필드 32개 표 · 결정은 「DB 직접 연계 · 파일 연계는 야간 배치가 늦어 버림 · 오류 시 재전송 3회」. 이슈 섹션은 지금 일지형이다(덩어리 둘 · 진행상태 처리중).

## ④ 판정 · 서식

인터페이스 문서가 없다 — 서식을 찾는다.

```
forms({ repo: "alpha", q: "인터페이스" })
forms({ repo: "alpha", form: "public-si/DE_501" })
```

`kind: 대상` · `registry` 제안 `인터페이스:*` · guide 의 「여기 적지 않는 것」 — 연계 결정의 경위는 작업 기록 · 진행 중인 물음은 이슈. 기록이 쓴 타입도 `인터페이스` 라 그대로 쓴다.

| 기록 | 판정 | 왜 |
|---|---|---|
| 사전 조사 | keep | 두 방식의 비교는 경위다 — 결론은 결정 기록에 있다. 이슈에도 남길 것이 없다 |
| 전문 규격 초안 | new → 인터페이스 · 이슈 | 규격의 정본 자리 — 새 문서로 세운다. 이슈에는 경과 한 줄 |
| 방향 결정 | reflect → 인터페이스 · 이슈 · 아키텍처 | 방식 · 재전송 규칙은 인터페이스에(정본) · 이슈는 결론 한 줄로 닫는다 · 아키텍처는 구성 한 줄 |

판정은 기록 단위라 기록마다 `touches` 를 다 본다 — 초안이 건드린 이슈도 `into` 에 넣었다(빼면 그 기록은 이슈에서 미반영이 아니게 되는데 판정표에 까닭이 없다).

## 충돌이 났다면

⑦ 에서 `시스템아키텍처:link` 가 `E_CONFLICT` — 그 사이 다른 큐레이터가 그 섹션에 다른 기록을 반영했다(`detail.current` 가 내가 읽은 applied 와 다르고 `detail.currentWork` 가 그 기록이다). `detail.content` 위에 내 한 줄을 다시 얹고 `applied` 에 `detail.current` 를 넣는다. `work({ id })` 로 묶음 A 의 기록들이 아직 `queued` 인지 본다 — 그대로면 dryRun 부터 다시 보이고 승인받는다.
