# cdp-seed — 문서 레포에서 지식 레포를 세운다

```
① 지도     ctx seed init 뼈대 → 문서마다 분류 · 좌표 · 서식 · 종류 · 기록 날짜 · touches 를 판단해 고친다
② 검사     ctx seed check — 오류 0 · 지도에 없는 md 0
③ 미리보기  ctx seed plan — 전 단계 dryRun. 표를 보이고 승인
④ 세우기   ctx seed apply — 기준선 → 관리 문서 → 기록. 세우는 흔적은 기록이 아니라 _seed.json 하나
⑤ 읽기     cdp-curate — 세운 기록을 묶음마다 읽어 원천의 어긋남(작업문서에만 · 모순 · 늦음)을 찾는다
⑥ 대조     ctx seed verify — 같음 · 형식 차이 · 확인 필요 · drift. 확인 필요는 원인을 가린다
⑦ 넘기기   정본이 둘이면 문서 레포의 작업 규칙에 「고쳤으면 cdp-save」 한 줄 · 큐레이터는 주 1회 ctx follow
```

**큐레이터만 쓴다.** apply 는 서버 save 를 큐레이터 토큰(`CDP_TOKEN`)으로 부른다. 원천 문서 레포에는 쓰지 않는다 — 지도 파일(`cdp-sources.json`)만 그 레포에 둔다(그 레포의 사람이 커밋한다).

**기계는 옮기기만, 판단은 사람과 이 세션.** apply 는 원문을 그대로 옮긴다. **세우는 흔적은 작업 기록이 아니다**(문서레포 세우기 검토 S13) — 이관 · 기준선 · 스냅샷 기록을 남기지 않고 레포 뿌리의 `_seed.json`(`{ at, from, records, sections }`) 하나를 쓴다. 함께 들인 기록은 판정 없이 반영됨(원천 문서가 이미 싣고 있다) · 세운 섹션의 근거는 원천(`from`)이다. 이력은 git 에.

## ① 지도 — `cdp-sources.json`

```
ctx seed init --from <문서 레포> [--root <문서 폴더>]
```

뼈대는 짐작이다(헤딩 모양 · 폴더 이름). **분류는 문서를 읽고 판단한다:**

| 무엇 | 어디로 | 판단 |
|---|---|---|
| 대상의 **지금**(정의서 · 규격 · 설계 · 대장 · 용어 · 범위) | `docs[]` — 관리 문서 | 「초안」 · 「v0.1」 이라는 이름은 미정이 아니다 — 지금 쓰는 기준이면 섹션이다 |
| 그 시점의 **판단**(조사 · 분석 · 검토 · 회의록 · 질의서 · 보고 · 제안) | `records[]` — 작업 기록 | 결론은 관리 문서에 이미 있고 원문은 근거로 남는다. 상대에게 낸 제안 · 회신 대기는 기록(판정은 ⑤ 에서 대기로) |
| 정리 기록 · 진행 중 체크리스트 · 표 원본(xlsx) | `ignore[]` 또는 지도 밖 | 링크는 글자로 남는다 |
| 같은 기록의 다른 판(축약본) | `alias` | 링크만 그 기록으로 |
| 문서 끝의 「부록 · 작업 기록」 섹션 | `records[]` 의 `from: <문서 key>` | 섹션에서 빼고 기록으로 |

문서마다 —

- `split` — `h2`(`## 값 — 설명` 하나가 좌표 하나) · `whole`(문서 전체가 좌표 하나 — `coord`) · `chapters`(`## n. 제목` → `chapters[n-1]` 값 · 머리는 `preamble` 섹션). 150줄을 넘는 섹션이 많고 자주 바뀌는 설계서는 `chapters` 가 낫다 — 미반영 · 주입이 장 단위가 된다. 판 단위로 바뀌는 계약(규격 · API)은 `whole`.
- `type` — 좌표 타입. 레포의 다른 문서 · 기록이 부를 이름으로. 서식(`forms`)의 `registry` 가 제안이다.
- `form` — 서식집의 id(`forms({ q })`). 맞는 서식이 없으면 `title` 과 `kind`(대상 · 대장 · 정의 · 사건 · 서술) — 종류가 drift 의 비대 잣대다.
- `aliases` · `chapterAliases`(`"설계 §{n}"`) — 다른 문서가 부르는 말. alias 는 주입의 단일 실패점이다.
- `figs`(그림 폴더) · `attach`(파일 — pdf · html) · `baseline`(DB · 코드에서 뽑은 문서면 출처 한 줄 — 기준선 블록으로).

기록마다 — `id`(`YYYY-MMDD-<주제>`) · `date`(**그 판단의 날** — 파일 첫 커밋 · 본문의 작성일) · `touches`(**그 기록이 바꾼 좌표만** — cdp-save ② · `@<문서 key>` 는 그 문서의 좌표 전부) · `attach` · `attachDir`.

`intent` — 세운 뒤 위키에서 일부러 모양을 바꾼 좌표(대장 경위 이관 등)와 까닭. verify 가 「형식 차이」 로 센다.
`target` — `{ server, repo }` 를 적어 두면 명령마다 `--server · --repo` 를 안 쓴다.
`skip` — `{ "<커밋 sha>": "<까닭>" }` · `ctx follow` 가 세지 않는 커밋(원천을 위키에 맞춘 커밋 · 운영자가 기록을 두지 않기로 한 커밋). 까닭은 꼭 적는다 — 누락을 숨기는 칸이 아니다.

## ② ~ ④ 검사 · 미리보기 · 세우기

```
ctx seed check --from <문서 레포>                         # 오류 0 · 경고(지도에 없는 md · 모르는 touches)를 본다
ctx seed plan  --from … --server … --repo …               # 전 단계 dryRun — 기록은 「앞 단계 뒤에 통과할 것」 이 정상
ctx seed apply --from … --server … --repo … [--date <이관 날>]
```

plan 의 표(문서 · 섹션 수 · 기록 수 · 첨부 · 글자로 남는 링크)를 사람에게 보이고 승인받은 뒤 apply. 반쯤 멈추면 같은 명령을 다시 — 이미 있는 문서 · 기록은 건너뛴다(멱등). 단계만 다시 하려면 `--stage baseline|managed|snapshot|records` · 하나만 `--only <key|id>`.

기록 파일은 편입한 판단 기록만 생긴다. 구조(등록부 · 어휘 · 섹션 `applied: null` · 첨부)는 기록 없이 커밋되고, 좌표가 `_seed.json` 의 sections 에 붙는다.

## ⑤ 읽기 — cdp-curate

세운 기록은 반영됨이라 대기열은 0 이다. 그래도 한 번은 읽는다 — 원천의 어긋남은 기록과 섹션을 견줘야 드러난다. cdp-curate 로 묶음(같은 좌표 · 같은 주제 · 섹션 50 이하)마다 기록을 읽어 —

- 사실이 섹션에 있으면 할 일이 없다(판정을 새로 남기지 않는다 — 세운 기록은 이미 반영됨).
- **기록에 있는데 섹션에 없는 사실** — 원천 안에서 산출물로 안 올라간 것이다(작업문서에만). 반영하고 판정표에 적는다.
- **산출물끼리 모순 · 늦음** — 섹션을 지금으로 고치고 판정표에 적는다. 정본이 둘이면 원천 쪽도 바로잡게 사람에게 알린다.
- 고칠 것이 있으면 그 묶음의 큐레이션 save(판정이 seeded 를 덮는다). 회신 대기 제안을 세운 기록에서 빼고 대기로 두려면 지도의 records 에서 빼고 따로 cdp-save 로 들인다 — 사람이 정한다.
- 대장 섹션이 비대하면 cdp-rebuild ④ 경위 이관.

## ⑥ 대조 — verify

```
ctx seed verify --from <문서 레포> --clone <지식 레포 클론(pull 해 둔 것)>
```

| 줄 | 뜻 | 할 일 |
|---|---|---|
| 같음 | 섹션 = 원천(링크 대상 · 경과 · 공백은 견주지 않는다) | — |
| 형식 차이 | `intent` 에 적은 좌표 | — |
| 확인 필요 | 원천이 나중에 바뀌었는데 기록이 없다(늦음 — `ctx follow`) · 큐레이션이 원천과 달리 고쳤다 · 틀림 | 까닭을 가려 `intent` 에 적거나 원천을 바로잡거나 기록으로 메운다 |
| drift | 근거 없음 0 이 정상 | cdp-rebuild |

## ⑦ 정본이 둘일 때 — 따라가기

원천 문서 레포를 계속 쓰면(정본 둘) 위키는 **기록으로만** 따라간다 — 큐레이터가 원천의 diff 를 보고 섹션을 고치지 않는다(「왜」 가 빠진 손 미러가 된다).

- 원천을 고친 세션은 작업 끝에 cdp-save 의 보통 기록 하나(「원천 문서 레포를 고쳤으면」 — 바꾼 좌표 · 왜 · `source` 에 커밋). writer 는 ctx 를 부르지 않는다 — 공식 도구(MCP)만 쓴다. 그 레포의 작업 규칙(CLAUDE.md)에 한 줄 넣어 둔다.
- 큐레이터는 주 1회 `ctx follow --from … --clone … --since <지난 점검 sha>` — 누락이 있으면 큐레이터가 그 커밋 범위로 `ctx update` 초안(바뀐 좌표 · 바뀐 줄)을 만들어 「왜」 를 아는 사람에게 묻고 남긴다. `ctx update` 는 큐레이터의 메우기 도구다. 누락 비율이 따라가기의 잣대다.

## 하지 않는 것

| | 어디로 |
|---|---|
| 기록 판정 · 섹션 다시 쓰기 | cdp-curate · cdp-rebuild |
| 원천 문서 레포 고치기 | 그 레포의 사람(작업 세션) |
| xlsx · hwp · pptx 내용 옮기기 | 첨부까지만 — 내용은 사람이 md 로 |
| 옛 지식 레포를 기록만으로 다시 세우기 | admin — `ctx repo new --records-from` |
