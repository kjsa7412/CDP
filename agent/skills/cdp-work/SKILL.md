# cdp-work — 요청 하나를 검토 · 주입 · 수행으로

```
① 검토   요청을 이해하고 대상을 뽑는다 — match · where · search. 관리 문서 · 작업 기록 본문은 아직 안 읽는다
② 주입   대상의 지금을 읽는다 — section 한 번이 섹션 · 미반영 기록 · 건 정본 · 기준선을 같이 준다
③ 수행   주입한 것을 근거로 요청을 한다. 미반영이 실려 왔으면 답에 적는다
```

**요청된 작업이 우선이다.** 절차는 그것을 돕는다 — 절차가 산출물이 되면 실패다. 순서를 바꾸거나 건너뛰지 않는다.

## 준비

- 도구는 MCP `cdp` 서버의 것이다. 안 보이면 연결이 없는 것이다 — 기억으로 답하지 말고 그렇게 말한다(작업 레포에서 설치 한 줄을 다시 돌린다).
- 레포는 작업 레포 `.claude/cdp.json` 의 `repo` 다. 모르면 `match` 를 `repo` 없이 부른다 — 결과의 `repo` 를 이후 도구에 그대로 넘긴다. 두 레포에 다 걸리면 둘 다 보고한다(고르지 않는다 · 한 답에 섞지 않는다).
- 세션 처음에 한 번 `brief({ repo })`. `[CDP]` 경고 줄(레포 어긋남 · 미러 · 번들 나이)은 답에 그대로 옮긴다. `큐레이션 대기 n` · `미반영 섹션 n` 은 이 레포에서 반영을 기다리는 기록 · 섹션의 수다.
- `derive` · `apply` · `sync` · `version` 도구는 부르지 않는다 — v1.0 에서 빠진다. 그 일은 `section` · `brief` 가 한다.

## ① 검토

1. **요청을 한 줄로 요약한다.**
2. **대상 후보를 뽑는다** — 요청문 · `git diff` · 열린 파일에서 테이블명 · 화면 코드 · API 경로 · 모듈명 · 도메인 용어 · 코드그룹.
3. **이름을 정본 좌표로 대조한다.**

   ```
   match({ repo, names: ["면접심사의견등록", "HR130", "서류심사"] })
   ```

   | 답 | 뜻 |
   |---|---|
   | `coord` · `matchedBy`(이름 · 값 · alias) | 정본 좌표. alias 로 걸렸으면 정본으로 바꿨다고 적는다 — 안 적으면 사람이 그 이름을 정본으로 안다 |
   | `coord: null` (미등재) | 어휘에 없다. 다른 좌표로 바꾸지 말고 그대로 적고 5번으로. `where` 로 확인하지 않는다 — 등록부 패턴으로 계산한 자리를 내어 등재된 것처럼 보인다 |
   | `deprecated` · `successor` | 폐기 좌표 — 후속 좌표를 쓴다 |
   | `docs` | 좌표가 아니라 문서 이름이다 — 필요하면 ② 에서 `docs({ doc })` |

   **타입 이름을 짐작하지 않는다.** 예시의 `screen:` · `code:` 는 설명용이다 — 타입은 그 레포의 `_vocab.md` 가 정한다(`화면설계서:HRC043` 처럼 한글 타입을 쓰는 레포도 있다).

4. **좌표인지 판정한다.**

   | 이 작업이 그 대상을… | 좌표 |
   |---|:--:|
   | 신설 · 변경(컬럼 추가 · 규격 변경 · 상태값 추가) · 삭제 · 폐기한다 | **O** |
   | 참조 · 호출 · 언급만 한다 · 그것을 쓰는 다른 것을 만든다 | **X** |

   기준은 하나다 — **6개월 뒤 그 대상을 맡은 사람이 이 작업을 찾아야 하는가.** 「주제인가」 는 답이 갈리지만 「바꾸는가」 는 결판난다.

5. **미등재가 나온 말은 `search` 로 넓힌다.**

   ```
   search({ repo, words: ["지출결의서"] })
   ```

   `match` 는 이름 · alias 만 본다 — 등재가 얇으면 요청의 핵심 명사가 전부 미등재로 떨어지고, **답을 가진 섹션이 레포에 멀쩡히 있는데도 빈손으로 돌아온다.** 실제로 「결의서 결제수단 디폴트」 요청에서 코드값 셋만 걸렸고 답은 `api:/adapter/erp/expense-slip` 섹션에 있었다. `search` 는 좌표 이름만 준다(본문을 싣지 않는다). 후보에도 4번 판정을 한다 — 후보를 그대로 다 주입하지 않는다.

6. **주입할 좌표를 정하고 자리를 본다.** 주입할 것은 **지금 상태를 모르면 요청을 할 수 없는 대상**만이다 — 많이 넣을수록 요청의 해석이 그 맥락에 끌려간다. 애매하면 넣되 후보를 늘리지 않는다.

   ```
   where({ repo, coord: "screen:HRC043" })
   ```

   `section` 의 `doc` · `anchor` · `line`~`end`(크기) · `state`(`ok` · `pending` · `missing`) · `pending`(미반영 수) · `works`(그 좌표를 건드린 기록, 최신순) · `registry: null`(관리 문서가 없는 타입 — 정상이다).

### 이미 정해진 것인지 본다

`where` 의 `works` 를 본다 — id 가 `날짜-주제` 라 **id 만으로 주제가 읽힌다.** 요청과 겹치는 것이 있으면 검토에 적고 ② 에서 `work({ repo, id })` 로 읽는다. 답은 「새로 정하자」 가 아니라 **「이미 이렇게 정해져 있다 — 이번 요청과 다른 것은 이것뿐이다」** 로 시작한다. 같은 요청이 두 번 왔고 첫 기록의 id 가 검토에 떠 있었는데 아무도 읽지 않아 처음부터 다시 정한 일이 있었다.

### 출력 — 【검토】

```
【검토】
요청  HRC043 면접심사의견등록에 심사위원 연대서명 출력물을 추가한다

대상
  screen:HRC043   변경   출력물 2종 추가
  code:HR130      ?      업무구분 코드를 쓸지 미정
  screen:HRC031   참조   첨부를 읽어 오지만 안 바뀐다 → 좌표 아님

주입  2건 — 좌표마다 섹션 하나와 그 미반영 기록
  screen:HRC043   docs/화면설계서.md ## HRC043 · 22줄 · 미반영 1건
  code:HR130      docs/코드정의서.md ## HR130 · 9줄 · 반영 최신
이미 정해진 것  2026-0821-면접심사의견-개편 — 같은 화면의 출력물을 정했다
```

- **좌표가 아닌 것도 적는다** — 무엇을 왜 뺐는지가 판정의 근거다. 애매하면 `?` 로 두고 단정하지 않는다.
- **주입 범위를 적는다** — 문서 · 섹션 앵커 · 크기 · 상태. 좌표 이름만 늘어놓으면 「그 좌표에 관한 것이 전부 들어온다」 로 읽힌다.
- 주입할 것이 없으면 `주입  없음` 한 줄.

### 금지 · 압축

- **이 단계에서 본문을 읽지 않는다** — `section` · `work` · `docs({ doc })` 는 ② 의 것이다. 어휘 · 등록부 · `where` · `search` 는 이름표라 요청 해석을 끌어가지 않지만, 관리 문서와 작업 기록은 의견을 담아 요청을 그 틀로 읽게 한다.
- **검토를 낸 뒤 멈추지 않는다** — 승인을 구하지 말고 ② 로 간다. 판정이 틀렸으면 ③ 의 답에서 드러나고 사람이 고친다. 모든 요청에 정지를 거는 비용이 잘못된 주입의 비용보다 크다.
- **길게 쓰지 않는다** — 검토가 답보다 길면 절차가 일을 잡아먹은 것이다.

| 상황 | |
|---|---|
| 대상이 이미 명시됐다(「HRC043 화면에…」) | 대상 한 줄로 |
| 좌표 후보가 0개 | `주입  없음` 만 적고 ③ |
| **요청이 크고 모호하다**(「채용 쪽 정리해 줘」) | **되묻고 멈춘다** — 맥락 문제가 아니라 요청 문제다 |

## ② 주입 — `section` 한 번

```
section({ repo, coord: "screen:HRC043" })
```

| 받는 것 | 뜻 |
|---|---|
| `content` | 큐레이터가 쓴 정본 서술 — 헤딩 · applied · 기준선 블록을 뺀 본문. **반영한 데까지의 지금** |
| `baseline` | 기준선 — 코드 · DB 에서 기계로 뽑은 블록(`src` 어디서 · `asof` 언제). 컬럼 · 타입 같은 사실 값의 근거 |
| `state` | `ok` · `pending` · `missing` — 아래 |
| `pending` · `pendingRecords` | 섹션 뒤에 그 좌표를 건드린 **미반영 기록** — 목록과 본문(오래된 순) |
| `refs` | 본문이 `` `좌표` `` 로 건 정본 섹션 — 한 단계 · 5개까지. 그 사실의 정본은 거기다 |
| `applied` | 마지막으로 반영된 기록 |
| `truncated` · `pendingOmitted` | 잘렸다 · 안 실은 미반영이 n건 더 있다 |

| `state` | 뜻 | 답에 |
|---|---|---|
| `ok` | 섹션이 지금이다 | — |
| `pending` | 섹션은 큐레이터가 반영한 데까지만 지금이다. 그 뒤 기록이 `pendingRecords` 로 실려 왔다 | **미반영을 적는다** — 어느 기록(id · 날짜 · 작성자)이 무엇을 바꿨나. 섹션과 어긋나면 늦은 기록이 지금이다 |
| `missing` | 섹션이 없다(`reason`: unregistered · doc-missing · anchor-missing) | 미반영 기록이 실려 왔으면 그것이 유일한 근거다. 아무것도 없으면 「문서에 없다 — 코드에서 읽어야 한다」 |

**보증은 도구가 한다.** 미반영 기록을 찾으러 `work` 를 돌지 않는다 — `section` 이 이미 실었다. 할 일은 실린 것을 답에 옮기는 것 하나다. 빠뜨리면 큐레이터가 반영하기 전까지 그 결정은 없는 것처럼 읽힌다.

- **빈 섹션을 조용히 쓰지 않는다** — `content` 가 비었거나 사실상 비어 있으면 그대로 말한다. 밝히지 않으면 「정의가 없다」 가 「제약이 없다」 로 읽혀 확신 있게 틀린 답이 된다.
- **`refs` 를 따로 다시 찾지 않는다** — 정본이 한 단계 같이 왔다. `truncated` 면 그 좌표를 `section` 으로 한 번 더.
- **기준선의 `asof` 가 오래면** 답에 그 날짜를 적는다 — 그 뒤 바뀐 것은 블록에 없다.
- **등록부에 없는 타입**(`registry: null` — `module:` · `domain:` 류)은 관리 문서가 없는 것이 정상이다. 작업 기록이 근거다 — `where` 의 `works` 최신 3건까지 `work({ repo, id })` 로 읽고, 더 있으면 「n건 중 3건」 이라 적는다.
- **문서를 통째로 읽지 않는다** — 테이블정의서 하나에 테이블이 수십 개다. 등록부 밖 문서(회의록 같은 날짜축)나 머리말이 필요할 때만 `docs({ repo, doc })`.

### 범위를 밝힌다

주입 단위는 **섹션 하나 + 그 섹션의 미반영 기록 + 건 정본**이다. 그 문서의 다른 섹션도, 이미 반영된 옛 기록도 안 들어온다. 답에 범위를 적어 「그 좌표의 전부」 로 읽히지 않게 한다.

작업 기록을 근거로 쓸 때는 **좌표별로 판정한다.** 한 기록에 좌표가 여럿이고 좌표마다 그 뒤 사정이 다르다 — 문서 단위로 「덮였다」 고 하지 않는다. 「후속이 있다」 를 「뒤집혔다」 로 쓰지 않는다 — 아는 것만 말한다.

## ③ 수행

주입된 상태를 근거로 요청을 한다. 산출물의 모양(코드 · 답 · 분석)은 요청이 정한다. 지킬 것 셋 —

1. **주입된 것을 근거로 쓴다.** 섹션 · 미반영 기록과 어긋나게 설계하지 않는다 — 어긋나야 하면 왜인지 적는다.
2. **미반영 · 잘림 · 빈 섹션 · 오래된 기준선을 답에 옮긴다.**

   ```
   ⚠ screen:HRC043 섹션 뒤에 미반영 기록 1건 — 2026-0905-HRC043-출력물(dev.b): 출력물을 PDF 한 종으로 고정.
     아래 설계는 섹션과 그 기록을 합친 상태가 기준이다. 큐레이터가 반영하면 섹션에 들어간다.
   ```

3. **「왜」 가 필요해지면 그때 기록을 연다** — 「이 컬럼이 왜 nullable 이지」 가 생기면 섹션 끝 `**경과**` 줄이 어느 기록을 볼지 알려 준다. `work({ repo, id })`. ② 에서 미리 다 읽지 않는다.

관리 문서를 고치는 것은 이 세션의 일이 아니다 — 섹션이 틀렸거나 바꿀 것이 생기면 그 내용을 기록으로 남긴다(cdp-save). 큐레이터가 반영한다.

## 다시 부르지 않는 경우 · 끝나면

- **주제가 그대로면 다시 부르지 않는다** — 이미 주입한 맥락을 쓴다. 매 턴 부르면 같은 섹션이 되풀이되고 절차가 소음이 된다. 다른 화면 · 다른 테이블로 넘어갈 때 다시 부른다.
- **이 스킬은 기록하지 않는다.** 요청 여럿이 한 작업일 수 있다 — 작업이 끝나면 `cdp-save` 를 **한 번** 부른다.

```
요청 1 → cdp-work ─┐
요청 2 → cdp-work ─┼→ 작업 하나 → cdp-save 한 번 → 기록 하나
요청 3 → (이어서) ─┘   같은 좌표면 ② 는 이미 주입돼 있다
```

## 부르지 않는 요청

「이 정규식이 왜 안 먹지? `^[A-Z]{3}\d{3}$`」 — 지식 레포와 무관하다. 그 정규식이 `screen:BZD020` 의 코드 안에 있어도 화면 사양을 바꾸는 것이 아니다. **억지로 좌표를 붙이지 않는다.**
