# cdp-save — 작업 기록 하나를 남긴다

```
① 길       이 세션의 작업 · 밖에서 온 문서(편입) · 문서를 고치라는 지시
② 좌표 판정  이 기록이 바꾼 · 정한 · 정의한 · 제기한 대상만
③ 기록     기록은 홀로 선다 — 값 · 표 · 결정 · 제약은 본문에
④ 승인     【좌표 판정】 과 기록을 보이고 승인을 받는다 — 필수
⑤ save     work · vocab · assets 한 번. 서버가 검사 · 커밋 · 미러한다
⑥ 끝 보고   커밋 · 미러 · 큐레이션 대기 n번째
```

**쓰는 것은 작업 기록뿐이다.** 관리 문서는 레포의 큐레이터가 반영한다 — 이 기록은 큐레이션 대기열에 서고, 반영되기 전까지 그 좌표의 `section` 이 섹션 옆에 이 기록을 같이 낸다. 그래서 늦은 반영이 정보를 잃지 않는다 — **이 기록이 홀로 서 있기만 하면.**

**요청 하나가 작업 하나가 아니다.** 요청 셋이 한 작업이면 기록은 하나다. 요청마다 기록하면 이력이 파편화되고, 큐레이터는 같은 좌표의 조각 여럿을 맞춰야 한다.

## 준비

- 레포는 작업 레포 `.claude/cdp.json` 의 `repo`(서버 주소는 `server`)다. `save` 에 **반드시** 넣는다 — 쓰기에서 기본값은 사고다.
- 처음 한 번 `brief({ repo })` — 이 연결(`.mcp.json`)의 기본 레포와 다르다는 `[CDP]` 줄이 붙으면 사람에게 그대로 전한다(설치 한 줄을 다시 돌리면 맞춰진다).
- `save` 가 `E_FORBIDDEN` 「쓰기 권한이 없다」 를 내면 읽기 전용(viewer) 토큰이다 — 남기려던 기록을 정리해 보이고 멈춘다(관리자에게 writer 권한을 청한다). `save` 가 아예 안 보이면 연결이 없는 것이다.

## ① 길 셋

| 길 | 언제 | 다른 점 |
|---|---|---|
| **이 세션의 작업** | cdp-work 로 한 일이 끝났다 | 본문을 새로 쓴다 — 무엇을 · 왜 · 어떤 제약 때문에 · 결과 값 |
| **편입** | 「이 회의록 레포에 넣어 줘」 · 「예전 검토서를 옮겨 줘」 | 원문을 보존하고 프론트매터만 씌운다 · `date` 는 사건의 날 · `source` 에 출처 · 문서 성격부터 가른다 — **[편입.md](편입.md)** |
| **문서 수정 지시** | 「화면설계서 BZD020 첨부 용량을 10MB 로 고쳐 줘」 — 코드 없이 문서만 바꾸라는 지시 | **지시 자체가 기록이다** — 아래 「문서 수정 지시」 |

- **끝나지 않은 작업은 아직 쓰지 않는다.** 작업 기록은 작업의 완료에서 나온다 — 상태(`status`) 필드는 없다(적으면 검사가 막는다). 끝나지 않은 것을 기록하면 레포가 할 일 목록 노릇을 하기 시작한다.
- **결정이 안 난 것은 결정으로 쓰지 않는다** — 아래 「결정이 안 났으면」.

## ② 좌표 판정

**이 기록이 바꾼 것만이다.**

| 이 기록이 그 대상을… | 좌표 |
|---|:--:|
| 신설 · 변경(컬럼 추가 · 규격 변경 · 상태값 추가) · 삭제 · 폐기했다 | **O** |
| (편입 · 지시) 신설 · 변경 · 폐기하기로 **정했다** | **O** |
| 용어 · 개념을 **정의했다 · 레포에 처음 도입했다** | **O** |
| 답이 안 난 것을 이슈로 **제기했다** | **O** |
| 참조 · 호출 · 언급 · 예로 들었다 · 그것을 쓰는 다른 것을 만들었다 | X |
| 「검토하기로 했다」 | X — 아직 안 정해졌다. 제기로 |

기준은 하나다 — **6개월 뒤 그 대상을 맡은 사람이 이 기록을 찾아야 하는가.** **억지 좌표는 없는 좌표보다 나쁘다** — 그 좌표를 찾는 사람에게 무관한 기록을 내민다. 반대로 **빠진 좌표는 조용하다** — 서버는 0개만 막고, 하나라도 있으면 나머지가 빠져도 통과한다. 큐레이터도 `touches` 로 반영할 자리를 찾는다. 빠진 것을 잡는 것은 승인하는 사람뿐이다.

- **정규화** — `match({ repo, names })`. 이름 · alias · 오타가 섞인 말을 정본 좌표로. 폐기 좌표(`deprecated`)면 `successor`(사슬이면 `successorLatest`)를 쓴다. 이미 있는 좌표를 `vocab` 에 보내면 건너뛰고 `vocabSkipped` · 경고로 온다 — label · alias 고치기 · 폐기 · 이름 바꾸기는 큐레이터의 일이다(요청문을 남긴다).
- **미등재(`coord: null`)는 등재 후보다** — 「레포와 관계없는 말」 이 아니다. 이 기록이 바꾸거나 정의한 대상이면 `vocab` 에 같이 보낸다. 이름은 `_vocab.md` 의 명명 규약을 따르고(`docs({ repo, doc: "_vocab.md" })`), 규약이 없는 타입이면 【좌표 판정】 에 「이름 제안」 으로 표시한다. 원문 · 구어 표기는 `aliases` 에 — alias 가 있어야 남이 자연어로 물어도 걸린다.
- **새 타입** — `vocab` 의 타입 섹션이 없으면 서버가 만든다(경고). 오타로 만들면 지우는 연산이 없으니 【좌표 판정】 에 「새 타입」 으로 올려 승인받는다.
- **`where` 의 `registry: null`** — 관리 문서가 없는 타입이다. **`touches` 가 그 좌표로 닿는 유일한 길이다** — 「채울 섹션이 없으니 좌표가 필요 없다」 가 아니다. 새 타입이 여럿으로 자라면 본문 끝에 「큐레이터에게 — <타입> 좌표 n개를 받을 관리 문서가 없다」 한 줄을 남긴다. 문서는 큐레이터가 세운다.
- **0개면 멈춘다** — 「이 기록은 어떤 좌표로도 찾을 수 없게 됩니다」 를 알리고 묻는다. 먼저 판정을 의심한다(정의한 용어를 전부 「설명」 으로 뺐나 · 바꾼 대상을 「참조」 로 뺐나). 사람이 0개를 승인하면 `touchesEmpty` 에 사유를 적는다 — 없으면 서버가 `E_INPUT` 으로 거절한다.
- **본문에만 쓴 좌표** — 본문에 `` `type:값` `` 으로 쓴 좌표가 `touches` 에 없으면 검사가 경고한다. 참조만 한 것이면 그대로 두고, 바꾸거나 제기한 것이면 넣는다.

## ③ 기록

### 기록은 홀로 선다

큐레이터는 **이 기록만 보고** 섹션에 반영하고, 반영 전까지 읽는 사람은 섹션 옆에 실린 **이 본문**을 본다. 둘 다 이 세션의 기억 · DB · 코드에 닿지 못한다.

| 본문에 쓴다 | 쓰지 않는다 |
|---|---|
| **값** — 컬럼 · 타입 · 길이 · 코드값 · 규격 · 기본값 · 한도 | 「섹션 X 참조」 · 「DB 에서 확인」 · 「코드를 보면 안다」 |
| **표** — 정한 값의 표 그대로 | 「기본값 표를 정했다」 (값 없는 사건) |
| **결정과 제약** — 무엇을 왜 · 어떤 제약 때문에 · 버린 안과 버린 이유 | 경위만 길게 · 누가 언제 물었나만 |
| **예외 · 남은 것** — 회신 대기 · 열린 물음(따로 한 절) | |

실제로 이렇게 샜다 — 결제수단별 기본값 표를 정한 기록이 「기본값이 여기서 정해진다」 만 남겼고, 같은 요청이 다시 왔을 때 이미 정한 값을 처음부터 다시 정했다.

- **큰 추출물은 첨부다** — DDL 전문 · 덤프 · 긴 목록 · 화면 캡처 · 구성도는 본문을 채우지 않는다. 바뀐 값의 요지는 본문 표로, 전문은 `assets` 로 — 올리기 · 링크 · HTML 시각 자료는 **[첨부.md](첨부.md)**. DB · 코드에서 정기적으로 기계로 뽑는 것이면 그것은 기준선 생성기의 일이다(큐레이터 · 관리자에게).
- **이유가 안 보이면 한 번 묻는다** — 「이 판단의 제약이 뭐였나요?」 한 번만. 답이 없으면 그대로 쓴다 — 캐물으면 기록 자체를 안 하게 된다. 6개월 뒤 이 결정을 뒤집으려는 사람은 「무엇을 했는지」 가 아니라 「어떤 제약 때문에」 를 찾는다.

### 필드 — `work`

| | |
|---|---|
| `id` | `YYYY-MMDD-slug` — 날짜와 짧은 주제. id 만으로 주제가 읽혀야 한다. 이미 있으면 `E_EXISTS` |
| `title` | 무엇에 관한 기록인지 보이게. 따옴표는 서버가 붙인다 |
| `date` | `YYYY-MM-DD HH:MM` — **시각까지.** 하루에 같은 좌표를 두 번 건드려도 선후가 결판난다. 편입 · 지시는 그 사건의 때 |
| `touches` | ② 의 결과 |
| `touchesEmpty` | 0개를 승인받았을 때만 — 사유 |
| `source` | 편입일 때만 — 원문이 어디서 왔나. 되짚을 유일한 길이다 |
| `supersedes` | **이 기록 자체가 틀렸을 때만** — 아래 |
| `tags` | 자유. 단 `curate` · `baseline` · `registry` · `docs-prune` · `derive` 는 큐레이터 몫이다(보내면 `E_FORBIDDEN`) |
| `body` | 마크다운 — 홀로 서는 본문 |

`author` 는 보내지 않는다 — 서버가 토큰에서 채운다. 원문 작성자 · 지시한 사람은 본문에 적는다.

### 오기재는 정정 기록으로

기록은 불변이다 — 고치거나 지우는 길이 없다. 틀렸으면 `supersedes: <틀린 기록 id>` 를 단 새 기록을 낸다. **좌표 누락도 오기재다** — `id` 는 `<원 id>-좌표정정` · `title` 은 `[정정] <원 제목> — 좌표 보완` · `date` 는 **원 기록의 날**(오늘이면 그 사이 같은 좌표의 기록과 선후가 뒤집힌다) · `touches` 는 빠졌던 좌표만 · 본문은 무엇이 왜 빠졌나와 원 기록 링크(원문을 다시 싣지 않는다).

같은 좌표를 나중에 또 바꾼 것은 `supersedes` 가 아니다 — 날짜와 `touches` 로 계산된다. 손으로 관계를 걸면 곧 어긋난다.

## 문서 수정 지시 — 지시가 곧 본문이다

1. **고칠 자리를 읽는다** — `section({ repo, coord })`. 미반영 기록이 실려 오면 그것까지가 지금이다. 등록부 밖 문서 · 머리말은 `docs({ repo, doc })`.
2. **어긋나면 되묻는다** — 지시가 지금 섹션 · 미반영 기록과 다르면 무엇이 맞는지 묻는다. 그렇게 정한 이유가 섹션이나 기록에 적혀 있으면 인용해 보인다 — 「'선택' 으로 정한 이유가 적혀 있습니다 … '추가' 로 되돌리는 것이 맞습니까?」. 좌표를 특정하지 않으면 `match` 후보를 보이고 고르게 한다. 사실관계를 모르면 묻는다 — 문서는 정본이라 틀리면 조용히 퍼진다.
3. **기록을 쓴다** — 세 대목.

   | | |
   |---|---|
   | **지시** | 말한 그대로 인용한다 — 요약하지 않는다. 「WAS 업로드 상한이 그거라서 20MB 로 적어 놔도 어차피 안 올라가」 가 제약의 출처다. 「10MB 로 변경」 으로 줄이면 6개월 뒤 「왜 10인가」 에 답할 수 없다 |
   | **바꿀 것** | 어느 문서 · 어느 섹션의 무엇을 어떻게 — 큐레이터가 이것만 보고 반영할 수 있게 **값까지** |
   | **확인한 것** | 되물은 것 · 근거를 본 것 · 지금 문서에 적힌 값과 그 출처 |

   `touches` 는 바꿀 좌표 · `date` 는 지시받은 때 · 지시한 사람은 본문에. 그림을 넣으라는 지시면 그림을 첨부로 올리고 「바꿀 것」 에 넣을 자리를 적는다.
4. **「어떨까?」 는 지시가 아니다** — 결정이 아니므로 아래로.

반영은 큐레이터가 한다. 끝 보고에서 「문서를 고쳤다」 고 하지 않는다 — **「고칠 것을 기록했다 · 큐레이터가 반영한다 · 그동안 섹션을 읽는 자리에 이 기록이 같이 실린다」.**

## 원천 문서 레포를 고쳤으면 — 보통 기록 하나

지식 레포가 기존 산출물 문서 레포에서 세워졌고(그 레포 루트에 `cdp-sources.json` 이 있다) **그 문서 레포도 정본으로 계속 쓰면**, 그 문서를 고친 작업도 **이 세션의 작업** 길의 기록 하나다 — 다른 도구를 부르지 않는다.

- `touches` — 이 작업이 바꾼 섹션의 좌표. `match` · `where` 로 확정한다(문서 · `##` 섹션 하나가 좌표 하나).
- 본문 — 무엇을 바꿨나(값까지) · **왜** · 버린 안 · 근거(회의 · 회신 · 실측). 「왜」 는 고친 세션만 안다 — 이것이 이 기록의 몫이다.
- `source` — `<문서 레포> 커밋 <sha>`(여러 커밋이면 `<첫 sha>..<끝 sha>`). 큐레이터의 누락 점검이 이 커밋을 이 기록에 잇는다.
- 지도 밖의 새 md 를 만들었으면 본문 끝에 한 줄 — 큐레이터가 지도에 넣을지 정한다.

바뀐 줄의 대조 · 빠진 커밋 메우기는 큐레이터가 한다(cdp-seed 「⑦ 정본이 둘일 때」).

## 결정이 안 났으면

결정을 기다리는 것은 기록할 사실이 아니라 아젠다다.

- **판단이 끝난 부분과 안 끝난 부분을 가른다.** 정해진 것은 기록이다 — 남은 것이 남의 회신뿐이면 그 열린 물음만 본문 끝 「남은 것」 에 따로 적는다. 한 원문이 둘로 갈라지는 것이 정상이다.
- **열린 물음은 제기한다** — 이 레포에 이슈를 받는 타입이 있으면(`match` · `_vocab.md` 로 확인) 새 이슈 좌표를 등재하고 `touches` 에 넣는다(② 의 「제기했다」). 큐레이터가 대장에 올린다. 타입이 없으면 「남은 것」 에 두고 큐레이터에게 한 줄 남긴다.
- 「이렇게 하면 어떨까?」 만 있고 아무것도 정해지지 않았으면 기록하지 않는다 — 정해지면 다시 부른다.

## ④ 승인 게이트 — 필수

**사람이 승인하기 전에는 `save` 를 부르지 않는다.** 기록은 커밋되면 고칠 수 없고(정정 기록만 된다), 서버 검사는 좌표를 **빠뜨린** 것을 모른다. 한 번에 끝내 달라는 요청이어도 한 번은 보이고 묻는다. 승인 뒤 사람이 고친 것은 다시 묻지 않고 고친 대로 보낸다. — 이 규칙은 cdp-curate · cdp-registry 의 승인에도 그대로다.

```
【좌표 판정】 기록 2026-0908-출장보고-사진첨부 · 길: 이 세션의 작업
  ―― 넣는다 ――
  screen:BZD020             변경   사진 첨부 영역 신설 · 입력 영역을 맨 위로
  table:pj_trip_photo_list  신설   사진 저장 테이블 (미등재 → 등재 · 이름 제안)
  issue:ISS-015             제기   차량 이용 여부를 무엇으로 가르나 — 회신 대기 (미등재 → 등재)
  ―― 뺀다 ――
  screen:BZD012             참조   출장등록에서 넘어오지만 안 바뀐다
  운행일지                   언급   「이용자는 운행일지로 갈음」 → 대상 아님
【기록】 제목 · date 14:30 · 본문 요지(첨부 자리 · 대상자 · 여러 장 · 남은 것 1) · 첨부 1
승인하시면 남깁니다. 고칠 좌표가 있으면 알려 주세요.
```

**넣은 것 · 뺀 것 · 제기한 것을 모두 싣는다** — 뺀 것이 안 보이면 사람이 고칠 수 없다. 미등재 · 새 타입 · 이름 제안 · 0개 사유도 여기 적는다. (타입 이름 `screen:` · `issue:` 는 예시다 — 그 레포의 `_vocab.md` 가 정한다.)

## ⑤ save

```
save({
  repo: "alpha",
  work: {
    id: "2026-0908-출장보고-사진첨부",
    title: "BZD020 출장보고작성 — 차량 미이용자 사진 첨부 · 입력 영역 상단",
    date: "2026-09-08 14:30",
    touches: ["screen:BZD020", "table:pj_trip_photo_list", "issue:ISS-015"],
    tags: ["출장"],
    body: "# BZD020 — 사진 첨부 영역과 입력 영역 위치\n\n(홀로 서는 본문)"
  },
  vocab: [
    { coord: "table:pj_trip_photo_list", label: "출장사진목록", aliases: ["출장사진", "사진목록"] },
    { coord: "issue:ISS-015", label: "차량 이용 여부 판정 기준" }
  ]
  // assets: [{ ref: "sha256:…", name: "첨부영역.png" }]   — 첨부.md
})
```

**`sections` · `managed` · `edits` · `examples` · `baseline` · `work.curates` 는 보내지 않는다** — 큐레이터의 입력이다.

| 거절 | 할 일 |
|---|---|
| `E_FORBIDDEN` `need: curate` | 큐레이터 입력을 실었다 — 빼고 `work` 만 다시. 고칠 내용은 기록 본문에 |
| `E_FORBIDDEN` (그 밖) | 그 레포에 쓰기 권한이 없다 — 관리자에게(요청문을 만들어 준다) |
| `E_INPUT` `field: work.touches` | 좌표 0개 — ② 를 다시 본다. 정말 0개면 승인받고 `touchesEmpty` |
| `E_INPUT` 「어휘에 없는 좌표」 | 그 좌표를 `vocab` 에 같이 |
| `E_EXISTS` | 그 id 가 있다 — 다른 id. 고치려던 것이면 정정 기록 |
| `E_CHECK` | **이 save 가 만든** 오류다 — `detail.findings` 를 고쳐 다시. 레포에 원래 있던 오류는 막지 않고 경고로 온다 |
| `E_GIT` `reason: dirty` | 서버 트리 문제다 — 관리자에게 「트리 되돌리기」 를 청한다. 보낼 것은 그대로 |

`warnings`(시각 없는 date · 레포에 없는 그림 · 아무 본문도 안 가리키는 첨부 · 원래 있던 오류)는 사람에게 그대로 전한다. 고칠 것은 정정 기록으로.

## ⑥ 끝 보고 — 응답에 있는 것만

`save` 응답의 `commit` · `mirror` · `mirrorReason` · `mirrorLast` 와 `brief` 만 근거로 말한다.

| 응답 | 이렇게 |
|---|---|
| `mirror: "ok"` | 서버에 커밋했고(`<commit>`) origin 미러에도 갔다 |
| `mirror: "queued"` | 서버에 커밋했다 · 미러는 가는 중이다(마지막 상태는 `mirrorLast` 그대로) |
| `mirror: "lag"` · `"diverged"` | 서버에 커밋했다 · 미러는 못 갔다 — `mirrorReason` 과 `warnings` 의 그 줄을 그대로. 고치는 것은 관리자다 |
| `mirror: "off"` | 서버에 커밋했다 · 이 레포는 원격이 없다 |

그리고 **큐레이션 대기** — `brief({ repo })` 의 `curation.queue` 가 대기열 길이다. 대기열은 오래된 순이라 오늘 날짜의 기록은 맨 뒤다 — 「큐레이션 대기 n번째」. 편입처럼 날짜가 옛것이면 앞에 선다 — 「대기열 n건 중 하나(날짜순)」.

push 를 권하거나 push 여부를 말하지 않는다 — 사람이 누를 push 가 없다. 응답에 없는 것(「origin 에서 확인했다」)을 보태지 않고, `mirrorLast` 가 `null` 이면 미러 상태를 모른다고 말한다. — 큐레이션 · 등록부 save 의 끝 보고도 이 표를 쓴다.
