# cdp-import — 이미 있는 문서를 들인다

```
① pull        쓰기 전에 받는다.  실패하면 시작하지 않는다
② 원문 읽기    날짜를 정한다.  **오늘이 아니다**
③ 좌표 판정    **여기가 가장 위험하다** — 언급과 변경을 가른다
④ 편입        원문을 보존한다.  프론트매터만 씌운다
⑤ 파생 갱신    등록부에 걸리는 관리 문서 섹션.  **④ 와 함께 필수**
⑥ 한 커밋      작업 기록 1 + 관리 문서 N.  push 는 하지 않는다
```

`cdp-save` 와 뼈대가 같다. 다른 것은 **③ 과 ④** 다 — 본문을 쓰는 것이
아니라 이미 있는 본문에서 좌표를 읽어내야 하고, 그 본문은 지식 레포의
규약을 모르고 쓰였다.

이하 `<repo>` 는 지식 레포 경로(모드 A 의 git 명령에만 쓴다).

> **본문의 호출은 MCP 도구다.** `cdp` 서버가 붙어 있으면 `match(...)` 처럼
> 그대로 부른다 — 모드 A(stdio)든 모드 B(HTTP)든 같다. 도구가 없는 자리
> (커밋 훅 · 사람이 터미널에서 칠 때)는 맨 끝 **「도구가 없을 때」** 를 본다.
> 둘은 같은 함수라 결과가 바이트까지 같다(MCP 설계서 §3.3 · §10).
>
> **`save` 도구가 있으면 서버 모드다**(§4.8). 그때는 쓰기 경로가 바뀐다 —
>
> | | `save` 없음 (모드 A) | `save` 있음 (모드 B) |
> |---|---|---|
> | 시작 | `git pull --ff-only` | **생략.** 서버가 언제나 origin HEAD 다 |
> | 고치기 | Write · Edit 로 파일에 | **메모리에 준비해 사람에게 보인다.** 파일을 안 만든다 |
> | 끝 | `git commit` → 커밋 훅이 검사 | `save({ work, sections, vocab })` **한 번.** 서버가 검사하고 커밋한다. `sections[].body` 는 `section` 의 **`content`**(헤딩 · applied 없이) — 헤딩을 넣으면 E_INPUT |
> | 충돌 | 훅이 막는다 | `E_CONFLICT` 의 `detail.content`(지금 본문) 위에 **다시 만들어** `applied` 에 `detail.current` 를 넣어 보낸다 — `section` 을 다시 부르지 않는다(`truncated` 일 때만) |
>
> 훅은 모드 A 에서만 돈다. 모드 B 는 클라이언트에 작업 트리가 없다.

## 언제 쓰지 않나

| | |
|---|---|
| 이 세션에서 한 작업 | `cdp-save`. 본문을 새로 쓴다 |
| 아직 결정이 안 난 문서 | 아젠다다. 위험및이슈관리대장으로 |
| 관리 문서를 고치라는 지시 | `cdp-edit` |
| 코드·설정 파일 | 지식이 아니다. 작업 레포에 둔다 |

**결정이 안 난 문서를 들이지 마라.** 회의록에 "다음에 정하기로 했다" 가
있으면 그 대목은 이슈 대장으로 가고, 정해진 것만 기록이 된다. 하나의 원문이
둘로 갈라지는 것이 정상이다.

---

## ① pull

> **모드 B 면 이 절은 없다.** `save` 도구가 있으면 받을 것이 없다 — 서버 트리가
> 그 레포의 유일한 작성자이고 언제나 origin HEAD 다. 다음 절로 간다.

```
git -C <repo> pull --ff-only
```

실패하면 멈춘다. `cdp-save` ① 과 같다 — 낡은 섹션 위에서 diff 를 만들면
남이 갱신한 것을 조용히 덮는다.

---

## ② 원문 읽기 — 날짜는 사건의 날짜다

**오늘 날짜를 쓰지 마라.** 작업 기록의 `date` 는 **그 일이 일어난 날**이다.
오늘로 적으면 6개월 뒤 이력이 통째로 어긋나고, 최신성 계산이 그 날짜로
돈다 — 반년 전 회의록이 어제 결정을 덮어쓴다.

찾는 순서 —

```
① 문서 본문의 날짜        회의 일자 · 작성일 · 결재일
② 파일명의 날짜
③ 파일 수정 시각          위 둘이 없을 때만
```

**셋 다 없으면 사용자에게 묻는다.** 추측해서 넣지 않는다.

원문에 날짜가 여럿이면(회의일 · 작성일 · 배포일) **사건이 일어난 날**을
쓴다. 회의록이면 회의한 날이다.

---

## ③ 좌표 판정 — 언급과 변경을 가른다

**이 단계가 이 skill 의 존재 이유다.**

밖에서 온 문서는 지식 레포의 규약을 모르고 쓰였다. 회의록 한 장에 화면
이름이 열다섯 개 나와도 **그 회의가 바꾼 것은 둘**일 수 있다. 나머지 열셋을
`touches` 에 넣으면 —

- 그 좌표를 찾는 사람에게 무관한 문서가 나온다
- 열세 개 섹션에 파생 의무가 생긴다. 채울 내용이 없는데 채워야 한다
- 억지로 채우면 **틀린 내용이 정본에 들어간다**

`cdp-save` ② 의 기준을 그대로 쓴다.

| 이 문서가 그 대상을… | 좌표 |
|---|:--:|
| 신설하기로 **정했다** | **O** |
| 변경하기로 **정했다** | **O** |
| 폐기하기로 **정했다** | **O** |
| 언급했다 · 예로 들었다 · 배경으로 설명했다 | **X** |
| "검토하기로 했다" | **X** — 아직 안 정해졌다 |

**밖에서 온 문서에는 X 가 훨씬 많다.** 그것이 정상이다.

### 정규화

```
match(["면접심사의견등록", "업무구분코드", "서류심사"])
```

원문은 통제 어휘를 모르므로 **별칭·구어체·오타가 섞여 있다.** 반드시 돌린다.

- `(미등재)` → ⑤ 에서 `_vocab.md` 에 등재한다. 안 하면 커밋이 막힌다
- `[폐기 … -> …]` → 후속 좌표를 쓴다

### 근거를 보여준다

```
【좌표 판정 — 원문: 2026-08-14 연심회 준비 회의록.md】
  screen:EXA021         변경   외부 위원 그리드에 소속 컬럼 추가로 결정
  code:PS130            신설   업무구분 코드그룹 신설로 결정
  screen:EXA022         언급   "다음 안건 화면도 봐야 한다" → 결정 아님
  table:ps_ext_emp_mst  배경   현재 구조 설명일 뿐 → 좌표 아님
  ―― 검토 예정으로 남은 것 ――
  결재 취소 시 GDI 반영    미결 → 위험및이슈관리대장 ISS-003 에 붙인다
```

**제외한 것과 이슈로 보낸 것을 함께 보여준다.** 사용자가 원문을 아는
유일한 사람이므로, 그가 고칠 수 있어야 한다.

## ④ 편입 — 원문을 보존한다

```
<repo>/work/YYYY-MMDD-slug.md
```

`slug` 는 원문 제목에서 뽑되 짧게. 파일명과 `id` 는 **반드시 같다** —
다르면 `ctx check` 가 막는다.

### 본문을 다시 쓰지 않는다

**프론트매터만 씌우고 본문은 그대로 둔다.**

요약하고 싶어진다. 하지 마라 — 원문의 군더더기처럼 보이는 대목이 6개월 뒤
"왜 그렇게 정했나" 의 유일한 단서인 경우가 많다. 회의록의 반대 의견,
검토서의 각주, 인수인계 문서의 여담이 그렇다.

```markdown
---
id: 2026-0814-연심회준비-회의록
title: 연심회 준비 회의 — 외부 위원 그리드 · 업무구분 코드
date: 2026-08-14
author: kjsa
source: 공유드라이브/2026/연심회/2026-08-14 준비회의록.docx
touches:
  - screen:EXA021
  - code:PS130
tags: [회의록, 심의]
---

(원문 그대로)
```

| 필드 | |
|---|---|
| `title` | 원문 제목을 쓰되, 무엇에 관한 것인지 보이게 다듬는다 |
| `author` | **원문 작성자.** 편입한 사람이 아니다 |
| `source` | 원문이 어디서 왔는지. 지우지 마라 — 되짚을 유일한 길이다 |

### 형식만 손댄다

원문이 md 가 아니거나 md 여도 깨져 있을 수 있다. **내용이 아니라 형식만**
고친다.

- 표·목록이 깨졌으면 md 문법으로
- 제목 레벨을 정리한다 (`#` 은 문서 제목 하나)
- 이미지·첨부는 `<repo>/work/assets/<id>/` 로 옮기고 상대 경로로 건다

**내용을 고쳐야 할 것 같으면 고치지 말고 사용자에게 알린다.** 원문이 틀렸다면
그것은 편입 후 별도의 정정 기록(`supersedes`)이 할 일이다.

### 여러 문서는 하나씩

한 번에 여러 개를 들이지 마라. 좌표 판정이 문서마다 다르고, 한 커밋에
묶으면 **어느 좌표가 어느 문서에서 왔는지** 사라진다.

---

## ⑤ 파생 갱신 — ④ 와 함께 필수

```
apply("<좌표>")
```

등록부에 걸리는 좌표마다 관리 문서 섹션을 갱신하고 `<!-- applied: <id> -->`
를 이 기록으로 바꾼다. `cdp-managed` 의 쓰는 법이 그대로 적용된다.

**미룰 수 없다.** `ctx check` 가 파생 누락을 오류로 잡아 커밋을 막는다.

### 옛 문서를 들일 때 — 날짜가 과거다

편입하는 문서의 날짜가 **이미 반영된 기록보다 이전**일 수 있다. 그때는
섹션이 이미 더 최신이므로 `applied` 를 **바꾸지 않는다.**

```
where("screen:EXA021")
  상태   반영 2026-0902-EXA021-외부심의위원      ← 09-02
편입하려는 것: 2026-08-14                        ← 이전이다
```

이 경우 섹션 본문의 `변경` 목록에 그 날짜로 한 줄만 끼워 넣는다.
`applied` 는 그대로 둔다 — **더 최신이 이미 실려 있다.**

판단이 헷갈리면 `ctx derive` 를 돌려 본다. 목록이 비어 있으면 맞다.

---

## ⑥ 한 커밋

> **모드 B 면 이 절을 건너뛰고 `save` 도구 한 번으로 끝낸다.** 커밋할 작업
> 트리가 클라이언트에 없고 훅도 없다. 인자 모양과 `E_CONFLICT` 대처는
> **`cdp-save` 의 ⑤B** 에 있다 — 여기서 되풀이하지 않는다.

```
git -C <repo> add work/<id>.md docs/<...>.md _vocab.md
git -C <repo> commit -m "<제목> 편입"
```

**push 는 하지 않는다.** 사람이 누른다.

커밋 메시지에 `편입` 을 남긴다 — 나중에 "이건 밖에서 온 문서였다" 를
git 로그에서 가려낼 수 있다.

# 실사용 예시 — 회의록 한 장

> **아래는 모드 A 다** — 이 PC 에 지식 레포(`C:/cdp`)가 있고 **git 으로 커밋**하는 경우.
> 도구 호출은 두 모드가 같고, 다른 것은 시작의 `pull` 과 끝의 커밋뿐이다.
> 모드 B 면 그 둘이 없고 그 자리에 `save` 한 번이 온다(`cdp-save` ⑤B).

## 원문

사용자가 준 파일: `2026-08-14 연심회 준비회의록.md`

```markdown
# 연심회 준비 회의

일시: 2026년 8월 14일 (목) 14:00~15:20
참석: 마종희 팀장, 홍길동, 김세정
작성: 홍길동

## 1. 외부 심의위원 그리드

EXA021 화면의 외부 심의위원 정보 그리드에 **소속 컬럼을 추가**하기로 했다.
지금은 성명·직급·전화·이메일만 있는데, 위원 명단을 출력할 때 소속이 없어서
매번 담당자가 손으로 채워 넣고 있다는 얘기가 나왔다.

> 마 팀장: 소속 없으면 명단이 아니죠. 그냥 넣읍시다.

관련해서 EXA022 안건 등록 화면도 한번 봐야 한다는 얘기가 있었으나
**이번 범위는 아니다.** 다음 스프린트에서 따로 본다.

## 2. 업무구분 코드그룹

외부인원을 위원회 성격으로 묶는 축이 필요하다. 부서로 묶으면 외부인원에는
부서가 없어서 묶이지 않는다.

**PS130 업무구분 코드그룹을 신설한다.** 값은 연심회 / 평가위원회 / 위원회
셋으로 시작한다.

## 3. A10 결재 취소

A10 에서 결재를 취소했을 때 GDI 에 자동 반영되는지 확인이 안 됐다.
**다음 회의까지 A10 담당자에게 확인**하기로 했다. 결정 못 함.

## 4. 기타

ps_ext_emp_mst 테이블 구조는 현재 그대로 쓴다. 별도 변경 없음.
```

## ② 날짜 — 오늘이 아니다

본문 첫 줄에 `2026년 8월 14일`. **그 날이 사건의 날이다.**

오늘(예: 09-08)로 적으면 이 회의록이 09-02 의 EXA021 작업보다 나중이 되어
**반년 전 결정이 최신 결정을 덮는다.**

## ③ 좌표 판정 — 넷 중 둘만이다

```
match(["EXA021", "EXA022", "업무구분", "ps_ext_emp_mst"])
EXA021          ->  screen:EXA021  (값 일치 · _vocab.md:106)
EXA022          ->  screen:EXA022  (값 일치 · _vocab.md:108)
업무구분        ->  (미등재)  _vocab.md 에 없습니다
ps_ext_emp_mst  ->  table:ps_ext_emp_mst  (값 일치 · _vocab.md:83)
```

```
【좌표 판정 — 원문: 2026-08-14 연심회 준비회의록.md】
  screen:EXA021         변경   외부 위원 그리드에 소속 컬럼 추가로 결정
  code:PS130            신설   업무구분 코드그룹 신설로 결정 (미등재 → 등재한다)
  screen:EXA022         언급   "한번 봐야 한다" · **이번 범위는 아니다** → 좌표 아님
  table:ps_ext_emp_mst  배경   "현재 그대로 쓴다. 별도 변경 없음"     → 좌표 아님
  ―― 이슈로 ――
  A10 결재 취소 자동 반영   결정 못 함 → issue:ISS-003 에 이미 있다. 거기 붙인다
```

**넷이 나왔는데 둘만 좌표다.** 넷 다 넣었으면 —

- `EXA022` 를 찾는 사람에게 "이번 범위는 아니다" 라고만 적힌 문서가 나온다
- 화면설계서 `## EXA022` 와 테이블정의서 `## ps_ext_emp_mst` 에 파생 의무가
  생긴다. **채울 내용이 없는데 채워야 한다**
- 억지로 채우면 틀린 내용이 정본에 들어간다

### 어휘 이름이 다를 때

## 도구가 없을 때

**에이전트는 이 절을 쓸 일이 없다.** `cdp` 서버가 붙어 있으면 본문 그대로 부른다.
여기는 **커밋 훅**과 **사람이 터미널에서 칠 때**를 위한 것이다.

`<repo>` 는 지식 레포 경로, `ctx` 는 `<repo>/bin/ctx` — **Node 가 없어도 돈다**
(없으면 `cdp.exe` 로 넘어간다 · 작업환경 §3.1).

| 본문 | 터미널 |
|---|---|
| `match(["a","b"])` | `ctx match "a" "b"` |
| `where("screen:PSC043")` | `ctx where screen:PSC043` |
| `section("screen:PSC043")` | `ctx where` 뒤에 그 섹션을 연다 — **도구 쪽이 한 번에 준다** |
| `apply("screen:PSC043")` | `ctx apply screen:PSC043` |
| `derive()` | `ctx derive` |
| `check()` | `ctx check` |
| `sync()` | `ctx sync` |
| `search("말")` | `ctx search "말"` |

**`cdp` 가 안 붙어 있으면 그것부터 고친다.** `ctx setup <작업레포>` 가
`.mcp.json` 을 쓰고, Claude Code 를 다시 켜면 `/mcp` 에 `cdp` 가 뜬다.
붙지 않은 채로 bash 로 `ctx` 를 부르는 것은 **되기는 하지만 정상이 아니다** —
그 상태에서는 도구 명함이 없어서 무엇을 언제 부를지가 이 문서에만 있다.
