# cdp-import — 이미 있는 문서를 들인다

```
① pull        쓰기 전에 받는다.  실패하면 시작하지 않는다
② 원문 읽기    날짜를 정한다.  **오늘이 아니다**
③ 좌표 판정    **여기가 가장 위험하다** — 문서 성격부터 가르고, 언급과 변경 · 정의를 가른다
   ③-6 승인    【좌표 판정】을 보이고 **승인을 받는다.  승인 없이 ④ 로 가지 않는다**
④ 편입        원문을 보존한다.  프론트매터만 씌운다
⑤ 파생 갱신    등록부에 걸리는 관리 문서 섹션.  **④ 와 함께 필수**
⑥ 한 커밋      작업 기록 1 + 관리 문서 N.  push 는 하지 않는다  (모드 B 는 `save` 한 번)
```

> **금지 — 【좌표 판정】을 보이고 사람이 승인하기 전에는 기록하지 않는다.**
> 모드 A 는 파일을 쓰지 않고, 모드 B 는 **`save` 를 부르지 않는다.** 판정이 틀려도
> 검사는 모른다 — `touches` 에서 빠진 좌표는 어떤 검사에도 걸리지 않고, 원문을 아는
> 사람만 잡는다(2026-09-17 dpms_wiki `b5a1fc6` — 도메인 지식 문서가 `touches: []` 로
> 들어가 정의한 용어 아홉이 어느 좌표로도 안 닿았다).

`cdp-save` 와 뼈대가 같다. 다른 것은 **③ 과 ④** 다 — 본문을 쓰는 것이
아니라 이미 있는 본문에서 좌표를 읽어내야 하고, 그 본문은 지식 레포의
규약을 모르고 쓰였다.

이하 `<repo>` 는 지식 레포 경로(모드 A 의 git 명령에만 쓴다).

> **본문의 호출은 MCP 도구다.** `cdp` 서버가 붙어 있으면 `match(...)` 처럼
> 그대로 부른다 — 모드 A(stdio)든 모드 B(HTTP)든 같다. 도구가 없는 자리
> (커밋 훅 · 사람이 터미널에서 칠 때)는 맨 끝 **「도구가 없을 때」** 를 본다.
> 둘은 같은 함수라 결과가 바이트까지 같다(MCP 설계서 §3.3 · §10).
>
> **`save` 도구가 있으면 서버 모드다**(§4.8). 그때는 쓰기 경로가 바뀐다 —
>
> | | `save` 없음 (모드 A) | `save` 있음 (모드 B) |
> |---|---|---|
> | 시작 | `git pull --ff-only` | **생략.** 서버가 언제나 origin HEAD 다 |
> | 고치기 | Write · Edit 로 파일에 | **메모리에 준비한다.** 파일을 안 만든다 |
> | 승인 | ③-6 — 파일을 쓰기 전에 | **③-6 — 필수.** 【좌표 판정】을 보이고 승인을 받기 전에는 **`save` 를 부르지 않는다** |
> | 끝 | `git commit` → 커밋 훅이 검사 | `save({ work, sections, vocab })` **한 번.** 서버가 검사하고 커밋한다. `sections[].body` 는 `section` 의 **`content`**(헤딩 · applied 없이) — 헤딩을 넣으면 E_INPUT |
> | 충돌 | 훅이 막는다 | `E_CONFLICT` 의 `detail.content`(지금 본문) 위에 **다시 만들어** `applied` 에 `detail.current` 를 넣어 보낸다 — `section` 을 다시 부르지 않는다(`truncated` 일 때만) |
>
> 훅은 모드 A 에서만 돈다. 모드 B 는 클라이언트에 작업 트리가 없다.

## 언제 쓰지 않나

| | |
|---|---|
| 이 세션에서 한 작업 | `cdp-save`. 본문을 새로 쓴다 |
| 아직 결정이 안 난 문서 | 아젠다다. 위험및이슈관리대장으로 |
| 관리 문서를 고치라는 지시 | `cdp-edit` |
| 코드·설정 파일 | 지식이 아니다. 작업 레포에 둔다 |

**결정이 안 난 문서를 들이지 마라.** 회의록에 "다음에 정하기로 했다" 가
있으면 그 대목은 이슈 대장으로 가고, 정해진 것만 기록이 된다. 하나의 원문이
둘로 갈라지는 것이 정상이다.

## ① pull

> **모드 B 면 이 절은 없다.** `save` 도구가 있으면 받을 것이 없다 — 서버 트리가
> 그 레포의 유일한 작성자이고 언제나 origin HEAD 다. 다음 절로 간다.

```
git -C <repo> pull --ff-only
```

실패하면 멈춘다. `cdp-save` ① 과 같다 — 낡은 섹션 위에서 diff 를 만들면
남이 갱신한 것을 조용히 덮는다.

## ② 원문 읽기 — 날짜는 사건의 날짜다

**오늘 날짜를 쓰지 마라.** 작업 기록의 `date` 는 **그 일이 일어난 날**이다.
오늘로 적으면 6개월 뒤 이력이 통째로 어긋나고, 최신성 계산이 그 날짜로
돈다 — 반년 전 회의록이 어제 결정을 덮어쓴다.

찾는 순서 —

```
① 문서 본문의 날짜        회의 일자 · 작성일 · 결재일
② 파일명의 날짜
③ 파일 수정 시각          위 둘이 없을 때만
```

**셋 다 없으면 사용자에게 묻는다.** 추측해서 넣지 않는다.

원문에 날짜가 여럿이면(회의일 · 작성일 · 배포일) **사건이 일어난 날**을
쓴다. 회의록이면 회의한 날이다.

## ③ 좌표 판정 — 문서 성격부터 가른다

**이 단계가 이 skill 의 존재 이유다.** 번호 순서대로 한다 — 건너뛰지 않는다.

밖에서 온 문서는 지식 레포의 규약을 모르고 쓰였다. 판정은 두 방향으로 틀린다 —

| 틀리는 방향 | 결과 |
|---|---|
| **넘치게** — 언급만 한 것까지 넣는다 | 그 좌표를 찾는 사람에게 무관한 문서가 나오고, 채울 내용 없는 섹션에 파생 의무가 생긴다. 억지로 채우면 **틀린 내용이 정본에 들어간다** |
| **모자라게** — 정의한 것까지 뺀다 | **그 기록은 어떤 좌표로도 닿지 않는다.** `match` 는 계속 `미등재` 를 돌려주고, 검사는 아무 소리도 안 낸다 |

넘치는 쪽은 검사와 파생이 시끄럽게 알려 주지만 **모자라는 쪽은 조용하다.** 그래서
③-5 와 ③-6 이 있다.

### ③-1 문서 성격을 가른다

| 성격 | 예 | 좌표가 되는 것 |
|---|---|---|
| **결정 문서** | 회의록 · 검토서 · 설계 메모 | 신설 · 변경 · 폐기하기로 **정한** 대상 |
| **정의 · 지식 문서** | 도메인 설명 · 용어 정리 · 구조 설명 · 인수인계 | 문서가 **정의하거나 레포에 처음 도입한** 용어 · 개념 · 대상 |

한 문서가 둘 다일 수 있다(인수인계 문서에 결정 몇 개). 그때는 두 기준을 다 적용한다.

**정의 · 지식 문서에 결정 문서의 기준만 대면 좌표가 0개가 된다** — 무엇도 "바꾸기로
정하지" 않았으니 모든 대상이 "설명" 으로 떨어진다. 그 문서가 레포에 들어오는 이유가
바로 그 설명이다.

### ③-2 판정표

`cdp-save` ② 의 기준에 **정의 한 줄**을 더한 것이다.

| 이 문서가 그 대상을… | 좌표 |
|---|:--:|
| 신설하기로 **정했다** | **O** |
| 변경하기로 **정했다** | **O** |
| 폐기하기로 **정했다** | **O** |
| **정의했다 · 레포에 처음 도입했다** (정의 · 지식 문서) | **O** |
| 언급했다 · 예로 들었다 · 다른 대상을 설명하는 배경으로 썼다 | **X** |
| "검토하기로 했다" | **X** — 아직 안 정해졌다. 이슈로 |

"정의했다" 의 기준 — **그 대상이 무엇인지 이 문서를 읽고 알게 되는가.** 절 하나 · 표의
한 행 · 용어 설명 한 단락이 그 대상에 할애돼 있으면 정의다. 지나가며 이름만 나오면
언급이다. 판정 기준은 `cdp-save` 와 같다 — **6개월 뒤 그 대상을 맡은 사람이 이 문서를
찾아야 하는가.**

결정 문서에는 X 가 훨씬 많다. 그것이 정상이다. 정의 · 지식 문서는 반대로 **O 가
여럿인 것이 정상이다.**

### ③-3 정규화

```
match(["면접심사의견등록", "업무구분코드", "서류심사"])
```

원문은 통제 어휘를 모르므로 **별칭·구어체·오타가 섞여 있다.** 반드시 돌린다.

- `[폐기 … -> …]` → 후속 좌표를 쓴다
- **이름은 `_vocab.md` 의 규약을 따른다.** 타입마다 명명 규칙(공백 · 대소문자 · 영문
  한글 혼용 · 약어)이 적혀 있으면 그대로 짓고, 원문 표기는 `aliases` 에 넣는다.
  규약이 없으면 지은 이름을 ③-6 의 판정표에 **「이름 제안」** 으로 표시해 사람이
  고칠 수 있게 한다

### ③-4 도구의 답을 읽는 법

| 답 | 뜻 | **틀린 해석** |
|---|---|---|
| `match` → `미등재` | 어휘에 아직 없다 — **등재 후보다.** 원문의 핵심 대상이면 좌표에서 빼지 말고 판정표에 올리고 ⑤ 에서 `_vocab.md` 에 등재한다(모드 B 는 `save` 의 `vocab`) | ~~"레포와 관계없는 말이다"~~ |
| `where` → `registry: null` | 그 타입은 관리 문서가 없다 — **작업 기록이 유일한 근거이고 `touches` 가 그 좌표로 닿는 유일한 길이다** | ~~"채울 섹션이 없으니 좌표가 필요 없다"~~ |

관리 문서가 없는 타입(`term:` · `module:` · `domain:` 등)일수록 좌표를 빼면 잃는 것이
크다. 섹션이 있으면 그 섹션이라도 남지만, 없으면 **이 기록을 찾을 길이 `touches` 뿐이다.**
채울 섹션이 없다는 것은 파생을 안 해도 된다는 뜻이지 좌표를 뺄 이유가 아니다.

### ③-5 0개면 멈춘다

판정 결과 좌표가 **0개면 여기서 멈추고** 사용자에게 알린다 —

```
이 문서는 어떤 좌표로도 찾을 수 없게 됩니다.
  문서 성격: 정의 · 지식 문서
  뺀 대상: PLC · SCADA · CimonD … (전부 "설명" 으로 판정)
정말 좌표 없이 들일까요? 그렇다면 그 사유를 기록에 남깁니다.
```

- 0개가 나오면 **먼저 ③-1 을 의심한다.** 정의 · 지식 문서를 결정 문서로 본 것이 가장 흔한 원인이다
- 사용자가 0개를 승인하면 그 사유를 남긴다 — 모드 B 는 `save` 의 **`work.touchesEmpty`**
  (없으면 서버가 `E_INPUT` 으로 거절한다), 모드 A 는 `touches: []` 아래 `touchesEmpty: <사유>`

### ③-6 【좌표 판정】을 보이고 승인을 받는다 — 필수

```
【좌표 판정 — 원문: 2026-08-14 연심회 준비 회의록.md · 성격: 결정 문서】
  ―― 넣는다 ――
  screen:EXA021         변경   외부 위원 그리드에 소속 컬럼 추가로 결정
  code:PS130            신설   업무구분 코드그룹 신설로 결정 (미등재 → 등재한다)
  ―― 뺀다 ――
  screen:EXA022         언급   "다음 안건 화면도 봐야 한다" → 결정 아님
  table:ps_ext_emp_mst  배경   현재 구조 설명일 뿐 → 좌표 아님
  ―― 이슈로 ――
  결재 취소 시 GDI 반영    미결 → 위험및이슈관리대장 ISS-003 에 붙인다
승인하시면 편입합니다. 고칠 좌표가 있으면 알려 주세요.
```

**넣은 것 · 뺀 것 · 이슈로 보낸 것을 모두 싣는다.** 뺀 것이 안 보이면 사용자가 고칠
수 없다 — 원문을 아는 사람은 사용자뿐이다. 미등재 · 이름 제안 · 0개 사유도 여기 적는다.

**승인이 날 때까지 ④ 로 가지 않는다.** 모드 B 에서 이 단계를 건너뛰고 `save` 를 부르면
틀린 판정이 그대로 커밋되고, 서버 검사는 좌표를 **빠뜨린** 것을 알 수 없다(0개만 막는다).
한 번에 끝내 달라는 요청이어도 판정표는 보이고 한 번 묻는다.

## ④ 편입 — 원문을 보존한다

```
<repo>/work/YYYY-MMDD-slug.md
```

`slug` 는 원문 제목에서 뽑되 짧게. 파일명과 `id` 는 **반드시 같다** —
다르면 `ctx check` 가 막는다.

### 본문을 다시 쓰지 않는다

**프론트매터만 씌우고 본문은 그대로 둔다.**

요약하고 싶어진다. 하지 마라 — 원문의 군더더기처럼 보이는 대목이 6개월 뒤
"왜 그렇게 정했나" 의 유일한 단서인 경우가 많다. 회의록의 반대 의견,
검토서의 각주, 인수인계 문서의 여담이 그렇다.

```markdown
---
id: 2026-0814-연심회준비-회의록
title: 연심회 준비 회의 — 외부 위원 그리드 · 업무구분 코드
date: 2026-08-14
author: kjsa
source: 공유드라이브/2026/연심회/2026-08-14 준비회의록.docx
touches:
  - screen:EXA021
  - code:PS130
tags: [회의록, 심의]
---

(원문 그대로)
```

| 필드 | |
|---|---|
| `title` | 원문 제목을 쓰되, 무엇에 관한 것인지 보이게 다듬는다 |
| `author` | **원문 작성자.** 편입한 사람이 아니다 |
| `source` | 원문이 어디서 왔는지. 지우지 마라 — 되짚을 유일한 길이다. 모드 B 는 `save` 의 **`work.source`** 로 보낸다(있으면 시각 없는 `date` 를 경고하지 않는다 — 밖에서 온 문서는 시각을 모르는 것이 보통이다) |
| `touchesEmpty` | ③-5 에서 0개를 승인받았을 때만. 그 사유 |

### 형식만 손댄다

원문이 md 가 아니거나 md 여도 깨져 있을 수 있다. **내용이 아니라 형식만**
고친다.

- 표·목록이 깨졌으면 md 문법으로
- 제목 레벨을 정리한다 (`#` 은 문서 제목 하나)
- 이미지·첨부는 `<repo>/work/assets/<id>/` 로 옮기고 상대 경로로 건다

**내용을 고쳐야 할 것 같으면 고치지 말고 사용자에게 알린다.** 원문이 틀렸다면
그것은 편입 후 별도의 정정 기록(`supersedes`)이 할 일이다.

### 이미 들인 기록의 좌표가 빠졌으면 — 정정 기록

**좌표 누락도 오기재다.** 기존 기록은 고치지 않으므로(`save` 는 `E_EXISTS`) 정정 기록을
하나 낸다 — `cdp-save` 의 「`supersedes` 는 오기재 정정에만」 그대로다.

| 필드 | |
|---|---|
| `id` | `<원 기록 id>-좌표정정` |
| `title` | `"[정정] <원 제목> — 좌표 보완"` (따옴표 — `[` 로 시작한다) |
| `date` | **원 기록의 `date` 그대로.** 정정하는 것은 그날 문서의 좌표이고, 오늘 날짜면 그 사이 같은 좌표의 기록보다 나중이 되어 선후가 뒤집힌다 |
| `source` | 원 기록에 있으면 같은 값 |
| `touches` | **빠졌던 좌표만** — ③ 을 다시 해 승인받은 것 |
| `supersedes` | 원 기록 id |
| 본문 | 원문을 다시 싣지 않는다. 무엇이 왜 빠졌고 무엇을 넣는지(③-6 판정표)와 원 기록 링크 |

원 기록은 그대로 남고 검색에서도 안 내려간다(`supersedes` 는 판정이 아니라 참조다).
좌표로 찾아온 사람은 정정 기록을 거쳐 원 기록에 닿는다.

### 여러 문서는 하나씩

한 번에 여러 개를 들이지 마라. 좌표 판정이 문서마다 다르고, 한 커밋에
묶으면 **어느 좌표가 어느 문서에서 왔는지** 사라진다.

---

## ⑤ 파생 갱신 — ④ 와 함께 필수

```
apply("<좌표>")
```

등록부에 걸리는 좌표마다 관리 문서 섹션을 갱신하고 `<!-- applied: <id> -->`
를 이 기록으로 바꾼다. `cdp-managed` 의 쓰는 법이 그대로 적용된다.

**미룰 수 없다.** `ctx check` 가 파생 누락을 오류로 잡아 커밋을 막는다.

### 옛 문서를 들일 때 — 날짜가 과거다

편입하는 문서의 날짜가 **이미 반영된 기록보다 이전**일 수 있다. 그때는
섹션이 이미 더 최신이므로 `applied` 를 **바꾸지 않는다.**

```
where("screen:EXA021")
  상태   반영 2026-0902-EXA021-외부심의위원      ← 09-02
편입하려는 것: 2026-08-14                        ← 이전이다
```

이 경우 섹션 본문의 `변경` 목록에 그 날짜로 한 줄만 끼워 넣는다.
`applied` 는 그대로 둔다 — **더 최신이 이미 실려 있다.**

판단이 헷갈리면 `ctx derive` 를 돌려 본다. 목록이 비어 있으면 맞다.

---

## ⑥ 한 커밋

> **모드 B 면 이 절을 건너뛰고 `save` 도구 한 번으로 끝낸다.** 커밋할 작업
> 트리가 클라이언트에 없고 훅도 없다. 인자 모양과 `E_CONFLICT` 대처는
> **`cdp-save` 의 ⑤B** 에 있다 — 여기서 되풀이하지 않는다.

```
git -C <repo> add work/<id>.md docs/<...>.md _vocab.md
git -C <repo> commit -m "<제목> 편입"
```

**push 는 하지 않는다.** 사람이 누른다.

커밋 메시지에 `편입` 을 남긴다 — 나중에 "이건 밖에서 온 문서였다" 를
git 로그에서 가려낼 수 있다.

```markdown
## 1. 외부 심의위원 그리드

EXA021 화면의 외부 심의위원 정보 그리드에 **소속 컬럼을 추가**하기로 했다.

**다음 회의까지 A10 담당자에게 확인**하기로 했다. 결정 못 함.

## 4. 기타

ps_ext_emp_mst 테이블 구조는 현재 그대로 쓴다. 별도 변경 없음.
```

## ② 날짜 — 오늘이 아니다

본문 첫 줄에 `2026년 8월 14일`. **그 날이 사건의 날이다.**

오늘(예: 09-08)로 적으면 이 회의록이 09-02 의 EXA021 작업보다 나중이 되어

## ③ 좌표 판정 — 넷 중 둘만이다

**③-1 성격: 결정 문서** — 회의록이다. 정한 것만 좌표다.

```
match(["EXA021", "EXA022", "업무구분", "ps_ext_emp_mst"])
EXA021          ->  screen:EXA021  (값 일치 · _vocab.md:106)
EXA022          ->  screen:EXA022  (값 일치 · _vocab.md:108)
업무구분        ->  (미등재)  _vocab.md 에 없습니다
ps_ext_emp_mst  ->  table:ps_ext_emp_mst  (값 일치 · _vocab.md:83)
```

```
【좌표 판정 — 원문: 2026-08-14 연심회 준비회의록.md】
  screen:EXA021         변경   외부 위원 그리드에 소속 컬럼 추가로 결정
  code:PS130            신설   업무구분 코드그룹 신설로 결정 (미등재 → 등재한다)
  screen:EXA022         언급   "한번 봐야 한다" · **이번 범위는 아니다** → 좌표 아님
  table:ps_ext_emp_mst  배경   "현재 그대로 쓴다. 별도 변경 없음"     → 좌표 아님
  ―― 이슈로 ――
  A10 결재 취소 자동 반영   결정 못 함 → issue:ISS-003 에 이미 있다. 거기 붙인다
```

**③-6 — 이 판정표를 보이고 승인을 받은 뒤에야 ④ 로 간다.**

**넷이 나왔는데 둘만 좌표다.** 넷 다 넣었으면 —

- `EXA022` 를 찾는 사람에게 "이번 범위는 아니다" 라고만 적힌 문서가 나온다
- 화면설계서 `## EXA022` 와 테이블정의서 `## ps_ext_emp_mst` 에 파생 의무가
  생긴다. **채울 내용이 없는데 채워야 한다**
- 억지로 채우면 틀린 내용이 정본에 들어간다

### 어휘 이름이 다를 때

원문은 `PS130` 이라 쓰는데 이 레포의 코드 어휘는 `PS-0xx` 꼴이다.
`ctx match` 가 `(미등재)` 로 잡아냈다.

**실제 프로젝트가 쓰는 이름을 정본으로 하고 별칭을 건다.**

```markdown
- `code:PS130` — 업무구분 (인사)
```

`ctx match` 를 거치지 않으면 조용히 두 이름이 생긴다. 밖에서 온 문서를
들일 때 **반드시 나오는 종류의 마찰**이다.


**기계가 규칙을 확인해 준다.** 헷갈리면 `ctx derive` 를 돌려 보면 된다.

# 실사용 예시 둘 — 도메인 지식 문서

회의록과 **반대 방향으로** 틀리는 경우다. 2026-09-17 실제로 이렇게 틀렸다.

## 원문

`PLC_CIMON_SCADA_구조_및_데이터흐름.md` — 현장 설비가 어떻게 연결되고 데이터가 어디로
흐르는지 설명한 문서. 결정은 하나도 없고, PLC · SCADA · CimonD · CimonX · I/O 드라이버
같은 용어를 절마다 정의한다.

## 틀린 판정 — 결정 문서의 기준을 댔다

```
【좌표 판정】
  term:PLC        설명   → 좌표 아님       ← 틀렸다
  term:SCADA      설명   → 좌표 아님       ← 틀렸다
  …
touches: []   →  save 가 경고 없이 커밋
```

무엇도 "바꾸기로 정하지" 않았으니 전부 X 가 됐다. `match` 의 `미등재` 는 "관계없는
말" 로, `where` 의 `registry: null` 은 "좌표가 필요 없다" 로 읽었다(③-4 의 틀린 해석
둘). 【좌표 판정】을 보이지 않고 `save` 를 불렀다(③-6 을 건너뛰었다).

## 맞는 판정

**③-1 성격: 정의 · 지식 문서** — 문서가 정의한 용어가 좌표다.

```
match(["PLC", "SCADA", "CimonD", "CimonX", "I/O 드라이버", "SCADA 태그"])
  전부  ->  (미등재)                ← ③-4: 등재 후보다
where("term:PLC")
  registry: null                    ← ③-4: touches 가 유일한 길이다
```

```
【좌표 판정 — 원문: PLC_CIMON_SCADA_구조_및_데이터흐름.md · 성격: 정의 · 지식 문서】
  ―― 넣는다 (전부 미등재 → 등재) ――
  term:PLC              정의   PLC 의 역할과 스캔 주기
  term:PLC디바이스주소    정의   디바이스 주소 체계 표         (이름 제안 — 원문 "PLC 디바이스 주소")
  term:SCADA            정의   SCADA 구성
  term:SCADA태그         정의   태그와 디바이스 주소의 대응     (이름 제안 — 원문 "SCADA 태그")
  term:CimonD           정의   수집 서버
  term:CimonX           정의   화면 런타임
  term:IO드라이버         정의   통신 드라이버                 (이름 제안 — 원문 "I/O 드라이버")
  ―― 뺀다 ――
  term:OPC              언급   "OPC 로도 붙일 수 있다" 한 줄 → 정의 아님
승인하시면 편입합니다. 이름을 바꾸거나 뺄 것이 있으면 알려 주세요.
```

(각 줄의 근거와 `OPC` 줄은 설명을 위한 예시다.) 등록부에 `term:` 이 없으므로 ⑤ 에서
파생할 섹션은 없고, `vocab` 에 일곱 줄 · `touches` 에 일곱 좌표 · `source` 에 원문
경로가 간다.

## 도구가 없을 때

**에이전트는 이 절을 쓸 일이 없다.** `cdp` 서버가 붙어 있으면 본문 그대로 부른다.
여기는 **커밋 훅**과 **사람이 터미널에서 칠 때**를 위한 것이다.

`<repo>` 는 지식 레포 경로, `ctx` 는 `<repo>/bin/ctx` — **Node 가 없어도 돈다**
(없으면 `cdp.exe` 로 넘어간다 · 작업환경 §3.1).

| 본문 | 터미널 |
|---|---|
| `match(["a","b"])` | `ctx match "a" "b"` |
| `where("screen:PSC043")` | `ctx where screen:PSC043` |
| `section("screen:PSC043")` | `ctx where` 뒤에 그 섹션을 연다 — **도구 쪽이 한 번에 준다** |
| `apply("screen:PSC043")` | `ctx apply screen:PSC043` |
| `derive()` | `ctx derive` |
| `check()` | `ctx check` |
| `sync()` | `ctx sync` |
| `search("말")` | `ctx search "말"` |

**`cdp` 가 안 붙어 있으면 그것부터 고친다.** `ctx setup <작업레포>` 가
`.mcp.json` 을 쓰고, Claude Code 를 다시 켜면 `/mcp` 에 `cdp` 가 뜬다.
붙지 않은 채로 bash 로 `ctx` 를 부르는 것은 **되기는 하지만 정상이 아니다** —
그 상태에서는 도구 명함이 없어서 무엇을 언제 부를지가 이 문서에만 있다.
