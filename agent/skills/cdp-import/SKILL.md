# cdp-import — 이미 있는 문서를 들인다

```
① pull        쓰기 전에 받는다.  실패하면 시작하지 않는다
② 원문 읽기    날짜를 정한다.  **오늘이 아니다**
③ 좌표 판정    **여기가 가장 위험하다** — 언급과 변경을 가른다
④ 편입        원문을 보존한다.  프론트매터만 씌운다
⑤ 파생 갱신    등록부에 걸리는 관리 문서 섹션.  **④ 와 함께 필수**
⑥ 한 커밋      작업 기록 1 + 관리 문서 N.  push 는 하지 않는다
```

`cdp-save` 와 뼈대가 같다. 다른 것은 **③ 과 ④** 다 — 본문을 쓰는 것이
아니라 이미 있는 본문에서 좌표를 읽어내야 하고, 그 본문은 지식 레포의
규약을 모르고 쓰였다.

이하 `<repo>` 는 지식 레포 경로. `ctx` 는 `<repo>/bin/ctx`.

---

## 언제 쓰지 않나

| | |
|---|---|
| 이 세션에서 한 작업 | `cdp-save`. 본문을 새로 쓴다 |
| 아직 결정이 안 난 문서 | 아젠다다. 위험및이슈관리대장으로 |
| 관리 문서를 고치라는 지시 | `cdp-edit` |
| 코드·설정 파일 | 지식이 아니다. 작업 레포에 둔다 |

**결정이 안 난 문서를 들이지 마라.** 회의록에 "다음에 정하기로 했다" 가
있으면 그 대목은 이슈 대장으로 가고, 정해진 것만 기록이 된다. 하나의 원문이
둘로 갈라지는 것이 정상이다.

---

## ① pull

```
git -C <repo> pull --ff-only
```

실패하면 멈춘다. `cdp-save` ① 과 같다 — 낡은 섹션 위에서 diff 를 만들면
남이 갱신한 것을 조용히 덮는다.

---

## ② 원문 읽기 — 날짜는 사건의 날짜다

**오늘 날짜를 쓰지 마라.** 작업 기록의 `date` 는 **그 일이 일어난 날**이다.
오늘로 적으면 6개월 뒤 이력이 통째로 어긋나고, 최신성 계산이 그 날짜로
돈다 — 반년 전 회의록이 어제 결정을 덮어쓴다.

찾는 순서 —

```
① 문서 본문의 날짜        회의 일자 · 작성일 · 결재일
② 파일명의 날짜
③ 파일 수정 시각          위 둘이 없을 때만
```

**셋 다 없으면 사용자에게 묻는다.** 추측해서 넣지 않는다.

원문에 날짜가 여럿이면(회의일 · 작성일 · 배포일) **사건이 일어난 날**을
쓴다. 회의록이면 회의한 날이다.

---

## ③ 좌표 판정 — 언급과 변경을 가른다

**이 단계가 이 skill 의 존재 이유다.**

밖에서 온 문서는 지식 레포의 규약을 모르고 쓰였다. 회의록 한 장에 화면
이름이 열다섯 개 나와도 **그 회의가 바꾼 것은 둘**일 수 있다. 나머지 열셋을
`touches` 에 넣으면 —

- 그 좌표를 찾는 사람에게 무관한 문서가 나온다
- 열세 개 섹션에 파생 의무가 생긴다. 채울 내용이 없는데 채워야 한다
- 억지로 채우면 **틀린 내용이 정본에 들어간다**

`cdp-save` ② 의 기준을 그대로 쓴다.

| 이 문서가 그 대상을… | 좌표 |
|---|:--:|
| 신설하기로 **정했다** | **O** |
| 변경하기로 **정했다** | **O** |
| 폐기하기로 **정했다** | **O** |
| 언급했다 · 예로 들었다 · 배경으로 설명했다 | **X** |
| "검토하기로 했다" | **X** — 아직 안 정해졌다 |

**밖에서 온 문서에는 X 가 훨씬 많다.** 그것이 정상이다.

### 정규화

```
<repo>/bin/ctx match "면접심사의견등록" "업무구분코드" "서류심사"
```

원문은 통제 어휘를 모르므로 **별칭·구어체·오타가 섞여 있다.** 반드시 돌린다.

- `(미등재)` → ⑤ 에서 `_vocab.md` 에 등재한다. 안 하면 커밋이 막힌다
- `[폐기 … -> …]` → 후속 좌표를 쓴다

### 근거를 보여준다

```
【좌표 판정 — 원문: 2026-08-14 연심회 준비 회의록.md】
  screen:EXA021         변경   외부 위원 그리드에 소속 컬럼 추가로 결정
  code:PS130            신설   업무구분 코드그룹 신설로 결정
  screen:EXA022         언급   "다음 안건 화면도 봐야 한다" → 결정 아님
  table:ps_ext_emp_mst  배경   현재 구조 설명일 뿐 → 좌표 아님
  ―― 검토 예정으로 남은 것 ――
  결재 취소 시 GDI 반영    미결 → 위험및이슈관리대장 ISS-003 에 붙인다
```

**제외한 것과 이슈로 보낸 것을 함께 보여준다.** 사용자가 원문을 아는
유일한 사람이므로, 그가 고칠 수 있어야 한다.

## ④ 편입 — 원문을 보존한다

```
<repo>/work/YYYY-MMDD-slug.md
```

`slug` 는 원문 제목에서 뽑되 짧게. 파일명과 `id` 는 **반드시 같다** —
다르면 `ctx check` 가 막는다.

### 본문을 다시 쓰지 않는다

**프론트매터만 씌우고 본문은 그대로 둔다.**

요약하고 싶어진다. 하지 마라 — 원문의 군더더기처럼 보이는 대목이 6개월 뒤
"왜 그렇게 정했나" 의 유일한 단서인 경우가 많다. 회의록의 반대 의견,
검토서의 각주, 인수인계 문서의 여담이 그렇다.

```markdown
---
id: 2026-0814-연심회준비-회의록
title: 연심회 준비 회의 — 외부 위원 그리드 · 업무구분 코드
date: 2026-08-14
author: kjsa
source: 공유드라이브/2026/연심회/2026-08-14 준비회의록.docx
touches:
  - screen:EXA021
  - code:PS130
tags: [회의록, 심의]
---

(원문 그대로)
```

| 필드 | |
|---|---|
| `title` | 원문 제목을 쓰되, 무엇에 관한 것인지 보이게 다듬는다 |
| `author` | **원문 작성자.** 편입한 사람이 아니다 |
| `source` | 원문이 어디서 왔는지. 지우지 마라 — 되짚을 유일한 길이다 |

### 형식만 손댄다

원문이 md 가 아니거나 md 여도 깨져 있을 수 있다. **내용이 아니라 형식만**
고친다.

- 표·목록이 깨졌으면 md 문법으로
- 제목 레벨을 정리한다 (`#` 은 문서 제목 하나)
- 이미지·첨부는 `<repo>/work/assets/<id>/` 로 옮기고 상대 경로로 건다

**내용을 고쳐야 할 것 같으면 고치지 말고 사용자에게 알린다.** 원문이 틀렸다면
그것은 편입 후 별도의 정정 기록(`supersedes`)이 할 일이다.

### 여러 문서는 하나씩

한 번에 여러 개를 들이지 마라. 좌표 판정이 문서마다 다르고, 한 커밋에
묶으면 **어느 좌표가 어느 문서에서 왔는지** 사라진다.

## ⑤ 파생 갱신 — ④ 와 함께 필수

```
<repo>/bin/ctx apply <좌표>
```

등록부에 걸리는 좌표마다 관리 문서 섹션을 갱신하고 `<!-- applied: <id> -->`
를 이 기록으로 바꾼다. `cdp-managed` 의 쓰는 법이 그대로 적용된다.

**미룰 수 없다.** `ctx check` 가 파생 누락을 오류로 잡아 커밋을 막는다.

### 옛 문서를 들일 때 — 날짜가 과거다

편입하는 문서의 날짜가 **이미 반영된 기록보다 이전**일 수 있다. 그때는
섹션이 이미 더 최신이므로 `applied` 를 **바꾸지 않는다.**

```
$ ctx where screen:EXA021
  상태   반영 2026-0902-EXA021-외부심의위원      ← 09-02
편입하려는 것: 2026-08-14                        ← 이전이다
```

이 경우 섹션 본문의 `변경` 목록에 그 날짜로 한 줄만 끼워 넣는다.
`applied` 는 그대로 둔다 — **더 최신이 이미 실려 있다.**

판단이 헷갈리면 `ctx derive` 를 돌려 본다. 목록이 비어 있으면 맞다.

---

## ⑥ 한 커밋

```
git -C <repo> add work/<id>.md docs/<...>.md _vocab.md
git -C <repo> commit -m "<제목> 편입"
```

**push 는 하지 않는다.** 사람이 누른다.

커밋 메시지에 `편입` 을 남긴다 — 나중에 "이건 밖에서 온 문서였다" 를
git 로그에서 가려낼 수 있다.
