# cdp-load — 좌표의 현재 상태를 주입한다

```
cdp-load <좌표> [<좌표> …]
cdp-load table:pj_plan_mst screen:HRC043
```

**좌표를 스스로 추출하지 않는다.** 추출은 `cdp-work` 의 ① 검토가 하고, 이 skill 은
받은 좌표에 대해서만 기계적으로 동작한다. **같은 좌표를 주면 항상 같은 것을 주입한다.**

인자가 없으면 **사용자에게 좌표를 묻고 멈춘다.** 추측하지 마라.

이하에서 `<repo>` 는 지식 레포 경로다.

> **본문의 호출은 MCP 도구다.** `cdp` 서버가 붙어 있으면 `match(...)` 처럼
> 그대로 부른다 — 모드 A(stdio)든 모드 B(HTTP)든 같다. 도구가 없는 자리
> (커밋 훅 · 사람이 터미널에서 칠 때)는 맨 끝 **「도구가 없을 때」** 를 본다.
> 둘은 같은 함수라 결과가 바이트까지 같다(MCP 설계서 §3.3 · §10).
>
> **`save` 도구가 있으면 서버 모드다**(§4.8). 그때는 쓰기 경로가 바뀐다 —
>
> | | `save` 없음 (모드 A) | `save` 있음 (모드 B) |
> |---|---|---|
> | 시작 | `git pull --ff-only` | **생략.** 서버가 언제나 origin HEAD 다 |
> | 고치기 | Write · Edit 로 파일에 | **메모리에 준비해 사람에게 보인다.** 파일을 안 만든다 |
> | 끝 | `git commit` → 커밋 훅이 검사 | `save({ work, sections, vocab })` **한 번.** 서버가 검사하고 커밋한다 |
> | 충돌 | 훅이 막는다 | `E_CONFLICT` 면 `section` 을 **다시 읽고 다시** 만든다 |
>
> 훅은 모드 A 에서만 돈다. 모드 B 는 클라이언트에 작업 트리가 없다.

---

## 0. 최신인지 확인한다 — **받지는 않는다**

> **모드 B 면 `받을 것` 이 늘 0 이다** — 서버 트리가 언제나 origin HEAD 라
> 뒤처질 자리가 없다. 대신 `sync` 가 주는 `kit.hash` 를 본다: 이 작업 레포
> `CLAUDE.md` 의 `cdp:kit` 값과 다르면 **여기 깔린 스킬이 낡은 것**이므로
> 답에 적는다 — 에이전트 세팅이 서버에서 바뀌었다는 뜻이다. 고치는 것은 **이 작업 레포의
> 담당자가 자기 PC 에서 한 줄**: 관리 › 작업 레포 의 「일괄 갱신」(설치기 `--update` — 그 PC 에
> 설치한 작업 레포를 전부 갱신한다). 팀원이면 담당자의 커밋을 pull 하면 된다. 스킬 파일을
> 손으로 고치지 않는다.

```
sync()
```

| | |
|---|---|
| `받을 것 0건` · 원격 없음 | 그대로 1 로 간다 |
| **`받을 것 N건`** | **주입 전에 알린다.** 아래 |

```
⚠ 받을 것이 3건 있습니다. 지금 주입하는 섹션이 최신이 아닐 수 있습니다.
   먼저 받을까요?   (git -C <repo> pull --ff-only)
```

### 왜 확인만 하나

**주입은 읽기다.** ff 가 안 되는 상태에서 pull 을 강제하면 **보는 것조차
막힌다** — 그건 과하다. 낡은 것이라도 보는 편이 아무것도 못 보는 것보다
낫고, 낡았다는 사실만 알면 사람이 판단한다.

### 왜 그냥 넘기지 않나

**여기서 주입한 것이 그 뒤 작업 전체의 근거가 된다.** 동료가 오늘 아침 그
섹션을 고쳤는데 모르고 설계하면, 끝에 가서 `cdp-save` 가 pull 할 때야
알게 된다 — 그때는 이미 만든 뒤다.

쓰기 쪽(`cdp-save`·`cdp-import`·`cdp-edit`·`cdp-managed`)의 pull 은
**레포가 깨지는 것**을 막는다. 읽기 쪽의 이 확인은 **틀린 것을 만드는 것**을
막는다. 뒤쪽이 더 비싸다.

`ctx sync` 는 받지 않는다. 원격이 없으면 `동기화할 것이 없습니다` 로
조용히 끝난다 — 원격 없는 레포에서 잡음이 나지 않는다.

## 1. 좌표 정규화

받은 좌표가 정본인지 `<repo>/_vocab.md` 로 확인한다.

- 정본이면 그대로 쓴다
- alias 면 정본으로 바꾸고 **바꿨다는 사실을 출력에 적는다**
- `_vocab.md` 에 없으면 **미등재**로 표시한다. 주입은 계속하되 그 사실을 알린다
  (미등재 좌표는 프로토콜 §9.6의 조용한 실패로 들어간다)

## 2. 관리 문서와 섹션 찾기

`<repo>/_managed.md` 의 등록부를 위에서부터 훑어 **먼저 걸리는 패턴**을 쓴다.

```
| 좌표 패턴     | 관리 문서                    | 섹션      |
| table:*      | docs/테이블정의서.md          | ## {값}   |
| screen:HR*   | docs/화면정의서_인사.md       | ## {값}   |
```

**`ctx where <좌표>` 가 등록부 조회와 반영 확인을 한 번에 한다.** 이것을 먼저 쓴다.

```
where("screen:HRC043")
```
```
screen:HRC043
  문서   docs/화면정의서_인사.md
  섹션   ## HRC043
  상태   반영 2026-0821-면접심사의견-개편
  작업   1건
    2026-08-21  2026-0821-면접심사의견-개편
```

`상태` 줄이 3번의 답이다. 그 뒤에 그 문서의 **해당 섹션만** 읽는다.

도구가 있으면 그 읽기가 `section` 이다 — 문서 경로도 줄 범위도 몰라도 되고,
파일을 열지 않으므로 **문서 전체를 읽을 방법 자체가 없다.**

| 결과 | |
|---|---|
| 등록부에 걸린다 | 그 문서의 **해당 섹션만** 읽는다 |
| 등록부에 없다 (`module:` `domain:` 등) | 관리 문서가 없다. **정상이다.** 5번의 폴백으로 간다. (기록할 때 그 타입이 여럿의 좌표로 자란다면 `cdp-save` 가 관리 문서를 만든다 — 읽는 쪽이 할 일은 아니다) |
| 걸렸는데 섹션이 없다 | **빈 섹션으로 취급**하고 그 사실을 알린다 |

> **문서 전체를 읽지 마라.** 테이블정의서에는 테이블이 수십 개 있다.
> 섹션 하나가 필요한데 977행을 읽으면 컨텍스트를 태운다.

## 3. 무엇이 실려 있나

섹션 머리의 주석이 마지막으로 반영된 작업 기록이다.

```markdown
## pj_plan_mst — 계획서마스터
<!-- applied: 2026-0821-계획서-상태값추가 -->
```

`ctx where` 의 `상태` 줄이 그 답이다 — `반영 <작업 id>`.

**"밀림"을 판정하지 않는다.** 파생은 필수이므로 섹션은 늘 최신이고, 안 됐으면
그것은 상태가 아니라 `ctx check` 가 커밋을 막는 **오류**다. 파생이 남은 전체
목록은 `ctx derive` 이고, 그것을 치우는 것은 `cdp-managed` 의 일이다.

`상태` 가 `파생 남음` 으로 나오면 **그 사실을 답변에 적는다** — 이 skill 은
읽기만 하고, 그 상태에서 주입한 섹션은 아직 최신이 아니다.

## 4. 좌표별 후속 판정

작업 기록을 근거로 실을 때는 **문서 단위로 판정하지 마라.**

한 작업 기록에 좌표가 여럿 있고 좌표마다 그 뒤 사정이 다르다.

```
2026-0710-ERP-어댑터-v1
  table:pj_plan_mst           후속 3건   ← 이 부분은 갱신됐을 수 있다
  api:/adapter/erp/plan-sync  최신       ← 이 부분은 이 문서가 마지막 말이다
```

**"후속 있음"을 "덮임"이라고 쓰지 마라.** 이후 문서가 그 좌표를 조금 손봤는지
완전히 뒤집었는지 알 수 없다. **아는 것만 말한다.**

## 5. 관리 문서가 없는 좌표

등록부에 없으면 작업 기록이 유일한 근거다.

- 그 좌표를 `touches` 에 가진 작업 기록을 **최신순 3건**까지
- 각각에 4번의 좌표별 후속 판정을 붙인다
- 3건을 넘으면 **절단을 알린다**(6번)

## 6. 절단

매칭됐으나 주입하지 않은 것이 있으면 **반드시 적는다.**

```
[절단] 매칭 8건 중 3건 주입. 나머지 id: 2026-06…, 2026-05…
```

적지 않으면 읽는 쪽은 그 5건이 **존재하지 않는다고 판단한다.**
id 나열은 수십 토큰이고, 얻는 것은 "더 있다"를 알고 필요하면 요청할 수 있게 되는 것이다.

## 출력 형태

좌표마다 이 블록을 낸다.

```
[좌표]   table:pj_plan_mst
[정본]   docs/테이블정의서.md  ## pj_plan_mst        ← 자리
[범위]   그 섹션만 — 24줄 · 약 700자 (docs/테이블정의서.md:112)
         **이 문서의 다른 섹션도, 이 좌표를 건드린 작업 기록도 안 실었다**
[상태]   반영 2026-0903-계획서-이력테이블

         (섹션 본문 그대로)

[근거]   2026-0710-ERP-어댑터-v1
         · table:pj_plan_mst          후속 3건 — 이 부분은 갱신됐을 수 있음
         · api:/adapter/erp/plan-sync 최신
[절단]   매칭 8건 중 3건 주입. 나머지 id: 2026-06…, 2026-05…
[보기]   viewer 검색창(Ctrl+K)에 `table:pj_plan_mst` — 섹션은 오른쪽 목차
```

`[정본]` · `[범위]` 는 `ctx where` 가 그대로 준다. 좌표 여럿을 한 번에 넘길 수 있다.

```
where("table:pj_plan_mst")
```

| 줄 | 언제 |
|---|---|
| `[정본]` · `[범위]` | 관리 문서가 있을 때. **생략하지 마라** — 아래 |
| `[보기]` | 항상. 사용자가 그 자리를 직접 열 수 있어야 한다 |
| `[좌표]` | 항상. alias 를 바꿨으면 그것도 |
| `[상태]` | 관리 문서가 있을 때. 섹션 본문을 그대로 싣는다 |
| `[근거]` | 작업 기록을 실을 때 (관리 문서 없거나 "왜"가 필요할 때) |
| `[절단]` | 주입하지 않은 매칭이 있을 때 |
| `⚠ 파생 남음` | `ctx where` 가 그렇게 답했을 때. 생략하면 안 된다 |

## 범위를 밝힌다 — 생략하면 오해가 남는다

**주입 단위는 섹션 하나다.** 좌표 이름과 본문만 내면 읽는 쪽은 그것을
*"그 좌표에 관한 것이 전부"* 로 읽는다. 실제로 안 실은 것이 셋 있다.

| 안 실은 것 | |
|---|---|
| 그 문서의 다른 섹션 | 테이블정의서에 테이블이 수십 개 있다 |
| 그 좌표를 건드린 작업 기록 | *"왜 그렇게 됐나"* 는 필요해질 때 여는 것이다 |
| 등록부에 안 걸리는 관련 좌표 | 요청한 좌표만 다룬다 |

`ctx where` 가 `** 사실상 비어 있다` 라고 하면 **그 줄을 그대로 옮겨 적는다.**
빈 섹션은 주입이 성공하고 내용이 없는 상태다 — 밝히지 않으면 읽는 쪽이
*"정의가 없다"* 를 *"제약이 없다"* 로 바꿔 읽는다.

## 무엇을 하지 않는가

- **작업 기록을 기본으로 넣지 않는다.** 관리 문서 섹션이 현재 상태이고, *"왜 이렇게 됐나"*
  는 필요해질 때 여는 것이다. 섹션의 변경 줄이 어느 기록을 볼지 알려준다
- **문서를 고치지 않는다.** 읽기만 한다. 쓰기는 `cdp-save` 의 일이다
- **좌표를 추측하지 않는다.** 인자로 받은 것만 다룬다

# 실사용 예시

## 예시 1 — 좌표 하나

### 사용자

> `table:pj_plan_mst` 지금 어떻게 돼 있어?

### 0. 최신 확인

```
sync()
차이    받을 것 0건 · 보낼 것 2건        ← 받을 것이 없다. 그대로 간다
```

### 1~3. 주입

```
where("table:pj_plan_mst")
table:pj_plan_mst
  문서   docs/테이블정의서.md
  섹션   ## pj_plan_mst
  상태   반영 2026-0428-계획서-이력3종
  작업   3건
    2026-04-28  2026-0428-계획서-이력3종
    2026-03-25  2026-0325-테이블-일괄생성
    2026-03-24  2026-0324-운영위심의-스키마
```

섹션 본문을 그대로 낸다.

```
【주입 — table:pj_plan_mst】
  정본   docs/테이블정의서.md  ## pj_plan_mst
  상태   최신 (파생 남음 없음)

  ## pj_plan_mst — 계획서마스터
  (섹션 본문 …)
```

## 예시 2 — alias 로 물었을 때

### 사용자

> 계획서마스터 상태 좀 보여 줘

```
match(["계획서마스터"])
계획서마스터  ->  table:pj_plan_mst  (alias · _vocab.md:27)
```

**바꿨다는 사실을 출력에 적는다.**

```
【주입 — table:pj_plan_mst】  ("계획서마스터" 를 정본으로 바꿨습니다)
```

적지 않으면 사용자는 자기가 부른 이름이 정본인 줄 안다. 그리고 다음에도
그 이름으로 부른다.

## 예시 3 — 파생이 남아 있을 때 (**가장 중요**)

```
where("table:hr_ext_emp_mst")
table:hr_ext_emp_mst
  문서   docs/테이블정의서.md
  섹션   ## hr_ext_emp_mst
  상태   파생 남음 — 작업 2건  (ctx apply table:hr_ext_emp_mst)
```

```
【주입 — table:hr_ext_emp_mst】
  ⚠ **이 섹션은 아직 안 채워진 상태입니다.** 2건이 남아 있습니다 —
     2026-09-02  BZA021 외부 심의위원 …
     2026-09-03  …

  아래 섹션 내용은 그 2건이 빠진 상태이므로, 설계 근거로 쓰기 전에
  두 작업 기록을 확인하는 것이 좋습니다.

  ## hr_ext_emp_mst — 외부인원마스터
  (섹션 본문 …)
```

**안 채워진 섹션은 낡은 것보다 나쁘다.** 낡은 문서는 날짜가 낡았다고
말해 주지만, 안 채워진 섹션은 **최신인 척한다** — 확신 있게 틀린 답을 준다.

## 예시 4 — 미등재 좌표

### 사용자

> `table:pj_trip_photo_list` 어떻게 돼 있어?

```
match(["pj_trip_photo_list"])
  pj_trip_photo_list  ->  (미등재)  _vocab.md 에 없습니다
```

```
【주입 — table:pj_trip_photo_list】
  ⚠ **_vocab.md 에 없는 이름입니다.** 좌표가 아직 아닙니다.
     이 이름으로 작업 기록을 남기면 커밋이 막힙니다 —
     먼저 어휘에 등재해야 합니다.
```

**`ctx where` 로 확인하지 마라.** 등재되지 않은 좌표에도 답을 준다 —

```
where("table:pj_trip_photo_list")
  문서   docs/테이블정의서.md
```

## 도구가 없을 때

**에이전트는 이 절을 쓸 일이 없다.** `cdp` 서버가 붙어 있으면 본문 그대로 부른다.
여기는 **커밋 훅**과 **사람이 터미널에서 칠 때**를 위한 것이다.

`<repo>` 는 지식 레포 경로, `ctx` 는 `<repo>/bin/ctx` — **Node 가 없어도 돈다**
(없으면 `cdp.exe` 로 넘어간다 · 작업환경 §3.1).

| 본문 | 터미널 |
|---|---|
| `match(["a","b"])` | `ctx match "a" "b"` |
| `where("screen:HRC043")` | `ctx where screen:HRC043` |
| `section("screen:HRC043")` | `ctx where` 뒤에 그 섹션을 연다 — **도구 쪽이 한 번에 준다** |
| `apply("screen:HRC043")` | `ctx apply screen:HRC043` |
| `derive()` | `ctx derive` |
| `check()` | `ctx check` |
| `sync()` | `ctx sync` |
| `search("말")` | `ctx search "말"` |

**`cdp` 가 안 붙어 있으면 그것부터 고친다.** `ctx setup <작업레포>` 가
`.mcp.json` 을 쓰고, Claude Code 를 다시 켜면 `/mcp` 에 `cdp` 가 뜬다.
붙지 않은 채로 bash 로 `ctx` 를 부르는 것은 **되기는 하지만 정상이 아니다** —
그 상태에서는 도구 명함이 없어서 무엇을 언제 부를지가 이 문서에만 있다.
