# cdp-rebuild — 어긋난 관리 문서를 원천에서 다시 세운다

```
① 진단       drift — 근거 없음 · 복제 · 비대 · 일지형 · 좌표 없는 기록. 순서를 정한다
② 원천 채우기  근거 없음 → 인용한 기록이 있으면 좌표정정 · 없으면 스냅샷(서버가 원문 그대로)
③ 좌표 보완   좌표 없는 기록 → 묶음마다 좌표정정 초안 → 승인 → 기록 save
④ 재유도     복제 · 비대 · 일지형 묶음 — 모으기 → 다시 쓰기 → 견주기(사라지는 사실) → 판정 → dryRun · 승인 → 재큐레이션 save
⑤ 끝 보고     진단 합계 전 → 후 · 남은 것
```

**큐레이터만 쓴다.** `drift` 도구가 안 보이거나 `E_FORBIDDEN` `need: curate` 가 오면 멈추고 그렇게 말한다.

**cdp-curate 와 무엇이 다른가.** cdp-curate 는 **아직 반영 안 된 기록**(대기열 · 미반영)을 다룬다. 이 스킬은 **반영된 뒤에 시간이 지나며 어긋난 정본**을 다룬다 — 미반영이 0 이어도 생긴다. 대기열이 남아 있으면 그것부터(cdp-curate) — 대기 기록이 정본보다 늦으니 재유도의 원천이 덜 찬 것이다.

**섹션을 쓰는 규칙은 cdp-curate ⑤ 그대로다**(정본 한 곳 · 홀로 선다 · 현재형 · 경과 · 기준선 블록 밖 · 종류별 모양). 여기 다시 적지 않는다. 승인 게이트 · 충돌 · 끝 보고의 커밋 · 미러도 cdp-curate · cdp-save 그대로다.

인자 — `cdp-rebuild <레포> [문서 · 좌표 …]`. 없으면 ① 부터 레포 전체.

## ① 진단

```
drift({ repo })                         # 합계 · 신호가 있는 섹션(200까지) · 좌표 없는 기록(50까지)
drift({ repo, doc: "docs/팩터정의서.md" })   # 문서 하나
drift({ repo, coord: "factor:A" })        # 섹션 하나와 그 복제 짝
```

| 신호 | 뜻 | 다루는 곳 |
|---|---|---|
| `unsourced` | 그 좌표를 건드린 기록 · 스냅샷 · 기준선이 없다 — **기록만 옮겨 다시 세우면 사라진다** | ② |
| `linked` (unsourced 안) | 근거는 없는데 본문이 기록을 인용한다 — 그 기록이 좌표만 빠뜨렸다 | ② 좌표정정 |
| `unreachable` | 좌표 0 · 좌표정정 없는 사람의 기록 — 정본과 영영 만나지 않는다 | ③ |
| `duplicated` | 같은 산문 줄이 다른 섹션에도 — 짝 좌표. 하나만 고쳐진다 | ④ |
| `oversize` | 대장 40줄 · 정의 25줄을 넘는다(등록부 「종류」 칸 · 모르면 40) — 경위 · 논의가 쌓였다 | ④ — 대장이면 **경위 이관**(아래) |
| `big` | 대상 · 서술 섹션이 150줄을 넘는다 — 주입이 무겁다 | 하위 좌표로 쪼갤 안을 사람에게(cdp-registry 행 · 새 섹션) |
| `diary` | 날짜별로 덧붙인 일지형 줄 | ④ |

**순서는 ② → ③ → ④ 다.** ④ 의 「사라지는 사실」 은 원천과 견주는 것이라 원천이 덜 차 있으면 멀쩡한 사실이 사라질 것으로 보인다. 진단 결과를 표로 보이고(문서별 신호 수 · 큰 것 다섯) 어디부터 할지 승인받는다. 다 하려 하지 않는다 — 문서 하나 · 묶음 하나씩.

## ② 원천 채우기 — 근거 없는 섹션

**(가) `linked` 가 있으면 — 그 기록의 좌표정정.** 섹션이 `[기록](../work/<id>.md)` 을 인용하는데 그 기록의 `touches` 에 이 좌표가 없다. 스냅샷보다 낫다 — 진짜 출처(사람의 기록)가 남는다. 쓰는 법은 ③ 과 같다(좌표정정 기록 · `supersedes` · touches 는 빠진 좌표만).

**(나) 없으면 — 스냅샷.** 서버가 섹션 원문을 그대로 기록 하나로 뜬다. **네가 본문을 쓰지 않는다** — 원천층에 합성이 들어가면 그 위의 재유도가 지어낸 것을 원천으로 삼는다.

```
save({ repo, work: { id: "<YYYY-MMDD>-스냅샷-<주제>", title: "정본 스냅샷 — <문서> n개", date: "<지금>", body: "<왜 — 한 문단>" },
       snapshot: [{ coord: "biz:현행" }, …], dryRun: true })
```

- 좌표만 보낸다(200 개까지) — 날짜(섹션 줄의 마지막 커밋) · 출처(`docs/<문서>@<sha>#<헤딩>`) · 본문은 서버가 짓는다. `work` 는 **봉투**다 — `touches` 없이(서버가 `touchesEmpty` · 태그 `snapshot` 을 붙인다).
- 다른 쓰기(`sections` · `curates` · `baseline` · `managed` · `edits`)와 섞지 않는다.
- 근거가 이미 있는 좌표는 서버가 건너뛴다(`snapshotSkipped`). 스냅샷은 대기열에 서지 않는다 — 이미 섹션에 있는 원문이다.
- 셸이면 `ctx rebuild snapshot --server <주소> --repo <레포> [--doc <문서>] [--all]` — 좌표를 진단에서 고른다(기본은 `linked` 를 빼고).
- 판정표 — 뜰 좌표 · 건너뛸 좌표(`linked` → 좌표정정으로) · 한 줄 사유. dryRun 의 `snapshots` 를 보이고 승인받는다.

## ③ 좌표 보완 — 좌표 없는 기록

`drift` 의 `unreachable`(좌표 0 · 좌표정정 없음). 옛 문서 편입(STATE · specs · wiki)이 대부분이다. **원 기록은 고치지 않는다**(불변) — 빠진 좌표만 단 **좌표정정 기록**을 낸다. 규약은 cdp-save 「정정」 그대로:

| 필드 | 값 |
|---|---|
| `id` | `<원 id>-좌표정정` |
| `title` | `[정정] <원 제목> — 좌표 보완` |
| `date` | **원 기록의 날**(오늘이면 그 사이 같은 좌표의 기록과 선후가 뒤집힌다) |
| `touches` | 빠졌던 좌표만 — 판정 기준은 cdp-save ② 「이 기록이 바꾼 것만」(참조 · 언급은 X) |
| `supersedes` | `<원 id>` |
| 본문 | 무엇이 왜 빠졌나 한 줄 + 원 기록 링크. **원문을 다시 싣지 않는다** |

1. **묶는다** — 주제 · 날짜가 가까운 것 20건 안팎. `work({ id })` 로 하나씩 읽는다.
2. **기록마다 하나** — 「좌표 n개」 · 「옮길 사실 없음(회의 잡담 · 버린 안 · 사전 지식)」 · 「모름」. 옮길 사실이 없으면 정정하지 않는다 — 그 기록은 큐레이터의 `keep` 거리다(이미 전환 기록이 keep 으로 뒀으면 그대로). 모르면 건너뛴다 — **틀린 좌표는 없는 좌표보다 나쁘다**(그 좌표를 찾는 사람에게 무관한 기록을 내민다).
3. **판정표**(아래 모양) → 승인 → 기록마다 `save`(writer 와 같은 기록 save — `dryRun` 먼저). 미등재 좌표면 `vocab` 에 같이.
4. 승인된 좌표정정은 보통의 기록이라 **대기열에 선다** — 그 좌표의 섹션에 미반영으로 실린다. 묶음이 끝나면 cdp-curate 로 반영하거나 ④ 로 이어 간다.

```
【좌표 보완】 묶음 2/9 — 2026-08 Dagster 운영 기록 18건
  기록                                         좌표                              까닭
  2026-0829-이집이지-Dagster-오케스트레이션-현황    job:ingest_daily · sensor:sla     현황 표가 두 대상의 스케줄을 정의한다
  2026-0830-회의-파이프라인-재기동                 (옮길 것 없음 — keep 거리)            장애 대응 논의 · 결론은 위 기록
  2026-0831-센서-임계-검토                        (모름 — 건너뜀)                      어느 센서인지 본문에 없다
승인하시면 좌표정정 기록 n건을 남깁니다.
```

## ④ 재유도 — 복제 · 비대 · 일지형

**단위는 좌표 묶음**이다 — 문서 하나 · 복제 짝 한 가족(`drift({ coord })` 가 짝을 낸다) · 사람이 고른 좌표들. 섹션 20 안팎.

**① 모은다** — 묶음의 좌표마다

```
section({ repo, coord })      # 지금 content · applied(잠금 값) · 기준선 · refs · pendingRecords
where({ repo, coord, limit: 50 })   # 그 좌표를 건드린 기록 전부(판정 무관)
work({ repo, id })            # 오래된 것부터 — 스냅샷(`[스냅샷]`) · 좌표정정도 원천이다
```

**② 다시 쓴다** — cdp-curate ⑤ 의 규칙으로, **원천에 있는 것만**. 지금 섹션은 참고이지 원천이 아니다.

- **복제 가족** — 같은 결정 · 함정이 여러 섹션에 있으면 **정본 자리를 하나 정한다**(그 사실을 가장 오래 책임지는 대상 — cdp-curate 「정본 자리」). 나머지 섹션은 한 줄 + `` `정본 좌표` `` 로 건다. 가족 전체를 덮는 자리가 없으면(카테고리 여섯이 같은 결정을 나눠 가진다) 넓은 좌표를 세운다 — 새 좌표 `vocab` + 그 섹션(등록부에 안 걸리면 cdp-registry 「행 더하기」). 가까운 가족 하나에 몰아 쓰지 않는다.
- **비대 · 일지형** — 경위 · 논의 · 날짜별 덧붙임은 기록의 것이다. 섹션에는 지금의 상태(값 · 규칙 · 예외 · 결착된 판단)만 남기고 경과 한 줄씩으로 출처를 건다.
- **복제가 아닌 반복** — 「실측은 [기록](…)」 같은 근거 가리킴 · 값 표의 같은 행 · 레포 규약 줄(`**SoT**` 가리킴처럼 넓게 반복되는 줄)은 고치지 않는다. 진단도 세지 않는다.

**대장의 경위 이관** — 대장(이슈 · 위험)은 표 · 결정 · 상태 · 결론이다. 쌓인 검토 · 판단 근거 · 단계 결과는 **새 작업 기록 하나에 원문 그대로** 옮기고(태그 `경위이관` · 그 이슈 좌표), 정책 · 규칙처럼 지금도 쓰는 내용은 그 사실을 오래 책임지는 정본 섹션(없으면 새 좌표)으로 원문 그대로 옮긴다. 기록을 먼저 save 하고 그다음 큐레이션 — 그래야 「사라지는 사실」 검사가 옮긴 줄을 그 기록에서 찾는다. 대장에는 정본 좌표 · 경위 기록 링크 한 줄과 **지금으로 고친 상태** 줄.

**③ 견준다** — 섹션마다 지금 `content` ↔ 다시 쓴 `body` diff, 그리고 **「사라지는 사실」** — 지금 섹션에 있는데 다시 쓴 섹션에도 · 어느 원천(기록 · 스냅샷 · 기준선)에도 없는 문장. 하나라도 있으면 **그 섹션은 다시 쓰지 않는다** — 원천이 덜 찼다. ② 로 돌아가 스냅샷부터 뜬다(사라질 뻔한 사실이 원천이 된다).

**④ 판정** — 섹션마다 `바꿈` · `그대로`(다시 쓴 것이 나아지지 않았다) · `보류`(사라지는 사실 · 확신 없음).

**⑤ 남긴다 — 재큐레이션.** cdp-curate ⑦ 의 save 와 같은 모양이다 — 큐레이션 기록 하나 · `curates` 에 묶음의 원천 기록 전부(`verdict: reflect` · `into` 는 그 기록이 쓰인 좌표 — 판정된 기록도 다시 판정한다 · **가장 늦은 판정이 이긴다**) · `sections`. 차이는 둘:

- `tags: ["rebuild"]` — 이력에서 「리빌딩으로 다시 쓴 섹션」 을 가른다.
- 본문 끝에 **진단 합계 한 줄** — `진단(전): 근거 없음 a · 복제 b · 비대 c · 일지형 d · 좌표 없는 기록 e` — 다음 리빌딩이 「지난번보다 늘었다」 를 계산한다.

```
【재유도】 factor 카테고리 가족 — 섹션 7 · 원천 기록 9 · 스냅샷 2
  정본   투자자문업 비해당 결정(등급 밴드 유지 · 값만 표시 I · 근거 신청서 §3.1) → factor:카테고리-공통 (새 좌표)
         factor:A · C · D · E · J · K → 한 줄 + `factor:카테고리-공통`
  섹션           판정    diff           사라지는 사실
  factor:A      바꿈    -6줄 +1줄       없음
  factor:I      그대로  —              —
  factor:J      보류    -4줄            「J 는 2026-09 부터 분기 갱신」 — 원천 없음 → 스냅샷부터
【dryRun】 통과 · warnings 그대로
승인하시면 커밋합니다.
```

## ⑤ 끝 보고

- `drift({ repo })` 의 합계 **전 → 후** · 남은 것 상위 다섯.
- 남긴 것 — 스냅샷 n · 좌표정정 n · 재큐레이션 기록과 바뀐 섹션 · 새 좌표.
- 보류한 섹션과 까닭 · 모름으로 건너뛴 기록(작성자에게 물을 것).
- 대기열(`brief` 의 `curation.queue`) — 좌표정정이 세운 대기가 있으면 cdp-curate 로 이어 간다고 말한다.

## 하지 않는 것

| | 어디로 |
|---|---|
| 아직 반영 안 된 기록(대기열 · 미반영) | cdp-curate |
| 스냅샷 본문을 쓰거나 고치기 | 없다 — 서버가 섹션에서 뜬다 |
| 원 기록 고치기 · 지우기 | 없다 — 좌표정정 기록 |
| 등록부 행 · 문서 이름 · 합치기 · 지우기 | cdp-registry |
| 기준선 블록 안 · 코드 · DB 와 어긋난 값(D6) | 프로젝트의 생성기(기준선 save) |
| 레포를 통째로 다시 세우기 | admin — 먼저 ② 로 원천을 채운 뒤 `ctx repo new --records-from`(스냅샷도 옮긴다) |
| 일정으로 돌리기 | 하지 않는다 — 다시 쓰기는 승인이 있어야 한다. 진단은 화면 · `brief` 에 늘 있다 |
