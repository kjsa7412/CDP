# cdp-push — 이 세션이 만진 것만 올린다

```
① 대상 선별   이 세션이 만든·고친 파일.  세션 밖은 건드리지 않는다
② 레포 유도   경로에서 위로 올라가 .git 을 만나면 그 레포다.  목록이 없다
③ 제외        자격증명·빌드 산출물.  세션이 만졌어도 뺀다
④ 스테이징 검사  staged 가 ① 과 같은가.  다르면 내린다
⑤ 커밋·push   레포별로.  원격이 없으면 커밋까지
⑥ 보고        레포별 결과 · 건너뛴 것
```

**이 스킬은 기록하지 않는다.** 작업 기록과 관리 문서 갱신은 `cdp-save` 가 한다.
둘을 한 스킬로 합치면 한쪽이 죽어도 **다른 쪽이 살아 있어서 죽은 줄 모른다.**

---

## ① 대상 선별 — 세션이 만진 것만

**이 대화의 도구 호출 이력에서** `Write` · `Edit` · `NotebookEdit` 로 만들거나 고친
파일, 그리고 `Bash` 로 생성·이동·리다이렉트한 파일을 **전부 열거한다.**

```
⚠  git add -A  ·  git add .  ·  git add <디렉터리>   전부 금지
```

**정확한 경로만 스테이징한다.** 이유는 편의가 아니다 —

| 세션 밖 dirty 의 정체 | |
|---|---|
| 다른 세션의 미완성 작업 | 올리면 남의 반쯤 된 것이 원격에 올라간다 |
| 사람이 손으로 고쳐 두고 안 올린 것 | 올릴 때가 아니라고 판단한 것이다 |
| 린터·포매터·빌드가 건드린 것 | 의도가 없다 |
| 도구가 남긴 로그·캐시 | 애초에 커밋 대상이 아니다 |

**넷 다 "내가 안 만졌다"는 하나로 갈린다.** 그래서 기준이 하나다 —
**이 세션이 만졌는가.**

확실하지 않은 파일은 **제외하고 보고한다.** *"이건 세션 변경이 아닌 듯해 뺐습니다."*
빼먹은 것은 다음에 올리면 되지만, **잘못 올린 것은 남의 눈에 이미 들어갔다.**

### 사용자가 "전부 올려" 라고 하면

**하지 않는다.** 이 스킬은 **관리 중인 레포를 훑는 도구가 아니다.**
전부를 올리는 순간 위 표의 넷이 함께 올라가고, 그러면 `git add -A` 를 금지한 것이
무의미해진다. 범위를 넓히면 그 금지가 사라진다.

대신 **무엇이 dirty 인지 보여주고 사람이 고르게 한다.**

```
git -C <repo> status --short
```

## ② 레포 유도 — 목록이 없다

각 파일 경로에서 **위로 올라가며 `.git` 을 처음 만나는 디렉터리**가 그 파일의 레포다.

```
…/myproj_web/src/routes/apt.js   →  …/myproj_web
…/myproj_data/docs/RUNBOOK.md    →  …/myproj_data
/tmp/scratch.txt                 →  레포 밖 → 건너뛰고 보고
```

**레포 목록을 두지 않는 이유** — 세션은 자기가 무엇을 만졌는지 이미 안다.
목록을 따로 적어 두면 그 순간부터 **둘이 어긋날 수 있고, 어긋나도 조용하다.**
목록에서 빠진 레포는 출력에 이름조차 안 나오므로 **누락이 성공처럼 보인다.**

| | |
|---|---|
| `.git` 이 **파일**이다 | worktree 다. 정상이고 그대로 그 레포로 다룬다 |
| 레포 밖 | 커밋할 곳이 없다. **건너뛰고 반드시 보고한다** |
| 한 레포도 안 나옴 | 올릴 것이 없다. 그렇게 말하고 끝낸다 |

## ③ 제외 — 세션이 만졌어도 뺀다

```
.env  .env.*  *.key  *.pem  *.p12  *.keystore  credentials*  *secret*
node_modules/  __pycache__/  .venv/  dist/  build/  .DS_Store  *.log
```

**자격증명은 세션이 만들었어도 올리지 않는다.** 한 번 push 된 비밀은 이력에서
지워지지 않는다 — 되돌린 커밋에도 남는다.

제외한 것이 있으면 **무엇을 왜 뺐는지 말한다.** 조용히 빼면 사용자는 올라간 줄 안다.

`.gitignore` 가 이미 막고 있어도 **이 목록을 따로 본다.** ignore 규칙은 레포마다
다르고, 없는 레포가 하나만 있어도 사고가 난다.

---

## ④ 스테이징 검사

```
git -C <repo> add <정확한 경로들>
git -C <repo> diff --cached --stat
```

**staged 목록이 ① 과 같은지 눈으로 대조한다.** 다르면 —

```
git -C <repo> restore --staged <목록 밖 경로>
```

`git add <경로>` 를 정확히 줘도 목록 밖이 딸려 오는 경우가 있다 — 디렉터리를 준 경우,
`.gitignore` 가 예상과 다른 경우, 심볼릭 링크. **그래서 넣고 나서 다시 본다.**

## ⑤ 커밋 · push

```
git -C <repo> commit -m "<한 줄 요약>"
git -C <repo> push
```

| 상황 | |
|---|---|
| **원격 없음** | 커밋까지 하고 *"원격이 없어 push 하지 않았다"* 고 **말한다.** 실패가 아니다 |
| **push 거부 (non-fast-forward)** | 여기서 멈춘다. `git pull --ff-only` 를 권하고 **자동으로 merge·rebase 하지 않는다** |
| **훅이 커밋을 거부** | 고치고 다시 커밋한다. `--no-verify` 로 넘기지 마라 |
| 브랜치가 `main`·`master` | 그대로 올린다. 브랜치 전략은 이 스킬이 정하지 않는다 |

### 지식 레포가 대상에 들어 있으면

**대개는 이미 올라가 있다.** `cdp-save` 가 커밋하고 push 까지 한다. 그때는
여기서 올릴 것이 없고, 그렇게 말하면 된다 — 실패가 아니다.

남아 있다면 `cdp-save` 의 push 가 거부됐거나(non-fast-forward) 원격이 없었던
것이다. **앞의 것이면 여기서도 거부된다 — `git pull --ff-only` 를 권하고 멈춘다.**

다만 **이 스킬이 지식 레포에 기록을 만들지는 않는다.** 기록 없이 push 만 하면
관리 문서가 갱신 안 된 채 올라갈 수 있다 — 그건 `ctx check` 가 커밋 때 막는다.

---

## ⑥ 보고

```
myproj_web     3 files   a1b2c3d   push 완료
myproj_data    1 file    e4f5a6b   push 완료
myproj_infra   2 files   9c8d7e6   커밋만 (원격 없음)

건너뜀  /tmp/scratch.txt          레포 밖
제외    myproj_web/.env.local     자격증명
```

**건너뛴 것과 제외한 것을 반드시 같이 낸다.** 올라간 것만 보고하면 사용자는
전부 올라간 줄 안다 — **누락은 소리를 내지 않는다.**

---

## 이 스킬이 하지 않는 것

| | 어디로 |
|---|---|
| 작업 기록 · 관리 문서 갱신 | `cdp-save` |
| 밖에서 온 문서 편입 | `cdp-import` |
| 관리 문서만 고치기 | `cdp-edit` |
| 관리 중인 레포 전체 훑기 | **아무 데도.** 그런 도구를 두지 않는다 |
| 브랜치 만들기 · PR 열기 | 사람이 한다 |

**커밋·push 는 지식 공유와 다른 일이다.** 이 스킬은 좌표를 보지 않고, 지식 레포가
어디인지 알 필요도 없다. 만진 파일이 어디 있었는지만 안다.
