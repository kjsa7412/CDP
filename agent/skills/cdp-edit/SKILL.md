# cdp-edit — 지시로 관리 문서를 고치고, 그 지시를 남긴다

```
① pull        쓰기 전에 받는다.  실패하면 시작하지 않는다
② 현재 상태    고칠 섹션을 읽는다 (cdp-load 와 같다)
③ 지시 확인    어긋나면 되묻는다.  **그대로 실행하지 않는다**
④ 문서 수정    관리 문서 섹션
⑤ 작업 기록    **지시가 곧 본문이다**
⑥ 한 커밋      작업 기록 1 + 관리 문서 N.  push 는 하지 않는다
```

---

## 왜 기록이 필요한가

관리 문서만 고치면 **출처 없는 변경**이 된다.

```
$ git log -p docs/화면설계서.md
  + 사진 첨부는 10MB 까지.
```

6개월 뒤 "왜 10MB 인가" 를 물으면 답할 것이 없다. 커밋 메시지 한 줄은
diff 를 설명할 뿐 **왜 그렇게 정했는지**를 담지 못한다. 그것을 담는 자리가
`work/` 이고, 그것이 이 레포가 두 층인 이유다.

  docs/   지금 어떤 상태인가   ← 고친다
  work/   무슨 일이 있었나     ← **지시가 그 사건이다**

그리고 실무적으로도 필요하다. 섹션의 `<!-- applied: … -->` 는 작업 기록을
가리키는데, 가리킬 기록이 없으면 섹션은 옛 기록을 가리킨 채 남는다 —
내용은 새것인데 출처는 옛것을 가리키는 상태다.

---

## ① pull

```
git -C <repo> pull --ff-only
```

실패하면 멈춘다. 남이 이미 그 섹션을 고쳤을 수 있다.

---

## ② 현재 상태를 읽는다

```
<repo>/bin/ctx where <좌표>
```

섹션 본문과 `applied`, 그리고 **파생이 남아 있는지**를 본다.

파생이 남아 있으면 사용자에게 먼저 알린다 —

```
⚠ 이 섹션에 파생이 2건 남아 있습니다 (2026-0902 · 2026-0903).
   지시하신 수정을 그 위에 얹으면 남은 것이 묻힙니다.
   먼저 cdp-managed 로 채울까요?
```

---

## ③ 지시를 확인한다 — 그대로 실행하지 않는다

**지시가 현재 문서와 어긋나면 되묻는다.**

| 어긋남 | 어떻게 |
|---|---|
| 지시가 이미 적힌 것과 다르다 | 무엇이 맞는지 묻는다. 조용히 덮지 않는다 |
| 지시가 좌표를 특정하지 않는다 | `ctx match` 로 후보를 보이고 고르게 한다 |
| 지시가 등록부 밖 문서를 가리킨다 | 회의록·일정 등은 좌표-섹션이 없다. 그냥 고치고 기록은 남기지 않는다 |
| 사실 관계를 모른다 | **묻는다.** 문서는 정본이라 틀리면 조용히 퍼진다 |

지시가 **아직 결정이 아닌 경우**도 있다. "이렇게 하면 어떨까?" 는 지시가
아니다. 그때는 고치지 말고 위험및이슈관리대장으로 보낸다.

---

## ④ 문서 수정

해당 섹션만 고친다. `<!-- applied: … -->` 는 ⑤ 의 기록 id 로 바꾼다.

**섹션 밖을 건드리지 마라.** 지시 하나가 문서 여러 곳을 바꿔야 한다면 그것은
좌표가 여럿인 것이고, `touches` 에 전부 적는다.

---

## ⑤ 작업 기록 — 지시가 곧 본문이다

```
<repo>/work/YYYY-MMDD-slug.md
```

`date` 는 **지시받은 날**이다. 그날 그 결정이 있었다.

```markdown
---
id: 2026-0908-EXD020-첨부용량
title: EXD020 사진 첨부 용량 10MB — 문서 반영
date: 2026-09-08
author: kjsa
touches:
  - screen:EXD020
tags: [문서반영]
---

# EXD020 사진 첨부 용량

## 지시

> 사진 첨부 용량은 10MB 로 해줘. WAS 업로드 상한이 그거라서 20MB 로
> 적어 놔도 어차피 안 올라가.

kjsa, 2026-09-08.

## 반영

`docs/화면설계서.md` `## EXD020` 의 첨부 표에서 용량을 20MB → 10MB.

## 확인한 것

기존 섹션에 20MB 로 적혀 있었다. 어디서 온 값인지 `2026-0908-사진첨부-용량`
을 확인했고, 회의에서 나온 말을 옮긴 것이지 WAS 설정을 본 것이 아니었다.
```

### 세 대목이 필요하다

| | |
|---|---|
| **지시** | **말한 그대로 인용한다.** 요약하지 마라 |
| **반영** | 어느 문서 어느 섹션을 어떻게 바꿨나 |
| **확인한 것** | 되물은 것, 근거를 확인한 것, 판단한 것 |

**지시를 요약하지 않는 이유** — 말의 표현 자체가 맥락이다. "20MB 로 적어
놔도 어차피 안 올라가" 는 *제약이 어디서 왔는지*를 담고 있고, 그것을
"10MB 로 변경" 으로 줄이면 6개월 뒤 "왜 10인가" 에 다시 답할 수 없다.

`author` 는 **지시한 사람**이다. 문서를 고친 것은 에이전트지만 정한 것은
사람이다.

### 지시가 여럿이면

한 세션에서 여러 섹션을 고치라는 지시를 받았다면 —

- **한 주제면 기록 하나.** `touches` 에 좌표를 여럿 적는다
- **다른 주제면 기록을 나눈다.** 6개월 뒤 따로 찾을 것이면 따로다

## ⑥ 한 커밋

```
git -C <repo> add work/<id>.md docs/<...>.md
git -C <repo> commit -m "<제목>"
```

**push 는 하지 않는다.**

---

## 이것을 건너뛰면 무엇이 깨지나

관리 문서만 고치고 기록을 안 남기면 `ctx check` 는 **아무 말도 하지 않는다.**
파생 누락 검사는 작업 기록을 기준으로 도는데, 기록이 없으면 기준이 없다.

**즉 이 절차는 기계가 막아 주지 않는다.** 그래서 skill 로 둔다 — 2층이
못 잡는 자리이므로 1층이 지켜야 한다.
