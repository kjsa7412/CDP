# cdp-managed — 파생이 남은 섹션을 채운다

**"밀림"이라는 상태는 없다.** 지식공유문서를 남기면 관리 문서 파생은 필수이고,
안 했으면 그것은 상태가 아니라 **오류**다 — `ctx check` 가 커밋을 막는다.
이 skill 은 **그 오류를 치운다.**

파생이 안 된 섹션은 낡은 것보다 나쁘다 — 낡은 문서는 날짜가 낡았다고
알려주는데, 안 채워진 섹션은 **최신인 척한다.** 읽는 사람이 확신을 갖고
틀린 상태로 설계한다.

```
① 목록      ctx derive
② 고를 것    자기 좌표 · 요청받은 좌표만.  전부 몰아서 하지 않는다
③ 반영      좌표 하나씩.  ctx apply 가 초안, 본문은 사람이
④ 커밋      좌표 단위로 나눈다
```

이하 `<repo>` 는 지식 레포 경로. `ctx` 는 `<repo>/bin/ctx` — Node 없어도 돈다.

> **`ctx` 호출은 MCP 도구 `cdp:*` 가 있으면 그것으로, 없으면 `<repo>/bin/ctx …` 로.
> 둘은 같은 함수다** — 결과가 바이트까지 같다(MCP 설계서 §3.3 · §10). 아래 예시는
> CLI 로 적혀 있고, 도구가 있으면 같은 이름의 도구를 부른다.
>
> | 이름이 다른 것 | 도구 |
> |---|---|
> | `ctx where <좌표>` 뒤에 섹션을 Read | `where` → **`section`**. 파일을 열지 않는다 |
>
> **`save` 도구가 있으면 서버 모드다**(§4.8). 그때는 쓰기 경로가 바뀐다 —
>
> | | `save` 없음 (모드 A) | `save` 있음 (모드 B) |
> |---|---|---|
> | 시작 | `git pull --ff-only` | **생략.** 서버가 언제나 origin HEAD 다 |
> | 고치기 | Write · Edit 로 파일에 | **메모리에 준비해 사람에게 보인다.** 파일을 안 만든다 |
> | 끝 | `git commit` → 커밋 훅이 검사 | `save({ work, sections, vocab })` **한 번.** 서버가 검사하고 커밋한다 |
> | 충돌 | 훅이 막는다 | `E_CONFLICT` 면 `section` 을 **다시 읽고 다시** 만든다 |
>
> 훅은 모드 A 에서만 돈다. 모드 B 는 클라이언트에 작업 트리가 없다.

---

## ⓪ pull 이 먼저다

> **모드 B 면 이 절은 없다.** `save` 도구가 있으면 받을 것이 없다 — 서버 트리가
> 그 레포의 유일한 작성자이고 언제나 origin HEAD 다. 다음 절로 간다.

```
git -C <repo> pull --ff-only
```

**실패하면 시작하지 않는다.** 섹션을 채우는 작업이므로 낡은 상태에서
시작하면 남이 방금 채운 것을 되돌린다.

## ① 목록

```
ctx derive
```
```
파생 남은 섹션 2곳

  api:/adapter/a10/expense-slip    작업 2건     인터페이스정의서
                                   실린 것 2026-0831-A10-결의일-기준
                                     + 2026-09-02  2026-0902-결의서-작성자고정
  code:PS130                       작업 1건     코드정의서
                                     + 2026-08-21  2026-0821-면접심사의견-개편

깨진 섹션 1곳 — 등록부가 없는 자리를 가리킨다
  screen:SEB020                    anchor-missing  화면설계서
```

**두 묶음이고 처리 방법이 다르다.**

| | 뜻 | 이 skill 이 |
|---|---|:--:|
| **파생 남음** | 그 좌표를 건드린 기록이 섹션에 안 실렸다. `applied` 가 낡았거나 아예 없다 | **한다** |
| **섹션 없음** | 등록부가 가리키는데 그 문서에 섹션이 없다 | **한다** — 만든다 |
| **문서 없음** | 등록부가 가리키는데 파일이 없다 | **한다** — 만든다 |
| **applied 깨짐** | 없는 작업 기록을 가리킨다 | **사람에게 알린다** (아래) |

> `applied` 가 낡은 것과 아예 없는 것을 **가르지 않는다.** 둘 다 파생을 안
> 한 것이고, 등급을 나누면 절반은 커밋을 막지 못한다.

### `applied 깨짐` 은 고치지 마라

`applied` 가 존재하지 않는 id 를 가리킨다는 것은 둘 중 하나다 —
**이름을 잘못 적었거나, 그 작업 기록이 지워졌다.**

어느 쪽인지 모르고 `applied` 를 바꾸면 **그 섹션의 이력이 끊긴다.**
사용자에게 그대로 알리고 판단을 받아라.

```
⛔ docs/테이블정의서.md ## rp_plnd_mst 의 applied 가
   2026-0801-계획서-초안 을 가리키는데 work/ 에 그 파일이 없습니다.
   이름 오기인지, 기록이 지워진 것인지 확인이 필요합니다.
```

## ② 무엇을 고를까

**전부 몰아서 하지 마라.** 세 가지가 걸린다.

| | |
|---|---|
| **내용을 모른다** | 남이 바꾼 테이블의 컬럼 의미를 그 작업 기록만 읽고 정확히 옮길 수 없다. 틀린 반영은 안 채운 것보다 나쁘다 |
| **충돌한다** | 20개 섹션을 한 번에 고치면 그 사이 아무도 커밋할 수 없다 |
| **검토가 안 된다** | 큰 diff 는 승인이 형식이 된다 |

그래서 **좌표를 좁게 고른다.**

| 우선순위 | |
|---|---|
| 1 | 사용자가 지정한 좌표 |
| 2 | 방금 자기가 작업한 좌표 (`cdp-save` 에서 건너뛴 것) |
| 3 | `섹션 없음` · `문서 없음` — 내용 판단이 필요 없다. **자리를 만드는 것뿐이다** |
| 4 | 남은 건수가 많은 좌표 — 오래 방치된 것 |

**5개를 넘기면 사용자에게 물어라.** *"파생이 6곳 남았습니다. 어디까지 하시겠습니까?"*

## ③ 반영 — 좌표 하나씩

### 초안 받기

```
ctx apply table:ps_ext_emp_mst
```

새 `applied` 값과 붙일 변경 줄, 그리고 **반영해야 할 작업 기록 목록**을 준다.

### 작업 기록을 읽는다

```
ctx where table:ps_ext_emp_mst
```

`applied` 이후의 기록을 **오래된 것부터** 읽는다. 순서가 중요하다 —
컬럼을 추가했다가 이름을 바꾼 경우, 최신만 읽으면 추가 사실을 놓친다.

### 섹션을 고친다

```diff
  ## ps_ext_emp_mst — 외부인원마스터
- <!-- applied: 2026-0821-면접심사의견-개편 -->
+ <!-- applied: 2026-0902-EXA021-외부심의위원 -->

  | `wrk_tp_cd` | varchar | 10 | Y | | 업무구분코드 (PS130) |

  **변경**
  · 2026-08-21 [`면접심사의견-개편`](../work/2026-0821-면접심사의견-개편.md) `wrk_tp_cd`·`tel_no` 추가
+ · 2026-09-02 [`EXA021-외부심의위원`](../work/2026-0902-EXA021-외부심의위원.md) `wrk_tp_cd` 를 선택 모달 그룹핑 키로 사용. 컬럼 변경 없음
```

| 규칙 | |
|---|---|
| **그 섹션 밖은 건드리지 않는다** | 다른 좌표를 같은 커밋에 넣으면 그 좌표를 갱신하는 사람과 충돌한다 |
| **`applied` 는 반영한 것 중 가장 최신** | 두 건을 반영했으면 뒤쪽 id |
| **변경 줄은 추가만** | 과거 줄을 지우지 않는다. 그것이 이 섹션의 이력이다 |
| **본문은 사람이 판단한다** | `ctx apply` 는 자리를 알려줄 뿐 내용을 모른다 |
| **섹션은 홀로 서야 한다** | 링크를 타고 가야 알 수 있으면 반영이 안 된 것이다. 아래 |
| **바뀐 게 없으면 그렇게 적는다** | 위 예의 "컬럼 변경 없음". 그 작업이 그 좌표를 **참조 방식만** 바꿨을 수 있다 |

### 섹션은 홀로 서야 한다

**그 섹션만 읽고 대상의 현재 상태를 알 수 있어야 한다.** 작업 기록 링크를
타고 가야 알 수 있으면 파생이 안 된 것이다.

이유는 하나다 — **주입은 섹션만 싣는다.** `cdp-load` 는 관리 문서 섹션이
현재 상태라는 전제로 돌고, 작업 기록은 기본으로 넣지 않는다. 그래서 값이
기록에만 있으면 **주입받은 쪽은 그 값이 없다고 판단하고 새로 정하려 든다.**

실제로 이렇게 새 나갔다. `2026-0831-A10-결의서-기본값` 이 지불 수단별
기본값 표를 정했는데, 파생된 섹션에 남은 것은 이 한 줄이었다.

```
결의서입력으로 넘어간다. 작성자·결의일·결제수단 기본값이 여기서 정해진다
                                          ↑ "정해진다" 만 있고 값이 없다
```

**표가 기록에만 남았다.** 그 뒤 같은 요청이 다시 왔을 때 주입은 이 한 줄을
싣고, 이미 정해진 값을 처음부터 다시 정하는 작업이 시작됐다.

**옮길 것** — 판단 · 표 · 규칙 · 값 · 제약. *"왜 그렇게 정했나"* 중 **대상의
성질이 된 것**은 전부. `ctx apply` 가 작업 기록의 목차를 보여준다.

**남길 것** — 그 결정에 이른 경위, 논의, 대안. 그것은 사건이라 기록의 것이다.

| 요약해도 되는 것 | 반드시 옮길 것 |
|---|---|
| *"현장 요청으로"* · *"협의 결과"* | **그래서 값이 무엇인가** |
| 누가 언제 무엇을 물었나 | 그 답이 만든 **규칙과 예외** |

> 변경 줄(`**변경** · 날짜 [링크]`)은 **출처 표시이지 내용이 아니다.**
> 그 줄만 붙이고 끝내면 섹션은 여전히 빈 것이다. 링크는 *"더 알고 싶으면"*
> 이고, *"알아야 하면"* 이 되면 안 된다.

### 확신이 없으면 반영하지 마라

작업 기록을 읽었는데 **섹션 본문을 어떻게 고칠지 모르겠으면** 넘긴다.

```
⚠ screen:SEC011 은 반영하지 않았습니다.
   2026-0902-연관위-readonly 가 "빈 row 판정 규칙"을 바꿨는데
   화면정의서의 어느 항목에 해당하는지 판단이 안 됩니다.
   그 작업 작성자(kjsa)가 반영하는 것이 맞아 보입니다.
```

**안 채운 채로 남는 것이 틀리게 채우는 것보다 낫다** — 안 채운 것은 검사가
알려주고, **틀리게 채운 것은 아무도 모른다.** 밀린 것은 표시가 있고,
틀리게 반영한 것은 표시가 없다 — 최신인 척한다.

## ④ 커밋

> **모드 B 에는 이 절차의 길이 아직 없다.** 여기서 멈추고 사용자에게 알린다.
>
> 이유는 `save` 의 모양이다. `work` 가 필수이고, 이미 있는 `id` 를 보내면
> `E_EXISTS` 로 거부된다 — 기존 기록은 고치지도 지우지도 않는다는 규칙이다.
> 그런데 **이 절차는 작업 기록을 만들지 않는다**(아래). 대상을 바꾼 것이
> 아니라 문서를 따라잡는 것이라서다. 둘이 맞물리지 않는다.
>
> 억지로 새 작업 기록을 지어내지 마라. **없는 사건을 만드는 것**이고,
> 그 기록의 `touches` 에 걸린 좌표는 6개월 뒤 찾는 사람에게 거짓을 말한다.
>
> 당분간은 그 레포에 셸이 있는 사람이 모드 A 로 치운다. `derive` 도구로
> **무엇이 남았는지는 모드 B 에서도 보인다** — 목록을 답에 적고 넘긴다.

**좌표 단위로 나눈다.** 한 커밋에 여러 좌표를 넣으면 되돌릴 때 통째로 되돌아간다.

```
git -C <repo> add docs/테이블정의서.md
git -C <repo> commit -m "테이블정의서 ps_ext_emp_mst 섹션 반영 (2026-0902-EXA021-외부심의위원)"
```

작업 기록을 새로 만들지 않는다 — **이 작업은 대상을 바꾼 것이 아니라
문서를 따라잡은 것이다.** 좌표가 없으므로 남길 것이 없다.

### 확인

```
ctx derive
ctx check
```

목록에서 빠졌는지 보고, `check` 가 통과하는지 본다. **push 는 하지 않는다.**

---

## 작업 기록이 없는 섹션은 목록에 안 나온다

어휘에는 있지만 아무도 작업한 적 없는 좌표의 섹션이 있다. **그것은 위반이
아니다** — 실을 것이 없으니 낼 것도 없다. `ctx derive` 는 그것을 내지 않는다.

추측으로 채우지 마라. **근거 없는 문서가 정본 자리에 앉는다.**

```
ctx derive --json    # pendingDerive[].total 이 그 좌표의 작업 기록 수다
```

## ② 순서를 정한다

**한 번에 다 하지 않는다.**

| 우선 | |
|---|---|

| ② | 방금 내가 작업한 좌표 |

| ④ | 오래 남은 것 |
