<!-- form:head -->
업무 흐름의 지금 상태. 그림이 아니라 **순서와 분기**를 적는다.

<!-- form:guide -->
**무엇** — 업무가 **누구를 거쳐 어떤 순서로** 흘러가는지, 어디서 갈라지는지를
적는다. 각 단계의 INPUT 과 OUTPUT 을 함께 둔다.
**언제** — 분석에서 AS-IS 를, 설계에서 TO-BE 를 만든다. 흐름이 바뀌면 고친다.
**누가** — 업무 담당 PL 이 현업과 확인하며 만든다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 단계 하나하나의 기능 명세 | `기능정의서` |
| 화면 동작 | `화면설계서` · `프로그램사양서` |
| **프로세스의 결함 · 개선 필요** | `위험및이슈관리대장` — 상태가 아니라 아젠다다 |

> **그림을 버리고 순서와 분기를 남긴다.** 원본은 스윔레인 흐름도 40장이었다.
> 흐름도의 값은 **누가 · 무슨 순서로 · 어디서 갈라지나** 셋이고 전부 글로
> 적을 수 있다. 레이아웃은 남길 것이 아니다.
>
> 입도는 **3단 번호**다. 4단(액티비티)은 121개로 잘고, 2단은 업무 영역에
> 가까워 `업무영역:` 축이다. 3단이 기능정의서의 중분류와 대응한다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<3단 번호> — <프로세스명>` | 필수 |
| 주체 | 이 흐름에 관여하는 역할들 | 필수 |
| INPUT · OUTPUT | 들어오는 것과 나가는 것. 문서 · 데이터 · 상태 | 필수 |
| 흐름 | **번호 목록.** 분기는 "분기 —" 로 시작하고 조건을 적는다 | 필수 |
| 연결 | 앞뒤 프로세스의 좌표 | 선택 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |

> **번호가 재부여되면 좌표가 깨진다.** 그때는 `_vocab.md` 에서 옛 번호를
> `deprecated` 로 두고 `supersededBy` 로 새 번호를 가리킨다. 지우지 않는다.

### 예시 — 1.1.1 — 과제접수

| | |
|---|---|
| 주체 | 연구원 · 과제 PM |
| INPUT | 제안서 · 연구비 산출근거 |
| OUTPUT | 접수된 연구과제 · 사전검토 대상 |

**흐름**

1. 연구원이 과제 제안 내용을 입력한다 (`기능정의서:EX-FNC-RP-01`)
2. 제안서를 붙인다 — **임시저장 상태에서는 검토 대상에 뜨지 않는다**
3. 과제 PM 이 접수를 확정한다
4. 분기 — 기본과제면 사전검토(`1.1.2`)로, 수탁·보조과제면 바로 선정심의로

**연결** — 다음은 `프로세스정의서:1.1.2` 사전검토.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 프로세스정의서

- `프로세스정의서:1.1.1` — (예시) 과제접수
  example: 서식 예시 — 지우고 시작한다
  aliases: 과제 접수, 접수 프로세스
```
