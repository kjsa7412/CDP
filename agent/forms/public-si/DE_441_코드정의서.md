<!-- form:head -->
공통코드의 지금 상태. **섹션 하나가 코드구분 하나**다 — 코드 하나하나가
아니다.

<!-- form:guide -->
**무엇** — 코드구분마다 그 안에 어떤 값이 있는지를 표로 둔다.
**언제** — 설계에서 만들고, 값이 늘거나 뜻이 바뀌면 고친다.
**누가** — 업무 담당 PL.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 어느 테이블의 어느 컬럼이 이 코드를 쓰나 | `테이블정의서` 가 `코드정의서:<구분>` 으로 가리킨다 |
| 코드 컬럼의 물리명 규칙 | `DB도메인용어정의서` |

> **코드 하나를 섹션으로 잡지 않는다.** 사람은 *"연구분류에 뭐가 있나"* 를
> 묻지 *"정책과제 코드가 어떻게 생겼나"* 를 묻지 않는다. 구분 단위면
> 181개 안팎이고, 코드 단위면 수천 개가 된다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<업무구분><구분코드> — <구분명>` (예 `EX010`) | 필수 |
| 코드 표 | 코드 · 코드명 · 사용 · 정렬 · 비고 | 필수 |
| 사용 | `Y` / `N`. **안 쓰는 코드를 지우지 않는다** — 과거 데이터가 참조한다 | 필수 |
| 비고 | 언제부터 안 쓰는지, 무엇이 따라붙는지 | 선택 |
| 연관 | 이 값에 따라 걸러지는 다른 구분을 `코드정의서:<구분>` 으로 | 선택 |
| 경과 | `**경과**` 아래 한 줄 `- 날짜 [작업 기록](../work/…) 무엇이` | 반영 때 필수 |

### 예시 — EX010 — 연구분류

| 코드 | 코드명 | 사용 | 정렬 | 비고 |
|---|---|:--:|--:|---|
| `010` | 정책과제 | Y | 1 | |
| `020` | 기본과제 | Y | 2 | |
| `030` | 수탁과제 | Y | 3 | 계약이 따라붙는다 |
| `040` | 보조과제 | N | 4 | 2026-03 부터 안 쓴다 |

**연관** — `코드정의서:EX020`(연구유형)이 이 값에 따라 걸러진다.

**경과**
- 2026-03-02 [`보조과제-종료`](../work/2026-0302-보조과제-종료.md) `040` 사용여부 `N`

> ⚠ **예시다.** 실제 섹션의 `applied` 는 서버가 쓴다. 경과의 링크는 실제 작업 기록을 가리킨다 — 여기 링크는
> 예시라 끊어져 있다.

### 예시 — 어휘

```
## 코드정의서

- `코드정의서:EX010` — (예시) 연구분류
  example: 서식 예시 — 지우고 시작한다
  aliases: 연구분류코드, 과제분류
```
