<!-- form:head -->
시스템 구성의 지금 상태. **좌표 넷을 팀이 등록한다** — 원본에 ID 가 없는
유일한 문서다.

<!-- form:guide -->
**무엇** — 서버 · DB · 소프트웨어 스택 · 외부 연계의 **구성**을 적는다.
버전과 수량이 여기 있어야 장애 때 무엇을 의심할지 정할 수 있다.
**언제** — 분석에서 초안, 설계에서 확정. 버전을 올리거나 서버를 늘리면 고친다.
**누가** — 인프라 · 아키텍처 담당.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 연계 건별 상세(테이블 · 주기 · Object) | `인터페이스정의서` |
| DB 스키마 · 컬럼 | `테이블정의서` |
| 설치 절차 | `운영자메뉴얼` |

> **다른 좌표는 문서에서 값을 뽑아낼 수 있는데 이것만 아니다.** 그래서
> `_vocab.md` 에 넷이 미리 등록돼 있다. 늘리거나 줄이려면 **어휘와 이 문서를
> 함께** 고친다.

### 고정 좌표

```
## 시스템아키텍처

- `시스템아키텍처:hw` — H/W 아키텍처
  aliases: 서버, 하드웨어, 장비 구성
- `시스템아키텍처:db` — DB 아키텍처
  aliases: 데이터베이스 구성, DB 서버
- `시스템아키텍처:sw` — S/W 아키텍처
  aliases: 소프트웨어 스택, 미들웨어, WAS
- `시스템아키텍처:link` — 데이터 연계
  aliases: 연계 구성, 인터페이스 구성, 연계 경로
```

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 | **넷 고정.** 늘리려면 `_vocab.md` 의 `## 시스템아키텍처` 도 함께 고친다 | 필수 |
| 표 | 구성 요소마다 한 행. **버전을 반드시 적는다** | 필수 |
| `link` | 경로만. 테이블 · 주기 · Object 는 인터페이스정의서다 | 필수 |
| 경과 | `**경과**` 아래 한 줄 `- 날짜 [작업 기록](../work/…) 무엇이` | 반영 때 필수 |

<!-- form:example -->
### 예시 — hw — H/W 아키텍처

| 순번 | 시스템 | 용도 | 이중화 | 망 | OS | CPU | Mem | Disk | 비고 |
|--:|---|---|:--:|---|---|--:|--:|--:|---|
| 1 | (예시) | AP #1 | O | 업무 | Amazon Linux | 4 | 16G | 200G | |
| 2 | (예시) | DB | O | 업무 | Amazon Linux | 8 | 32G | 1T | 암호화 |

> ⚠ **예시 행이다 — 지우고 시작한다.**

### 예시 — db — DB 아키텍처

| 리소스 | 시스템 | Database | Schema | User | 용도 |
|---|---|---|---|---|---|
| (예시) 운영 | EX | `exdb` | `ex` | `ex_dba` | DBA |

### 예시 — sw — S/W 아키텍처

| 구분 | 패키지 | 용도 | 버전 |
|---|---|---|---|
| WAS | (예시) Apache Tomcat | 서블릿 컨테이너 | 10 |
| Backend | (예시) OpenJDK | 런타임 | 17 |

### 예시 — link — 데이터 연계

**구성** — (예시) 외부 시스템 → ESB → 우리 DB. 건별 상세는
`인터페이스정의서` 가 갖는다. 여기는 **어떤 경로가 있는지**만 그린다.
