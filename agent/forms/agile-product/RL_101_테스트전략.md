서술형. **무엇을 어느 층에서 시험하고, 무엇이 통과해야 내보내나.**

<!-- form:guide -->
**무엇** — 테스트 피라미드 · 층별 범위 · 자동화 · E2E · 품질 게이트 · 수동 점검 · 시험 데이터.
**언제** — 첫 스프린트 전에 세운다. 결함이 운영으로 새어 나가면 회고에서 「어느 층이 잡았어야
했나」 를 묻고 그 답으로 고친다.
**누가** — QA · 리드 개발자.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 기능별 수용 기준 | `기능명세` — 시험은 그것을 덮는다 |
| CI 단계의 순서 · 막는 조건 | `개발규약` 의 CI 게이트 |
| 자원별 계약 시험의 위치 | `인터페이스명세` |
| 내보낸 판 · 알려진 문제 | `릴리스노트` |
| 시험 코드 · 시나리오 원문 | 코드 레포 |

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 피라미드 | 층마다 무엇을 · 언제 돈다. 팀이 실제로 돌리는 것만 | 필수 |
| 자동화 범위 | 무엇을 자동화하고 **무엇을 안 하나** | 필수 |
| 품질 게이트 | 숫자로. CI 가 막는 것과 사람이 보는 것을 가른다 | 필수 |
| 수동 점검 | 기기 매트릭스 · 탐색 시험 · 스토어 점검 | 조건 |
| 시험 데이터 | 개인정보를 어떻게 피하나 | 필수 |
| 결정 | 기준을 바꾼 이유는 작업 기록에 | 필수 |
| 변경 | 문서 맨 아래에 `**변경** · 날짜 [작업기록](../../work/…) 무엇이` 를 쌓는다 | 변경 시 필수 |

<!-- form:example -->
> 아래는 **권장 출발점**이다 — 팀에 맞게 고친다. 숫자(커버리지 · 성능 기준)는 팀이
> 지킬 수 있는 값으로 바꾼다. 지키지 않는 기준은 기준이 아니다.

### 예시 — 테스트 피라미드

| 층 | 무엇을 | 양 | 언제 돈다 |
|---|---|---|---|
| 단위 | 함수 · 컴포넌트 — 규칙 · 계산 · 분기 | 가장 많이 | 커밋마다 · 1분 안 |
| 통합 | API ↔ DB · 외부 연동은 테스트 더블 | 중간 | PR 마다 |
| 계약 | API 제공자 ↔ 소비자(웹 · 앱) | 자원마다 | PR 마다 |
| E2E | 핵심 사용자 흐름 · 실제 브라우저 · 기기 | 적게(열 개 안팎) | `main` 머지 · 배포 전 |
| 탐색 | 새 기능 · 접근성 · 기기 호환 — 사람이 | 기능마다 | 출시 전 |

### 예시 — 자동화 범위

- 수용 기준(Given/When/Then)의 **행마다 시험 하나** — 층은 잡을 수 있는 가장 낮은 곳
- E2E 는 **막히면 매출이 0 이 되는 흐름**만 — 가입 · 로그인 · 장바구니 · 결제 · 주문 조회
- 흔들리는 시험(flaky)은 격리하고 이슈를 연다. 다시 돌려서 초록을 만들지 않는다

### 예시 — 품질 게이트 — 내보내는 조건

| 게이트 | 기준 |
|---|---|
| 자동 시험 | 전부 통과. 격리한 시험은 담당 · 기한이 있다 |
| 커버리지 | 변경 줄 80% 이상 — 전체 숫자는 보지 않는다 |
| 성능 | (예시) 결제 API p95 300ms 이하 · 웹 LCP 2.5초 이하 |
| 접근성 | 자동 검사 위반 0 · 새 화면은 스크린리더로 한 번 |
| 보안 | 높음 이상 취약점 0 |

> ⚠ **예시 행이다 — 지우고 시작한다.** 「(예시)」 가 붙은 행만 그렇다.

### 예시 — 수동 점검 — 출시 전

| | |
|---|---|
| 기기 · 브라우저 | (예시) iOS 최신 둘 · Android 최신 셋 · Chrome · Safari · Edge 최신 |
| 탐색 시험 | 새 기능마다 30분. 찾은 것은 출시 전에 이슈로 |
| 앱 스토어 | 심사 제출 전 점검표 — 권한 문구 · 스크린샷 · 판 번호 |

> ⚠ **예시 행이다 — 지우고 시작한다.**

### 예시 — 시험 데이터

- 운영 데이터를 그대로 쓰지 않는다 — 가명화한 사본 · 시드 데이터
- 결제는 PG 의 테스트 모드와 테스트 카드로만
