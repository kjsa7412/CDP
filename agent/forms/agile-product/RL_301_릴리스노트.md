<!-- form:head -->
판(버전) 축. **사용자에게 보이는 변화**를 판마다 쌓는다 — 커밋 목록이 아니다.

<!-- form:guide -->
**무엇** — 판마다 새로 된 것 · 바뀐 것 · 고친 것 · **알려진 문제** · 지원 종료 알림.
**언제** — 판을 내보낸 날. 앱은 스토어 심사를 통과해 공개된 날.
**누가** — 그 판의 출시 담당(돌아가며). 제품 책임자가 문구를 본다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 커밋 · PR 목록 | 코드 레포의 태그 · 변경 이력 |
| 기능의 범위 · 수용 기준 | `기능명세` |
| 플래그 뒤에 숨은 미완성 기능 | `기능플래그` — 사용자에게 연 날 여기 적는다 |
| 스프린트에서 한 일 전부 | `스프린트기록` |

> **트렁크 기반에서는 배포와 출시가 다르다.** 코드는 매일 나가도 사용자는 플래그를 연
> 날 본다. 여기는 **사용자가 본 날**을 적는다 — 플래그를 전체로 연 것도 한 판처럼 적는다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<판> — <YYYY-MM-DD>`. 판은 SemVer(`v1.4.0`). 웹만 매일 나가면 날짜판(`2026.10.02`) | 필수 |
| 순서 | **새 판을 위에.** 열면 지금이 먼저 보인다 | 필수 |
| 플랫폼 · 공개 | 어느 클라이언트 · 판 · 몇 % · 전체 | 필수 |
| 새로 된 것 · 바뀐 것 · 고친 것 | **사용자의 말로.** 내부 이름 · 이슈 키만 쓰지 않는다 | 필수 |
| 알려진 문제 | 알고 내보낸 것과 고칠 판. 없으면 「없음」 | 필수 |
| 지원 종료 | API · 앱 판 · 기능을 닫는 날 | 조건 |
| 관련 좌표 | 바뀐 기능 · API 의 좌표 | 선택 |
| 변경 | 나간 뒤 고친 줄은 그 섹션 끝에 `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 변경 시 필수 |

<!-- form:example -->
### 예시 — v1.4.0 — 2026-10-02

| | |
|---|---|
| 플랫폼 | 웹 · iOS 1.4.0 · Android 1.4.0 |
| 공개 | 전체 |

**새로 된 것**
- 한 페이지 결제 — 배송지와 결제수단을 한 화면에서 고르고 바로 결제한다(`기능명세:EX-CHECKOUT`)

**바뀐 것**
- 장바구니의 쿠폰 입력이 결제 단추 위로 올라왔다

**고친 것**
- 품절 상품이 섞이면 합계가 맞지 않던 문제

**알려진 문제**
- Android 9 에서 결제수단 추가 시트가 키보드에 가려진다 — 1.4.1 에서 고친다

**지원 종료 알림** — 주문 목록 API 의 오프셋 페이지는 2026-12-31 에 닫는다(`인터페이스:ex-orders`)

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**
