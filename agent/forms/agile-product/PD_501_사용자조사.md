<!-- form:head -->
날짜축. 인터뷰 · 사용성 시험은 대상이 아니라 **사건**이라 좌표-섹션이 1:1로
대응하지 않는다.

<!-- form:guide -->
**무엇** — 누구를 · 어떻게 만났고 · **무엇을 알게 됐나** · 그것이 어디로 이어졌나.
**언제** — 세션이 끝난 날. 여러 날에 걸친 조사는 한 섹션으로 묶고 날짜는 마지막 세션으로 한다.
**누가** — 조사를 이끈 사람(디자이너 · 제품 책임자). 관찰자 메모를 합친다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 녹화 · 원본 메모 · 참가자 연락처 | 리서치 저장소 — 여기는 링크와 요약만 |
| 그래서 바꾼 기능 범위 · 수용 기준 | `기능명세` — 여기서는 가리킨다 |
| 그래서 바꾼 화면 동작 | `화면명세` |
| 그래서 내린 결정 | 작업 기록(`work/`) |

> **참가자를 이름으로 적지 않는다.** P1 · P2 로 적고 연락처 · 녹화는 리서치 저장소의
> 권한 안에 둔다 — 이 레포는 팀 전체가 읽는다. 동의서 없이 녹화하지 않는다.
>
> **사용자조사는 옮겨 적는 곳이 아니라 가리켜지는 곳이다.** 기능명세의 「문제」 가 이
> 문서의 한 날짜를 근거로 가리킨다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<YYYY-MM-DD> — <조사 이름>`. 같은 날 둘이면 이름으로 가른다 | 필수 |
| 방법 | 인터뷰 · 사용성 시험 · 설문 · 현장 관찰 — 과제 수 · 시간 | 필수 |
| 참가자 | 수와 **선정 조건**. 이름 · 연락처를 적지 않는다 | 필수 |
| 원본 | 녹화 · 메모가 있는 곳의 링크 | 필수 |
| 알게 된 것 | 번호 목록. **관찰(무엇을 했나)과 해석을 가른다** · n/전체를 붙인다 | 필수 |
| 이어지는 곳 | 바꾼 좌표 — `기능명세:<값>` · `화면명세:<값>` | 조건 |
| 정해지지 않은 것 | 다음 조사로 넘긴 질문 | 선택 |
| 변경 | 나중에 해석을 고치면 그 섹션 끝에 `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 변경 시 필수 |

<!-- form:example -->
### 예시 — 2026-09-22 — 모바일 결제 사용성 시험

| | |
|---|---|
| 방법 | 원격 사용성 시험 · 과제 3개 · 세션당 40분 |
| 참가자 | 5명 — 최근 30일 모바일 구매 경험. 그중 3명은 결제 중 이탈 경험 |
| 진행 · 관찰 | 디자이너 · 제품 책임자 · 개발 1 |
| 원본 | (예시) 리서치 저장소 「2026-09 결제 시험」 |

**알게 된 것**

1. **4/5 가 배송지 확인 화면에서 뒤로 갔다** — 「다음」 이 배송비를 바꾸는 단추인지 몰랐다
2. 3/5 가 쿠폰 입력란을 결제를 마친 뒤에 찾았다 — 결제 단추 아래에 있었다
3. 저장된 카드가 있으면 결제수단 화면은 거의 보지 않는다(5/5)

**이어지는 곳** — `기능명세:EX-CHECKOUT` 수용 기준 1 · `화면명세:EX-CART` 쿠폰 위치

**정해지지 않은 것** — 비회원 결제를 같은 화면에 넣을지. 다음 조사로 넘긴다.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**
