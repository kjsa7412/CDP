<!-- form:head -->
시스템 구성의 지금 상태. **좌표 넷이 고정이다** — C4 모델의 위 두 층(컨텍스트 ·
컨테이너)에 배포 · 보안을 더했다.

<!-- form:guide -->
**무엇** — 시스템이 **누구와 무엇을 주고받나(context) · 무엇으로 이루어졌나(container) ·
어디서 어떻게 도나(deploy) · 누가 무엇을 할 수 있나(security)**. 장애 · 온보딩 · 보안 점검 때
가장 먼저 여는 장이다.
**언제** — 첫 스프린트 전에 초안을 쓴다. 외부 연동 · 배포 단위 · 저장소 · 환경 · 인증 방식이
바뀌면 그 섹션을 고친다.
**누가** — 리드 개발자 · 아키텍트. 구성을 바꾼 사람이 고친다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| API 자원별 계약 | `인터페이스명세` |
| 엔터티 · 필드의 뜻 · 보존 | `데이터모델` |
| 브랜치 · 리뷰 · CI 규칙 | `개발규약` |
| 인프라 코드(Terraform · 매니페스트) · 파이프라인 정의 | 코드 레포 — `정본 위치` 로 가리킨다 |
| **왜 이 구조인가** · 버린 대안 | 작업 기록(`work/`) — **작업 기록이 ADR 이다** |

> **ADR 문서를 따로 두지 않는다.** 「PostgreSQL 을 고른 이유」 는 그 결정을 내린 작업
> 기록이 갖고, 그 기록의 `touches:` 에 `시스템아키텍처:container` 를 적어 여기를 고치게
> 한다. 결정을 뒤집으면 같은 좌표를 건드린 새 작업 기록을 낸다 — 기록은 고치지 않고,
> `supersedes` 는 기록 자체가 틀렸을 때만 단다. 이 문서에는 **지금 어떻게 생겼나**만 남는다.
>
> **다른 좌표는 대상마다 값이 생기는데 이것만 넷으로 고정이다.** 그래서 `_vocab.md` 에 넷이
> 미리 등록돼 있다. 늘리거나 줄이려면 `_vocab.md` 의 `## 시스템아키텍처` 와 이 문서를 **함께**
> 고친다.

### 고정 좌표

```
## 시스템아키텍처

- `시스템아키텍처:context` — 시스템 컨텍스트
  aliases: 시스템 경계, 외부 연동, 사용자와 외부 시스템
- `시스템아키텍처:container` — 컨테이너 구성
  aliases: 구성 요소, 서비스 구성, 기술 스택
- `시스템아키텍처:deploy` — 배포 · 환경
  aliases: 배포 구성, 운영 환경, 환경 구성
- `시스템아키텍처:security` — 인증 · 권한 · 비밀
  aliases: 보안 구성, 인증 구조, 비밀 관리
```

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 | **넷 고정.** 늘리거나 줄이려면 `_vocab.md` 의 `## 시스템아키텍처` 를 함께 고친다 | 필수 |
| context | 사람 · 외부 시스템마다 한 행 — 주고받는 것 · 방향 · 장애 시 영향 | 필수 |
| container | 배포 단위마다 한 행. **기술과 판을 반드시 적는다** · 정본 위치 · 담당 | 필수 |
| deploy | 환경마다 한 행 · 배포 방식 · 되돌리기 · 인프라 코드 위치 | 필수 |
| security | 인증 · 권한 · 비밀 · 개인정보. **키 · 비밀번호 값을 적지 않는다** | 필수 |
| 결정 이유 | 여기 쓰지 않는다 — 작업 기록에 쓰고 `touches:` 로 이 섹션을 건다 | 필수 |
| 그림 | 뷰어는 mermaid 를 그리지 않는다. 표로 적고, 그림은 `work/assets/` 에 두고 링크 | 선택 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |

### 예시 — context — 시스템 컨텍스트

우리 시스템을 상자 하나로 보고 **바깥만** 적는다.

| 누가 · 무엇 | 종류 | 주고받는 것 | 방향 | 비고 |
|---|---|---|:--:|---|
| (예시) 회원 | 사람 | 상품 탐색 · 주문 · 결제 | → | 웹 · iOS · Android |
| (예시) 상점 운영자 | 사람 | 상품 · 재고 · 주문 처리 | → | 관리자 웹 |
| (예시) PG사 | 외부 시스템 | 결제 승인 · 취소 · 결과 웹훅 | ↔ | 장애 시 주문을 보류한다 |
| (예시) 택배사 | 외부 시스템 | 송장 발급 · 배송 상태 | ↔ | 30분마다 동기화 |

> ⚠ **예시 행이다 — 지우고 시작한다.**

### 예시 — container — 컨테이너 구성

배포 단위(앱 · 서비스 · 저장소)마다 한 행.

| 컨테이너 | 기술 · 판 | 책임 | 정본 위치 | 담당 |
|---|---|---|---|---|
| (예시) 웹 앱 | Next.js 15 · Node 22 | 화면 · 서버 렌더링 | `web/` | 프론트엔드 |
| (예시) 모바일 앱 | React Native · iOS 17+ · Android 10+ | 앱 화면 · 푸시 | `app/` | 모바일 |
| (예시) API 서버 | Kotlin · Spring Boot 3 | 주문 · 결제 · 회원 | `api/` | 백엔드 |
| (예시) 주 DB | PostgreSQL 16 | 주문 · 회원 · 상품 | `api/db/migrations/` | 백엔드 |
| (예시) 캐시 · 큐 | Redis 7 | 세션 · 재고 잠금 · 작업 큐 | — | 백엔드 |

> ⚠ **예시 행이다 — 지우고 시작한다.**

### 예시 — deploy — 배포 · 환경

| 환경 | 어디 | 배포 방식 | 데이터 | 접근 |
|---|---|---|---|---|
| (예시) prod | 클라우드 서울 리전 · 컨테이너 | `main` 머지 → CI → 카나리 10% → 전체 | 운영 | 온콜 · 승인된 사람 |
| (예시) stg | 같은 계정 · 다른 클러스터 | `main` 머지마다 자동 | 가명화한 운영 사본 | 개발팀 |
| (예시) preview | PR 마다 임시 환경 | PR 을 열면 서고 닫으면 지운다 | 시드 데이터 | PR 작성자 · 리뷰어 |

**되돌리기** — (예시) 이전 이미지로 재배포 5분 안. 스키마는 앞으로만 바꾼다(expand → contract) — `개발규약`.

**정본 위치** — (예시) `infra/`(Terraform) · `.github/workflows/`

> ⚠ **예시 행이다 — 지우고 시작한다.**

### 예시 — security — 인증 · 권한 · 비밀

| 항목 | 지금 |
|---|---|
| (예시) 회원 인증 | OIDC(자체 계정 + 소셜 로그인) · 액세스 토큰 15분 · 리프레시 토큰 회전 |
| (예시) 운영자 권한 | 역할 셋 — 조회 · 운영 · 관리자. 관리자 작업은 감사 기록을 남긴다 |
| (예시) 서비스 간 | 내부망 + 서비스 계정 토큰 |
| (예시) 비밀 | 클라우드 비밀 관리자. 코드 · 환경 파일에 두지 않는다 · 90일 회전 |
| (예시) 개인정보 | 주소 · 연락처는 컬럼 암호화 · 조회 기록 보존. 엔터티별은 `데이터모델` |
| (예시) 결제정보 | 카드 번호를 저장하지 않는다 — PG 토큰만 |

> ⚠ **예시 행이다 — 지우고 시작한다.**
