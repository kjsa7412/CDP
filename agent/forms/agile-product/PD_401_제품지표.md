<!-- form:head -->
지표의 **정의**. 섹션 하나가 지표 하나다 — 같은 이름의 숫자가 대시보드마다
다르게 나오지 않게 한다.

<!-- form:guide -->
**무엇** — 지표마다 **무엇을 세나(계산식) · 어디서 오나(출처 이벤트) · 어디서 보나(대시보드) ·
얼마면 좋은가(목표) · 누가 지키나(담당)**.
**언제** — 지표를 처음 정의할 때 세운다. 이벤트 이름 · 계산식 · 빼는 조건 · 목표가 바뀌면 그
섹션을 고친다 — **숫자가 끊긴 자리를 나중에 설명할 수 있게.**
**누가** — 제품 분석 담당 · 제품 책임자.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 지표의 값(이번 주 몇 %) | 대시보드 — 문서는 정의만 갖는다 |
| 쿼리 원문 · 이벤트 수집 코드 | 코드 레포 · 분석 도구 — `정본 위치` 로 가리킨다 |
| 어느 기능이 이 지표를 올리려 하나 | `기능명세` 의 성공 지표 |
| 북극성 지표가 무엇인가 | `제품개요` |
| 실험 설계 · 결과 · 해석 | 작업 기록(`work/`) |

> **정의가 바뀌면 숫자가 끊긴다.** 계산식을 고친 날과 이유를 `**경과**` 줄로 남겨야
> 6개월 뒤 그래프의 계단을 설명할 수 있다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<지표 키> — <지표 이름>` | 필수 |
| 정의 | 사람의 말 한 문장 | 필수 |
| 계산식 | 분자 ÷ 분모 · 단위(세션 · 사용자 · 주문) · 기간 | 필수 |
| 출처 이벤트 | 이벤트 이름 그대로 | 필수 |
| 정본 위치 | 쿼리 · 지표 정의 파일의 경로. **쿼리를 여기 옮기지 않는다** | 필수 |
| 대시보드 | 이름 또는 링크 | 선택 |
| 목표 | 값 · 기한 · 지금 값 | 선택 |
| 빼는 것 · 주의 | 숫자를 잘못 읽게 만드는 것 — 계측이 바뀐 날 · 빼는 트래픽 | 조건 |
| 개인정보 | 사용자 단위로 세면 식별자를 어떻게 다루나 | 조건 |
| 경과 | `**경과**` 아래 한 줄 `- 날짜 [작업 기록](../work/…) 무엇이` — **정의를 바꾼 날은 반드시** | 반영 때 필수 |

### 예시 — ex_checkout_conversion — 결제 전환율

| | |
|---|---|
| 정의 | 결제 화면에 들어온 세션 중 주문 완료까지 간 비율 |
| 계산식 | `order_completed` 가 있는 세션 수 ÷ `checkout_started` 가 있는 세션 수 — 같은 세션 · 24시간 안 |
| 출처 이벤트 | `checkout_started` · `order_completed` — 웹 · 앱 공통 |
| 정본 위치 | (예시) 분석 레포 `metrics/checkout_conversion.sql` |
| 대시보드 | (예시) 「결제 퍼널」 |
| 주기 · 나눠 보기 | 일 · 주 / 플랫폼 · 신규 · 재구매 |
| 목표 | 70%(2026 4분기) — 지금 62% |
| 담당 | 결제 스쿼드 · 제품 분석 |
| 관련 좌표 | `기능명세:EX-CHECKOUT` |

**빼는 것** — 내부 직원 · 테스트 계정 · 봇으로 판정된 세션.

**주의** — 결제 실패 뒤 다시 시도한 세션은 한 번으로 센다. 앱 2.3 이전은 `checkout_started` 가
두 번 찍혀 분모가 부푼다 — 2026-08 이전과 견주지 않는다.

**개인정보** — 세션 단위 집계. 회원 식별자는 가명 ID 로만 쓴다.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 제품지표

- `제품지표:ex_checkout_conversion` — (예시) 결제 전환율
  example: 서식 예시 — 지우고 시작한다
  aliases: 전환율, 결제 CVR
```
