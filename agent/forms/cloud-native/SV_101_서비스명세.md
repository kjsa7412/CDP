<!-- form:head -->
서비스의 지금 상태. **섹션 하나가 배포 단위 서비스 하나다** — 무엇을 책임지고, 누가 맡고,
무엇에 기대며 누가 이 서비스에 기대는가.

<!-- form:guide -->
**무엇** — 책임(하는 일 · **하지 않는 일**) · 담당 팀 · 코드 레포 · 런타임 · 의존(위 · 아래) · 등급 · 소유한 데이터.
**언제** — 서비스를 만들 때 세운다. 담당 팀이 바뀌거나 의존을 더하거나 등급을 올리면 그 섹션을 고친다.
**누가** — 그 서비스를 소유한 팀의 테크 리드.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| API 연산 · 호환성 · 한도 | `인터페이스명세` |
| 내고 받는 이벤트의 스키마 · 순서 · 재처리 | `이벤트명세` |
| DB · 캐시 · 버킷의 백업 · 보존 · 개인정보 | `데이터저장소` |
| 가용성 · 지연 목표 | `서비스수준` |
| 서비스 사이의 큰 그림 | `시스템아키텍처` 의 `시스템아키텍처:context` |
| 배포 매니페스트 · 이미지 · 리소스 요청 · 오토스케일 값 | 코드 레포(Helm · Kustomize) — `정본 위치` 로 가리킨다 |
| 왜 이렇게 쪼갰나 · 왜 이 언어 · 이 프레임워크인가 | 작업 기록(`work/`) |

> **카탈로그를 옮겨 적지 않는다.** 서비스 카탈로그(Backstage 의 `catalog-info.yaml` 같은 것)가 있으면 이름 ·
> 담당 · 레포는 그것이 정본이다. 여기는 카탈로그가 말하지 못하는 것 — **책임의 경계 · 의존의 이유 ·
> 그것이 멈추면 어떻게 되나 · 등급의 근거**를 적는다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<서비스 키> — <서비스 이름>`. 배포 단위 하나에 섹션 하나. 묶음은 `<!-- 도메인 -->` 주석으로 | 필수 |
| 책임 · 하지 않는 것 | 한 줄씩. **하지 않는 것이 경계다** — 비우면 책임이 새어 들어온다 | 필수 |
| 담당 팀 · 호출 대상 | 팀 이름과 당번 호출 대상. 사람 이름을 쓰지 않는다 | 필수 |
| 코드 레포 · 정본 위치 | 레포 · 카탈로그 파일 · 배포 매니페스트 경로. **값을 옮기지 않는다** | 필수 |
| 런타임 | 언어 · 프레임워크 · 런타임 판 · 워크로드 종류 · 파드 범위 | 필수 |
| 등급 | 1등급(멈추면 매출 · 핵심 흐름이 멈춘다) · 2등급(우회가 있다) · 3등급(내부 · 배치). 1등급은 `서비스수준:` 좌표가 있어야 한다 | 필수 |
| 도메인 | `도메인:` 좌표. 찾기 · 묶기에만 쓴다 | 선택 |
| 소유 데이터 · 내놓는 것 | 그 문서의 좌표로 가리킨다 | 필수 |
| 의존 | 방향 · 상대 · 방식 · **그것이 멈추면.** 마지막 칸이 없으면 의존을 적은 것이 아니다 | 필수 |
| 내릴 때 | 섹션을 지우지 않는다 — 첫 칸에 「종료 · 날짜」, 어휘 줄에 `deprecated:` | 조건 |
| 경과 | `**경과**` 아래 한 줄 `- 날짜 [작업 기록](../work/…) 무엇이` | 반영 때 필수 |

### 예시 — ex-order-api — 주문 서비스

| | |
|---|---|
| 책임 | 주문 생성 · 조회 · 취소 — **주문 상태의 정본** |
| 하지 않는 것 | 결제 승인(결제 서비스 payment-api) · 재고 차감 · 배송 추적 |
| 담당 팀 | (예시) 커머스 팀 · 호출 대상 `commerce-oncall` |
| 코드 레포 | (예시) `order-api` · 카탈로그 `catalog-info.yaml` |
| 정본 위치 | (예시) 배포 매니페스트 `gitops/apps/order-api/` (Helm 차트 · 환경별 values) |
| 런타임 | Kotlin · Spring Boot · JVM 21 · 쿠버네티스 Deployment · 파드 3~12(HPA) |
| 등급 | **1등급** — 멈추면 결제가 멈춘다 · `서비스수준:ex-checkout-availability` |
| 도메인 | `도메인:ex-ordering` |
| 소유 데이터 | `데이터저장소:ex-order-db` — 다른 서비스는 직접 읽지 않는다(API · 이벤트로) |
| 내놓는 것 | `인터페이스:ex-order-v1` · `이벤트명세:ex.order.placed` |
| 런북 | `런북:EX-ORDER-5XX` |

**의존**

| 방향 | 상대 | 방식 | 그것이 멈추면 |
|:--:|---|---|---|
| → 부른다 | 결제 서비스(payment-api) | gRPC · 시간 초과 3초 · 서킷 브레이커 | 주문을 「결제 대기」 로 받고 재시도 — 생성은 막지 않는다 |
| → 부른다 | `데이터저장소:ex-order-db` | JDBC · 풀 파드당 20 | **멈춘다** — 단일 장애점 |
| → 부른다 | 카프카 | 트랜잭셔널 아웃박스 · 비동기 | 이벤트가 늦을 뿐 주문은 된다 |
| ← 불린다 | 웹 · 앱 BFF · 정산 배치 | REST · 이벤트 구독 | — 바꾸기 전에 물어볼 곳이다 |

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 서비스명세

- `서비스명세:ex-order-api` — (예시) 주문 서비스
  example: 서식 예시 — 지우고 시작한다
  aliases: 주문 서비스, order-api
```
