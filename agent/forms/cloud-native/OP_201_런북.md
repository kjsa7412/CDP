<!-- form:head -->
경보에 대응하는 법의 지금 상태. **섹션 하나가 경보(또는 운영 절차) 하나다** — 새벽 세 시에 처음 보는
당번이 따라 할 수 있게 쓴다.

<!-- form:guide -->
**무엇** — 경보 · 심각도 · 서비스 · 관련 서비스수준 · **증상 · 확인(대시보드 · 쿼리) · 완화 단계 · 에스컬레이션** ·
마지막 점검.
**언제** — 호출 경보를 만드는 작업과 같이 세운다. 장애에서 절차가 틀렸거나 모자랐으면 회고의 후속 조치로 고친다.
**누가** — 그 서비스의 담당 팀. 당번이 따라 해 보고 고친다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 경보 규칙의 식 · 문턱 원문 | 코드 레포(경보 규칙) — 경보 칸에 이름과 위치만 |
| 목표 · 오류 예산 | `서비스수준` |
| 장애 등급 · 선언 · 전파 | `온콜체계` |
| 이번 장애의 경과 · 원인 | `장애회고` |
| 서비스의 의존 · 담당 | `서비스명세` |

> **완화가 먼저 · 원인은 나중이다.** 단계는 「무엇을 보면 · 무엇을 한다」 로 쓴다. 판단이 필요한 단계에는
> 판단 기준을 같이 적는다 — 기준이 없으면 당번은 에스컬레이션한다.
>
> **런북 없는 호출 경보를 만들지 않는다.** 할 일이 없는 경보는 호출이 아니라 티켓이다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<경보 키> — <무엇이 일어났나>` | 필수 |
| 경보 | 규칙 이름 · 라벨 · 문턱 한 줄 · 정본 위치. **식을 옮기지 않는다** | 필수 |
| 심각도 · 서비스 · 서비스수준 | 호출인가 티켓인가 · `서비스명세:` · `서비스수준:` 좌표 | 필수 |
| 증상 | 사용자와 대시보드에서 보이는 것 | 필수 |
| 확인 | 대시보드 이름 · 쿼리 · 볼 순서를 **번호 목록**으로 | 필수 |
| 완화 | 「보이는 것 → 할 일」 표. 플래그 · 명령은 정확한 이름으로 | 필수 |
| 에스컬레이션 | 몇 분 뒤 누구에게 · 장애 선언 기준 | 필수 |
| 마지막 점검 | 날짜와 누가 따라 해 봤나. **반년 넘게 안 본 런북은 틀렸다고 본다** | 필수 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |

### 예시 — EX-ORDER-5XX — 주문 API 5xx 급증

| | |
|---|---|
| 경보 | `HighErrorRate` · `service=order-api` — 5분 5xx 비율 2% 초과 · 정본 `observability/alerts/order-api.yaml` |
| 심각도 | 호출 — 업무 시간 밖에도 |
| 서비스 | `서비스명세:ex-order-api` |
| 서비스수준 | `서비스수준:ex-checkout-availability` — 이 경보가 예산을 태운다 |
| 마지막 점검 | (예시) 2026-09-10 게임데이 — 당번 둘이 따라 해 봄 |

**증상** — 결제 단계에서 「잠시 후 다시 시도」 · 주문 목록은 열린다 · 결제 가용성 번레이트 경보가 같이 울릴 수 있다.

**확인**

1. 대시보드 「order-api 개요」 — 5xx 가 한 연산에 몰렸나 전부인가
2. 최근 배포 — Argo CD 의 `order-api` 동기화 이력 · 카나리가 진행 중인가
3. 의존 — 결제 서비스 지연 · DB 연결 대기 · 카프카 발행 오류

```
sum(rate(http_server_requests_seconds_count{service="order-api",status=~"5.."}[5m]))
  / sum(rate(http_server_requests_seconds_count{service="order-api"}[5m]))
```

**완화**

| 보이는 것 | 할 일 |
|---|---|
| 배포 30분 안 | 카나리면 중단(abort) · 다 나갔으면 GitOps 레포에서 이미지 태그 커밋을 되돌린다 |
| 결제 서비스 지연 | 서킷 브레이커가 열렸나 본다 · 플래그 `checkout.defer-payment` 를 켜 「결제 대기」 로 받는다 |
| DB 연결 대기 | HPA 최대를 늘리지 않는다(연결을 더 먹는다) · 느린 쿼리를 본다 · 배치를 멈춘다 |
| 15분 지나도 모름 | 에스컬레이션 |

**에스컬레이션** — 15분 안에 줄지 않으면 2차 당번(커머스 팀 리드) · 결제 쪽이면 결제 팀 당번 ·
결제 성공률이 90% 아래면 장애 선언(등급은 `온콜체계`).

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 런북

- `런북:EX-ORDER-5XX` — (예시) 주문 API 5xx 급증
  example: 서식 예시 — 지우고 시작한다
  aliases: 주문 오류율 경보, HighErrorRate order-api
```
