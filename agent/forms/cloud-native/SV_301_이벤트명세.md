<!-- form:head -->
비동기 이벤트의 지금 상태. **섹션 하나가 이벤트(토픽) 하나다** — 스키마는 스키마 레지스트리 · AsyncAPI 가
정본이고, 여기는 이벤트의 **뜻 · 누가 내고 누가 받나 · 순서 · 보존 · 실패하면 어떻게 하나**를 적는다.

<!-- form:guide -->
**무엇** — 뜻(언제 내나) · 내는 쪽 · 받는 쪽 · 브로커와 토픽 · 정본 위치 · 스키마 판과 호환성 모드 · 순서 · 전달 보장 ·
보존 · 재처리(DLQ) · 개인정보.
**언제** — 이벤트를 설계할 때 세운다. 받는 쪽이 늘거나 스키마 판이 오르거나 보존 · 재처리를 바꾸면 고친다.
**누가** — 내는 쪽 서비스의 담당 팀. 받는 쪽은 「받는 쪽」 칸에 제 이름을 더하는 작업 기록을 낸다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 필드 타입 · 스키마 본문 | 스키마 레지스트리 · 코드 레포의 AsyncAPI — `정본 위치` 로 가리킨다 |
| 동기 호출(REST · gRPC) | `인터페이스명세` |
| 내는 서비스의 책임 · 의존 | `서비스명세` |
| 브로커 클러스터 · 파티션 운영 | `시스템아키텍처` 의 `시스템아키텍처:platform` |
| DLQ 가 쌓일 때의 대응 절차 | `런북` |
| 왜 이벤트로 했나 · 왜 이 키인가 | 작업 기록(`work/`) |

> **이벤트는 사실이다 — 명령이 아니다.** 「주문이 접수됐다」 를 알릴 뿐 받는 쪽에 무엇을 하라고 시키지 않는다.
> 받는 쪽은 **멱등하게** 받는다 — 전달은 최소 한 번(at-least-once)이라 같은 이벤트가 두 번 온다.
>
> **깨지는 스키마 변경은 새 이벤트 · 새 좌표다** — `ex.order.placed.v2` 를 따로 세우고 옛 것을 받는 쪽이 다 옮길 때까지 둘을 같이 낸다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<이벤트 이름> — <뜻을 과거형으로>` | 필수 |
| 뜻 | 언제 내나 · **무엇이 아닌가**. 받는 쪽이 가장 자주 틀리는 자리다 | 필수 |
| 내는 쪽 · 받는 쪽 | 내는 쪽은 `서비스명세:` 좌표, 받는 쪽은 서비스와 쓰는 목적 | 필수 |
| 브로커 · 토픽 · 키 | 파티션 키가 순서를 정한다 — 키를 적는다 | 필수 |
| 정본 위치 · 스키마 판 | 레지스트리 subject · 원본 경로 · 호환성 모드. **스키마를 옮기지 않는다** | 필수 |
| 순서 · 전달 · 보존 | 무엇이 보장되고 무엇이 안 되나 | 필수 |
| 재처리 | 재시도 횟수 · DLQ · 재주입 절차. 절차가 길면 `런북:` 좌표로 | 필수 |
| 개인정보 | 싣는 것 · 싣지 않는 것 | 필수 |
| 필드의 뜻 | 헷갈리는 필드만 | 선택 |
| 경과 | `**경과**` 아래 한 줄 `- 날짜 [작업 기록](../work/…) 무엇이` | 반영 때 필수 |

### 예시 — ex.order.placed — 주문 접수됨

| | |
|---|---|
| 뜻 | 주문이 저장되고 결제를 기다린다 — **결제 완료가 아니다** |
| 내는 쪽 | `서비스명세:ex-order-api` — 트랜잭셔널 아웃박스로 발행(주문 커밋과 같이 · 유실 없음) |
| 받는 쪽 | 결제 서비스(payment-api) — 결제 요청 · 정산 배치 · 알림 · 분석 적재 |
| 브로커 · 토픽 | (예시) Kafka · 토픽 `ex.order.placed` · 파티션 12 · 키 `orderId` |
| 정본 위치 | (예시) 스키마 레지스트리 subject `ex.order.placed-value`(Avro) · 원본은 `order-api` 레포 `schemas/` |
| 스키마 판 · 호환성 | 판 3 · 모드 **BACKWARD** — 기본값이 있는 필드만 더한다 |
| 순서 | 같은 주문(키) 안에서만 보장. 주문 사이의 순서는 없다 |
| 전달 · 멱등 | 최소 한 번 · 받는 쪽은 `eventId` 로 중복을 거른다 |
| 보존 | 7일 — 받는 쪽이 7일 넘게 멈추면 다시 받을 수 없다 |
| 재처리 | 3회 실패 → DLQ `ex.order.placed.dlq` → 원인을 고친 뒤 재주입 |
| 개인정보 | 주문자 ID 만 싣는다 — 이름 · 연락처 · 주소는 싣지 않는다 |

**필드의 뜻** — 타입은 정본이 갖고, 여기는 헷갈리는 것만.

| 필드 | 뜻 | 주의 |
|---|---|---|
| `occurredAt` | 주문이 저장된 시각(UTC) | 발행 시각이 아니다 — 아웃박스 지연만큼 늦게 온다 |
| `totalAmount` | 할인 뒤 · 배송비 포함 금액(원) | 결제 금액과 다를 수 있다(포인트) |

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

  aliases: 주문 접수 이벤트, order.placed
