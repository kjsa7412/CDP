<!-- form:head -->
동기 API 의 지금 상태. **섹션 하나가 API(REST · gRPC) 하나의 메이저 판이다** — 요청 · 응답 스키마는
OpenAPI · proto 가 정본이고, 여기는 그것이 말하지 못하는 것을 적는다.

<!-- form:guide -->
**무엇** — 정본 위치 · 제공 서비스 · 판 · **호환성** · 쓰는 서비스 · 노출(내부 · 외부) · 인증 · 한도 · 시간 초과와 재시도.
**언제** — API 를 설계할 때 세운다. 필드를 빼거나 뜻을 바꾸거나 오류 코드 · 상태 값을 더하면 그 섹션을 고친다 —
**깨지는 변경은 반드시.**
**누가** — 그 API 를 제공하는 서비스의 담당 팀.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 요청 · 응답 스키마 · 필드 타입 | 코드 레포의 OpenAPI · `.proto` — `정본 위치` 로 가리킨다 |
| 비동기 메시지 · 토픽 | `이벤트명세` |
| 제공 서비스의 책임 · 의존 | `서비스명세` |
| 가용성 · 지연 목표 | `서비스수준` |
| 게이트웨이 · 메시 · 진입점 구성 | `시스템아키텍처` 의 `시스템아키텍처:network` |
| 왜 이렇게 설계했나 · 버린 안 | 작업 기록(`work/`) |

> **스키마를 옮겨 적지 않는다.** 옮긴 스키마는 다음 PR 에서 틀린다. 깨지는 변경은 CI 가 막는다 —
> OpenAPI 는 diff 검사, proto 는 `buf breaking` 같은 것. 여기는 **누가 쓰나 · 무엇이 깨지면 안 되나 ·
> 언제 없어지나**를 적는다.
>
> **깨지는 변경은 새 메이저 판 · 새 좌표다** — `ex-order-v2` 를 따로 세우고, 옛 판 섹션에 지원 종료일을 적는다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<API 키>-v<메이저> — <API 이름>`. REST 는 자원 묶음 하나, gRPC 는 proto 서비스(`package.Service`) 하나 | 필수 |
| 정본 위치 | OpenAPI · proto 파일 경로와 CI 의 깨짐 검사. **스키마를 옮기지 않는다** | 필수 |
| 제공 서비스 | `서비스명세:` 좌표 | 필수 |
| 판 | 지금 마이너 판. 깨지는 변경은 새 섹션 | 필수 |
| 노출 · 인증 | 내부(메시 안) · 외부(게이트웨이) · 토큰 종류 · 범위 | 필수 |
| 쓰는 서비스 | 서비스 · 앱(최소 판) · 외부 파트너. **바꾸기 전에 물어볼 곳**이다 | 필수 |
| 한도 · 시간 초과 · 재시도 | 수치로. 재시도해도 되는 연산과 안 되는 연산을 가른다 | 필수 |
| 연산 | 이 API 고유의 규칙이 있는 것만. 목록 전체는 정본이 갖는다 | 선택 |
| 호환성 · 지원 종료 | 무엇이 깨지나 · 언제 닫나 · 어떻게 알리나 | 필수 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |

### 예시 — ex-order-v1 — 주문 API v1

| | |
|---|---|
| 종류 | REST(HTTP · JSON) |
| 제공 서비스 | `서비스명세:ex-order-api` |
| 정본 위치 | (예시) 코드 레포 `order-api` 의 `api/openapi.yaml` — 배포 전에 CI 가 깨지는 변경 검사 |
| 판 | 1.4 — 마이너 판은 필드를 더할 때만 오른다 |
| 노출 | 외부 — API 게이트웨이 `/v1/orders` · 인증 OAuth 2.0 액세스 토큰 · 운영자는 `orders:manage` 범위 |
| 쓰는 서비스 | 웹 · 앱 BFF · 결제 서비스(payment-api, 상태 조회만) · 정산 배치 |
| 한도 | 클라이언트당 초당 50 · 버스트 100 · 넘으면 429 와 `Retry-After` |
| 시간 초과 · 재시도 | 쓰는 쪽 시간 초과 2초 · 재시도는 조회만 · 생성은 `Idempotency-Key` 가 있을 때만 |
| 서비스수준 | `서비스수준:ex-checkout-availability` |

**연산**

| 연산 | 하는 일 | 멱등 | 규칙 |
|---|---|:--:|---|
| `POST /v1/orders` | 주문 생성 · 결제 시작 | 키 | 같은 `Idempotency-Key` 는 같은 주문을 돌려준다 · 24시간 |
| `GET /v1/orders/{id}` | 주문 한 건 | O | 남의 주문은 404 |
| `POST /v1/orders/{id}/cancel` | 취소 | O | 배송이 시작되면 409 |

**호환성** — 필드를 **더하는 것**은 깨지지 않는다(쓰는 쪽은 모르는 필드를 무시한다). 빼기 · 이름 바꾸기 · 뜻 바꾸기 ·
필수로 바꾸기는 깨진다. `status` 에 값을 더하면 앱 구판이 「알 수 없음」 으로 보인다 — 쓰는 쪽에 먼저 묻는다.
**지원 종료** — v1 은 v2 가 서면 6개월 뒤. `Deprecation` · `Sunset` 헤더로 알린다.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 인터페이스

- `인터페이스:ex-order-v1` — (예시) 주문 API v1
  example: 서식 예시 — 지우고 시작한다
  aliases: 주문 API, /v1/orders
```
