쓰는 모델의 지금 상태. 섹션 하나가 **용도 하나에 쓰는 모델** 하나다.

<!-- form:guide -->
**무엇** — 그 용도에 **어느 공급자의 어느 판을 고정해 쓰는가**, 그리고 그 모델을 쓰는 조건 —
데이터 처리 조건 · 한도 · 비용 · 대체 모델 · 평가.
**언제** — 처음 고를 때 쓰고, 판을 올리거나 공급자 · 단가 · 데이터 조건이 바뀌면 고친다.
판을 올리는 작업은 **그 모델을 재는 평가셋 좌표도 같이 적는다.**
**누가** — AI 엔지니어. 데이터 처리 조건은 개인정보 담당이 본다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 그 모델을 부르는 프롬프트 | `프롬프트명세` |
| 품질 수치 · 사례 | `평가셋` — 여기는 어느 평가셋을 언제 넘었는지만 |
| 게이트웨이 · 재시도 · 캐시 | `시스템아키텍처` |
| 왜 이 모델인가 · 견준 후보 | 작업 기록(`work/`) · 비교 수치는 `실험기록` |

> **값은 용도이고 판은 칸이다.** 판을 올려도 좌표는 그대로이고 섹션의 `판` 칸과
> `applied` 가 바뀐다 — 판을 값에 넣으면 올릴 때마다 좌표가 새로 생기고 이력이 끊긴다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<모델 키> — <용도 이름>`. 키는 용도로 — 공급자 모델 이름이 아니다 | 필수 |
| 공급자 · 모델 · 판 | **판을 고정해 적는다.** 「최신」 은 판이 아니다 | 필수 |
| 데이터 처리 조건 | 학습 사용 여부 · 보존 · 처리 지역. 계약 · 약관을 확인한 날짜는 작업 기록에 | 필수 |
| 한도 · 비용 | 문맥 길이 · 요청 한도 · 단가 · 기능당 평균 비용 | 필수 |
| 대체 모델 | 언제 바꾸나 · 그 모델도 같은 평가셋을 넘었나 | 필수 |
| 평가 | 넘은 평가셋 좌표와 날짜 | 필수 |
| 판 종료 예정 | 공급자가 판을 내리는 날 — 다음 판 평가를 그 전에 | 선택 |
| 임베딩 · 재순위 · 심판 모델 | 각각 한 섹션. **심판 모델을 바꾸면 점수의 뜻이 바뀐다** | 조건 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |

<!-- form:example -->
### 예시 — ex-answer-llm — 답변 생성 모델

| | |
|---|---|
| 용도 | 상담 답변 초안 생성 — `기능명세:EX-SUPPORT-ANSWER` |
| 공급자 · 모델 | (예시) 공급자 X · 대형 언어 모델 A |
| 판 | **2026-08 고정** — 「최신」 별칭을 쓰지 않는다 |
| 호출 | LLM 게이트웨이 경유 — `시스템아키텍처:serving` |
| 데이터 처리 조건 | 입력을 학습에 쓰지 않는 계약 · 공급자 보존 30일 · 처리 지역은 확인 중 |
| 한도 | 문맥 128k 토큰 · 분당 600 요청 |
| 비용 | 입력 100만 토큰 3,000원 · 출력 100만 토큰 12,000원 — 문의당 평균 18원 |
| 대체 모델 | (예시) 공급자 Y · 대형 언어 모델 C — 오류 · 시간 초과 때만. **같은 평가셋을 넘은 판** |
| 쓰는 프롬프트 | `프롬프트:ex-support-answer` |
| 평가 | `평가셋:ex-support-golden` — 2026-09-20 출시 기준 통과 |
| 판 종료 예정 | 2027-02 — 공급자 공지. 그 전에 다음 판을 평가한다 |

**알려진 약점** — 표가 섞인 도움말에서 숫자를 옮기다 틀린다. 프롬프트에서 표 원문 인용을 시킨다.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 모델카드

- `모델카드:ex-answer-llm` — (예시) 답변 생성 모델
  example: 서식 예시 — 지우고 시작한다
  aliases: 답변 모델, 생성 모델
```
