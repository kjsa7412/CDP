<!-- form:head -->
날짜축. 실험은 대상이 아니라 **사건**이라 좌표-섹션이 1:1로 대응하지 않는다.

<!-- form:guide -->
**무엇** — 무엇을 바꾸면 나아지리라 봤고(가설), 무엇으로 쟀고(설정), 어떻게 나왔고(결과),
그래서 무엇을 했나(결정) · 어디서 틀렸나(오류 분석).
**언제** — 실험 당일. **진 실험도 적는다** — 안 되는 것을 다시 시도하지 않게.
**누가** — 실험한 사람.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 실험 끝에 바꾼 프롬프트 · 모델 | `프롬프트명세` · `모델카드` — 바꾼 작업이 그 섹션을 고친다 |
| 출시 기준 · 출시에 쓴 수치 | `평가셋` |
| 운영 중 품질 추이 | `운영모니터링` |

> **실험은 결정이 아니다.** 실험이 「바꾼다」 로 끝나면 그 변경은 작업 기록이 되고 정본
> 문서가 갱신된다. 여기는 **그 결정의 근거로 가리켜지는 곳**이다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<YYYY-MM-DD> — <무엇을 바꿔 봤나>`. 같은 날 둘이면 이름으로 가른다 | 필수 |
| 가설 | 한 문장 — 「~하면 ~가 나아지고 ~는 나빠지지 않는다」 | 필수 |
| 설정 | 모델 · 프롬프트 판 · 평가셋 판 · 채점을 **좌표와 판으로**. 판이 없으면 다시 할 수 없다 | 필수 |
| 결과 | 기준과 실험을 나란히 · 비용 · 지연도 | 필수 |
| 결정 | 낸다 · 버린다 · 더 본다. 냈으면 그 작업 기록이 정본 문서를 고친다 | 필수 |
| 오류 분석 | 틀린 것을 묶어 세고 묶음마다 다음 할 일. 고칠 사례는 평가셋으로 | 필수 |
| 진 실험 | 지우지 않는다 — 결정에 「버린다」 와 이유 | 필수 |
| 경과 | 지난 섹션을 고쳤으면 그 끝에 `**경과**` 아래 한 줄 `- 날짜 [작업 기록](../work/…) 무엇이` | 고친 때 |

<!-- form:example -->
### 예시 — 2026-09-20 — 답변 프롬프트 v7 · 근거 인용 강제

| | |
|---|---|
| 가설 | 모든 안내 문장에 근거 인용을 강제하면 환각이 줄고 정답 일치는 떨어지지 않는다 |
| 모델 | `모델카드:ex-answer-llm` — 2026-08 고정 |
| 프롬프트 판 | `프롬프트:ex-support-answer` v6(기준) → v7(실험) |
| 평가셋 | `평가셋:ex-support-golden` 판 2026-09-15 · 320 사례 |
| 채점 | LLM 심판(근거 충실) · 사람 표본 60(정답 일치) |

**결과**

| | v6 | v7 | 차이 |
|---|--:|--:|--:|
| 근거 충실 | 0.86 | 0.93 | +0.07 |
| 정답 일치(사람) | 4.1 | 4.2 | +0.1 |
| 인젝션 저항 | 40/40 | 40/40 | — |
| 평균 출력 토큰 | 410 | 470 | +15% |
| p95 지연 | 5.1초 | 5.6초 | +0.5초 |

**결정** — v7 을 낸다. 토큰 · 지연 증가는 기능명세의 예산 안이다. 프롬프트 좌표와 평가셋
좌표를 단 작업 기록으로 남겼고, 그 기록이 두 섹션을 고쳤다.

**오류 분석** — v7 이 아직 틀리는 21건을 묶었다.

| 묶음 | 건수 | 예 | 다음 |
|---|--:|---|---|
| 표 속 숫자를 잘못 옮김 | 9 | 무료 배송 기준 금액 | 표 원문 인용 지시 · 쪼개기에서 표 보존 |
| 근거 문서가 낡음 | 7 | 끝난 이벤트 안내 | 원천 팀에 만료일 칸 요청 |
| 주문 조회 실패 뒤 추측 | 5 | 「곧 도착합니다」 | 조회 실패 때 문구 고정 |

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**
