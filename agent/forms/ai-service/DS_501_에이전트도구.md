<!-- form:head -->
모델이 부를 수 있는 도구의 지금 상태. 섹션 하나가 도구(함수 · MCP 도구) 하나다.

<!-- form:guide -->
**무엇** — 모델이 이 도구로 **무엇을 할 수 있고 무엇은 못 하나.** 서명 · 부작용 · 권한 ·
**승인 필요 여부** · 범위 · 한도.
**언제** — 도구를 붙이기 **전에** 쓴다. 권한을 넓히거나 부작용이 생기면 먼저 여기를 고치고 붙인다.
**누가** — 도구를 만든 엔지니어. 쓰기 도구는 보안 담당이 본다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 도구 스키마 원문 · 구현 | 코드 레포(`정본 위치`) |
| 언제 도구를 부르라는 지시 | `프롬프트명세` |
| 도구 호출이 흐름의 어디에 끼나 | `시스템아키텍처` |
| 도구 오남용 위험과 그 상태 | `AI위험관리` |

> **모델의 권한은 도구의 권한이다.** 프롬프트로 「하지 마라」 고 막는 것은 막는 것이 아니다 —
> 인젝션 한 줄이면 풀린다. 못 하게 하려면 도구를 주지 않거나, 최소 권한으로 주거나,
> **실행 전에 사람이 확인**하게 한다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<도구 이름> — <하는 일>` | 필수 |
| 정본 위치 | 구현 · 스키마의 자리. **스키마를 옮겨 적지 않는다** | 필수 |
| 서명 | 인자와 돌려주는 것을 한 줄로 | 필수 |
| 부작용 | 무엇을 바꾸나 · 되돌릴 수 있나. 없으면 「없다」 | 필수 |
| 권한 · 범위 | 어느 계정으로 · 어디까지. **최소 권한** | 필수 |
| 승인 필요 | 예 · 아니오. 부작용이 있으면 기본은 예 — 아니오면 왜인지 | 필수 |
| 한도 | 횟수 · 시간 초과 · 실패하면 어떻게 하나 | 필수 |
| 쓰는 곳 · 기록 | 부르는 프롬프트 좌표 · 추적에 무엇을 남기나 | 필수 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |

### 예시 — ex_lookup_order — 주문 조회

| | |
|---|---|
| 정본 위치 | (예시) 코드 레포 `tools/orders.py` · 함수 스키마 `lookup_order` |
| 서명 | `lookup_order(order_id: string)` → 상태 · 품목 · 발송일 · 도착 예정일 |
| 부작용 | **없다** — 읽기만 |
| 권한 | 상담 서비스 계정 · 주문 읽기 범위만. 결제 · 주소 칸은 응답에서 뺀다 |
| 승인 필요 | 아니오 — 읽기만이라 사람 확인 없이 부른다 |
| 범위 | 문의한 고객의 주문만 — 상담 세션의 고객과 주문의 고객이 다르면 거절한다 |
| 한도 | 요청당 1회 · 시간 초과 2초 · 실패하면 주문 정보 없이 계속 |
| 쓰는 곳 | `프롬프트:ex-support-answer` |
| 기록 | 호출 · 인자 · 결과 크기를 추적에 남긴다 — `시스템아키텍처:observability` |

**하지 않는 것** — 취소 · 환불 · 주소 변경. 그런 도구를 더하면 **승인 필요 = 예**(상담원이
확인 단추를 눌러야 실행)로 따로 섹션을 세운다.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 에이전트도구

- `에이전트도구:ex_lookup_order` — (예시) 주문 조회
  example: 서식 예시 — 지우고 시작한다
  aliases: 주문 조회 도구, lookup_order
```
