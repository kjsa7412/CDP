<!-- form:head -->
검색 증강(RAG)에 쓰는 원천의 지금 상태. 섹션 하나가 원천 하나다.

<!-- form:guide -->
**무엇** — 모델이 근거로 읽는 문서 묶음마다 — 누가 소유하고, 얼마나 자주 바뀌고, 어떻게 쪼개
색인하며, 누가 어떤 문서를 볼 수 있고, 개인정보가 섞이는가.
**언제** — 원천을 붙일 때 쓰고, 쪼개기 · 임베딩 모델 · 갱신 주기 · 권한이 바뀌면 고친다.
쪼개기나 임베딩을 바꾸면 검색 결과가 바뀌므로 **평가셋 좌표도 같이 적는다.**
**누가** — 검색 담당 AI 엔지니어 · 원천 소유 팀.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 원천 문서의 내용 | 원천 시스템(CMS · 위키) — 옮겨 오지 않는다 |
| 검색 결과를 쓰는 프롬프트 | `프롬프트명세` |
| 검색 품질 수치(재현율 · 근거 충실) | `평가셋` |
| 임베딩 모델의 판 · 단가 | `모델카드` |
| 색인 작업의 지연 · 실패 경보 | `운영모니터링` |

> **원천의 권한이 답의 권한이다.** 사용자가 볼 수 없는 문서를 검색해 답에 쓰면 그것이
> 유출이다 — 색인에 권한을 싣고, 검색할 때 그 사용자의 권한으로 거른다.

### 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<원천 키> — <원천 이름>` | 필수 |
| 원천 · 소유 | 시스템 이름 · 소유 팀. 원천이 바뀌면 누구에게 묻나 | 필수 |
| 갱신 | 주기 · 방식(전체 · 증분) · 지운 문서를 어떻게 빼나 | 필수 |
| 쪼개기 · 임베딩 · 검색 | **수치와 판을 적는다.** 바꾸면 평가를 다시 돌린다 | 필수 |
| 접근 권한 | 누가 어떤 문서를 보나 · 검색할 때 어디서 거르나 | 필수 |
| 개인정보 | 섞이는가 · 어디서 거르나. 없으면 「없어야 한다」 와 그 확인 방법 | 필수 |
| 쓰는 곳 · 평가 | 기능 · 프롬프트 · 평가셋을 좌표로 | 필수 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |

### 예시 — ex-help-center — 도움말 센터

| | |
|---|---|
| 원천 | (예시) 도움말 센터 CMS — 공개 도움말 · 상담원 전용 문서 |
| 소유 | (예시) 고객경험팀 |
| 크기 | 문서 약 1,200 · 조각 약 9,000 |
| 갱신 | 매일 새벽 증분 색인 · 원천에서 지운 문서는 다음 색인에서 뺀다 |
| 쪼개기 | 제목 단위 · 최대 500 토큰 · 겹침 50 · **표는 통째로** |
| 임베딩 | (예시) 임베딩 모델 B · 판 2026-05 — **바꾸면 색인을 다시 만든다** |
| 검색 | 벡터 + 키워드 혼합 · 상위 8 → 재순위 상위 4 |
| 접근 권한 | 공개 문서는 누구나 · 상담원 전용은 상담원 역할만. 색인에 대상 칸을 싣고 검색할 때 거른다 |
| 개인정보 | 없어야 한다 — 색인 전에 전화번호 · 주문번호 모양을 찾아 그 조각을 뺀다 |
| 쓰는 곳 | `기능명세:EX-SUPPORT-ANSWER` · `프롬프트:ex-support-answer` |
| 평가 | `평가셋:ex-support-golden` — 검색 재현율 묶음 |

**알려진 약점** — 이벤트 공지처럼 기간이 있는 문서가 끝난 뒤에도 남는다. 원천 팀에
만료일 칸을 요청했다.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

### 예시 — 어휘

```
## 지식소스

- `지식소스:ex-help-center` — (예시) 도움말 센터
  example: 서식 예시 — 지우고 시작한다
  aliases: 도움말 문서, FAQ
```
