지식 레포다. 두 층이다.

  docs/   관리 문서 — 지금 어떤 상태인가. 팀이 하나로 관리하는 산출물
  work/   작업 기록 — 무슨 일이 있었나. append-only. 여러 좌표가 함께 있다

  _vocab.md     좌표 어휘 — 정본과 alias
  _managed.md   등록부 — 좌표 패턴 → 관리 문서 · 섹션

## 좌표 타입은 이 레포가 정한다

`_vocab.md` 의 `## <타입>` 이 **그 목록의 전부**다. skill 과 매뉴얼의 예시에
나오는 타입(`table:` · `screen:` 같은 것)은 **설명을 위한 것이지 정해진 이름이
아니다.** 레포마다 다르다 — 관리문서 이름을 한글로 그대로 쓰는 레포도 있다
(`테이블정의서:ex_plan_mst`).

**모르면 지어내지 말고 `_vocab.md` 를 열어라.** 없는 타입을 쓰면
`_vocab.md 미등재 좌표` 로 커밋이 막힌다.

## 절차는 여기 없다

`.claude/skills/` 에 있다.

  cdp-work     작업 요청 하나를 ① 검토 → ② 맥락 주입 → ③ 요청수행 으로 처리
  cdp-load     좌표를 인자로 받아 현재 상태를 주입
  cdp-save     이 세션에서 한 작업을 기록 + 관리 문서 섹션 갱신
  cdp-import   밖에서 온 문서(회의록·검토서 등)를 작업 기록으로 편입
  cdp-edit     코드 작업 없이 관리 문서만 고치라는 지시 — 지시를 기록으로 남긴다
  cdp-managed  파생이 남은 섹션 채우기
  cdp-push     이 세션이 만진 파일을 커밋·push. **사람이 부를 때만** — 기록은 안 만든다

**읽는 규칙·파생 통보·좌표별 판정·최신화가 전부 그 skill 안에 있다.**
쓰기 전에는 받고(`pull --ff-only`), 읽기 전에는 확인한다(`ctx sync`).
같은 것을 이 파일에도 적으면 한쪽만 고쳐지고, 그 순간 어느 쪽이 맞는지 알 수 없다.

## 기계가 보증하는 것

커밋 시 `.githooks/pre-commit` 이 `bin/ctx check` 를 돌린다. 거부되는 것 —

  관리 문서 파생 누락      좌표를 건드렸는데 정본 섹션을 안 채웠다
  _vocab.md 미등재 좌표
  등록부가 가리키는 섹션 없음
  status: 미결 · 제안      아젠다다. 위험및이슈관리대장으로
  프론트매터 오류 · id ≠ 파일명

**`status` 는 적지 않는다.** 쓸 수 있는 값이 하나도 없다 — 지식공유문서는
작업의 **완료**에서 발생하고, 항상 그 시점에 완료된 것이 넘어온다. 끝나지
않은 일은 문서가 아니다.

    git config core.hooksPath .githooks    ← clone 직후 한 번

훅은 clone 을 따라오지 않는다.
