# 업무규칙정의서

서술형. **문서 전체가 내용**이라 쪼갤 대상이 없다 — 등록부에 올리지 않는다.

| | |
|---|---|
| 관리번호 | `GDI_DE_431` |
| 제출시기 | 설계완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

**무엇** — 코드로 옮기기 전에 **말로 못 박은 업무 규칙**. "이럴 때는 이렇게 한다" 의
목록.
**언제** — 설계. 화면·프로그램 설계와 나란히.
**누가** — 업무 담당 PL 이 현업과 확인하며.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 그 규칙을 구현한 프로그램 | `프로그램사양서` 의 처리 규칙 |
| 화면에서 어떻게 보이나 | `화면설계서` |
| 코드값 목록 | `코드정의서` |

> **좌표형으로 올릴지 아직 정하지 않았다.** 규칙마다 ID 가 있으면
> `rule:` 좌표를 만들어 등록부에 올릴 수 있다. 이 패키지에는 **실물이
> 없어서**(원본에 서식이 없었다) 판단을 미뤘다 — 첫 프로젝트에서 규칙이
> 실제로 몇 개고 어떻게 참조되는지 보고 정한다.
> 
> 올리기로 하면 `_managed.md` 에 `rule:*` 한 줄과 이 문서의 섹션 구조를
> 함께 바꾼다.

## 제목 뼈대

아래 절을 채운다. **발주처 양식이 있으면 그것이 우선**이고, 이 뼈대는
무엇을 빠뜨리지 말아야 하는지의 점검표로 쓴다.

| # | 절 | 무엇을 적나 |
|--:|---|---|
| 1 | 규칙 목록 | 규칙마다 `ID · 대상 · 조건 · 처리 · 예외` |
| 2 | 우선순위 | 규칙이 충돌할 때 무엇이 이기나 |
| 3 | 근거 | 각 규칙이 어느 요구(`req:`)나 회의에서 왔나 |

> 제목은 자유롭게 쓴다 — **등록부 비대상이라 좌표와 충돌하지 않는다.**
> 다만 `## 작성지침` 은 남겨 둔다.
