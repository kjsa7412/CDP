# 월간보고서

날짜축. 월 단위 공정 · 이슈 · 계획. **주간보고서 와 같은 6절 구조**이고 기간만 다르다.

| | |
|---|---|
| 관리번호 | `GDI_BM_431` |
| 제출시기 | 매월 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 날짜축이다 |

**무엇** — 이번 월에 **계획 대비 어디까지 갔고 무엇이 막혔는지**. 그리고 다음 월에 무엇을 할 것인지.
**언제** — 월 마지막 근무일. 미루면 기억으로 쓰게 된다.
**누가** — PM 이 취합하고 각 PL 이 자기 단계를 채운다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 진도율의 **근거** | `WBS` · `개발일정계획서` — 여기는 **옮겨 적는 것**이다 |
| 이슈의 전체 이력 | `위험및이슈관리대장` — 여기는 이번 월 움직임만 |
| 설계 판단 | 작업 기록(`work/`) |

> **진도율을 여기서 세지 않는다.** WBS 와 개발일정계획서의 실적에서 나온다.
> 여기에 따로 세면 두 숫자가 갈리고, 그때 사람은 보고서를 믿는다.
