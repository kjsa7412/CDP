# AN_112 요구사항추적표

요구사항이 **어디로 이어졌는가**. 행 하나가 요구사항 하나다.

| | |
|---|---|
| 관리번호 | `AN_112` |
| 제출시기 | 수시 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 집계다 |

**무엇** — 요구사항 하나가 어느 화면 · 프로그램 · 시험으로 이어졌는지를
한 줄로 본다. 발주처가 *"이건 어디서 확인하나"* 를 물을 때 내는 문서다.
**언제** — 수시. 실제로는 **검수 직전에 제일 많이 본다.**
**누가** — PM · PL.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 요구의 내용 · 협의 경위 | `요구사항정의서` |
| 그 화면·프로그램이 무엇인가 | `화면설계서` · `프로그램사양서` |

> **손으로 채우면 빈다.** 원본에는 요구사항정의서 안에 추적 컬럼(화면ID ·
> 프로그램ID · 시험ID)이 있었는데 **84건 중 0건이 채워져 있었다.**
>
> 그래서 이 표는 **작업 기록에서 나온다.** 작업 기록의 `touches` 에
> `req:` 와 `screen:` · `prog:` · `scenario:` 가 함께 들어가면 그 연결이
> 생기고, 뷰어의 **뻗어나가기**가 따라간다. 이 표는 그것을 **제출 서식으로
> 옮겨 적은 것**이다 — 원천이 아니다.

| 요구사항ID | 요구 요약 | 화면 | 프로그램 | 시험 | 완료 |
|---|---|---|---|---|:--:|
| (예시) `EX-SFR-01-01` | 반응형 웹 | 전체 | | `IT-공통` | Y |
| (예시) `EX-USR-RP-01` | 참여율 이력 | `EXA011` | `EXA011` | `IT-EXA011` | N |

> ⚠ **예시 행이다 — 지우고 시작한다.**

---

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 요구사항ID | 좌표 `req:` 와 같은 값 | 필수 |
| 화면 · 프로그램 · 시험 | 좌표 값. 여럿이면 공백으로 나열 | 필수 |
| 완료 | `Y` / `N`. **N 인 채로 검수에 들어가지 않는다** | 필수 |

> **채우는 대신 뽑는 것을 권한다.** `ctx where <좌표>` 가 그 좌표에 걸린
> 작업 기록과 섹션을 보여 준다. 손으로 옮겨 적기 전에 그것으로 확인한다.
