# EC_101 개발일정계획서

개발 일정의 지금 상태. 행 하나가 **프로그램 하나**다.

| | |
|---|---|
| 관리번호 | `EC_101` |
| 제출시기 | 구현완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 시간축이고 계속 바뀐다 |

**무엇** — 프로그램마다 **누가 · 며칠에 · 언제** 만드는지를 적고 실적을 채운다.
진척률이 여기서 나온다.
**언제** — 구현 준비에서 만들고, 매일 실적을 채운다.
**누가** — 개발 PL.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 사업 단위 일정 | `WBS` — 이쪽은 **프로그램 단위**다 |
| 그 프로그램이 무엇을 하나 | `프로그램사양서` |
| 프로그램이 몇 개인가 · 권한은 | `프로그램목록` |

> **차수를 열로 늘리지 않는다.** 원본은 1차·2차 개발을 같은 행에 두 벌로
> 두어 컬럼이 스물이 넘었다. 차수가 갈리면 **행을 나눈다** — 같은 프로그램의
> 2차 개발은 별도 행이고 `차수` 로 구분한다.

| 대분류 | 프로그램ID | 프로그램명 | 차수 | 유형 | 공수(M/D) | 담당 | 계획 시작 | 계획 완료 | 실제 시작 | 실제 완료 |
|---|---|---|:--:|---|--:|---|---|---|---|---|
| (예시) EX | `EXA010` | 과제접수목록 | 1 | 화면 | 0.5 | 개발A | 2026-04-01 | 2026-04-01 | 2026-04-01 | 2026-04-01 |
| (예시) EX | `EXA011` | 과제접수등록 | 1 | 화면 | 1.0 | 개발A | 2026-04-02 | 2026-04-02 | 2026-04-02 | |
| (예시) EX | `EXA010` | 과제접수목록 | 2 | 화면 | 0.5 | 개발A | 2026-05-10 | 2026-05-10 | | | 

> ⚠ **예시 행이다 — 지우고 시작한다.**

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 프로그램ID | `프로그램목록` 과 **같은 값**. 좌표 `프로그램사양서:` 와도 같다 | 필수 |
| 차수 | 1 · 2 …. 같은 프로그램의 재작업은 **행을 나눈다** | 필수 |
| 유형 | 화면 · 배치 · API · 출력물 · 기안문 | 필수 |
| 공수 | M/D. 화면과 버퍼를 나누지 말고 **합쳐서 하나로** | 필수 |
| 담당 | 역할 또는 개발자 구분. 인사이동을 생각하면 역할이 낫다 | 필수 |
| 계획 · 실제 | `YYYY-MM-DD`. **실제 완료가 진척률의 분자다** | 필수 |

> **진척률은 세지 않고 계산한다.** 실제 완료가 채워진 행 ÷ 전체 행이다.
> 별도 시트에 숫자를 적어 두면 표와 갈라진다 — 원본이 그랬다.
