# DE_501 인터페이스정의서

연계의 지금 상태. 섹션 하나가 인터페이스 하나다. **요약과 컬럼 매핑을 한
섹션에** 둔다.

| | |
|---|---|
| 관리번호 | `DE_501` |
| 제출시기 | 설계완료 |
| 필수 제출 | 아니오 |
| 등록부 | `인터페이스:*` → `## {값}` · `배치:*` → `## {값}` |
| 좌표 값 | 인터페이스 ID · 배치 Object |

**무엇** — 외부와 주고받는 것마다 **누가 · 무엇을 · 언제 · 어떻게** 를 적고,
컬럼 단위 매핑을 붙인다.
**언제** — 설계에서 만들고, 주기나 항목이 바뀌면 고친다.
**누가** — 연계 담당.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 연계 경로의 큰 그림 | `시스템아키텍처정의서` 의 `시스템아키텍처:link` |
| 테이블의 컬럼 구성 | `테이블정의서` |
| 연계 목록만 | `인터페이스목록` — 여기는 건별 상세다 |

> **원본은 요약 시트와 상세 시트 21장으로 갈려 있었다.** 한눈에 보려던
> 장치인데, MD 에서는 목록이 필요하면 `INDEX.md` 가 만든다. **섹션 하나에
> 둘 다 둔다.**
>
> **`배치:` 는 `처리형태 = Batch` 인 것에만 붙인다.** 값은 스케줄러
> Object 명이다. Object 가 없는 건은 `인터페이스:` 만 갖는다 — 이름을 지어내지
> 않는다.

## EX-INT-1001 — (예시) 거래처정보 수신
<!-- applied: null -->

| | |
|---|---|
| 사용여부 | Y |
| Source | 외부시스템 · `EXDB` · `EX_PARTNER` |
| Target | 우리 · `exdb` · `테이블정의서:ex_partner` |
| 전송주체 | Target (우리가 가져온다) |
| 처리형태 | Batch · 24시간 · 01:00 |
| 연계방식 | Pull — 수신 측이 제공 DB 를 조회 |
| 연계기술 | JDBC |
| Object | `배치:ExPartnerBatchJob` |

**컬럼 매핑**

| No | Source 컬럼 | Target 컬럼 | 타입 | PK | 비고 |
|--:|---|---|---|:--:|---|
| 1 | `PARTNER_CD` | `PARTNER_CD` | VARCHAR(10) | PK | |
| 2 | `PARTNER_NM` | `PARTNER_NM` | VARCHAR(100) | | |
| 3 | `USE_YN` | `USE_YN` | VARCHAR(1) | | `N` 도 받아 둔다 |

**실패 시** — 재시도하지 않는다. 다음 주기에 전량 다시 받는다.

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

<!-- 스케줄러 Object -->

## ExPartnerBatchJob — (예시) 거래처정보 수신 배치
<!-- applied: null -->

| | |
|---|---|
| 스케줄러 | Quartz |
| 주기 | 매일 01:00 |
| 무엇을 옮기나 | `인터페이스:EX-INT-1001` |
| 실패 알림 | 운영 채널 |

> ⚠ **이 섹션도 예시다 — 지우고 시작한다.**
>
> **Object 가 인터페이스와 1:1이 아니라서 따로 선다.** 원본 실측에서 Batch
> 15건이 Object 14개를 나눠 썼다 — 한 배치가 인터페이스 둘을 돌리는 자리가
> 있었다. 그래서 `배치:` 는 `인터페이스:` 의 속성이 아니라 **제 좌표**다.
>
> Object 가 없는 연계는 이 섹션을 만들지 않는다. **이름을 지어내지 마라.**

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<인터페이스ID> — <한 줄 요약>`. Object 섹션은 `<Object명> — <한 줄 요약>` | 필수 |
| Source · Target | `<시스템> · <DB> · <테이블>`. 우리 쪽은 `테이블정의서:` 로 가리킨다 | 필수 |
| 전송주체 | Source / Target. **누가 움직이나** | 필수 |
| 처리형태 | `Batch` · `실시간` · `수동` + 주기 + 실행시각 | 필수 |
| 연계방식 · 기술 | Pull/Push · JDBC/REST 등 | 필수 |
| Object | 배치면 `배치:<Object명>`. **그 Object 의 섹션도 따로 만든다** | 조건 |
| Object 섹션 | 스케줄러 · 주기 · 무엇을 옮기나(`인터페이스:` 로 가리킨다) · 실패 알림 | 조건 |
| 컬럼 매핑 | Source ↔ Target 한 행씩 | 필수 |
| 실패 시 | 재시도 · 알림 · 수동 복구 중 무엇인가 | 필수 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |
