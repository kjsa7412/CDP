# TE_102 단위테스트시나리오

단위테스트의 지금 상태. 섹션 하나가 **프로그램 하나**다.

| | |
|---|---|
| 관리번호 | `TE_102` |
| 제출시기 | 구현완료 |
| 필수 제출 | 아니오 |
| 등록부 | `scenario:UT-*` → `## {값}` |
| 좌표 값 | `UT-` + 프로그램ID |

**무엇** — 개발자가 자기 프로그램을 **혼자** 확인하는 절차다. 남에게 보여 주기 전에
스스로 밟는 순서.
**언제** — 구현하면서 만들고, 프로그램이 바뀌면 고친다.
**누가** — 개발 담당 본인

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 밟은 결과 · PASS/FAIL · 수정요청 | `단위테스트결과서` — **회차마다 쌓이는 사건**이다 |
| 언제 누가 모여서 하나 | `단위테스트계획서` |
| 화면 생김새 | `화면설계서` |

> **시나리오는 상태이고 결과는 사건이다.** 절차와 점검사항은 대상에
> 붙어 갱신되지만, 밟은 결과는 회차마다 따로 남는다. 원본은 한 시트에
> 섞어 두었는데 그러면 지난 회차가 덮인다.

## UT-EXA010 — (예시) 과제접수목록
<!-- applied: null -->

| | |
|---|---|
| 모듈 | 연구과제 › 과제접수 |
| 프로그램 | `prog:EXA010` |
| 담당 | 개발 담당 |

**절차**

| # | 구분 | 무엇을 |
|--:|---|---|
| 1 | 조회 | 조건 없이 〈조회〉 → 목록이 뜨는가 |
| 2 | 등록 | 필수값을 비우고 저장 → **막히는가** |
| 3 | 등록 | 정상 저장 → 목록에 즉시 반영되는가 |
| 4 | 권한 | 권한 없는 계정으로 등록 버튼이 **안 보이는가** |

**중점 점검사항**

- 저장 뒤 상태값이 `10`(임시) 인가
- 필수값 검증 메시지가 어느 필드인지 말하는가

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**
