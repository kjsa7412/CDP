# DE_431 데이터값검증방안서

서술형. **문서 전체가 내용**이라 쪼갤 대상이 없다 — 등록부에 올리지 않는다.

| | |
|---|---|
| 관리번호 | `DE_431` |
| 제출시기 | 설계완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

**무엇** — 데이터가 **맞는지 어떻게 확인할 것인가**. 이관 전후 대사 · 입력 검증 ·
정합성 점검 방법.
**언제** — 설계 후반. 이관 스크립트를 만들기 전에.
**누가** — DB 설계 담당 + 이관 담당.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 이관 대상 목록 · 진행 | `데이터이관정의서` |
| 업무 규칙 자체 | `업무규칙정의서` |
| 성능 확인 | `성능테스트시나리오` |

> **"검증했다" 의 결과는 여기 적지 않는다.** 여기는 방법이고, 실제 대사
> 결과는 이관 회차의 기록이다 — `데이터이관정의서` 의 완료 열이나
> `위험및이슈관리대장` 으로 간다.

## 제목 뼈대

아래 절을 채운다. **발주처 양식이 있으면 그것이 우선**이고, 이 뼈대는
무엇을 빠뜨리지 말아야 하는지의 점검표로 쓴다.

| # | 절 | 무엇을 적나 |
|--:|---|---|
| 1 | 검증 대상 | 어떤 데이터를 본다는 것인가 |
| 2 | 건수 대사 | 원천 대 이관 후 건수 비교 방법과 허용 오차 |
| 3 | 값 대사 | 금액 합계 · 코드 매핑 · 날짜 범위 등 표본 비교 |
| 4 | 정합성 | FK · 필수값 · 중복 확인 쿼리 |
| 5 | 입력 검증 | 화면에서 막을 것과 DB 제약으로 막을 것의 경계 |
| 6 | 실패 시 | 무엇을 하고 누구에게 알리나 |

> 제목은 자유롭게 쓴다 — **등록부 비대상이라 좌표와 충돌하지 않는다.**
