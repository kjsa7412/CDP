# DE_421 ERD모델링

엔터티 사이의 **관계**. 행 하나가 관계 하나다.

| | |
|---|---|
| 관리번호 | `DE_421` |
| 제출시기 | 설계완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — `테이블정의서:` 은 `테이블정의서` 가 갖는다 |

**무엇** — 어떤 테이블이 어떤 테이블을 참조하고, 하나에 여럿인지 여럿에
여럿인지를 적는다.
**언제** — 설계에서 만든다. **테이블정의서와 같이 움직인다.**
**누가** — DB 설계 담당.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 컬럼 구성 · 타입 · 제약 | `테이블정의서` |
| 이관 시 참조 순서 | `데이터이관정의서` 의 선행 의존 |

> **`테이블정의서:` 좌표를 여기에 걸지 않는다.** 테이블의 "지금 상태" 는
> 테이블정의서가 갖는다. 셋(테이블정의서 · ERD모델링 · 데이터이관정의서)이
> 같은 좌표를 나눠 가지면 **정본이 셋**이 된다 — 등록부가 패턴 하나에 문서
> 하나인 이유다.
>
> **그림은 첨부로 둔다.** 관계도를 그렸으면 `work/assets/<작업id>/` 에 두고
> 여기서 링크한다. 이 표가 정본이고 그림은 보조다.

| 부모 | 자식 | 관계 | FK 컬럼 | 삭제 시 | 비고 |
|---|---|---|---|---|---|
| (예시) `ex_prj_mst` | `ex_plan_mst` | 1:N | `PRJ_ID` | 막는다 | 과제에 계획서 여럿 |
| (예시) `ex_plan_mst` | `ex_plan_targr_list` | 1:N | `PLAN_ID` | 같이 지운다 | 대상자 목록 |
| (예시) `ex_code_mst` | `ex_code_dtl` | 1:N | `CD_GRP` | 막는다 | |

> ⚠ **예시 행이다 — 지우고 시작한다.**
