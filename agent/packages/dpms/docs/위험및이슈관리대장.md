# 위험및이슈관리대장

결정이 필요한 것 · 위험 · 막힌 것. **아직 끝나지 않은 것**을 다룬다.

| | |
|---|---|
| 관리번호 | `GDI_BM_501` |
| 제출시기 | 수시 |
| 필수 제출 | 아니오 |
| 등록부 | `issue:*` → `## {값}` |
| 좌표 값 | 이슈 식별 ID |

**무엇** — 답이 안 난 것을 한 자리에 모은다. 식별 → 해결방안 → 해결 3단으로
상태가 흐른다.
**언제** — **생기는 즉시.** 주간보고에서 몰아 쓰면 이미 늦다.
**누가** — 발견한 사람이 올리고, 처리 담당이 갱신한다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| **끝난 판단** | 작업 기록(`work/`) — 지식공유문서는 **완료**에서 나온다 |
| 일정 지연 자체 | `WBS` · `개발일정계획서`. 여기는 **왜 막혔나**다 |
| 테스트 실패 건 | `통합테스트결과서` — 회차마다 쌓이는 사건이다 |

> **여기와 작업 기록의 경계가 이 문서의 핵심이다.** 끝난 것은 작업 기록으로
> 가고, 여기는 **아직 아젠다인 것**만 남는다. 작업 기록에 `status: 미결`
> 같은 것을 붙이면 `ctx check` 가 막는다 — 그런 상태는 없다.

## 작성지침

작성지침은 원본 대장의 `작성지침` 시트를 따른다 — **실제 대장보다 항목이
많다.** 지침이 표준이고 대장은 그 프로젝트의 구현이다.

| 구분 | 항목 | 작성방법 | 필수 |
|---|---|---|:--:|
| 식별 | 섹션 제목 | `<식별ID> — <이슈명>` | 필수 |
| | 유형 | 계약 · 일정 · 범위 · 품질 · 기술 등 | 필수 |
| | 관련 영역 | 업무 또는 서비스 | 필수 |
| | 식별단계 | 착수 · 분석 · 설계 · 구현 · 시험 · 이행 | 필수 |
| | 제기 | `날짜 · 역할` | 필수 |
| | 중요도 · 긴급도 | 상 / 중 / 하 | 필수 · 선택 |
| | 내용 | 무엇이 막혔나. **배경까지** | 필수 |
| | 원인 | 왜 이렇게 됐나 | 선택 |
| 해결방안 | 처리 담당 | 역할 | 필수 |
| | 해결방안 | 무엇을 할 것인가 | 필수 |
| | 완료 예정 | 날짜 | 선택 |
| 해결 | 진행상태 | **검토 · 처리중 · 해결** 셋 중 하나 | 필수 |
| | 경과 | `` `날짜` 무엇이 `` 목록으로 **쌓는다** | 필수 |
| | 관련 좌표 | 이 이슈가 걸린 대상 | 선택 |

> **경과는 덮어쓰지 않고 쌓는다.** 원본에서는 적을 자리가 없어 한 셀 안에
> `<7/5 기준>` 같은 접두를 붙이는 관행이 생겼다. 여기는 목록이 그 자리다.
