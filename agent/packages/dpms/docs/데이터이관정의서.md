# 데이터이관정의서

이관의 지금 상태. 행 하나가 **테이블 하나**다.

| | |
|---|---|
| 관리번호 | `GDI_DE_461 · GDI_EC_301` |
| 제출시기 | 설계완료 · 구현완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — `table:` 은 `테이블정의서` 가 갖는다 |

**무엇** — 옛 시스템의 데이터를 **무엇을 · 어떻게 · 누가 · 어느 순서로** 옮길
것인지와 그 진행 상황.
**언제** — 설계에서 대상을 정하고, 구현에서 스크립트를 만들며 채운다.
**누가** — 이관 담당 + 업무 담당(대상 판단).

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 테이블의 컬럼 구성 | `테이블정의서` |
| 이관 당일 시간표 | `안정화계획서` 또는 이행 일정 |
| 이관 중 터진 문제 | `위험및이슈관리대장` |

> **`table:` 좌표를 여기에 걸지 않는다.** 진행 상황은 "지금 상태" 이긴
> 하지만 그 대상의 정본은 테이블정의서다. 둘이 같은 좌표를 나눠 가질 수 없다.
>
> **원본은 대장에 두 번 올라 있었다** — 설계(`DE_461`)와 구현(`EC_301`)에
> 띄어쓰기만 다르게. 한 문서로 합쳤고, 단계는 `이관방식` 과 진행 컬럼으로
> 구분한다.

| 그룹 | 테이블 | 설명 | 행수 | 대상 | 이관방식 | 스크립트 | 선행 | 완료 | 담당 |
|---|---|---|--:|:--:|---|---|---|:--:|---|
| (예시) 기초 | `ex_code_mst` | 공통코드 | 180 | Y | 전량 | `01_code.sql` | | Y | 이관A |
| (예시) 기초 | `ex_code_dtl` | 코드상세 | 1,240 | Y | 전량 | `02_code_dtl.sql` | `01_code.sql` | Y | 이관A |
| (예시) 과제 | `ex_prj_mst` | 과제마스터 | 3,120 | Y | 정리 후 | `10_prj.sql` | `02_code_dtl.sql` | N | 이관B |
| (예시) 과제 | `ex_tmp_log` | 임시로그 | 82,000 | **N** | — | | | — | | 

> ⚠ **예시 행이다 — 지우고 시작한다.**

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 그룹 | 이관 묶음. **선행 관계가 그룹을 넘지 않게** 짠다 | 필수 |
| 테이블 | 물리명(소문자). `테이블정의서` 의 섹션 값과 같게 | 필수 |
| 행수 | 원천 기준 건수. **0 이면 대상에서 빼는 근거가 된다** | 필수 |
| 대상 | `Y` / `N`. **N 도 지우지 않고 남긴다** — 왜 안 옮기는지가 근거다 | 필수 |
| 이관방식 | 전량 · 정리 후 · 수기 · 연동 | 대상이면 필수 |
| 스크립트 · 선행 | 파일명과 먼저 돌아야 하는 스크립트. **순서가 여기서 나온다** | 대상이면 필수 |
| 완료 | `Y` / `N`. 리허설과 본이관을 나누려면 열을 늘린다 | 필수 |

> **대상이 아닌 것을 지우지 마라.** 지우면 6개월 뒤 *"이건 왜 안 옮겼지"* 에
> 답할 것이 없다. `N` 으로 두고 비고에 이유를 적는다.
