# 관리번호

산출물마다 붙는 번호의 규칙. **이 파일 하나가 규칙의 정본**이다 — 각 문서
머리 표의 `관리번호` 는 여기서 정한 값을 적은 것이다.

---

## 1. 모양

```
BM _ 4 3 1
 │    │ │ └ 일련    그 TASK 안의 몇 번째 산출물인가   1..9
 │    │ └── 중분류   그 단계 안의 TASK               0..9  (없으면 0)
 │    └──── 대분류   공정 안의 단계                   1..9
 └───────── 공정     BM AN DE EC TE TR
```

`BM_431` = 사업관리 › 의사소통관리(4) › 월간보고(3) › 1번째 = **월간보고서**.

### 공정 여섯

| 코드 | 공정 | 언제 | 문서 |
|---|---|---|--:|
| `BM` | 사업관리 | **전 기간** | 11 |
| `AN` | 분석 | 분석 단계 | 2 |
| `DE` | 설계 | 설계 단계 | 17 |
| `EC` | 구현 | 구현 단계 | 2 |
| `TE` | 시험 | 시험 단계 | 9 |
| `TR` | 이행 | 이행 단계 | 4 |
| | | | **45** |

**`BM` 은 순서 축에 놓이지 않는다.** 착수보고서는 맨 앞이고 완료보고서는 맨
끝이며 주간보고는 전 기간이다. 그래서 폴더가 둘이다 — §3.

---

## 2. 사업 코드는 여기에만 적는다

제출물의 파일명은 앞에 **사업 코드**가 붙는다.

```
레포 안    docs/2.개발/DE_331_화면설계서.md
제출물     ____-DE_331_화면설계서.pptx
           └ 여기에 사업 코드
```

| | |
|---|---|
| **이 사업의 코드** | `____` ← **여기를 고친다** |

**문서 46개에 사업 코드를 적지 않는다.** 레포 안에는 사업이 하나뿐이라 그
자리는 정보가 0 이고, 틀릴 자리만 46개 생긴다. 사업이 바뀌면 위 한 칸만
고친다.

---

## 3. 배치 — 번호순이 곧 일하는 순서다

```
docs/
  1.관리/     BM_111 … BM_601          전 기간에 걸친 것
  2.개발/     AN_… DE_… EC_… TE_… TR_…  분석 → 설계 → 구현 → 시험 → 이행
```

개발 폴더 안에서는 **파일명 오름차순이 그대로 업무 순서**다. 공정 코드
`AN < DE < EC < TE < TR` 이 이미 그 순서이기 때문에 따로 순번을 붙이지 않았다.
순번을 붙이면 공정 코드와 같은 말을 두 번 하게 되고, 어긋날 자리만 생긴다.

> **폴더는 규약이 아니다.** CDP 는 `docs/` 아래 어떤 깊이든 관리 문서로 읽는다
> (`docs/**/*.md`). 평평하게 쓰던 레포는 그대로 두어도 된다 — 이 두 폴더는
> 이 패키지가 고른 배치일 뿐이다.
>
> **깊이를 바꾸면 둘을 같이 고쳐라** — `_managed.md` 의 문서 경로, 그리고
> 문서 안에서 작업 기록을 가리키는 상대 경로. 지금은 두 단계라 `../../work/`
> 다. 평평하게 두면 `../work/` 가 된다.

## 4. 번호를 새로 줄 때

1. **공정**을 고른다 — 그 산출물을 *만드는* 단계다. 내는 시기가 아니다.
   (개발가이드는 구현완료에 내지만 설계에서 만들므로 `DE` 다.)
2. **대분류**는 그 공정 안의 단계. 이미 있는 것을 쓰고, 새 단계면 다음 수를 준다.
3. **중분류**는 그 단계 안의 TASK. 단계가 쪼개지지 않으면 `0`.
4. **일련**은 그 TASK 안에서 1 부터. **이미 있으면 반드시 올린다.**

> **제일 흔한 실수가 4번**이다. 원본에서 단위·성능·통합테스트의
> 계획서·시나리오·결과서가 각각 **셋이 한 번호**였고, 운영자·사용자메뉴얼도
> 한 번호였다. 번호가 겹치면 형상관리대장에서 어느 행이 어느 파일인지
> 알 수 없게 된다.

**번호는 식별자가 아니라 속성이다.** 이 레포에서 문서를 가리키는 것은
**문서명**이다. 번호는 발주처와 말을 맞추기 위한 것이고, 손으로 붙이는 것이라
언제든 어긋날 수 있다.

### 자리가 차면 TASK 를 쪼갠다

세 자리가 각각 `1..9` 다. **한 TASK 아래 열 번째 산출물이 생기면 적을 자리가
없다.** 그때 번호를 두 자리로 늘리지 마라 — 자릿수가 위치를 뜻한다는 성질이
거기서 깨진다.

**열 개가 한 TASK 라는 것이 먼저 의심스럽다.** 중분류를 둘로 쪼개고 다음
수를 준다. 지금 이 패키지는 한 TASK 최대 **3개**다(`DE_42*` 테이블·코드·ERD,
시험 3종). 자리가 찰 일은 당분간 없다.

### 빈 번호는 메우지 않는다

`AN_111` `AN_121` 처럼 비어 있는 자리가 있다. 그 TASK 가 원본에 있었고 이
패키지에서 산출물이 다른 공정으로 옮겨 갔다는 기록이다. 당겨서 메우면 번호가
위치를 뜻한다는 성질이 깨진다.

## 5. 원본과 다르게 준 자리

이 패키지는 `C:\project\DPMS` 의 번호를 그대로 쓴다. **아래 셋만 고쳤다.**

### 5.1 겹친 번호 — 일련 자리를 올렸다

| 원본 | 이 패키지 | 문서 |
|---|---|---|
| `BM_111` ×2 | `BM_111` `BM_112` | 착수보고서 · 사업수행계획서 |
| `DE_431` ×2 | `DE_431` `DE_432` | 데이터값검증방안서 · 업무규칙정의서 |
| `DE_441` ×2 | `DE_441` `DE_442` | 메타데이터현행화결과 · 데이터개방지원방안 |
| `TE_101` ×3 | `TE_101` `TE_102` `TE_103` | 단위테스트 계획서 · 시나리오 · 결과서 |
| `TE_201` ×3 | `TE_201` `TE_202` `TE_203` | 성능테스트 〃 |
| `TE_301` ×3 | `TE_301` `TE_302` `TE_303` | 통합테스트 〃 |
| `TR_211` ×2 | `TR_211` `TR_212` | 운영자메뉴얼 · 사용자메뉴얼 |

### 5.2 번호가 둘이던 문서 — **만드는 단계**로 모았다

원본 대장은 같은 이름을 분석 단계와 설계 단계에 각각 올려 두었다. 이 패키지는
문서를 하나로 합쳤으므로 번호도 하나다.

| 문서 | 이 패키지 | 버린 것 |
|---|---|---|
| 프로세스정의서 | `DE_211` | `AN_211` |
| 프로그램목록 | `DE_321` | `AN_231` |
| 코드정의서 | `DE_423` | `AN_251` |
| 시스템아키텍처정의서 | `DE_101` | `AN_261` |
| 데이터이관정의서 | `DE_601` | `EC_301` |

분석 단계 것은 AS-IS 조사이고 설계 단계 것이 TO-BE 정본이다. 문서 하나가 둘을
다 담으므로 **정본 쪽**을 쓴다. AS-IS 를 따로 관리해야 하는 사업이라면 문서를
둘로 쪼개고 `AN_` 번호를 되살려라.

### 5.3 대장이 틀린 자리 — **폴더와 실물 파일**을 따랐다

| 문서 | 대장 | 이 패키지 | 근거 |
|---|---|---|---|
| 기능정의서 | `AN_221` | `DE_221` | 실물이 `GDI_DE_221_기능정의서.xlsx` 이고 폴더가 `설계/프로세스설계` |
| 요구사항정의서 | `AN_111` | `AN_211` | 폴더가 `분석(AN)/02. 요구사항분석` — 대분류는 2 다 |
| 인터페이스목록 | `AN_241` | `AN_141` | 대장의 `현황분석` 은 폴더의 `01. 사전분석` 이다 |
| 인터페이스정의서 | `DE_451` | `DE_501` | 폴더가 `설계/05. 인터페이스설계` — 대분류는 5 다 |
| 데이터이관정의서 | `DE_461` | `DE_601` | 실물이 `GDI_DE_601_데이터이관.xlsx` 이고 폴더가 `06. 데이터이관설계` |

`DE_451` `DE_461` 은 대장이 `441` 다음에 **수를 이어 센 것**이다. 그러면
대분류 `4` 가 DB설계와 인터페이스설계 둘을 뜻하게 되어, 번호가 위치를 뜻한다는
규칙이 그 자리에서 깨진다. 실물 파일 `GDI_DE_601` 이 폴더 쪽 읽기를 지지한다.

**`AN` 은 대분류가 통째로 뒤집혀 있었다.** 대장은 `1 = 요구사항분석`,
`2 = 현황분석` 으로 셌는데 폴더는 `01. 사전분석`, `02. 요구사항분석` 이다.
폴더를 따른다 — `사전분석` 이 곧 대장이 말한 `현황분석` 이다.

| | 대장 | 이 패키지 |
|---|---|---|
| 대분류 1 | 요구사항분석 | **사전분석** (= 대장의 현황분석) |
| 대분류 2 | 현황분석 | **요구사항분석** |

> 여기서만 **실물 파일이 대장 편**이다 — `GDI_AN_111_요구사항정의서.xlsx` 가
> `02. 요구사항분석` 폴더에 들어 있으면서 번호는 `1` 이다. 폴더 이름과 파일
> 번호가 정면으로 부딪히는 유일한 자리이고, **폴더를 택했다.** §1 의 규칙을
> 폴더에서 역산했으므로 그 편이 일관된다.

> 발주처가 원본 번호로 말을 맞춰 둔 사업이라면 이 셋을 되돌려라.
> **고칠 곳은 문서 머리 표와 파일명, 그리고 형상관리대장 행뿐**이다.
