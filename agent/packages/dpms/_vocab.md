# 좌표 어휘

이 파일이 통제 어휘(authority file)다. 같은 대상을 가리키는 여러 표기 중
**정본을 하나 정하고 나머지를 `aliases` 로 연결한다.** `aliases` 가 이 파일의
진짜 핵심이다 — 정본 목록만 있으면 작성자만 편해지고, `aliases` 가 있어야
수신자가 자연어로 물어도 걸린다.

**운영 원칙** — 추가는 한 줄, 삭제는 하지 않는다(`deprecated` 로 표시),
alias 는 발견될 때마다 추가한다.

---

## 무슨 일을 하면 무엇을 적나

작업 기록의 `touches:` 에 좌표를 적으면 **그 관리 문서를 고칠 때까지 커밋이
막힌다.** 그것이 파생 강제다. 어느 일이 어느 문서로 가는지가 아래 표다.

| 이런 일을 했으면 | `touches:` 에 | 고쳐야 하는 관리 문서 |
|---|---|---|
| 요구사항을 받거나 바꿨다 | `req:<요구사항ID>` | `AN_211` 요구사항정의서 |
| 업무 흐름을 바꿨다 | `proc:<프로세스번호>` | `DE_211` 프로세스정의서 |
| 기능을 더하거나 뺐다 | `func:<기능ID>` | `DE_221` 기능정의서 |
| 서버 · DB · 스택 · 연계 구성을 바꿨다 | `arch:hw` `db` `sw` `link` | `DE_101` 시스템아키텍처정의서 |
| 화면을 만들거나 고쳤다 | `screen:<화면ID>` | `DE_331` 화면설계서 |
| 프로그램 로직을 바꿨다 | `prog:<프로그램ID>` | `EC_201` 프로그램사양서 |
| 테이블 · 컬럼을 바꿨다 | `table:<물리명>` | `DE_422` 테이블정의서 |
| 표준 용어를 정했다 | `term:<논리명>` | `DE_412` DB도메인용어정의서 |
| 코드값을 더하거나 뺐다 | `code:<구분코드>` | `DE_423` 코드정의서 |
| 연계를 만들거나 바꿨다 | `api:<인터페이스ID>` | `DE_501` 인터페이스정의서 |
| 배치 Object 를 바꿨다 | `batch:<Object명>` | 〃 |
| 시험 시나리오를 바꿨다 | `scenario:UT-*` `PT-*` `IT-*` | `TE_102` `TE_202` `TE_302` |
| 위험 · 이슈가 생기거나 닫혔다 | `issue:<이슈ID>` | `BM_501` 위험및이슈관리대장 |

**여기 없는 일에는 좌표가 없다.** 회의 · 보고 · 시험 결과는 *사건*이라
파생할 대상이 없고, 대장 · 계획서 · 가이드는 *집계*거나 *서술*이라 좌표와
섹션이 1:1이 아니다. 그것들은 **작업 기록 자체가 원천**이다 — 좌표를
지어내서 억지로 걸지 마라.

> **하나의 일이 좌표 여럿을 건드리는 것이 정상이다.** 화면 하나를 고치면서
> 테이블을 바꿨으면 `screen:` 과 `table:` 을 둘 다 적는다. 적은 만큼 고쳐야
> 하고, 그것이 문서가 갈라지지 않는 이유다.

## 값이 예시로 채워져 있다 — 지우고 시작한다

아래 값은 **문서의 예시 섹션과 짝**이다. `ex_` · `EX` · `예시` 로 시작하는
줄과 `proc:1.1.1` 이 그것이고, 문서의 예시 섹션을 지울 때 여기 줄도 같이
지운다. 한쪽만 지우면 `ctx check` 가 막는다 — 그게 정상이다.

**지우기 전에 한 바퀴 돌려 보면 좋다.** 이 한 벌이 붙어 있어서 부은 직후에도
파생 고리가 실제로 돈다.

```
ctx where table:ex_plan_mst      정본이 어느 문서 어느 섹션인가
ctx derive                       파생이 남은 섹션
ctx apply table:ex_plan_mst      섹션에 붙일 초안
```

**`arch:` 넷만 예시가 아니다.** 원본에 ID 가 없는 유일한 문서라 좌표를 팀이
정해야 하는데, 넷은 어느 사업에나 있으므로 값으로 박아 두었다.

> `## <타입>` 의 **순서가 화면 · CLI 의 카테고리 순서**이므로 순서는 건드리지
> 않는다. 쓰지 않는 타입은 통째로 지운다.

## req

- `req:EX-SFR-01-01` — (예시) 반응형 웹 지원
  aliases: 반응형, 모바일 지원
- `req:EX-USR-RP-01` — (예시) 참여율 이력 관리
  aliases: 참여율 이력, 참여율

## proc

- `proc:1.1.1` — (예시) 과제접수
  aliases: 과제 접수, 접수 프로세스

## func

- `func:EX-FNC-RP-01` — (예시) 연구과제 접수
  aliases: 과제접수 기능

## arch

- `arch:hw` — H/W 아키텍처
  aliases: 서버, 하드웨어, 장비 구성
- `arch:db` — DB 아키텍처
  aliases: 데이터베이스 구성, DB 서버
- `arch:sw` — S/W 아키텍처
  aliases: 소프트웨어 스택, 미들웨어, WAS
- `arch:link` — 데이터 연계
  aliases: 연계 구성, 인터페이스 구성, 연계 경로

## screen

- `screen:EXA010` — (예시) 과제접수목록
  aliases: 과제접수 목록화면, 접수목록

## prog

- `prog:EXA010` — (예시) 과제접수목록
  aliases: 과제접수목록 프로그램

## table

- `table:ex_plan_mst` — (예시) 계획서마스터
  aliases: 계획서, 계획서테이블, EX_PLAN_MST

## term

- `term:예시계약금액` — (예시) 금액 도메인
- `term:예시참여율` — (예시) 비율 도메인
- `term:예시진행상태코드` — (예시) 코드 도메인

## code

- `code:EX010` — (예시) 연구분류
  aliases: 연구분류코드, 과제분류

## api

- `api:EX-INT-1001` — (예시) 거래처정보 수신
  aliases: 거래처 연계, 파트너 수신

## batch

- `batch:ExPartnerBatchJob` — (예시) 거래처정보 수신 배치
  aliases: 거래처 배치

## scenario

- `scenario:UT-EXA010` — (예시) 과제접수목록 단위시험
- `scenario:PT-EXA010` — (예시) 과제접수목록 성능시험
- `scenario:IT-EXA010` — (예시) 과제접수목록 통합시험

## issue

- `issue:EX-RIS-01` — (예시) 외부 연계 계정 발급 지연
  aliases: 계정 발급 지연

## domain

**등록부 비대상이다.** 문서로 파생하지 않고 **찾기에만 쓴다** — DPMS 는 같은
업무 영역을 문서마다 다르게 불렀다(코드정의서는 `RP` 하나인데 프로그램목록은
`SE` · `EX` · `MG` 셋). 그 표기를 여기 모아 둔다.

- `domain:EX` — (예시) 예시업무
  aliases: 예시, EXAMPLE
