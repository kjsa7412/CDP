# 좌표 어휘

이 파일이 통제 어휘(authority file)다. 같은 대상을 가리키는 여러 표기 중
**정본을 하나 정하고 나머지를 `aliases` 로 연결한다.** `aliases` 가 이 파일의
진짜 핵심이다 — 정본 목록만 있으면 작성자만 편해지고, `aliases` 가 있어야
수신자가 자연어로 물어도 걸린다. 「원페이지 결제」 로 물어도, 「/v1/orders」 로
물어도 같은 섹션이 나와야 한다.

**운영 원칙** — 추가는 한 줄, 삭제는 하지 않는다(`deprecated` 로 표시),
alias 는 발견될 때마다 추가한다. 이슈 트래커의 에픽 키 · 디자인 프레임 이름 ·
API 경로 · 테이블 이름처럼 **팀이 이미 부르는 이름**을 alias 로 건다.

---

## 무슨 일을 하면 무엇을 적나

작업 기록의 `touches:` 에 좌표를 적으면 **그 관리 문서를 고칠 때까지 커밋이
막힌다.** 그것이 파생 강제다. 어느 일이 어느 문서로 가는지가 아래 표다 —
**처음 부은 상태의 안내**다. 지금 등록부는 그 아래 생성 블록이 정본이다.

| 이런 일을 했으면 | `touches:` 에 | 고쳐야 하는 관리 문서 |
|---|---|---|
| 기능을 기획하거나 범위 · 수용 기준 · 상태를 바꿨다 | `기능명세:<기능 키>` | `PD_301` 기능명세 |
| 지표를 새로 정의하거나 계산식 · 출처 이벤트 · 목표를 바꿨다 | `제품지표:<지표 키>` | `PD_401` 제품지표 |
| 외부 연동 · 서비스 구성 · 배포 환경 · 인증 구조를 바꿨다 | `시스템아키텍처:context` `container` `deploy` `security` | `DS_101` 시스템아키텍처 |
| 화면을 만들거나 상태 · 동작 · 접근성을 바꿨다 | `화면명세:<화면 키>` | `DS_201` 화면명세 |
| API 자원을 더하거나 계약(필드 의미 · 오류 · 판)을 바꿨다 | `인터페이스:<자원 키>` | `DS_301` 인터페이스명세 |
| 엔터티를 더하거나 필드의 뜻 · 상태 전이 · 보존을 바꿨다 | `데이터모델:<엔터티 키>` | `DS_401` 데이터모델 |

**등록부에 없는 일에는 파생할 관리 문서가 없다.** 처음 부은 상태에서 사용자조사 ·
릴리스 · 스프린트는 *사건*이라 파생할 대상이 없고, 로드맵 · 기능플래그는 *집계*,
제품개요 · 개발규약 · 테스트전략은 *서술*이라 좌표와 섹션이 1:1이 아니다. 그것들은
**작업 기록 자체가 원천**이다 — 좌표를 지어내서 억지로 걸지 마라. 팀이 그런 문서를
등록부에 올리면(`save` 의 `managed` · 손으로는 `_managed.md`) 그때부터는 좌표가 있다.

**결정은 작업 기록이 갖는다 — 작업 기록이 ADR 이다.** 「결제 대행사를 바꾼다」 는
결정을 적을 타입을 따로 만들지 않는다. 그 결정이 바꾼 대상(`시스템아키텍처:context` ·
`인터페이스:ex-orders` 같은)을 `touches:` 에 적으면 정본 문서가 따라 고쳐진다. 결정을
뒤집으면 같은 좌표에 새 기록을 낸다 — 어느 것이 뒤인지는 도구가 날짜와 `touches:` 로
센다. `supersedes` 는 기록 자체가 틀렸을 때(오기재)만 단다.

> **하나의 일이 좌표 여럿을 건드리는 것이 정상이다.** 한 페이지 결제를 만들면서
> 주문 API 에 멱등 키를 더하고 주문 엔터티에 컬럼을 더했으면 `기능명세:EX-CHECKOUT` ·
> `인터페이스:ex-orders` · `데이터모델:ex_order` 를 다 적는다. 적은 만큼 고쳐야 하고,
> 그것이 문서가 갈라지지 않는 이유다.

### 말로 언급한 것은 좌표가 아니다

타입을 한글로 쓰면 걱정이 하나 생긴다 — *"스프린트 회고에서 **기능명세** 얘기가
나왔다고 적으면 기능명세가 파생 대상이 되나?"*

**안 된다.** 막는 것이 넷이다.

| | |
|---|---|
| 1 | **파생은 `touches:` 만 본다.** 본문 산문은 파생 계산에 들어가지 않는다 |
| 2 | **좌표는 `타입:값` 이다.** 산문의 「기능명세」 는 좌표가 아니고 `기능명세:EX-CHECKOUT` 이 좌표다 |
| 3 | 본문 검사는 **백틱 안에 쓴, 이미 등재된 좌표**만 본다. 그것도 **경고**이고 커밋을 막지 않는다 |
| 4 | **등록부에 행이 없는 타입은 파생되지 않는다.** 무엇이 파생되는지는 위 「지금 등록부」 가 말한다 |

세 번째 줄이 **일부러 경고인 이유**가 있다. 오류로 올리면 사람이 검사를
피하려고 본문에서 좌표 표기를 지우기 시작하고, 그러면 *"빠뜨렸다"* 는 신호
자체가 사라진다. `cdp-save` 의 좌표 판정표도 **신설 · 변경 · 삭제는 O,
참조 · 호출 · 언급은 X** 로 못박고 있다.

### 타입 이름은 정본 문서 이름에서 딴다

규칙은 하나다.

> **정본 문서 이름에서 서식 꼬리(`명세` · `정의서` · `대장`)를 뗀다. 떼고 나서
> 보편적인 낱말이 되면 떼지 않는다.** 이름만 보고 어느 문서로 가는지 알아야 한다.

| 문서 | 떼면 | 보편적인가 | 타입 |
|---|---|:--:|---|
| 기능명세 | 기능 | **예** | `기능명세` |
| 제품지표 | 지표 | **예** — 떼지 않는다(꼬리가 아니다) | `제품지표` |
| 시스템아키텍처 | 시스템아키텍처 | 아니오 — 뗄 꼬리가 없다 | `시스템아키텍처` |
| 화면명세 | 화면 | **예** | `화면명세` |
| 인터페이스명세 | 인터페이스 | 아니오 | `인터페이스` |
| 데이터모델 | 데이터모델 | 아니오 — 뗄 꼬리가 없다 | `데이터모델` |
| (찾기 축 · 등록부 비대상) | — | — | `제품영역` |

**타입은 한글로 시작한다.** 어휘 파서는 대문자 영문 타입도 받지만 MCP · 서버형
save 는 좌표를 검사할 때 **영문이면 소문자만** 받는다(`C:/경로` 를 좌표로 읽지 않으려고).
`API:` · `PRD:` · `ADR:` 같은 타입은 이 파일에는 써지는데 에이전트가 쓰는 순간
`E_COORD` 로 거절된다. 영문 약어는 한글 낱말로 쓴다 — API 는 `인터페이스`, PRD 는
`기능명세`. **값은 무엇이든 된다** — `인터페이스:ex-orders` 의 `ex-orders` 는 팀이 정한다.

## 값이 예시로 채워져 있다 — 지우고 시작한다

아래 값은 **문서의 예시 섹션과 짝**이다 — 가상의 「(예시) 온라인 상점」(장바구니 ·
주문 · 결제)이다. `example:` 이 붙은 줄이 그것이고, 문서의 예시 섹션을 지울 때 여기
줄도 같이 지운다.

**`example:` 은 "이건 좌표로 세지 마라" 는 표시다.** 좌표 수에도 `INDEX` 에도
들어가지 않는다. 그래서 예시를 달고 일해도 숫자가 부풀지 않고, 급하지 않으면
나중에 지워도 된다 — `ctx check` 가 남아 있다고 **경고로** 알려 준다.

**한 번에 지운다.** 셸(모드 A)은 `ctx examples --purge`(파일만 고친다 — 커밋은 사람이),
서버형은 save 의 `examples: "purge"`, 세울 때부터 빼려면 `ctx repo new … --no-examples`.
셋 다 어휘 줄과 짝 섹션을 **같이** 지운다. 한쪽만 지우면 커밋은 막히지 않지만
`ctx where` 가 *"섹션이 없음 — 주입해도 빈손이다"* 를 낸다.

**지우기 전에 한 바퀴 돌려 보면 좋다.** 이 한 벌이 붙어 있어서 부은 직후에도
파생 고리가 실제로 돈다 — `touches:` 에 적으면 그때는 좌표로 센다.

```
ctx where 기능명세:EX-CHECKOUT       정본이 어느 문서 어느 섹션인가
ctx derive                           파생이 남은 섹션
ctx apply 기능명세:EX-CHECKOUT       섹션에 붙일 초안
```

**`시스템아키텍처:` 의 넷은 예시가 아니다** — 어느 제품에나 있는 관점(C4 의 컨텍스트 ·
컨테이너에 배포 · 보안을 더했다)이라 값으로 박아 두었다. 문서 쪽 표의 행만 예시다.
늘리거나 줄이려면 아래 `## 시스템아키텍처` 절과 `DS_101` 을 함께 고친다.

> `## <타입>` 의 **순서가 화면 · CLI 의 카테고리 순서**이므로 순서는 건드리지
> 않는다. 쓰지 않는 타입은 통째로 지운다 — 등록부 행 · 문서와 함께.
