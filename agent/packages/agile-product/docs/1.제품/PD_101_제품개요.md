# PD_101 제품개요

서술형. 이 제품이 **왜 있고 누구를 위한 것인가** — 팀이 분기마다 돌아와
방향을 맞춰 보는 한 장이다.

| | |
|---|---|
| 관리번호 | `PD_101` |
| 언제 | 제품을 시작할 때 · 분기 계획 전에 다시 읽는다 |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

**무엇** — 비전 · 풀려는 문제 · 대상 사용자 · 가치 제안 · 북극성 지표 · **하지 않는 것**.
**언제** — 제품을 시작할 때 쓴다. 분기마다 로드맵을 짜기 전에 다시 읽고, 방향이 바뀌면 그때 고친다.
**누가** — 제품 책임자(PO · PM)가 쓰고 팀 전체가 읽는다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 분기 목표(OKR) · 무엇을 언제쯤 | `로드맵` |
| 기능 하나의 범위 · 수용 기준 | `기능명세` |
| 지표의 계산식 · 출처 이벤트 | `제품지표` — 여기는 **어느 지표가 북극성인가**만 |
| 방향을 바꾼 이유 · 버린 대안 | 작업 기록(`work/`) — 결정은 거기 남는다 |

> **한 장을 넘기지 않는다.** 길어지면 아무도 다시 읽지 않는다. 시장 조사 · 경쟁
> 분석 같은 근거 자료는 링크로 둔다.

> ⚠ **아래 「(예시)」 줄은 서식 예시다 — 절 제목은 두고 줄은 지우고 시작한다.**

## 비전

(예시) 동네 가게의 물건을 **3분 안에** 산다.

## 풀려는 문제

| 누가 | 무엇이 불편한가 | 지금 어떻게 버티나 |
|---|---|---|
| (예시) 모바일로 처음 사는 사람 | 결제가 네 화면이라 이동 중에 끝내지 못한다 | 장바구니에 담아 두고 잊는다 |
| (예시) 단골 | 지난번 산 것을 다시 사려면 처음부터 찾는다 | 메신저로 가게에 직접 주문한다 |

## 대상 사용자

| 상황 | 하려는 일 | 잘됐다는 신호 |
|---|---|---|
| (예시) 퇴근길 지하철 · 한 손 | 저녁 장보기를 5분 안에 끝낸다 | 결제까지 한 번에 간다 |
| (예시) 주말 · 집 | 한 주 치 생필품을 묶어 산다 | 지난 주문에서 바로 담는다 |

## 가치 제안

(예시) 대형 쇼핑몰보다 **빨리 받고**, 메신저 주문보다 **덜 번거롭다** — 동네 가게의
당일 배송을 한 화면 결제로.

## 북극성 지표

| 지표 | 왜 이것인가 |
|---|---|
| (예시) 주간 구매 고객 수 | 「빨리 산다」 는 가치가 전달됐는지 가장 짧게 말한다. 하위 지표(결제 전환율 등)의 정의는 `제품지표` 에 둔다 |

## 하지 않는 것

| 하지 않는 것 | 왜 |
|---|---|
| (예시) 오프라인 매장 POS 연동 | 올해는 온라인 주문만 — 가게 쪽 도입 비용이 크다 |
| (예시) 해외 배송 | 당일 배송이 가치의 중심이다 |

> ⚠ **예시 행이다 — 지우고 시작한다.**

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 비전 | 한 문장. 기능 이름이 들어가면 비전이 아니다 | 필수 |
| 풀려는 문제 | 사용자의 말로. **해결책을 적지 않는다** | 필수 |
| 대상 사용자 | 페르소나보다 **상황**으로 — 언제 · 어디서 · 무엇을 하려다 | 필수 |
| 가치 제안 | 지금 버티는 방법(대안)보다 무엇이 나은가 | 필수 |
| 북극성 지표 | 하나. 정의는 `제품지표` 에 두고 여기는 이름과 이유만 | 필수 |
| 하지 않는 것 | **적어 두지 않으면 매 분기 다시 논의한다** | 필수 |
| 근거 자료 | 조사 · 분석은 링크. 우리 조사는 `사용자조사` 의 날짜를 가리킨다 | 선택 |
| 변경 | 문서 맨 아래에 `**변경** · 날짜 [작업기록](../../work/…) 무엇이` 를 쌓는다 | 변경 시 필수 |
