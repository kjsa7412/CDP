# PD_201 로드맵

대장형. **Now · Next · Later** — 무엇을 왜 언제쯤 하는가의 지금 상태.
행 하나가 테마 하나다.

| | |
|---|---|
| 관리번호 | `PD_201` |
| 언제 | 분기 계획에서 다시 짜고 · 스프린트 리뷰에서 상태를 고친다 |
| 등록부 | **비대상** — 집계 · 우선순위다 |

**무엇** — 테마(풀 문제) · 목표(OKR 의 핵심 결과) · 기능 · 시점 · 상태 · 담당.
*"다음에 무엇을 하나 · 왜 그것인가"* 에 답하는 자리다.
**언제** — 분기 계획에서 다시 짠다. 스프린트 리뷰에서 상태를 고치고, 순서를 바꾸면 그날 고친다.
**누가** — 제품 책임자. 리드 개발자 · 디자이너가 함께 본다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 기능 하나의 범위 · 수용 기준 | `기능명세` |
| 스프린트 단위의 목표 · 완료 · 이월 | `스프린트기록` — 할 일 하나하나는 이슈 트래커 |
| 이미 사용자에게 나간 것 | `릴리스노트` |
| 순서를 바꾼 이유 · 버린 안 | 작업 기록(`work/`) |

> **날짜가 아니라 시점으로 적는다.** Later 에 날짜를 박으면 약속이 된다. Now 만 구체적이고,
> Next 는 탐색 중, Later 는 방향이다.
>
> **기능은 좌표 값으로 적고 링크하지 않는다** — 정본은 `기능명세` 다. 링크를 걸면 정본이
> 둘로 보인다. 값만 적고 뷰어의 좌표 찾기에 맡긴다.

| 시점 | 테마 | 목표(핵심 결과) | 기능 | 상태 | 담당 |
|---|---|---|---|---|---|
| Now | (예시) 결제 이탈 줄이기 | 결제 전환율 62% → 70% | `EX-CHECKOUT` 한 페이지 결제 | 개발 중 | 결제 스쿼드 |
| Now | (예시) 장바구니 신뢰 | 품절로 인한 결제 실패 절반으로 | 장바구니 품절 표시 | 출시 | 결제 스쿼드 |
| Next | (예시) 재구매 | 30일 재구매율 +5%p | 지난 주문에서 다시 담기 | 탐색 | 성장 스쿼드 |
| Next | (예시) 비회원 구매 | 첫 구매 전환 +3%p | 비회원 결제 | 기획 | 결제 스쿼드 |
| Later | (예시) 정기 배송 | — | — | 아이디어 | |

> ⚠ **예시 행이다 — 지우고 시작한다.**

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 시점 | Now(이번 분기 · 진행 중) · Next(다음 · 탐색 중) · Later(언젠가) 셋 중 하나 | 필수 |
| 테마 | **풀 문제로** 적는다 — 기능 이름이 아니다 | 필수 |
| 목표 | 핵심 결과(KR) — 숫자와 방향. 지표 이름은 `제품지표` 의 것을 쓴다 | Now 필수 |
| 기능 | 기능명세의 좌표 값(`EX-CHECKOUT`)과 이름. **링크하지 않는다** | 조건 |
| 상태 | 아이디어 · 탐색 · 기획 · 개발 중 · 출시 · 보류 | 필수 |
| 담당 | 팀 · 스쿼드. 사람 이름은 바뀐다 | 선택 |
| 정렬 | 시점 → 우선순위 순. 위에 있을수록 먼저다 | 필수 |
| 끝난 행 | 출시하고 한 분기가 지나면 지운다 — 남은 기록은 `릴리스노트` 와 작업 기록이 갖는다 | 필수 |
| 변경 | 순서를 바꿨으면 문서 맨 아래에 `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 변경 시 필수 |
