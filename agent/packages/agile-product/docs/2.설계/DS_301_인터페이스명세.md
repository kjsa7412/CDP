# DS_301 인터페이스명세

API 의 지금 상태. **섹션 하나가 REST 자원 하나**다 — 요청 · 응답 스키마는 OpenAPI 가
정본이고, 여기는 OpenAPI 가 말하지 못하는 것을 적는다.

| | |
|---|---|
| 관리번호 | `DS_301` |
| 언제 | 자원을 더할 때 · 계약(필드의 뜻 · 오류 · 판)을 바꿀 때 |
| 등록부 | `인터페이스:*` → `## {값}` |
| 좌표 값 | 자원 키 — 소문자 · 하이픈(`ex-orders`). 경로의 자원 이름과 맞춘다 |

**무엇** — 자원마다 정본 위치(OpenAPI) · 연산 표 · 인증 · **호환성(판 · 지원 종료)** ·
쓰는 쪽 · 계약 시험 · 한도.
**언제** — 자원을 설계할 때 세운다. 필드를 빼거나 뜻을 바꾸거나 오류 코드 · 상태 값을 더하면
그 섹션을 고친다 — **깨지는 변경은 반드시.**
**누가** — 그 자원을 소유한 백엔드 개발자.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 요청 · 응답 스키마 · 필드 타입 | 코드 레포의 OpenAPI — `정본 위치` 로 가리킨다 |
| 저장 구조 · 상태 전이 · 보존 | `데이터모델` |
| 화면이 응답을 어떻게 보이나 | `화면명세` |
| 서비스 경계 · 인증 방식 전체 | `시스템아키텍처` |
| 오류 형식 · 페이지 · 날짜 표기 같은 공통 규칙 | `개발규약` |
| 왜 이렇게 설계했나 · 버린 안 | 작업 기록(`work/`) |

> **OpenAPI 를 옮겨 적지 않는다.** 옮긴 스키마는 다음 PR 에서 틀린다. 여기는 **누가
> 쓰나 · 무엇이 깨지면 안 되나 · 언제 없어지나**를 적는다 — 코드가 말하지 못하는 것이다.
>
> **바꾸기 전에 「쓰는 쪽」 을 본다.** 앱은 구판이 몇 달씩 살아 있다 — 웹은 오늘 고쳐도
> 앱 사용자는 지난 판으로 이 API 를 부른다.

## ex-orders — (예시) 주문 API
<!-- applied: null -->

| | |
|---|---|
| 정본 위치 | (예시) `api/openapi/orders.yaml` |
| 기본 경로 | `/v1/orders` |
| 인증 | 회원 액세스 토큰 · 운영자는 `orders:manage` 범위 |
| 판 | v1 — 깨지는 변경은 v2 로 |
| 쓰는 쪽 | 웹 앱 · 모바일 앱(1.2 이상) · 관리자 웹 · 정산 배치 |
| 계약 시험 | (예시) `api/contract/orders/` — 웹 · 앱이 소비자 |
| 한도 | 회원당 분당 30회 |
| 관련 좌표 | `데이터모델:ex_order` · `기능명세:EX-CHECKOUT` |

**연산**

| 메서드 | 경로 | 하는 일 | 멱등 | 규칙 |
|---|---|---|:--:|---|
| `POST` | `/v1/orders` | 장바구니로 주문 생성 · 결제 시작 | 키 | `Idempotency-Key` 헤더 필수 — 같은 키는 같은 주문을 돌려준다 |
| `GET` | `/v1/orders/{id}` | 주문 한 건 | O | 남의 주문은 404 |
| `GET` | `/v1/orders` | 내 주문 목록 | O | 커서 페이지 · 최근 1년 |
| `POST` | `/v1/orders/{id}/cancel` | 취소 | O | 배송이 시작되면 409 |

**호환성**

- 응답에 필드를 **더하는 것**은 깨지지 않는다 — 쓰는 쪽은 모르는 필드를 무시한다
- `status` 에 값을 더하면 앱 구판이 「알 수 없음」 으로 보인다 — **앱의 최소 지원 판을 먼저 올린다**
- 지원 종료 — (예시) 오프셋 페이지(`?page=`)는 2026-12-31 에 닫는다. `Deprecation` · `Sunset` 헤더로 알린다

**오류** — 공통 형식(RFC 9457). 이 자원 고유: `ORDER_STOCK_CHANGED`(409 · 재고가 바뀜) ·
`ORDER_PAYMENT_DECLINED`(402 · 결제 거절)

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**
