# 관리 문서 등록부

좌표가 어느 관리 문서의 어느 섹션에 대응하는지 **여기에만** 적는다.
매핑이 두 곳에 있으면 반드시 어긋난다.

| 좌표 패턴 | 관리 문서 | 섹션 |
|---|---|---|
| `서비스명세:*` | `docs/1.서비스/SV_101_서비스명세.md` | `## {값}` |
| `인터페이스:*` | `docs/1.서비스/SV_201_인터페이스명세.md` | `## {값}` |
| `이벤트명세:*` | `docs/1.서비스/SV_301_이벤트명세.md` | `## {값}` |
| `데이터저장소:*` | `docs/1.서비스/SV_401_데이터저장소.md` | `## {값}` |
| `시스템아키텍처:*` | `docs/2.플랫폼/PF_101_시스템아키텍처.md` | `## {값}` |
| `인프라:*` | `docs/2.플랫폼/PF_201_인프라구성.md` | `## {값}` |
| `서비스수준:*` | `docs/3.운영/OP_101_서비스수준.md` | `## {값}` |
| `런북:*` | `docs/3.운영/OP_201_런북.md` | `## {값}` |
| `장애:*` | `docs/3.운영/OP_301_장애회고.md` | `## {값}` |

**패턴은 위에서부터 먼저 걸리는 것을 쓴다.** 그리고 **대소문자를 구분한다** —
값의 앞자리를 패턴에 넣으면(`런북:OPS-*` 같은 것) 소문자로 적은 값은 그 행에 걸리지 않는다.
처음 부은 패턴은 전부 `타입:*` 이라 값의 대소문자를 타지 않는다.

## 등록부에 없는 좌표는 정상이다

관리 문서는 **자주 쓰는 내용을 하나로 모아 둔 것**이다. 모든 것이 여기 녹지
않는다 — 덜 쓰는 것을 하나로 모으는 부담이 이득보다 크다.

| | 원천 |
|---|---|
| 자주 바뀌고 여럿이 보는 것 | 관리 문서 섹션 — 하나로 수렴시키고 그 대가로 갱신 부담을 진다 |
| 한 번 정하고 끝나는 판단 | **그 작업 기록 자체** — 「왜 이 메시인가」 는 ADR 문서가 아니라 작업 기록이다 |
| 배포 하나하나 | GitOps 레포의 이력 — 날짜축이고 좌표를 지어내지 않는다 |

`도메인:`(바운디드 컨텍스트)이 그렇다. 바꾸는 대상이 아니라 **서비스를 묶는 축**이라
등록부에도 없고 정착도 계산에서도 뺀다.

## 장애가 한 행인 이유

회고는 사건이다 — 사건은 보통 날짜축이다. 그런데 장애회고는 **후속 조치가 닫힐 때까지 살아 있다.**
원인을 고치는 작업 기록이 `touches:` 에 그 장애 좌표를 달면 회고 섹션의 「후속 조치」 를 고칠 때까지
커밋이 막힌다 — 「회고를 쓰고 잊는다」 를 파생이 막는다.

| 이런 작업이면 | 보통 같이 적는 것 |
|---|---|
| 장애의 후속 조치로 시간 초과를 고쳤다 | 장애 좌표 · 그 서비스의 서비스명세 좌표 |
| 장애에서 모자랐던 대응 절차를 보탰다 | 장애 좌표 · 그 경보의 런북 좌표 |
| 장애 뒤 목표나 경보 문턱을 바꿨다 | 장애 좌표 · 그 서비스수준 좌표 |

## 등록부 대상이 아닌 관리 문서

위 표에 행이 없는 문서가 그것이다 — 대장 · 서술 축이라 좌표-섹션이
1:1로 대응하지 않는다. **앱은 문서로 읽고 열 수 있지만 섹션 판정을 하지 않는다.**

어느 문서가 대상인지는 등록부에서 센다 — MCP `docs` · `ctx docs`, 그리고 문서마다
머리 표의 `등록부` 칸(save · `ctx index` 가 이 표에서 찍는다). **여기 개수나 목록을
적지 않는다** — 행을 하나 더하는 순간 틀린다.
