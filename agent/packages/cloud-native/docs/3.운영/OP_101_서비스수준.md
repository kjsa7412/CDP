# OP_101 서비스수준

서비스수준 목표(SLO)의 지금 상태. **섹션 하나가 SLO 하나다** — 무엇을 재고(SLI), 얼마를 약속하고,
오류 예산을 다 쓰면 무엇을 멈추나.

| | |
|---|---|
| 관리번호 | `OP_101` |
| 언제 | SLO 를 정할 때 · SLI · 목표 · 경보 · 오류 예산 정책이 바뀔 때 |
| 등록부 | `서비스수준:*` → `## {값}` |
| 좌표 값 | SLO 키 — `<사용자 여정>-<성질>`(`ex-checkout-availability` · `ex-search-latency`) |

**무엇** — 대상(사용자 여정) · 서비스 · SLI 정의 · 목표 · 기간 · 오류 예산 · **오류 예산 정책** · 번레이트 경보 ·
정본 위치 · 지금 달성.
**언제** — 1등급 서비스를 내보내기 전에 세운다. 목표 · SLI · 경보를 바꾸면 그 섹션을 고친다.
**누가** — 서비스 담당 팀이 쓰고, SRE 가 SLI 정의와 경보를 본다.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| SLO · 경보 규칙의 정의 파일 | 코드 레포(SLO 정의 · 경보 규칙) — `정본 위치` 로 가리킨다 |
| 경보가 울리면 할 일 | `런북` |
| 예산을 크게 태운 사건 | `장애회고` |
| 서비스의 등급 · 의존 | `서비스명세` |
| 동결이 배포를 어떻게 막나 | `배포파이프라인` |
| 왜 이 목표인가 · 견준 수치 | 작업 기록(`work/`) |

> **SLO 는 사용자가 느끼는 것을 잰다.** CPU · 메모리는 SLI 가 아니다. 사용자 여정 하나에 가용성 하나 ·
> 지연 하나면 대개 충분하다 — 많으면 아무도 보지 않는다.
>
> **100% 는 목표가 아니다.** 오류 예산은 쓰라고 있는 것이다 — 남으면 더 빨리 내보내고, 바닥나면 멈춘다.

## ex-checkout-availability — (예시) 결제 가용성
<!-- applied: null -->

| | |
|---|---|
| 대상 | 사용자 여정 「결제하기」 — 주문 생성부터 결제 승인까지 |
| 서비스 | `서비스명세:ex-order-api` · 결제 서비스(payment-api) |
| SLI | 좋은 요청 ÷ 전체 요청 — 게이트웨이 기준 `POST /v1/orders` 중 5xx 가 아니고 3초 안에 끝난 것 |
| 목표 · 기간 | **99.9%** · 30일 이동 창 |
| 오류 예산 | 0.1% — 30일에 약 43분 어치 실패 |
| 정본 위치 | (예시) `observability/slo/checkout.yaml` — 경보 규칙을 여기서 만든다 |
| 경보 | 번레이트 — 1시간 14.4배(+5분 확인) · 6시간 6배(+30분) → 호출 / 3일 1배 → 티켓 |
| 런북 | `런북:EX-ORDER-5XX` |
| 지금 | (예시) 2026-09 · 99.93% · 예산 30% 남음 — 관측 도구에서 옮긴 값 |
| 지난 장애 | `장애:EX-INC-001` — 예산의 45% |

**목표의 근거** — 결제 대행사의 약속이 99.95% 라 그 위로 잡을 수 없고, 99.5% 면 행사 날 하루치 실패가
예산 안에 든다. 99.9% 로 잡았다.

**오류 예산 정책**

| 남은 예산 | 하는 일 |
|---|---|
| 50% 넘게 | 평소대로 |
| 50% 아래 | 위험한 배포(스키마 · 인프라 교체)는 카나리 단계를 늘린다 |
| 바닥 | **기능 배포 동결** — 신뢰성 · 보안 수정만. 해제는 담당 팀 리드와 SRE 가 같이 |
| 한 장애가 20% 넘게 | 회고 필수 — `장애회고` 섹션 |

> ⚠ **이 섹션은 예시다 — 지우고 시작한다.**

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 제목 | `<SLO 키> — <여정 · 성질>` | 필수 |
| `applied` | 이 섹션에 반영한 작업 기록 id. 없으면 `null` | 필수 |
| 대상 · 서비스 | 사용자 여정 하나. 서비스는 `서비스명세:` 좌표 | 필수 |
| SLI | 좋은 것 ÷ 전체 — **어디서 재나**(게이트웨이 · 클라이언트 · 합성)까지 | 필수 |
| 목표 · 기간 · 예산 | 수치로. 예산은 시간으로도 적는다 | 필수 |
| 근거 | 왜 이 수치인가 한두 줄. 자세한 비교는 작업 기록에 | 필수 |
| 경보 | 번레이트 창과 배수 · 호출인가 티켓인가 | 필수 |
| 정본 위치 | SLO 정의 파일. **규칙 식을 옮기지 않는다** | 필수 |
| 오류 예산 정책 | 남은 예산마다 무엇을 하나 · 누가 해제하나 | 필수 |
| 지금 · 지난 장애 | 손으로 옮기는 값. 옮긴 날짜를 붙인다 | 선택 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |
