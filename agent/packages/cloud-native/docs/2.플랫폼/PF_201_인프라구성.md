# PF_201 인프라구성

환경의 지금 상태. **좌표 셋이 고정이다** — 운영 · 스테이징 · 개발은 어느 팀에나 있는 자리라
값으로 박아 두었다. 섹션 하나가 환경 하나다.

| | |
|---|---|
| 관리번호 | `PF_201` |
| 언제 | 환경을 세울 때 · 계정 · 리전 · 클러스터 · 네트워크 · 접근이 바뀔 때 |
| 등록부 | `인프라:*` → `## {값}` |
| 좌표 값 | `prod` · `stg` · `dev` **셋 고정** |

**무엇** — 환경마다 클라우드 계정 · 리전과 가용 영역 · 클러스터 · 네트워크 대역 · **IaC 와 GitOps 의 위치** ·
누가 어떻게 들어가나 · 데이터 · 비용 태그. **환경 사이의 차이**가 한눈에 보이게 같은 칸으로 적는다.
**언제** — 환경을 만들 때 세운다. 클러스터를 갈아 끼우거나 접근 방식을 바꾸면 그 섹션을 고친다.
**누가** — 플랫폼 팀.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 테라폼 · 차트의 값 자체 | 코드 레포(IaC · GitOps) — `IaC` · `GitOps` 칸으로 가리킨다 |
| 환경을 가로지르는 구성(메시 · 브로커 · 관측) | `시스템아키텍처` 의 `시스템아키텍처:platform` |
| 저장소 하나하나의 백업 · 보존 | `데이터저장소` |
| 접근 · 비밀의 공통 규칙 | `보안기준` |
| 환경별 비용 | `비용현황` |
| 왜 계정을 나눴나 · 왜 이 리전인가 | 작업 기록(`work/`) |

> **셋은 서식 예시가 아니다** — 섹션은 두고 안의 (예시) 행만 바꾼다. 환경을 더하거나(재해 복구 리전 ·
> 고객 전용 · 부하 시험) 줄이려면 **`_vocab.md` 의 `## 인프라` 절과 이 문서를 함께** 고친다.
>
> **운영과 스테이징의 차이는 장애의 흔한 원인이다.** 다르게 둔 칸은 「왜 다른가」 를 같이 적는다.

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 섹션 | **셋 고정.** 늘리거나 줄이려면 `_vocab.md` 의 `## 인프라` 절도 함께 고친다 | 필수 |
| `applied` | 셋 다 `null` 로 시작한다 | 필수 |
| 칸 | 셋이 **같은 항목**을 쓴다 — 견줘 읽는 문서다. 다른 칸은 왜 다른지 적는다 | 필수 |
| 계정 · 리전 · 클러스터 | 이름 · 판 · 노드 풀 | 필수 |
| IaC · GitOps | 경로. **값을 옮기지 않는다** | 필수 |
| 접근 | 사람 · 비상 접근 · 변경 경로 | 필수 |
| 데이터 | 실데이터 · 가명 · 합성 중 무엇인가 | 필수 |
| 비용 태그 | 필수 태그. 배분은 `비용현황` 이 이 태그로 한다 | 필수 |
| 변경 | `**변경** · 날짜 [작업기록](../../work/…) 무엇이` | 작업 후 필수 |
