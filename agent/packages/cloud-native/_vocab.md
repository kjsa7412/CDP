# 좌표 어휘

이 파일이 통제 어휘(authority file)다. 같은 대상을 가리키는 여러 표기 중
**정본을 하나 정하고 나머지를 `aliases` 로 연결한다.** `aliases` 가 이 파일의
진짜 핵심이다 — 정본 목록만 있으면 작성자만 편해지고, `aliases` 가 있어야
수신자가 자연어로 물어도 걸린다. 경보 규칙 이름 · 토픽 이름 · 카탈로그 이름처럼
**코드에 박힌 이름**을 aliases 에 걸어 두면 당번이 경보 이름으로 물어도 걸린다.

**운영 원칙** — 추가는 한 줄, 삭제는 하지 않는다(`deprecated` 로 표시),
alias 는 발견될 때마다 추가한다. 서비스를 내려도 줄을 지우지 않는다 — 지난 장애가 그 좌표를 부른다.

---

## 무슨 일을 하면 무엇을 적나

작업 기록의 `touches:` 에 좌표를 적으면 **그 관리 문서를 고칠 때까지 커밋이
막힌다.** 그것이 파생 강제다. 어느 일이 어느 문서로 가는지가 아래 표다 —
**처음 부은 상태의 안내**다. 지금 등록부는 그 아래 생성 블록이 정본이다.

| 이런 일을 했으면 | `touches:` 에 | 고쳐야 하는 관리 문서 |
|---|---|---|
| 서비스를 세우거나 책임 · 담당 · 의존 · 등급을 바꿨다 | `서비스명세:<서비스 키>` | `SV_101` 서비스명세 |
| 동기 API(REST · gRPC)를 더하거나 계약 · 판 · 한도를 바꿨다 | `인터페이스:<API 키>-v<메이저>` | `SV_201` 인터페이스명세 |
| 이벤트를 새로 내거나 받는 쪽 · 스키마 판 · 보존 · 재처리를 바꿨다 | `이벤트명세:<이벤트 이름>` | `SV_301` 이벤트명세 |
| DB · 캐시 · 버킷을 세우거나 엔진 판 · 백업 · 보존 · 접근을 바꿨다 | `데이터저장소:<저장소 키>` | `SV_401` 데이터저장소 |
| 서비스 지도 · 클러스터 · 메시 · 진입점 · 보안 경계를 바꿨다 | `시스템아키텍처:context` `platform` `network` `security` | `PF_101` 시스템아키텍처 |
| 환경의 계정 · 리전 · 클러스터 · 네트워크 · 접근을 바꿨다 | `인프라:prod` `stg` `dev` | `PF_201` 인프라구성 |
| SLO 를 세우거나 SLI · 목표 · 경보 · 오류 예산 정책을 바꿨다 | `서비스수준:<SLO 키>` | `OP_101` 서비스수준 |
| 호출 경보를 만들거나 대응 절차를 바꿨다 | `런북:<경보 키>` | `OP_201` 런북 |
| 장애를 회고했거나 후속 조치를 진행 · 완료했다 | `장애:<장애 ID>` | `OP_301` 장애회고 |

**장애의 후속 조치는 좌표 둘이다** — 원인을 고친 대상(서비스 · 런북 · 서비스수준)과 그 장애.
둘 다 적어야 고친 대상의 섹션과 회고의 「후속 조치」 가 같이 움직인다.

**등록부에 없는 일에는 파생할 관리 문서가 없다.** 처음 부은 상태에서 배포 하나하나는
GitOps 이력이고, 배포파이프라인 · 보안기준 · 온콜체계는 *서술*, 비용현황은 *집계*라
좌표와 섹션이 1:1이 아니다. 그것들은 **작업 기록 자체가 원천**이다 — 좌표를 지어내서
억지로 걸지 마라. 팀이 그런 문서를 등록부에 올리면(`save` 의 `managed` · 손으로는
`_managed.md`) 그때부터는 좌표가 있다.

> **하나의 일이 좌표 여럿을 건드리는 것이 정상이다.** API 에 필드를 더하면서

> 적은 만큼 고쳐야 하고, 그것이 문서가 갈라지지 않는 이유다.

### 말로 언급한 것은 좌표가 아니다

타입을 한글로 쓰면 걱정이 하나 생긴다 — *"회고에 **런북** 얘기가 나왔다고 적으면
런북이 파생 대상이 되나?"*

**안 된다.** 막는 것이 넷이다.

| | |
|---|---|
| 1 | **파생은 `touches:` 만 본다.** 본문 산문은 파생 계산에 들어가지 않는다 |
| 2 | **좌표는 `타입:값` 이다.** 「런북을 봤다」 에는 콜론과 값이 없다 — 산문에 콜론과 값을 같이 쓸 일이 없다 |
| 3 | 본문 검사는 **백틱 안에 쓴, 이미 등재된 좌표**만 본다. 그것도 **경고**이고 커밋을 막지 않는다 |
| 4 | **등록부에 행이 없는 타입은 파생되지 않는다.** 파생되는 타입은 위 「지금 등록부」 가 전부다 |

세 번째가 **일부러 경고인 이유**가 있다. 오류로 올리면 사람이 검사를 피하려고
본문에서 좌표 표기를 지우기 시작하고, 그러면 *"빠뜨렸다"* 는 신호 자체가 사라진다.

> **사람·에이전트 쪽 보호도 따로 있다.** `cdp-save` 의 좌표 판정표가
> **신설 · 변경 · 삭제는 O, 참조 · 호출 · 언급은 X** 로 못박고 있다.
> 주문 서비스가 결제 API 를 「불렀다」 고 그 API 좌표를 적지 않는다.

### 타입 이름은 정본 문서 이름에서 딴다

규칙은 하나다.

> **정본 문서 이름에서 서식 꼬리(`명세` · `구성` · `회고`)를 뗀다. 떼고 나서
> 보편적인 낱말이 되면 떼지 않는다.** 이름만 보고 어느 문서로 가는지 알아야 한다.

| 문서 | 떼면 | 보편적인가 | 타입 |
|---|---|:--:|---|
| 서비스명세 | 서비스 | **예** — 어느 문서에나 서비스가 나온다 | `서비스명세` |
| 인터페이스명세 | 인터페이스 | 아니오 | `인터페이스` |
| 이벤트명세 | 이벤트 | **예** — 사용자 행동 이벤트 · 행사 · 장애 이벤트와 갈리지 않는다 | `이벤트명세` |
| 데이터저장소 | (꼬리 없음) | 아니오 | `데이터저장소` |
| 시스템아키텍처 | (꼬리 없음) | 아니오 | `시스템아키텍처` |
| 인프라구성 | 인프라 | 아니오 — 값이 환경이다 | `인프라` |
| 서비스수준 | (꼬리 없음) — SLO 의 우리말 | 아니오 | `서비스수준` |
| 런북 | (꼬리 없음) | 아니오 | `런북` |
| 장애회고 | 장애 | 아니오 — 값이 장애 ID 다 | `장애` |
| (등록부 비대상) | — | — | `도메인` |

**타입은 한글로 시작한다.** 어휘 파서는 대문자 영문 타입도 받지만, MCP 의 좌표 검사와
서버형 save 의 `managed` 는 영문이면 **소문자만** 받는다 — 경로(`C:/…`)를 좌표로 읽지
않으려는 것이다. 그래서 `SLO:` · `API:` · `K8S:` 같은 약어 타입은 여기 써지는데 MCP · save
가 `E_COORD` 로 거절한다. SLO 는 `서비스수준`, API 는 `인터페이스` 다.

**값 짓기** — 값에는 공백을 쓸 수 없다. 섹션을 찾을 때 대소문자 · 하이픈 · 밑줄은 무시되므로
그것만 다른 값 둘을 만들지 않는다.

| 타입 | 값 | 판을 넣나 |
|---|---|---|
| 서비스명세 · 데이터저장소 | 배포 이름 · IaC 자원 이름 그대로 | 넣지 않는다 |
| 인터페이스 | API 키 + 메이저 판 | **메이저만** — 깨지는 변경은 다른 계약이라 새 좌표다 |
| 이벤트명세 | 이벤트 이름 = 토픽 이름 | 깨지는 스키마 변경만 꼬리를 붙여 새 좌표 |
| 서비스수준 · 런북 · 장애 | SLO 키 · 경보 키 · 장애 관리 도구의 번호 | 넣지 않는다 |

## 값이 예시로 채워져 있다 — 지우고 시작한다

아래 값은 **문서의 예시 섹션과 짝**이다. `example:` 이 붙은 줄이 그것이고,
문서의 예시 섹션을 지울 때 여기 줄도 같이 지운다. 예시는 가상 업무 「(예시) 온라인
상점」 의 주문 · 결제다 — 주문 서비스 하나와 그 API · 이벤트 · DB · 결제 가용성 · 경보 · 장애 한 벌.

**`example:` 은 "이건 좌표로 세지 마라" 는 표시다.** 좌표 수에도 `INDEX` 에도
들어가지 않는다. 급하지 않으면 나중에 지워도 된다 — `ctx check` 가 남아 있다고
**경고로** 알려 준다. 지울 때는 한 번에 — `ctx examples --purge`(서버형은 save 의
`examples: "purge"`)가 어휘 줄과 짝 섹션을 같이 지운다.

**지우기 전에 한 바퀴 돌려 보면 좋다.** 이 한 벌이 붙어 있어서 부은 직후에도
파생 고리가 실제로 돈다 — `touches:` 에 적으면 그때는 좌표로 센다.

```
ctx where 장애:EX-INC-001        정본이 어느 문서 어느 섹션인가
ctx derive                       파생이 남은 섹션
ctx apply 장애:EX-INC-001        섹션에 붙일 초안
```

**`시스템아키텍처:` 넷과 `인프라:` 셋은 예시가 아니다.** 어느 팀에나 있는 관점 · 환경이라
값으로 박아 두었다. 늘리거나 줄이려면 그 절과 `시스템아키텍처` · `인프라구성` 문서를 함께 고친다.

> `## <타입>` 의 **순서가 화면 · CLI 의 카테고리 순서**이므로 순서는 건드리지
> 않는다. 쓰지 않는 문서는 `README.md` 「첫날」 1 로 지운다.
