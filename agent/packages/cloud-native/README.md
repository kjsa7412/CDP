# cloud-native — 클라우드 네이티브 서비스 운영

**문서 13종.** 여러 서비스(MSA)를 쿠버네티스 · 퍼블릭 클라우드에서 운영하는 플랫폼 · SRE ·
백엔드 팀의 한 벌이다 — 서비스(무엇이 있고 누가 쓰나) · 플랫폼(어디서 어떻게 도나) ·
운영(얼마나 잘 도나 · 깨지면 어떻게 하나). **서비스 · API · 이벤트 · 서비스수준 · 런북 · 장애를
좌표로 잇고, 결정은 작업 기록이 갖는다.**

## 이런 팀

| | |
|---|---|
| 맞는다 | 서비스 여럿을 여러 팀이 나눠 맡고, GitOps · IaC 로 배포하며, SLO · 오류 예산으로 신뢰성을 관리하고, 당번이 경보를 받는 팀 — 「이 API 누가 쓰지」 · 「이 경보 뜨면 뭘 하지」 · 「지난 장애 후속 조치 닫혔나」 를 매주 묻는다 |
| 예시 | 가상 업무 「(예시) 온라인 상점」 의 주문 · 결제 — 주문 서비스 하나와 그 API · 이벤트 · DB · 결제 가용성 · 경보 · 장애 한 벌. 예시 값은 `ex` · `EX` 로 시작한다 |

다른 패키지가 맞는 팀 —

| 패키지 | 이런 팀이면 |
|---|---|
| `public-si` | 발주처에 단계별 산출물(분석 · 설계 · 시험 · 이행)을 내는 공공 · SI 사업 |
| `agile-product` | 서비스 한둘을 스프린트로 만드는 제품팀 — 기능명세 · 화면 · 릴리스가 중심이고 운영은 곁가지다 |
| `ai-service` | LLM · RAG · 에이전트 기능을 만들고 평가하며 운영한다 — 모델카드 · 프롬프트 · 평가셋 |
| `blank` | 맞는 서식이 없다 — 문서 · 타입을 직접 세운다 |

**패키지는 섞지 않는다.** 운영 문서가 조금 필요한 제품팀이면 `agile-product` 로 세우고, 여기서
필요한 문서(서비스수준 · 런북 같은 것)를 등록부 행 · 어휘 절과 같이 가져온다.

## 이 패키지는 **서식**이다

| 있다 | 없다 |
|---|---|
| 문서 13개 골격 — 머리 표 · 예시 섹션 · 작성지침 | 그 팀의 서비스 · API · SLO · 경보 |
| `_managed.md` — 좌표 패턴 → 관리 문서 · 섹션 | OpenAPI · proto · AsyncAPI · Terraform · Helm · 매니페스트 · 경보 규칙 — **코드 레포가 정본이다** |
| `_vocab.md` — 좌표 타입과 **순서** | 좌표 값 (`시스템아키텍처:` 넷 · `인프라:` 셋만 예외) |
| 같은 가상 업무 「(예시) 온라인 상점」 의 예시 한 벌 | **ADR 문서** — 작업 기록이 그것이다 |

**프로젝트 맞춤은 레포 안에서 한다** — 안 쓰는 문서를 지우고 좌표를 등록한다. 패키지를 고치지 않는다.

## 붓는다

```
xcopy /E /I <배포본>\knowledge-repo-cloud-native C:\cdp
copy <배포본>\cdp.exe C:\cdp\tools\
cd /d C:\cdp
git init && git config core.hooksPath .githooks
```

서버형은 콘솔 › 지식 레포 › 새 레포에서 `cloud-native` 를 고른다. 부으면 `_vocab.md` 가 생기고
**그 순간 그 폴더가 지식 레포**가 된다 — 작업 기록이 0건이면 `ctx check` 는 `이상 없음` 이다.

## 첫날

```
1  안 쓰는 문서를 지운다            이벤트를 안 쓰면 이벤트명세 · 비용을 다른 도구에서 보면 비용현황
2  서식 예시를 지운다              ctx examples --purge · 서버형은 save 의 examples: "purge"
3  _vocab.md 에 좌표를 등록한다      서비스 · 환경부터 — 여기 없는 좌표를 쓰면 커밋이 막힌다
4  ctx check                       이상 없음이 나오면 시작할 수 있다
```

**1 은 한 번에 한다.** 파일만 지우면 등록부 행이 없는 파일을 가리킨 채 남고, 그 타입에 작업
기록이 처음 닿는 순간 커밋이 막힌다(`ctx check` 가 「등록부 행이 없는 관리 문서를 가리킴」 으로 미리 경고한다).

| | 어떻게 |
|---|---|
| 서버형 · 세울 때 | 콘솔 › 지식 레포 › 새 레포의 「문서 고르기」 에서 체크를 푼다 |
| 서버형 · 세운 뒤 | 레포 › 관리 › 「관리 문서」(admin) — 사용 현황을 보고 골라 미리보기 → 지우기 |
| 셸(모드 A) | `bin/ctx docs drop SV_301 PF_501 --dry-run` → `--apply-suggest --reason "이벤트 · 비용은 다른 도구에"` → `bin/ctx index` → 커밋 |
| 에이전트(큐레이터) | `cdp-registry` 「안 쓰는 문서 지우기」 — 산문 언급까지 고쳐 쓴다 |

**3 은 서비스 · 환경부터.** 나머지가 다 이 둘을 가리킨다.

| 순서 | 등록할 좌표 | 짝 섹션 |
|--:|---|---|
| 1 | 서비스 — `서비스명세:<서비스 키>` | `서비스명세` |
| 2 | 환경 — `인프라:` 셋은 이미 있다. 더 있으면(재해 복구 리전 · 고객 전용) 어휘 줄과 섹션을 더한다 | `인프라구성` |
| 3 | 1등급 서비스의 SLO — `서비스수준:<SLO 키>` | `서비스수준` |
| 4 | 그 SLO 의 호출 경보 — `런북:<경보 키>` | `런북` |
| 다음 | API · 이벤트 · 저장소 — 작업 기록이 닿을 때 한 줄씩 | |

좌표 줄과 짝 섹션(`## <값> — <이름>` 바로 아래 `<!-- applied: null -->`)을 같이 세운다.
서버형은 save 의 `vocab` · `sections` 가 한 커밋으로 낸다.

## 원칙

| 원칙 | 이 패키지에서 |
|---|---|
| **작업 기록이 ADR 이다** | 결정 · 버린 대안 · 이유는 `work/` 의 작업 기록에 쓴다(불변) — ADR 문서를 따로 두지 않는다. 「왜 이 메시인가 · 왜 이 DB 엔진인가 · 왜 99.9% 인가」 가 그것이다. 결정을 뒤집으면 같은 좌표에 새 기록을 낸다(어느 것이 뒤인지는 도구가 날짜로 센다). `supersedes` 는 기록 자체가 틀렸을 때만 단다 |
| **코드가 정본인 것은 옮기지 않는다** | OpenAPI · proto · AsyncAPI · 스키마 레지스트리 · Terraform · Helm · Kustomize · 쿠버네티스 매니페스트 · 카탈로그(`catalog-info.yaml`) · 경보 규칙은 제자리에 둔다. 문서에는 `정본 위치` 한 줄과 **코드가 말하지 못하는 것** — 왜 · 누가 쓰나 · 호환성 · 정책 · 판단 기준 — 만 적는다. 옮긴 값은 다음 PR 에서 틀린다 |
| **좌표는 바뀌고 여럿이 보는 대상에만** | 서비스 · API · 이벤트 · 저장소 · 아키텍처 관점 · 환경 · SLO · 경보 · 장애. 배포 하나하나는 GitOps 이력이, 비용은 대장(`비용현황`)이 갖는다 — 좌표를 지어내 걸지 않는다 |
| **장애회고가 좌표형인 이유** | 회고는 사건이지만 **후속 조치가 닫힐 때까지 살아 있다.** 원인을 고치는 작업 기록이 `touches:` 에 그 장애 좌표를 달면 회고의 「후속 조치」 를 고칠 때까지 커밋이 막힌다 — 「회고를 쓰고 잊는다」 를 파생이 막는다 |

## 번호

| | |
|---|---|
| 모양 | **묶음 접두 + 세 자리** — `SV` 서비스 · `PF` 플랫폼 · `OP` 운영. 백의 자리가 문서 종류다 |
| 성격 | **번호는 속성이지 식별자가 아니다.** 등록부 · 링크는 파일 경로를 가리키고, 이름은 문서명이다. 번호는 문서 고르기 · 참조 찾기 · `ctx docs drop` 이 부르는 손잡이다 |
| 새 번호 | 새 종류는 그 묶음에서 쓰지 않은 백의 자리(운영에 하나 더하면 OP_501), 같은 종류를 나누면 끝자리. 파일 이름 `<번호>_<문서명>.md` · 첫 줄 `# <번호> <문서명>` · 머리 표 `관리번호` 를 같이 쓴다 |

## 더할 만한 것

처음 부은 한 벌에는 없다. 필요해지면 세운다 — 서버형은 save 의 `managed`(writer)가 등록부 행과
문서를 한 커밋으로, 셸은 `_managed.md` 행 + 문서 + `_vocab.md` 타입 절을 더하고 `bin/ctx index`.
대장 · 서술 문서는 행 없이 문서만 둔다. 서식은 이 패키지 문서의 머리 표 · `## 작성지침` 을 본뜬다.

| 문서 | 이럴 때 |
|---|---|
| 기술부채대장 | 미룬 업그레이드 · 지원 끝난 판 · 임시 우회가 쌓여 분기마다 골라야 한다 |
| 용량계획 | 행사 · 성장으로 클러스터 · DB · 브로커의 한계를 미리 재야 한다 |
| 위협모델 | 외부 노출 서비스 · 결제 · 개인정보 흐름을 서비스마다 따로 따져야 한다 |
| 변경관리 | 규제 · 감사가 운영 변경의 승인 기록을 따로 요구한다 |

## 알려진 한계

| | |
|---|---|
| 코드와 문서의 어긋남 | `정본 위치` 는 가리킬 뿐이다 — 도구는 OpenAPI · 스키마 레지스트리 · Terraform 을 읽지 않는다. 호환성 칸이 실제 스키마와 같은지는 리뷰에서 사람이 본다 |
| 지표 수치 | SLO 달성률 · 오류 예산 · 비용은 관측 · 비용 도구에서 손으로 옮긴다 — 실시간이 아니다 |
| 대장 · 서술 문서 | 결정론적 보증이 없다 — 비용 초과 · 낡은 당번 규칙은 커밋을 막지 않는다 |
| 서비스가 많을 때 | 섹션이 수백이 되면 문서가 길다 — `<!-- 도메인 -->` 그룹 주석으로 묶는다. 문서를 나누려면 등록부 패턴을 값의 앞자리로 가른다(대소문자 구분) |
| 그림 | 뷰어는 mermaid 를 그리지 않는다 — 흐름은 번호 목록 · 표로 적고, 그림은 `work/assets/` 에 두고 링크한다 |
