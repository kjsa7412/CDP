# TE_301 통합테스트계획서

서술형. **문서 전체가 내용**이라 쪼갤 대상이 없다 — 등록부에 올리지 않는다.

| | |
|---|---|
| 관리번호 | `TE_301` |
| 제출시기 | 테스트완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

**무엇** — 통합테스트를 **언제 · 누가 · 무엇을 · 어떤 기준으로** 할 것인가.
**현업이 참여한다.** 그래서 일정 조율이 이 문서의 절반이다.
**언제** — 테스트 단계 직전. 시나리오를 쓰기 전에 범위를 정한다.
**누가** — PM · 개발 PL.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 밟을 절차 · 점검사항 | `통합테스트시나리오` |
| 밟은 결과 · PASS/FAIL | `통합테스트결과서` |
| 고치지 못한 것 | `위험및이슈관리대장` |

> **시나리오와 결과서가 짝이다.** 계획(언제 누가) · 시나리오(무엇을 어떻게)
> · 결과서(어떻게 됐나) 셋으로 나뉜다. 원본은 셋을 한 파일에 섞어 두어
> 회차가 덮였다.

## 제목 뼈대

아래 절을 채운다. **발주처 양식이 있으면 그것이 우선**이고, 이 뼈대는
무엇을 빠뜨리지 말아야 하는지의 점검표로 쓴다.

| # | 절 | 무엇을 적나 |
|--:|---|---|
| 1 | 목적 | 무엇을 확인하려는가 |
| 2 | 범위 | 대상 프로그램 · 업무. **제외 대상과 그 이유** |
| 3 | 일정 | 회차와 날짜. 타임테이블이 필요하면 표로 |
| 4 | 참가자 | 역할. 현업 참여자를 반드시 적는다 |
| 5 | 환경 | 서버 · 데이터 · 계정. 테스트 데이터 준비 방법 |
| 6 | 합격 기준 | 무엇을 만족하면 통과인가. 전건 PASS 인지 일부 허용인지 |
| 7 | 실패 처리 | FAIL 이 나오면 누가 언제까지 고치고 어떻게 재확인하나 |

> 제목은 자유롭게 쓴다 — **등록부 비대상이라 좌표와 충돌하지 않는다.**
> 다만 `## 작성지침` 은 남겨 둔다.
