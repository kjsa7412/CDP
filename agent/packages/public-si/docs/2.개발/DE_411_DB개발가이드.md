# DE_411 DB개발가이드

서술형. **문서 전체가 내용**이라 쪼갤 대상이 없다 — 등록부에 올리지 않는다.

| | |
|---|---|
| 관리번호 | `DE_411` |
| 제출시기 | 설계완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

**무엇** — DB 를 만들 때 지킬 규칙. 명명 · 타입 · 기본 컬럼 · 인덱스.
**언제** — 설계 초반. **테이블을 만들기 전에** 있어야 한다.
**누가** — DB 설계 담당.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 용어 자체(논리명 ↔ 물리명) | `DB도메인용어정의서` |
| 실제 테이블 구성 | `테이블정의서` |
| 애플리케이션 코딩 규칙 | `개발가이드` |

> **타입 규칙을 두 곳에 적지 마라.** `DB도메인용어정의서` 의 접미어 표가
> 정본이면 여기서는 그것을 가리킨다. 실제 원본은 다른 프로젝트의
> `개발표준안(DB)` 이었고 이 패키지에는 **내용이 없다** — 틀만 세웠다.

## 제목 뼈대

아래 절을 채운다. **발주처 양식이 있으면 그것이 우선**이고, 이 뼈대는
무엇을 빠뜨리지 말아야 하는지의 점검표로 쓴다.

| # | 절 | 무엇을 적나 |
|--:|---|---|
| 1 | 명명 규칙 | 테이블 · 컬럼 · 인덱스 · 제약의 이름 짓는 법 |
| 2 | 타입 규칙 | 접미어별 타입. `AMT`→BIGINT 같은 대응. **용어정의서와 같은 표** |
| 3 | 공통 컬럼 | 모든 테이블이 갖는 등록자 · 등록일시 · 사용여부 등 |
| 4 | 키 · 인덱스 | PK 규칙 · FK 정책 · 인덱스 명명 |
| 5 | 금지 | 예약어 · 한글 컬럼명 · 물리 삭제 등 |
| 6 | SQL 작성 규칙 | 대소문자 · 조인 방식 · 힌트 사용 |

> 제목은 자유롭게 쓴다 — **등록부 비대상이라 좌표와 충돌하지 않는다.**
> 다만 `## 작성지침` 은 남겨 둔다.
