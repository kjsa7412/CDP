## 붓는다

```
xcopy /E /I <배포본>\knowledge-repo-public-si C:\cdp
copy <배포본>\cdp.exe C:\cdp\tools\
cd /d C:\cdp
git init && git config core.hooksPath .githooks
```

부으면 `_vocab.md` 가 생기고 **그 순간 그 폴더가 지식 레포**가 된다.
바로 `ctx check` 가 돈다 — 작업 기록이 0건이면 `이상 없음` 이다.

## 첫날 무엇을 하나

```
1  안 쓰는 문서를 지운다            40종을 다 쓰는 프로젝트는 드물다 — 등록부 행 · 예시 좌표 · 가리키는 목록 행이 같이 간다
2  서식 예시를 지운다              ctx examples --purge · 서버형은 save 의 examples: "purge"
3  _vocab.md 에 좌표를 등록한다      여기 없는 좌표를 쓰면 커밋이 막힌다
4  ctx check                       이상 없음이 나오면 시작할 수 있다
```

**1 은 한 번에 한다.** 파일만 지우면 등록부 행이 없는 파일을 가리킨 채 남고, 그 타입에 작업 기록이 처음 닿는 순간
커밋이 막힌다(`ctx check` 가 「등록부 행이 없는 관리 문서를 가리킴」 으로 미리 경고한다).

| | 어떻게 |
|---|---|
| 서버형 · 세울 때 | 콘솔 › 지식 레포 › 새 레포의 「문서 고르기」 에서 체크를 푼다 |
| 서버형 · 세운 뒤 | 레포 › 관리 › 「관리 문서」(admin) — 사용 현황을 보고 골라 미리보기 → 지우기 |
| 셸(모드 A) | `bin/ctx docs drop TE_201 TE_202 TE_203 --dry-run` → `--apply-suggest --reason "성능시험 없음"` → `bin/ctx index` → 커밋 |
| 에이전트 | `cdp-managed` 「문서 정리」 — 산문 언급까지 고쳐 쓴다 |

지운 문서는 `_managed.md` 「지운 관리 문서」 표에 남는다. 산문으로 남은 언급은 `ctx check` 의
「없는 관리 문서를 가리키는 줄」 이 계속 알려 준다.

## 어디서 왔나

공공 SW 사업의 표준 산출물 체계(사업관리 · 분석 · 설계 · 구현 · 시험 · 이행)를 **실제 사업 하나의 산출물
폴더에서 역산했다** — 폴더에 자리가 있는 산출물만 세웠다. 표준 목록에서 뺀 것 · 더한 것과 되살리는 법은
[`관리번호.md`](관리번호.md) §5 다.

**요구사항추적표는 없다.** 요구사항이 어느 화면 · 프로그램 · 시험으로 갔는지는 손으로 유지하는 표가 아니라
**좌표가 답한다** — `ctx where 요구사항:…` 가 그 요구사항에 실린 작업을 전부 세우고 `INDEX-by-coord.md` 가
파일로 만든다.

**15종은 골격만 세웠다** — 보고(착수 · 중간 · 완료 · 사업수행계획서) · 시험(단위 · 성능의 계획서 · 시나리오 · 결과서) ·
이행(운영자 · 사용자메뉴얼 · 안정화계획서) · 이관(계획서 · 결과서). 필수 제출물 둘(`착수보고서` · `사업수행계획서`)은
**발주처 양식**이 우선이다 — 이 골격은 무엇을 빠뜨리지 말아야 하는지의 점검표다.
