# DE_321 프로그램목록

프로그램의 집계. 행 하나가 프로그램 하나다. **각 프로그램의 내용은
`프로그램사양서` 가 갖는다** — 여기는 무엇이 있는지만 본다.

| | |
|---|---|
| 관리번호 | `DE_321` |
| 제출시기 | 분석완료 · 설계완료 |
| 필수 제출 | 아니오 |
| 등록부 | **비대상** — 집계다 |

**무엇** — 만들 프로그램의 전체 목록과 권한 배치. 개수를 세고 범위를 확인하는
자리다.
**언제** — 분석에서 AS-IS 를 뽑고, 설계에서 TO-BE 를 확정한다.
**누가** — PL.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 그 프로그램이 무엇을 하나 | `프로그램사양서` |
| 화면 생김새 | `화면설계서` |
| 언제 누가 만드나 | `개발일정계획서` |

> **좌표를 링크로 걸지 않는다.** `프로그램사양서:EXA010` 의 정본은 프로그램사양서다.
> 대장에서 링크를 걸면 정본이 둘로 보인다 — 값만 적고 뷰어의 좌표 검색에
> 맡긴다.
>
> **TAB 열을 두지 않았다.** 원본에 `TAB ID` · `TAB명` 컬럼이 있었지만
> **200행 전부 비어 있었다.** 안 채울 칸은 두지 않는다.

| 대분류 | 중분류 | 프로그램ID | 프로그램명 | 상위 | 처리여부 | 권한 | 비고 |
|---|---|---|---|---|---|---|---|
| (예시) EX 연구과제 | EXA 과제접수 | `EXA010` | 과제접수목록 | | 완료 | 전체(조회) | |
| (예시) EX 연구과제 | EXA 과제접수 | `EXA011` | 과제접수등록 | `EXA010` | 완료 | 과제 PM | |
| (예시) EX 연구과제 | EXB 사전검토 | `EXB010` | 사전검토목록 | | 제거 | | 접수목록으로 병합 |

> ⚠ **예시 행이다 — 지우고 시작한다.**

## 작성지침

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 대분류 · 중분류 | `<코드> <이름>`. 화면설계서의 업무구분 · 분류와 같게 | 필수 |
| 프로그램ID | 좌표 `프로그램사양서:` · `화면설계서:` 와 **같은 값**. 상위·하위가 같은 ID 공간이다 | 필수 |
| 상위 | 하위프로그램이면 그 부모 ID. 최상위면 비운다 | 조건 |
| 처리여부 | 완료 · 진행 · **제거**. 지운 것도 남기고 비고에 왜를 적는다 | 필수 |
| 권한 | `<역할>(<할 수 있는 것>)`. 없으면 비운다 | 선택 |
| 비고 | 병합 · 제거 · 보류의 이유 | 조건 |
