# 좌표 어휘

이 파일이 통제 어휘(authority file)다. 같은 대상을 가리키는 여러 표기 중
**정본을 하나 정하고 나머지를 `aliases` 로 연결한다.** `aliases` 가 이 파일의
진짜 핵심이다 — 정본 목록만 있으면 작성자만 편해지고, `aliases` 가 있어야
수신자가 자연어로 물어도 걸린다.

**운영 원칙** — 추가는 한 줄, 삭제는 하지 않는다(`deprecated` 로 표시),
alias 는 발견될 때마다 추가한다.

---

## 무슨 일을 하면 무엇을 적나

작업 기록의 `touches:` 에 좌표를 적으면 **그 관리 문서를 고칠 때까지 커밋이
막힌다.** 그것이 파생 강제다. 어느 일이 어느 문서로 가는지가 아래 표다 —
**처음 부은 상태의 안내**다. 지금 등록부는 그 아래 생성 블록이 정본이다.

| 이런 일을 했으면 | `touches:` 에 | 고쳐야 하는 관리 문서 |
|---|---|---|
| 요구사항을 받거나 바꿨다 | `요구사항:<요구사항ID>` | `AN_211` 요구사항정의서 |
| 업무 흐름을 바꿨다 | `프로세스정의서:<프로세스번호>` | `DE_211` 프로세스정의서 |
| 기능을 더하거나 뺐다 | `기능정의서:<기능ID>` | `DE_221` 기능정의서 |
| 서버 · DB · 스택 · 연계 구성을 바꿨다 | `시스템아키텍처:hw` `db` `sw` `link` | `DE_101` 시스템아키텍처정의서 |
| 화면을 만들거나 고쳤다 | `화면설계서:<화면ID>` | `DE_331` 화면설계서 |
| 프로그램 로직을 바꿨다 | `프로그램사양서:<프로그램ID>` | `EC_201` 프로그램사양서 |
| 테이블 · 컬럼을 바꿨다 | `테이블정의서:<물리명>` | `DE_431` 테이블정의서 |
| 표준 용어를 정했다 | `도메인용어:<논리명>` | `DE_421` DB도메인용어정의서 |
| 코드값을 더하거나 뺐다 | `코드정의서:<구분코드>` | `DE_441` 코드정의서 |
| 연계를 만들거나 바꿨다 | `인터페이스:<인터페이스ID>` | `DE_501` 인터페이스정의서 |
| 배치 Object 를 바꿨다 | `배치:<Object명>` | 〃 |
| 시험 시나리오를 바꿨다 | `시험시나리오:UT-*` `PT-*` `IT-*` | `TE_102` `TE_202` `TE_302` |
| 위험 · 이슈가 생기거나 닫혔다 | `이슈:<이슈ID>` | `BM_501` 위험및이슈관리대장 |

**등록부에 없는 일에는 파생할 관리 문서가 없다.** 처음 부은 상태에서 회의 ·
보고 · 시험 결과는 *사건*이라 파생할 대상이 없고, 대장 · 계획서 · 가이드는
*집계*거나 *서술*이라 좌표와 섹션이 1:1이 아니다. 그것들은 **작업 기록 자체가
원천**이다 — 좌표를 지어내서 억지로 걸지 마라. 팀이 그런 문서를 등록부에
올리면(`save` 의 `managed` · 손으로는 `_managed.md`) 그때부터는 좌표가 있다.

> **하나의 일이 좌표 여럿을 건드리는 것이 정상이다.** 화면 하나를 고치면서

> 만큼 고쳐야 하고, 그것이 문서가 갈라지지 않는 이유다.

### 말로 언급한 것은 좌표가 아니다

타입을 한글로 쓰면 걱정이 하나 생긴다 — *"회의에서 **테이블정의서** 얘기가
나왔다고 적으면 테이블정의서가 파생 대상이 되나?"*

**안 된다.** 막는 것이 넷이다.

| | |
|---|---|
| 1 | **파생은 `touches:` 만 본다.** 본문 산문은 파생 계산에 들어가지 않는다 |
| 2 | **좌표는 `타입:값` 이다.** `회의록` 은 좌표가 아니고 `회의록:2026-0916` 이 좌표다. 산문에 콜론과 값을 같이 쓸 일이 없다 |
| 3 | 본문 검사는 **백틱 안에 쓴, 이미 등재된 좌표**만 본다. 그것도 **경고**이고 커밋을 막지 않는다 |
| 4 | **등록부에 행이 없는 타입은 파생되지 않는다.** 처음 부은 상태에는 회의 · 보고 · 형상관리 타입이 없고, 파생되는 타입은 위 「지금 등록부」 가 전부다 |

실제로 돌려 본 것 —

```
본문에 "회의록을 정리했고 주간 보고서도 냈다. 형상관리 대장도 훑었다.
       이슈 하나를 말로 꺼냈다. 테이블정의서도 언급했다."
touches: []
→ ctx check: 이상 없음                        아무것도 파생되지 않는다

본문에 `테이블정의서:ex_plan_mst` (백틱 · 등재된 좌표)
touches: []
→ [경고] 본문에만 있는 좌표                    경고일 뿐 커밋은 된다
```

세 번째 줄이 **일부러 경고인 이유**가 있다. 오류로 올리면 사람이 검사를
피하려고 본문에서 좌표 표기를 지우기 시작하고, 그러면 *"빠뜨렸다"* 는 신호
자체가 사라진다.

> **사람·에이전트 쪽 보호도 따로 있다.** `cdp-save` 의 좌표 판정표가
> **신설 · 변경 · 삭제는 O, 참조 · 호출 · 언급은 X** 로 못박고 있다.
> 말로 꺼낸 것은 좌표가 아니다.

### 타입 이름은 정본 문서에서 딴다

전에는 `table:` `screen:` `req:` 같은 영문 약어였다. **그 낱말들은 너무
보편적이다** — 어느 시스템에나 테이블이 있고 화면이 있어서, 이름만으로는
무엇을 가리키는지도 어디로 가는지도 알 수 없었다. `_managed.md` 를 열어 봐야
드러났다.

규칙은 하나다.

> **정본 문서 이름에서 서식 꼬리(`정의서` · `설계서` · `사양서` · `대장`)를
> 뗀다. 떼고 나서 보편적인 낱말이 되면 떼지 않는다.**

| 문서 | 떼면 | 보편적인가 | 타입 |
|---|---|:--:|---|
| 요구사항정의서 | 요구사항 | 아니오 | `요구사항` |
| 프로세스정의서 | 프로세스 | **예** | `프로세스정의서` |
| 기능정의서 | 기능 | **예** | `기능정의서` |
| 시스템아키텍처정의서 | 시스템아키텍처 | 아니오 | `시스템아키텍처` |
| 화면설계서 | 화면 | **예** | `화면설계서` |
| 프로그램사양서 | 프로그램 | **예** | `프로그램사양서` |
| 테이블정의서 | 테이블 | **예** | `테이블정의서` |
| DB도메인용어정의서 | 도메인용어 | 아니오 | `도메인용어` |
| 코드정의서 | 코드 | **예** | `코드정의서` |
| 인터페이스정의서 | 인터페이스 | 아니오 | `인터페이스` |
| 인터페이스정의서(Object) | 배치 | 아니오 | `배치` |
| 시험시나리오 3종 | 시나리오 | **예** | `시험시나리오` |
| 위험및이슈관리대장 | 이슈 | 아니오 | `이슈` |
| (등록부 비대상) | — | — | `업무영역` |

**값은 손대지 않았다.** `화면설계서:EXA010` 의 `EXA010` 은 프로젝트가 정하는
그대로다.

> CDP 는 타입에 영문도 그대로 받는다. 한글로 쓰는 것은 **이 패키지의 선택**이지
> 도구의 요구가 아니다 — skill 과 매뉴얼의 예시가 `table:` 인 것은 그래서다.

## 값이 예시로 채워져 있다 — 지우고 시작한다

아래 값은 **문서의 예시 섹션과 짝**이다. `example:` 이 붙은 줄이 그것이고,
문서의 예시 섹션을 지울 때 여기 줄도 같이 지운다.

**`example:` 은 "이건 좌표로 세지 마라" 는 표시다.** 좌표 수에도 `INDEX` 에도
들어가지 않는다. 그래서 예시를 달고 일해도 숫자가 부풀지 않고, 급하지 않으면
나중에 지워도 된다 — `ctx check` 가 남아 있다고 **경고로** 알려 준다.

> **한쪽만 지워도 커밋은 막히지 않는다.** dangling 검사는 작업 기록의
> `touches` 만 보기 때문이다. 대신 문서 쪽만 지우면 `ctx where` 가
> *"섹션이 없음 — 주입해도 빈손이다"* 를 낸다. **둘을 같이 지워라.**

**지우기 전에 한 바퀴 돌려 보면 좋다.** 이 한 벌이 붙어 있어서 부은 직후에도
파생 고리가 실제로 돈다 — `touches:` 에 적으면 그때는 좌표로 센다.

```
ctx where 테이블정의서:ex_plan_mst      정본이 어느 문서 어느 섹션인가
ctx derive                       파생이 남은 섹션
ctx apply 테이블정의서:ex_plan_mst      섹션에 붙일 초안
```

**`시스템아키텍처:` 넷만 예시가 아니다.** 원본에 ID 가 없는 유일한 문서라 좌표를 팀이
정해야 하는데, 넷은 어느 사업에나 있으므로 값으로 박아 두었다.

> `## <타입>` 의 **순서가 화면 · CLI 의 카테고리 순서**이므로 순서는 건드리지
> 않는다. 쓰지 않는 타입은 통째로 지운다.
