# 관리번호

산출물마다 붙는 번호의 규칙. **이 파일 하나가 규칙의 정본**이다 — 각 문서
머리 표의 `관리번호` 는 여기서 정한 값을 적은 것이다.

---

## 1. 모양

```
BM _ 4 3 1
 │    │ │ └ 일련    그 TASK 안의 몇 번째 산출물인가   1..9
 │    │ └── 중분류   그 단계 안의 TASK               0..9  (없으면 0)
 │    └──── 대분류   공정 안의 단계                   1..9
 └───────── 공정     BM AN DE EC TE TR
```

`BM_431` = 사업관리 › 의사소통관리(4) › 월간보고(3) › 1번째 = **월간보고서**.

### 자릿수는 **폴더 번호**다

대분류 · 중분류는 `C:\project\DPMS` 폴더의 앞 두 자리를 그대로 쓴다.

```
02. 개발 산출물 / 02. 설계(DE) / 04. DB설계 / 03. 테이블정의
                       │            │           └ 중분류 3
                       │            └───────────── 대분류 4
                       └────────────────────────── 공정 DE
                                                   → DE_431
```

**형상관리대장이 아니라 폴더를 읽는다.** 대장은 이 사업에서 고쳐야 할
문서이고, 실제 일하는 자리를 말하는 것은 폴더다 — §5.3 이 그 차이다.

### 공정 여섯

| 코드 | 공정 | 언제 | 문서 |
|---|---|---|--:|
| `BM` | 사업관리 | **전 기간** | 10 |
| `AN` | 분석 | 분석 단계 | 1 |
| `DE` | 설계 | 설계 단계 | 12 |
| `EC` | 구현 | 구현 단계 | 3 |
| `TE` | 시험 | 시험 단계 | 9 |
| `TR` | 이행 | 이행 단계 | 5 |
| | | | **40** |

**`BM` 은 순서 축에 놓이지 않는다.** 착수보고서는 맨 앞이고 완료보고서는 맨
끝이며 주간보고는 전 기간이다. 그래서 폴더가 둘이다 — §3.

---

## 2. 사업 코드는 여기에만 적는다

제출물의 파일명은 앞에 **사업 코드**가 붙는다.

```
레포 안    docs/2.개발/DE_331_화면설계서.md
제출물     ____-DE_331_화면설계서.pptx
           └ 여기에 사업 코드
```

| | |
|---|---|
| **이 사업의 코드** | `____` ← **여기를 고친다** |

**문서 46개에 사업 코드를 적지 않는다.** 레포 안에는 사업이 하나뿐이라 그
자리는 정보가 0 이고, 틀릴 자리만 46개 생긴다. 사업이 바뀌면 위 한 칸만
고친다.

---

## 3. 배치 — 번호순이 곧 일하는 순서다

```
docs/
  1.관리/     BM_111 … BM_601          전 기간에 걸친 것
  2.개발/     AN_… DE_… EC_… TE_… TR_…  분석 → 설계 → 구현 → 시험 → 이행
```

개발 폴더 안에서는 **파일명 오름차순이 그대로 업무 순서**다. 공정 코드
`AN < DE < EC < TE < TR` 이 이미 그 순서이기 때문에 따로 순번을 붙이지 않았다.
순번을 붙이면 공정 코드와 같은 말을 두 번 하게 되고, 어긋날 자리만 생긴다.

> **폴더는 규약이 아니다.** CDP 는 `docs/` 아래 어떤 깊이든 관리 문서로 읽는다
> (`docs/**/*.md`). 평평하게 쓰던 레포는 그대로 두어도 된다 — 이 두 폴더는
> 이 패키지가 고른 배치일 뿐이다.
>
> **깊이를 바꾸면 둘을 같이 고쳐라** — `_managed.md` 의 문서 경로, 그리고
> 문서 안에서 작업 기록을 가리키는 상대 경로. 지금은 두 단계라 `../../work/`
> 다. 평평하게 두면 `../work/` 가 된다.

---

## 4. 번호를 새로 줄 때

1. **공정**을 고른다 — 그 산출물을 *만드는* 단계다. 내는 시기가 아니다.
   (개발가이드는 구현완료에 내지만 설계에서 만들므로 `DE` 다.)
2. **대분류**는 그 공정 안의 단계. 이미 있는 것을 쓰고, 새 단계면 다음 수를 준다.
3. **중분류**는 그 단계 안의 TASK. 단계가 쪼개지지 않으면 `0`.
4. **일련**은 그 TASK 안에서 1 부터. **이미 있으면 반드시 올린다.**

> **제일 흔한 실수가 4번**이다. 원본에서 단위·성능·통합테스트의
> 계획서·시나리오·결과서가 각각 **셋이 한 번호**였고, 운영자·사용자메뉴얼도
> 한 번호였다. 번호가 겹치면 형상관리대장에서 어느 행이 어느 파일인지
> 알 수 없게 된다.

**번호는 식별자가 아니라 속성이다.** 이 레포에서 문서를 가리키는 것은
**문서명**이다. 번호는 발주처와 말을 맞추기 위한 것이고, 손으로 붙이는 것이라
언제든 어긋날 수 있다.

### 자리가 차면 TASK 를 쪼갠다

세 자리가 각각 `1..9` 다. **한 TASK 아래 열 번째 산출물이 생기면 적을 자리가
없다.** 그때 번호를 두 자리로 늘리지 마라 — 자릿수가 위치를 뜻한다는 성질이
거기서 깨진다.

**열 개가 한 TASK 라는 것이 먼저 의심스럽다.** 중분류를 둘로 쪼개고 다음
수를 준다. 지금 이 패키지는 한 TASK 최대 **3개**다(`DE_42*` 테이블·코드·ERD,
시험 3종). 자리가 찰 일은 당분간 없다.

### 빈 번호는 메우지 않는다

`AN_1xx`(사전분석) 이 통째로 비어 있고 `DE_421` 아래 일련도 비어 있다.
폴더에 자리가 있는데 산출물을 안 두기로 했거나, 산출물이 다른 공정으로 옮겨
갔다는 기록이다. 당겨서 메우면 번호가 위치를 뜻한다는 성질이 깨진다.

## 5. 원본과 다르게 준 자리

**원천은 폴더다.** 형상관리대장은 이 사업에서 고쳐야 할 문서이고, 대장과
폴더가 부딪히면 폴더를 따른다. 대장을 그 구조로 다시 쓰는 것이 이 패키지를
쓰는 첫 일 중 하나다.

### 5.1 겹친 번호 — 일련 자리를 올렸다

| 원본 | 이 패키지 | 문서 |
|---|---|---|
| `BM_111` ×2 | `BM_111` `BM_112` | 착수보고서 · 사업수행계획서 |
| `TE_101` ×3 | `TE_101` `TE_102` `TE_103` | 단위테스트 계획서 · 시나리오 · 결과서 |
| `TE_201` ×3 | `TE_201` `TE_202` `TE_203` | 성능테스트 〃 |
| `TE_301` ×3 | `TE_301` `TE_302` `TE_303` | 통합테스트 〃 |
| `TR_211` ×2 | `TR_211` `TR_212` | 운영자메뉴얼 · 사용자메뉴얼 |

### 5.2 번호가 둘이던 문서 — **만드는 단계**로 모았다

원본 대장은 같은 이름을 분석 단계와 설계 단계에 각각 올려 두었다. 이 패키지는
문서를 하나로 합쳤으므로 번호도 하나다.

| 문서 | 이 패키지 | 버린 것 |
|---|---|---|
| 프로세스정의서 | `DE_211` | `AN_211` |
| 프로그램목록 | `DE_321` | `AN_231` |
| 코드정의서 | `DE_441` | `AN_251` |
| 시스템아키텍처정의서 | `DE_101` | `AN_261` |

분석 단계 것은 AS-IS 조사이고 설계 단계 것이 TO-BE 정본이다. 문서 하나가 둘을
다 담으므로 **정본 쪽**을 쓴다. AS-IS 를 따로 관리하지 않기로 했으므로
`01. 사전분석` 자리는 비어 있다.

### 5.3 대장이 틀린 자리 — **폴더를 따랐다**

| 문서 | 대장 | 이 패키지 | 폴더 |
|---|---|---|---|
| 요구사항정의서 | `AN_111` | `AN_211` | `분석(AN)/02. 요구사항분석` |
| 기능정의서 | `AN_221` | `DE_221` | `설계(DE)/02. 프로세스설계` |
| DB도메인용어정의서 | `DE_412` | `DE_421` | `04. DB설계/02. DB도메인용어정의` |
| 테이블정의서 | `DE_422` | `DE_431` | `04. DB설계/03. 테이블정의` |
| 코드정의서 | `DE_423` | `DE_441` | `04. DB설계/04. 코드정의` |
| 인터페이스정의서 | `DE_451` | `DE_501` | `설계(DE)/05. 인터페이스설계` |
| 데이터이관정의서 | `DE_461` | `DE_601` | `설계(DE)/06. 데이터이관설계` |

어긋나는 방식이 둘이다.

**하나 — 대장이 수를 이어 세었다.** `441` 다음에 `451` `461` 을 주는 바람에
대분류 `4` 가 DB설계 · 인터페이스설계 · 데이터이관설계 셋을 뜻하게 됐다.
폴더는 `04` `05` `06` 으로 나란한 단계다.

**둘 — DB설계 안에서 축이 다르다.** 대장은 TASK(데이터표준화 · 데이터구조설계
· …)로 묶고 폴더는 산출물(DB개발가이드 · DB도메인용어정의 · 테이블정의 ·
코드정의)로 나눈다. 폴더의 `01~04` 를 중분류로 쓴다.

> **실물 파일명은 대장 편이다** — `GDI_AN_111_요구사항정의서.xlsx` 도
> `GDI_DE_422_테이블정의서.xlsx` 도 대장 번호를 달고 있다. 그래도 폴더를
> 택했다. 규칙을 폴더에서 역산했으므로 그 편이 일관되고, **한 자리에서라도
> 깨지면 번호는 아무것도 뜻하지 않는다.**
>
> 발주처가 원본 번호로 말을 맞춰 둔 사업이라면 되돌려라.
> 고칠 곳은 **문서 머리 표 · 파일명 · 형상관리대장 행** 셋뿐이다.

### 5.4 뺀 7종 · 더한 2종

**폴더에 자리가 없는 것은 뺐다.**

| | 대장 번호 | 왜 |
|---|---|---|
| 보안서약서 | `BM_601` | 보안관리 자리가 폴더에 없다 |
| 데이터 값 검증 방안서 · 업무규칙(BR) 정의서 | `DE_431` | 데이터구조검증 자리 없음 |
| 메타데이터 현행화 결과 · 데이터 개방 지원 방안 | `DE_441` | 데이터개방 자리 없음 |
| ERD모델링 | `DE_421` | 전용 자리 없음 |
| 인터페이스목록 | `AN_241` | 전용 자리 없음 |

**되살리려면** 그 TASK 폴더를 만들고 §4 대로 번호를 준 다음 문서를 세운다.
`DE_431` `DE_441` 은 지금 테이블정의서 · 코드정의서가 쓰고 있으므로
**같은 번호를 다시 주지 마라** — 새 중분류를 연다.

**폴더에 자리가 있는데 대장이 비운 것은 세웠다.**

| 폴더 자리 | 세운 것 |
|---|---|
| `03. 구현(EC)/03. 데이터이관계획` | `EC_301` 데이터이관계획서 |
| `05. 이행(TR)/01. 구축/01. 데이터이관` | `TR_111` 데이터이관결과서 |

이관이 셋으로 갈린다 — 무엇을(`DE_601`) · 언제 어떻게(`EC_301`) ·
어떻게 됐나(`TR_111`). 대장은 정의서를 두 번 세고 나머지 둘을 비워 두었다.
