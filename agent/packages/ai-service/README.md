# ai-service — AI · LLM 서비스

**문서 12종.** LLM 기능 — 어시스턴트 · 검색 증강(RAG) · 도구를 부르는 에이전트 — 을 만들고,
평가로 내보내고, 운영하며 지켜보는 팀의 한 벌이다. **모델 · 프롬프트 · 평가셋을 따로 두고,
평가셋을 출시 기준으로 쓴다.**

## 이런 팀

| | |
|---|---|
| 맞는다 | LLM 기능을 제품 · 사내 업무에 붙이고 **프롬프트 · 모델 판을 자주 바꾸는** 팀 — 바꿀 때마다 평가로 확인하고, 운영에서 품질 · 비용 · 지연을 보고, 가드레일 · 개인정보 · AI 규제를 챙겨야 한다 |
| 예시 | 가상 업무 「(예시) 온라인 상점」 의 상담 보조 — 도움말 센터에서 근거를 찾아 답변 초안을 쓰고 주문을 조회한다. 예시 값은 `ex` 로 시작한다 |

다른 패키지가 맞는 팀 —

| 패키지 | 이런 팀이면 |
|---|---|
| `public-si` | 발주처에 단계별 산출물(분석 · 설계 · 시험 · 이행)을 내는 공공 · SI 사업 |
| `agile-product` | AI 가 기능 하나일 뿐인 웹 · 모바일 제품팀 — 스프린트 · 기능명세 · 릴리스가 중심이다 |
| `cloud-native` | 여러 서비스를 클라우드에서 운영하는 플랫폼 · SRE 팀 — 서비스 · 서비스수준 · 런북이 중심이다 |
| `blank` | 맞는 서식이 없다 — 문서 · 타입을 직접 세운다 |

**패키지는 섞지 않는다.** 제품팀이 AI 기능 하나를 붙이는 것이면 `agile-product` 로 세우고,
여기서 필요한 문서(프롬프트명세 · 평가셋 같은 것)를 등록부 행 · 어휘 절과 같이 가져온다.

## 이 패키지는 **서식**이다

| 있다 | 없다 |
|---|---|
| 문서 골격 — 머리 표 · 예시 섹션 · 작성지침 | 그 팀의 기능 · 모델 · 프롬프트 · 평가셋 |
| `_managed.md` — 좌표 패턴 → 관리 문서 · 섹션 | 프롬프트 원문 · 평가 데이터 · 도구 스키마 — **코드 레포가 정본이다** |
| `_vocab.md` — 좌표 타입과 **순서** | 좌표 값 (`시스템아키텍처:` 넷만 예외) |

**프로젝트 맞춤은 레포 안에서 한다** — 안 쓰는 문서를 지우고 좌표를 등록한다. 패키지를 고치지 않는다.

## 붓는다

```
xcopy /E /I <배포본>\knowledge-repo-ai-service C:\cdp
copy <배포본>\cdp.exe C:\cdp\tools\
cd /d C:\cdp
git init && git config core.hooksPath .githooks
```

서버형은 콘솔 › 지식 레포 › 새 레포에서 `ai-service` 를 고른다. 부으면 `_vocab.md` 가 생기고
**그 순간 그 폴더가 지식 레포**가 된다 — 작업 기록이 0건이면 `ctx check` 는 `이상 없음` 이다.

## 첫날

```
1  안 쓰는 문서를 지운다            에이전트가 없으면 에이전트도구 · 검색이 없으면 지식소스
2  서식 예시를 지운다              ctx examples --purge · 서버형은 save 의 examples: "purge"
3  _vocab.md 에 좌표를 등록한다      모델 · 프롬프트 · 평가셋부터 — 여기 없는 좌표를 쓰면 커밋이 막힌다
4  ctx check                       이상 없음이 나오면 시작할 수 있다
```

**1 은 한 번에 한다.** 파일만 지우면 등록부 행이 없는 파일을 가리킨 채 남고, 그 타입에 작업
기록이 처음 닿는 순간 커밋이 막힌다(`ctx check` 가 「등록부 행이 없는 관리 문서를 가리킴」 으로 미리 경고한다).

| | 어떻게 |
|---|---|
| 서버형 · 세울 때 | 콘솔 › 지식 레포 › 새 레포의 「문서 고르기」 에서 체크를 푼다 |
| 서버형 · 세운 뒤 | 레포 › 관리 › 「관리 문서」(admin) — 사용 현황을 보고 골라 미리보기 → 지우기 |
| 셸(모드 A) | `bin/ctx docs drop DS_501 --dry-run` → `--apply-suggest --reason "도구 호출 없음"` → `bin/ctx index` → 커밋 |
| 에이전트 | `cdp-managed` 「문서 정리」 — 산문 언급까지 고쳐 쓴다 |

**3 은 셋부터.** 기능 하나가 돌려면 이 셋이 먼저 서야 한다.

| 순서 | 등록할 좌표 | 짝 섹션 |
|--:|---|---|
| 1 | 쓰는 모델 — `모델카드:<용도 키>` | `모델카드` |
| 2 | 그 모델을 부르는 프롬프트 — `프롬프트:<프롬프트 키>` | `프롬프트명세` |
| 3 | 그 둘을 재는 평가셋 — `평가셋:<평가셋 키>` | `평가셋` |
| 다음 | 기능 · 지식소스 · 도구 — 생길 때 | |

좌표 줄과 짝 섹션(`## <값> — <이름>` 바로 아래 `<!-- applied: null -->`)을 같이 세운다.
서버형은 save 의 `vocab` · `sections` 가 한 커밋으로 낸다.

## 원칙

| 원칙 | 이 패키지에서 |
|---|---|
| **작업 기록이 ADR 이다** | ADR 문서를 따로 두지 않는다. 「왜 이 모델인가」 · 「왜 이 쪼개기인가」 는 `work/` 의 작업 기록이고(불변), 뒤집으면 같은 좌표에 새 기록을 낸다(어느 것이 뒤인지는 도구가 날짜로 센다). `supersedes` 는 기록 자체가 틀렸을 때만 단다. 정본 문서에는 **지금 상태**만 |
| **코드가 정본인 것은 옮기지 않는다** | 프롬프트 원문 · 평가 데이터 · 도구 스키마 · 가드레일 설정은 코드 레포(프롬프트 레지스트리 · 데이터 저장소)에 둔다. 문서에는 `정본 위치` 와 판, 그리고 코드가 말하지 못하는 것 — 의도 · 지킬 것 · 바꾸면 무엇을 다시 재나 |
| **모델 · 프롬프트 · 평가는 따로 바뀐다** | 셋을 한 문서에 묶으면 하나가 바뀔 때 셋이 다 낡아 보인다. 따로 두고 좌표로 서로 가리킨다 — 모델 · 프롬프트 · 지식소스를 건드린 작업은 보통 평가셋 좌표도 적는다 |
| **평가셋이 출시 기준이다** | 출시 기준(지표 · 문턱 · 막는 실패)은 `평가셋` 섹션에 있다. 못 넘으면 내보내지 않는다 — 기준을 낮추는 것도 작업 기록이다 |
| 좌표는 바뀌고 여럿이 보는 대상에만 | 실험은 날짜축(`실험기록`), 위험은 대장(`AI위험관리`) — 좌표를 지어내 걸지 않는다 |

## 번호

관리번호는 **묶음 접두 + 세 자리**다 — `AI`(기획) · `DS`(설계) · `EV`(평가운영). 백 자리가 문서,
아래 두 자리는 같은 자리에 하나 더 세울 때 쓴다.

**번호는 속성이지 식별자가 아니다.** 문서의 식별자는 이름(파일 경로)이고 등록부는 경로로
가리킨다. 번호는 머리 표에 적고, 문서 고르기 · 참조 찾기(`bin/ctx docs`)가 사람에게 보이는 이름으로 쓴다.
새 문서는 그 묶음의 다음 백 자리를 쓴다 — 평가운영에 하나 더하면 EV_401.

## 더할 만한 것

처음 부은 한 벌에는 없다. 필요해지면 세운다 — 서버형은 save 의 `managed`(writer)가 등록부 행과
문서를 한 커밋으로, 셸은 `_managed.md` 행 + 문서 + `_vocab.md` 타입 절을 더하고 `bin/ctx index`.
대장 · 서술 문서는 행 없이 문서만 둔다.

| 문서 | 이럴 때 |
|---|---|
| 데이터카드 | 미세조정 · 학습 데이터를 직접 만든다 — 출처 · 동의 · 라이선스 · 개인정보 |
| 라벨링지침 | 사람이 평가셋 · 학습 데이터에 정답을 단다 — 채점 기준이 사람마다 갈린다 |
| 사용자피드백대장 | 신고 · 고친 차이가 쌓여 평가셋으로 옮길 것을 골라야 한다 |
| 비용예산 | 토큰 비용이 예산의 큰 몫이 된다 — 월 × 기능 · 모델 |

## 알려진 한계

| | |
|---|---|
| 평가 결과 수치는 사람이 옮겨 적는다 | 평가 도구 · 추적 도구와 연동하지 않는다 — `평가셋` 의 「최근 결과」 는 평가 실행에서 손으로 옮긴다 |
| 원문과 명세의 판 | 도구는 코드 레포의 프롬프트를 읽지 않는다 — `정본 위치` 의 판과 명세의 판이 같은지는 리뷰에서 사람이 본다 |
| 법규 판단 | `AI위험관리` · `AI안전정책` 은 점검할 자리를 줄 뿐 판단하지 않는다 — 적용 여부는 팀이 확인해 적는다 |
| 운영 지표 | 대시보드를 대신하지 않는다 — `운영모니터링` 은 무엇을 보고 언제 움직이는지만 |
