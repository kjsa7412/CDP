# 좌표 어휘

이 파일이 통제 어휘(authority file)다. 같은 대상을 가리키는 여러 표기 중
**정본을 하나 정하고 나머지를 `aliases` 로 연결한다.** `aliases` 가 이 파일의
진짜 핵심이다 — 정본 목록만 있으면 작성자만 편해지고, `aliases` 가 있어야
수신자가 자연어로 물어도 걸린다.

**운영 원칙** — 추가는 한 줄, 삭제는 하지 않는다(`deprecated` 로 표시),
alias 는 발견될 때마다 추가한다.

---

## 무슨 일을 하면 무엇을 적나

작업 기록의 `touches:` 에 좌표를 적으면 **그 관리 문서를 고칠 때까지 커밋이
막힌다.** 그것이 파생 강제다. 어느 일이 어느 문서로 가는지가 아래 표다 —
**처음 부은 상태의 안내**다. 지금 등록부는 그 아래 생성 블록이 정본이다.

| 이런 일을 했으면 | `touches:` 에 | 고쳐야 하는 관리 문서 |
|---|---|---|
| AI 기능을 붙이거나 입력 · 출력 · 품질 기준 · 예산을 바꿨다 | `기능명세:<기능ID>` | `AI_201` 기능명세 |
| 처리 흐름 · 게이트웨이 · 추적 구성을 바꿨다 | `시스템아키텍처:context` `pipeline` `serving` `observability` | `DS_101` 시스템아키텍처 |
| 모델을 바꾸거나 판을 올렸다 | `모델카드:<모델키>` + `평가셋:<평가셋키>` | `DS_201` 모델카드 · `EV_101` 평가셋 |
| 프롬프트를 고쳤다 | `프롬프트:<프롬프트키>` + `평가셋:<평가셋키>` | `DS_301` 프롬프트명세 · `EV_101` 평가셋 |
| 검색 원천을 더하거나 쪼개기 · 임베딩 · 권한을 바꿨다 | `지식소스:<원천키>` + `평가셋:<평가셋키>` | `DS_401` 지식소스 · `EV_101` 평가셋 |
| 모델에 도구를 주거나 권한 · 승인 규칙을 바꿨다 | `에이전트도구:<도구이름>` | `DS_501` 에이전트도구 |
| 평가셋에 사례를 더하거나 출시 기준을 바꿨다 | `평가셋:<평가셋키>` | `EV_101` 평가셋 |

**세 가지는 따로 바뀐다** — 모델 · 프롬프트 · 지식소스 중 무엇을 바꿔도 품질이
움직인다. 그래서 그 셋을 건드린 작업은 보통 평가셋 좌표도 같이 적는다. 평가를 다시
돌렸고 그 섹션의 「최근 결과」 를 고쳤다는 뜻이다 — **「다시 재지 않았다」 를 파생이 묻는다.**

**등록부에 없는 일에는 파생할 관리 문서가 없다.** 처음 부은 상태에서 실험은
*사건*이라 파생할 대상이 없고, 위험 대장 · 안전정책 · 운영모니터링은 *집계*거나
*서술*이라 좌표와 섹션이 1:1이 아니다. 그것들은 **작업 기록 자체가 원천**이다 —
좌표를 지어내서 억지로 걸지 마라. 팀이 그런 문서를 등록부에 올리면(`save` 의
`managed` · 손으로는 `_managed.md`) 그때부터는 좌표가 있다.

> **하나의 일이 좌표 여럿을 건드리는 것이 정상이다.** 프롬프트를 고치면서
> 평가셋에 사례를 더했으면 프롬프트 좌표와 평가셋 좌표를 둘 다 적는다. 적은
> 만큼 고쳐야 하고, 그것이 문서가 갈라지지 않는 이유다.

### 말로 언급한 것은 좌표가 아니다

타입을 한글로 쓰면 걱정이 하나 생긴다 — *"실험 회고에 **모델카드** 얘기가
나왔다고 적으면 모델카드가 파생 대상이 되나?"*

**안 된다.** 막는 것이 넷이다.

| | |
|---|---|
| 1 | **파생은 `touches:` 만 본다.** 본문 산문은 파생 계산에 들어가지 않는다 |
| 2 | **좌표는 `타입:값` 이다.** 「모델카드를 봤다」 에는 콜론과 값이 없다 — 산문에 콜론과 값을 같이 쓸 일이 없다 |
| 3 | 본문 검사는 **백틱 안에 쓴, 이미 등재된 좌표**만 본다. 그것도 **경고**이고 커밋을 막지 않는다 |
| 4 | **등록부에 행이 없는 타입은 파생되지 않는다.** 파생되는 타입은 위 「지금 등록부」 가 전부다 |

세 번째가 **일부러 경고인 이유**가 있다. 오류로 올리면 사람이 검사를 피하려고
본문에서 좌표 표기를 지우기 시작하고, 그러면 *"빠뜨렸다"* 는 신호 자체가 사라진다.

> **사람·에이전트 쪽 보호도 따로 있다.** `cdp-save` 의 좌표 판정표가
> **신설 · 변경 · 삭제는 O, 참조 · 호출 · 언급은 X** 로 못박고 있다.
> 프롬프트를 고치며 모델을 「불렀다」 고 모델 좌표를 적지 않는다.

### 타입 이름은 정본 문서 이름에서 딴다

규칙은 하나다.

> **정본 문서 이름에서 서식 꼬리(`명세` · `카드` · `셋`)를 뗀다. 떼고 나서
> 보편적인 낱말이 되면 떼지 않는다.** 이름만 보고 어느 문서로 가는지 알아야 한다.

| 문서 | 떼면 | 보편적인가 | 타입 |
|---|---|:--:|---|
| 기능명세 | 기능 | **예** | `기능명세` |
| 시스템아키텍처 | (꼬리 없음) | 아니오 | `시스템아키텍처` |
| 모델카드 | 모델 | **예** — 데이터 모델 · 도메인 모델과 갈리지 않는다 | `모델카드` |
| 프롬프트명세 | 프롬프트 | 아니오 | `프롬프트` |
| 지식소스 | (꼬리 없음) | 아니오 | `지식소스` |
| 에이전트도구 | 도구 | **예** — 개발 도구 · 사내 도구와 갈리지 않는다 | `에이전트도구` |
| 평가셋 | 평가 | **예** — 평가는 사람 평가 · 성과 평가도 된다 | `평가셋` |

**타입은 한글로 시작한다.** 어휘 파서는 대문자 영문 타입도 받지만, MCP 의 좌표 검사와
서버형 save 의 `managed` 는 영문이면 **소문자만** 받는다 — 경로(`C:/…`)를 좌표로 읽지
않으려는 것이다. 그래서 `LLM:` · `RAG:` · `MCP:` 같은 약어 타입은 여기 써지는데 MCP · save
가 `E_COORD` 로 거절한다. RAG 원천은 `지식소스`, 함수 · MCP 도구는 `에이전트도구` 다.

**값에 판을 넣지 않는다.** 값은 대상의 이름이고 판은 섹션의 칸이다 — 프롬프트 키에
`-v7` 을 붙이면 판을 올릴 때마다 좌표가 새로 생기고 이력이 끊긴다. 모델카드의 값도
공급자 모델 이름이 아니라 **용도**(`ex-answer-llm`)로 짓는다 — 모델을 갈아 끼워도
좌표는 남는다.

## 값이 예시로 채워져 있다 — 지우고 시작한다

아래 값은 **문서의 예시 섹션과 짝**이다. `example:` 이 붙은 줄이 그것이고,
문서의 예시 섹션을 지울 때 여기 줄도 같이 지운다. 예시는 가상 업무 「(예시) 온라인
상점」 의 상담 보조다 — 도움말 센터에서 근거를 찾아 답변 초안을 쓰고 주문을 조회한다.

**`example:` 은 "이건 좌표로 세지 마라" 는 표시다.** 좌표 수에도 `INDEX` 에도
들어가지 않는다. 급하지 않으면 나중에 지워도 된다 — `ctx check` 가 남아 있다고
**경고로** 알려 준다. 지울 때는 한 번에 — `ctx examples --purge`(서버형은 save 의
`examples: "purge"`)가 어휘 줄과 짝 섹션을 같이 지운다.

**지우기 전에 한 바퀴 돌려 보면 좋다.** 이 한 벌이 붙어 있어서 부은 직후에도
파생 고리가 실제로 돈다 — `touches:` 에 적으면 그때는 좌표로 센다.

```
ctx where 프롬프트:ex-support-answer     정본이 어느 문서 어느 섹션인가
ctx derive                              파생이 남은 섹션
ctx apply 프롬프트:ex-support-answer     섹션에 붙일 초안
```

**`시스템아키텍처:` 넷만 예시가 아니다.** 어느 AI 서비스에나 있는 자리라 값으로
박아 두었다. 늘리거나 줄이려면 이 절과 `시스템아키텍처` 문서를 함께 고친다.

> `## <타입>` 의 **순서가 화면 · CLI 의 카테고리 순서**이므로 순서는 건드리지
> 않는다. 쓰지 않는 문서는 `README.md` 「첫날」 1 로 지운다.
