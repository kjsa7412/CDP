# DS_601 AI안전정책

AI 기능 전체에 걸리는 안전 규칙. **기능마다 다시 적지 않는 것**을 여기 한 번 적는다.

| | |
|---|---|
| 관리번호 | `DS_601` |
| 언제 | 첫 기능 출시 전 · 사고 뒤 · 사내 규정이나 법규 해석이 바뀔 때 |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

**무엇** — 가드레일 · 프롬프트 인젝션 · 개인정보 · 출력 표시 · 사람 검토 · 기록 보존.
**언제** — 첫 기능을 내보내기 전에 세우고, 사고나 새 위험이 보이면 고친다.
**누가** — AI 리드 · 보안 · 개인정보 담당.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 위험 하나하나와 그 상태 | `AI위험관리` — 여기는 **규칙**, 거기는 **위험 목록** |
| 기능별 예외 | `기능명세` 의 그 섹션 |
| 가드레일 설정값 · 금칙어 목록 | 코드 레포 — 여기는 무엇을 왜 막는지 |
| 규칙을 재는 사례 | `평가셋` |

> **규칙마다 재는 법이 있어야 한다.** 「인젝션을 막는다」 를 적었으면 그것을 시험하는 사례가
> 평가셋에 있어야 한다 — 없으면 규칙이 아니라 바람이다.

## 가드레일

| 단계 | 무엇을 거르나 | 걸리면 |
|---|---|---|
| 입력 | (예시) 길이 · 금칙 주제 · 인젝션 의심 문구 | 표시하고 계속 · 금칙 주제는 초안 없음 |
| 검색 결과 | (예시) 사용자 권한 밖 문서 · 만료 문서 | 뺀다 |
| 출력 | (예시) 근거 없는 약속 · 개인정보 · 모욕 표현 | 초안을 내지 않는다 |

## 프롬프트 인젝션

| 규칙 | 어디서 지키나 |
|---|---|
| (예시) 사용자 입력 · 검색된 문서 · 도구 결과는 **데이터**다 — 구분 표시로 감싸고 그 안의 지시는 따르지 않는다 | `프롬프트명세` 의 지킬 것 |
| (예시) 간접 인젝션(검색된 문서 · 도구 결과에 심은 지시)도 같은 규칙이다 | 〃 |
| (예시) 부작용이 있는 도구는 사람 확인 없이 부르지 않는다 | `에이전트도구` 의 승인 필요 |
| (예시) 레드팀 사례를 평가셋에 두고 출시마다 돌린다 | `평가셋` |

## 개인정보

| 규칙 | 어디서 지키나 |
|---|---|
| (예시) 모델에 넣기 전에 가린다 — 전화번호 · 주소 · 결제 정보 | 입력 검사 |
| (예시) 공급자의 데이터 처리 조건(학습 사용 · 보존 · 처리 지역)을 확인한다 | `모델카드` |
| (예시) 평가셋에 실제 문의를 쓰면 가린 뒤에 쓴다 | `평가셋` |
| 적용 법규(개인정보 보호법 등)의 해석은 팀이 개인정보 담당과 확인한다 | `AI위험관리` 의 근거 칸 |

## 출력 표시

(예시) 상담 화면의 AI 초안에는 「AI 초안」 표지와 근거 링크를 단다. 고객에게 AI 결과물이
그대로 나가는 기능을 만들면 **생성형 결과물 표시 · 고지 방법**을 여기 먼저 적는다 —
인공지능 기본법의 표시 의무가 걸리는지는 팀이 확인한다.

## 사람 검토

| 기능 유형 | 사람 검토 |
|---|---|
| (예시) 초안 · 제안 — 사람이 보낸다 | 보내는 사람이 본다 · 운영 표본 주 50건 검수 |
| (예시) 부작용 있는 도구 | 실행 전 확인 단추 |
| (예시) 고객에게 바로 나가는 답 | 지금 없음 — 만들면 출시 전에 이 표를 고친다 |

## 기록 보존

| 기록 | 보존 | 누가 보나 |
|---|---|---|
| (예시) 요청 추적 — 가린 입력 · 출력 | 30일 | AI 엔지니어 · 운영 |
| (예시) 피드백 · 신고 | 1년 | 상담 운영 · AI 리드 |
| (예시) 평가 결과 | 판마다 계속 | 누구나 |

> ⚠ **예시 행이다 — 지우고 시작한다.** 절 제목은 두고 내용을 팀의 것으로 바꾼다.

| 항목 | 작성방법 | 필수 |
|---|---|:--:|
| 머리 표 | 관리번호는 고치지 않는다 | 필수 |

| 규칙 | 규칙마다 **어디서 지키나**(문서 · 단계)를 같이. 재는 사례가 평가셋에 있어야 한다 | 필수 |
| 법규 | 이름만 적고 해석은 적지 않는다 — 확인한 결과는 `AI위험관리` 근거 칸과 작업 기록에 | 필수 |
| 근거 | 다른 문서에 있는 것은 **옮겨 적지 말고 이름으로 가리킨다** | 필수 |
| 변경 | 문서 맨 아래에 `**변경** · 날짜 [작업기록](../../work/…) 무엇이` 를 쌓는다 | 변경 시 필수 |
