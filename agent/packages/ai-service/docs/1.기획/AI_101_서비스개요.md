# AI_101 서비스개요

AI 서비스 전체의 한 장. **왜 AI 를 쓰고, 언제 쓰지 않는지**를 먼저 적는다.

| | |
|---|---|
| 관리번호 | `AI_101` |
| 언제 | 기획 시작 · 사용자 · 범위 · 성공 기준이 바뀔 때 |
| 등록부 | **비대상** — 문서 전체가 내용이다 |

**무엇** — 목적 · 사용자 · AI 를 쓰는 이유와 **쓰지 않는 경우** · 성공 기준 · 사람의 역할.
기능 하나하나는 `기능명세` 가 갖고, 여기는 그 기능들이 함께 무엇을 하려는지다.
**언제** — 기획을 시작할 때 쓰고, 대상 사용자 · 범위 · 성공 기준이 바뀌면 고친다.
**누가** — 제품 책임자 · AI 리드.

**여기 적지 않는 것**

| | 어디로 |
|---|---|
| 기능별 입력 · 출력 · 품질 기준 · 예산 | `기능명세` |
| 위험 · 법규 검토 | `AI위험관리` |
| 쓰는 모델 · 판 | `모델카드` |
| 왜 이렇게 정했나 | 작업 기록(`work/`) — 결정은 기록이 갖는다 |

> **「AI 를 쓰지 않는 경우」 가 이 문서의 값이다.** 규칙 · 검색 · 사람이 더 나은
> 자리를 적어 두지 않으면 기능마다 LLM 을 붙이자는 말이 다시 나온다.

## 목적

(예시) 상담원이 같은 질문에 같은 답을 손으로 쓰는 시간을 줄인다 — 도움말 센터와 주문
정보로 **답변 초안**을 만들고, 상담원이 고쳐 보낸다.

## 사용자

| 사용자 | 하는 일 | AI 와 만나는 자리 |
|---|---|---|
| (예시) 상담원 | 문의에 답한다 | 답변 초안을 받아 고치고 보낸다 |
| (예시) 고객 | 문의를 남긴다 | **AI 를 직접 만나지 않는다** — 사람이 보낸 답만 받는다 |
| (예시) 상담 운영 | 품질 · 지표를 본다 | 피드백 · 평가 결과를 본다 |

## AI 를 쓰는 이유 · 쓰지 않는 경우

| | |
|---|---|
| 쓴다 | (예시) 도움말 문서가 많고 자주 바뀌어 규칙으로 답을 고르기 어렵다 · 같은 뜻을 다르게 묻는다 |
| **쓰지 않는다** | (예시) 환불 · 보상 결정 — 정책 규칙과 사람이 한다 · 주문 상태 자체 — 시스템 값을 그대로 보인다 · 분쟁 문의 — 바로 사람에게 |

## 성공 기준

| 지표 | 지금 | 목표 | 어디서 보나 |
|---|--:|--:|---|
| (예시) 초안 채택률 — 고치지 않거나 조금 고쳐 보낸 비율 | — | 60% 이상 | `운영모니터링` |
| (예시) 문의당 처리 시간 | 6분 | 4분 | 상담 시스템 |
| (예시) 근거 없는 안내(환각) 신고 | — | 월 5건 이하 | `운영모니터링` |

## 사람의 역할

(예시) **고객에게 나가는 모든 답은 상담원이 보낸다** — AI 는 초안만 쓴다. 도구는 읽기만 하고,
쓰기(취소 · 환불)는 AI 에게 주지 않는다. 기능을 끄는 스위치(기능 플래그)는 상담 운영이 쥔다.

> ⚠ **예시 행이다 — 지우고 시작한다.** 절 제목은 두고 내용을 팀의 것으로 바꾼다.
