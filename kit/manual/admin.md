# CDP 사용 매뉴얼 — 관리자용

하루 쓰는 법은 [MANUAL.md](MANUAL.md) 에 있다. 여기는 **세우고 · 늘리고 ·
나눠주고 · 고장을 고치는** 사람의 문서다.

**폐쇄망에서는 물어볼 사람이 없다.** 이 문서가 그 사람을 대신한다.

---

## 1. 무엇을 관리하는가

지식 레포는 **두 층 · 세 파일 · 한 검사**다. 그게 전부다.

```
<repo>/
  work/            ① 작업 기록 — 사건.  불변. 계속 쌓인다
  docs/            ② 정본 문서 — 상태.  가변. 덮어쓴다
  _vocab.md        ③ 통제 어휘  — 좌표의 이름표
  _managed.md      ④ 등록부     — 좌표 패턴 → 문서 · 섹션
  .githooks/       ⑤ pre-commit — 유일한 결정론적 보증
  bin/ctx          ⑥ 자족 실행기 (Node 없어도 돈다)
  .claude/skills/  ⑦ 절차 — LLM 이 읽는 지시문
  MANUAL.md        이 문서들
```

> **설계서는 레포에 안 들어온다.** 전에는 `design/` 에 도구 설계서를 통째로
> 복사했는데, 그 안에 개발 중 작업 메모까지 따라 들어왔다 — 레포를 여는
> 사람은 자기 프로젝트를 찾으러 온 것이다. 자족 층은 이 매뉴얼 두 부가
> 맡고, 설계서는 배포본의 `docs/` 에 있다.

**관리자가 실제로 손대는 것은 ③④⑤⑥뿐이다.** ①②는 사용자가 쓴다.

| | 누가 | 언제 |
|---|---|---|
| ③ `_vocab.md` | 사용자가 추가, **관리자가 정리** | 새 좌표가 나올 때 |
| ④ `_managed.md` | **관리자만** | 새 문서 종류를 정본으로 삼을 때 |
| ⑤ 훅 | 관리자가 배포, **각자 한 번 설정** | clone 직후 |
| ⑥ `bin/ctx` | **관리자가 재번들·배포** | 도구를 고칠 때마다 |

> **③④를 사용자에게 완전히 열면 어휘가 갈라진다.** 같은 대상에 두 이름이
> 생기고 그 순간 좌표는 좌표가 아니다. 반대로 완전히 닫으면 커밋이 관리자를
> 기다리게 된다. **어휘 추가는 열고, 등록부는 닫는다** — 이게 그 타협이다.

## 2. 처음 세우기

### ① 레포를 만든다

```
mkdir knowledge-repo && cd knowledge-repo
git init
mkdir -p work/assets docs .githooks bin .claude/skills
```

**`_vocab.md` 와 `_managed.md` 가 있는 폴더가 지식 레포다.** 앱은 그것으로
판별한다.

### ② 어휘의 타입을 정한다

`_vocab.md` 의 `## <타입>` 섹션 순서가 **곧 화면의 카테고리 순서다.**
알파벳순으로 다시 매기지 않으므로, **자주 쓰는 것을 위에 둔다.**

```markdown
# 좌표 어휘

## table

- `table:rp_plnd_mst` — 계획서마스터
  aliases: 계획서, 연구계획서

## screen

- `screen:PLA011` — 연구계획서 등록
  aliases: 계획서등록
```

| 타입 | 무엇 | 등록부 대상 |
|---|---|:--:|
| `table` | DB 테이블 | O |
| `screen` | 화면 | O |
| `api` | 인터페이스 엔드포인트 | O |
| `code` | 코드그룹 | O |
| `term` | 도메인 용어 | O |
| `batch` · `module` | 배치 · 공통 컴포넌트 | O |
| `issue` | 아젠다 | O |
| `domain` | **작업을 묶는 축.** 대상이 아니다 | **X** |

> **`domain:` 은 등록부에 넣지 않는다.** 그것은 바꾸는 대상이 아니라 분류이고,
> 최신성 계산에서도 뺀다. 넣으면 *"심의 도메인의 지금 상태"* 라는 있을 수 없는
> 섹션을 요구하게 된다.

### ③ 등록부를 정한다 — **여기가 판단이 필요한 자리다**

```markdown
| 좌표 패턴 | 정본 문서 | 섹션 |
|---|---|---|
| `table:*` | `docs/테이블정의서.md` | `## {값}` |
| `screen:*` | `docs/화면설계서.md` | `## {값}` |
| `code:*` | `docs/코드정의서.md` | `## {값}` |
| `issue:*` | `docs/위험및이슈관리대장.md` | `## {값}` |
```

**모든 좌표가 정본 문서 섹션을 가져야 하는 것이 아니다.**

관리 문서는 **자주 쓰는 내용을 한곳에 모아 둔 것**이다. 모든 것이 거기 녹지는
않는다 — 덜 쓰는 것을 하나로 모으는 리소스 부담이 이득보다 크다. **그때는 그
지식공유문서가 원천이다.**

| 그 좌표를… | 등록부에 |
|---|---|
| 여러 사람이 자주 찾고, 한 문서에서 모아 보는 게 이득이다 | **올린다** |
| 드물게 찾고, 그 작업 기록 하나로 충분하다 | **안 올린다** |

**등록부에 패턴을 올리는 것이 곧 "이건 정본 문서로 관리한다"는 팀의 결정이다.**
올리면 그 좌표를 건드린 모든 작업이 그 섹션 갱신을 요구받는다 — 검사가 막는다.
그래서 **가볍게 올리지 않는다.**

> 등록부에 없는 좌표는 **결함이 아니다.** 앱은 *"관리 문서가 없다"* 라고
> 말하지 않고 *"원천 — 지식공유문서 N건"* 이라고 말한다.

### ④ 관리 문서 16종

프로젝트 표준 산출물에 맞춘 기본 세트다. **좌표를 갖는 것과 안 갖는 것이
섞여 있다.**

| 좌표를 갖는다 (등록부 O) | 좌표가 없다 (등록부 X) |
|---|---|
| 테이블정의서 · 화면설계서 · 코드정의서 | **회의록** — 날짜축. 사건이라 좌표-섹션이 1:1이 아니다 |
| DB도메인용어정의서 · 인터페이스정의서 | **프로그램목록** — 집계. 내용은 사양서가 갖는다 |
| 프로그램사양서 · 요구사항정의서 | **개발일정계획서** — 시간축. 계속 바뀐다 |
| 프로세스정의서 · 기능정의서 | |
| 시스템아키텍처정의서 · 위험및이슈관리대장 | |
| 테스트케이스 · 테스트시나리오 | |

**등록부 대상이 아닌 문서도 앱은 문서로 읽는다.** 섹션 판정만 하지 않는다.

### ⑤ 훅을 넣는다

배포본의 `repo-kit/` 을 통째로 부어 넣으면 훅·스킬·규약·매뉴얼·`bin/ctx` 가
한 번에 들어온다.

```
xcopy /E /I <배포본>\repo-kit\* .
git config core.hooksPath .githooks
```

### ⑥ exe 를 레포 안에 둔다

```
mkdir tools
copy <배포본>\cdp.exe tools\
```

두 가지가 여기에 달려 있다.

**뷰어** — `tools\cdp.exe` 를 더블클릭하면 이 레포를 열고 화면이 뜬다.
레포 안에 있으므로 `--repo` 를 줄 필요가 없다.

**Node 없는 PC 의 검사** — `bin/ctx` 는 Node 가 있으면 `bin/ctx.mjs` 를 쓰고,
없으면 `tools/cdp.exe` 로 넘어간다. 그 파일이 없으면 `exit 127` 을 내고 훅이
검사를 건너뛴다. **커밋은 통과하고 보증은 사라진다.** 폐쇄망 PC 에 Node 가
없다면 이 단계는 선택이 아니다.

exe 는 `.gitignore` 로 빼 둔다 — 68MB 를 git 이력에 넣으면 되돌릴 수 없다.
그래서 반입할 때 **파일이 두 개**다(번들 + exe). clone 하나로 끝내고 싶으면
그때 `.gitignore` 에서 `*.exe` 를 지운다.

### ⑦ 줄바꿈

**`.gitattributes` 를 반드시 같이 둔다.**

```
* text=auto eol=lf
```

훅과 `bin/ctx` 는 sh 스크립트다. **CRLF 로 체크아웃되면 shebang 뒤에
캐리지리턴이 붙어 훅이 실행되지 않는다 — 그리고 조용히 실패한다.** 커밋은
통과하고 검사는 안 돈다. `core.autocrlf=true` 인 PC 에서만 깨지므로 폐쇄망에
옮긴 뒤에 발견된다.

### ⑧ 작업 레포에 에이전트 세팅을 넣는다

**코드가 있는 레포에서 클로드를 열면 지식 레포의 skill 이 보이지 않는다.**

하네스는 **프로젝트 루트의 `.claude/skills/`** 만 읽는다. 설계서는 "절차는
지식 레포의 skill 에 있다" 고 적어 두었는데, 그것은 사람에게 하는 안내지
기계적 연결이 아니다. 실측에서 작업 레포에는 skill 이 **하나도** 잡히지
않았고, 그 상태로 작업하면 `cdp-work` 가 아예 발동하지 않는다.

한 번 넣어 준다.

```
<지식 레포>\tools\cdp.exe ctx setup C:\gdi
```

두 가지가 들어간다.

```
CLAUDE.md            서식의 {{REPO}} 가 지식 레포 실제 경로로 바뀐 것
.claude/skills/      cdp-work · cdp-load · cdp-save · cdp-managed
```

원래 `CLAUDE.md` 가 있었으면 `CLAUDE.md.bak` 으로 옮겨 둔다 — 내용을 합치는
것은 사람이 판단할 일이다.

**`.gitignore` 를 확인한다.** 많은 프로젝트가 `.claude/*` 를 통째로 막아
둔다. 그대로 두면 skill 이 **설치한 사람 PC 에만** 남고 팀은 받지 못한다 —
그리고 설치한 사람은 되니까 됐다고 생각한다. `ctx setup` 이 이 경우를
알려 주지만, 고치는 것은 사람이 한다.

```
.claude/*
!.claude/skills/     ← 이 줄
```

**손으로 복사하지 마라.** 규약 · skill · 규약 안의 경로 셋 중 하나만
빠져도 조용히 작동하지 않는다.

**경로를 맞출 필요가 없다.** 지식 레포 경로는 커밋되지 않는 포인터 파일
`.claude/cdp.json` 에 들어간다 — `CLAUDE.md` 에는 없다. 각자 어디에 두든
된다.

```
CLAUDE.md            커밋. 규약만
.claude/cdp.json     **커밋하지 않는다.** .gitignore 에 넣는다
```

작업 레포는 여럿이어도 된다. **지식 레포가 하나인 것이 중요하다.**
포인터 파일이 작업 레포당 하나이므로 그것이 지켜진다.

전체 순서는 배포본 루트의 `설치.md` 를 본다 — 설치는 네 자리에서 벌어지고,
이 매뉴얼은 그중 지식 레포 쪽만 자세히 다룬다.

### ⑨ 원격

```
git remote add origin <url>
git push -u origin main
```

**원격이 유일한 수신 채널이다.** 안 보낸 커밋은 남에게 존재하지 않는다.

## 3. 검사 — 무엇이 커밋을 막는가

`.githooks/pre-commit` 이 `bin/ctx check` 를 돌리고, **error 가 하나라도 있으면
exit 1** 이다.

| 등급 | 뜻 | 커밋 |
|---|---|:--:|
| **error** | 이 상태로 남기면 나중에 **틀린 답을 확신 있게** 준다 | **막힌다** |
| warn | 알아야 하지만 지금 막을 근거는 아니다 | 된다 |
| info | 참고 | 된다 |

### error 목록

| 검사 | 왜 error 인가 |
|---|---|
| `필수 필드 누락` (`id` `title` `date` `author`) | 없으면 그 기록을 찾을 수도 판정할 수도 없다 |
| `id ≠ 파일명` | 등록부의 `applied` 가 id 로 가리킨다. 어긋나면 참조가 끊긴다 |
| `_vocab.md 미등재 좌표` | 좌표가 이름표인데 이름표가 없다. 두 이름이 갈라지는 시작점이다 |
| **`관리 문서 파생 누락`** | 아래 |
| `등록부가 가리키는 섹션이 없음` | 등록부가 자리를 아는데 문서에 없다. 갱신할 곳이 없다 |
| `applied 가 없는 기록을 가리킴` | 유령 참조. 이력이 끊겼다 |
| **`status: 미결` · `제안`** | 아젠다를 지식공유문서에 뒀다. 불변인 사건과 가변인 상태가 섞인다 |

### 파생 누락을 error 로 두는 이유

수행 설계서 v1.0 §6.2 는 이것을 warn 으로 뒀고 이유 셋을 댔다. **셋 다 성립하지
않는다.**

| 미루고 싶은 이유 | 왜 안 되나 |
|---|---|
| 파생이 넓다 | 넓어도 해야 한다. 넓다는 것은 그 작업이 실제로 그만큼 건드렸다는 뜻이다 |
| 남의 확인이 필요하다 | 필요 없다. 판단 근거가 지식공유문서에 이미 다 들어 있다 |
| 급하다 | **막히는 것은 코드 커밋이 아니라 지식 레포 커밋**이고, 그것은 작업이 끝난 뒤에 하는 일이다 |

그래서 **"밀림"이라는 상태가 없다.** 갱신을 안 한 섹션은 상태가 아니라 오류다.
등급을 나누면(한쪽은 error, 한쪽은 warn) 절반이 안 막히고, 그 순간 없는 상태가
화면에 다시 생긴다.

> **error 를 함부로 늘리지 마라.** 막히는 것이 잦으면 사람들이
> `--no-verify` 를 쓰기 시작하고, 그 순간 보증 층이 통째로 사라진다.

### warn

| | |
|---|---|
| `INDEX.md 불일치` | `ctx index` 로 재생성 |
| `deprecated 좌표 사용` | 어휘가 폐기 표시한 이름을 썼다 |
| `본문이 얇다` | 길이로 어림한 것이라 오탐이 있다. 확인 요청으로 읽는다 |
| `훅 미설치` | **조용한 실패다.** 커밋은 통과하고 검사는 안 돈다 |

## 4. 어휘 운영

### 늘리기 — 사용자가 한다

사용자가 새 좌표를 쓰면 커밋이 막히고, 그때 `_vocab.md` 에 한 줄 추가한다.
**관리자를 기다리게 하지 않는다.**

```markdown
- `code:PS130` — 외부인원 업무구분
  aliases: 업무구분코드, PS130
```

### 정리하기 — 관리자가 한다

주기적으로 볼 것 셋.

| 볼 것 | 왜 |
|---|---|
| **같은 대상에 좌표 둘** | 어휘가 갈라졌다. 하나를 `deprecated` 로 접고 alias 로 흡수한다 |
| **alias 가 없는 좌표** | 수신자가 자연어로 물어도 안 걸린다. 실제로 쓰는 표현을 넣는다 |
| **alias 가 라벨을 붙여 쓴 것뿐인 좌표** | 아래. **가장 흔하고 가장 조용한 결함이다** |
| **작업 0건인 좌표** | 등재만 하고 아무도 안 쓴 이름. 지우지 말고 그냥 둔다 — 미래에 쓸 수 있다 |

```
ctx term <이름>       어휘 조회 (정본 / alias / deprecated)
ctx match <이름...>   이름 → 정본 좌표 대조
ctx search <말...>    말 → 좌표 후보 (대조가 미등재를 낼 때)
```

### alias 는 맥락 주입의 **단일 실패점**이다

주입은 이 사슬로 돈다.

```
자연어 도메인 용어 → (alias) → 좌표 → 관리 문서 섹션
                       ↑
               여기가 끊기면 전부 빈손
```

**끊겨도 오류가 안 난다.** `ctx check` 는 어휘에 *없는* 좌표를 잡지만, 어휘에
있으면서 **아무 자연어로도 안 불리는** 좌표는 잡지 않는다. 그런 좌표는 조용히
안 걸리고, 요청을 받은 쪽은 그것을 *"레포에 내용이 없다"* 로 읽는다.

가장 흔한 형태는 **라벨을 붙여 쓴 alias 하나**다.

```markdown
- `api:/adapter/a10/expense-slip` — 지출결의서 생성 연계
  aliases: 지출결의서생성연계          ← 이렇게 부르는 사람이 없다
```

`지출결의서` 도 `결의서` 도 안 걸린다. 실제로 이렇게 새 나갔다 — *"결의서
결제수단 디폴트를 정해라"* 는 요청에서 `결제수단`·`과세구분`·`채주유형`
셋만 걸렸는데, **그 셋은 코드값 목록이라 요청문이 이미 전부 나열해 놓은
것**이었다. 답은 위 API 섹션에 있었고 주입되지 않았다.

**넣을 것** — 그 대상을 **부르는 말**을 실제로 쓰는 대로. 줄여 부르는 말,
화면에서 쓰는 말, 요구사항서에 나오는 말.

```markdown
  aliases: 지출결의서생성연계, 지출결의서, 지출결의, 결의서, 결의서생성, 결의서입력
```

**넣지 말 것** — 그 대상의 **속성**. `결제수단`·`과세구분` 은 그 자체가 다른
좌표(`code:AC-040` 등)이므로 여기 넣으면 서로 잡아먹는다. **먼저 등재된 쪽이
조용히 이긴다** — 충돌은 오류로 안 나온다.

> 좌표 이름이 **API 경로나 모듈명**인 타입을 특히 살펴라. 요구사항은 업무
> 언어로 오는데 좌표는 엔지니어링 식별자다. 그 둘을 잇는 것은 alias 뿐이다.

### 지우지 않는다

```markdown
- `table:rp_rdc_opl_mst` — 연관위 의견 (구)
  deprecated: 2026-03-26 오타 정정
  supersededBy: table:rp_rdc_opl_list
```

**과거 문서가 그 이름을 쓰고 있다.** 지우면 그 문서들이 검색에서 사라지고,
그때 "없는 것"이 된다. `deprecated:` 는 새로 쓰면 warn 을 내되 과거를 살려 둔다.

## 5. 배포

### 무엇을 나눠주는가

| | 무엇 | 크기 |
|---|---|---|
| **① exe** | `release/v<버전>/cdp.exe` — 앱 + `ctx` 가 한 파일 | ~68MB |
| **② 레포 번들** | `git bundle` 또는 clone | 수 MB |
| ③ `bin/ctx.mjs` | 레포 안에 이미 들어 있다 (자족) | ~156KB |

**exe 는 git 에 넣지 않는다**(`.gitignore`). 파일 두 개를 옮긴다.

### exe 만들기

```
npm run release          # 화면 → ctx → exe → 샘플 → release/v<버전>/
```

**결과는 `release/v<버전>/` 하나다.** 그 폴더를 통째로 옮기면 CDP 를 쓸 수
있다 — exe · `repo-kit/` · 샘플 · 설계서가 다 들어 있다. `release.cmd` 를
더블클릭해도 되고, 버전을 지정하려면 `npm run release -- 0.3.0`.

또는 단계별로:

```
npm run build            # 화면 (dist/)
npm run build:ctx        # dist/ctx/ctx.mjs 번들
npm run build:exe        # dist + ctx 를 exe 에 인라인
```

빌드가 **스스로 확인한다** — 마지막에 `cdp.exe ctx version` 이 날짜를 내놓지
않으면 실패로 보고 **반쪽 파일을 지운다.**

> **없는 것과 깨진 것은 다르고, 깨진 쪽이 더 나쁘다.** 없으면 다시 만들지만,
> 깨진 것은 다음 사람이 정상으로 믿는다.

### exe 빌드가 `EBUSY` 로 멈추면

```
taskkill /F /IM cdp.exe
```

떠 있는 `cdp.exe` 가 `build/` 를 잡고 있거나, 갓 복사한 68MB 파일을 백신이
스캔하는 중이다. 빌드가 재시도하다가 안 되면 위 안내를 찍고 멈춘다.

### **번들을 같이 갱신해야 한다** — 가장 자주 나는 사고

지식 레포는 `bin/ctx.mjs` 를 **자기 안에** 들고 있다(폐쇄망 자족). 그래서
도구를 고칠 때마다 레포마다 새 번들을 넣어야 한다.

**잊으면 그 레포만 옛 번들로 돌고, 조용하다.**

```
증상   ctx: 모르는 명령 "derive"
확인   ctx version   ← 세 곳이 같아야 한다
       cdp.exe ctx version
       <repo>/bin/ctx version
```

`CDP_REPO` 를 설정해 두면 `build:ctx` 가 그 레포까지 같이 갱신한다.

```
CDP_REPO=C:/cdp npm run build:ctx
[build-ctx] CDP_REPO 도 갱신: C:\cdp\bin
```

레포가 여럿이면 **그 수만큼 복사해야 한다** — 자동으로 찾을 방법이 없다
(레포 목록을 아는 곳이 없다).

### 폐쇄망 반입

```
# 망 안쪽
git bundle create knowledge.bundle --all
#   → knowledge.bundle + cdp.exe 두 파일을 옮긴다

# 옮긴 PC
git clone knowledge.bundle knowledge-repo
cd knowledge-repo
git config core.hooksPath .githooks     ← 잊지 마라
bin/ctx check
```

**CDN·인터넷을 타는 것이 하나도 없어야 한다.** 화면의 폰트까지 base64 로
인라인돼 있다 — `@import` 가 막히면 **조용히** 대체 폰트로 그려지고, 개발 PC
에서는 정상으로 보이므로 이관한 뒤에야 발견된다.

## 6. 운영 점검

### 매일 — 30초

상단 **⭮**(문서 동기화)를 누르면 fetch → (뒤처졌으면) ff pull → 재스캔을
한 번에 한다. 터미널이면 —

```
ctx brief
```
```
[CDP] 레포: 작업 기록 30 · 관리 문서 16
```

`파생 남음` · `미등재 좌표` · `미결` 이 뜨면 그 수만큼 커밋이 막혀 있다는 뜻이다.

### 주기적으로

| | 명령 | 볼 것 |
|---|---|---|
| 갱신이 남은 섹션 | `ctx derive` | 오래 남은 것 — 아무도 안 맡고 있다 |
| 인덱스 | `ctx index` | `INDEX.md` · `INDEX-by-coord.md` 재생성 |
| 원격 | `ctx sync` | 앞섬/뒤섬 · **훅 설정 여부** |
| 어휘 | `ctx term` · 앱 좌표 탭 | 갈라진 이름 · alias 없는 좌표 |

### 레포 경로를 바꾸려면

`⚙ 설정 → 지식 레포 → 로컬 경로` 에 넣는다. 입력하면 그 경로가 지식 레포인지
바로 확인해 주고(`_vocab.md` 가 있나), 맞으면 `이 경로로 바꾸기` 가 뜬다.

바꾸면 앱이 다시 읽는다 — 캐시·읽음 표시·좌표 인덱스가 전부 달라지므로 부분
갱신하지 않는다.

`--repo <경로>` 로 띄우면 그 경로가 우선한다.

### git 로그인은 앱이 하지 않는다

**자격 증명을 앱에 넣는 자리를 만들지 않았다.** 인증은 git 이 OS 자격 증명
관리자로 처리한다 — 앱이 아이디·토큰을 들고 있으면 그것을 저장할 자리가 하나
더 생기고, **그 자리가 가장 약한 곳이 된다.**

```
git config --global credential.helper manager
```

한 번 설정하고 아무 `git push` 를 하면 OS 창이 뜬다. 그 뒤로는 앱의
받기·보내기가 그대로 된다. SSH 키를 쓰면 그것도 그대로 된다.

설정 화면은 지금 연결된 원격(`origin/main` 등)만 보여 준다.

### 앱 상태바가 알려주는 것

| | |
|---|---|
| `✓ 검사` / 오류 배지 | 눌러서 결과. `Esc` 로 닫는다 |
| `⬇ 원격 N건 받기` | `pull --ff-only` |
| `⬆ 미전송 N건 보내기` | push — **사람이 누른다** |
| `⚠ 훅 없음` | `core.hooksPath` 미설정. 검사가 안 돈다 |
| `감시 중` / 끊김 | 파일 감시. 끊기면 상태바가 되살아난다 |

## 7. 장애 대응

| 증상 | 원인 | 고침 |
|---|---|---|
| **커밋은 되는데 검사가 안 돈다** | `core.hooksPath` 미설정, 또는 훅이 CRLF | `git config core.hooksPath .githooks` · `.gitattributes` 확인 |
| **`ctx: 모르는 명령`** | 그 레포의 번들이 낡았다 | §5 — 세 곳의 `ctx version` 을 맞춘다 |
| **한 레포만 다른 답을 낸다** | 같은 원인 | 같음 |
| **좌표가 하나도 안 잡힌다 (미등재 폭발)** | `_vocab.md` 가 CRLF 로 저장됐다 | 파일을 LF 로. 앱은 읽는 경계에서 정규화하지만 옛 번들은 안 한다 |
| 앱에 문서 0건 | 경로가 지식 레포가 아니다 | `_vocab.md` 가 있는 폴더를 지정 |
| 앱이 안 뜬다 · 콘솔 창도 없다 | 콘솔 없는 앱이다 | 로그를 본다 (아래) |
| `ff 불가` | 원격이 앞서 있고 로컬에도 커밋이 있다 | 터미널에서 `git pull --rebase`. **기계가 섞지 않는다** |
| exe 빌드 `EBUSY` | `cdp.exe` 가 떠 있다 | `taskkill /F /IM cdp.exe` |
| exe 는 있는데 `Cannot find module 'ctx'` | **SEA blob 주입 전에 죽은 반쪽 파일** | 지우고 다시 빌드. 지금 빌드는 스스로 막는다 |

**로그**

```
%LOCALAPPDATA%\cdp\logs\app.log
<exe폴더>\data\logs\app.log        ← 포터블 모드 (exe 옆에 빈 파일 cdp.portable)
```

**보안** — 앱은 loopback 에만 리스너를 연다. 루프백이 아닌 주소에 열면 상태바에
상시 경고가 뜬다. 토큰이 없는 접근은 401 이다.

## 8. 하지 않는 것

관리자가 "이거 넣으면 좋겠다" 고 생각하기 쉬운데 **일부러 안 하는 것들**이다.

| | 왜 |
|---|---|
| **알림** | 무시되기 시작하면 되돌릴 수 없고, 그때 *"알림이 안 왔으니 없는 것"* 이라는 더 나쁜 오해가 자리 잡는다 |
| **관리 문서 자동 생성** | 입도는 팀이 정한다. 기계가 정하면 아무도 안 본다 |
| **자동 push** | 커밋은 되돌릴 수 있지만 push 는 남의 눈에 들어간다 |
| **자동 merge · 충돌 해결** | 섹션 두 갱신을 기계가 섞으면 그 결과가 정본 자리에 앉는다 |
| **작업 할당 · 이슈 트래커** | 조직 구조와 얽힌다. CDP 가 답할 문제가 아니다 |
| **RAG · 임베딩** | 좌표가 답이다. 근사 검색은 "없는 것"을 "비슷한 것"으로 채운다 |
| **본문 형식 강요** | 자유 형식 md. 4섹션 강제는 이미 폐기했다 |
| **하네스 훅으로 절차 강제** | skill `description` 이 발동 규칙이고 그 뒤에 git 훅이 있다. **비결정을 비결정으로 덮지 않는다** |
